# The Settings form engine

The engine behind every Settings screen and wizard step (architecture §10.10). Screens import from `index.ts`; the components (`SettingsForm.svelte`, `SettingField.svelte`) by path. Decisions: `docs/decisions/2026-10-23-M-settings-form.md`, `2026-10-23-M-settings-form-2.md` and `2026-10-24-M-settings-form-3.md`.

## What's in a section's first view, and why

A Settings screen has the owner's 45 KB route budget (§10.1), and the engine is most of it. So only what a section shows on first paint is a static import. Everything else is a dynamic import, loaded once per page when it's first needed. That includes the save pipeline, as one edit chunk that loads with the first edit (owner, 2026-10-24). The merge and the draft restore stay synchronous once it's in.

**Eager (static imports):**

| File                                                         | Why it's in the first view                                                                                                             |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `form.svelte.ts`                                             | The store: loading, the field view, staging an edit, the debounces, events. Its `Engine` class is the `SettingsForm` the screen holds. |
| `draft-store.ts`                                             | Writing drafts, so an edit is kept from the first keystroke even if the edit chunk never loads.                                        |
| `schema.ts`, `types.ts`, `requests.ts`, `values.ts`          | Reading the schema into fields, the requests (and what a refusal names), saved values and staging.                                     |
| `messages.ts`, `message-map.ts`                              | Field labels and help: the lookup, and the loaders of the per-section maps (`message-maps/*`, on demand, below).                       |
| `widgets.ts`                                                 | Picking each field's control.                                                                                                          |
| `SettingsForm.svelte`, `leave.ts`                            | The form's frame, the leave guard's decision, and the lines that say part of the page couldn't load.                                   |
| `SettingField.svelte`                                        | The field: label, help, error, Automatic, the status line.                                                                             |
| `Control.svelte`                                             | The two controls cheap enough to keep: the toggle and the text input.                                                                  |
| `LazyControl.svelte`, `controls.svelte.ts`, `lazy.svelte.ts` | Loading the rest, with a placeholder of the right height so nothing moves.                                                             |

**Keep it that way.**

- A message used only on a lazy path belongs in a lazy file.
- A lazy file imports shared code from the eager files, never the other way round: an eager import of a lazy file makes it eager. `lazy-imports.test.ts` fails on one; add a new on-demand file to its list.
- The `index.ts` barrel exports only what screens use; a re-export there keeps its module in the first view.
- Rolldown pays about 400 B gz per chunk, so group what loads together into one entry (as `menu.ts` does) rather than many small ones.
- A chunk that fails to load can't be retried (browsers keep the failure), so every lazy path has a visible fallback: the "couldn't load" line in a control's place, under a previewed field or a field whose menu didn't load, instant mode putting the value back with it, the form's Reload banner when the edit chunk didn't load, or the draft offer's "couldn't load" banner with Retry (a reload; the stored draft is kept for it).
- A new on-demand file also goes in `settingsOnDemand` in `web/.size-limit.mjs`, so the screen route's entry stops at it and "Settings controls (on demand)" gates it.
