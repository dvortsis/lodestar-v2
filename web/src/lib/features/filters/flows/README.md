# features/filters/flows

The filters change flows (M-filters-dialogs): every filtering change previewed, warned about and confirmed exactly as the server says (architecture §20.10, §20.11, §20.7 "As built"), and the 18+ confirmation for "Show adult content" (§20.9, B17). Decisions: `docs/decisions/2026-10-23-M-filters-dialogs.md`.

**The server decides.** Whether a change weakens filtering, needs the password, is allowed at all and what it does all come from the preview job and `POST /filters/apply`. Nothing here judges a change, builds a warning or caches a password.

## API

Import from `$lib/features/filters/flows`; components by path, and lazily (`await import(...)` on first use), so none of this is in a route's first load.

| Export                                                                                                                                                                                                                                                                               | What it does                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `createChangeFlow(): ChangeFlow`                                                                                                                                                                                                                                                     | One change at a time. `state: FlowState`; `start(change)` (always previews first, as a job), `apply()` (in `review`), `confirm(password)` (in `confirm`), `variant(change)` (re-preview from `review`/`confirm`), `retry()` (in `failed`), `cancel()` (any state → `closed`). |
| `coreSwitch`, `packSwitch`, `addRule`, `updateRule`, `removeRule`, `addOverride`, `removeOverride`, `addException`, `removeException`, `addAllow`, `removeAllow`, `release`, `confirmAbuse`, `falsePositive`, `revealName`, `reportAbuse`, `removeCs1`, `floorRemoval`, `undoChange` | Change builders, typed to `Change`; no logic.                                                                                                                                                                                                                                 |
| `createAdultConfirm()`, `setShowAdult(on, adult)`                                                                                                                                                                                                                                    | The 18+ confirmation and the `content.show_adult` PATCH.                                                                                                                                                                                                                      |
| `errorText(e)`, `adultErrorText(e)`                                                                                                                                                                                                                                                  | What a refused change says.                                                                                                                                                                                                                                                   |
| `ChangeDialog.svelte`                                                                                                                                                                                                                                                                | `{ flow, title, applyLabel?, shadowDays?, onapplied?, onclose? }`: every state of one change, from progress to "What changed".                                                                                                                                                |
| `ImpactSummary.svelte`                                                                                                                                                                                                                                                               | `{ preview, neutralize? }`: the exposure summary; with `neutralize`, both CSX-5 strengths side by side.                                                                                                                                                                       |
| `EffectWarning.svelte`                                                                                                                                                                                                                                                               | `{ text, id?, password? }`: the server's warning, as text.                                                                                                                                                                                                                    |
| `AdultConfirmDialog.svelte`                                                                                                                                                                                                                                                          | `{ confirm }`: render once with the `createAdultConfirm()` it answers.                                                                                                                                                                                                        |

### States

| State        | Shown                                                                                                                    | Leaves on                                                                                                                                                                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `previewing` | phase, done of total                                                                                                     | job `done` → `review` (`confirm: false`) or `confirm` (`confirm: true`); `failed` / 429 → `failed`; `cancelled` → `closed`; job 404 → a new job, once                                                                                                       |
| `review`     | summary (and the warning, if any)                                                                                        | `apply()` → `applying` (no `password` key)                                                                                                                                                                                                                  |
| `confirm`    | summary, warning, password                                                                                               | `confirm(pw)` → `applying`; empty → `confirm` with `error: 'empty'`, nothing sent; before `retryAt` → nothing                                                                                                                                               |
| `applying`   | the same, Apply busy                                                                                                     | 200 → `done`; 428 → `confirm` (`changed` when the assessment differs); 401 `bad_password` → `confirm`; 429 `rate_limited` → `confirm` with `retryAt`; 409 `changed_since_preview` → `previewing`; 401 `login_required` → `closed`; anything else → `failed` |
| `done`       | "What changed": previewed beside applied, plus `released`, `removed`, `deleted`, `settled`, `id`, `exception`, `version` | Close                                                                                                                                                                                                                                                       |
| `failed`     | the server's message                                                                                                     | Retry (network, 408, 429, 5xx) → `previewing`; Close                                                                                                                                                                                                        |

### Caveats for callers

- **`cancel()` from outside during `applying` drops the answer.** The request is already sent, so the change may still apply on the server. `ChangeDialog` never does this: a close while applying waits for the result. Callers that cancel a flow themselves should refresh `GET /filters` afterwards.
- **`variant()` is accepted only in `review` and `confirm`.** One sent while `previewing` is ignored, so a control that switches variants (part 2's CSX-5 strength) must hold its choice and send it once the preview settles, or be disabled while previewing.
- **`onclose` fires once per close**, whether the user closed the dialog or the flow closed on its own (a job cancelled elsewhere, a sign-out).

## Mounting

- **S-filters** (Settings → Filters & Safety): one `createChangeFlow()` per screen and one `<ChangeDialog>` bound to it; each switch, rule, exception, Always allow entry, review-queue action, floor removal and Undo calls `flow.start(builder(...))`. Name the action in `applyLabel` ("Turn off CS-4a"). Pass `shadowDays` (e.g. 7) where shadowing makes sense; it's offered only for `add_rule`, `update_rule` and `add_override`. Refresh `GET /filters` in `onapplied`. Undo is `flow.start(undoChange())` from a new "What changed" action you place; it may ask for the password.
- **S-appearance** ("Show adult content"): `const adult = createAdultConfirm()`, render `<AdultConfirmDialog confirm={adult} />` once, and call `setShowAdult(on, adult)` from the toggle. When the screen saves through M-settings-form's form instead, register its hook in one line:

  ```ts
  form.onConfirm('adult_confirmation_required', async () =>
  	(await adult.ask()) ? { confirm_adult: true } : null
  );
  ```

- **S-search, S-detail** ("Block this…", reveal): part 2 adds `BlockThisDialog` and `RevealNameDialog` here.

## Security properties

- The password lives only in `ChangeDialog`'s input. It's cleared as soon as it's sent and whenever the flow leaves `confirm` (any outcome, a variant, a re-preview, close). It's never in the flow's state, a preview or job request, a URL, storage, a log, a toast or an error.
- It's sent only in `POST /filters/apply`'s body, only from `confirm`, for the change and assessment on screen. A floor removal sends back exactly the shown assessment's `floor_entries`.
- No "remember for N minutes": every weakening change asks again.
- The warning and the server's messages render as text, never `{@html}`.
