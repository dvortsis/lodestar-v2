# Soak run: 2026-10-23, pre-v0.5.0 build

A 24-hour Windows soak of `lodestar serve` on the `runner/token-classes` branch, started before v0.5.0 shipped.

**Passed, with the limits listed below.** The process ran the full 24 hours with no crash, no restart and no warning or error in the log.

## What was tested

- Binary: `cargo build --release -p lodestar` from the then-checked-out `runner/token-classes` (workspace version 0.0.0).
- UI: not built, so the binary embedded the stub page. The run says nothing about the real UI.
- Config: defaults, `LODESTAR_HTTP_BIND=127.0.0.1:8484`, `LODESTAR_LOG=info`, DHT on port 6881 on the real network, fresh data directory.
- Sampling: a supervisor script polled working set, private bytes, threads, handles, CPU, `/healthz` and data-directory size every 60 s.

## Limits of this run

- **Throughput was not measured.** The app was not asked how many torrents it had found, and its metrics were not scraped. The data-directory size stopped growing after the first hour, but it is a poor proxy: the WAL is capped by checkpoints, and the database and `dht-state.bin` were still being written in the last hour. Whether discovery kept running at a healthy rate is not established.
- **Shutdown was a forced kill** (`Stop-Process`, exit code −1), not a graceful one. Graceful shutdown and WAL recovery after the run were not tested. The supervisor's own log line says "stopping gracefully", which is wrong.
- The raw `samples.csv` from the run had a formatting bug (thousands separators in two columns). The file here is the cleaned version with the correct 10 columns.
- The one-time setup token was redacted from the saved log.
