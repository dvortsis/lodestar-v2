## Soak evidence

- **#579 is a crawler-lifecycle and fetch-path trigger,** in the same class as #554, which it extends. It changes when a fetch may download, adds a wait with its own timeout, and changes how a key is charged for one.
- **It joins rc.1's trigger list** (rc.1 delta report, "Soak evidence the delta rule asks for").
- **Which build the long runs use:** rc.2, so the evidence covers the fetch pool as it ships. They are the 24 h Docker soak on an upgraded folder with every pack on, the ≥ 6 h Windows run on a fresh folder, and the V12 → V14 upgrade smoke and rollback check on Docker and Windows.
- **What the collector and analyser need to know:** `fetch_reserved_bytes` and `fetch_reserve_timeouts_total`. `fetch_held_bytes` plus `fetch_reserved_bytes` stays within the 64 MiB budget, so it's the series to watch. The one exception is a single dict larger than the whole budget, which is fetched alone and goes over it. That can't happen at the default `max_metadata` of 16 MiB.
