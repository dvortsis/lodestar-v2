## What this means for the soak
**Everything in rc.4 changes memory behaviour, so r4's evidence doesn't carry over** (`docs/build-plan.md` §0.4, the delta rule). THP off and the musl allocator change how every allocation is backed; the gauges add a sampler on the storage tick; the `url.rs` change runs on every log line that holds a URL.

rc.4 needs **a fresh frozen soak, r5**, on the rc.4 image: the 6-hour sampling wait, a 30-minute warm-up, then a 24-hour baseline. It passes when the upper 95 % CI of the private-memory slope over hours 12–24 is ≤ 2.0 MiB/h, with gate evidence yes. The new `mem_*` gauges let r5 attribute any growth to mimalloc, SQLite or the rest.

What still carries over: rc.4 changes no store schema, no migration and no outbound endpoint policy, so r1's clean upgrade still counts.
