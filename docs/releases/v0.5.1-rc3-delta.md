## What it doesn't touch, so r3's soak evidence carries over
Nothing in rc.3 changes the crawler's lifecycle (DHT, sampling, fetch, the 6-hour sampling wait), the storage sampler, the outbound endpoint policy, the store schema or the migrations. #357 changes how stored filter rows load and how unreadable ones are reported: the filter engine's load, the Insights exception, `/metrics`, the digest and the web Insights view. With every stored row readable, which is the case on a fresh data directory such as r3's, the filter's hot path is unchanged. So the r3 soak on rc.2, and the gluetun leg run on rc.2, carry over to rc.3 under the delta rule (`docs/build-plan.md` §0.4). A short Unraid smoke of the rc.3 image confirms it starts, upgrades and serves (Track R step R3).

## The stand-in gap
rc.3 holds what an unreadable rule's stand-in matches: quarantines, and adult holds and Adult labels from an unreadable Is adult classification rule. **Nothing in rc.3 undoes those holds automatically** when the row becomes readable again (for example, after upgrading to a version that reads it). rc.3 also **doesn't write the `filter.stand_ins` record** that a later version needs to find them. F-filter-standin-undo (#367, on `main`) does both. It isn't in rc.3, because §2.29 limits rc.3 to rc.2 + #357.

**What is lost if nobody acts:** adult holds made meanwhile by an unreadable Is adult rule show as `adult_hold` in the review queue and **become tombstones at the 30-day purge** (§20.3) unless they're released by hand. A stand-in's quarantines expire the same way.

What still works in rc.3: editing or removing the row in Filters & Safety **while rc.3 still can't read it** repairs it. Fixing a rule releases its stand-in's quarantine, and removing an unreadable Is adult rule re-queues every torrent for classification. Once a later version reads the row again, that repair is only partial: removing the now-readable rule re-queues only what its real query matches, so torrents that only the stand-in marked Adult keep the label until they're next re-enriched. Until #367 ships, release anything the rule held from the review queue by hand. The gap only ever over-holds; it never loosens filtering.
