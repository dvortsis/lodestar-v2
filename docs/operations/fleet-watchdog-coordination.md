# Existing watchdogs: read-only inspection and broker handoff

This is a preparation procedure, not authorization to invoke functions, alter schedules, deploy, retrieve secrets or delete resources. The two services below were reported active in the [cloud assets record](lodestar-cloud-assets.md); their present state, deployed code and deletion paths have not been reverified by this remediation. Failed or unavailable reads are deployment blockers, never evidence of an empty fleet.

| Existing stack / function | Recorded schedule | Source scope / relationship to broker |
|---|---|---|
| `lodestar-expiration-guard` / `lodestar-aws-expiration-guard` | Every 15 minutes | AWS EC2 Windows, required ownership tags, VPC/security group, instance type and expiration/48-hour clock. The Linode broker does not replace this guard. |
| `lodestar-akamai-watchdog` / `lodestar-akamai-expiration-guard` | Every 30 minutes | Linodes selected by `lodestar` + `test` tags, `lodestar-` label, `us-east`, approved types, activation floor and age. It can overlap broker-registered IDs and does not use the broker authorization ledger. |

These are repository descriptions, not certified live boundaries. Public source deliberately differs from the last reconciled deployments. In particular, do not assume the AWS guard uses the improved first-start clock or that either deployed service has the source heartbeat/out-of-scope alarms.

## Collect a private, read-only evidence packet

Use only the existing authorized observer identity, with owner-refreshed credentials. Verify its actual account against the owner-selected canonical fleet account and confirm the region from stack ARNs. Stop on an unexpected identity; do not assume another role or grant permissions to finish the inspection. Keep resource IDs, account UUIDs, network identifiers, code and stack parameter values in private operator records. Do not dump Lambda environment variables, secret values, signed code download URLs or whole templates into public logs/chat.

The following PowerShell examples perform GET/List/Describe operations only. They are prepared commands and were not executed here. Supply the non-secret expected account from the owner's approved configuration:

```powershell
$ExpectedAccountId = Read-Host 'Approved canonical AWS account ID'
$ObserverProfile = 'lodestar-observer'
$Region = 'us-east-1'
$IdentityJson = aws sts get-caller-identity --profile $ObserverProfile --output json
if ($LASTEXITCODE -ne 0) { throw 'Observer identity unavailable; stop' }
if (($IdentityJson | ConvertFrom-Json).Account -cne $ExpectedAccountId) { throw 'Unexpected AWS account; stop' }

foreach ($Stack in @('lodestar-expiration-guard', 'lodestar-akamai-watchdog')) {
    aws cloudformation describe-stacks --stack-name $Stack --region $Region --profile $ObserverProfile --query 'Stacks[].{Id:StackId,Status:StackStatus,Updated:LastUpdatedTime}'
    if ($LASTEXITCODE -ne 0) { throw 'Stack inspection incomplete; stop' }
    aws cloudformation list-stack-resources --stack-name $Stack --region $Region --profile $ObserverProfile --query 'StackResourceSummaries[].{Type:ResourceType,Logical:LogicalResourceId,Id:PhysicalResourceId,Status:ResourceStatus}'
    if ($LASTEXITCODE -ne 0) { throw 'Resource inventory incomplete; stop' }
}
```

Resolve actual schedule, role, alarm and log-group IDs from these resources, not guessed names. For each stack inspect the following with the read-only APIs listed; complete all pagination and check every result. If targets use an EventBridge Scheduler schedule rather than an Events rule, inspect that service too. Store only selected non-secret results in the evidence packet.

1. **Schedule and delivery:** `events:DescribeRule`, `ListTargetsByRule`, `ListRuleNamesByTarget`, `ListEventBuses` and `ListRules`; where relevant `scheduler:ListSchedules` / `GetSchedule`. Record enabled state, rate/cron, bus, exact target ARN/alias/version, fixed payload, retry policy, maximum event age and dead-letter destination. Check all discovered buses/regions for duplicate triggers. Defaults must be resolved from current service documentation; absent retry fields do not mean no retries. Inspect target payloads privately before retaining selected fields.
2. **Deployed code and authority:** `lambda:GetFunction` (handle its signed download location privately), `GetFunctionConfiguration`, `GetPolicy`, `GetFunctionConcurrency`, `ListEventInvokeConfigs`, `ListAliases`, `ListVersionsByFunction`, `ListEventSourceMappings`, and function URL configuration if present. Compare downloaded code/hash, runtime, handler, pinned target version, account/region checks, deletion selection, dry-run semantics and exception handling against the reviewed source. Read the execution role's trust, attached/inline policies, policy versions and permission boundary using IAM GET/List calls. Resolve secret ARN **metadata** with `secretsmanager:DescribeSecret`; never `GetSecretValue`. Record only allowlisted non-secret configuration such as activation floor, VPC/SG and token-required flag. Do not assume a secret name establishes which Linode account its PAT belongs to.
3. **Health and actual activity:** `cloudwatch:DescribeAlarms`, `DescribeAlarmHistory`, `GetMetricData`; `logs:DescribeLogStreams`, `FilterLogEvents`; SNS `GetTopicAttributes` and `ListSubscriptionsByTopic`. Privately review recent scan summaries, confirmed deletion/error records, missing runs, delivery failures, asynchronous event age/drops and notifications. Verify subscription confirmation and policy scope without publishing addresses. Read CloudTrail events for configuration changes and known manual invokes where recorded; absence of invocation events is not proof of inactivity. No Lambda invocation, including a claimed dry run, is part of this inspection.
4. **Ownership and overlap:** independently obtain current EC2 and paginated Linode/firewall inventory using authorized read-only access. Verify Linode account UUID and scopes without copying the token. Compare **exact IDs, creation times, region, ownership, attachments and deadlines** with the recovered shared state, manifest, mismatch flag and `fleet/cleanup-authorization.json` (private S3 read with expected bucket owner). For every live resource record the existing reaper's eligibility/deadline and broker eligibility/deadline, or the reason it is unregistered. Never adopt by tags alone or repair state to make the comparison pass.

The observer may require separately approved read permissions: the listed CloudFormation, Events/Scheduler, Lambda, IAM metadata, CloudWatch/Logs, SNS and secret-metadata reads, EC2 Describe calls, CloudTrail lookup and narrowly scoped S3 List/Get on verified backend/control keys. Linode needs a separate short-lived read-only token (`account`, `linodes`, `firewall`). IAM/secret writes, `iam:PassRole`, Lambda Invoke, schedule changes, token retrieval and Terraform writes are unnecessary for inspection. If any access is unavailable, identify the missing API/resource and leave activation blocked; do not change permissions here.

## Owner decision and controlled handoff

1. **Keep provisioning disabled.** Freeze concurrent Terraform/operator/manual resource writers. Review the evidence packet, live inventory and the new broker's account UUID, activation floor, exact registration, expiration limits, retained firewalls/state and alert destinations. Unknown/unregistered or partially applied resources require a separate owner recovery plan. Do not create another fleet/backend or transfer them to the broker by editing its authorization document.
2. **Preserve AWS protection.** Keep the existing AWS EC2 guard and its alarms intact when its verified scope is separate from the Linode broker. The new broker supplies no AWS EC2 expiration. Any guard code/clock/permission update requires a separate reviewed change set; this PR authorizes none.
3. **Resolve overlapping Linode authority explicitly.** The legacy watchdog's tag-based selection can delete a registered Linode without broker version/account-ledger checks, and can race broker validation/deletion or leave state mismatched. Later age eligibility is not disjoint scope. Do not claim the broker's exact-resource boundary protects against an independently active broader reaper. Choose an owner-approved retirement/handoff of the overlapping watchdog, or a separately reviewed, demonstrably disjoint legacy scope. Do not remove ownership tags, shift activation dates or weaken deletion checks as a shortcut. Keep legacy protection for any resources the broker cannot cover until their separately authorized recovery/expiry is complete.
4. **Commission without unattended coverage gaps.** Separately authorize deployment of the reviewed broker with `EnableExpiration=false` and emergency disabled. Independently authorize credential setup, notification tests, read-only broker validation and a disposable, exactly registered deletion canary. Freeze provisioning throughout. Before any overlapping production authority is enabled, separately authorize the legacy Linode schedule handoff. An owner must supervise the bounded transition and specify the rollback deadline and manual response for every existing resource; if safe coverage cannot be maintained, stop. No current authorization permits these actions.
5. **Drain rather than assume.** A disabled rule does not establish that earlier deliveries, Lambda asynchronous retries, dead letters, another trigger or an invocation already running cannot delete. Derive the maximum drain period from the actual target delivery policy, Lambda event-invoke configuration, function timeout and service defaults. AWS documents [EventBridge delivery retries](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-rule-retry-policy.html) separately from [Lambda's asynchronous queue/retries](https://docs.aws.amazon.com/lambda/latest/dg/invocation-async-error-handling.html); both stages must be accounted for. Inspect invocations, logs and retry/DLQ evidence through that period; no replay/redrive. Verify the old function has no remaining invocation authority capable of affecting the broker fleet, through a separately reviewed retirement/restriction if needed. Do not rotate shared tokens or remove a secret/role/log group as an unreviewed shortcut. Retain evidence and alarms.
6. **Activate only after owner sign-off.** Separately authorize the exact reviewed change set enabling independent expiration, then verify recurring successful heartbeats, notification delivery and broker deadlines on the canary. Separately authorize emergency environment/role configuration and verify owner/main/first-attempt admission, no reviewer queue and negative claims before enabling emergency dispatch. Only then consider enabling owner-approved provisioning. Record the cutover time, code/template hashes, legacy state and retained resources.
7. **Rollback is an owner operation.** On errors, missing heartbeat, unconfirmed deletion or uncertain scope, keep provisioning off, retain mismatch flags and inspect exact inventory. An overlap re-enable can violate the same boundary: revalidate targets/deadlines before a separately approved rollback. No automatic state reconciliation, tag-wide deletion, secret rotation or Terraform recreation is allowed. Confirm full removal of authorized compute, separately approve retained firewall cleanup and reconcile shared state before another fleet.

Completion evidence must show which service owns each resource's expiration, no unaccounted overlapping deletion authority, verified alerts, a completed canary and retained-state reconciliation. Live code/identity, inventory, signed JWT/STS, queued deliveries and deletion behavior remain unresolved until these owner-authorized checks complete. Repository tests cannot certify them.
