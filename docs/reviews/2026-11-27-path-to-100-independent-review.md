# Independent review of the path to 100/min

**Decision.** Adopt the all-on-first experiment and the Balanced-first selection rule. Set Aggressive's fallback eligibility before rehearsal. Hold the acceptance booking until the four issues below have an owner-approved rule and a fixture that exercises the actual collector-to-verdict path. They can change which candidate qualifies even when everyone follows the run sheet.

The attachment is revision 4. The linked branch contained revision 5 at `a7a98d85f` when reviewed. Revision 5 addresses the earlier review's five subjects covering full-roster input, candidate segment validity, product-failure classification, per-arm leak-test cleanup, and the order of comparator and shipping work. The findings below apply to revision 5. This is a review of the design, source, and archived reports. The new harness and live host behavior have yet to be demonstrated. ## Before the acceptance booking

1. **An all-on candidate can be voided for an idle switch, or pass without evidence that another switch worked.** Both candidates enable `route_backoff`. The segment analyzer marks zero skipped routes as `void/no_opportunity` whenever that switch is on, including in a `comb` run. CR-SPEC explicitly anticipates zero opportunities on the default IPv4-only bind. The cloud screen did observe skips. Whether the box will see any remains open. In the other direction, lookup-cost checks run only for treatment `lc`, and the absent-soft-counter check runs only for `soft`. A true settings gauge establishes configuration but cannot establish that the mechanism operated. Freeze a per-switch table of required evidence, what a measured zero means, and which checks apply to the bundle. If the owner retains route's existing rule, specify what happens to the all-on candidate. Exercise zero route opportunities, a missing required counter, and an over-cap interval through `segment` and `gate-round`. [Mechanism dispatch](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/soak/tools/analyze_cr.py#L683-L701) · [Route verdict](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/soak/tools/analyze_cr.py#L1003-L1013) · [Cloud screen](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/plan/evidence/2026-11-24-cloud-screens/allon.md)

2. **A correctly spaced, invalid comparator can accompany a pass.** The proposed gate requires the booked report and timeline, but its explicit validity requirements apply to the candidate. The existing spacing helper reads timestamps. A comparator whose count stalled for an hour can provide every timestamp it needs. Require the booked run ID, `kind=comparator`, a valid non-rehearsal 24 h report, and the expected host and network identity. Rule 6.8 also requires a new comparator after a public-IP or network change. Specify how the physical uplink and the deliberately rotated VPN exits are identified for this rule. Use the segment's `timeline.window_end_utc` for spacing. The collector writes `result.json.ended` at finalization, including on an early stop. Test a complete but invalid comparator and an interrupted one before treating the box slot as available. [Gate and spacing code](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/soak/tools/analyze_cr.py#L1522-L1573) · [Collector finalization](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/soak/tools/linux/collect.py#L2193-L2218) · [CR-SPEC §6](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/decisions/2026-11-02-CR-SPEC.md#6-analysis)

3. **Some failure paths have no legal next layout.** If O2 makes A diagnostic and A repeatedly fails on day 2, §6.3 says to drop it. Both concurrent layouts require A, solo is reserved for contention, and the layout is fixed across both days. The rehearsal timeout also names a failing C or candidate but leaves a diagnostic A unaccounted for. Predeclare either termination with a report or a fresh two-day block in an explicitly permitted reduced layout. Record the attempt ID, layout and candidate digest so a day from before the change cannot be paired with one after it. Give an unresolved B a terminal disposition before the runner considers A. A failed leak test should stop all affected crawling through repair and successful verification. Repeated infrastructure failures need a retry budget and an explicit return to the owner. [Layouts and event precedence](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/plan/2026-11-27-revised-path-to-100.md#63-layout-rotation-rehearsal-and-retries) · [Existing leak-test stop condition](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/infra/fleet/steps/vm/leak-test.sh#L1-L6)

4. **Independent collector shutdown can invalidate a healthy peer.** Each arm gets its own observed `T_open` and final boundary scrape. If B closes two minutes before A, the existing run sheet's `--stop` stops B while A still needs B active. A full roster of reports cannot prove those last two minutes. Give one coordinator ownership of normal shutdown. Close each measurement on its own boundary, keep all healthy peers crawling through the latest final scrape, then stop the stacks. Archive evidence of process activity and egress through that last boundary. Rehearse staggered starts and finishes as well as a peer that actually dies during the overhang. ## Measurement and downstream decisions

- **Make shipping eligibility reproducible from the archive.** The proposed command lists three crawler tests. A separate memory fit determines whether B or A can ship. Emit a crawler verdict, both per-day memory verdicts, and the final Balanced-first selection from the same manifest. The existing fitter can return a numerical confidence interval for an incomplete window while leaving `meets_bar` unset. Test that case, missing `anon`, and B passing on rate but failing memory while an authorized A passes both. Also correct §6.4's cohort wording. Carry-in is subtracted for the mean and hourly rates. CR-SPEC deliberately retains carry-in in the latency histogram and charges dropped samples above 600 s. A fixture near the 95% boundary should catch accidental filtering. [Memory fitter](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/soak/tools/analyze_cr0.py#L593-L653) · [CR-SPEC cohort](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/decisions/2026-11-02-CR-SPEC.md#3-the-cohort)

- **A shared bottleneck can turn a Balanced pass into a valid-looking miss.** The contention tests cover CPU, steal and disk latency. An Aggressive peer could saturate the shared uplink while all three stay below threshold and every tunnel remains healthy. B's low hour would then end its claim and could select A as the default. Decide in advance whether that concurrent-load result is the intended product criterion. If it is not, define measurable network contention and when it warrants solo confirmation. Also define coverage of the 10 s host samples, the backing device for `/data`, and treatment of intervals with no completed writes. Missing samples during a stall must not improve the percentile. Budget disk against all simultaneous stores and retained archives. Three collectors can each observe the same 50 GiB free. [Contention rules](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/plan/2026-11-27-revised-path-to-100.md#63-layout-rotation-rehearsal-and-retries) · [Host storage bounds](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/soak/runsheets/host-stage1-ab-runsheet.md#L130-L149)

- **The break-even arithmetic works for its illustration. Some round-2 diagnoses exceed what the counters identify.** At yield 0.27, 100 stored/min needs 6.17 completions/s, about 191 lookup queries/s at 31 per completion, and mean slot hold of at most 13.0 s with 80 slots. The six reported full all-on hours average 97.35 gross stored/min, with no net-searchable conversion. The ledger clocks residence after dequeue even though a queued request can already hold a permit. Its standard query numerator counts `peer_lookup`, while hinted queries have a separate purpose. Aggregate attempt/success counts also cannot identify how many distinct hashes an additional attempt would recover. Name the source and denominator for each proposed diagnosis. When attribution is unavailable, report the uncertainty or test that hypothesis in round 2. [Lookup ledger definitions](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/decisions/2026-11-20-CR-LEDGER.md) · [Analyzer ratios](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/decisions/2026-11-20-CR-COL-5.md) · [All-on hourly data](https://github.com/dvortsis/lodestar-v2/blob/a7a98d85f/docs/plan/evidence/2026-11-24-cloud-screens/allon.md)

- **Replace Checkpoint 1's calculation as well as its name.** Section 3.4 asks for the rule 6.9 projection while retiring the uTP control segments and winning A/B effects that supply its inputs. It explicitly routes a projection below 100 to the owner, leaving unclear what happens at 100 with a projected 65/min worst hour, unmeasured latency, or only a memory failure. Freeze a replacement report built from the two days actually observed and record what sends the decision back to the owner. A memory-only miss calls for a memory diagnosis. A missing or inconclusive measurement needs an explicit outcome.
