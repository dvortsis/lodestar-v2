# X-e2e-orphan-specs decisions

- **Three real-server specs ran nowhere.** `filters-flows.fixture.routes.test.ts`, `insights.fixture.routes.test.ts` and `settings-form.fixture.routes.test.ts` talk to `lodestar serve --fixture` but ended in `routes.test.ts`, so only `core` matched them. `core` sets no `E2E_FIXTURE_URL`, so each skipped silently, and the nightly `fixture` project (`*.fixture.test.ts`) never saw them. They are wired in by renaming to `*.fixture.test.ts` (same contents, header commands updated). No `e2e.yml` change: the nightly `fixture` job already runs that project against the real server (`E2E_FIXTURE_URL`, `E2E_FIXTURE_PASSWORD`, `VITE_DEV_ROUTES=1` build). None is removed: none duplicates another spec or tests a removed feature.
- **`settings-smoke-fixture.routes.test.ts` stays in `core`.** "fixture" in its name is the mock data module `support/settings-fixture`; it uses the OpenAPI mock and runs in `core`.
- **Guard.** `playwright.config.ts` throws at load when a `*.test.ts` under `e2e/` matches no project (opt-in ones count), or when a spec reads `E2E_FIXTURE_URL` without the `.fixture.test.ts` suffix (the near miss that caused this). Checked against `zz-near.fixtures.test.ts` and `zz.routes.test.ts`; both fail the config.
- **Not changed:** the fixture job stays nightly/manual and out of `ci-ok` (§14 CI budget; a Rust build per PR is the cost). Moving it to a required job is a separate decision for the runner. `docs/plan/2026-11-06-v052-feature-manifest.md` still names the old `settings-form.fixture.routes` path (a historical record, left as is).
- **One sign-in for the fixture project (runner-approved, adds `web/e2e/support/fixture-session.ts`).** With the three specs added, the project signed in about 20 times and the server's login limiter (a burst of 5, then one every 12 s per address) refused 9 tests. The limiter is unchanged. A `globalSetup`, added only when the `fixture` project is selected, waits up to 60 s for `/healthz`, signs in once and writes the session to `test-results/.auth/fixture.json` (gitignored via `test-results`). Specs load it as `storageState` or `fixtureCookies()`. A failed sign-in fails the run with a message; specs are not skipped. `filters-flows.fixture.test.ts` keeps one real sign-in through the login form.
- **`search-query.fixture.test.ts` asserted a stale message.** GS-0 (e8df8330) made `sig:` real, so a short `sig:7a9f3c12` now answers "use all 16 hex digits of a payload signature…", not "arrives with grouping keys". The spec now expects the current text. This is why the nightly fixture job was red on 2026-11-13.
- **Verified:** built `lodestar` (debug, `VITE_DEV_ROUTES=1` UI), ran `serve --fixture`, and `--project=fixture` passed 24 of 24.
