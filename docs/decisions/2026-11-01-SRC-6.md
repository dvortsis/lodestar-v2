# SRC-6 decisions (Torznab/Newznab parser)

Slice SRC-6 of `docs/plan/2026-11-01-v06-sources.md`. It covers architecture §18.2 (Prowlarr/Jackett, plugin #1) and §18.9, and feeds the claims and provenance SRC-0 bounds (`crates/sources/src/claims.rs`).

- **A new crate, `crates/sources-feeds`, holds the feed parsers** (plan §4.1). `torznab::parse_each(body, &Limits, emit)` is a pure function from bytes to items, handing each item to `emit` as it ends; `torznab::parse` collects them with the default caps. No I/O, no async, `unsafe_code` forbidden by the workspace lints.
  - It depends on `lodestar-metainfo` (hash types) and `quick-xml` at the workspace's pin, `=0.42.0`, with no default features (approved in the brief). It doesn't depend on `lodestar-sources`: SRC-7 maps items to claims. A test checks the shared numbers match the contract's (`MAX_BODY`, `MAX_NAME`, `MAX_EXTERNAL_REF`).
- **Two kinds of cap.** Structural caps stop the parse with a `Stop` reason and keep the items already finished. Field caps skip the one item and count it in `Skipped`. A half-read item is never used.

  | Cap | Default | Over it | Why this value |
  |---|---|---|---|
  | `max_bytes` | 16 MiB | stop (`Bytes`); the prefix is parsed | The `Fetch` contract's `MAX_BODY`. A Torznab page of 100 items is 100–300 KiB, so this is 50× a big page |
  | `max_depth` | 16 | stop (`Depth`) | A Torznab item's fields are 4 deep (`rss > channel > item > field`). 16 leaves room for wrappers and stops a `<a><a><a>…` bomb at once |
  | `max_elements` | 1,000,000 | stop (`Elements`) | About 30 elements an item × 5,000 items is 150,000. This bounds the work in a body of tiny elements (16 MiB of `<a/>` is 4 M) |
  | `max_items` | 5,000 | stop (`Items`) | Prowlarr and Jackett pages hold 100 by default and rarely more than 1,000. Kept and skipped items both count |
  | `max_attrs` | 16 | skip the item | The widest element read is `enclosure` with 3. Counted only on elements the parser reads (`torznab:attr`, `newznab:attr`, `enclosure`, a root `error`); others' attributes are never parsed |
  | `max_attr_len` | 16 KiB | skip the item | A `magneturl` with many trackers is a few KiB |
  | `max_text` | 64 KiB | skip the item | A field's text, summed over its text, CDATA and entity pieces. Only kept fields' text is copied; a long `<description>` is skipped without being held |

  Smaller per-field limits trim instead of skipping, as the claims clamp does: title ≤ 1,024 B (`MAX_NAME`, cut on a character boundary, control characters removed); 16 category ids; 8 tags of ≤ 64 B; external IDs ≤ 32 B. A GUID or link over 2,048 B (`MAX_EXTERNAL_REF`) is dropped, since a cut URL points somewhere else.
- **Memory stays flat.** The reader borrows from the body; the parser holds one item and copies only the text of fields it keeps, each under `max_text`. What it emits is bounded by the body: every kept string is a trimmed copy of body text.
- **No DTDs, no entity expansion.** A `<!DOCTYPE` stops the parse (`Doctype`), so no internal or external entity is ever defined. Only character references and the five XML entities resolve, through `quick_xml::escape::resolve_xml_entity` (not the predefined resolver, which a workspace-wide `escape-html` feature would widen to HTML5's). Any other entity, or an invalid character reference, skips the item it's in; outside an item it's ignored.
- **Malformed XML stops the parse** (`Malformed`), keeping the finished items: quick-xml can't resynchronise after, say, a raw `&` in text. Prowlarr and Jackett write well-formed XML, so this costs nothing in practice.
- **The body must be UTF-8.** Torznab is UTF-8; past the first invalid byte the parse stops (`NotUtf8`) and the valid prefix is used. A byte-order mark is fine. The `encoding` declaration is ignored.
- **Element names are matched literally:** `torznab:attr` and `newznab:attr`, the prefixes every indexer manager writes. Namespace URIs aren't resolved; that's simpler and nobody rebinds them.
- **The info hash comes from `torznab:attr name="infohash"`, else the first magnet** among `magneturl`, `link`, `enclosure url` and `guid`.
  - 40 hex digits or 32 base32 characters are v1; 64 hex digits are v2. A magnet's `xt=urn:btih:` is v1 and `xt=urn:btmh:1220…` is v2; a hybrid magnet gives both. `Hashes::key()` is the DHT key (the v1 hash, else the v2 truncated, BEP 52).
  - With a valid `infohash` attribute, the magnet adds the other version when the two agree on the one they share: Prowlarr sends `infohash` as v1 and a hybrid's v2 only in `magneturl`. A magnet that disagrees adds nothing.
  - An `infohash` attribute that is present but invalid skips the item (`bad_hash`) even when a magnet is good: the indexer's two statements disagree, and the brief says anything else skips the item.
  - An item with no hash and no magnet is skipped (`no_hash`), unless it has `newznab:attr` and no `torznab:attr`, which makes it a `Usenet` item (parsed for v0.7; nothing uses it yet).
- **Fields kept:** title, size (`size` attribute, else `<size>`, else the enclosure `length`), category ids (numeric `<category>` and `category` attributes, deduplicated), `pubDate` (RFC 2822 to Unix seconds; numeric zones and GMT/UT/UTC/Z), seeders, leechers, peers, files, the download and upload volume factors (finite, 0–1,000), indexer `tag`s (Prowlarr's flags: `freeleech`, `internal`, …), IMDb/TMDB/TVDB ids (`0` means unknown and is dropped; a bare IMDb number gets its `tt`), GUID and link. The first non-empty value of each field wins.
  - **Not kept:** `description`, `comments`, `poster` and any uploader name. A Newznab `poster` is an e-mail-like identity, and §18.7 forbids profiles of people; SRC-7 can add a publisher claim later if one is wanted.
- **The external reference loses credentials** (`external_ref`). Prowlarr and Jackett download links carry the manager's API key, and private trackers' links carry passkeys; these would otherwise be stored in provenance.
  - Magnets are dropped as references (the hash is the identity, and a private magnet's `tr` URLs carry passkeys).
  - In http(s) URLs the user info and the fragment are removed, and so is every query parameter whose percent-decoded name looks like a credential: names containing `key`, `token`, `auth`, `pass`, `secret`, `sign`, `session` or `cookie`, and the names `sid`, `uid`, `sig`, `pid`, `user`, `u`, `i`, `r`, `k`, `pk`, `h` and `hash` (nZEDb's `&i=<user>&r=<apikey>`, whose query starts with `&`). Parameters split on `&` and `;`; a name that doesn't decode is removed.
  - Any other reference is kept only as an opaque id of ASCII letters, digits and `.:_-` (`urn:uuid:…`): no query to hide a key in, and no `javascript:` or `data:` for a page to link. The UI should still link only http(s) references.
  - A credential in a URL path can't be told apart and stays. Private indexers' items are `private_source` and never leave the machine (§18.7). SRC-7 decides whether to store the link at all.
- **Torznab error answers** (`<error code="100" description="…"/>`) give `Summary::error`, the code only. The description is the server's text and isn't kept.
- **Fuzzing:** `fuzz/fuzz_targets/torznab.rs`, with seeds in `fuzz/seeds/torznab/`. The first byte picks tight caps, so fuzzed documents reach every cap. CI's fuzz matrix lists `fuzz/fuzz_targets/*.rs` itself (`.github/scripts/ci_changes.py`), so the target runs whenever this crate changes; no workflow edit was needed.
- **One line outside the owned paths:** `("lodestar_sources_feeds", Component::Sources)` in `crates/lodestar/src/logging/mod.rs` `TARGETS`, which `targets_cover_every_crate` requires for every workspace crate. Approved by the runner, 2026-11-02; SRC-7's brief carries the same allowance.
- **Golden fixtures are written for the tests, in the exact shapes Prowlarr, Jackett and Newznab indexers answer with** (element order, attribute names, `apikey` links, `prowlarrindexer`/`jackettindexer` elements), with open-movie titles and `.example` hosts. The plan asked for recorded answers; this session has no indexer manager to record from, and the launch brief said to write our own and not copy third-party content. SRC-7's recorded-fixture contract tests will replay real recordings through this parser.
