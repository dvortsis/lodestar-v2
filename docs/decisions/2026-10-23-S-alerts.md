# S-alerts decisions (Alerts pages and dialogs)

Architecture §10.8, §10.3, §10.4, §10.13, §10.14, §10.17, §8 "Saved searches → alerts", with the B9, B10a, W9 and B16 decision files. No owner decision is reversed or loosened, and no owner number changes. The refinements the runner flags to the owner (§2.19) are marked **(§2.19)**.

## Screens

- **The list is a table from `large` (640 px) up and a stacked list below it (§2.19).** Columns: name (row header, a link), query, new, channels, last alert, then the pause toggle and Delete. One data path renders either; only one is in the DOM, chosen with `matchMedia('(min-width: 40rem)')` read synchronously at mount so a desktop never paints the stack first.
- **The list shows the two channels the API has, "In the app" and "RSS".** The notifier's external channels (webhook, ntfy, Discord, email) are stored in `saved_searches.channels` but neither returned nor settable (B9, B10a). Nothing is faked; the dialogs and the list gain them with the notifications settings section (S-settings-2).
- **The "New since …" divider is a heading (`<h2>`) in a grid row, not a separator.** The brief allows either. A `role="separator"` inside a listbox is rejected by axe (`aria-required-children`, and a focusable separator needs `aria-valuenow`), so the detail list is a `grid` (`VirtualList role="grid"`) whose rows hold one `gridcell`; the divider is a row with an `<h2>` that has the label as its text. It is visible text, not hover-only, and sits between the last unread row and the first read row (`since.ts`).
- **The divider's time is the first read row's `created_at`.** There is no last-viewed time in the API, so the label states what is true: every alert above it is newer than the last one you had seen. No read row loaded yet and more pages exist: no divider until one loads. All unread, last page: none. Nothing unread: none.
- **The new-alerts banner sits between the header and the list**, above the rows it describes, so nothing shifts under the reader. Its text also goes to a polite `aria-live` region updated at most once every 10 s (`throttle.ts`); clearing the region doesn't use up the window.
- **The empty query reads "Every new torrent"** (an empty `q` matches every new torrent).
- **No "Open in Search" per list row.** It is on the detail page, where the query and its sort are shown; the list stays to one action per concern (open, pause, delete).
- **Layout.** Pages are `max-inline-size: calc(var(--rail-width) * 5)` (1,320 px) so a table doesn't stretch on a wide display; the detail's list has a viewport-derived block size (`max(6 comfortable rows, 100dvh − 64 spacing steps)`) so the virtual list owns one scroller. Row heights are measured (`measureRows`): a row with a raw-name line is taller than one without, and the positioned rows use `transform`, which doesn't count towards CLS.

## Behaviour

- **Read marks.** `POST /alerts/read { saved_search, through }` is sent once per load and once per "Show", with the id of the top row, only when that row is unread. Never for a page loaded later, never in a loop; a failure is silent. The client never counts unread rows: the header's "N new" is the server's `unread` as the page opened and does not drop when the rows are marked.
- **Events.** List: any `alerts` event refetches `listSavedSearches` through a `latest()` slot, coalesced per task so events delivered in one frame cause one request; rows change in place. Detail: an event whose `saved_search` is this page's id refetches `getSavedSearch` (same coalescing) and the banner shows the server's `unread`, never a sum of `matched`. `onResync` refetches the list on the list page and the search (the banner count) on the detail; the loaded rows stay until "Show" so the list never moves under the reader.
- **Pause** is a switch whose accessible name includes the search's name ("Paused: <name>"). It shows `aria-busy` until the answer, ignores a second flip meanwhile, then shows the server's value; an error returns it to the previous state with an error toast. The resume rule is shown as help text after a resume.
- **Dialogs are lazy** (`import()` on first open) on both pages. The save dialog opens on its Name field, the delete dialog on Cancel (the safe choice); both restore focus to the opener on close (the primitive). After a delete from the list, focus goes to the next row's name, else the previous one's, else the heading; from the detail the page goes to `/alerts` with a toast. A `404 saved_search_not_found` on delete counts as already deleted.
- **Save dialog.** `q` and `sort` are omitted when empty/null. A name is checked locally (1–200 characters after trimming) so an empty name never leaves the page; every other check is the server's.
- **Links keep `density`** (§10.3), like the navigation, through the shell's `withDensity`.
- **Registered commands** are `alerts.new` ("New alert…", palette only, no key) on the list, and `list.next` (`j`) / `list.previous` (`k`) on the detail, all in scope `alerts`. They register in `onMount`: the registry's `register` and `pushScope` read and write its version, so inside an `$effect` they loop (`effect_update_depth_exceeded`). `lib/keys/README.md` says "in an `$effect` or `onMount`"; for this registry only `onMount` is safe. That is a note for the keys owner, not a change here.

- **Subscriptions start once the first load has succeeded (§2.19).** The brief says to subscribe in an `$effect` on each page. A page that opens the stream before the shell has installed its 401 hand-off (the chrome loads after first paint) leaves the stream stopped on a sign-in redirect nobody performed, so a signed-out visit never reached `/login`. Gating on data fixes that; the cost is that nothing subscribes while the first load is failing, and events between the response and the subscription are covered by that response (the next event or a resync refetches).
- **`invalid_value` with `field: 'sort'`** has no field in the dialog (the Alerts page sends no sort; Search passes its own), so it is a form-level "report a bug" message, like the codes that mean a bug.
- **Show and paging use separate request slots**, so a page-load can't abort a Show; a Show cancels any page in flight. Retry on the detail repeats whichever request failed last (load or refresh), and a `saved_search_not_found` from either shows the not-found state.

## Styling

- **No Tailwind utility is added.** Every layout rule is in a component `<style>` block with token variables (`var(--…)`, `calc(var(--spacing) * n)`, `var(--text-*)`); the only utilities used are ones the primitives and the shell already ship (`btn`, `btn-outline`, `border-field-border`, `size-4`, `sr-only`, the focus ring). Plain CSS needs no `@reference`, and the one breakpoint rule is `@media (min-width: 40rem)` (the 640 px breakpoint in rem, so it follows the user's text size). The search route's CSS stays 19.82 KB.

## Interim and stand-ins

- **`AlertHitRow.svelte` is a feature-local row** with `// TODO(S-search-2): replace with the shared result row`. It isn't clickable as a link (a link inside a grid row is a nested interactive control); a click or Enter on the row opens `/t/<hash>` through `VirtualList`'s `onActivate`, and only for a 40-hex hash.
- **Group labels and `dominant_share`** are `alerts_group_*` and `alerts_dominant_share` with `TODO(S-detail)` until S-detail adds the shared keys.
