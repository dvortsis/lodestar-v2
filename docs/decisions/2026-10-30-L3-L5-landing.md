# L3–L5 landing: runner decisions

Runner, 2026-10-30, for the combined L3–L5 landing PR. Flagged to the owner under `docs/owner-decisions.md` §2.19.

## Detail drawer size entry: 28.5 KB → 29 KB

- **What changed.** L3's visibility revalidation (cached detail is never shown before a fresh check, and a content-settings change clears the detail caches) subscribes the drawer to `settings` events. That pulls the shared event client (`events.svelte`, 2.1 KB gzipped) into the drawer's own chunk set, because the search route doesn't load it yet.
- **Measured.** 28,504 B on CI and 28,492 B locally, against 28,500 B. Trims that don't change behaviour moved the figure by less than the ±15 B that chunk-hash churn adds to each build.
- **Decision.** Raise the entry to 29 KB. That is +1.7%, well under the "measured + 10%" rule the other entries use (31.3 KB). The event client leaves this entry once the shell loads it (F-status's progress-aware status pill is the expected first user).
- **Not changed.** §10.1's 15 KB drawer target and the on-demand "Detail sections" entry (33.9 KB) are unchanged. Nothing moved out of this entry into another one.

## Key-screen review after the regeneration (`fix/L5-e2e`)

- **Welcome now snapshots the welcome page.** `/welcome` checks auth and sends a visitor without a session to sign-in, and its smoke route mocked no auth, so the regenerated "welcome" baselines were a second sign-in screen. The route now mocks `getAuthStatus` as signed in with setup done and asserts the "Setup complete" heading. The next CI run regenerates the welcome baselines (the `.update-snapshots` marker stays).
- **Settings shows the static top bar, as search does. Expected.** The new settings baselines have no status pill, palette or More button. That is the static bar from `app.html` (`#boot-header`), which has no right-hand controls. Since S-search-1 (`docs/decisions/2026-10-23-S-search-1.md`) the full bar (`Chrome.svelte`, `TopBar.svelte`) loads on the first interaction or after 30 s, and a smoke screenshot has neither. The previous settings baseline (`0cf1abc8`, 2026-10-23 05:26) was generated before that deferral (`21bd01bc`, 17:57 the same day), so it still showed the full bar. The search baselines regenerated after the deferral (`a5aebdbe`) have the same static bar. A local probe at 1366 px on `/search` and `/settings/general` found `#boot-header` present and no `status-pill` or `palette-button` before any input, both present after one click, and no console messages or page errors. No product change.
