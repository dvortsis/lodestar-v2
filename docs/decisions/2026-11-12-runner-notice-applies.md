# Runner decisions: the Legal Notice's "Applies to" line (#725)

- **The line on `main` names `main`'s builds, not a release** (owner delegation, `docs/owner-decisions.md` §2.57). It now reads: "Applies to the development builds of Lodestar on the `main` branch, which lead to the next release cut from `main`. … Each release carries its own copy of this notice, written for what that build does: v0.5.1 carries version 3, and v0.5.2 carries version 4."
  - **Why:** the old line said `main`'s version 5 applied to 0.5.2, which carries version 4 (`release/v0.5.2`, `NOTICE_VERSION = 4`). A notice that claims to describe a release it doesn't ship with is wrong in exactly the place a reader checks first.
  - **"The next release cut from `main`", not a number:** the next version number isn't decided, and a patch release cut from `release/v0.5.2` would not carry `main`'s notice, so "the release after 0.5.2" could mislead. When a release branch is cut from `main`, its copy names that release and `main`'s line stays as it is. Keeping this line accurate at each cut is part of the same delegation (§2.57) and of keeping the legal documents current before publishing (§2.48).
  - **"A development build may report an earlier version number"** stays: `main`'s workspace version is still 0.5.0.
- **`NOTICE_VERSION` stays 5, and so does its date (2026-11-11).** The change says which software the notice describes and nothing about what that software does, so it isn't a change in substance (`crates/api/src/legal.rs`). No admin of a released build has seen version 5; only development hosts running `main` have, and nothing they accepted has changed in substance. The precedent is commit 9cf2998d, which corrected version 4 before its release without raising it. The date stays because it records when version 5's substance was set. Both copies stay byte-identical (`crates/lodestar/tests/legal_facts.rs`).
- **`release/v0.5.2` has the mirror-image slip,** and it must be fixed before the v0.5.2 tag (§2.48). Its two notice copies and `docs/legal/operator-guidance.md` say version 4 applies to "the development builds that lead to it (the `main` branch)", and `main` now carries version 5. The fix is an editorial PR into `release/v0.5.2`: the line names 0.5.2 and its release candidates only, and version 4 stays. The runner tracks it with the v0.5.2 cut.
- **The operator guidance's status line on `main`** belongs to X-event-log-followups (#721), which already moves it to "version 5". The runner asked that slice to use this wording in the same edit.
- **X-event-log-followups' `owns`** gain `crates/lodestar/src/update/windows/rollback.rs`, `update/windows/helper.rs` and `windows/acl.rs`, the three files #721 edits outside its list, so the overlap check holds them while it's open.
