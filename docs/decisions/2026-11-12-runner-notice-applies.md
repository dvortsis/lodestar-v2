# Runner decisions: the Legal Notice's "Applies to" line (runner PR, 2026-11-12)

- **The line on `main` names `main`'s builds, not a release** (owner delegation, `docs/owner-decisions.md` §2.57). It now reads: "Applies to the development builds of Lodestar on the `main` branch, which lead to the release after 0.5.2. … Each release carries its own copy of this notice, written for what that build does: v0.5.1 carries version 3, and v0.5.2 carries version 4."
  - **Why:** the old line said `main`'s version 5 applied to 0.5.2, which carries version 4 (`release/v0.5.2`, `NOTICE_VERSION = 4`). A notice that claims to describe a release it doesn't ship with is wrong in exactly the place a reader checks first.
  - **"The release after 0.5.2", not a number:** the next version number isn't decided. When a release branch is cut from `main`, its copy names that release, as the 0.5.2 copy does, and `main`'s line moves on to the release after it. That edit is editorial too, and it's the release cut's job (§2.48: keep the legal documents current before publishing).
  - **"A development build may report an earlier version number"** stays: `main`'s workspace version is still 0.5.0.
- **`NOTICE_VERSION` stays 5.** The change says which software the notice describes and nothing about what that software does. No released build has shown version 5, so nobody has accepted the old wording of version 5. The precedent is commit 9cf2998d, which corrected version 4 before its release without raising it. Both copies stay byte-identical (`crates/lodestar/tests/legal_facts.rs`).
- **The operator guidance's status line is not changed here.** `docs/legal/operator-guidance.md` belongs to X-event-log-followups (#721), which already moves it to "version 5". The runner asked that slice to match this wording in the same edit.
