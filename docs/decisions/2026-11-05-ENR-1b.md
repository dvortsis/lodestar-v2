# ENR-1b decisions (enrichment gate, generation race, NoQuery)

Slice ENR-1b (runner brief, 2026-11-05T12:50Z). It closes the #480 review follow-ups that `2026-11-05-ENR-1.md` records under "What isn't done here", before the enrichment runtime is wired in. Read it with that file; where they differ, this one wins.

- **Only an enrichment source may attach an adult section** (`unverified::Ctx::enrichers`). The pipeline builds the set from the registered manifests with `Kind::Enrichment` (`adult_enrich::EnrichSources`, beside `AdultSources::of` in `Pipeline::start`), and the writer passes it to `ingest`.
  - Any other source's section is dropped before judging. The rest of its claims take the usual path.
  - So an always-adult source (X-source-adult) can't use a section to skip the matches path's `touched` and `adult` accounting, and its mask still applies.
  - Claims that held nothing else are refused.
  - An enrichment source that's also always adult keeps its mask: its stored match adds the torrent to `adult` too.
  - An empty set (the default, and every `Ctx` built without it) lets no source attach one.
- **The generation race.** `apply_matches` now takes the live `Handle`. It reads the classification generation first, then the rules, as the backfill does, instead of the engine the writer took before the batch. A rules change landing in between can no longer be written over: the old order could clear the backfill's mark and keep an item a new Not adult rule covers being looked up.
  - Without a filter in the `Ctx`, matches are all left for the backfill.
  - Deferred matches raise the writer's `reenrich` flag (`Ctx::reenrich`), so the backfill runs without waiting for a restart.
- **A record rewritten without its claims** is marked so the backfill applies the match again (`enrich::mark_matched`). The case is a partial import's upgrade, which writes prepare's record.
  - The helper and its test are here.
  - **The call in the writer's commit is the runner's decision.** It needs a hook in `writer.rs` beyond the `Ctx` fields this slice may add (RP-4 owns `writer.rs`). Until it lands, the kind pin returns at the next parser or rules change, as `2026-11-05-ENR-1.md` says.
- **Intake doesn't count a match as harvested** (`adult_enrich::is_match`: strategy 202 and an adult section). It's an answer about a stored torrent, not a key the source found. `received` still counts it.
- **A name that says nothing useful sends nothing, in either form** (runner §2.33, stricter than Q2; the runner flags it to the owner).
  - This covers "New folder", an ambiguous name, or one the parser resolved from the files: `named.title.ambiguous`, which includes `is_uninformative`, or `resolved`.
  - Such a lookup can't match, costs budget, and tells the service an adult item was viewed.
  - The check runs on the torrent's name alone, with no files.
  - **A single-file torrent's name is its file name.** That's allowed: it's the display name the torrent carries, not a name read from its file list.
- **`writer.rs` and `lib.rs` hunks** (shared, kept minimal):
  - `writer.rs`:
    - the `Writer.enrichers` field;
    - `ingest_found`'s `Ctx` gains `enrichers`, `filter` and `reenrich`;
    - the promotion and refile `Ctx` literals gain `..Default::default()`;
    - the test `Writer` gains `enrichers: Default::default()`.
  - `lib.rs`:
    - `EnrichSources::of` beside `AdultSources::of`;
    - `enrichers` in the `Writer` literal;
    - the `HARVESTED` line in `intake`, behind `is_match`.
- **Tests** (`crates/pipeline/tests/adult_enrich.rs`, unit tests in `adult_enrich.rs`). Each fails without its fix; the gate and the race were checked by reverting each fix.
  - an always-adult source's section can't skip its mask, and a section alone from a non-enrichment source stores nothing;
  - a rules change between the writer's snapshot and the match isn't overwritten: the row stays marked and no stale kind is written;
  - deferred matches raise the backfill flag, and with no filter they're all deferred;
  - a pending torrent is eligible again once the backfill has run;
  - a rewritten match is marked and the backfill applies it again;
  - a vague name sends nothing in the name form;
  - `is_match` and `EnrichSources::of`.

  No fixed sleeps: the race is forced by doing the rules change between taking the snapshot and calling `ingest`, in sequence.
- **Out of scope** (with SRC-11c and ENR-7): the host wiring of `AdultEnrichSource`, `Switches`, `StoreState` and `Interest`, and ENR-7's rate limit on user-interest lookups.
