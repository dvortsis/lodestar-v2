# F-filters decisions

Three content-filter semantics fixes from the v0.5 code review, Area 3 (A3-1 to A3-3; `docs/code-review/codex-review-v0.5-area-3-results.md` on `fix/dht-cr0`). They restore architecture §20.6, §20.9 and §20.12 as written. No owner decision changes.

- **A3-1: an exception covers its own list only (§20.12, §20.6).** The pack layer used to reduce the subscribed lists that had a torrent to the strongest one, then apply exceptions to that one list. An exception to that list therefore lifted every other list too. Now each list is excepted on its own, and then the strongest action left among packs and lists wins. With no exceptions, the verdict and the rule it names are unchanged: the last of the strongest still wins.
  - **Before the fetch (`blocked_hash`)**, a torrent is refused when any dropping list still has it and no exception to *that* list could release it. Before, only the strongest list was checked, so an exception to one dropping list let a torrent through to the fetch even when another list still dropped it. *Always allow* and hash-matching Override entries still let the fetch happen, as before, because they need the text. After the fetch, every list is judged again.
- **A3-2: stored reclassification reads the swarm hashes (§20.7, §20.9).** Classification rules on a stored torrent were judged with no hashes, so `hash:` never matched and `-hash:` always did. They now get the same hashes ingest uses: the primary hash and, for a hybrid, the truncated v2 hash. Your own correction still comes first.
- **A3-3: a neutralized word supplies no evidence in any form (§20.6, "Neutralize term removes that word's evidence from the core and from query rules").** A *Neutralize term* used to be compared only with a whole query word, or with a whole phrase as if it were one word. Phrases compared the folded text of the entire phrase, and NEAR ignored neutralizing altogether (the follow-up recorded in `2026-10-22-F-near.md`). Now:
  - **Words, phrases and NEAR words are compared word by word.** The comparison covers each word in the text and each run of words with no space between them, up to 8 words. So `amber` is neutralized in `"amber beacon"`, `amber NEAR/1 beacon` and `amber.beacon`. Any word the clause needs being neutralized makes the clause false, wherever it stands. This keeps positions: the rest of a phrase isn't matched as a shorter phrase.
    - **A word is a run of parts with nothing between them.** So `x265` is one word, and neutralizing `x` leaves `x265` alone, as it does for the plain word `x265`.
  - **Prefixes and fuzzy words skip a token that is a neutralized word.** So `amb*` and `~ambar` no longer match on `amber` alone, but still match on other tokens such as `ambient`.
  - **Negation is unchanged in kind:** a neutralized clause is false, so its negation is true, as for a bare word since CSX-5 shipped (`neutralized_words_never_count`).
  - **`unless`, exceptions and CSX-5 scopes read the torrent as it is**, as before. An `unless` is an exception to its rule (§20.12), so neutralizing never takes an exception away. This choice is open to the runner. Neutralizing inside `unless` would hide more, not less.
  - **Always allow is already judged with neutralizing**, so an allow query that needs a neutralized word inside a phrase or NEAR now matches less. That protects more.
  - **The reference matcher** (`matcher_reference.rs`) uses the same comparison (`neutral_folds`), so the property test comparing the two matchers still checks the evaluation paths.
- **What this changes for users.** A user rule whose phrase, NEAR, dotted word, prefix or fuzzy word depended on a neutralized word stops matching on that word, as §20.6 describes. Core and pack rules don't change: they already read the neutral term set. Subscribed lists now hold where an exception to another list wrongly released them. A stored torrent with a matching `hash:` classification rule becomes Adult at its next reclassification.
- **Cost.** Compiling a rule now folds each word run of its words, phrases and NEAR words, once per rule. When nothing is neutralized, evaluation costs one extra empty-slice check per clause. The `budget` gate (10,000 rules) is re-run in the PR.
