# GS-4 decisions (Detail drawer: Related)

Spec: architecture §10.5 item 5 (Related) and §10.14; UI review 02 §5.1 ("four labelled lists (Other versions, Identical clones, Same file, Similar payloads), each with a count, the attributes that differ shown per row, and Compare these pre-filling /compare (2–5)"). Data: `GET /torrents/{hash}/siblings` (GS-2, `docs/decisions/2026-11-12-GS-2.md`). Built for the runner's stand-in.

- **The four lists always show, in the UI plan's order, each labelled.** An available list shows its count beside its label ("12", or "20+" when the server says more matched than it listed); one with no rows says "None found."; an unavailable one names its reason in a sentence instead of a count (no parsed title, no content files, v1-only for Same file, a payload too small or too round, a partial file list, too few large files, search off, and "until the search index is rebuilt" for the index-side reasons). Keeping all four, rather than hiding empty ones, keeps the section's shape the same from torrent to torrent and says why a list is empty. **Refinement (§2.19):** the brief allowed either.
- **"Some may be missing" is said once per list** when the server flags it: still being indexed (`*_partial`), or only the largest files were looked up (`same_file_capped`). Partial wins over capped.
- **A row shows the release name and only what differs from the open torrent:** title, resolution, type, size, files and seeders, in that order, compared with the open torrent's search hit (where the parsed fields are). Without a hit, only size, files and seeders are compared: a field the open torrent's data doesn't carry is never called different. A missing value and a null one count as the same; a differing field the row has no value for (no resolution) isn't shown.
- **Compare these:** each row has a checkbox; the open torrent is always the first column, so 1 to 4 picks make the 2 to 5 /compare takes (§10.6). The picks keep the order they were made in. Outside that range the button is disabled and a line beside it says why ("Pick 1 to 4 torrents…", or how many to unpick); in range the same line counts the picks and the button is a link to `/compare?h=…` (`compareHref`). A torrent in two lists is one pick.
- **Nothing the API withheld shows.** Rows are exactly what the server returned (its visibility rules: hidden, Show adult content, private), less the open torrent and repeats. A 404 for the open torrent removes the whole section, heading included. A load that outlives a content-settings change (the detail caches' generation moved) is dropped, and an answer about another hash is treated as a failure. Other failures say "Couldn't load related torrents." with Retry.
- **In the drawer a row opens in the drawer** (`openDetail`, one history entry, as j/k does); a modified click and every click on /t follow the link to `/t/{hash}`. The new load unmounts the row, so focus moves to the drawer's title first. `open.ts` is imported on demand, so /t never downloads it.
- **Estimated seeders keep their ≈**, as on result rows; a torrent never scraped says so. A checkbox gets the full touch target on a coarse pointer. Retry moves focus to the section's heading, since its button goes with the failed block. The Compare bar shows only when some list has rows.
- **Lazy, like the other below-the-fold sections.** `related/RelatedMount.svelte` is the one mount line in `DetailView.svelte` (plus its import): a placeholder heading and skeleton, and the section's chunk loads when it scrolls near in the drawer, at once on /t. The mount carries `data-section="related"`, so a later scroll target exists before the chunk loads.
- **Sizes (runner §2.26):** a new entry, "Detail Related section (on demand)", measured 5,370 B, limit 5.4 KB. /t's own view 15.48 → 15.69 KB (15,682 B): the mount's placeholder and dynamic import. "Detail sections (on demand)" 47.49 → 47.87 KB (47,864 B): Related's on-demand import of the drawer's `open.ts` (and the magnet chunk it shares) counts in /t's on-demand graph, though /t never calls it; the drawer already loads them. The drawer's own view grows about 250 B (27.79 → 28.04 KB) and stays under its 28.31 KB limit.
- **Show all still opens the best version's drawer (GS-5).** Opening Related directly needs a section target in the drawer's open API (`open.ts`, `DetailHost`) and a change in `features/search/collapse/**`, both outside this slice's owns. Left to a follow-up for the runner to place; the mount has `data-section="related"` to scroll to.
- **Related and Parsed both fetch `/siblings`** for the same torrent (Parsed for its own use). Sharing one request needs a cache in a file outside this slice's owns; left to the runner to place.
- **Shared-file lines:** `web/src/lib/features/detail/DetailView.svelte` (the import and the mount line, replacing the Related slot comment); `web/.size-limit.mjs` (Related in the drawer's lazy list, its entry, and the two raises above).
