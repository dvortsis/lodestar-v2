# ENR-13 decisions: detail drawer, "Identified as" section

Slice ENR-13 (runner brief, 2026-11-12). Spec: §10.5, §10.14; the field shape is `IdentifiedAs` (ENR-10, ENR-12).

- **One component, `detail/identified/Identified.svelte`, mounted from `DetailView.svelte`** (a ~5-line edit outside the slice's owned path, which the runner was told about before it was made), so the drawer and `/t/[hash]` share it. It is a lazy chunk, imported only when the detail has `identified_as`; the API omits the field when there is nothing to show (hidden, held, private or Adult torrents, no answer, no visible source), so then the chunk is never requested.
- **Plain text with bidi isolation.** Every text (canonical and alternative titles, genres, ids, the source's name) is rendered as text, never markup. Each goes through `showBidi` (direction controls made visible) and sits in a `<bdi>` (the source line as a whole), so stored text cannot reorder what is around it. An alternative title's `lang` is set only when it looks like a BCP 47 tag; `und` and anything else are left off.
- **A null `resolved_via` is never "from the name".** The section says nothing about the origin: `chosen` marks a plugin's title, and a file-tree resolution (`files`, `folder`, `structure`) is already shown in the view's header line, so repeating it here would duplicate it. The section renders only when there is at least one answer (the API never sends `identified_as` with none). Two plugins that disagree are both shown, in the order the API sent (surest first). **Follow-up for the runner:** `parsed/Parsed.svelte` still shows "From: name" when `hit.resolved_via` is null, which contradicts this section when a plugin's title is chosen; it is another slice's file.
- **`Interest::opened` is not done here, and needs a Rust slice.** The brief's item is not met by this PR. `DrawerInterest` (`crates/api/src/torrents.rs`) feeds ENR-1's adult-enrichment runtime and only for the admin with Show adult content on; the `Interest` ENR-14 left unwired is `lodestar_pipeline::identify::Interest`, which nothing in `crates/api` or `crates/lodestar` reaches. A web call can't fix that safely (a client-triggered lookup would bypass any server rate limit), so the detail GET should offer the id to `identify::Interest` behind a per-client and overall rate limit, not gated on adult. The runner accepted the move to a Rust slice (2026-11-12); the host's not mounting `DrawerInterest` is tracked as X-always-adult-detail-mask.
- **Messages** are in `detail/identified/messages/{en,zh}.json`, keys `detail_identified_*` (the part-folder rule, as for the adult and provenance sections).
- **Size** (the ENR-8 pattern). New on-demand entry "Detail identified-as section (on demand)" (measured 1,830 B, limit 2,000 B); the chunk is left out of "Detail sections (on demand)" and of the two first views via `detailLazy`. The one dynamic import in `DetailView.svelte` costs the first views what ENR-8's did: Detail drawer 28,064 B limit, measured +54 B over; `/t/[hash]` 21,904 B limit, measured +32 B over. **Raised by the runner (§2.26, 2026-11-12; flagged to the owner):** Detail drawer 28,064 B -> 28,128 B (measured 28,118 B, +54 B over the old limit); `/t/[hash]` 21,904 B -> 21,952 B (measured 21,936 B, +32 B over). The new section's own entry stays at measured 1,830 B, limit 2,000 B. No other limit changed.
- **The mount test sits next to the mount.** The case that the section mounts only when `identified_as` is present is in `DetailView.test.ts` (outside the slice's owned paths; the runner accepted the edit), and that file now waits for lazy chunks up to 10 s (`configure({ asyncUtilTimeout: 10_000 })`).
