# ENR-13 decisions: detail drawer, "Identified as" section

Slice ENR-13 (runner brief, 2026-11-12). Spec: §10.5, §10.14; the field shape is `IdentifiedAs` (ENR-10, ENR-12).

- **One component, `detail/identified/Identified.svelte`, mounted from `DetailView.svelte`** (a ~5-line edit outside the slice's owned path, which the runner was told about before it was made), so the drawer and `/t/[hash]` share it. It is a lazy chunk, imported only when the detail has `identified_as`; the API omits the field when there is nothing to show (hidden, held, private or Adult torrents, no answer, no visible source), so then the chunk is never requested.
- **Plain text with bidi isolation.** Every text (canonical and alternative titles, genres, ids, the source's name) is rendered as text, never markup. Each goes through `showBidi` (direction controls made visible) and sits in a `<bdi>`, so stored text cannot reorder what is around it. An alternative title's `lang` is set only when it looks like a BCP 47 tag; `und` and anything else are left off.
- **A null `resolved_via` is never "from the name".** The section shows a "Resolved via files/folder/structure" line only when the value is set, and nothing about the origin otherwise (it can be a plugin or an unreadable record; `chosen` marks a plugin's title). With no answers and a null `resolved_via` the section does not render at all. Two plugins that disagree are both shown, in the order the API sent (surest first).
- **`Interest::opened` needs no web call.** The API already offers the torrent's id to the runtime on the detail GET (`DrawerInterest`, rate-limited per client and overall, `crates/api/src/torrents.rs`); a second request from the drawer would only add a path around that limit. What is left is on the Rust side: `crates/lodestar` does not yet mount `DrawerInterest` on the router (`router(state).layer(Extension(interest))`). That is outside this slice and already tracked as X-always-adult-detail-mask (runner, 2026-11-12).
- **Messages** are in `detail/identified/messages/{en,zh}.json`, keys `detail_identified_*` (the part-folder rule, as for the adult and provenance sections); "Resolved via" reuses `detail_resolved_via`.
- **Size** (the ENR-8 pattern). New on-demand entry "Detail identified-as section (on demand)" (measured 1,610 B, limit 1,800 B); the chunk is left out of "Detail sections (on demand)" and of the two first views via `detailLazy`. The one dynamic import in `DetailView.svelte` costs the first views what ENR-8's did: Detail drawer 28,064 B limit, measured +48 B over; `/t/[hash]` 21,904 B limit, measured +26 B over. **No existing limit was raised in this PR; that is the runner's call (§2.26).**
