# PK-guide-1 decisions

Ports what is still missing from `release/v0.5.1`'s user guide into `main`'s newer guide, and cleans up after PK-unraid (#680). Brief: runner, 2026-11-11.

- **Almost nothing was unported:** one sentence was, the Docker health-check caveat in 2.4 (`healthy` means only that the process is alive; the status pill shows whether torrents are found), which is ported. #574 already carried the v0.5.1 first-hours wording to `main`: the note in 2.5, the 6-hour sampling wait in 3.5 and 5.3, the "Starting" status-pill row, the troubleshooting row, and a README that names the published release. All of that was already on `main`. `main`'s guide is ahead of the release branch everywhere else (Windows chapters, 6.2, the Legal Notice, newer PNGs), so none of that was touched.
- **What was missing is "when full speed starts"** (plan Q12, `docs/plan/2026-11-06-m6-gap-audit.md`): sections 2.5, 3.5, 5.3 and the 6.1 row now say "Full speed starts after those 6 hours."
- **Q12's second sentence is not used.** "With safe restart on, later clean restarts skip the wait" describes a development build. The guide covers the published v0.5.1, whose chapters 3.5 and 6.1 say the safe-restart switch isn't available, and documenting it here would present an unreleased feature as built. PK-ui uses the full wording on `main` for v0.5.2; this guide takes it when the guide moves to that release.
- **Appendix B no longer lists Hot path and Cold path,** so it matches chapter 2 after #680.
- **`revisions.md` gets 2.6 (#680) and 2.7 (this change).** `docs/decisions/2026-11-11-PK-unraid.md`'s heading now carries `(#680)`.
- **The v0.5.1 template still shows Hot path and Cold path (runner's call, 2026-11-11):** 2.2 says to leave both empty, because Lodestar doesn't use them and a later template removes them. The question below was answered this way.
- **Question that led to it:** the guide covers the published v0.5.1, whose Unraid template (the one 2.1 tells users to download) still shows Hot path and Cold path in Advanced View. Chapter 2 and Appendix B now say no other folder is needed, as the runner asked, so a v0.5.1 user sees two fields the guide doesn't mention. Their descriptions say they are unused and to leave them empty. A one-line note in 2.2 would close the gap if the runner wants it.
- **Not touched:** `docs/operations.md` (PK-ops), `docs/architecture.md`, `runner/`, Rust, and the CI job for `validate.py`; the runner tracks those. `docs/setup.facts.md` is generated from the v0.5.1 tag and stays as it is.
- **Checks:** `docs_tool.py sync` and `sync --check` (up to date), `lint_docs.py --strict` (0 failed, 0 warnings).
