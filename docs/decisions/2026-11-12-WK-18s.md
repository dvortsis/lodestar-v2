# WK-18s decisions

The crates half of the Windows "Join an existing Lodestar as a worker" install (runner's split of WK-18w, 2026-11-12). Affects architecture §11 (the Windows service) and §19.6 (joining).

- **`lodestar worker --join <url> --token-file <file> --join-only` joins, saves the credentials and exits 0, without running the worker.** It needs `--token-file` (clap `requires`), so it never takes `LODESTAR_TOKEN`, and it can't be combined with `--rotate-key`. On a folder that has already joined it refuses (exit 3, "refused") before reading the token or opening the key: only `cluster/credentials` existing counts, and the worker is named only if its credentials can be read. The message never holds a token. The MSI's one-shot join (WK-18w) uses it. Without it, `--join` always goes on to run the worker, so a bounded join could only time out.
- **Plain `lodestar worker` is a Windows service command line.** `service_command` now returns a `ServiceCommand { config, role }`, with role `Serve` or `Worker`. It is `Worker` only when no other flag is given: a service never joins (a token file would join again on every start), never rotates the key, and keeps the default folder, which the service's start-up ACL check secures. The SCM path loads the config, checks the data folder and starts logging exactly as for `serve` (the folder defaults to `%ProgramData%\Lodestar`), then runs the worker until Stop, Shutdown or Preshutdown resolves its stop. An error ends it with code 1, so the recovery actions restart it, as for `serve`. Restart now, the restart ledger and the store don't apply to a worker.
- **An ordinary console `lodestar worker` run starts as before.** The Windows hook returns at once for it, without the serve-only start-up work (priority, port check).
- **A worker service's stop is bounded.** The worker's runtime ends with `shutdown_timeout(RUNTIME_GRACE)`, as `serve`'s does, so a stuck blocking task can't hold a Stop or a shutdown without limit. Console runs get the same.
- **Why a worker service stopped is kept.** The final error, which says what to do and never holds a token, is appended to `%SystemRoot%\Temp\lodestar-service.log` (Administrators only), where a refused start's reason goes. `SERVICE_FAILED` names the kind `worker`.
- **Who makes the worker's files readable by the service: WK-18w.** `--join-only` runs as SYSTEM, so `secrets.key` (OWNER RIGHTS, SYSTEM and Administrators only, `integrations/src/secret.rs`) is SYSTEM's. The installer hands the key and `cluster\` to `NT SERVICE\Lodestar` with `icacls /setowner` after the join. It runs `SecureDataFolder` before the join, because `--join-only` doesn't check the folder's ACL itself.
- **Open (follow-up WK-18s-win-tests):** cfg(windows) tests. These are a registered `worker` service (start, then Stop ends it with 0; an unjoined folder ends it with 1) and `--join-only` end to end against `worker_join.rs`'s coordinator. The worker service also doesn't run the serve-only `startup` (below-normal priority, port check): decide whether it should.
- **Follow-up (X-worker-service-log):** under the SCM, the worker's progress lines (joined, connecting, revoked, …) are dropped, because the structured log has no free-text field by design. The service's own start, stop and failure events are logged. Each worker line needs a typed event in `logging/events.rs`.
