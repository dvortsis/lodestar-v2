# ENR-igdb decisions (IGDB parser and plugin, Account, Twitch credentials)

Slice ENR-igdb (API lane brief, 2026-11-16). Spec: `runner/slices.yaml` (ENR-igdb: §18.2, §18.7; notes "/security-review (OAuth client-credentials token kept in SecretStore)"), and the TMDB plugin's pattern (ENR-tmdb, #948, `docs/decisions/2026-11-15-ENR-tmdb.md`).

## Terms (ENR-terms)
- **Source of the terms:** the IGDB API documentation (`https://api-docs.igdb.com`) and the Twitch Developer Services Agreement it sits under, as the slice brief summarises them. They weren't re-read live in this slice. **Before the plugin is switched on**, the slice that does it re-reads both and adjusts `igdb::TERMS` if they changed.
- **`background_walk: false`.** The licence covers lookups for your own app, with a rate limit (4 requests a second, at most 8 open). Nothing allows bulk use, so it looks up only the items you open.
- **`redistribute: false`.** The Developer Services Agreement doesn't allow passing on IGDB's data to third parties. The answers stay in Lodestar's own UI and never rename the record that search, Torznab and export serve.
- **`retention: Retention::DEFAULT`** (180 days). IGDB sets no shorter limit that we know of. The default refreshes a claim after 150 days and drops it at 179.
- **`attribution`: "Game data from IGDB.com.", linking `https://www.igdb.com`.** IGDB asks apps to credit it with a link. `logo: None`: no logo is required, and none is bundled. As with TMDB, no manifest or UI field shows the attribution yet; the slice that registers enrichment plugins has to show it.
- **`adult_marker_required: false`, `adult: Some(true)` for the Erotic theme.** IGDB marks adult games only by their themes: theme id 42 is "Erotic". It has no "not adult" marker, and it leaves out the `themes` key when a game has none, which most games do. Requiring the marker would refuse almost every answer, so the plugin opts out, as Open Library does. The search asks for `themes`. A game with theme 42 gets `adult: Some(true)`, which the terms (and the runtime) always refuse. Any other game gets `None`, never `Some(false)`, because the absence of a theme isn't a statement that a game is safe.
- **An Erotic game isn't passed over in `choose`.** It takes part in the match like any other, so a tie with a same-titled clean game is no match. If it was filtered out, a clean game could stand in for an adult torrent. When it's the one match, the answer is marked adult and refused.

## Account class, Twitch credentials
- **The manifest:** `igdb`, an Enrichment source, Consent `Account`, endpoints `https://api.igdb.com` and `https://id.twitch.tv` only, off by default, risk Low, never always-adult, never finds private.
- **Two credentials, both Secret (masked):** `client_id` ("Twitch Client ID") and `client_secret` ("Twitch Client secret"). Both are read on each lookup, before either is checked, so a lookup reads exactly what the policy declares (`credential_spec.rs`). Each must be 1–128 ASCII letters and digits (Twitch's are 30), checked before it goes into a header or a form.
- **The app access token** (OAuth client credentials): `POST https://id.twitch.tv/oauth2/token` with `client_id`, `client_secret` and `grant_type=client_credentials` in an `application/x-www-form-urlencoded` body, never in the URL, where proxies and logs could keep it. The answer is parsed by `igdb::parse_token`: a whole JSON object with a header-safe `access_token` (1–512 bytes of letters, digits, `-`, `_`, `.`), a positive `expires_in` (capped at 90 days) and, if present, `token_type` `bearer`. Anything else is "Twitch's token answer wasn't understood".
- **Where the token lives:** only in the plugin's memory, as a `Secret` (zeroed on drop), with the Client ID it was issued for and a renewal time 5 minutes before Twitch's expiry. It is never written to the credential store, a log, a fixture, the config, an error or Debug output (`Igdb`'s and `parse_token`'s `Token`'s Debug are redacted). The brief allowed the SecretStore or memory: memory is enough, since a new token costs one request after a restart, and nothing has to be purged when the source is. **Changing the Client ID** makes the held token unusable at once; changing only the secret takes effect at the next renewal or 401.
- **Refresh on 401, once, never loops.** A 401 or 403 from IGDB drops the held token and fails the lookup ("IGDB refused the access token"). The host limiter then holds `api.igdb.com`. While it's held, a lookup returns "on hold" before sending anything, including a token request. After the hold, the next lookup asks Twitch once for a new token and searches once. A lookup sends at most one token request and one search. A 400, 401 or 403 from Twitch is "Twitch refused the Client ID or secret".

## What is sent
- **The search, from a fixed Apicalypse template:** `POST https://api.igdb.com/v4/games`, body `search "<title>"; fields name,first_release_date,themes,genres; limit 20;`, headers `Accept`, `Content-Type: text/plain`, `Client-ID` and `Authorization: Bearer <token>` only.
- **The title is one string literal** (`igdb::literal`): control characters dropped, `\` and `"` escaped, at most 255 bytes before escaping, cut on a character boundary. A title can't close the literal or add a clause (`a_hostile_title_is_one_literal`).
- **The year isn't sent.** The match still requires it locally when the query has one. **The kind** is the endpoint (games). Nothing else leaves: never the hash, the torrent's name or its files. `igdb::SENDS` says so for the Sources row.
- **Kinds: Game only.** Any other kind, or a title that folds to nothing, sends nothing and reads no credential.
- **Rate:** at most one request a second per host, no burst (`HostRate::per_second(1)`), a 1 s `min_interval` between lookups, back-off from 60 s to 6 h after a 401, 403, 429 or 5xx. IGDB allows 4 a second.
- **No redirects:** a 3xx is "the request failed" (the plugin sends through `Client::send`, which never follows one).

## The parser (`sources-feeds/src/igdb.rs`)
- **On the shared bounded JSON reader,** TMDB's shape: pure, no I/O, no panics.
- **Caps (`LIMITS`):** 256 KiB (twenty games with four short fields is a few KiB), depth 8 (a game's deepest part is `themes`, depth 3), 50,000 values, 1,000 elements per array, 4 KiB per decoded string, 20 games (the request's `limit 20`; more stops the parse), 32 theme ids and 32 genre ids per game (IGDB has 23 genres and 22 themes). Token answers (`TOKEN_LIMITS`): 8 KiB, depth 4, 64 values.
- **Strict shape:** whole only when the root is an array read to its end with nothing skipped. An object at the root (IGDB's `{"message": …}`), or an item with no positive integer id (its `[{"title": …, "status": 400}]` errors), is never whole. In a game, an escaped or repeated read key, a wrong type, an id that isn't plain digits, a `first_release_date` that isn't an integer of Unix seconds in years 1–9999 (UTC), or a theme or genre id that isn't a `u32` spoils it.
- **What it keeps:** id, `name` (cleaned by the shared title rule), the UTC year of `first_release_date`, theme ids, genre ids.

## Choosing a match (`igdb::choose`)
- **One game must agree:** its name equal to the query's after folding (TMDB's `fold`), and the query's year when it has one. None, or more than one, is no match.
- **Confidence:** 90 with a year, 70 without.
- **The answer:** `igdb:<id>` (a scheme the store already accepts, 1–20 digits), the name as the canonical title, genres by name from IGDB's fixed genre list (`igdb::genre`), so no answer text becomes a genre, and the year. No alternative titles (IGDB's `alternative_names` would be a second expanded field; left for later).

## Fixtures and tests
- **Hand-written and synthetic** (`crates/sources-plugins/fixtures/igdb/README.md`), with made-up credentials (`testclientid0`, `testclientsecret0`) and token (`faketoken0000igdb`). **Carried forward:** the slice that switches the plugin on records real answers (credentials and token stripped) and fixes the parser for any shape difference.
- **Parser:** golden shapes, strictness and caps in `crates/sources-feeds/tests/igdb.rs`, property tests over random bytes and shaped games, and the `igdb` fuzz target (`fuzz/fuzz_targets/igdb.rs`; first byte bit 0 picks tight caps).
