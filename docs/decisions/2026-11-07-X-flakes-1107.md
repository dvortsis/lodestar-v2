# X-flakes-1107 decisions (#590)

Two e2e timing flakes (2026-11-07Z).

Test-only. No product code changes, no owner decision touched.

## `shell.routes.test.ts`: "a server that never answers shows the unreachable page, and Try again reloads"
- **Cause:** the test unrouted the dead API before clicking Try again. The page's own retries (probe, REST) could then succeed first and remove the button, so the click waited on a button that was gone.
- **Fix:** the API stays dead until the reload's navigation request goes out (Try again is `location.reload()`). A flag flipped by that request lets the new document through. The test asserts nothing recovered before the click, then that Search shows after it. It still proves Try again reloads.

## `filters-block.keyboard.test.ts`: "from a result: Shift+F10, Block this…, preview, Apply adds one rule"
- **Cause:** the menu item is visible before Bits UI moves focus into the menu. `End` pressed in that gap goes to the row and is lost. Once focus is in the menu it is not dropped, so this is a test race, not a product bug.
- **Fix:** wait for the menu itself to hold focus, then press `End`.

`--repeat-each=50 --workers=4` per test with four busy loops running: 50/50 passed each (details in the PR).
