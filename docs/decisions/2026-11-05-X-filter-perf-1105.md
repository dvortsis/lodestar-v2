# X-filter-perf-1105 decisions

Runner brief X-filter-perf-1105, 2026-11-05T08:58Z: win back filter-budget headroom after RP-UC (#469), without changing any verdict. The owner's 50 µs per torrent at 10,000 rules (§1.6.6, architecture §20.8), the EPYC 7763 reference, every held case and every gate constant in `crates/filter/tests/props.rs` are unchanged.

## How it was measured
- **Instruction counts first.** The `profile` test under callgrind (`docs/decisions/2026-10-23-F-perf.md`), because wall time on a shared 4-core host moves ±10% between runs. Cache and branch simulation (`--cache-sim=yes --branch-sim=yes`) were used too, so a change that saves instructions but costs misses would show.
- **`profile` takes the shapes now.** `LODESTAR_PROFILE` also accepts `near`, `negation`, `fuzzy`, `prefix` and `title`, the 10% sets of each [`Shape`]. The brief's Fuzzy target couldn't be profiled before. This is measurement only: the budget test, its cases and its limits are untouched.
- **Then wall time,** before and after on the same machine, alternating binaries (table below).

## Where the time was (mixed set, before)
Per torrent judged, as a share of instructions:
- the torrent's keys (`DocKeys::with_near`, the byte scan): 40%;
- the rule narrowing (`RuleList::candidates`, including the cheap checks): 24%;
- the core's tokenizer (`Core::patterns`): 20%;
- the packs (`Ctx::matches`): 8%, of which UC-3's allow-list check (`allowed`) was 3.2%;
- the enrichment (`Record::new` and `DocEnrichment::new`): 4.6%;
- allocation: about 9% of instructions overall, from about 700 vector growths per torrent.

The 10% Fuzzy set adds the full fuzzy match. 12% of its instructions were the scan of the vocabulary's lengths in `DocKeys::vocabulary_near`, and more than half of that scan was `u64::count_ones`. The build targets baseline x86-64, which has no `POPCNT` instruction, so `count_ones` compiles to a dozen-instruction sequence.

## What changed
Each change keeps every answer identical. Where the code is rewritten rather than reordered, a property test checks the new form against the old one.
- **UC-3's allow list reads the title once** (`packs/unauthorised_copy.rs`). The old code split and lowercased the title again for each of the 38 entries. Now it builds the title's key once (words lowercased per character, one space apart) and compares it with each entry whole. It stops as soon as the key is longer than the longest entry.
  - **The proof:** the old function is kept in the tests. A proptest (Unicode titles, separators, `İ` and `Σ`) and every entry under seven spellings and three years compare the two.
- **Fuzzy words test their character bound in a row** (`prefilter.rs`). `by_chars` now keeps each entry's characters (`has`) beside its order. `vocabulary_near` filters on that contiguous list and reads an entry only when it passes.
  - The "at most `2 × distance` differing characters" test clears the lowest bit `n` times (`bits_at_most`) instead of calling `count_ones`, as `FuzzyGate::could` already did.
  - A proptest checks `bits_at_most` against `count_ones` for every `n` from 0 to 69.
- **The fuzzy gate's length windows** (`DocKeys::length_windows`) are built from the narrow window either side, not by folding each one. A proptest checks them against the fold for random tables.
- **The packs compare file extensions without a library call** (`packs/mod.rs`, `Ctx::with_ext`, and `Ext::as_bytes` in `classify/src/ext.rs`). They compare bytes in line rather than validating UTF-8 per file and per set. Only lowercase ASCII is ever stored, so the answer is the same. `Ctx::new` sizes its file list once.
  - **Which part of `packs/mod.rs`:** only `Ctx::new` and the `with_ext` helper. No rule's definition in `Ctx::matches` changed (RP-1b owns those).
- **Tags without `format!`** (`search/src/doc.rs`, `DocEnrichment::new`). Each `key:value` tag is built in a sized string, the value lowercased in place when it's ASCII. Otherwise it's lowercased with `str::to_lowercase` as before, so a final sigma still reads `ς`. Search builds its documents the same way, so its tags are unchanged.
- **Fewer allocations:**
  - `Record::new` sizes its field list once;
  - `sorted_starts` reserves the vocabulary's length;
  - `classify::crack::words` (`junk::words`) lowercases an ASCII word with `to_ascii_lowercase`, which is the same string as `to_lowercase` for ASCII.

## Tried and not kept
- **A bit set for the char pairs** (520 bytes, not 4 KiB). It saved the clear but cost more in the fuzzy gate's reads, which are the hot side. Valgrind also counts a `rep stosb` clear byte by byte, which overstates what the clear costs on hardware.

## Ownership
The brief owns `engine.rs`, `load.rs`, `unauthorised_copy.rs`, `classify/src/**` and the bench. The profile showed the headroom in `prefilter.rs` (the keys and narrowing, 64%), plus small pieces in two other files:
- `packs/mod.rs`, `Ctx::new` and `with_ext` only, not rule definitions;
- `search/src/doc.rs`, `DocEnrichment::new`'s tag building.

No open PR touched any of these when this was written (checked against #460, #472, #473 and #478 to #482). The runner was told before the work went past the brief's list. `engine.rs` and `load.rs` needed no change.
