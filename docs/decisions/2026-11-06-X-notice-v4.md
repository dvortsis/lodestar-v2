# X-notice-v4 decisions (#546)

**`main`'s Legal Notice goes to version 4** (runner, 2026-11-06, §2.33; flagged to the owner under §2.19). R-rc5-notice (#540) raised the release branch's notice to version 3 for v0.5.1, so `main`, whose notice was also at 3, would have shown a v0.5.1 install nothing on upgrade although its text differs. The follow-up the runner asked for: the constant, the version line, and the stale OpenAPI example with its regenerated files. No wording changes.

- **`crates/api/src/legal.rs`:** `NOTICE_VERSION` 3 → 4. **`docs/legal/legal-notice.md`** and the identical **`crates/api/src/legal/notice.md`:** the heading reads "Version 4 · 2026-11-06", and the "Applies to" line says the v0.5.1 release carries version 3 (it said version 2, which rc.5 superseded). Nothing else in the notice changes.
- **The OpenAPI example** (`crates/api/src/dto/auth.rs`, `LegalNotice`) read "Version 3 · 2026-11-05" and `"version": 3`; it now matches the constant. `web/src/lib/api/openapi.json` and `schema.d.ts` are regenerated (`cargo run -p lodestar --bin openapi`, `npm run api:types`), four lines each.
- **Tests follow the constant:** `auth.rs` `a_v0_5_1_install_sees_version_4_once` (a store with `notice_version: 3` sees 4 once, a stale accept of 3 is refused, accepting 4 records 4) and `tests/legal.rs` `a_v0_5_1_install_sees_the_new_notice_once_at_login` (the same through the gate). The three e2e specs that posted or served version 3 (`auth.routes`, `auth.keyboard`, `docs/shots.docs`) now read it from the new `web/e2e/support/notice.ts`, which takes the `LegalNotice` example out of `openapi.json`, the same source the generated mock's default comes from, so the next raise can't leave a spec behind.
- **Why no text change:** the owner's corrections landed in #534 at version 3 on `main`; this PR changes a number, not substance, and exists only so that `main` stays above every number a build has shown. A v0.5.2-dev install that accepted 3 sees the notice once more; no released install has accepted 3 from `main`.
- **Cross-references, not wording:** `docs/legal/operator-guidance.md`'s status line names version 4, and `docs/releases/v0.5.2.md`'s notice bullet says v4, since v0.5.2 is built from `main`. `legal.rs`'s module doc names this raise as the sanctioned exception to "substance only".
- **Dashboard:** this PR's placement rule only (`X-notice-v4`, beside `X-legal-docs-r2`).
- **Gates:** `cargo test -p lodestar-api` (`legal::`, `auth::`, `tests/legal.rs`), `cargo fmt --check`, the openapi drift job's own command, prettier on the two e2e files, `tools/status-connector` `npm test`.
