# X-hidden-count decisions

Slice `X-hidden-count`, the rest of P7 from the UI review of 2026-11-13 (`docs/review/2026-11-13-ui-ux/01-review.md` P7, `02-skills-pass…md:66`): "2,196 results", "2,208 torrents" and "2.2K" appeared together on Search with nothing saying what each counts. The runner decided A–C at step 0 (§2.26) and flags them to the owner (§2.19).

## What each count was
- **"2,196 results"** (toolbar): `GET /search` `total`, the matches after the default exclusions (filter-hidden, unverified, and Adult while it's hidden). Correct; unchanged.
- **"2,208 torrents"** ("Index still growing" banner, Home's "Search … torrents"): `GET /search/state` `searchable_torrents`, the serving index's `num_docs`, so every indexed torrent, the hidden ones included. The same figure as Insights' "Searchable torrents".
- **"2.2K"** (status pill, "Idle · 2.2K torrents"): the `crawler` event's `torrents`, rows in the store (`Pipeline::torrents()`), which also holds what the index hasn't committed yet. A third figure, close to the other two but not equal.

## Decisions
- **A (runner): "N hidden · Show" is built here.** X-search-toolbar (#1075) deferred it (its decisions file): `/search` had no hidden count, so the 12-torrent gap between results and searchable had nothing to explain it.
  - **`hidden_total` on `GET /search`:** the matches a filter rule hid, which `hidden=true` would add to `total`. First page only (`offset` 0, no cursor); null on cursor and offset pages, with `hidden=true`, when the query names `hidden` itself, when the count runs out of the shared recovery budget (`RECOVERY_BUDGET`, 20 ms) or when it would be an estimate.
  - **It counts exactly what "Show" brings back (runner; content safety, §20.9, §2.12).** The count runs `base_query` with `hidden: true` under the request's own Adult visibility and verified default, ANDed with `hidden:yes`. So it never counts Adult while Adult is hidden, and it doesn't count unverified torrents: "Show" (`hidden=true`) doesn't bring those back ("Show unverified" does, §18.6). The runner's step-0 wording named unverified torrents too; counting them would have broken its own rule that the count match what "Show" adds, so they're left out. Quarantined and dropped torrents are never in the index, so they're never counted; a torrent a held write deletes drops out of the count at the next commit, as it drops out of `total`. Tested in `adult_visibility.rs` (an Adult and a film both filter-hidden, Adult hidden: count 1, and `hidden=true` adds exactly that one; Adult shown: 2).
  - **Cost.** One more count on the page's own lease (the same searcher, the AST already parsed, `recovery::totals_on`), measured on the bench corpus (see the PR).
  - **The toolbar** shows "2,196 results · 12 hidden · Show" when `hidden_total` is above 0, and nothing extra for 0 or null. "Show" sets `hidden=true` (`search.setHidden`), so Back undoes it. The button's accessible name is "Show", described by "12 hidden". Under a coarse pointer its 44 px target is padding taken back by a negative margin, so the count line keeps its height. The results store keeps the first page's count through "Load more" and drops it with the query.
- **B (runner): the status pill counts searchable torrents.** `CrawlerEvent` gains `searchable` (the serving index's `num_docs`, as `/stats`'s `searchable_torrents`; null with search off); `torrents` stays for other readers. The pill reads "Idle · 2.2K searchable" and shows no count while it's unknown (before: "— torrents"). `PillState.torrents` is renamed `searchable`.
- **The banner and Home say "searchable" (runner).** "Index still growing: 2,208 searchable." (the line X-search-toolbar shortened to fit one line at 360–390 px stays as short: "searchable" replaces "torrents"), "2,208 searchable torrents so far." and "Search 2,208 searchable torrents".
- **Two figures, each labelled.** Searchable (the index, the pill, the banner, Home, Insights) and results (the toolbar), with the hidden ones that separate them counted beside the results.
- **Glossary.** `searchable` and `hidden_by_filters` say where each count shows and how they relate (`docs/ui-glossary.md`).
- **zh strings are machine-drafted** (`个可搜索`, `个已隐藏`, `显示`), for the translator (W4) to confirm, like the glossary's zh column.
