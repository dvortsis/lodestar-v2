# FX-4: Settings form and copy (M5 design review)

Runner, 2026-11-01. Findings B6, B7, I3, I5, I8, P2, P3, P11.

- **Where the strings live.** The brief names `web/messages/*.json`, which only exist as a merged build output; the sources are the per-feature files. FX-4 edited `features/settings/messages/{en,zh}.json` and `features/insights/messages/{en,zh}.json`.
- **B6.** Added `settings_<section>_<field>_option_<value>` (en + zh) for every enum a generated screen renders: `crawler.encryption`, `crawler.intensity` (settings and wizard), `notifications.email_security`, `insights.digest`, `insights.digest_day`, `logging.console_level`, `logging.file_level`. Message maps regenerated. New `form/enum-options.test.ts` reads the golden settings index and fails when any enum outside the hand-built screens (crawler intensity, Updates, Appearance, Logging) lacks an option message in en or zh. Existing unit and e2e tests that used the raw value now use the label.
- **B7.** "hashes" → "keys" in the Insights harvested strings (also the discovery-cohort and by-source help and the "reported" chart label); Trackers help and DHT-scrape help say "seeders and leechers".
- **I3.** Locked text, number and JSON fields are `readonly` in `text-base-content`, not `disabled`; the value stays selectable. A locked slider shows its value as the readonly number only.
- **I5.** The Appearance segmented controls are `self-start`, so they are as wide as their segments.
- **I8.** Appearance `<h1>` is `text-title`; its section `<h2>`s step down to `text-body-lg` to match the other screens. The Backup description is `text-body`. Every other Settings `<h1>` was already `title`. About keeps its visually hidden `<h1>` (its version `<h2>` is the display moment). Keyboard goes with FX-3.
- **P2.** The stage-strip hint drops "(≈)", leaving it on the number. The chart label keeps it, since it labels a chart, not a number.
- **P3.** `insights_overview_updated` is "Updated" (the relative time follows it).
- **P11.** `scripts/bans.mjs` rejects Tailwind default size classes (`text-xs … text-9xl`, `text-h1…h6` and similar). **Deviation:** `text-label` is used in 27 files and is not a token either (it renders unstyled, as `text-h2` did), but banning it now would fail CI in files other batches own. Left allowed; reported to the runner. The ban also scans `.css` for text sizes only; `.css` spacing is off the ramp in `appearance/editor.css` and `shortcuts/shortcuts.css`, so that is left for a follow-up.
- **Coarse-pointer copies** in `SettingsShell.svelte` and `SaveBar.svelte` stay: FX-2 had not merged to `main`.
- **Size limit (runner ruling, §2.26).** "Settings logging messages (on demand)" rises from 0.95 KB to 1.05 KB for the logging console and file level option labels (measured 1.03 KB).
- **Snapshots.** `web/e2e/.update-snapshots` is added for the Settings smoke images and the insights paused/starting states (B7 copy); remove it in the next push after CI's baseline commit.
