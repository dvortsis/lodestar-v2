# SRC-7 decisions (#395; Prowlarr/Jackett plugin #1, recorded-fixture contract tests)

Slice SRC-7 of `docs/plan/2026-11-01-v06-sources.md`. It covers architecture §18.2 (rank 1), §18.7 and §18.9, and owner decisions §2.28 Q2 and Q15. The code is the new crate `crates/sources-plugins`: `src/prowlarr.rs`, its fixtures and contract tests, and `README.md`, the pattern later plugins copy.

## Q2: the ToS and API check
- **Prowlarr and Jackett: automated API access is allowed.** Both are open-source programs (GPL-3.0) that the user installs and runs themselves, and both exist to be polled by other programs:
  - **Prowlarr** documents its REST API (`/api/v1`, API-key authenticated, an OpenAPI spec in the project) and its per-indexer Torznab/Newznab endpoints, which Sonarr, Radarr and the other *arr apps poll on a schedule.
  - **Jackett** documents its Torznab API (`/api/v2.0/indexers/<id>/results/torznab/api`) in its README, as the way Sonarr, Radarr and torrent clients use it.
  - There is no hosted service and no terms of service between the user and either project. The only access control is the instance's own API key, which the user gives Lodestar.
- **Indexer terms stay the user's choice.**
  - Lodestar polls only the indexers the user has added **and enabled** in their manager. Disabled indexers, Usenet indexers and Jackett's `all` aggregate are never polled.
  - Every request goes through the manager, which applies its own per-indexer limits, and Lodestar asks for one RSS page per indexer at most every 15 minutes. That is the rate Sonarr's default RSS sync already uses.
  - Finds from private and semi-private indexers stay on this server (below). Whether a tracker allows a tool like this is for the user to judge, as it is for Sonarr. SRC-15b's consent text (Account, drafted in SRC-4) says so.
- **No grey case** came up, so nothing goes to the owner under Q2.

## The plugin
- **Torznab XML, not Prowlarr's `/api/v1/search` JSON.** Both managers speak Torznab, so one code path covers both. SRC-6's parser is already bounded, fuzzed and tested on their shapes. The JSON search is Prowlarr's alone and would need a second untrusted-input parser.
- **Each poll:**
  1. lists the indexers: Prowlarr's `GET /api/v1/indexer` (JSON), or Jackett's `t=indexers&configured=true` (XML);
  2. asks each enabled BitTorrent indexer for `t=search&extended=1&limit=100` with no query. That is the RSS view, the newest releases;
  3. maps each item to a key with claims (below).
- **Units and caps** (Q4, runner): the list is the unit `indexers`, and each indexer is `indexer/<id>`. Each is polled at most every 15 minutes, through `Client::poll`.
  - **Per host:** one request every 2 s with a burst of 2, so a long list doesn't bunch up on the manager. Every indexer shares one host.
  - **Back-off:** 60 s up to 6 h.
  - These are performance numbers, the runner's call under §2.26.
- **Agents (§18.4): indexers queried at once,** 1–8, default 2. They're workers in a `JoinSet` that is dropped on shutdown or on the first refusal, so shutdown is prompt.
- **Distribution:** `ShardedUnit` (§19.5's "Prowlarr per indexer").
- **API key placement.** Prowlarr's key goes in the `X-Api-Key` header, never a URL. Jackett's Torznab API reads it only from the `apikey` query parameter, so it goes there. The plugin never puts a URL, a header or the server's text in an error or a log line.
- **A refused key stops the plugin with an error** ("the indexer manager refused the API key") rather than knocking every 15 minutes. That covers a 401 or 403, and a Torznab error 100–102 (bad key, suspended account, insufficient rights). Other failures (5xx, a transport error, a malformed list) skip that unit until its next poll, and the limiter's back-off applies.
- **The key is checked before use:** 1–128 ASCII letters, digits, `-` and `_`, so it can't inject a header or a query parameter. Both managers issue 32 hex digits.
- **Usenet indexers are skipped** until the `usenet` tier lands (v0.7). So are Prowlarr indexers marked `supportsRss: false`: an empty search returns nothing from them.
- **A redirect on the list stops the plugin with "needs setup".** Redirects are never followed (SRC-0), so one means the address is wrong (`http` for `https`, or a missing base path). Silently failing every 15 minutes would hide that.
- **Known limitation: one indexer's 429 blocks the whole manager.** Prowlarr answers 429 with `Retry-After` when an indexer reaches its query limit or is in Prowlarr's own failure back-off. The limiter treats that as the host blocking us (`http::classify`), and every indexer shares the manager's host, so all of them wait until `Retry-After` passes (at most 24 h). Repeated 5xx from one broken indexer likewise raise the shared host back-off. Nothing is lost: the next poll after the block catches up on each RSS page. The fix is a block scoped to the poll unit in `crates/sources/src/http.rs`, which SRC-14a owns. The runner has been told.

## Settings and credentials
- **Settings:** `{"url", "manager": "prowlarr"|"jackett", "agents"}`. Unknown fields are refused.
  - The address must be http(s) with a host. It may not carry a user name, password, query or fragment.
  - It must pass the SSRF guard's download-client policy: LAN and loopback are allowed (the manager is usually a companion on this machine or the LAN, §18.10), but link-local and metadata addresses never are. A path is kept, for a reverse-proxy prefix.
- **`api_key` is a credential, not a setting.** The schema marks it `writeOnly`, and `Config::from_json` refuses it, so a plaintext key can't land in the settings. The plugin reads it once at start through the new `Credentials` trait. `SourceCredentials` (SRC-4) implements that trait on the blocking pool, and `StaticCredentials` serves the tests.
- **Endpoints.** The manifest lists none: there's no built-in host. `Prowlarr::endpoints()` gives SRC-5's egress the user's host only, under the download-client policy, and `None` until it's set up.
  - **Follow-up for SRC-15b:** the consent text's `{hosts}` should show the configured address.
- **Not done here (SRC-4's follow-up):** making Account's condition require the schema's `writeOnly` + `required` names. That's `crates/sources/src/consent.rs`, outside this slice. Any stored non-SOCKS credential still counts. The plugin is safe either way: with no `api_key` it fails at start with "needs setup".

## Indexer lists (untrusted input)
- **Both parsers:**
  - cap the body at 8 MiB, keep at most 500 indexers and drop duplicate ids;
  - accept only ids of 1–64 ASCII letters, digits, `-` and `_`, so an id is safe in a URL path (no `..`, `/` or `?`);
  - **treat any privacy value they don't recognise as private.**
- **Prowlarr's JSON** goes through serde with four fields kept (`id`, `enable`, `protocol`, `privacy`). Everything else is skipped with `IgnoredAny`, and serde_json skips values without recursion, so deep nesting can't overflow the stack. A value of the wrong type or a duplicate key refuses the whole list (fail closed). `privacy` must be exactly `public` to count as public. `private`, `semiPrivate`, missing and anything else are private.
- **Jackett's XML** goes through a small quick-xml reader:
  - a DTD is refused, nesting is capped at 16, elements at 500,000 and attributes at 16 per element;
  - the root must be `indexers` and appear once;
  - only `id`, `configured` and the first `type` text are read, compared as raw text. An entity or CDATA in them leaves the id invalid or the type unrecognised (so private), and nothing is expanded;
  - `configured` must be `true`;
  - Jackett's `all` (its aggregate of every indexer, which would hide each one's privacy) is never polled;
  - a root `<error code="100–102">` is a refused key.

## Claims, not verified metadata
- **Every item is an unverified claim** through SRC-2's pipeline. The key comes from SRC-6's parser: the `infohash` attribute or a magnet's `xt`, never a link.
  - **Claims:** the title, the size (1 B to 1 PiB, otherwise dropped) and the IMDb, TMDB and TVDB ids.
  - **Provenance:** the publish date (from 2001-07-02, BitTorrent's release, to a day past now, otherwise dropped) and confidence `Low`.
  - **Not claimed:** seeders and peers (the pipeline counts swarms itself, §18.7), categories, tags and the volume factors. Nothing names an uploader.
- **The item's `link` is never kept.** It's the manager's own download URL, holding the user's host and often the key.
- **The `guid` is a public find's external reference,** with SRC-6's credential stripping. It's dropped when it points at the manager's own host, or when it's the same URL as the `link`.
- **Private finds (Q15):** an indexer the manager calls anything but public makes its finds `private_source`, with **claims only and no external reference**. A private tracker's URLs can hold passkeys in the path, which SRC-6's stripping can't tell apart.
  - **This plugin never downloads a `.torrent`,** from any indexer. Q15's "fetch on explicit interest" is a later slice's (SRC-13 or SRC-14), through the private indexer, rate-limited and with the snatch warning.
  - **Keeping these finds out of Torznab, Stremio, exports and public peer finding** is enforced downstream on `private_source` (§18.7, SRC-2). SRC-G tests it end to end (`tests/safety.rs`).

## Fixtures and tests
- **The fixture pattern** is documented in `crates/sources-plugins/README.md`, on SRC-0's `Replayer` and `FakeCtx`. Six cases:
  - **`prowlarr_rss`:** two cycles, with a public, a private, a disabled and a Usenet indexer;
  - **`jackett_rss`:** public, semi-private, unconfigured and `all`;
  - **`prowlarr_refused`:** a 401;
  - **`jackett_refused`:** Torznab error 100;
  - **`prowlarr_indexer_error`:** a 500 on one indexer, while the other is still polled;
  - **`prowlarr_redirect`:** a 301 on the list.
- **What the tests check:**
  - every request is recorded and every recording is requested, so a `.torrent`, a disabled indexer or `all` would fail the test;
  - each unit's polls are at least 15 minutes apart;
  - the plugin stops within a second;
  - Prowlarr's key is never in a URL;
  - no error or `Debug` string holds the key.
- **Not captured from a live manager.** The fixtures are written in the shapes Prowlarr and Jackett answer with (field names and order, `prowlarrindexer`/`jackettindexer`, `apikey` links), with `.example` hosts, `REDACTED` keys and open-licence titles, as SRC-6's were. This session had no manager to record from. The README says how to record and scrub real ones.
- **Fuzzing:** `fuzz/fuzz_targets/prowlarr.rs`, with seeds in `fuzz/seeds/prowlarr/`.
  - The first byte picks the manager, the input (an indexer list, or a Torznab page through `to_found`) and the privacy.
  - CI's fuzz matrix finds the target itself. Property tests in `tests/prowlarr.rs` run the same checks in every `cargo test`.
  - A local run went 2.03 M executions in 181 s with no findings.

## Registration
- **Not wired into the running app yet.** The pipeline gives every plugin `Kit::default()` (no egress), and nothing stores a plugin's settings yet. Both belong to the slice that builds the per-plugin kit from `EgressFactory` and the settings form (SRC-14 or its split, which owns `crates/pipeline/src/lib.rs`). That slice adds, in `crates/lodestar/src/services.rs`:
  - `Prowlarr::new(Config::from_json(saved)?, Arc::new(source_credentials))`, or `Prowlarr::unconfigured(..)` when nothing is saved;
  - the kit, from `EgressFactory::build(ID, &egress, plugin.endpoints().unwrap_or(nothing))`.
  The runner has been told.
