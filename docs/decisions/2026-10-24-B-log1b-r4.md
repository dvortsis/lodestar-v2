# B-log1b decisions, part 2c (#162): the runner's follow-ups to #158

The runner's review of #158 (2026-10-24) asked for these, in a small PR after it. They refine part 2b's file (`2026-10-23-B-log1b-r3.md`), which they supersede where they differ. No owner decision is reversed or loosened, and no security or content-safety decision is weakened. The refinements the runner flags to the owner (§2.19) are marked **(§2.19)**.

- **The runner kept the 10 s shutdown bound (§2.19).** A packaging PR gives Unraid containers `--stop-timeout=60`, since Docker's default 10 s would kill the process before the save.
- **Addresses read as URLs again on the console (runner, §2.19).** This supersedes r3's "`Listen` prints the bind address" and part 2a's note on the setup token's line.
  - **The console's text** (and the Windows service's `lodestar.log`) writes a `Listen` field the way the API's `ui_address` does: `http://<this host's address>:8191/` for an unspecified bind (`0.0.0.0`, `[::]`), else `http://<address>/`. It's quoted, since it holds spaces.
  - **The JSONL file keeps the address as it is** (`0.0.0.0:8191`, kind `label`). So do the ring, history and the API. Text downloads, which are made from the ring or history, show it as it is too; only the live console (and the service's `lodestar.log`) shows the URL.
  - **Affected lines:** the setup token's line (the token still comes right after `enter setup token`), `app.serving`, `fixture.public` and the address timer's lines.
  - **How it's done:** the entry keeps the field's type (`FieldType::Listen`, a label everywhere else), and only the console's text renders it.
- **A logs folder the Windows service makes is locked down first.** `LogFile::open` creates `<data>\logs` before the runtime's file sink would. The sink's lock-on-create (part 1) then found an existing folder and left its ACL alone. So in an admin-chosen data folder that lets Users read, `lodestar.log` and `lodestar.jsonl` (which hold the setup token) inherited Users' read access.
  - **The fix:** `LogFile::open` now restricts a folder it creates (owner, SYSTEM and Administrators, `restrict_dir_acl`). If that fails, it removes the folder again and opens nothing.
  - **Nothing planted in the gap:** until `icacls` has run, whoever may write to the data folder could create a file in the new folder (it keeps its own ACL) or swap the folder for a link. So after the restriction it must still be an empty real folder; otherwise it's removed and nothing is opened, as when the restriction fails.
  - **An existing folder keeps its ACL;** the file sink judges it, and says `logging.folder_shared` when it isn't private.
  - **The test:** a Windows test makes a data folder Users can read and checks that the new logs folder is private while an existing one is untouched.
- **A bounded runtime shutdown.** Once serving ends, `lodestar serve` and the Windows service drop their tokio runtime with `shutdown_timeout(RUNTIME_GRACE)` (5 s). A blocking task that's still running (a stuck read) can't hang the exit or keep the SCM waiting.
  - Every save is awaited inside `Services::run`, before the timeout starts. What can be cut off is detached work: a dropped connection's blocking task, or under the service, a stop during start that interrupts the store's opening (a migration is one transaction and runs again at the next start).
  - With `SHUTDOWN_GRACE` and the saves, that stays inside the update supervisor's and the SCM's 30 s.
- **The stall test proves the server is blocked.** Before the signal, the test now also requires the server socket's send queue in `/proc/net/tcp` to hold data, beside the client's receive queue having stopped growing.
- **`address.reverting` is only the timer's.** It no longer has `why`, and keeps `minutes` (Warn). Undoing a change on request is its own event: `address.revert_asked`, Info, with `address` and `previous`, and no window.
- **Not done:** a second Ctrl+C that skips the rest of the grace period. The runner marked it optional, and `Services::run` takes one shutdown future; it would need the signal handling reworked on both platforms.
- **`main.rs`'s `command_failed` helper** (from #158) logs `app.command_failed` with the error's kind, then prints the scrubbed text to stderr. It's named here because the runner asked for it to be named.
