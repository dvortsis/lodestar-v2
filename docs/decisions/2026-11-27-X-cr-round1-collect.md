## Collector (`docs/soak/tools/linux/collect.py`)
- **`--round N --attempt ID --day D --arm X [--repeat K] [--run-id R] --identity-salt-file F`** makes a comb run a round-1 arm. It needs `--intensity` (the declared preset), refuses `--stop` (the coordinator owns shutdown, §5.2 item 11) and refuses a salt file another user can read or shorter than 16 bytes. It reads the uplink's address at launch and refuses to start without it.
- **Effective settings (§5.2 item 1):** the §5.1 gauge decides. `config_identity`'s "unset means false, source `default`" stays for every run without `--round`.
- **Egress (§5.2 item 4):** the IP echo is read inside the crawler's network namespace: a throwaway thread joins `/proc/<pid>/ns/net` with `setns` and opens its socket there, so the request leaves by the crawler's own route through its tunnel. The echo service's name is resolved by the host's resolver first and the TLS check still uses the name. Only `HMAC-SHA256(salt, "ip:" + address)` is written. Egress and the uplink are both kind `ip`, so a crawler whose traffic bypassed its tunnel shows the uplink's own hash, which the coordinator refuses at bring-up.
- **CR-0w first start:** with the gauge showing `safe_restart` off, a zero beside reason `off` is the steady state (no restart check runs, and since CR-0w sampling starts at once), so it counts as `T_open` after 60 s. With it on, `off` is still only the pre-check moment, and a first start opens on its `first_start` scrape within seconds. Without the gauge the old reading holds (6 h). The analyzer still applies the old reading to a zero beside `off`; every round-1 arm has `safe_restart` on (`safe_restart_on` voids otherwise), so the two never disagree on a judged window.
- **Bounds:** a round-1 arm's outstanding bound is its declared preset's cap (256, 1,024, 4,096). **Runner-approved addition (2026-11-27):** its peer-request bound (`dht_peer_active + dht_peer_queued`) is the preset's slots (32, 80, 256) when the gauge shows `preset_slots` on, and 32 only when it shows it off; with the gauge unread, the preset's. Today's fixed `> 32` would have stopped every B and A collector three scrapes after their slots filled (`docs/metrics.md`: running plus queued stays within `dht_lookup_slots_capacity`). Runs without `--round` keep 32 and 1,024.

## Per-arm stacks (`infra/fleet/steps/vm/compose.yaml`)
- **`LODESTAR_INTENSITY` passes through by bare name** (unset in the cloud lane: the shipped preset), so arm A's declared Aggressive reaches its container. The self-review found it missing: A would have run Balanced and voided every window.
- **Each arm is its own Compose project** (`-p lodestar-<arm>`, so its own bridge) in its own stack directory (its own `secrets/wg0.conf`, `data`, `witness`). `LODESTAR_ARM_SUFFIX=-<arm>` names its containers (`gluetun-b`, `lodestar-b`, `lodestar-docker-proxy-b`) and `LODESTAR_UI_PORT` its loopback port. Unset, both default to today's names and 8090, so the cloud lane's commands need nothing new.

## Leak test (`infra/fleet/steps/vm/leak-test.sh`)
- **`LODESTAR_ARM=<a-z>` with `LODESTAR_UI_PORT`** tests that arm alone: its containers and project, probe containers `lodestar-leak-flow-<arm>` and `-drive-<arm>`, tags `lodestar-leak-guard-<arm>`, `lodestar-leak-egress-<arm>` and `lodestar-leak-host-<arm>` (block-lib's `HOST_TAG`, set after sourcing it, so `block-lib.sh` is unchanged), and its project's bridge for the IPv6 check. Every cleanup path finds rules by its own tag only (`clear_tagged` matches the whole tag), so another arm's are never removed.
- **The endpoint block is scoped to the arm's bridge** (`-i <bridge>`) in arm mode, so it can't cut another arm's tunnel. The recreate guard and host guard stay endpoint-scoped, as today: **the arms must use three different PIA servers**, which the run sheet checks before any leak test. Distinct exits already make that so in practice; it isn't left to chance.
- **An arm refuses to start** without its own port, or while its own Lodestar runs (leak tests run only while no window is open, §6.3).
- **Unset, every command is as before** (one `awk` reads the counter by `index` instead of a regex, with the same tag); the existing tests pass unchanged.

## Host sampler (`docs/soak/tools/linux/host_samples.py`)
- **One line per 10 s UTC slot,** stamped with the slot's start; a slot whose work starts more than 1 s late is skipped, never backfilled. A value it can't read is `null`. So a stall shows as missing, which gate-round counts over the threshold.
- **CPU** is user + nice + system + irq + softirq over all time in the aggregate `/proc/stat` line (guest is already in user); **steal** is its own share. **Disk** is the mean write time per completed write since the last slot on the declared device, and the writes in flight now.
- **Uplink drops** are recorded as `uplink_rx_dropped` and `uplink_tx_dropped` beside their sum, plus the card's own `rx_missed_errors` and `rx_fifo_errors` where it exposes them: Linux counts frames of unhandled protocols in `rx_dropped`, which would breach "no uplink drops" every hour on some cards. `drops` prints each series' rise per hour; the rehearsal checks them, and the runner writes the drop rule against the series it shows flat (runner, 2026-11-27).
- **Tunnel probe:** one ICMP echo to the arm's declared target from inside its gluetun namespace (`nsenter`, root). A reply is `{rtt_ms, lost: false}`, ping's "no reply" is `{lost: true}`, and anything else (no PID, ping's own error) leaves that arm's reading out of the slot, which gate-round counts as lost. **The target is declared per arm** in the coordinator file before the rehearsal (runner, 2026-11-27), and the rehearsal step checks it answers: PIA doesn't answer every ping (compose.yaml's own note), and a target that doesn't would leave contention `not_judged` on coverage.

## Coordinator (`infra/fleet/steps/vm/round1-coordinator.py`)
- **Start gates (`check-start`, also run by `up`):** no arm starts before the comparator's `timeline.window_end_utc` + 12 h; free space on the data volume covers 1.2 × (every arm's expected 24 h growth + the round directory's size), one check for the host; every arm has a passing leak test before the start; every arm's `data` and `witness` are empty (fresh, §6.3).
- **Exits (`bring-up`):** each arm's egress inside its gluetun namespace, hashed; two arms on one exit, or an arm whose egress is the uplink, is refused.
- **Leak tests only while no window is open:** `leak` refuses while any collector is still measuring. A log whose only failures are the script's own refusals before testing (arguments, a running block or Lodestar, a missing file or tool) is `not_run`: nothing is recorded or stopped.
- **A failed leak test (`leak`)** stops that arm's Lodestar (every arm's with `--host-level`) and blocks `check-start`, `up` and `collect` for it until a passing `--phase retest`. **Runner's call (2026-11-27, §2.19, flagged to the owner):** before the day's collectors have started nothing was measured, so the failure and the repair go in the day's notes (in the archive) and the day can still run; if the repair changed a server, `bring-up` checks the exits again and the archive keeps every check (`exit_checks`). After the start, or an `after` test, it's an `infrastructure` event (§6.3). A close the coordinator itself caused by that stop isn't classed as a product failure.
- **Activity:** every 60 s, each arm's `/healthz` and `dht_queries_out_total`. An arm is active from the first scrape that is healthy with the counter above the one before, through the last of the unbroken run after it. A failed scrape, a counter that stops rising, or a gap over 180 s (rule 6.6) ends it, and it never restarts, so a peer that drops out mid-day is never "active through".
- **Activity sources:** the coordinator's scrapes and each collector's own (`health` and `dht_lookups_completed_total` in `samples.jsonl`) both count, and an isolated failed scrape doesn't end the span; more than 180 s with neither showing the process working does. So a watch restarted inside a window loses nothing; in the overhang only the coordinator's scrapes cover an arm.
- **A collector that dies without `result.json`** (a refusal at launch, a kill) counts as closed with reason `collector_died`, an `unclassified` event, so the day ends and fails closed. `collect` waits up to 60 s for each collector's `run.json` and reports one that exits first. `watch` runs once per day; `stop` ends a day early (the rehearsal's 4 h limit). The sampler is signalled only if its PID still runs `host_samples.py`.
- **Rehearsal:** never before the comparator's window has ended and it has closed; rule 2.2's 12 h doesn't apply to it (§8 item 5). Its day is marked and never in the manifest; nor is a day whose collectors never started.
- **Shutdown (`watch`, §5.2 item 11):** once every collector has written `result.json`, it waits until the latest final boundary scrape of the day + 2 min, reads each arm's egress once more, stops every stack (`docker compose -p lodestar-<arm> stop`), stops the sampler and writes the archive. Collectors run without `--stop` and close at their own final boundary.
- **Early closes become events** so gate-round sees them: a collector reason that says the process failed is `product` with diagnosis `pending` (the runner diagnoses, §6.3); a storage guard is `infrastructure`; anything else is class `unclassified`, which gate-round reads as an unknown event, so the day fails closed until the runner classes it.
- **Manifest (`manifest`, `end-attempt`):** every input by SHA-256, relative to the round directory. It refuses a declaration or report on another image digest, a missing or repeated run ID (the comparator's included), and repeats that don't run 0..k. `end-attempt` writes `attempt_ends` with `days_run` from the days actually listed.
- **Not collected here:** the WireGuard handshake ages that §6.3's "a tunnel without a handshake for more than 180 s" names. The sampler's tunnel probe shows a dead tunnel as loss; a handshake series needs NET_ADMIN in each gluetun and is a follow-up if the runner wants it.

## From the runner's review of #1150 at 36ba68cf (2026-11-27)
- **A repeated day** takes its repeat number from its first command (`--repeat <k>` on its first `leak`); later commands read it from the day folder. A value given that differs from the stored one is refused.
- **The coordinator file lives outside the round's folder** and the coordinator refuses one inside it: it names the stacks, the salt and the password files, and the round's folder is what's copied off. `declaration` and `comparator_report` are read from `round_dir`. The e2e scans every archived file for those paths too.
- **No arm restarts by itself.** gluetun's restart policy is `${LODESTAR_GLUETUN_RESTART:-unless-stopped}`; the coordinator sets `no` for every round-1 stack, its leak tests included, so after a reboot nothing crawls without its leak test. The cloud lane's default is unchanged.
- **The coordinator runs the leak test** (`leak --arm X --phase P`), no longer reading a log the operator supplies: from a fresh 0700 temporary folder with the three step files copied in, deleted afterwards (its captures hold raw addresses), with the arm's `LODESTAR_ARM`, `LODESTAR_UI_PORT` and `LODESTAR_GLUETUN_RESTART=no`. Only the test's grammar lines (stdout) are kept, as `leak-<arm>-<phase>-<n>.log` in the day folder. A lock in the round's folder (`.leak-test.lock`) keeps the round's leak tests to one arm at a time (one round runs on the box at a time, so that covers the host). `leak-test.sh`'s failing `install` no longer prints the stack path.
- **`check-start` (and so `up`) needs an exit check later than every arm's latest leak test.**
- **A step that stops stacks** saves its state and archive first, then exits 1 if any stack didn't stop. A partial `up` stops the arms it had started.
- **Commands run in a scrubbed environment** (`PATH`, `HOME`, `LANG` and what the step sets): no stray `LODESTAR_*` or proxy from root's shell reaches a stack, a collector or the leak test. `collect` restarts a sampler whose PID no longer runs `host_samples.py`, and notes it.
- **The final boundary's egress** is retried in place when its read fails (up to 3 tries, 20 s apart, inside rule 1.4's 90 s), each in the row's `egress_retries` with its own time; the coordinator takes those readings into the archive. A failed final read would otherwise void the day, since no later scrape retries it.
- **Boundary rows carry `api.switches`** even when the boundary's API call failed. `--round` with any run kind other than comb is refused.
- **Host samples:** `run` writes a header line (start time, device, tunnels, the box's vCPU count) and the device in every line; `assemble` refuses samples from another device, takes the arms and vCPUs from the header (no fallback to the machine assembling), and with `--archive` lists every UTC hour from the sampler's start to the day's shutdown, an empty hour at 0. `drops` carries each series' last reading across hours.
- **gate-round still sums rx and tx drops;** the runner settles the drop rule in CR-SPEC-R1 from the rehearsal's `drops` output.

## X-cr-round1-collect-fixes (runner's check of #1150, 2026-11-27)
- **A hung leak test cleans up after itself.** The coordinator runs it as `timeout -s TERM 1500 bash leak-test.sh …`, with Python's own limit 120 s longer, as `steps/remote.py` runs steps: TERM reaches the test's traps, so its guard rules, endpoint block and captures are released before its temporary folder is deleted. A timeout adds `fail leak_test_timed_out` and `fail leak_test` to the log and is never a pass, whatever the test printed before. A real-subprocess test checks the cleanup ran with the folder still there.
- **A partial `up` stops the arm that failed too**, since its containers may be up although the command failed or timed out.
- **The final boundary's retried egress reading is stamped when the read began**, never after it, so a slow read can't land past + 90 s. The e2e has an arm whose final read fails once, is retried and still binds its window in `gate-round`.
- **Partial hours are prorated:** the first and last hours' expected slots are those in the part the sampler covered (from its start, to the day's shutdown), so only a real gap reads under 98 %.
- **Every leak-test run gets its own log number,** a `not_run` one included.

## Harness gaps found by CR-SPEC-R1 (runner, 2026-11-27; `analyze_cr.py`, `test_gate_round.py` and `fixtures/round1` granted)
- **A. The comparator is bound after its window** (runner's ruling, §2.19, flagged to the owner). cr-ab-comp-2 runs under a collector without round-1 fields, so its report has no binding. `round1-coordinator.py bind-comparator --comparator-run DIR` writes `comparator-binding.json` into the round folder, once: `run_id` = `comparator-<run directory name>` (the directory the operator copies off, so stable), `host_identity` and `network_identity` computed at bind time with the round's salt as the arms compute theirs, `ended_utc` from its `result.json`, `bound_utc`, `bound_after_window: true`. It refuses an unfinished comparator, one that ended before its report's `timeline.window_end_utc`, and a second binding. The manifest carries it (`comparator_binding`); `load_manifest` gives it to a comparator report that has no binding of its own (a report's own binding wins), so `comparator_problems` reads it unchanged; the verdict echoes `comparator_bound_after_window`. The rehearsal's gate reads the binding's `ended_utc` too.
- **B. D3** (plan §8 item 6; owner §2.85; the runner's revision, 2026-11-27). `collect.py note --category array_operation` takes `--kind mover|parity|other` and a `--pool` for every pool the operation touches (the entry's `pools`: Unraid's mover moves files between a cache pool and the array). With the declaration's `pools` map (pool → devices), a mover or parity entry doesn't count under rule 6.11 only when every pool it lists is mapped and none holds the arm's `backing_device` (listed in `activity_exempt_d3`); everything else, an unmapped pool included, still counts.
- **C. Exits are judged against the exit in force at the time.** `egress_problems` reads the archive's `exit_checks` as a timed history: inside the window, the exit checked last before the window's start; before it, the exit in force then. A pre-repair reading of an earlier server is history, not a fault. Each check is stamped with its first reading's time.
- **D.** The run sheet now says a pre-start leak failure is a note, and the day runs after a passing re-test.
- **E. Classification comes first** (§6.3: "the first that applies decides"). A breach on a day that also has an infrastructure fault or a product failure (pending or diagnosed), or an unknown event, sets no `solo_confirmation_required` (nor `solo_confirmation_failed` in layout S); the day records `contention_class`.
- **F. `enough_values`** (CR-LOOKUP-END's own end) is kept by the collector and counts as an end on values in the ledger where it's rendered; absent, it counts 0, so **older runs keep their numbers** (none of the committed stage-1 fixtures render it). The round-1 `lookup_end` row requires `lookups_end_on_enough_values` > 0; absent or zero voids. Stage 1's `lc` check is unchanged.
- **G. L2c** = {A candidate on X then Y, C diagnostic on Y then X}, allowed only as the attempt after an L3 attempt (B dropped).
- **H. `analyze_cr.py drop-c SAMPLES --arm X=DIR …`** applies §6.3's drop-C rule: the last 60 min once every arm is crawling (sampling, its store grown in the previous 10 min); C is dropped if host CPU p95 > 0.70 or steal p95 > 0.03, nearest rank over every 10 s slot, a missing slot ranking over (shown as `null`). Fewer than 60 crawling minutes, or an arm that never crawled, is `not_judged`.
- **I.** The rehearsal's run-sheet step runs `segment --declaration` on each arm, so the gauge is checked against the declaration before day 1.
- **J. vCPUs:** the declaration carries `vcpus` (8, required); `contention` refuses host samples whose `vcpus` differ (`vcpus_differ`, not judged). The CPU thresholds stay shares of the declared 8.
- **K. Digest form:** the declaration's `image_digest` (and each entry's) is `name@sha256:<64 hex>`; reports, whose digest the collector records without the repository, are compared on the part after the last `@`, so another image fails. The run sheet pulls by tag once and records `docker inspect --format '{{index .RepoDigests 0}}'`.
- **L.** Round-1 segment reports (`round1.round1_spec`) and the verdict (`round1_spec`) name `docs/decisions/2026-11-27-CR-SPEC-round1.md`; `spec` stays CR-SPEC for old runs.
- **The golden verdict** (`fixtures/round1/l3_pass_verdict.json`) is regenerated: `make_archive.py`'s digest is now `lodestar@sha256:…` and its declaration carries `vcpus` and the new layout; the verdict gains `round1_spec` and `comparator_bound_after_window`, and the days' digests read `lodestar@sha256:…`.
- **Append-only declaration** (the runner's CR-SPEC-R1 ruling): identities, `vcpus` and the digest are filled once before the rehearsal; the run sheet says so.
