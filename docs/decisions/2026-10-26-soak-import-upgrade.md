# Verified partial-import upgrade decisions (local slice)

- **Verified names replace imported names.** The existing partial-to-complete transaction now writes `name`, `name_raw` and `name_enc` together. Plain UTF-8 names clear obsolete raw/encoding fields. Complete rows and unverified duplicates keep the existing behavior. This completes the canonical metadata contract in architecture §§6–7 without changing provenance or adding a migration.
- **Archive the prepared verified dictionary.** If preparation supplies raw metadata under the existing archive setting, the upgrade upserts it alongside files and enrichment. Preparation still strips `pieces`. With no prepared archive, the upgrade does not create or delete one. Existing raw data on a partial row is replaced when verified archive bytes are available.
- **Failure stays atomic.** A failure later in the transaction must roll back names, archive, files, flags and reindex work. Regression cases cover both direct and prepared insertion paths, UTF-8/legacy encoding transitions, archive on/off, unverified duplicates, and injected reindex failure followed by retry.
- **No historical repair is implied.** Already-complete rows affected by the old code do not become partial again. Repairing those rows would need a separate policy and verified metadata source. Runtime regression execution is deferred until the active soak ends.
