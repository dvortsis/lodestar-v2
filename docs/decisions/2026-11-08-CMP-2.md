# CMP-2 decisions

Companion archive extraction and the install layout (plan `docs/plan/2026-11-06-v06-companions.md` §4 CMP-2, Q13, Q16; architecture §12, §18.10). These are refinements the slice may make (owner §2.33, the brief's list). None of them loosens a refusal or a Q16 cap, except that the ratio floor below is named for the runner to confirm.

## Dependencies (Q13)
- **`zip` 9.4.2, `default-features = false`, feature `deflate-flate2` only.** MIT. `zip-rs/zip2`, the maintained successor of the original `zip` crate, with regular releases through 2026. Only stored and deflate entries can be read; bzip2, zstd, lzma, xz, deflate64, PPMd, AES and the legacy methods aren't compiled in, so an entry using one is refused as corrupt. It adds `typed-path` (MIT OR Apache-2.0), `constant_time_eq` (CC0-1.0 OR MIT-0 OR Apache-2.0) and, through `zeroize`'s features, `zeroize_derive` (Apache-2.0 OR MIT), all on the licence allowlist. Its lockfile entries also bring `nix` 0.31.3 and `cfg_aliases` 0.2.2 (both MIT); neither is built for a shipped target, so `web/licenses/rust.json` doesn't list them.
- **`tar` 0.4.46, `default-features = false`** (no `xattr`). MIT OR Apache-2.0. Maintained in `composefs/tar-rs`, its long-standing home. It adds `filetime` (MIT/Apache-2.0). Only its reader's header parsing is used: never `unpack`, which applies the archive's own paths, modes and links.
- **`flate2` 1.1.10** with the `rust_backend` feature, already in the lockfile for other crates. Pinned exactly like the crate's other dependencies.

## Names
- **Printable ASCII only.** A name with a control byte, a non-ASCII byte or one of `<>"|?*` is refused. That's stricter than the brief, and it makes normalisation exact: there is no Unicode normal form to compute (no normalisation crate is needed), and case-folding is ASCII lower-casing, which is what NTFS, APFS and ext4's case-folding agree on for ASCII. Prowlarr's archives, the only v0.6 zip and tar.gz entries, are all ASCII.
- **Normalisation:** one trailing `/` marks a directory; one leading `./` is dropped (what `tar -C dir .` writes), and a bare `./` is the root and is skipped. Every other `.` component is refused, as are empty components, `..`, a leading `/`, `C:`-style drive letters (`c:x` included), `//host` UNC prefixes and backslashes. Windows device names (`CON`, `PRN`, `AUX`, `NUL`, `COM0`–`COM9`, `LPT0`–`LPT9`, `CONIN$`, `CONOUT$`, `CLOCK$`) are refused with any extension and with spaces before it. Caps: 255 bytes a component, 64 components, 1,024 bytes a name.
- **Duplicates** compare by the ASCII-lower-cased, `/`-joined name. A directory created because a later name needed it may be listed afterwards; listed twice, or a file and a directory with one name, is a duplicate. A child whose parent's case differs from an earlier spelling goes into the folder on disk (the first spelling), so nothing depends on the filesystem's case rules. A create that still finds its name taken (an 8.3 short-name alias on NTFS, say) is refused as a duplicate.
- **The executable must match the catalogue's spelling exactly,** as written on disk. A file that only folds to it is refused as missing, since on a case-sensitive filesystem it's another file.

## Kinds, modes and caps
- **Zip modes are read from the raw external attributes.** The `zip` crate's `unix_mode` clears setuid, setgid and sticky bits and ignores the Unix half on a DOS-made entry, so it can't refuse them. Any non-zero upper 16 bits are taken as a Unix mode, whatever system the entry claims: a symlink type refuses as a link; any type but none, regular or directory refuses as special; any of `0o7000` refuses. A directory needs both the trailing `/` and an empty body.
- **Tar:** regular files and directories only. Symlinks and hard links refuse as links; devices, FIFOs, contiguous and sparse files and unknown types as special. pax global headers (`git archive` writes one) carry no file and are skipped, but counted as entries. Each entry's mode is checked for `0o7000`.
- **A size mismatch refuses.** An entry whose bytes written differ from its header's size is refused (`size_mismatch`), and the zip reader stops at the claimed size and then fails the CRC, so a header that lies small is refused too. The 2 GiB cap counts bytes as they're written, never a claim: one byte past stops it.
- **The ratio is checked as bytes are written, per entry and for the archive, with a 64 KiB floor (runner to confirm).** Output up to 64 KiB, per entry or in all, isn't refused for its ratio alone: a small file of one repeated byte can pass 100:1 honestly, and deflate and gzip framing make the ratio of a few kilobytes meaningless. Beyond it every byte is checked against 100:1. The denominators come from what was really read, never from a header or the caller: the archive's is its length, measured by seeking to its end; a zip entry's is the bytes read from the archive while it's decoded, plus the 8 KiB the zip reader may have read ahead (its header's compressed size could be inflated up to the archive's length); a tar.gz entry's is the compressed bytes read during it, plus the 32 KiB the gzip reader may have read ahead. This keeps Q16's 100:1 for anything that matters; if the runner wants no floor, it's one constant.
- **Everything a tar.gz decompresses is bounded, not only file bodies** (self-review). The tar parser reads GNU long names (`L`, `K`) and pax records (`x`) whole into memory, and skips the bodies of pax global headers (`g`), before an entry reaches the writer. A guard between the gzip decoder and the parser counts every decompressed byte: more than the 2 GiB cap plus 64 MiB of overhead (headers, records, padding; 20,000 tiny files need about 40 MiB) refuses as too large, and the ratio is checked on it against the compressed bytes read. So one header claiming gigabytes is refused within the ratio, before its body is in memory.
- **An encrypted zip entry refuses as `encrypted`,** read from the entry's raw view, since the zip reader fails such an entry before it can be named.
- **The gzip trailer is read** after the tar's end (at most 1 MiB of padding), so a bad CRC or length past the last entry still refuses the archive. Only the first gzip member is read; bytes after it are ignored, as `gzip` itself does with trailing garbage.
- **Memory before the entry cap.** The `zip` crate reads the whole central directory before its entry count can be checked; its allocation is bounded by the directory's real size, so by the archive, which CMP-1 caps at 512 MiB and pins by hash. Tar is checked entry by entry.

## Writing
- **No `O_NOFOLLOW` constant is needed.** Every file is opened with `create_new` (`O_CREAT|O_EXCL` on Unix, `CREATE_NEW` on Windows), which fails on anything already at the name, a dangling symlink included, so it can never write through a link. Every directory is one this extraction created, below a staging folder it created with `create_dir` (which fails if anything is there), so no path traverses anything else. This avoids a `rustix` or `libc` dependency and `unsafe`.
- **Modes are set through the handle** (`fchmod`) after the file is written, so the umask can't change 0644 or 0755. Directories are set to 0755 at the end, after an `lstat` check. Windows inherits the companion folder's ACL; there's no ACL code.
- **Durability:** each file is fsynced; at the end each directory is fsynced, deepest first, then the staging folder; after the rename, the companion folder. Windows can't open a directory with `std`, so its directory fsyncs are skipped, as in the updater.

## Errors
- **`ExtractError`** is a closed enum: `Refused { refusal, entry }`, `Corrupt`, `NotAnArchive`, `StagingInTheWay`, `Io(ErrorKind)` and `Cleanup { cause, kind }` (extraction failed and so did removing the staging folder; the next stage or sweep removes it). `Refusal` has one variant per rule, each with a stable `code()`. The parser's own messages are dropped, since they can quote the archive; the only archive text kept is `EntryName`: at most 96 bytes, every byte outside printable ASCII shown as `?`.
- **`LayoutError`** wraps `ExtractError` and adds `OutsideRoot`, `AlreadyStaged`, `NotStaged`, `NoPrevious`, `NoCurrent`, `BadPointer` and `Io(ErrorKind)`.
- **No log events in this slice.** A new event needs its names and help in the logging screen's messages (`web/`), outside this slice's paths, and the steps are CMP-5's to report. CMP-5 logs the error's `code()`.

## The install layout and the API CMP-5 calls
- **The "current" pointer is a small JSON file,** `<data>/companions/<id>/current`: `{"format":1,"current":"5.0.3","previous":"5.0.2"}`, read strictly (`deny_unknown_fields`, format 1, versions that parse and re-print the same, at most 4 KiB). It's written by a new `current.tmp`, fsync, rename over `current`, fsync of the folder. A rename over a file is atomic on Windows (`MoveFileExW` with replace) as on Unix, so no symlink or junction is needed, and a crash leaves the old pointer or the new one. A damaged pointer is reported (`BadPointer`), never guessed or rewritten.
- **The API, on `layout::Install`:**
  - `open(data_dir, id)` creates and checks the folder; `existing` checks it without creating it;
  - `stage(version, kind, archive, executable)` extracts into `<version>.staging/` and renames it to `<version>/`; a stale staging folder is removed first if it's a plain directory, and an existing `<version>` (even a link) refuses;
  - `commit(version)` points at it and keeps the old current as `previous`;
  - `rollback()` points back to `previous` and deletes the rolled-back version;
  - `prune_previous()` deletes `previous` once the new version is healthy;
  - `sweep()` deletes version and staging folders the pointer doesn't name, and a leftover `current.tmp`, and nothing else (so other slices' files in the folder are safe). CMP-5 runs it at start;
  - `remove()` deletes the whole folder; plus `pointer()`, `version_dir()` and `executable()`.
- **Only one previous version is kept.** A second commit without a prune makes the old current the previous and deletes the one before it.
- **Deletion:** the folder and `<data>/companions/` must be real directories (not links), and the folder's canonical path must equal the canonical data folder joined with `companions/<id>`. That's checked when the folder is opened and again before every delete. Everything deleted is a direct child of the folder or the folder itself, removed with `std::fs::remove_dir_all`, which never follows a symlink or a junction (it's race-safe on Unix and Windows) and removes a link found inside as a link.
- **Windows links:** a junction or directory symlink found where a real folder must be refuses; one found inside is removed with `remove_dir`, which removes the link. The tests make junctions with `mklink /J`, which needs no privilege, so Windows CI covers this; symlink tests are Unix-only because creating one on Windows needs a privilege.
- **One caller per companion.** Every changing step takes `&mut self`; CMP-5 holds one `Install` per companion and serialises its steps. There's no lock file.
- **The state row is CMP-5's** (plan §3): it mirrors the pointer. If they ever disagree, the pointer on disk is what runs.
