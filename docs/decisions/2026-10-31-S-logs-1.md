# S-logs-1 decisions: the live log page (`/logs`)

Architecture §10.10.12, §10.1, §12.1; B-log2 decisions (`2026-10-23-B-log2.md`). No owner decision is reversed or loosened, and no security or content-safety decision is weakened. Refinements the runner flags to the owner (§2.19) are marked **(§2.19)**.

- **The stream is read with `fetch`, not `EventSource`,** as `/events` is (`lib/state/events.svelte.ts`), so a `401`, `429 too_many_streams` or `503 logs_unavailable` keeps its status and `Retry-After`. It has its own small client in `features/logs/logs.svelte.ts` (the shared one is `/events`-only and in `lib/state`). Reconnects double from the server's `retry:` with jitter, up to 30 s; they resume with `Last-Event-ID`. A `resync` reloads from the ring.
- **Opening:** `GET /logs` (500 lines, same filters) gives the recent lines, and the stream resumes from the newest id, so there's no gap and no repeat. If history fails, the stream still starts and an error with retry shows.
- **Filters are server-side** (`level`, `components`, `text`, text debounced 300 ms); a change restarts the list, so filtered-out lines never travel.
- **Virtualisation:** the repo's `VirtualList` (TanStack Virtual) with `measureRows`, so a row grows when expanded or wrapped; collapsed rows are one line. `VirtualList` has no `log` role, so a `role="log" aria-live="off"` wrapper surrounds it. The row is an `option` of a `listbox` (roving tabindex, Enter expands). `aria-expanded` isn't allowed on `option`, so expansion isn't exposed as a state **(§2.19)**.
- **Cap:** 10,000 lines kept; older ones dropped with a note; Load earlier stops at the cap. A `purge` frame rewrites kinds to `[hidden]` and removes an opt-in's lines in what's held.
- **Untrusted text:** every value goes through `safe()` into a text node (no `{@html}`): control, bidi and invisible format characters become visible `\uXXXX` escapes (newline, tab and NUL as ⏎ ⇥ ␀), long values are cut (400 characters in a row, 2,000 expanded), binary-looking text becomes `[binary data, N characters]`. Copy and Download write the same safe text.
- **Hidden tab:** the stream closes after 5 s hidden and resumes from the last id on return.
- **Identifying-data banner:** `GET /logs/catalog` (admin session) exposes the kinds' `until`, so the banner shows the time left when an identifying kind or opt-in is on. **"Turn off now" is not on this page:** no API this slice may use turns kinds off (Settings owns that write), so the banner links to Settings → Logging. The status chip ("Normal · Private") comes from the catalog's presets and links there too. If the catalog can't be read, neither shows. **(§2.19)**
- **"Record detailed logs for 30 minutes"** needs a write API, so it isn't here; at Debug or Trace with no debug-level event on, a banner says debug lines aren't being recorded and points to Settings. S-logs-2 can add the button.
- **Open full log** links to `/settings/logging` (arrives with S-logs-2). The overflow-menu "Logs" link comes later (`lib/shell` isn't touched here).
- **Keys:** `/` focuses the filter and `Space` pauses (neither while typing in a field nor on a button); registered locally on the page, not in the key registry (`lib/state` and the registry's defaults are not touched). `Home` and `End` are the list's own.
- **Size:** `/logs` gets its own entry (measured + 10%); no other route's first load changes.
- **Size gate (runner, §2.26):** adding `/logs` re-splits shared chunks. Diffing the build manifests with and without the route shows three modules that had been merged into other routes' chunks now in chunks of their own, because `/logs` also uses them: `VirtualList` (and its CSS), the virtualiser's `index-client`, and `state/sse` (the SSE parser). Alerts, Alert, Search results, Search cards and `/t/[hash]` carry the extra chunk overhead. Reusing the shared `VirtualList` and `SseParser` is the point of the slice, so no import change removes it. Limits raised by the measured overage, rounded up to 0.1 KB: Alerts 29.1 → 29.2 KB (+69 B), Alert 45.9 → 46 KB (+86 B), Search results 43.2 → 43.3 KB (+92 B), Search cards 8.19 → 8.3 KB (+21 B), `/t/[hash]` 22.5 → 22.6 KB (+35 B).
