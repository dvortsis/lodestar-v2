# X-claim-store decisions

Slice session, 2026-11-05. Runner brief X-claim-store, the follow-up `2026-11-05-X-claim-trackers.md` asked for. Architecture §18.5 (claims before storage) and §12 (the SSRF guard). It completes X-claim-trackers' rule: no guard check is loosened, and every class it refuses is still refused.

- **Claimed trackers are stored in the guard's canonical form.** `unverified::tracker_url(raw) -> Option<String>` now returns `lodestar_integrations::net::public_tracker_url(raw)`, the address the guard judged, instead of keeping a claim only when the raw text already equals it. `https://t.example:443/announce` is stored as `https://t.example/announce`, `UDP://T.Example:6969/a` and `udp://%74.example:6969/a` as `udp://t.example:6969/a`, `http://tracker.example` as `http://tracker.example/`, and an IDNA name in its `xn--` form. Before this, such claims were dropped: every tracker with a default port, no path, or an upper-case or encoded host, all common in public tracker lists and magnet `tr=` parameters.
  - **Why storing the rewritten form is safe:** the guard's output is what it judged, it reads back as itself (`public_tracker_url(k) == Some(k)`), it has no `@`, nothing but host and port in the authority, and only hostname characters in the host (X-claim-trackers). So no reader finds a different host in the stored text than the guard did. The raw text is never stored.
- **`tracker_url` keeps its checks on the raw text,** on top of the guard: `scheme://` followed by a host, at most `claims::MAX_TRACKER` (2048) bytes, and no whitespace or control characters. The `url` crate repairs these rather than refusing them: `http:1.1/announce` reads as `http://1.0.0.1/announce`, leading and trailing spaces are stripped, and tabs and newlines are removed anywhere (`http://t.exa\tmple/` would become `http://t.example/`). A feed that sends such text is malformed, so the tracker is dropped, not repaired, as before. The canonical form is held to the same 2048-byte limit, since it can be longer than the raw text (IDNA, percent-encoding). The store refuses the whole claim set if one tracker is over the limit, so dropping that one tracker keeps the rest of the claims.
- **`tracker_url` stays a separate function** rather than being replaced by the guard, because of those checks. Its doc no longer mentions `wss` (refused since X-claim-trackers) or a text-level check.
- **Duplicates are dropped after canonicalising** (`unverified::stored_trackers`): two spellings of one tracker are stored once, in the place of the first, and the order is otherwise the claim's. The claims' cap (`claims::MAX_TRACKERS`, 64) applies after the dedup, so duplicates don't use up places. The emitter clamps the raw list to the same cap first (`lodestar_sources::Claims::clamp`), so at most 64 raw entries are judged.
- **No backfill.** The old rule stored a tracker only when its raw text was already the guard's canonical form, so every stored tracker is already in the form this rule stores. The only difference an old row can show is a repeat: the old rule didn't dedup, so a feed that sent the same text twice has it stored twice. That's inert. Nothing dials, emits or returns claimed trackers yet (X-claim-trackers), and the first reader for output must apply the guard anyway, which can drop repeats at the same time. Claims stored from now on have none.
- **Tests.** `crates/pipeline/tests/claim_trackers.rs`:
  - non-canonical spellings are kept in canonical form (`:443`, `:80`, upper-case scheme and host, no path, mixed-case and percent-encoded `udp` hosts, IDNA), and every kept form maps to itself;
  - every refused class is still refused: loopback, private, link-local, CGNAT, documentation and mapped addresses; `localhost` names, single labels and `*.local` (including mixed-case and encoded `udp` spellings); `,` or `;` in the host; `@` in the authority or after a `udp` port; `wss` and other schemes; text without `scheme://` and a host; whitespace and control characters;
  - the length limit holds before and after canonicalising;
  - two spellings are stored once, the cap applies after the dedup, and `store_claims` stores the canonical list in claims that pass the store's own check.

  The `verified_claims` fuzz target (the `torrent_cache` claims path) already checked that kept trackers are guarded: no non-public literal or `localhost` name, hostname characters only, the judged `udp` host. It now also asserts each one is the guard's own fixed point, `public_tracker_url(t) == Some(t)`, so the pipeline stores the cache's trackers unchanged.
