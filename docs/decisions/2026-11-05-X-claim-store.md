# X-claim-store decisions

Slice session, 2026-11-05. Runner brief X-claim-store, the follow-up `2026-11-05-X-claim-trackers.md` asked for. Architecture §18.5 (claims before storage) and §12 (the SSRF guard). It completes X-claim-trackers' rule: no guard check is loosened, and every class it refuses is still refused.

- **Claimed trackers are stored in the guard's canonical form.** `unverified::tracker_url(raw) -> Option<String>` now returns `lodestar_integrations::net::public_tracker_url(raw)`, the address the guard judged, instead of keeping a claim only when the raw text already equals it. `https://t.example:443/announce` is stored as `https://t.example/announce`, `UDP://T.Example:6969/a` and `udp://%74.example:6969/a` as `udp://t.example:6969/a`, `http://tracker.example` as `http://tracker.example/`, and an IDNA name in its `xn--` form. Before this, such claims were dropped: every tracker with a default port, no path, or an upper-case or encoded host, all common in public tracker lists and magnet `tr=` parameters.
  - **Why storing the rewritten form is safe:** the guard's output is what it judged, it reads back as itself (`public_tracker_url(k) == Some(k)`), it has no `@`, nothing but host and port in the authority, and only hostname characters in the host (X-claim-trackers). So no reader finds a different host in the stored text than the guard did. The raw text is never stored.
- **`tracker_url` keeps its checks on the raw text,** on top of the guard: `scheme://` followed by a host, at most `claims::MAX_TRACKER` (2048) bytes, and no whitespace or control characters. The `url` crate repairs these rather than refusing them: `http:1.1/announce` reads as `http://1.0.0.1/announce`, leading and trailing spaces are stripped, and tabs and newlines are removed anywhere (`http://t.exa\tmple/` would become `http://t.example/`). A feed that sends such text is malformed, so the tracker is dropped, not repaired, as before. The canonical form is held to the same 2048-byte limit, since it can be longer than the raw text (IDNA, percent-encoding). The store refuses the whole claim set if one tracker is over the limit, so dropping that one tracker keeps the rest of the claims.
- **The trackers fit under the claims' total** (fresh review, blocking). The emitter's clamp fills files up to `claims::MAX_TOTAL` (1 MiB) counting trackers at their raw length, and the canonical form can be longer (`http://t.example` → `http://t.example/`). The store refuses the whole claim set over the total, so a near-full pack with one such tracker would have lost its name and files. `store_claims` now builds the other claims first and gives the trackers only the room left under the total: a tracker that doesn't fit is dropped, and a later, shorter one can still be kept. The old rule never grew a tracker, so it couldn't hit this. The room is filled first-fit, in the claim's order, so in a near-full pack it can trade one tracker for another (X-claim-store-polish, from #512's review): `[http://t.example, udp://u.example:1/a]` measures 16 + 19 = 35 bytes raw, so the clamp keeps both in exactly 35 bytes of room, but the canonical forms take 17 + 19 = 36, so `http://t.example/` is stored and `udp://u.example:1/a` is dropped. It's deterministic, and it happens only within the clamp's slack, the bytes canonicalising adds.
- **`tracker_url` stays a separate function** rather than being replaced by the guard, because of those checks. Its doc no longer mentions `wss` (refused since X-claim-trackers) or a text-level check.
- **Duplicates are dropped after canonicalising** (`unverified::stored_trackers`): two spellings of one tracker are stored once, in the place of the first, and the order is otherwise the claim's. The claims' cap (`claims::MAX_TRACKERS`, 64) applies after the dedup, so duplicates don't use up places. The emitter clamps the raw list to the same cap first (`lodestar_sources::Claims::clamp`), so at most 64 raw entries are judged: 64 spellings of one tracker followed by others still lose the others before the pipeline sees them. That clamp is in `crates/sources`, outside this slice, and it bounds the work per claim, so it stays. A trailing root dot is a different canonical form (`udp://t.example.:6969/a` and `udp://t.example:6969/a` are both kept), as the guard has it.
- **A private find's `external_ref` is never stored** (runner, from its security pre-audit of `main`, finding L3; X-claim-store-polish). `store_claims` now clears it whenever `found.private_source` is set, because a private tracker's reference can be a passkey URL. The prowlarr, clients and arr plugins already drop it, so nothing stored changes today; the rule is now enforced in one place, so a future plugin can't store one. The rest of the provenance is kept. Its claimed trackers aren't stored either, for the same reason: a private announce URL can carry a passkey in its path or query, which the host guard doesn't check. Where a key turns private after a public tracker list arrived (the `torrent_cache` race), losing those public trackers is the stricter outcome, and it's accepted. This tightens behaviour and is the runner's call. Test: `a_private_finds_external_ref_and_trackers_are_not_stored`.
- **No backfill.** Rows stored since X-claim-trackers (#500) hold only trackers whose raw text was already the guard's canonical form, so they're in the form this rule stores; the only difference one can show is a repeat, since the old rule didn't dedup. Rows from before #500 passed only the text check and can hold `wss`, upper-case or non-public trackers; `2026-11-05-X-claim-trackers.md` already records them as inert. Both stay as they are: nothing dials, emits or returns claimed trackers yet, and the first reader for output must apply the guard, which covers both kinds and can drop repeats at the same time.
- **Tests.** `crates/pipeline/tests/claim_trackers.rs`:
  - non-canonical spellings are kept in canonical form (`:443`, `:80`, upper-case scheme and host, no path, mixed-case and percent-encoded `udp` hosts, IDNA), and every kept form maps to itself;
  - every refused class is still refused: loopback, private, link-local, CGNAT, documentation and mapped addresses; `localhost` names, single labels and `*.local` (including mixed-case and encoded `udp` spellings); `,` or `;` in the host; `@` in the authority or after a `udp` port; `wss` and other schemes; text without `scheme://` and a host; whitespace and control characters;
  - the length limit holds before and after canonicalising;
  - two spellings are stored once, the cap applies after the dedup, and `store_claims` stores the canonical list in claims that pass the store's own check;
  - a near-full claim set whose tracker grows past the total keeps its other claims, drops that tracker and keeps a shorter one that fits;
  - first-fit in a near-full pack keeps the earlier tracker, as in the example above (X-claim-store-polish);
  - a property test (X-claim-store-polish) over mixed spellings (scheme case, `%`, `[]`, IDNA hosts with `ü`, `ⓛ` and `。`, ports 0–70,000, paths with `@ ? # \ " ^` and spaces, 0–120 colliding spellings, `room` 0–300 or the whole total): every kept form is a fixed point of `tracker_url` within 2,048 bytes, and `stored_trackers` returns at most 64 fixed points, within `room`, without repeats and in the claim's order.

  The `verified_claims` fuzz target (the `torrent_cache` claims path) already checked that kept trackers are guarded: no non-public literal or `localhost` name, hostname characters only, the judged `udp` host. It now also asserts each one is the guard's own fixed point, `public_tracker_url(t) == Some(t)`, so, together with the raw-text checks and caps the target already asserts, `tracker_url(t) == Some(t)`. The target doesn't call the pipeline; the property test above covers `stored_trackers`.
