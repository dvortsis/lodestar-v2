# SRC-13c decisions (plugin settings write path, exact consent compare)

Slice session, 2026-11-05. Runner brief SRC-13c. It closes the OPEN item in `docs/decisions/2026-11-05-SRC-13b.md` and meets the runner's two conditions from the review of #479. It refines SRC-4's consent versions (`docs/decisions/2026-11-02-SRC-4.md`, "Consent-text versions") and SRC-13b's "a changed path on the same host doesn't ask again". Architecture §18.7, §18.9.

## The write path
- **`PATCH /sources/{id}` takes `config`:** a JSON object of at most 16 KiB (`MAX_CONFIG_BYTES`, checked in the API and again in `Control::update_source`). Anything else is `400 invalid_config`.
- **The plugin checks it with its own rules.** New `SourcePlugin` methods:
  - `config_editable()`: whether its settings can be written. Defaults to false, so every other plugin refuses `config` ("this source has no settings to change").
  - `check_config(json)`: the plugin's own check, which gives the form to save. For the torrent cache, that's `Config::from_json`: unknown fields refused, at most 8 caches of at most 512 bytes. It saves `Config::to_json`, with each template trimmed, which reads back to the same settings.
  - `config_json()`: the settings it was built with at this start, in the saved form.
- **A refusal names the rule, never a value.** The control's `SourceChange` and the API's `SourcePatch` print `config` as `…` in `Debug`. Templates aren't in any error or log.
- **Stored in the sources config row** (`SourceSetting::Config`, SRC-13b), in the same `set_source_settings` write as egress, schedule and agents. It doesn't need the admin password: what it changes is gated by consent (below), unlike a route change.
- **It applies at the next start,** when the plugin is built from what's saved, as egress and schedules do. `restart_required` is now also true when the saved settings differ from the running ones (`SourceView::config_pending`). `editable` lists `config` only for a plugin whose settings can be written.
- **`GET /sources` doesn't return `config`.** For the torrent cache, `endpoints` holds the list it runs with. A generic read, with `writeOnly` fields left out, is SRC-15b's to add with the generated forms if they need one.

## Condition 1: the consent compare is exact
- **The version is the exact list now, not a digest** (`consent::version`). The form is `t<text version>`, then ` <length>:<address>` for each address, sorted and once each. The length prefix makes it injective, so two versions are equal only when the text version and the address sets are. `Ack::covers` compares it as a string. A property test (`versions_are_injective`) checks this over arbitrary printable addresses, and a fixed test covers lists a separator could confuse.
- **The record holds that version, unchanged in shape:** `<class>|<version>|<0 or 1>`. An address may hold `|`, so the version is read as everything between the first and the last `|`.
- **No new dependency.** SHA-256 would have needed one for `lodestar-sources`. The list is short: at most 8 × 512 bytes for a torrent cache, and a few hosts for a compiled-in manifest.
- **Old records fail closed.** A record SRC-4 wrote (`<text version>-<FNV-1a digest>`) still reads, but it never equals the new form. So it covers nothing: the source is switched off at the next start, and enabling it asks again. This covers every acknowledgeable class, compiled-in manifests included, and it's intended: the stored form can't be compared exactly, so it can't be trusted. Each affected user re-acknowledges once. Compiled-in manifests keep working: their new acknowledgements are of the same exact form. Test: `a_record_in_the_old_digest_form_fails_closed`, which writes the very record SRC-4 wrote for a manifest.
- **The FNV collision is gone by construction.** A collision needs a digest, and none is left. A pair of colliding lists costs about 2^32 work, so the test doesn't build one. It shows instead that a record in the old form (the only form a collision could target) covers nothing, and that the new form is injective.
- **The API's `consent_version` is the same exact string.** The client sends back what it was shown. So a list changed between the dialog and the PATCH is refused (`409 consent_required`), as before, with no digest a crafted list could match. The `409` message no longer quotes the version: the version holds every address, and an address can be a per-user one. `GET /sources` gives it.

## Condition 2: full addresses in the consent dialog
- **The torrent cache's manifest endpoints are its full templates** (`https`, then the template after `https://`), not its hosts. So `GET /sources`'s `endpoints`, which feeds the dialog, lists `https://cache.example/~me/{hash}.torrent`, and the acknowledgement covers exactly that.
- **This tightens SRC-13b:** a changed path or query now asks again, as does a changed port or placeholder case. On a host with per-user paths, each path is a different party. A host change still switches the plugin off at the next start until it's acknowledged again (step 4). Tests: `a_new_or_changed_address_asks_again_and_an_unchanged_list_doesnt` (plugin crate), and `a_config_written_through_the_api_turns_the_cache_off_until_acknowledged` (host, through `PATCH /sources/{id}`).
- **`Endpoint.host` is now documented as "what follows `://`"**: a host for a compiled-in manifest, or a template for one built from settings. The egress host list never came from it for the torrent cache (`SourcePlugin::endpoints`), so it's unchanged. `consent::addresses` is the one place that turns endpoints into the shown list. The API uses it, so the dialog shows exactly what's compared.
- **A template is printable ASCII with no spaces, starting `https://`** (new `Config::new` rules). The dialog shows it as written, so a control, bidirectional or look-alike character can't hide part of the address. A non-ASCII host is written in its `xn--` form. A `\` is refused too: the URL parser reads it as `/`, so `https://a.example\@b.example/` would show one host and reach another (from `/security-review`). `HTTPS://`, which the URL parser accepted, is now refused so the shown text is the canonical scheme.
- **The web row lists the addresses** (`SourceRow.svelte`, `sources_addresses_heading` and `sources_addresses_none`, en and zh) while a source needs its endpoints or consent acknowledged. It shows them in the mono face, wrapped. The consent dialog itself is still SRC-15b's; it should show the same `endpoints` list.
