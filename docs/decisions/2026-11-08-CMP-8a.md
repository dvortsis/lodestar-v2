# CMP-8a decisions

Companion detection and health adapters (plan `docs/plan/2026-11-06-v06-companions.md` §4 CMP-8a, Q12). These are the slice's decisions under §2.33. None loosens an owner decision, Q12's scope or the SSRF guard. The runner flags them to the owner (§2.19).

## Scope and the guard
- **The probe set is fixed (Q12).** `detect::probe_targets` builds, for each catalogue entry:
  - loopback on each **internal TCP** port;
  - then the entry's container name on the same ports.

  A peer-to-peer port (qBittorrent's 6881) isn't an HTTP service, so it isn't probed. `detect::auto_probes` covers the three entries that have adapters. A test pins the exact list: 8080, 9696 and 8000, each on loopback and on its container name. A second test checks that `auto_detect` sends to nothing else. An entered URL is probed only when a caller passes one.
- **Loopback means `127.0.0.1`, then `::1`.** `Target::Loopback` names one port, and its doc comment says `127.0.0.1`. When nothing listens there, `CompanionHttp` tries `[::1]` on the same port, within the same deadline. That's still loopback on a catalogue port, so it doesn't widen Q12, and `adapter.rs` is unchanged.
- **`CompanionHttp` is this crate's `GuardedHttp`.** It wraps `lodestar_integrations::net::GuardedClient` in download-client mode: private ranges and loopback; never link-local, metadata or reserved. It holds two clients:
  - **Fixed targets** use a resolver wrapper (`LocalOnly`). A container name must resolve only to private or loopback addresses, so a DNS search domain can't send a probe to a public host. The download-client policy alone would allow a public address.
  - **An entered URL** gets the plain download-client policy, checked at connect time. Its literal is checked before any connection (169.254.169.254, `fe80::`, `[::ffff:169.254.169.254]`, `fd00:ec2::254` and `100.100.100.200` are refused at once, as is a name that resolves to any of them).
- **No redirects.** `GuardedClient::send` never follows one, and `CompanionHttp` doesn't call `send_following`. A 3xx comes back as its status, its `Location` is never read, and every adapter treats it as "not this companion".
- **One deadline per probe, body included.** The request's `Limits` timeout wraps the whole exchange in `tokio::time::timeout`: connecting, both loopback families, the head and the last body byte. A slow drip ends there. The body goes through `read_limited` at the request's cap, so a declared or chunked body one byte over fails with `TooLarge`. Detection and health use `Limits::PROBE` (5 s, 64 KiB, CMP-0's numbers).
- **Nothing identifying.** Probes send `User-Agent: Lodestar-Companions` (CMP-1's) and the adapter's own headers, which none of the three sets. The client sends no cookie, proxy or `Referer`. **Detection sends no credential.** A test checks every recorded request for `Authorization`, `Cookie`, `X-Api-Key`, `Referer` and `Origin`.
- **Errors keep only a code.** Guard errors map to `Blocked`, `Unreachable`, `Timeout`, `TooLarge` or a fixed `Protocol(&'static str)`, never a URL or body. "Nothing listening" is `Ok(None)` for detection and `Unreachable` for health. Timeouts and guard refusals are errors.

## Endpoints and markers
Checked against upstream sources on 2026-11-08 (raw files on GitHub, at the tags named). The catalogue pins no versions yet, so the fixtures follow the current releases.
- **qBittorrent.**
  - **Probe:** `GET /api/v2/app/version`.
    - `200` and `v<version>` means found, with the version: authentication is bypassed for this address, or there's a session.
    - `403` and exactly `Forbidden` means look at the login page. That body is the 4.6.3 recording in `crates/integrations/tests/fixtures/qbittorrent/`.
  - **Login page:** `GET /`, upstream's `src/webui/www/public/index.html`. Its title is translated, so the marker is two strings that are untranslated at `release-4.6.3`, `release-5.0.3` and `master`: `id="loginform"` and `images/qbittorrent-tray.svg`. Both are required.
  - **Version:** strictly `v` plus a `Version`, with one trailing newline tolerated. A version outside the grammar (`v5.1.0beta1`) is "not found" rather than found without a version, because a 200 that doesn't read as a version is no evidence of qBittorrent.
  - **Health:** the version probe. A version is healthy, and so is a `403 Forbidden`, which is a live WebUI without a session. Anything else that answers is unhealthy.
- **Prowlarr.**
  - **Probes:** `GET /ping` is `[AllowAnonymous]` (`PingController.cs`) and answers `200 {"status": "OK"}`, or `500 {"status": "Error"}` when its database fails. Every *arr program answers `/ping` the same way, so detection also reads `GET /login` (`frontend/src/login.html`, served whatever the auth setting) and looks for `<title>Login - Prowlarr</title>`.
  - **Never `/initialize.json`:** it's behind the UI policy and carries the API key.
  - **Version:** no anonymous endpoint gives one, so `Detected::version` is `None`.
  - **Health:** `/ping` with `OK`.
- **gluetun.**
  - **Probe:** `GET /v1/vpn/status` on the control server.
    - `200` with a known state means found. The states are `running`, `starting`, `stopping`, `stopped`, `crashed` and `completed`.
    - Since v3.39.1 every route needs a role, so without a credential it answers `401` and exactly `Unauthorized\n`. That's found only if `GET /` also gives exactly `404 Not Found\n`. The auth middleware (`internal/server/middlewares/auth`) returns that for any path outside its routes, before checking roles. A server that answers 401 everywhere fails this check.
  - **Never `/v1/publicip/ip`:** the public address is personal data.
  - **Health:** `running` is healthy. Any other state is unhealthy, **and so is a `401`**: a VPN that can't be seen to be up is never reported as up, because companions' traffic and the kill-switch depend on it. With a credential (CMP-8b, Q19) this can read the real state.
  - **Version:** none; the control server doesn't report one.
- **The answers are closed values.** `Detected` carries the target Lodestar chose and an optional `Version`. Health is `HealthStatus`. The parsers' own results are closed enums too: `prowlarr::Ping` and `gluetun::Vpn`, never the status string. No header is read: `ProbeResponse` carries none, so a hostile `Server` header or a wrong content type has nothing to reach, and the body is judged on its own.
- **JSON is read with `lodestar_sources_feeds::json`**, the bounded reader. It's a new dependency of this crate on a workspace crate already in the lock, with no cycle: sources-feeds depends only on metainfo. Caps: depth 4, 64 values, strings of 32 bytes. A duplicate `status`, trailing text, a non-string value or a non-UTF-8 body is "no answer".

## Fixtures and tests
- **Layout:** `crates/companions/fixtures/<companion>/<case>/NNN.http` and `NNN.body`, the SRC-7 recorded-exchange shape. `.gitattributes` there marks every file `-text`, because markers like `Unauthorized\n` are byte-exact on Windows checkouts too.
- **Cases:**
  - found;
  - authentication required (qBittorrent 4.6.3 and 5.0.3 login pages, gluetun's 401);
  - the companion's own error state (Prowlarr's database, gluetun stopped);
  - another program on the port (nginx, a router page, Sonarr, a server that asks for authentication everywhere).

  "Down" is a closed port. Prowlarr's `/ping` and `/login` are anonymous whatever its auth setting, so its "auth required" case is a reverse proxy that asks for authentication.
- **Fixture bodies are trimmed.** Prowlarr's login page keeps its head (with the title) and an empty form. qBittorrent's are upstream's page with the WebUI's substitutions applied.
- **Tests run against a local server on loopback, with no fixed sleeps.** The slow-drip server sleeps only to pace its writer; the test waits on the client's deadline. Each parser has property tests.

## Not here
- **No new log events.** Each one needs the web logging catalogue's names and messages (`web/src/lib/features/settings/logging/`) and the settings golden, none of which this slice owns. The adapters return typed codes. CMP-5g's watch loop, which decides what's worth logging, adds the events with the companion id and the code.
- **Wiring** `CompanionHttp` and the adapters into the binary is CMP-5g's. FlareSolverr is CMP-12's: it adds one registration line in `detect::detector` and `detect::health` and a name in `ADAPTERS`.
