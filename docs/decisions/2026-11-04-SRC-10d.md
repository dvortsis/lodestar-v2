# SRC-10d decisions (Academic Torrents plugin)

Slice SRC-10d of `docs/plan/2026-11-01-v06-sources.md`, architecture §18.2 rank 19. The code is `crates/sources-plugins/src/academic.rs`, its fixtures in `fixtures/academic/` and its contract tests in `tests/academic.rs`. It builds on SRC-8b (#419), which taught the RSS parser to read Academic Torrents' bare `<infohash>` and plain-integer `<size>`.

## Scope
- **Academic Torrents only** (runner, 2026-11-04). The plugin id is `academic_torrents`.
- **No official distribution feeds in this slice.** None was checked for hashes and a Q2 result, and the brief allows them only if reachable, clear and carrying hashes. Each would need its own check here. **Follow-up** for the runner.

## Q2 checks (owner-decisions §2.28)
Endpoint: `https://academictorrents.com/rss.xml`, checked 2026-11-04 through the proxy.
- **robots.txt:** `User-agent: *` with only `Allow:` lines (`/browse.php`, `/collections.php`, `/details/`, `/docs/`) and a sitemap. There is no `Disallow`, so nothing is refused to a crawler.
- **Terms** (`/terms.php`, 2016): no clause on automated access. The site's footer links the RSS feed.
- **Result: clear.** Not a grey case.
- **The feed:** RSS 2.0, 200 with `Content-Type: text/xml`, 30 items, about 43 KB, behind Cloudflare. Each item has a title, free-text category, bare `<infohash>`, guid and link (both `/details/<hash>` pages), a description and a size in bytes. No magnet, enclosure or date.

## Consent class, risk and rate
- **Consent `None`** (a toggle), as §18.7 lists "Academic/official lists". Risk Low, not enabled by default, Singleton.
- **One fixed endpoint** (`https`, `academictorrents.com`), no credentials, an empty config schema. Egress is narrowed to that host with `Endpoints::manifest`.
- **Poll interval: 1 hour** (plan Q4, "Academic lists hourly"), per-host 5 s with burst 1, back-off 60 s up to 6 h (as Nyaa). A user can slow it, never speed it up.
- **Parser caps:** the SRC-8 limits, tightened to 150 items and 1 MiB for a 30-item, 43 KB feed (Nyaa's are 300 and 4 MiB for 75 items).

## What is fetched, and what is claimed
- **Only the feed.** The `/details/<hash>` page is never requested (it is `robots.txt`-allowed but not needed), and there is no `.torrent` link.
- **Key** only from the parser's typed hashes (`Item::hashes`). The hash is not lifted from the guid URL. An item with no valid hash is skipped by the parser or by `to_found`.
- **Claims map** (all Low confidence, unverified, through SRC-2):

  | Feed field | Claim |
  |---|---|
  | `<title>` | `name` |
  | `<size>` (bytes) | `size`, kept only within 1 B to 1 PiB |
  | `guid` | provenance `external_ref` (the details page, never fetched) |
  | `pubDate` | none in this feed; the field is kept if one appears, within BitTorrent's release to now + 1 day |

- **The category is left out.** The feed's `<category>` is free text ("Dataset"), and SRC-8's `Item::category` holds only Nyaa's numeric ids, so the parser drops it. The brief's Do list asks for the category "where the source gives them", and the runner's note allows leaving it out if `Item` doesn't expose it. No content-type claim is made; the classifier decides. **Follow-up for the runner:** a small change to `crates/sources-feeds/src/rss.rs` (not editable in this slice) to keep a plain-text `<category>` would let this plugin claim a content type; mapping "Dataset" then is a few lines here.
- **Files, trackers, publisher and description** aren't claimed. The description is long third-party prose.

## Fixtures
`fixtures/academic/academic_rss` is a recording of the real feed (five of 30 items, descriptions replaced by a placeholder; titles are the uploaders' public dataset names). The empty, no-hash, duplicate, cut-off and DTD cases are hand-edited from the same recording. The 429 and 503 responses (not their bodies) and the `academic_html` challenge page are hand-written. The 429 carries `Retry-After: 7200`, longer than the poll interval, so the test shows the header is honoured. The oversized case is generated by the test.

## Shared files
Only the `pub mod academic;` line in `crates/sources-plugins/src/lib.rs`. Not wired into `services.rs` or the pipeline: the host builds `Academic::new()` in SRC-14/SRC-15b.
