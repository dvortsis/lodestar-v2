# RP-6 decisions: Filters & Safety, Packs panels (PR to be numbered)

Plan `docs/plan/2026-11-04-v06-rulepacks.md` §4.3 "RP-6"; architecture §20.7, §20.10, §10.10, §10.14. UI only on RP-3's API (`2026-11-05-RP-3.md`); `crates/**` untouched.

- **The server decides what weakens; the UI never does.** Accept opens the existing change dialog, and the password field appears only when the preview's assessment says `confirm`. A rule's direction text and the "Stricter" / "Looser" badges only echo `pack_acceptance.strengthens` and `in_doubt`. A direction the UI doesn't know, or none, reads "Effect not recorded".
- **In doubt is a plain reason** inside the dialog ("We can't confirm this change is safe, so it needs your password."), per rule, from `pack_acceptance[].in_doubt`.
- **Versions and base are sent back** (outside the owned paths: `flows/machine.ts`). `forApply` adds the previewed `pack_versions` as `versions` to `accept_pack_versions`, and the previewed `pack_base` as `base` to `set_pack_override` and `confirm_pack_override`, as RP-3 requires of a confirmed change; without it the server answers 400 `pack_versions_needed` / `pack_override_needs_base`. `assessmentDiffers` compares both, so a changed set re-asks (`changed_since_preview` also re-previews through the flow's existing path).
- **Dialog shows the acceptance impact** (outside the owned paths: a block in `flows/ChangeDialog.svelte`). It lazy-loads `screens/packs/PackImpact.svelte` only when the assessment carries `pack_acceptance`, so other changes pay nothing.
- **`unless` is a text field, not the query builder** (runner to confirm). The Builder (`features/search/assist`) is bound to the search bar's AST and `/parse`, not reusable for a value of another screen. The server validates `unless` in the preview, as it does for `add_rule` on the same screen; the dialog shows its refusal. A builder for rule fields can follow as its own slice.
- **Mounted from the lazy packs part, not `Switches.svelte`** (runner to confirm). A second `{#await import}` in `Switches.svelte` put +141 B on the Filters first view (31.07 kB limit; baseline 31.01). The panels mount at the end of `Packs.svelte`, which is already loaded on demand from there, so the first view is unchanged (31.01 kB).
- **Size.** New entries "Filters pack panels (on demand)" (9 kB; measured 8.36) and "Filters pack impact (on demand)" (2.4 kB; measured 2.14). "Filters packs list (on demand)" 1.6 → 1.7 kB (measured 1.68: the mount's await block), the one existing limit raised (runner to confirm). The action names are the panel's own keys (`filters_packs_act_*`) rather than the Rules list's, since sharing them moved six messages into a shared chunk on the first view (+254 B). Nothing in the panel's files uses the bare word `diff`, which makes Tailwind emit daisyUI's `.diff` component (+181 B of global CSS).
- **Corpus status** comes from `GET /filters/fixtures` once per screen load: "All examples pass", "N to look at" (failing examples plus direction disagreements) or "Couldn't be checked" when the corpus doesn't load; known gaps show separately and don't fail it, as in CI. A failed read says "Not known", never "passing".
- **Changelogs are text:** `whitespace-pre-wrap` text nodes, never `{@html}`. Status uses Badge (icon and text).
- **User guide:** the packs section is in chapter 3.6 ("Pack versions and your password"), where the content filters' guide already lives; there is no separate Filters chapter. Revisions 1.8.

## Review round (Opus, on af340a23)

- **Corpus badge:** "All examples pass" only when the corpus loaded, passes and the pack has rows; no rows reads "Not known", and a failing corpus adds a global note.
- **Lazy parts have `{:catch}`** with their own message keys (`filters_packs_part_failed`, `filters_packs_impact_failed`): sharing `filters_part_failed` or one key between the two moved messages into shared chunks (+106 B on the first view, +105 B on the dialogs). "Filters packs list (on demand)" is now 1.85 kB (measured 1.79; the catch costs ~0.11 kB), still the one raised limit.
- **Unsaved override edits** survive a reload; the editor is seeded again only when the stored action or `unless` changes.
- Changelog heading renamed "Changelog" (it duplicated "What changed" in the done dialog); changelog entries keyed by index.
