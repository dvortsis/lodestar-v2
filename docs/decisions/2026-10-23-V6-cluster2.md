# V6-cluster2 decisions: cluster transport, protocol, heartbeats and fencing

Remote workers v1, PR 2 of 6 (`docs/build-plan.md` P4; architecture §19.2, §19.3, §19.6, §19.8). Builds on `2026-10-22-V6-cluster1.md`. Everything is in `crates/cluster`; wiring it into `lodestar serve` and `lodestar worker` is the runner's (hooks listed at the end).

## Transport and frames
- **WebSocket over the cluster1 mutual-TLS configuration** on the cluster port, path `/cluster` (anything else gets 404). `tokio-tungstenite` runs over a `tokio-rustls` stream; the TLS side, ALPN choice and certificate checks stay cluster1's (`CoordinatorTls::config_for`, `identify`).
- **A frame is one WebSocket binary message:** a format byte (0 postcard, 1 zstd-compressed postcard), then the message. Messages of 1 KiB or more (the batches) are compressed when that makes them smaller (level 3).
- **Strict, bounded decoding** (`frame.rs`): at most 1 MiB on the wire and 1 MiB decompressed; zstd limited to a 2^20-byte window and a single frame, read one byte past the cap and refused; no trailing bytes; then each message's `validate` limits (claims ≤ 512 keys, §19.2; outcomes and grants ≤ 1,024; opaque payloads ≤ 512 KiB; certificates ≤ 4 KiB). Every message within its limits fits in a frame (tested), so the in-process link needn't encode at all: its receiver runs the same `validate`.
- **"Never allocates past the cap"** is enforced by construction (the caps above; postcard only pre-allocates what the remaining input could hold) and checked by the `cluster_frame` fuzz target under `-malloc_limit_mb=8`: 2.8 M runs in 60 s, clean. A counting allocator in a unit test would need `unsafe`, which the workspace forbids.
- **Protocol version:** `Hello` carries major and minor (`1.0`). Another major is refused with `Stop(VersionMismatch { coordinator_major })`; the worker refuses a `Welcome` with another major.
- **The join exchange is not a WebSocket.** On ALPN `lodestar-join/1` the worker sends one length-prefixed frame (`JoinRequest`: major, token text, public key; at most 1 KiB) and gets one (`JoinReply::Granted` or `Refused`). This keeps HTTP parsing off the only unauthenticated path. Every refusal is the same `Refused` (cluster1).

## Messages as implemented (§19.2)
| From → to | Message | Notes |
|---|---|---|
| W → C | `Hello` | major/minor, worker id (must match the certificate, else `Stop(IdentityMismatch)`), capabilities (cores, RAM, ≤ 8 external IPs, companions bitset, egress code) |
| C → W | `Welcome` | **added**: the accepted version, heartbeat interval, lease TTL, `renew_now` during a CA rotation |
| C → W | `Assign` | shape only: a revision and an opaque payload |
| C ↔ W | `Heartbeat` / `HeartbeatAck` | stats, clock-offset timestamps, lease count; the ack carries the offset estimate and the skew flag |
| W → C | `Claim` | batch id (never 0) and ≤ 512 keys with source, strategy, discovery time |
| C → W | `Grants` | one item per key: `Granted { token, ttl_secs }` or `Denied { Stored \| HeldElsewhere \| Draining }`; batch 0 carries re-grants |
| W → C | `Outcome` | key, fencing token, `Fetched \| PeerFound { reason } \| Lost { reason }` |
| W → C / C → W | `Renew` / `Renewed`, `RenewRefused` | **added**: certificate renewal over the session |
| C → W | `Drain`, `Stop(reason)` | reasons: revoked, version, identity, protocol, heartbeat timeout, drained, replaced, shutdown |
| W → C | `Drained` | **added**: the drain finished |
| stubs | `Results`, `Counters`, `HaveSnapshot`, `HaveDelta`, `Update` | opaque, size-capped, accepted and ignored until cluster3/cluster5 |

- **Grant and Deny are one reply message** (`Grants`) with a result per key, in claim order, rather than two messages: a claim batch usually gets both.
- **Peer hints aren't in `Claim` yet.** Relaying them to the holder in memory (§19.3) is cluster5's, with fetching.

## Coordinator: before and after authentication
- **Pre-auth limits** (`ServerConfig`): at most 256 connections in their handshake at once and 8 per address (IPv6 by /64, IPv4-mapped as IPv4); the excess is closed as soon as it's accepted and counted. The whole handshake (TLS, then the WebSocket upgrade, or the join exchange) has 10 s. Buffers: rustls' (a ClientHello ≤ 64 KiB), 16 KiB WebSocket reads, a ≤ 1 KiB join request.
- **Authenticated sessions don't count against the caps.** Workers behind one NAT share an address, and the number of sessions is bounded by the issued certificates anyway: one session per worker, a new connection replacing the old (`Stop(Replaced)`).
- **Identity before anything is read:** `identify()` right after the TLS handshake, before the WebSocket upgrade request; then `Hello` within the handshake timeout.
- **Concurrency:** one task per connection with a bounded queue (256) plus a one-slot stop channel; the fleet state (leases, sessions, offsets) behind a `std` mutex taken only for synchronous work; the PKI (store and secrets) behind its own mutex taken only inside `spawn_blocking`. No lock is held across an `.await`. A peer that doesn't read for three heartbeats is dropped (send timeout).

## Leases, heartbeats and clock offsets
- **The in-memory lease table** (cluster1's `LeaseTable`) is the authority. "Harvested" is counted at first grant; a repeated claim by the holder gets its own lease back; a claim for a key held elsewhere merges its source bit and is denied.
- **Heartbeats renew all of a worker's leases at once** (the table renews per worker, not per key). Heartbeats carry the worker's lease count, the ack the coordinator's, so either side can see drift. Per-key renewal lists would cost a heartbeat proportional to the leases held.
- **An outcome counts only with the current token from the current holder.** A stale token, a duplicate or another worker's report is ignored and counted (`stale_reports`); nothing is counted twice.
- **Expiry and re-grant:** each tick expires the leases of workers silent past the TTL (10 min) and grants the keys, with cohort, sources and strategy kept, to connected non-draining workers holding the fewest, as unsolicited `Grants` (batch 0). Keys wait in a queue while no worker is available. A session silent for three heartbeats (15 s) is closed, but its leases stand until the TTL, so a brief disconnect loses nothing.
- **Revocation and drain return leases at once** (§19.6): a revoked worker's leases, and any a draining worker still holds when it says `Drained`, go straight to re-grant.
- **Clock offset**, coordinator-side, NTP-style from four timestamps: the heartbeat's send time and our receive time, and our last ack's send time and the worker's receive time (echoed in the next heartbeat): θ = ((t0 − t1) + (t3 − t2)) / 2, cancelling symmetric latency; before the first echo, θ ≈ t0 − t1. More than 60 s is flagged once (`skewed` in the ack, a `ClockSkewed` event on the worker, the snapshot's flag). Claimed discovery times are corrected by θ before the lease records them (§19.3).
- **A controllable clock** (`Clock`, `ManualClock`, `OffsetClock`) drives leases, heartbeats, offsets and certificate validity on both sides; ticks and heartbeats can be driven by hand (`auto_tick`, `auto_heartbeat`). The tests assert outcomes, never durations; wall-clock time is only hang guards and the pre-auth timeout.

## Revocation and the shared PKI (§19.8)
- **Chosen: the server reloads the PKI from the store on every heartbeat tick** (`Coordinator::reload`), rather than a single PKI owner with CLI commands routed through the running server. The store is already the source of truth, and cluster1 already made spending a token safe with two coordinators on one database. Reloading needs no IPC or API endpoint, works for the API and a CLI process alike, survives crashes, and costs one indexed read of the `cluster.` rows every 5 s. A SHA-256 digest of the rows skips the parse when nothing changed. Redeem and renew reload first, so a token made by the CLI redeems at once.
- **Every tick then checks each open session's certificate** (`CoordinatorTls::still_valid`: on record, not revoked, not expired) and stops the session with `Stop(Revoked)`: revocation from any process closes the connection within one heartbeat. `ClusterServer::revoke` applies at once without waiting for a tick.
- **A failed reload keeps the state in memory** and is counted (`pki_errors`); the next tick tries again. A transient `SQLITE_BUSY` shouldn't drop the fleet; the counter makes a persistent failure visible.

## Carry-forwards from #96
- **Renewal is rate-limited:** at most once an hour per worker (`RENEW_MIN_INTERVAL_SECS`, measured from the worker's newest certificate), so a worker can't pile up 72-hour `cluster.cert.*` rows. A worker on a CA being rotated out may renew onto the new CA at once, once.
- **`maintain` runs hourly from the tick** (`maintain_every_secs`), so the coordinator's own 72-hour leaf renews at half-life.
- **Re-sealing on a secrets-key rotation:** `Coordinator::reseal` rewrites the CA, previous-CA and coordinator key records under the primary key in one transaction; `Credentials::reseal` does the worker's file. The rotation order is `SecretStore::rotate` → `reseal` → `SecretStore::retire_old_keys` (tested both ways: with the reseal the PKI opens, without it it doesn't).
- **The join token comes from a file or stdin, not argv or the environment** (§13): `read_join_token` (first non-blank line, ≤ 1 KiB, zeroed buffers) and `read_join_token_file`. This refines §19.6's `--token …` example; the CLI form becomes `lodestar worker --join https://coord:8091 --token-file <path>` (`-` for stdin), which also fits Docker secrets.

## Deferred
- **Persisting outstanding leases** with the fetch queue (§19.3) needs the store's fetch queue; `LeaseTable::restore` exists for it. cluster5, with fetch and prepare on workers.
- **Have-filter replication** (`HaveSnapshot`/`HaveDelta`): cluster3. **Sharded DHT and `Assign` contents:** cluster4. **`Results`, `Counters`, peer-hint relay, the spool and its replay:** cluster5. **The chaos harness and the §19.8 gates** (grant latency, RSS, multi-worker exactly-once under kills and partitions): cluster6.
- **Signed `Update` offers** (§19.6): after the update catalogue exists.

## Hooks for the runner (not wired here)
- `lodestar serve`: open `Coordinator`, build `ClusterServer::new(Pki { coordinator, store, secrets }, Arc::new(SystemClock), ServerConfig::default(), Some(stored_check))`, bind the cluster port (default 8091) and spawn `server.serve(listener)`; run the built-in worker through `server.connect_local()` and `WorkerSession::start`.
- `lodestar worker --join <url> --token-file <path|->`: `read_join_token_file` / `read_join_token(stdin)`, `Joining::new`, `client::join`, `Credentials::save`; afterwards `Credentials::load`, `connect`, `WorkerSession::start`, renewing at half-life with `begin_renewal` / `WorkerSession::renew` / `Credentials::renewed`.
- The secrets-key rotation command: call `Coordinator::reseal` (and `Credentials::reseal` on workers) between `rotate` and `retire_old_keys`.
- Settings → Workers: `ClusterServer::snapshot`, `create_join_token`, `revoke`, `drain`.
