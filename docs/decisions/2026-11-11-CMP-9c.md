# CMP-9c decisions

The wizard's "Install qBittorrent for me" option (plan `docs/plan/2026-11-06-v06-companions.md` CMP-9c; architecture §10.10.10, §18.10). None loosens an owner or security decision.

- **Native is what the server says.** The option shows only when `GET /companions` lists `qbittorrent` with `refusal: null`, an `available` version and no `installed` version. Docker and Unraid (`native_in_container`), Windows (`guided_only`) and unsupported systems get no option and no error. Companions off (`503`) hides it too. The UI never reads the user agent.
- **Offer, then confirm.** `GET /companions/qbittorrent/install` fills the confirmation (program, version, licence, size, SHA-256). "Where it runs" is fixed text: native installs always run on this computer, started by Lodestar (the offer has no such field). `POST` sends the offer's own `version` and `sha256`, unchanged, only after the user confirms.
- **Progress is one waiting state.** The install route answers once, when the install has finished, and there is no progress or cancel route. So the step shows a busy button and a banner, with no cancel button, rather than a made-up percentage.
- **Failures** map the server's refusal codes to plain sentences; an unknown code gets a generic one. Retry always fetches a fresh offer.
- **Afterwards.** The step re-reads its client field after an install. On `main` a native install does not yet hand qBittorrent to Integrations: only the guided path calls `configure::hand_over` (CMP-5g-3's decisions file says so). That hand-over is the core slice X-cmp-native-handover (runner's call, §2.26), and this PR's merge waits on it. Until it lands, the done note ("It's now your download client") isn't accurate; it becomes true when the hand-over merges, so the text stays as it is. The install reply carries no credential and the step never calls reveal; Settings → Companions (CMP-9a) is where Q5's reveal lives.
- **Mid-install.** Continue refuses while the install runs and says why. Back and Skip belong to the shell (`WizardPage`), which this slice doesn't own: they stay enabled, and the install carries on in the server.
