# CMP-0 decisions (CMP-0a, then CMP-0)

The companions crate, its contracts and the catalogue (plan `docs/plan/2026-11-06-v06-companions.md` §4.3, CMP-0). These are refinements, decided by the slice or the runner and flagged to the owner by the runner (owner §2.19). None of them loosens an owner decision.

## CMP-0a: the crate, input types and adapter traits
- **CMP-0 is split in two (runner, 2026-11-06T17:37Z).**
  - **Why:** the combined change was about 3,650 lines, over the ~3k line where the runner splits a slice (CLAUDE.md, multi-session work). It's also a 2R slice of security-sensitive validation, and each of the two reviewers reads a smaller PR more closely.
  - **CMP-0a, this part:** the crate skeleton, `inputs.rs`, `adapter.rs` and the binary's log registration.
  - **CMP-0, after 0a merges:** the catalogue, its data and its tests. It keeps the id CMP-0, so the slices that depend on it don't change.
- **`CompanionId` and `Version` live in `inputs.rs`.** Both the adapter traits (0a) and the catalogue (CMP-0) need them, and a version is also read from a companion's own answers, so it gets the same strict grammar as the other closed inputs. A version is 1–4 dot-separated numbers with no leading zeros.
- **`HostPath` refuses more than the plan lists, and refuses parents too** (both 2R reviews, 2026-11-06T18:49Z). A folder exposes everything below it, so each refusal covers every folder that contains a refused one. Refused:
  - `/` and the system folders (`/bin`, `/boot`, `/dev`, `/etc`, `/lib*`, `/opt`, `/proc`, `/root`, `/run`, `/sbin`, `/snap`, `/sys`, `/usr`);
  - **all of `/var`, except strictly below `/var/lib/lodestar/companions` and `/var/spool/lodestar`.** That keeps out `/var/run`, where the Docker socket may live, `/var/lib/docker` (Docker's own state), and **Lodestar's own data folder**: the systemd unit's `/var/lib/lodestar`, with `secrets.key`, which seals every stored credential, and the database. A mounted data folder would also hand that key to a third-party container. A linuxserver.io image's init runs `chown -R` on its config folder, which would take the folder away from Lodestar;
  - `/home` and `/home/<user>`, which hold `~/.docker` (Docker Desktop's and rootless Docker's socket);
  - **under `/mnt`:**
    - anything shorter than `/mnt/<pool>/<share>`, so `/mnt/user` can't expose `system/docker/docker.img`;
    - Unraid's `system` share on any pool;
    - the `appdata` share itself, which holds every container's config;
    - `appdata/lodestar` and `appdata/lodestar-worker` (the Unraid template's data folders), except strictly below their `companions` folder. Share and folder names compare without case;
  - any `*.sock` and any `.docker` folder.

  **What it can't see:** the check is on the path as typed, for another machine. **CMP-7 must also refuse a path inside the running instance's real data folder,** because a custom `LODESTAR_DATA_DIR` can be anywhere. Symlinks can't be seen either, so CMP-7's output and the guide say to mount real folders only.
- **`ContainerName` can't be an address or a domain.** It's looked up as a host through `Target::Container`. So it's a lower-case letter, then `[a-z0-9_-]`, with no `.`: `169.254.169.254`, `2130706433` and `qbit.example.com` are refused. `NetworkName` keeps Docker's own rule, because it's never a host.
- **The values are safe once quoted, not bare.** A `HostPath` may hold a space, and a name may read as a YAML 1.1 keyword or number. The crate README carries CMP-7's contract:
  - quote every YAML key and value (`serde_json`), and write XML through `quick-xml`;
  - pass values as separate arguments, never in a shell line;
  - golden-test the YAML 1.1 keywords;
  - give `TZ` and `UMASK` closed types or hard-code them.
- **`Puid` and `Pgid` refuse `0`,** so a generated container never runs its program as root. Ports start at 1024.
- **A network name refuses `host`, `none`, `default` and `bridge`.** `NetworkMode` can express only a named network or `service:gluetun`.
- **The adapter traits return closed values and reach companions only through `GuardedHttp`.**
  - **Shape:** they're object-safe, async through boxed futures, so no macro crate is needed.
  - **The guarded client is a parameter** (`&dyn GuardedHttp`), so CMP-8a won't need to change the signatures later. The SSRF guard, the timeout and the byte cap are types, not doc comments:
    - every `ProbeRequest` carries `Limits`: a timeout of 100 ms to 30 s and a cap of 1 B to 1 MiB. `Limits::PROBE` is 5 s and 64 KiB, the slice's numbers for detection and health;
    - a `ProbeResponse` can't be built over its cap;
    - request paths refuse `//`, `.` and `..` segments, including the `%2e` forms;
    - a credential stays a `Secret` header value.
  - **They return:**
    - a strict `Version`;
    - a `HealthStatus`;
    - an `AdapterError` that carries only the code's own words, never response text.
  - **`Configure::apply` refuses a plan made for another companion** before anything is sent. Implementations write `apply_plan`. A configuration plan lists setting names (`SettingKey`), never values.
  - **`Credentials::get` returns `Result<Option<Secret>, CredentialError>`,** so a broken store is never mistaken for a missing credential.
  - **`EnteredUrl` checks shape only:**
    - RFC 3986 characters with well-formed `%` escapes;
    - a non-empty host of letters, digits, `.` and `-`, or bracketed IPv6;
    - a port of `1..=65535`;
    - no user information.

    Its `Debug` hides the address. Where it points is the SSRF guard's call at connect time (CMP-8a). It's never rendered into a template.
- **`serde` and `serde_json` aren't in this half.** Nothing in CMP-0a parses JSON, so CMP-0 adds them, exact-pinned, as its catalogue parser needs them. The `testing` feature is declared now, with nothing behind it yet. CMP-0 puts the catalogue override behind it.
- **The crate is registered with the binary's logging now (runner-approved shared edits).**
  - **Why:** a new workspace crate needs a `logging::TARGETS` line (`targets_cover_every_crate`), and its log catalogue needs a `logging::CATALOGUES` line (`every_declared_catalogue_is_registered`). Both lines need `lodestar-companions` as a dependency in `crates/lodestar/Cargo.toml`. CMP-0a's `owns` lists all three.
  - **The event:** `companions.catalogue_invalid` is declared now: `Error` level, required, carrying only the rule's code. CMP-0's loader emits it.
  - **Its name and help in Settings → Logs:** `web/src/lib/features/settings/logging/event-names.ts` and the feature's `en.json` and `zh.json` gain the new event's id only (`event-labels.test.ts` requires every catalogued event to be named). The golden `crates/lodestar/src/settings/golden/logs_catalog.txt` is regenerated with `LODESTAR_BLESS=1`. The runner approved both as part of the same shared edit. `web/licenses/rust.json` gains the crate's name too, regenerated with `python3 .github/scripts/licenses.py` (owner §2.12: the shipped-licence list must match the binary's crates).

## CMP-0: the catalogue
- **The compiled-in v0.6 entries ship awaiting their pins** (runner, 2026-11-06T17:13Z).
  - **What's in each entry:** qBittorrent, Prowlarr and gluetun carry their structure, per owner §2.47 cq6: platforms, archive kinds, hosts, image names, ports, health and templates. Every `pin` and `digest` is `null`.
  - **Why:**
    - pins are CMP-13's output (plan §4.3: "every `catalogue.json` pin came from CMP-13's tool");
    - this session couldn't reach github.com or the registries, so any pin written here would have been unverified;
    - waiting for a pin is the fail-safe state: nothing runs until a pin that has been checked against upstream lands (§18.10, owner §2.46 cq2).
  - **"Awaiting pin" is its own state:** `Pinned::AwaitingPin`, never an empty or placeholder hash.
    - The hash accessors hand one out only when pinned.
    - `Entry::installable` and `Entry::renderable`, which CMP-1, CMP-5 and CMP-7 use, refuse an unpinned build or image with `NotAvailable::AwaitingPin`.
    - Tests check that every shipped entry is awaiting its pin and is refused.
  - **For CMP-13 and CMP-G, a requirement:** a release must not ship a catalogue that offers to install anything still awaiting its pin. That gate belongs to CMP-13's release-workflow step; CMP-0 doesn't build it.
  - **For CMP-13's brief:** its pins land in `crates/companions/data/catalogue.json`. Its first pin also has to change `tests/catalogue.rs`'s `builtin_entries_await_their_pins_and_are_refused`, which asserts that every shipped entry is still awaiting its pin. Both files need to be in CMP-13's `owns` or listed as its shared edits.
- **Validation is stricter than plan §4.3 lists.**
  - **Hosts:** an entry's download hosts must also be in a code-level `DOWNLOAD_HOSTS`, and images must come from `REGISTRIES` (`lscr.io`, `ghcr.io`, `docker.io`, per cq6). So adding a host is a code change with its own review.
  - **URLs:** `https` with no port, user information, query, fragment or percent-encoding.
  - **Archives:**
    - the archive kind must match the file name. A bare binary has no extension on Linux and exactly `.exe` on Windows;
    - executables stay inside the archive and end in `.exe` exactly on Windows. They have no all-dot component, no trailing `.` and no Windows device name;
    - installers are Windows-only.
  - **Pins:** all pins in an entry name the same version, written identically. A SHA-256 of one repeated digit is refused as a placeholder.
  - **Ports and health:**
    - ports start at 1024;
    - only a download client may publish (`p2p`) a port;
    - health uses an internal TCP port.
  - **Needs:**
    - `challenge_solver` requires `opt_in` (owner §2.47, Q21);
    - `vpn_route` is container-only, because the native VPN is v1.x (plan §2).
- **The licence URL and homepage hosts aren't restricted** to the allowlist. They're shown as links only and never fetched.
- **The validated catalogue types can only be read outside the crate.** They're `#[non_exhaustive]` and not `Clone`, the catalogue's entries are private, and `Sha256`'s bytes are private. So a later crate holds only shared references to what validation built: it can't write a struct literal, or clone a value and change a field. Compile-fail doctests check both. Field reads stay public.
- **`MAX_ARTIFACT_SIZE` is 512 MiB** (536,870,912 bytes), reading plan Q16's "512 MB" as binary megabytes.
- **gluetun's service must be named `gluetun`.** The VPN route is written as `network_mode: service:gluetun` (`NetworkMode::ServiceGluetun`), so a `vpn_route` entry's container name is fixed. File extensions (`.exe`, `.zip`, …) compare without case.
- **`builtin()` parses once and logs `companions.catalogue_invalid` on failure,** through `load()`, which is tested on bad text. It's lazy, so CMP-5's wiring calls it while services start, so a bad catalogue is logged at start rather than on first use.
- **A fourth archive kind, `binary`.** The plan lists `zip|tar.gz|installer`. But the userdocs static `qbittorrent-nox` (cq6) is published as a bare executable, so `binary` means "the downloaded file is the program". CMP-2 installs it without extracting.
- **`upstream_sig` takes two forms:** `none`, or `verified_at_pin` with the upstream key's OpenPGP fingerprint, which records what CMP-13 checked (cq2). A run-time minisign form is left for when a companion publishes minisign signatures.
- **Template ids are a closed enum:** `qbittorrent_conf`, `prowlarr_config_xml`, `compose_service` and `unraid_template`. An id with no writer behind it is refused.
- **Health notes for CMP-8a:**
  - gluetun's entry has no `health`, because its control-server routes and their authentication vary by version. CMP-8a's fixtures settle it as a one-line catalogue edit.
  - qBittorrent's `/api/v2/app/version` answers 403 without a session unless localhost authentication is bypassed. CMP-8a treats an authenticated 403 as "answered".

## CMP-0: findings from CMP-0a's delta review (runner, 2026-11-06T19:26Z)
The runner put these into CMP-0 as required items, so CMP-0's `owns` also lists `inputs.rs`, `adapter.rs`, the crate README and `lib.rs`.
- **`ContainerName` refuses the names a container resolves from its own `/etc/hosts`** before Docker's DNS (`localhost*`, `ip6-*`), and Lodestar's own names (`lodestar`, `lodestar-worker`).
- **Header injection is closed.**
  - Every header value, a credential included, is built through a checked constructor that refuses CR, LF, NUL and other controls.
  - Header names refuse framing, target and hop-by-hop names (`Host`, `Content-Length`, `Transfer-Encoding`, `Connection`, `Keep-Alive`, `Proxy-*`, `TE`, `Trailer`, `Upgrade`, `Expect`) in any case.
- **`RequestPath` refuses encoded separators:** `%2f`, `%5c` and `;` before the query, and `%00` anywhere.
- **`EnteredUrl` refuses `?` and `#`.** It's a base that request paths are joined to, so a query or fragment would swallow them.
- **The plan check can't be skipped.** `apply` is an inherent method on `dyn Configure`, so implementations can't override it, and implementations receive a `CheckedPlan` that only it can construct.
- **`HostPath` refuses dot-folders directly under `/home/<user>`** (`~/.ssh`, `~/.local`, `~/.config`), and every comparison now ignores case. A deterministic test checks that every folder towards each sensitive path, the path included, is refused in mixed case.
- **For CMP-7's brief:**
  - Under Docker, Lodestar sees `/data`, not the host folder, so `HostPath` can't recognise Lodestar's own data folder there. `/srv/lodestar`, `/data/lodestar` and `$PWD/data` all pass.
  - So CMP-7 must take the host data path from the Unraid template's values or from the user, cover Unraid's optional hot and cold data paths, and refuse a companion path inside any of them.
  - Natively, it checks against the real `LODESTAR_DATA_DIR` after `canonicalize`.
  - It also refuses a companion's path inside another catalogue companion's `appdata/<name>` folder or host data path. `HostPath` accepts `/mnt/user/appdata/prowlarr`, which is right for Prowlarr, but a qBittorrent container given it could read Prowlarr's `ApiKey`.
- **Also from the fresh review:** header names refuse every `Proxy-*`. Request paths refuse `%25` before the query, so a server that decodes twice can't be steered. Container names refuse a container-id-shaped name (12 or 64 hex digits), since that's the container's own hostname in `/etc/hosts`.
