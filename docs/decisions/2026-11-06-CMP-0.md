# CMP-0 decisions (CMP-0a, then CMP-0)

The companions crate, its contracts and the catalogue (plan `docs/plan/2026-11-06-v06-companions.md` §4.3, CMP-0). These are refinements, decided by the slice or the runner and flagged to the owner by the runner (owner §2.19). None of them loosens an owner decision.

## CMP-0a: the crate, input types and adapter traits
- **CMP-0 is split in two (runner, 2026-11-06T17:37Z).**
  - **Why:** the combined change was about 3,650 lines, over the ~3k line where the runner splits a slice (CLAUDE.md, multi-session work). It's also a 2R slice of security-sensitive validation, and each of the two reviewers reads a smaller PR more closely.
  - **CMP-0a, this part:** the crate skeleton, `inputs.rs`, `adapter.rs` and the binary's log registration.
  - **CMP-0, after 0a merges:** the catalogue, its data and its tests. It keeps the id CMP-0, so the slices that depend on it don't change.
- **`CompanionId` and `Version` live in `inputs.rs`.** Both the adapter traits (0a) and the catalogue (CMP-0) need them, and a version is also read from a companion's own answers, so it gets the same strict grammar as the other closed inputs. A version is 1–4 dot-separated numbers with no leading zeros.
- **`HostPath` refuses more than the plan lists, and refuses parents too** (both 2R reviews, 2026-11-06T18:49Z). A folder exposes everything below it, so each refusal covers every folder that contains a refused one. Refused:
  - `/` and the system folders (`/bin`, `/boot`, `/dev`, `/etc`, `/lib*`, `/opt`, `/proc`, `/root`, `/run`, `/sbin`, `/snap`, `/sys`, `/usr`);
  - **all of `/var`, except strictly below `/var/lib/lodestar/companions` and `/var/spool/lodestar`.** That keeps out `/var/run`, where the Docker socket may live, `/var/lib/docker` (Docker's own state), and **Lodestar's own data folder**: the systemd unit's `/var/lib/lodestar`, with `secrets.key`, which seals every stored credential, and the database. A mounted data folder would also hand that key to a third-party container. A linuxserver.io image's init runs `chown -R` on its config folder, which would take the folder away from Lodestar;
  - `/home` and `/home/<user>`, which hold `~/.docker` (Docker Desktop's and rootless Docker's socket);
  - **under `/mnt`:**
    - anything shorter than `/mnt/<pool>/<share>`, so `/mnt/user` can't expose `system/docker/docker.img`;
    - Unraid's `system` share on any pool;
    - the `appdata` share itself, which holds every container's config;
    - `appdata/lodestar` and `appdata/lodestar-worker` (the Unraid template's data folders), except strictly below their `companions` folder. Share and folder names compare without case;
  - any `*.sock` and any `.docker` folder.

  **What it can't see:** the check is on the path as typed, for another machine. **CMP-7 must also refuse a path inside the running instance's real data folder,** because a custom `LODESTAR_DATA_DIR` can be anywhere. Symlinks can't be seen either, so CMP-7's output and the guide say to mount real folders only.
- **`ContainerName` can't be an address or a domain.** It's looked up as a host through `Target::Container`. So it's a lower-case letter, then `[a-z0-9_-]`, with no `.`: `169.254.169.254`, `2130706433` and `qbit.example.com` are refused. `NetworkName` keeps Docker's own rule, because it's never a host.
- **The values are safe once quoted, not bare.** A `HostPath` may hold a space, and a name may read as a YAML 1.1 keyword or number. The crate README carries CMP-7's contract:
  - quote every YAML key and value (`serde_json`), and write XML through `quick-xml`;
  - pass values as separate arguments, never in a shell line;
  - golden-test the YAML 1.1 keywords;
  - give `TZ` and `UMASK` closed types or hard-code them.
- **`Puid` and `Pgid` refuse `0`,** so a generated container never runs its program as root. Ports start at 1024.
- **A network name refuses `host`, `none`, `default` and `bridge`.** `NetworkMode` can express only a named network or `service:gluetun`.
- **The adapter traits return closed values and reach companions only through `GuardedHttp`.**
  - **Shape:** they're object-safe, async through boxed futures, so no macro crate is needed.
  - **The guarded client is a parameter** (`&dyn GuardedHttp`), so CMP-8a won't need to change the signatures later. The SSRF guard, the timeout and the byte cap are types, not doc comments:
    - every `ProbeRequest` carries `Limits`: a timeout of 100 ms to 30 s and a cap of 1 B to 1 MiB. `Limits::PROBE` is 5 s and 64 KiB, the slice's numbers for detection and health;
    - a `ProbeResponse` can't be built over its cap;
    - request paths refuse `//`, `.` and `..` segments, including the `%2e` forms;
    - a credential stays a `Secret` header value.
  - **They return:**
    - a strict `Version`;
    - a `HealthStatus`;
    - an `AdapterError` that carries only the code's own words, never response text.
  - **`Configure::apply` refuses a plan made for another companion** before anything is sent. Implementations write `apply_plan`. A configuration plan lists setting names (`SettingKey`), never values.
  - **`Credentials::get` returns `Result<Option<Secret>, CredentialError>`,** so a broken store is never mistaken for a missing credential.
  - **`EnteredUrl` checks shape only:**
    - RFC 3986 characters with well-formed `%` escapes;
    - a non-empty host of letters, digits, `.` and `-`, or bracketed IPv6;
    - a port of `1..=65535`;
    - no user information.

    Its `Debug` hides the address. Where it points is the SSRF guard's call at connect time (CMP-8a). It's never rendered into a template.
- **`serde` and `serde_json` aren't in this half.** Nothing in CMP-0a parses JSON, so CMP-0 adds them, exact-pinned, as its catalogue parser needs them. The `testing` feature is declared now, with nothing behind it yet. CMP-0 puts the catalogue override behind it.
- **The crate is registered with the binary's logging now (runner-approved shared edits).**
  - **Why:** a new workspace crate needs a `logging::TARGETS` line (`targets_cover_every_crate`), and its log catalogue needs a `logging::CATALOGUES` line (`every_declared_catalogue_is_registered`). Both lines need `lodestar-companions` as a dependency in `crates/lodestar/Cargo.toml`. CMP-0a's `owns` lists all three.
  - **The event:** `companions.catalogue_invalid` is declared now: `Error` level, required, carrying only the rule's code. CMP-0's loader emits it.
  - **Its name and help in Settings → Logs:** `web/src/lib/features/settings/logging/event-names.ts` and the feature's `en.json` and `zh.json` gain the new event's id only (`event-labels.test.ts` requires every catalogued event to be named). The golden `crates/lodestar/src/settings/golden/logs_catalog.txt` is regenerated with `LODESTAR_BLESS=1`. The runner approved both as part of the same shared edit. `web/licenses/rust.json` gains the crate's name too, regenerated with `python3 .github/scripts/licenses.py` (owner §2.12: the shipped-licence list must match the binary's crates).
