# CMP-9a decisions

Settings → Companions (plan `docs/plan/2026-11-06-v06-companions.md` CMP-9a; architecture §10.10.8, §18.10). None loosens an owner decision or weakens a security decision. The runner flags the refinements to the owner (§2.19). Items 3 and 4 touch budgets and need the runner's call (§2.26).

- **The screen shows only what the server says.** Every request is built from a server reply: the install request echoes the offer's `version` and `sha256` and nothing else; the removal request echoes the companion's id. A failed or refused request leaves the list as it was.
- **The install confirmation shows** program, version (and the version it replaces), licence, download size, SHA-256 and where it runs, then waits for a press of Install. "Where it runs" is one fixed sentence (on this computer, started and stopped by Lodestar): the offer has no field for it, so it is the client's wording of what an install always does; a server-supplied field would be better (a small API addition, for the runner). It does not claim the companion is unreachable from elsewhere, since qBittorrent exposes its peer port. A companion in a container is refused by the server (`native_in_container`) and the screen says so in words, with the template panel as the way forward.
- **Credentials.** A reveal asks for the admin password every time (the server's rule, Q5), shows the value until Hide, and drops it on Hide, on regenerate and when the panel closes. The typed password is cleared on send and never rendered. A pasted temporary password goes in a `type="password"` field with autocomplete off, is cleared the moment it is sent, and is never echoed, kept or put in an error. The paste is offered only for a companion that isn't installed by Lodestar and whose refusal is `guided_only` (the server refuses it anywhere else, in words).
- **Egress (API gap, runner informed).** No HTTP route reads or writes `companions.<id>.egress`, and `Companion` has no route field, so this slice has no egress editor and cannot tell whether Prowlarr is on SOCKS5. It says, on each companion that takes a route, that the route is copied from the source that needs it at the companion's first start and that a later change to that source's route doesn't reach it (`egress_setting` in `crates/lodestar/src/companions.rs` reads the companion's own saved row once it exists), so it keeps the route it started with. On Prowlarr and FlareSolverr it always shows the SOCKS5 notes, worded "if this companion's route uses a SOCKS5 proxy": email notifications connect directly (leave them off), a FlareSolverr pairing leaves directly, and per-indexer proxies bypass the route (`2026-11-11-X-cmp-egress-prelaunch.md` lines 38–43). An editor and live warnings need a `crates/` change first.
- **Refusals are words.** Each stable code has a sentence; an unknown code gets a generic sentence that prints neither the code nor the server's text. Log lines are text nodes in a `<pre>`, never HTML.
- **Platform differences come from the API** (`refusal`, `templates`), never the user agent.
- **Registry:** the screen registers in the Crawling group after Jobs (§10.10.2's order already lists `companions`). The icon and the purpose line share one module (`icon.ts`) to keep the registry entry small. `settings_about_conn_companions` is relabelled "Companion downloads" (Q1(a)).
- **Shared edits outside the brief's `owns`** (each needed to keep a gate green): `shell/screens.test.ts` and `shell/SettingsShell.test.ts` list the registered screens, so each gains `companions`; `web/.size-limit.mjs` registers the screen's body, icon module and lazily loaded dialogs and panels like Updates' (a first-view line, "parts" and "icon and purpose" on-demand lines). Budgets: the first view measures 32.5 KB (limit 33 KB); the dialogs and panels (Dialog's code, the credential, log and template panels) load on first use, 27.3 KB (limit 28 KB). **The registry entry costs ≈ 80 B on every Settings first view; "Settings section" had 20 B of headroom at the §10.1 45 KB cap, so its limit moves to 45.1 KB (measured 45.06 KB) (Notifications stays at 45.1 KB, measured 45.09 KB).** That is a change to an owner-set number: the runner decides (§2.26).
- **The e2e spec is `web/e2e/companions.routes.test.ts`,** not `companions.spec.ts`: no Playwright project matches `*.spec.ts`, so that name would never run.
- **Not built:** the guided plan/confirm flow and "forget" (the wizard, CMP-9c), and the dependency chip (CMP-9b).
- **Download size** is formatted by a small local IEC formatter (`bytesText`, same output as `formatBytes`), not `src/lib/format`: importing the shared formatter (statically or lazily) splits its chunk and adds ≈ 120 B to the Alert, detail-drawer and `/t` routes, which sit at their §10.1 caps, or pulls the whole barrel into the Settings graph. Runner to decide whether to keep it.
- **Templates** offer the server's `route` (direct, new gluetun, existing gluetun with its container name) and the two host folders, warn that "direct" leaves outside any VPN, and show the Unraid add-container path and filled fields. `puid`, `pgid` and `network` keep the server's defaults.
- **A detected companion** is added with the exact target the server found (`POST /target`), never a guessed address. After a restart the row is refreshed every 3 s for up to a minute until it reports healthy. After an install or a removal focus goes to the row's name.
