# X-event-names-split decisions

Splits the on-demand log event-names chunk by component. Brief: runner, 2026-11-11.

- **One chunk per catalogue component** (`logging/event-names/<component>.ts`, generated by `scripts/event-names.mjs`), plus a generated loader map `event-names.ts`. A label loads only its component's chunk; an unknown component or id keeps showing the stable id, as before.
- **Rows render only in an open group** (`EventList.svelte`, outside the brief's owned paths but needed for it): a closed group's rows would otherwise ask for every chunk on first render. Searching or "changed only" opens the groups it shows, so a search loads the chunks of the groups with matches.
- **Budgets (runner §2.26, performance):** the single 16.6 KB budget becomes 12 per-chunk budgets, each measured + ~10% (`eventNamesLimits` in `.size-limit.mjs`). A component without a budget fails the config, as does a budget for a component that no event has. The chunks total about 19.3 KB gzipped against 15.1 KB for the one chunk, since each compresses alone; they are on demand, so the §10.1 first-load budget is unchanged.
- **"Settings logging parts (on demand)" 17.15 → 17.55 KB:** the loader map and the own-key lookups (about 0.31 KB) live in the event list's chunk.
- **Component ids must match `[a-z][a-z_]*`** (they become a file name, an object key and a size-limit pattern); the generator refuses others.
