# ENR-terms decisions

Slice ENR-terms (runner brief, 2026-11-16). The runner decided, under §2.19/§2.69, that the identify harness enforces each lookup service's terms with strict defaults before any lookup plugin is wired into the host. The decision is in the runner's comments on #948, #938 and #954. It's stricter than the owner's Q12 and was flagged to the owner. Spec: `docs/decisions/2026-11-12-ENR-10.md`, architecture §6, §18.2 and §18.7.

## Terms, with strict defaults
- **`Identifier::terms() -> &Terms`** is a provided method returning `Terms::STRICT`, so existing `Manifest` literals and plugin impls keep compiling (runner, 2026-11-16). `Terms` lives in `lodestar_sources::terms` and is re-exported from `identify`. A plugin that says nothing gets:
  - **`background_walk: false`:** only the items you open, within its rate cap and the day's count;
  - **`redistribute: false`:** its answers stay in Lodestar's own UI;
  - **`retention: Retention::DEFAULT`:** 180 days;
  - **`attribution: None`;**
  - **`adult_marker_required: true`.**
- **The ages are derived from `max_age`** (runner, 2026-11-16):
  - **refresh after `max_age − 30 d`**, never under half of it: 150 days by default. The next user interest past that age asks again, whatever the cache holds.
  - **drop at `max_age − 1 d`:** 179 days by default. The sweep drops the claim even if nobody opens the item, so a sweep that runs a little late still drops it before the limit.
  - **TMDB's six months** is 180 days as a hard limit. The shortest six months is 181 days, so dropping at 179 meets the rule with two days' margin.
  - A `max_age` under 2 days reads as 2 days, so the drop margin always fits.
- **Adult marker:** `Identification` gains `pub adult: Option<bool>`, the service's own marker (runner, Q2).
  - Marked adult (`Some(true)`) is always refused.
  - Unmarked (`None`) is refused unless the plugin's terms opt out.
  - A refused answer counts as a miss (`stats.refused_adult` and `missed`), emits nothing, and drops the plugin's old claim on that item.
  - The marker is never stored.
  - A full `Identification { … }` literal without the field doesn't compile. That's deliberate: every plugin has to declare its marker.

## Runtime enforcement (`lodestar_pipeline::identify`)
- **Background walk:** `IdentifySource::new` forces `Config.background` off unless the terms allow a walk, whatever the host sets. The per-day cap, the eligibility gate, consent and what may be sent (ENR-10 Q5) are unchanged.
- **Retention needs each claim's age.** Schema **V15** adds `torrent_claims.stored_at` (Unix seconds) and the index `torrent_claims_stored (source_id, stored_at)` (runner, Q1).
  - Every claims write through `write_claims` stamps the row. Ingest's identification path calls the new `Store::put_claims_at(…, now)` with its own clock, the runtime's clock. Every other writer keeps `put_claims` and the store's clock.
  - A promotion that keeps an existing row (`ON CONFLICT DO NOTHING`) leaves its stamp, and a finder's claims are never dropped by age.
  - A row written before V15 gets 0. No identify plugin has run on any store yet, and other sources' claims are never dropped by age.
- **The retention mark** is raised with a compare-and-set, so two connections can never move it back.
- **Refresh:** the plugin's own claim's `stored_at` is read only on a cache hit and on a miss, the two cases where it changes the outcome. A claim past the refresh age bypasses the cache and is asked again. If the read fails, the item waits; it isn't counted as ineligible. A miss, or a refused answer, drops the old claim (`Store::drop_claims`), so nothing is kept that a fresh lookup wouldn't give. A match replaces it and stamps it again.
- **The sweep (`identify::sweep_expired`):** one bounded step deletes at most `SWEEP_BATCH` (256) of the plugin's rows that are at or past the drop age, or stamped more than `FUTURE_SLACK_SECS` (1 hour) ahead of the clock, since such a row has no age that can be trusted. The slack is well under the one-day drop margin, so even such a row goes before its limit.
  - It never touches another source's rows: the delete is keyed by `source_id`.
  - It's resumable with no cursor: a deleted row no longer matches, so each step takes rows still due. The query has no order, and none is needed.
  - It doesn't check the source's state, so a disabled source's claims expire too.
  - Each torrent that lost a row is marked for the backfill in the same transaction, so a title it resolved goes too.
  - The bundled SQLite has no `DELETE … LIMIT` (`SQLITE_ENABLE_UPDATE_DELETE_LIMIT` is off), so the rows are chosen by a limited `SELECT` through the index first, then deleted by key.
- **Clock stepping back:** the sweep's clock is `max(now, high-water)`. The high-water mark is kept in the plugin's `source_state` (`enr10/clock`, which the plugin can't write), and the running runtime also advances it by monotonic time between sweeps. A wall clock that steps back can't keep a claim past its limit.
  - The cost: a clock set far in the future and then corrected makes the plugin's claims drop until real time catches up. That fails closed. `stats.clock_ahead` (runtime) and `Swept::clock_ahead` (host sweep) report it, so the status page can say so. Purging the source clears its state.
  - The mark is created by `record_terms` before the plugin first runs, so later writes never need a new state key and can't fail against the plugin's 1,024-key cap. A failed record counts in `stats.unrecorded`, and readers then take the strictest terms.
  - A refresh uses the same clock.
- **When the sweep runs:** the runtime sweeps at start and then every `SWEEP_EVERY` (10 minutes), sooner while a step comes back full. It sweeps whether or not the plugin may look anything up (consent, kill switch, the day's count).
  - **A source that isn't running** (disabled, paused, or its plugin gone from the build) has no runtime. So the host calls **`identify::sweep_recorded(store, now)`** once at start, before anything is served, so an install that was off for weeks drops expired claims first, and then on a timer (runner, 2026-11-16). It sweeps every source with a terms record, with the retention the record holds, whatever its state. The runner adds this to the notes of the slice that wires identify plugins into the host. Until a plugin is wired in, no identify claims exist.
- **Tests:** one per rule in `crates/pipeline/tests/identify.rs`:
  - the background walk;
  - the adult marker;
  - refresh and drop on a miss;
  - the runtime's sweep;
  - a bounded, resumable sweep with the clock stepping back;
  - redistribution;
  - the terms record, and tightened terms marking the served titles for the backfill;
  - the host's sweep of a source that isn't running;
  - a property test over random retention, claims (own and other sources, past and future stamps) and clock sequences that step back. After every sweep it checks that no claim of the plugin is at or past its drop age by the high-water clock, none is stamped beyond the slack, every other claim of the plugin is kept, and no other source's claim changes.

## Redistribution
- **`stored_title`** (the record's effective title, which search, Torznab and export serve) only reads an answer from a plugin whose terms allow redistribution (`identify::may_redistribute`).
  - The backfill has no list of the plugins, so `identify::record_terms` writes the plugin's `Terms::record()` to `enr10/terms` in its `source_state`, where the plugin can't write. The runtime calls it when it starts; **the host calls it when it registers the plugin**, whatever its source's state, so a build that tightens a plugin's terms applies them to a stopped source too.
  - When a record goes from redistributable to not, every torrent holding that source's claims is marked for the backfill (one statement through the source index), so a title already resolved leaves the served record. The mark comes before the record is written, so a failed mark is retried on the next call (tested).
  - A missing or unreadable record reads as not allowed. Before a plugin's first run there are no claims to read.
- **The paths I checked:**
  - **Torznab, export and search** never read claims. They serve the indexed record, whose plugin title comes only from `stored_title`, so the filter above covers them.
  - **`crates/integrations`** doesn't read claims.
  - **The detail API** (`crates/api/src/torrents.rs`: the Identified-as section and the provenance claim differences) serves claims to API-key and feed-token callers (`Viewer::Public`). Filtering it is **ENR-terms-api** (runner, Q3), so this PR doesn't touch `torrents.rs`.
- **ENR-10's `via_plugin` doesn't fire for ENR-10's own lookups** (ENR-10, "Effective title"), so today no plugin answer renames any record. The filter guards the path for when one does.

## Attribution
- **`Attribution { text, link, logo }`** is in the terms, and the runtime doesn't need it. **ENR-terms-api** carries it into the detail DTO and the Sources page through the ops catalogue, and **ENR-terms-ui** renders it.

## Plugins on main
- **Wikidata:** `background_walk` and `redistribute` (CC0), so ENR-12's renamed titles keep showing (a test pins it), 180 days. CC0 needs no attribution, but it carries a courtesy credit ("Wikidata (CC0)", `https://www.wikidata.org`) (runner, 2026-11-16). It opts out of the marker because Wikidata has no adult marker; the gate never asks about Adult, and its kinds are Movie and TV.
- **Open Library (ENR-ol):** user interest only. `redistribute: false`, because its API terms don't clearly allow passing answers on. Its attribution is the link back its terms ask for ("Open Library", `https://openlibrary.org`), 180 days. It opts out of the marker because Open Library has none.

## For the open lane PRs (the runner relays)
Each adds one `adult` line per `Identification` literal, plus `fn terms(&self) -> &Terms`:
- **MusicBrainz:** `background_walk: true, redistribute: true` (CC0), `Retention::DEFAULT`, attribution none, `adult_marker_required: false`, with a comment that MusicBrainz marks no adult content.
- **TMDB:** `background_walk: false, redistribute: false`, `Retention::days(180)` (the hard limit), attribution with TMDB's prescribed text, link and logo (move `tmdb::ATTRIBUTION` into it), `adult_marker_required: true`. Its `adult` is `Some(result.adult)`, and a result without the key is `None`, which is refused.
- **AniList:** `background_walk: false, redistribute: false`, `Retention::DEFAULT`, `adult_marker_required: true`, and `adult: Some(media.isAdult)`.
- **TVDB and Discogs:** `Terms::STRICT` unless their terms are shown to allow more. Each must map its own adult marker, or opt out with a comment if the service has none.

## Store format, downgrade and backup
- **Migration number:** V15, assigned by the runner on 2026-11-16, replacing CR-3's reservation. If `main` gains another migration before this merges, it takes the next free number.
- **Downgrade:** a build before V15 refuses a V15 store as newer (`SchemaTooNew`) and changes nothing, the store's existing rule, now tested for V12, V13 and V14 builds. To go back, restore the `lodestar.pre-v15.db` snapshot the migration takes, or a backup.
- **Snapshot purge:** V15 has the same plan as V14 (`Plan::KNOWN_THROUGH = 15`). Claims cascade from torrents, and `stored_at` holds no names.
- **Migration snapshots keep claims past their retention.** A migration snapshot (`lodestar.pre-v<N>.db`) is kept for 90 days (`RETAIN_SECS`) and holds the claims as they were. So an identify claim close to its limit when the snapshot is taken outlives that limit inside the snapshot, by up to 90 days. That would break TMDB's six months. The snapshot purge doesn't drop claims by age yet. The follow-up is runner slice **X-snapshot-claims-retention** (runner, 2026-11-16), which must merge before ENR-tmdb does. This PR doesn't change `snapshots.rs`.
- **Backup:** `lodestar backup` copies the database with `VACUUM INTO`, so the new column and index come with it. Restore is unaffected.
