# X-detail-polish decisions

Runner brief, 2026-11-01. Follow-ups from S-filters-2c (#316) and S-send (#321). No owner decision changes; Block still only adds a rule, and Cancel or a refusal still sends nothing.

- **Done: a hidden torrent drops after Block (item 1).** After a successful apply, the drawer's and the result menu's "Block this…" fire a `ls-stale` event on `window`; a one-time listener in `RowActions.svelte` (loaded with the first results) calls `results.reload()`; the result menu calls it directly when its dialog closes after an apply. An event rather than an import, because any import of the results store from the drawer pulled it into the drawer's size entries (+1 KB). The result menu waits for its dialog to close first (the reload removes the row and the dialog with it). The listener does nothing on `/t`. `reload` refetches from the top; dropping the row locally is a follow-up. Cancel and refusal never call `onapplied`.
- **Done: a failed flows door shows the error toast (item 2).** The drawer's `load()` failure (it reuses "Couldn't get the magnet link", per the brief; a neutral string is a follow-up) (the door import and `load()` itself) now pushes the same error toast as magnet copy/open, through `commands.ts` on demand, so the toast store stays out of the first view.
- **Done: the Send label follows Settings (item 3).** The drawer asks `sendLabel(true)` when it mounts, which re-reads the integrations section instead of using the session cache. It runs after mount, never in first paint. No settings-saved event exists, so this is the "cheap re-check when the drawer opens" option; the result menu still reads on its first More.
- **Skipped: stale-press guard on Send (item 4).** The Send button is only shown after `send.ts` has loaded and calls `sendHash` synchronously with the hash at press time, so no window exists between a press and the module loading. The row menu's hash is the row's own. Nothing to guard.
- **Skipped: `s` waits for the torrent on /t (item 5).** It needs the drawer to publish "loaded" state to `send.ts` (an effect plus a target export), ~+50 B in both entries, over budget with items 1–3, and the real fix is in `DetailHostBody.svelte`, not owned here. Suggested alternative for later: `DetailHostBody`/the /t page set the key target only once `model.detail` is present.
