# S-insights-2 decisions

**One generic page for four stages.** Fetch, Understand, Index and Serve share `features/insights/stages/StagePage.svelte`; `model.ts` maps each response to labelled metrics, charts, bars and tables (§10.9.5). One component keeps the route small, and the stage-specific parts are data, not markup. The route file lazy-loads it, as `/insights` does with the overview.

**Discover waits for a schema fix.** Two Rust structs are named `DiscoverResponse` (`dto/discover.rs`, the Search feed, and `dto/insights.rs`, the Insights stage), so `schema.d.ts` types `getInsightsDiscover` as the Search shape. The runner renames the Insights struct (`InsightsDiscoverResponse`); the Discover page follows once that is on `main`. Until then `/insights/discover` shows the existing "not available" page. The page is not hand-typed (runner, 2026-10-31).

**Never a fake zero.** A field the server sends as `null` shows "—" with "Not available yet", in the KPI, the detail list or the histogram. Nothing is computed on the client: a Compare value is the previous period's own field, shown as "Previous period: X", not a delta (the stage responses carry no delta fields).

**Missing from the endpoints (shown as "Not available yet" when null, or left out), with the series each needs (`docs/metrics.md` §7.7):**

- Fetch: `utp_share`, `mse_share` (transport and encryption outcome counters), `ephemeral_port_pressure` (socket counters), `queue_age_s`, `limiter_rejections` and the latency percentiles (the pool and a latency histogram). The **fetch-latency histogram** and the **outcome breakdown over time** have no field at all: only p50/p95 and the losses by reason (the totals) are returned, so neither chart is drawn.
- Understand: `parser_confidence` and `junk_distribution` (confidence and junk rollups), `resolution_rate`, `recent_corrections`. There is no field for blocklist drops beyond the count, which is what the spec wants.
- Index: `sizes`, `projection_days`, `disk_free_bytes` (free space), `segments`, `merges`, `file_index_coverage`, `scrape_coverage`, `scrape_freshness_s`, `trackers` (swarm rollups). The **growth projection chart** has no series; only `projection_days` is shown.
- Serve: `searches`, latency, `zero_result_rate`, `cancel_rate`, alerts, notifications, sends (their counters). **Top queries** appear only when the server sends them, which needs query logging on; a null list reads "Query logging is off".

**Estimates.** Latency percentiles always carry "≈" (log-bucket histograms, metrics.md §5), and so does the Serve facet sampling rate. Histogram bins marked `backfill` are not flagged separately; the bins are shown as the server sends them.

**Context.** The breadcrumb and the stage links keep `range`, `from`, `to` and `compare` (not `reason`, which belongs to Fetch). Range and Compare on a stage page are plain links, so each is a URL, and Back works. The stage strip on a stage page is its own five-link nav with `aria-current="page"`; the overview's `StageStrip` is unchanged (it scrolls, and shows the headline numbers, which a stage response does not carry).

**CSV.** Each chart and bar list links to its `export.csv` panel where B11b has one: `fetch.trend`, `fetch.losses`, `understand.trend`, `understand.by_group`, `understand.by_content_type`, `index.trend`, `index.removed_by_type`, `serve.trend`. The overview's `csvHref` builds the link, so the range and Compare carry over.

**Sizes (§10.1, Insights ≤ 45 KB).** The stage route's own JS and CSS is 33.96 KB gzipped, limit 37.4 KB (measured + 10%). uPlot (22 KB) loads with the first chart and has its own entry at 24.2 KB. No existing limit changed, and the search route's first load did not grow. Message lookups use explicit maps: a lookup by built key (`m[...]`) kept every message in the bundle and grew the shared chunks.
