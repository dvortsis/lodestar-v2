# F-filters-packs decisions

Pack rules now honour CSX-5 *Neutralize terms*, as architecture §20.5.5 says: a neutralized keyword "stops counting as evidence in every non-floor core rule and pack rule", while all other evidence still counts. This closes the gap that `2026-10-30-F-filters.md` left for this slice. No owner decision or number changes.

- **The five pack rules that read keyword lists:** MW-3 (lure names on an executable), LU-2 ("how to open" notes), LU-4 (unlock and survey notes), SC-1 (service and scam words) and FK-2 (the `trailer`/`sample` guard). The first four now leave the torrent's neutralized words out of their keyword evidence. FK-2's words are only a guard, so it doesn't change (below).
- **The neutral set is the one the core and your rules get.** It holds the keys of the Neutralize entries that apply to the torrent (`Engine::released`, `rules::neutral_sets`): entries that haven't expired, aren't in shadow mode, and whose word the core reads in the name or a path. A torrent with an Override entry still skips the packs entirely, as before.
- **How a word is neutralized: by token, with the shared code.** A pack rule reads a name or file name as words, each a whole run of letters and digits, lowercased. Before a rule counts them, each word that is a neutralized word (`matcher::neutral_token`, the check prefix and fuzzy words use) is blanked, and its position is kept (`packs::Ctx::evidence`).
  - **Joined words can't borrow a neutralized word.** A word is a whole run, so `CodecSetup` is the word `codecsetup`. It never was `codec` or `setup` to the packs, and neutralizing `codecsetup` leaves `Codec-Setup`'s two words alone.
  - **Phrases use whole forms.** A blanked word keeps its place, so a phrase that needs it (`how to open`, `human verification`) is broken where it stands. The same phrase elsewhere, or another phrase in the same note, still counts.
  - **Only lowercase ASCII words are checked.** Every pack keyword is lowercase ASCII letters and its own key (`keywords_are_plain_words`), so any other word can't be evidence. This only skips work.
- **Guards read the torrent as it is** (a content-safety reading of "mustn't widen"). FK-2's `trailer`/`sample` and SC-1's `trainer`/`mod`/`offline` keep a rule from matching. Neutralizing one of them would make the rule match more, so they read the words unchanged, as `unless` and exceptions do (`2026-10-30-F-filters.md`). So FK-2, whose only keywords are guards, never changes: a neutralized `sample` still guards a tiny video. Neutralizing only ever takes a pack match away.
- **Other evidence still counts.** Another lure name, note, phrase, service or scam word in the same torrent keeps the rule matching. Rules that read file types and the classifier's junk reasons (MW-1, MW-2, MW-4, MW-5, LU-1, LU-3, FK-1, FK-4, FK-5, SP-1, SP-2) are unchanged. So a neutralized `codec` still leaves MW-2 hiding the executable beside a movie.
- **Not changed: LU-1's `lure-file` reason.** The classifier works it out from file names (`password.txt`, "visit www…") for the junk score, and the packs share it so the two never disagree (§20.6). Neutralize doesn't reach it. That needs a change in `lodestar-classify`, outside this slice. It's flagged to the runner as a possible follow-up.
- **The floor and the core are unchanged.** CS-1a, CS-1b and CS-8a, with the CS-1 hash lists, are judged before overrides, neutralizing and packs, as before. The core's own Neutralize handling (`Core::signals`) isn't touched. `the_floor_is_untouched_by_pack_neutralizing` neutralizes every word of a confirmed torrent with packs on, and CS-1a still holds it, before and after the fetch.
- **Tests.**
  - Per rule (`packs::tests`): a neutralized word that was a rule's sole evidence no longer triggers it (MW-3, LU-2, LU-4, SC-1); a torrent with other evidence is still caught; guards aren't neutralized (FK-2, SC-1); words are whole.
  - **Property** `neutralizing_removes_only_sole_evidence`: random names and files from pack keywords, guards, extensions, a joined word, a look-alike and filler, in assorted cases, with random words neutralized. A rule matches with neutralizing exactly when it matches both on the torrent as it is and on the torrent with the neutralized words replaced in place by a word no rule reads, with the classification unchanged. So neutralizing only removes a match whose sole evidence was a neutralized word. Names often start with an HD or scam lead, with and without a guard word, so guards are exercised too; it runs 2,000 cases. A no-op `evidence` fails it, and so does a guard that reads the neutralized words.
  - Engine level (`tests/semantics.rs`): the decision through `Engine::judge`, including a shadow-mode entry, which neutralizes nothing.
  - No golden or intent fixture changed.
- **Cost.** When a torrent has no Neutralize entry, the packs do what they did: one empty-slice check. With one, a rule copies the words it reads once and compares each lowercase word with the neutral keys. The budget numbers are in the PR.
