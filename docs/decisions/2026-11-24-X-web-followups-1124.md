# X-web-followups-1124 decisions

- **A new `resetKey` keeps a focused row active (`VirtualList`).** When the list starts over (a new query or sort answered) while one of its rows has focus itself, and that row (by key) is still in the new rows, it stays the active row and is scrolled into view; otherwise the first row is active and the list scrolls to the top, as before. This is the list's side of #1115's table fix: without it the focused row and the tabindex-0 row disagree, so j/k move from the first row while the arrows move from the focused one (§10.13, §10.14). Both follow the focused row's torrent, since both key their rows by it. A control inside a row doesn't count, so the cards view starts over as before: focus is on a tile inside a list row, and its rows are chunks keyed by their first tile, so the row isn't the focused tile.
- **The route editor follows the server while untouched (rv-1114).** `Route.svelte` re-fills from `c.egress` whenever the server's route changes and the form still shows what it was last filled with, so Save can't send an older route back over a newer one. A form the user changed keeps their choice and is compared with the newer route from then on.
- **Route words (rv-1114).** `routeText` names `bind_address` explicitly; a route kind newer than the UI gets neutral words ("Route: a kind this version of Lodestar can't describe") instead of being labelled as another kind. New message key `settings_companions_route_unknown` (en, zh).
- **The row's route note and panel (rv-1114).** A new route try or refusal clears an older note on the row, so a refusal never shows beside a stale "Restarting…" note. The row's panel resets when the row stops offering a route, so the editor doesn't reopen by itself when the route comes back.
- **Unmount mid-PUT is commented, not changed (rv-1114).** Closing the editor while the PUT is in flight dismisses the password dialog, which resolves null even though the save may still apply; the store's refresh shows the row's real route, and nothing claims either outcome.
