# X-flake-cap-index-move decisions

- **The proptest's `Move` op skips a key that already has a usenet row.** `the_kept_count_matches_the_rows` (`crates/store/tests/unverified_cap_index.rs`, from X-unverified-cap-index, V16) failed at random with `UNIQUE constraint failed: unverified_items.network, unverified_items.key`. Shrunk case: `[FindBt(0,0,true), Move(0), FindBt(0,0,true), Move(0)]`. The first `Move` turns the BitTorrent row into a usenet row; the second `FindBt` stores a new BitTorrent row for the same key; the second `Move` then asked SQLite for a second `(usenet, key)` row, which the schema forbids. The op now adds `AND NOT EXISTS (… network = 4 AND key = ?1)`, so it still models "an item's network changed outside the API" without asking for an impossible state. Any other error still fails the test. The bug was in the test's model; the store and the kept count behaved correctly.
- **The shrunk case is a named test and a proptest seed.** `a_key_found_again_after_a_move_is_not_moved_twice` replays it every run and checks that one BitTorrent row and one usenet row remain, and `unverified_cap_index.proptest-regressions` holds a seed proptest found on the old model (the same shape on key 8), so the generator replays it first on every run. To share one body, the proptest's loop moved into `run(ops)`, which returns the store; the ops and checks are unchanged.
- **Proof:** the named case and the seed each failed with the UNIQUE error before the change and pass after it; the proptest passes at `PROPTEST_CASES=10000`.
- Test code only; no owner decision is touched.
