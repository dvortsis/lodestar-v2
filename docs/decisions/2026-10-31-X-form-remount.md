# X-form-remount decisions: the Settings form keeps its body through a reload

- **The body stays mounted once it has rendered.** `SettingsForm.svelte` shows the loading line only until the first render. A later `load()` (status `loading`) keeps the children in place and sets `aria-busy="true"` on the form region. A reload that fails keeps the body and shows the engine's existing error banner with Retry above it. Nothing moves: the children are not wrapped, so layout is unchanged.
- **What the engine does today.** Only `load()` sets `loading`, and only the first load and Retry from a failed first load call it. `resync()` and `refetch()` never do, so a resync after a save doesn't swap the body for the loading line, whatever `S-logs-2` recorded. The new engine test and the Playwright spec (`settings-form-focus.keyboard.test.ts`, with a real `resync` event) show focus, the Logging search text and the switch surviving a save and a resync. This change makes that a guarantee for any later `load()`, so it can't drop keyboard focus (WCAG 2.4.3).
- **Edits during a reload.** The body stays interactive, as it does during a save, and a finished `load()` replaces the loaded values. Nothing calls `load()` after the first render except Retry, so a staged edit can't be overwritten today; a caller that adds one must merge instead (`mergeCurrent`).
- **The #289 workaround stays.** `opened` at module level in `EventList.svelte` also survives leaving and re-entering the screen, which is its intent, and `features/settings/logging/**` is being edited by S-logs-2b. Removing it isn't needed for this fix; a follow-up can once that slice has landed.
- No engine semantics, sizes or baselines changed.
