# P-v06-companions decisions

Planning slice for E-v06-companions. The plan is `docs/plan/2026-11-06-v06-companions.md`. Docs only; nothing here is built. Each choice below is the planner's, for the runner to accept or change in review. Questions that belong to the owner are in the plan's §5 (Q1–Q5 and Q15) and are not decided here.

- **One new crate, `lodestar-companions`** (architecture §13 already names `crates/companions/`). Every Opus core piece (catalogue, fetch and verify, extraction, credentials, supervisor) gets its own files in it, so wave 2 runs four slices at once with only `lib.rs` `mod` lines shared.
- **Seventeen `CMP-*` slices, about 11,500 lines, none over ~1,000.** CMP-0 also defines the adapter traits, so the supervisor and the adapters can run at once. The supervisor is split into the concurrency core (CMP-4a) and the platform limits and egress hook (CMP-4b). The install flow (CMP-5) stays one slice because it's one state machine that crashes must leave consistent.
- **Both adapter slices on Opus, stricter than build-plan Track K's [S] mark** (plan Q14). Detection (CMP-8a) probes a URL you enter, reads untrusted responses and chooses the SSRF guard's loopback-allowed mode; auto-configuration (CMP-8b) writes generated credentials into third-party APIs (CLAUDE.md: security-sensitive code and untrusted input are never delegated). Compose and template generation (CMP-7) stays Sonnet with `/security-review` for its escaping.
- **No migration** (plan §3, Q10): per-companion state and sealed credentials go in `settings` rows, the #367 pattern the rule-pack plan also used. The migration queue is unchanged.
- **Windows qBittorrent is its own slice, CMP-11, gated on the owner's answer** (plan Q4), so no other slice builds an answer the owner hasn't given. Q1 and Q15 (whose binaries run) gate CMP-0, Q2 CMP-1, Q3 CMP-4a and Q5 CMP-6.
- **A companion's route is its own setting** (plan Q18), seeded from the egress of the plugin that needs it and built through `lodestar_sources::PluginEgress` handed in by `crates/lodestar`, so `crates/companions` never depends on `crates/pipeline`.
- **Guided installs never put a secret in a generated file** (plan Q19): you paste the companion's own key or temporary password once, and Lodestar seals it and replaces the temporary password.
- **CMP-9b waits for SRC-15b,** which owns `web/src/lib/features/sources/**`, and mounts its chips with one-line shared edits.
- **Recommended deferrals, for the runner to confirm and flag to the owner** (§2.19): managed-container mode past v0.6 (Q11), and native VPN beyond the existing egress settings (plan §2 "Not in this plan"). Both narrow scope without loosening any owner decision: §1.7.2 asks for guided installs on Docker and Unraid, which the plan builds.
- **Recommendations stricter than the spec, the runner's call** (§2.19): no LAN scanning in detection (Q12); a companion that can't follow the egress route doesn't start (Q8); native installs refused inside containers (Q17); `/security-review` on every slice but the docs slice (CMP-D), and an unanchored second read on CMP-0, CMP-1, CMP-2 and CMP-G.
- **Numbers proposed under §2.26** (performance and UX, flagged): supervision backoff, crash and health thresholds and the 1 MB log ring (Q7); download and extraction caps (Q16).
- **The plan doesn't edit `runner/slices.yaml` or `runner/dashboard.yaml`** (brief): §4.1 gives the slice lines, the six `ext:owner-cq*` conditions and the `CMP-G` gate entry for the runner to add.
