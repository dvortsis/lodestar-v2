# LU-1-neutralize decisions

LU-1 (a lure note beside an archive standing in for media) now honours CSX-5 *Neutralize terms*, as architecture §20.5.5 says. This closes the gap `2026-10-30-F-filters-packs.md` left ("Not changed: LU-1's `lure-file` reason"). No owner decision or number changes.

- **The classifier says which lures it found.** `lodestar_classify::lure_hits(file)` gives the lure texts (`password`, `click here`, `visit www`, …) a file's name holds, as the `lure-file` reason reads them: ASCII-lowercase substrings, small files only (under 64 KiB), never padding. The junk score uses it, and so does LU-1, so the size and the list live only in `lodestar-classify` (§20.6).
- **The junk score doesn't change.** The `lure-file` reason and its weight are worked out exactly as before. Neutralize is a filter entry; it never changes the classifier's score or reasons. A test judges with a Neutralize entry and checks the junk is unchanged.
- **With nothing neutralized, LU-1 is what it was:** `lure-file` and `archive-for-media`, read from the classifier. So the packs and the junk score can't disagree there.
- **With a neutral set, a lure must survive it.** LU-1 then also needs one lure text in some file with no neutralized word over it. The torrent's neutral set is the one the other packs get (`2026-10-30-F-filters-packs.md`).
  - **Same token rules as MW-3.** A file name's words are whole runs of letters and digits, lowercased, as `packs::Ctx::evidence` reads them. A neutralized word blanks its span (`matcher::neutral_token`), positions kept. A lure found there is broken where a blanked word stands, so `click here` goes when `click` or `here` is neutralized. The same phrase elsewhere, or another lure note, still counts. `password` and `passwd` are whole words, so neutralizing `pass` doesn't touch them.
  - **A joined word stays evidence.** The classifier matches substrings, so `MyPassword.txt` holds `password`. Its word is `mypassword`, not `password`, so neutralizing `password` leaves it, and LU-1 still holds. Neutralizing the whole word `mypassword` takes it away. This fails safe, and it's the packs' rule that joined words can't borrow a neutralized word. The classifier's own matching isn't narrowed.
  - **Every file is read,** not only the first 1,000 the other rules read, because the classifier reads them all: a lure past them still counts.
  - **`archive-for-media` is read unchanged.** Neutralizing only ever takes LU-1 away.
- **Tests.** Per rule (`packs::tests::lure_notes_honour_neutralize`): the sole lure word neutralized stops LU-1; another lure note keeps it; either word of a phrase breaks it; `pass` and an unrelated word don't; a joined word stays evidence; `archive-for-media` is still needed; a lure past the first 1,000 files counts. The property `neutralizing_removes_only_sole_evidence` now includes lure notes (`click`, `here`, `www`, `passwd`, `MyPassword`) beside archive-for-media torrents, and its masked run reads the masked notes for LU-1. Engine level (`tests/semantics.rs`): the decision through `Engine::judge`, a shadow-mode entry (neutralizes nothing), and the unchanged junk. No golden or intent fixture changed.
- **Cost.** No Neutralize entry: one empty-slice check, as before. With one, LU-1 reads file names only when both junk reasons already hold. The budget numbers are in the PR.
