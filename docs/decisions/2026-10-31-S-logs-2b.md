# S-logs-2b decisions: Settings → Logging, part 2b

The second part of S-logs-2 (§10.10.12, §12.1): outputs, log files, the Danger zone and the preview. Part 2a's decisions are in `2026-10-31-S-logs-2.md`.

- **Outputs are engine fields.** That covers the console format and detail, the console level, and the log file's on/off, folder, level, size, files kept, age and cap. They're staged, saved and undone like the events.
  - **Console detail** is a Privacy field. Saving "Same as the file" asks first, because the console and `docker logs` would then get every torrent detail the file gets, and Lodestar can't delete those. Focus starts on Cancel. Going back to Private asks nothing.
  - **Windows Event Log** shows only when `GET /system` says Lodestar runs as a Windows service. If that can't be read, it stays hidden.
- **The preview is served by the API** (`POST /settings/preview`). The panel sits under the log file settings and sends the staged values the preview depends on, debounced. It shows:
  - the console's and the file's volume per day, and how many days the files would hold;
  - the server's example lines, rendered from sample data. The client never makes up a line.

  The engine ignores estimate names it doesn't know, so these show only in this panel, not under each field. §10.10.12 asks for a size preview on each file setting; one panel under the file settings gives the same figures once instead. That is a refinement for the runner to confirm: showing them per field would mean teaching the engine's `display.ts` the logging estimates.
  - It sends every staged event and output change, plus one field the server will preview. Verbosity is left out when `LODESTAR_LOG` sets it, since the server refuses fields the environment sets, even in a preview.
  - Only the volumes are a live region; the example lines are for reading. Each example says which output it's from.
- **Downloads remove torrent details by default.**
  - One "Remove torrent details" box covers every download, and it's on by default. It appears only when some file has details, and it's ticked again whenever the list is read again.
  - A file with details is downloaded with `redact=true` unless the user unticks the box. A file without details is downloaded as it is.
  - Download all (zip) follows the same box.
  - Downloads are plain links: same-origin, with the session cookie and no script.
- **Danger zone.** Delete files with torrent details, and Delete all log files. Each opens a dialog with the count and size, focus starts on Cancel, and the button names the action ("Delete log files (2, 6 KiB)"). The total size is the client's sum of the listed files' sizes, as in 2a's delete offer. Files the server skips are named after the result.
- **When nothing is listed**, the screen says why, in words the user can act on: off, stopped, the folder can't be opened, isn't a folder, isn't private, or can't be read. When the details index can't be read, it says every file is treated as having details.
- **Docker hint and folder.** The folder shows with Copy (`copyText`, with a fallback that selects it). On Docker and Unraid, a line says the console log is also in `docker logs`.
- **Order and loading (size, §10.1).** The page follows §10.10.12's order: events, data kinds, opt-ins, never logged, outputs (with the preview), log files, Danger zone. Everything after the events loads after the first view, through `DataKinds` → `Tail` (outputs, then files).
  - The output fields render outside `SettingsForm`'s frame, because they come after the data kinds. They're still the same form, so Save and Undo cover them.
  - Logging's first view is 44.57 KB.
  - The label map now holds the output fields' labels, so its own limit moves from 0.86 to 1.48 KB (measured 1.35 KB), pending the runner's ruling.
  - Only the help texts that say something the label doesn't are kept. The two level fields (Advanced) show the level ids as they are.
  - Nothing outside Logging grows against `main` beyond build-to-build noise. Each build embeds a timestamp and a random app id, and chunk hashes change, which moves every entry by a few bytes; Results toolbar sits on its 4.6 KB limit on `main` too.
  - Three causes of growth were found and removed: new utility classes in the shared CSS, a dynamic import of the clipboard helper that re-split a shared chunk, and a `!list` in the code that Tailwind read as daisyUI's `list` class with the important modifier.
