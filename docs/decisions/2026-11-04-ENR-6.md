# ENR-6 decisions (#436)

Slice session, 2026-11-04. Architecture §20.7 ("Filtering ignores corrections, except to be stricter"), §20.9, V8/V9; v0.6 rule-packs plan, ENR-6 and §5 Q13.

- **A new entry point, `classify_enriched(name, files, fix, enrichment)`,** beside `classify` and `classify_corrected`, which now calls it with no match. With no match it gives exactly what `classify_corrected` gave: the golden corpus is unchanged, and a property test in `adult.rs` checks unmatched detection against a frozen copy of the pre-change `detect`. So the classifier golden corpus is unchanged, `CLASSIFY_VERSION` stays 3 and nothing is re-derived. No pipeline caller changes; ENR-1 reads the stored v2 claim into it.
- **A match is a kind only: `EnrichmentMatch { kind: MatchKind }`, with `MatchKind` Scene, Movie or VR.** The plan names these three as the kinds a service reports, and a separate type means a caller can't pin Photos, Comics, Game or Audio from a video match. The confidence is not the caller's: it's always `MATCH_CONFIDENCE`, 99 (Q13), so a low service score can't lower detection's, and whether a service result counts as a match at all is ENR-1's decision before it calls.
- **What a match does in `adult.rs` (`detect_matched`):** the torrent is adult at 99. Detection's score is at most 99 (`SCORE_CAP`, checked against `MATCH_CONFIDENCE` at compile time), so the match never lowers it.
  - **The kind never gets less specific** (brief: "more adult or more specific, never less", runner review). The reported kind is pinned only where the torrent's own kind (detection's, or the nearest kind for its type, `forced_kind`) is video: Scene, Movie or VR. A non-video kind from the files (Photos, Comics, Game, Audio) is kept. VR words in the name or largest file keep a Scene or Movie match as VR, the same rule that turns detection's Scene or Movie into VR (§20.9 "As built").
  - **Counter-signals don't weaken a match.** §20.9's counters (documentary, educational, medical words; season and episode numbers) are about the name. Only items already classified adult are looked up (Q2), and a match names the specific title, so letting a name word take 40 off it would make a match able to leave an item non-adult. The child-safety core still judges the enrichment text itself (Q3, ENR-1). This is a refinement of §20.9's "counter-signals that win" in the stricter direction, for the runner to flag to the owner (§2.19). It covers the name counters scanned today; how a future mainstream match (TMDB, TVDB, MusicBrainz) weighs against an adult match is for the slice that adds it.
- **A correction or classification rule still wins** (both reach the classifier as `Correction.adult`, V8/V9):
  - **Not adult** skips adult detection, match included: the result is exactly `classify_corrected` with Not adult.
  - **Is adult** with a match gives the matched kind (as above) at confidence **100**, the correction's own. The correction decides the outcome, not the kind (without a match it keeps detection's kind too), and 100 keeps the match from lowering the confidence Is adult gives when detection found nothing (Q13: "still below a user correction or rule (100)").
  - **Not junk** applies as before.
- **Filtering never judges the enriched result alone (§20.7, runner review).** Pack and user rules key on the content type: MW-3 fires only for Movie, TV or Video (`filter/src/packs/mod.rs`), and `Engine::judge_classified` returns early for Adult. Relabelling an item Adult can therefore drop a hold: `Lantern.Bay.2019.1080p.WEB-DL` with its `.mkv` and a `codec.exe` gets MW-2 and MW-3 unmatched, but only MW-2 as a matched Movie. So the engine judges detection's own, unmatched result (`classify`, or `classify_enriched` with `Correction::default()` and no match), and when a match makes adult an item detection didn't call adult, it also judges the adult reading and keeps the stricter verdict, as the Is adult path in `judge_classified` and `reclassify_row` already does.
  - **ENR-1 requirement:** never wire the enriched result in as the only reading the filter judges.
  - **Tests handed to ENR-1** (`crates/pipeline/tests/adult_enrich.rs`): a name the child-safety core holds stays held with a perfect match; the MW-3 case above stays hidden with a Movie match.
- **What the tests here assert.** A property test checks that a match never changes composition, structure, title, junk, largest file, depth or extension count; never turns an adult item non-adult; never lowers the confidence; keeps detection's VR and any non-video kind; and that the uncorrected enriched reading is Adult even when a Not adult correction hides it from the stored classification.
