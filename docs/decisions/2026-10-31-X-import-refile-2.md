# X-import-refile-2 decisions: import polish from the #276 and #280 reviews

Optional findings from B-import-server-1 (#276) and B-import-refile (#280), folded into one slice by the runner. No schema change, no API change, no new metric or log event. It tightens content safety and loosens nothing.

- **The refile sweep retries after a store error** (#280 review 1). An error (`SQLITE_BUSY` past the busy timeout, say) no longer ends the sweep: it waits, then tries the same batch again when a flush tick finds the wait over (`CandidateSweep::retry_at`). The wait is 5 s after the first error in a row, doubling to a 300 s cap, so it never spins; a batch that goes through resets it. Names the current rules hold no longer stay at rest until the next rule change or start.
  - **Backfill has the same pattern** (`Writer::backfill`'s error arm sets `backfill_done`, until the next start or re-enrich request). It isn't fixed here: its state lives on `Writer` itself, built in `pipeline/src/lib.rs`, outside this slice. Follow-up: give backfill the same retry (a `retry_at` beside `backfill_done`).
- **Intake's held set only takes a sweep batch's hashes under current rules** (#280 review 2). `Writer::hold_refiled` drops them when the engine moved on after the batch was written: the restarted sweep, or a store reload, settles them.
- **A refile never adds a phantom count** (#280 review 3). `Store::refile_import_candidates` moves a job's counters only when it counts a candidate (`candidates > 0`); debug builds assert it. Before, `max(candidates - 1, 0)` would have added one to `filtered` or `quarantined` with nothing taken from `candidates`, hiding a conservation break.
- **The no-name log test proves its sink is live** (#280 review 4): it drives the sweep's error arm (a temporary table shadows the candidates with an unreadable row) and asserts `pipeline.enrichment_failed` reached the capture before checking for names. This also replaces the B-import-refile note that the error arm isn't driven.
- **Only the sweep moves counters** (#280 review 5): one line added to `2026-10-31-B-import-refile.md`. A hash-trigger removal (CS-1 hash, tombstone) and a candidate later stored as a torrent don't move counters or flip `complete_with_issues`.
- **A class-rule test** (#280 review 6): `import_refile::a_class_rule_makes_an_adult_hold`, an Is adult rule plus the Adult-only core gives a CS-5a quarantine marked as an adult hold, name sealed.
- **CLI and server filters agree on a floor-marked subscribed list** (#276 review 2): `the_cli_and_the_server_build_the_same_filter` seeds one with a fetched version holding a hash, blocked on both paths. The "Left untested" bullet in `2026-10-31-B-import-server-1.md` is now "Not caught", keeping only the `services.rs` caveat.
- **A stale sentence** (#276 review 1) dropped from `2026-10-31-IMP-4b.md`.
- **One candidate judgement for import and the sweep** (B-import-refile follow-up): `lodestar_filter::reclassify::judge_candidate`, with `judge_with_rules` (hashes first, then the name with your classification rules) and `rule_fix` beside it. It lives in `lodestar-filter` because `sources-importers` can't depend on `pipeline` without pulling in the crawler, and both already depend on the filter crate. `sources-importers`' `judge_candidate` and `judge_torrent` and the pipeline's sweep call it; `pipeline::enrich::rule_fix` re-exports it.
  - **The import driver now checks a hybrid candidate's truncated v2 hash** against the engine's lists, as the sweep did, and records the hold under both hashes. That closes the stricter-sweep difference B-import-refile noted.
- **Tests wait for no timer:** the retry test passes explicit times to `retry_due`.
