# S-search-2a decisions (the results list)

The search page's results list and the shared result row (architecture §10.4, §10.5, §10.12, §10.15). The facet rail is S-search-2b. Items marked **(§2.19)** are runner decisions that refine an owner decision. The runner flags them to the owner.

## The runner's decisions on the brief

- **(§2.19) The shared row replaces both interim rows.** `ResultRow` (`features/search/results/`) is the row for Search, Alerts and Discover. `AlertHitRow`, Discover's `HitRow` and Discover's copy of `composition.ts` are deleted, along with the 24 messages only they used. #140 merged before this PR was pushed, so Discover's swap is here, not in 2b (runner, 2026-10-24). Discover's side panels give their rows their own test-id prefix (`discover-<section>-row-<hash>`), so a torrent listed twice doesn't share ids. Its list keeps the id on its cell (`ResultRow`'s `root={false}`). Its rules between rows are inset shadows, not borders, so the shared row's 64 px fit the cell exactly. The rows show the shared row's badges, which Discover's interim row left out.
- **(§2.19) No "+N in the last hour" in the empty state yet.** `fetched_per_hour` counts fetched metadata, not newly searchable torrents, so it would overstate the figure. The line waits for an API figure for the last hour's newly searchable torrents.
- **(§2.19) Cold start means fewer than 1,000,000 searchable torrents** (`searchable_torrents` from `/stats`). Below that, an info banner says how many there are so far.
- **(§2.19) Badges:** at most 5. First the content type, or the adult kind for an adult torrent, then the private, v2, hybrid and imported flags.
- **(§2.19) A list whose query has a file clause uses the 84 px Comfortable row.** The server sends `matched_files` only for such a query, so the whole list takes the taller fixed height (§10.1: one height per list, never measured).

## Loading and the first load

- **The panel loads with a query, or on the first interaction.** It loads when the URL has `q` or `hidden`, or else through `onFirstInteraction` (`KEYS_AFTER_MS` fallback). The bare page's first paint and its Lighthouse figure are unchanged: Search JS 40.7 KB (main 40,745 B) and global CSS 19.83 KB.
- **Route nodes keep CSS only in their preload lists.** `routePreloads` (`scripts/first-load.mjs`) now covers kit's route nodes as well as its entry. Without it, `/search`'s own node listed the 45 chunks the lazy panel uses (+452 B on the first load). `.size-limit.mjs` now fails if any first-load file lists JS to preload, which extends `2026-10-24-search-first-load-routes.md`'s guard.
- **Lazy styles live in plain sheets** (`row.css`, `results.css`), imported with the panel. A lazily imported component's own `<style>` loads with the route (kit). Tokens only: utility names would join the global sheet. A bare identifier `stats` anywhere Tailwind scans (the whole project, `e2e/` included) adds daisyUI's `.stats` (+13 B global CSS), so the panel and the e2e fixtures call it `figures`.
- **The page grid's rule moved from `query/bar.css` to `results/results.css`.** The page awaits the results sheet before it mounts the panel, but loads the bar's sheet without waiting. Under load, the panel could paint full-width before the rail's track arrived, a layout shift of 0.08. The search README's rule ("the first slice that paints into a region moves the rule") now points here.

## No layout shift on a pasted link

- **The strip's line is held while its chunk loads.** When the parsed query has chips, `Live.svelte` renders an unseen, inert chip and "Clear all" (`filter-strip-reserve`) until `FilterStrip` arrives, so its height matches the strip's, coarse-pointer targets included. This fixes the gap S-search-1's README left open.
- **The first rows wait for `/stats`, for at most 1 s.** The cold-start banner sits above them, and Lighthouse against the fixture (2,208 torrents) caught it arriving after them: a 0.063 shift. An e2e spec answers `/stats` only after the results.
- **The panel paints nothing while a pasted link's query parses.** Before, it showed the empty state for a moment, then moved down when the reserve appeared. A parse error keeps it blank, and the bar explains the error. The e2e spec measures CLS < 0.01 on a pasted link with filters.

## The store and the list

- **One store** (`results.svelte.ts`) holds the results; S-search-3's toolbar reads it. Its contract is in `results/README.md`.
  - The latest query wins.
  - Refining, an error and a parse error all keep the last rows.
  - Paging follows `next_cursor`. `cursor_expired` or `bad_cursor` reloads the query from the top, keeping the rows while it does, and a notice says the list started again.
  - **The same query is never asked for twice.** W5 sets `ast` before it writes the URL, and any URL change (density, a resubmit of the same text) re-runs the panel's effect. The store skips a query whose key is in flight or already settled, so an edit sends one results request, and scrolled-in pages survive a density change. A failure waits for Retry.
- **`load` runs untracked.** The panel calls it from an effect. Reading the rows inside it made the effect depend on them, so every answer loaded the query again: an endless request loop on an empty answer, caught by e2e. A runes test (`results.svelte.test.ts`) keeps it fixed.
- **The list resets its scroll only when new rows land** (`resetKey` is the store's `shown` key), not while a refine or a parse error is out.
- **`c`/`o` act on the focused row, whatever focused it** (Tab, a click, the arrows, j/k). The panel sets S-detail's target from `focusin` and clears it on `focusout`, synchronously through `detail/target.ts`. An `import()` there let a quick `c` act on the previous row. Details are prefetched on focus and on hover (§10.1).
- **j/k from outside the list go to the active row first**, then step through the list's own `move`. **With the drawer open they move the drawer and leave focus in it** (§10.5: "the row stays put"), so Esc still closes it and returns to the row. Shortcuts don't fire in the bar (§10.16): Tab reaches the list, one tab stop.
- **(§2.19) Row actions are out of the tab order; Shift+F10 or the menu key opens the focused row's More menu.** The list is one tab stop with roving focus. Copy magnet is `c`, and More's items (Open in a new tab, Copy info hash) open from the keyboard, so nothing is pointer-only (WCAG 2.1.1). The More button carries `aria-keyshortcuts`. The actions show on hover and focus, and always under a coarse pointer (§10.4: never hover-only on touch).
- **Copy info hash falls back like the magnet:** the Clipboard API, then the textarea copy (`util/clipboard.ts`). Plain-HTTP LAN origins have no Clipboard API.
- **The More menu loads on its first click.** Bits UI's menu, popper and portal are about 34 KB gzipped. The panel only needs a button until More is clicked.

## States

- **No results offers the way back (§10.4).** With filters, the panel lists them, each with "Remove", plus "Clear all filters" (one history entry, as the strip's Clear all). Without filters, it suggests other words. Per-clause zero-result counts wait for the server.
- **Errors say what happened, then what to do (§10.14).** A 429 or 503 says Lodestar is busy, with `Retry-After`'s seconds when sent. Another 4xx says the search couldn't run and to change the query. Anything else says Lodestar didn't answer.
- **The count is announced politely once per answered query (§10.13):** "N torrents", "About N torrents" or "No torrents match". W5's debounce already spaces the queries, so there's no further throttle. S-search-3's toolbar shows the count.
- **The rebuild banner reads the shell's own stream subscription** (a `rebuild` getter on `shell/status.svelte.ts`). A second `rebuild` subscriber could open the stream before the shell and reconnect it with another topic set.
- **Skeletons are the rows' final height** in either density, so nothing moves when the rows arrive.
- **Cold start** says how many torrents are searchable so far. The link to the bitmagnet import and a "+N per hour" figure wait for the import UI and an API figure (follow-ups).

## Size budgets (reported to the runner)

- **(§2.19) "Search results (lazy)" measures what the panel adds beyond the view it loads into** (runner, 2026-10-24).
  - That view is the first load, the bar's lazy part (`Live.svelte`, engaged by a URL with a query or the first interaction) and the shell's engagement set (`Chrome.svelte` and what it loads at mount).
  - It's `ownChunk(..., beyond)`, with the set from `viewOf(...)`, next to `onDemand` on the shared walk (`own` takes `beyond` too), so other lazy views can reuse it.
  - Measured 31.32 KB, so the limit is 34.5 KB (measured + 10%, under the 45 KB per-view cap). The runner's 41.5 KB came from my first figure (37.6 KB), which counted the shell's key registry and event client.
  - The biggest parts are VirtualList with its virtualiser (12 KB), the panel (5.2 KB), the row (3.9 KB) and the row actions (1.9 KB).
  - On demand: the drawer, copying a magnet and the More menu. The Detail entries gate the first two.
- **(§2.19) The Alert route stays under the owner's 45 KB route budget (§10.1): 44.45 KB** (main 43.19 KB). The runner approved the approach below.
  - With the shared row alone it measured 47.4 KB. The row's own share is about +4.2 KB: badges about 0.6, the arrow and backfill icons about 0.4, `showBidi` about 0.6, `row.css` 0.7.
  - To fit, Alerts' j/k registration moved to `alerts/commands.ts`. It loads after mount with the key registry and is marked on demand, as Detail's commands are.
  - The page keeps `measureRows` for its "since you last looked" divider rows. Each alert cell has the row's fixed height and the estimate matches it, so only the divider is measured.
- **Discover: 44.81 KB** (main 42.75 KB), within its 45 KB as the runner required: the shared row brings badges and `row.css`.
- **Alerts list:** 28.43 KB (main 28.46 KB).
- **"Search results (lazy)" fails if it finds no chunk** rather than dropping out of the gate.

## Shared files this PR edits (outside `results/**`)

- `routes/search/+page.svelte`: the panel's mount line (S-search-1's README names it).
- `features/search/query/Live.svelte` (the strip reserve) and `query/bar.css` (the grid rule moved out): S-search-1's, both for the pasted-link layout shift above.
- `features/alerts/*` and `features/discover/*`: the row swaps (runner decision 1), Alerts' lazy commands and fixed cell height.
- `scripts/first-load.mjs` (`routePreloads` for route nodes) and `.size-limit.mjs` (the preload guard, `beyond`, the results entry): first-load guards, for every route.
- `scripts/messages.ts`: nested message folders (the brief's named hook edit).
- `shell/status.svelte.ts`: the `rebuild` getter above.
- `e2e/shell.routes.test.ts`: its "server that never answers" specs now block all of `/api/v1`, since an engaged `/search` asks for `/stats` and any REST answer tells the shell the server is up. `e2e/discover.routes.test.ts` checks `.rr-row` for clipping, and `e2e/search-query.*` scope their announcer and "Clear all" lookups now that the results add their own.
- `e2e/mock/openapi-mock.ts`: answers `listSavedSearches` with no saved searches by default, like its `getEvents` and `getAuthStatus` defaults, because every spec that passes through `/search` and interacts now loads the panel.
