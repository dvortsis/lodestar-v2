# S-search-1 decisions (#132)

The search page shell, the query bar and its highlighter, the parse-error states, the active-filter strip and the Syntax popover (architecture §10.1–§10.4, §10.13–§10.16). Choices that clarify or refine the plan are below. Two of them change what W9 decided; both are refinements the runner approved (`docs/owner-decisions.md` §2.19), and the owner's numbers are unchanged.

## First load (§10.1: owner budgets, unchanged)

- **The chrome waits for the first interaction, or 30 s** (refines W9's deferral order; runner, 2026-10-23).
  - With any query bar on the bare `/search`, Lighthouse measured 104,825 B against the 102,400 B limit, with about 0.5 KB left before this slice.
  - `Shell.svelte` now imports `Chrome.svelte` on the first `pointerdown`, `keydown`, `touchstart` or `focusin` (focus on `<body>` is kit's own and doesn't count), or after 30 s. That is the full bar, palette, toaster and stream.
  - `Chrome` gets `engaged`, so its own deferred parts (keys, pill, connection states) start at once instead of waiting for a second interaction.
  - Until then the static bar from `app.html` stays in the slot. Its links are real anchors that kit's router takes over.
- **The 401 redirect stays eager.** `installAuthHandlers()` moved from `Chrome.svelte` to `Shell.svelte`'s mount, so a signed-out visitor whose first request fails goes to sign-in without touching the page. `search-query.routes.test.ts` covers this with no interaction.
- **"Idle or 30 s" is read as W9's rule: first interaction or 30 s.** The runner's note named idle. A `requestIdleCallback` fires inside Lighthouse's load window, so the bytes would count again. A user who never interacts still gets the full bar after 30 s.
- **A tap on the static menu button opens the menu** once the chrome arrives. Without that, the first tap on a phone would do nothing.
- **The static first-paint shell now includes the search heading and the query bar** (`app.html` `#boot-main`, about +236 B). The bar's placeholder is larger than the heading, so when JS drew it, it became a late LCP element (3.03 s mobile against 2.5 s). Painted from HTML it is the first paint (about 1.5 s).
  - The static bar is inert (`aria-hidden`); the app's own bar takes typing.
  - `boot-shell.routes.test.ts` compares the heading's and the bar's boxes (≤ 1 px) as it does the top bar's.
  - The owner's condition on that file (mobile LCP ≤ 2.5 s, W9 "Owner permission") holds.
- **The bar's first-load part is markup plus a loader.** The editor, W5's state, the tokenizer, the error line, the chips and the Syntax popover load on the first interaction, or at once when the URL carries `q` or `hidden`. Typing works natively in the meantime, and the editor adopts the text (and an Enter) when it loads.
- **The bare page sends no `/parse`.** An empty query in an empty bar has nothing to adopt, so `search.sync()` is skipped until there is one. Every spec that interacts with `/search` would otherwise need a parse mock, and Lighthouse would count the request.
- **Kit loads a lazily imported component's own `<style>` with the route.** The bar's lazy styles are therefore in `query/bar.css`, imported after `Live.svelte` mounts. That includes the token classes, the error mark, the sticky bar and the page grid.
- **The page grid's rule is lazy for now.** The regions are empty until the first interaction. The first slice that paints into one on first load moves the rule into the route's stylesheet.
- **No new global CSS (19.82 kB before and after).** Writing a utility's name anywhere in `src/`, comments included, adds it to the global sheet. So the lazy sheet uses token variables (`var(--color-accent-ink)`) where the utility isn't already emitted. First-paint geometry uses emitted utilities and `var()` style bindings (`--query-bar-height`, `--spacing`, `--border`).
- **The placeholder is an `aria-hidden` sibling, not `data-placeholder` with `::before`.** The CSS rule would have been the route's only first-load stylesheet: a new request and bytes in a budget with nothing left. It is still never the accessible name; the label is.

## The editor (§10.4)

- **A `contenteditable="plaintext-only"` element** with its own undo stack, as the brief and the runner accepted. The spans are built as DOM nodes from `tokenize()`, never from markup.
- **Undo coalescing:**
  - consecutive edits of one kind (typing, or deleting) less than 1 s apart are one step;
  - a typed space ends the step, so each word undoes on its own;
  - paste, Esc, undo and redo and outside changes (the URL, the canonical text, a "Try") are steps of their own;
  - 200 steps at most.
- **Esc** closes an open popover first (the Syntax popover; S-search-4's listbox will join it). Otherwise it clears the text, and undo brings it back. On an empty bar it is left to others.
- **Token classes** (the gap filled by `typography-ui`, §10.4's weight + mono + colour):

  | Kind | Look |
  |---|---|
  | field | mono, semibold, primary |
  | value | mono |
  | range | mono, medium, accent ink |
  | operator | semibold, accent ink |
  | phrase | medium, quotes in muted text |
  | text | plain |

  Mono loads only when a mono token renders.
- **The error mark** is a wavy underline in the error colour, shown only while the text is the one parsed (`!parsing` and the text equals the URL's `q`, which W5 sets to the raw text on an error). An empty span marks one character, or a mark after the last one.
- **Parse errors are English only.** The server sends `query_syntax` with an English `message`. A localized reason code is a backend follow-up.
- **The search landmark** is a `<search>` element (svelte-check accepts it) labelled "Search torrents", the same label as the editor.

## The strip (§10.4)

- **Chips:** every top-level clause except free text (`word`, `phrase`, `near`, `prefix`, `fuzzy` on `any`, and an `or` of only those). A negated word (`-cam`) is not free text, so it gets a chip ("Not: cam").
- **Labels** (patterns; values through `$lib/format` only):
  - `{key}: {value}`, `{key}: at least {v}`, `{key}: at most {v}`, `{key}: {lo} to {hi}`;
  - dates: "Discovered in the last {span}", "… more than {span} ago", "… on / since / until {date}" (UTC days), "… {from} to {to}";
  - `Not: …`, `Any of: … or …`, `All of: … and …`, `A file matching: …`, nested three deep and cut at 80 characters (the accessible name keeps it all);
  - lists use `Intl.ListFormat` in the current locale.
- **Field names:** `name:` is the glossary's "Raw name" and `title:` "Resolved title"; `path:` is "File paths".
- **Values:** tag values show in mono as the server normalised them. `type` and `adult` values use labelled messages. The hash shows 12 characters and "…", with the full hash in the accessible name.
- **Year, season and episode are identifiers:** plain integers, not grouped ("2019", not "2,019").
- **A `>` bound** is lowered by the server to `lo + 1` and shows as "at least" the formatted value ("Size: at least 4.00 GiB").
- **The `hidden=1` chip** reads "Including: Hidden by filters". The colon keeps the glossary term as it is, rather than lowercasing it.
- **Clear all** keeps the free text and clears `hidden`. W5 has no combined write, so it is two history entries (`setAst`, then `setHidden`); a combined one is a follow-up for W5's owner.
- **Removing:** a failed removal keeps the chip and shows an error banner with Retry. Focus moves to the next chip, else the editor (Chip's `fallbackFocus`), and the polite region says "Removed filter: {label}".

## The page

- **Regions:** `search-rail`, `results` and `search-drawer`, with no landmark role until filled.
- **The drawer:** a lazy `import.meta.glob('/src/lib/features/detail/DetailHost.svelte')`, rendered while `'detail' in page.state`. It is empty until S-detail lands.
- **`ensureSearchPath()`** precedes every search write. See `web/src/lib/features/search/README.md`.
- **The heading** uses the `display` step (§10.2: page headings).
- **The Syntax popover** shows the seven query rows of `docs/query-language.md` "Start here", plus `~bnuny` (the eighth row there is a hash paste, not a query). There is no `/help/syntax` link until a slice owns that page.
