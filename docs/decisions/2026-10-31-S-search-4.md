# S-search-4 decisions: autocomplete, smart chips, natural phrasing and the Builder

Part 1 of 3 of the M5 "Search completion" backlog. Spec: §10.4 "Query bar". Code: `web/src/lib/features/search/assist/`.

- **Everything loads on demand.** `Live.svelte` (already lazy) imports the assist chunk when the bar is focused or typed in, and the natural-phrasing preview and the Builder only when their buttons are pressed. The `/search` first load is unchanged: `QueryBar.svelte` is not edited.
- **The listbox joins the editor from outside.** `Assist.svelte` adds a capture-phase `keydown` listener to the bar, so a key it takes (arrows, Tab, Esc, and Enter on an option the user moved to) never reaches the editor's own handler, and `editor.ts` is untouched. It sets `aria-expanded`, `aria-controls` and `aria-activedescendant` on the existing combobox element. The editor's `onescape` hook stays for the Syntax popover; the listbox takes Esc itself. DOM focus stays in the bar (§10.13).
- **Tab accepts the active option, else the first;** Enter accepts only an option the user moved to, so Enter still means "search". Shift+Tab and Tab with no list open keep their normal meaning.
- **Items come from `/suggest` as the server sends them.** The server already orders them (did you mean, chips, fields, values, titles) and returns units as `value` items, so the client adds no unit list. Recent queries (this browser only, `localStorage`, newest first, 8 at most, every access in try/catch) and saved searches (`GET /saved-searches`, fetched when the list first opens) follow, filtered by the typed text. An item's `replace` range is in characters, so applying it and the `pos` sent to the server use code points, not UTF-16 units.
- **No "≈" on suggestion counts.** `SuggestItem.count` has no approximate flag in the API, so counts are always exact (`formatCount`). If the server adds one, the list shows it through the same formatter.
- **Stale answers are never accepted.** An answer is used only while the text still equals the text it was asked for; between keystrokes the server items hide and the local ones stay. Requests are debounced (120 ms), latest wins, and a new keystroke aborts the one in flight.
- **Smart chips are the server's `chip` items.** Accepting one replaces the typed word through the editor and the search state (`setText`), so the server parses it into the AST and the strip shows its chip. The client recognises nothing itself.
- **Natural phrasing never changes the query by itself.** The "Natural phrasing" button (enabled when the bar has text) sends the text to `/parse?natural=true` and shows `natural.chips` and the kept words in an inline panel. Apply puts `natural.canonical` in the bar and searches; Dismiss or Esc closes it and leaves the text. Focus goes to Apply when the preview arrives, and back to the bar on close.
- **Builder: the API has no field catalogue, so the list is typed against the schema.** `builder.ts` lists fields by kind (`text`, `tag`, `ext`, `num`, `date`) with `satisfies` against the generated `AstTextField`, `AstTagKey`, `AstNumField` and `AstDateField`, so a field the server drops or renames fails `npm run check`. Operators are per kind (`:`, `>=`, `<=`, `>`, `<`). Nothing in the existing query code lists fields.
- **Builder round trip.** Rows are the AST's structured top-level clauses (the same ones as the strip). An edited row is joined as `field:operator value`, parsed by the server (`/parse`, which owns syntax and units such as `10GB`), swapped into the AST (`withNode`) and sent through `setAst`, so the bar shows the server's canonical text. Typing in the bar changes the AST and so the rows. A clause that isn't one field/operator/value (groups, two-sided ranges, `size` in bytes, `file:`) shows as a read-only row with its label and a Remove button. The Builder never prints or reads query text beyond that join.
- **No new dependency, no change to `lib/state`, `lib/ui`, `lib/keys`, `lib/shell`, `lib/api`.** `Live.svelte` gets the mount lines (the owner of the bar's lazy part); `QueryBar.svelte` is unchanged.
- **zh:** the new `search_assist_*` keys are English only and use the documented fallback.
