## One label formatter per field
- **Where they are.** Each field has its own module in `web/src/lib/format/`. `labels.ts` gathers them for the tests and as an index.

| Field | Formatter (module) | Words | Examples |
|---|---|---|---|
| Video codec | `videoCodecLabel` (`label-release`) | proper names | `h264` → H.264, `h265` → H.265 (HEVC), `vc1` → VC-1 |
| Audio codec | `audioCodecLabel` (`label-release`) | proper names | `dts-hd-ma` → DTS-HD MA, `truehd` → Dolby TrueHD, `ac3` → Dolby Digital |
| HDR | `hdrLabel` (`label-release`) | proper names | `dv` → Dolby Vision, `hdr10+` → HDR10+ |
| Release source | `releaseSourceLabel` (`label-release`) | names; the kinds of copy as messages | `web-dl` → WEB-DL, `bluray` → Blu-ray, `cam` → Camcorder (摄像机录制), `tv` → TV broadcast |
| Language | `languageLabel` (`label-release`) | `Intl.DisplayNames` in the UI language; `multi` is a message | `fr` → French (法语), `multi` → Multiple languages |
| Release group | `groupLabel` (`label-release`) | as sent, never re-cased | `RARBG` → RARBG |
| Parsed attribute (Compare) | `attributeLabel` (`label-release`) | the field's formatter, one part of a list at a time | `acodec` "dts-hd-ma, truehd" → "DTS-HD MA, Dolby TrueHD" |
| Content type | `typeLabel` (`label-type`) | glossary `content_type` | `ebook` → Ebook, `video` → Video |
| Adult type | `adultTypeLabel` (`label-type`) | glossary `adult_kind` | `vr` → VR |
| File-type group | `fileGroupLabel` (`label-type`) | glossary `category_group` | `video` → Video |
| Source, with the server's name | `sourceLabel` (`label-source`) | the glossary's "DHT"; else the server's name; else the importers' messages | `dht` → DHT, `bitmagnet` → bitmagnet import |
| Source, by id alone | `sourceIdLabel` (`label-source-names`) | the plugin's manifest name | `nyaa` → Nyaa, `archive_org` → Internet Archive |
| Query field (Builder) | `fieldLabel` (`label-field`) | the glossary's words, else the filter chips' labels, else new messages | `res` → Resolution, `name` → Raw name, `seeders` → Seeders, `sig` → Payload signature |
| Theme | `themeLabel` (`label-theme`) | the theme's own family name from `themes.json` or the browser's custom themes | `riverstone` → Riverstone |

- **A value with no label shows as sent**, never as an empty label. Lookups read own keys only, so a value such as `constructor` is never resolved through the prototype.
- **No glossary change (runner).** Codec, HDR, release-source and language words are messages or proper names.
- **The vocabularies are checked against `crates/` at test time** (`labels.test.ts`). The test fails, naming the value, when:
  - the release parser's codec, audio, HDR or source lists gain a value with no label, in en or zh;
  - a plugin manifest in `crates/sources-plugins` has a name the table doesn't match;
  - a query field in `crates/search/src/query.rs` has no label.

  Each check was mutation-tested. The test also fails when it can't read an entry (review): it reads every `Manifest { … }` construction in `crates/sources-plugins`, subdirectories included and in any field order, resolving an id or name given as a string, a const or a path to one, and fails on any it can't. A copy (`..MANIFEST`) that sets no id is left out. It also counts the FIELDS rows and fails if the pattern missed one, whatever characters a name has.

## Why each field has its own module (runner call, §2.26)
- **The brief asked for one module exported from `format/index.ts`, "the way the others are".**
  - Rolldown kept the label tables in every screen that imports `$lib/format`.
  - About 15 size entries grew by about 3.5 kB, including every Settings screen, Alerts and Welcome.
- **So the formatters are per-field modules, and `index.ts` exports only `bucketTimeZone`, which has no table.**
  - A screen imports the module of the field it shows, so a table loads only with the screens that show it, as the brief asks for tables not needed on first render.
  - The plugin-name table (`label-source-names`) is split out for Insights, which gets ids alone. The detail gets names from the server, so its first view carries only "DHT" and the importers.
  - Adult types have their own formatter, so screens that never show them don't carry them.

## Call sites (label lines only)
- **Facets:**
  - every term facet's values go through `valueLabel`;
  - the Source facet uses `sourceLabel`, which replaces `shortName` (`search/unverified/source.ts`, removed);
  - FacetRail's own type map is removed.
  - A long list's "Find" box matches the label or the code, in any case, so `fr` and "French", `h264` and "H.264" both find their entry: the codes are what a query types (review).
- **Builder:**
  - Fields read "Resolution (res)": the label, with the code beside it.
  - A native `<select>` option can't style part of its text, so the code is in parentheses rather than mono.
  - Values read as their labels ("Movie", "H.264"), and a flag's `yes` and `no` read "Yes" and "No", as the facet rail says them (review). The option values, and so the query, stay the codes. `network` values have no table and show as sent.
- **Detail:** "Found by" and its Differences use `sourceLabel`.
- **Compare:**
  - Attribute values use `attributeLabel`.
  - The type and group cells use the shared formatters.
  - Its own `compare_type_*` and `compare_group_*` maps and messages are removed.
- **Insights:**
  - Sources in Segments and on the Discover stage use `sourceIdLabel`.
  - The Discover stage's CSV export keeps plugin ids. It's the server's `/api/v1/insights/export.csv`, which writes `key` (`crates/api/src/insights/csv.rs:177`). X-insights-source-names, which the runner queues, will consider names there.
  - Types use the glossary's labels (below).
- **Appearance:** "Current theme: Riverstone", not `riverstone`.
- **Filter chips (`search/query/clauses.ts`) are left alone (runner):** they echo what the user typed.

## Release-group case (follow-up)
- **Facet values for release groups arrive lower-cased.** The search index stores tag terms lower-cased (`crates/search/src/doc.rs:129`), and facets read those terms back (`crates/search/src/facets.rs:1115`). No client formatter can recover "RARBG" from "rarbg".
- **`groupLabel` passes the value through** in this slice. Compare already gets the parser's original case and shows it.
- **The runner queues the display form on `crates/search` as its own slice.**

## Dates in the chosen time zone (U28)
**The rule is `docs/metrics.md` §1–2:**
- Times show in the zone Language & region chose. With "Automatic", that's the browser's zone (`displayTimeZone()`).
- Day buckets are UTC days on the server, so they're shown in UTC and named UTC.

**`bucketTimeZone(bucket, zone)` (`format/zone.ts`) decides which:**
- an instant or an hour bucket uses the chosen zone;
- a day or week bucket uses UTC.

**Insights:**
- **Instants are in the chosen zone:**
  - the "updated" time and "Times in {zone}";
  - stale since;
  - annotations and import markers;
  - Needs attention's "since";
  - the print header.
- **Hour buckets are in the chosen zone:** the movement charts and their tooltips, hourly funnel cohorts, and the "Event time, in {zone}" captions.
- **Day buckets stay UTC days,** and their captions name UTC ("Event time, in UTC"), whatever the chosen zone.
- **The range text ("Oct 1 – Oct 7") stays in UTC:** it's the UTC days the query covers, as the URL writes them.

**Logs:**
- Local time follows the chosen zone. It used the browser's, and ignored the setting: the same U28 bug.
- The UTC switch is unchanged.
- A zone the browser doesn't know falls back to the browser's clock.

**Tests:**
- Hourly cohorts and annotations in `Pacific/Honolulu` (UTC−10) across a date boundary; daily cohorts as UTC days; Automatic resolving to the browser's zone (`zone.test.ts`).
- Logs at UTC, Tokyo and Honolulu, with the UTC switch winning.
- An e2e run at `timezoneId: 'Pacific/Honolulu'`, which shows "Times in Pacific/Honolulu". The other Insights e2e cases pin `timezoneId: 'UTC'`, so they don't depend on the machine.
