# B-search-meta decisions

Runner brief, 2026-11-01, a follow-up from #250. No owner decision changes.

## Approximate suggestion counts (§8 "Counts", §10.4)
- **Named `count_approx`, not `approximate`.** The brief asked to reuse the name search totals use, and every count's flag in the API is `<count>_approx` (`total_approx` on search, facets, Discover and jobs). `SuggestItem.count_approx` is optional in the schema and absent when false, so existing goldens and clients are unchanged.
- **Only title counts can be approximate.** Value, flag and chip counts run `count::exact` under the request's budget; past it the request fails (`suggest_timeout`), it never returns a partial count. Field names, `cat:`/`bytes:` categories and "did you mean" carry no count, so no flag.
- **A title's count is approximate exactly when it isn't counted live:** the title set's count is above 1,000 (`LIVE_CAP`) and the live walk reached the cap, so the set's number stands. That's the same rule as search totals (exact up to a bound, an estimate past it, marked). The flag comes from the walk suggest already did: the bound, the early stop and the reported numbers are unchanged, so suggest's cost is too. A title set a build behind can still undercount a title newer torrents share, until its next build, as before; that's staleness bounded by the set's rebuild, not an estimate, and isn't flagged. An earlier draft counted one past the set's count to prove exactness, but that loses the early stop on every title the set has right, which the brief rules out. `search-bench --torrents 200000 --gate` after the change, `/suggest` p95 per class (target 15 ms): title prefix 4.64, short prefix 6.31, field value 2.49, smart chip 2.84, did you mean 3.19, did you mean 32 words 4.59, field name 6.02 ms; all PASS.

## Field catalogue, `GET /search/fields` (§8, §10.4 "Builder")
- **One source of truth.** `lodestar_search::catalogue` reads the parser's own `query::FIELDS` table. A later name for a field kind already listed is its alias (`age` for `discovered`). Value types and operators come from an exhaustive match on the parser's `FieldKind`, so a new kind doesn't compile until it's described. A test parses every listed operator and value of every field and alias, and another checks every field the parser accepts is listed exactly once. Fields that only arrive later (`sig:`) are left out, as suggest leaves them out.
- **Shape:** `name`, `aliases`, `type` (`text`, `number`, `size`, `date`, `enum`, `keyword`, `flag`, `hash`, `magnet`, `share`, `file`, `time`), `operators` (`eq`, `gt`, `gte`, `lt`, `lte`, `range`, `any_of`, `phrase`, `prefix`, `fuzzy`, `group`), `values` when the list is fixed, and `facetable`. Open tag fields (`res`, `codec`, `lang`, `group`…) are `keyword` with no values: their values come from the index, and `/suggest` and `/facets` already serve them with visibility applied. `cat:`/`bytes:` are `share` with the file categories as values. `facetable` comes from `Facet::ALL`; the `category` facet is the query's `cat:`.
- **Content safety (§20.9, B17):** the only Adult names in the query language are the `adult:` field (its subtypes) and `type:adult`. With "Show adult content" off, both are left out, as the Adult facet and the Adult subtype filters are. `hidden:`, `demoted:` and `flagged:` stay: they name filter states the user set up (§20.3), not hidden content. Nothing in the catalogue reveals a filter rule, list or match.
- **Cheap and stable:** built once per visibility (two static tables), then a clone per request, O(fields). It doesn't read the index, so it answers while search is turned off. Same auth as `/suggest`.
- **`facetable` means a term facet** (`Facet::ALL`). The histograms `/facets` also serves (`size`, `discovered`, `year`) are false; a later Builder slice can add a `histogram` flag from `Histo::ALL` if it needs one.
- **Follow-up, not changed here:** `/suggest` still offers the `adult:` field name while Adult is hidden (`suggest::field_names`, pre-existing). The catalogue leaves it out, so the two disagree until a slice that owns suggest's field list filters it.
