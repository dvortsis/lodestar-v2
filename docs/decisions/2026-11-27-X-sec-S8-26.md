# X-sec-S8-26 decisions

Security fix slice, 2026-11-27. Finding S8-26 (important; surface: the enrichment runtimes). Spec: architecture §18.7 and §20.9; owner-decisions §2.37 and §2.47; `docs/decisions/2026-11-24-ENR-G.md` properties 1 and 2. A tightening of content-safety rules only: nothing is loosened.

- **The gate is asked again for every request, just before it goes.** Both enrichment runtimes (`adult_enrich`, `identify`) still judge an item with their whole gate (`check_with`) before calling the plugin. The plugin is now handed only a checked client (`crates/pipeline/src/presend.rs`, over `Client::checked`): the same limiter, so the pacing is shared, and a check that runs the same gate again, for the same item and the same query, after the client's pacing and back-off waits and just before the request is handed to egress. `send`, `poll` and `poll_stream` all go through it. The gate reads everything afresh then: Show adult content, the kill switch, the source's state, consent, holds, hides, the live filter, corrections and the item's adult reading.
  - **Fail closed, and for the whole lookup.** A refusal, a store error, a panic or a changed query sends nothing, and every later request of the same lookup is refused too.
  - **A refused request is not the host's fault.** It fails with `HttpError::EgressDown`, which the limiter doesn't count against the host, and the identify runtime's timeout path charges no host for a refused lookup.
  - **The answer of a refused lookup is dropped**: not emitted, not cached, counted as `withheld` in each runtime's stats. A plugin-wide reason (Show adult content off, the kill switch, the source off or unconsented, or a store error) makes the runtime wait, as the first check does; an item reason passes the item over. A lookup refused after one of its requests already went counts as asked, so the next lookup still waits the runtime's interval. A withheld lookup still counts against the day's budget and in `looked_up` (the safe side).
- **The writer stores no identification on an item that's Adult now** (`unverified::ingest`, `identify::adult_now`). Adult by any reading the identify gate uses: stored as adult, your correction, an always-adult finder, detection now or a rule under the live filter. `adult_now` shares its reading with the gate (`own_correction`, `read_now`), so the two can't disagree. An item no longer stored reads as adult. A refused answer counts as `refused`.
- **`Client::checked` in `crates/sources/src/http.rs`** (runner, 2026-11-27, a shared edit beside X-sec-S8-25): a client on the same limiter that asks a check before every request, after the limiter's waits, on `fetch` and `fetch_stream`, failing closed with `EgressDown`. The inner fetch stays private, so a plugin can't reach the network past the limiter or past a check, and checking a checked client keeps both checks. Unit tests there cover each of these.
- **Tests** (`crates/pipeline/tests/adult_enrich.rs` and `tests/identify.rs`, `::the_gate_is_asked_again_when_the_request_goes`; `tests/identify.rs::no_identification_is_stored_on_an_adult_item`; `src/presend.rs` unit tests): a lookup waits before its request while one condition changes, for each condition the gate reads; the request is never sent and nothing is emitted, and with nothing changed the one request goes. Every path of the client asks the gate. Waits poll a condition with a 10 s deadline.
- **Not changed:** the pacing, the budgets, the lookup timeout and the plugins themselves. Egress may still probe a proxy route between the gate and the socket; that probe sends nothing to the service.
