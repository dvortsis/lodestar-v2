# S-logs-2 decisions: Settings → Logging, part 2a

Part 2a of the slice: events, data kinds, opt-ins, never logged, the banners and `/logs`'s Turn off now (§10.10.12, §12.1). Part 2b adds outputs, log files, the Danger zone and the preview.

- **Privacy changes are sent at once, not staged** (§10.10.7 Privacy, §12.1). A data kind, a data preset, an opt-in and Turn off now each send `PATCH /settings` themselves, after their dialog, instead of waiting for the Save bar. Reasons:
  - a deadline should start when you confirm it, not when you later press Save;
  - a switch shows on only once the server has saved it, so a refused or failed request leaves the kind off;
  - the banners reload `GET /logs/catalog` after every change.
    Each change is built from `GET /settings/logging` read after the dialog is answered, and sent with that `if_revision`. A change made meanwhile, in another tab or by Turn off now on `/logs`, is refused rather than overwritten, so a stale snapshot can't turn a kind back on. If the state can't be read after a successful change, the screen says so, and the catalog keeps reloading every tick until it can be read.
    Only Verbosity, the events, the per-component levels and the Libraries filter are on the form engine. Those are Safe changes: staged, saved, Undo. The form merges the new revision through `received`.
- **The UI never decides that a kind is on.** The switches, the time left and the banners all read the catalog's `until`. When a deadline the catalog listed has passed, the catalog is reloaded. The UI never assumes the kind is off: the server enforces deadlines (`settings/logging.rs`), and the UI computes one only to send it, on the server's clock (the catalog's `now`).
- **The duration is asked with the confirmation dialog's answers.** The answers are Cancel, Until I turn it off, For 24 hours and For 1 hour, with 1 hour as the main action. Focus starts on Cancel, so pressing Enter by accident turns nothing on. The opt-ins have no "until I turn it off" (§12.1).
- **Presets.** A preset other than Private asks first, sets its deadline and clears the identifying per-kind switches. Switches of kinds that identify no one (client addresses, sizes) survive a preset, as they survive Turn off now. A preset never sends the opt-in fields. Custom is shown, never chosen: per-kind switches make it.
- **Delete offer.** Whenever a change turns off any identifying kind or opt-in (a kind switch, a preset such as Full → Hashes, or Turn off now), the user is offered to delete the files with torrent details (`DELETE /logs/files {which: "details"}`). The dialog shows their count and total size, and focus starts on Keep. The total is the client's sum of `GET /logs/files` sizes, because no endpoint reports it. That is the one count the client computes; it is formatted through `$lib/format`.
- **`/logs` Turn off now** turns off everything its single banner covers: the identifying kinds and both opt-ins. It uses the same module (`settings/logging/privacy.ts`), loaded on the click.
- **Event names.** The catalog names each event's messages (`logs.event.<id>.label/help`), but none exist yet: about 200 events × 2 messages × 2 locales. Until a follow-up slice writes them, a row shows the event's stable id. `logging/event-labels.ts` holds the lookup.
- **What the first view holds (size, §10.1).** The first view is the heading, the "Open live log" link and the events form. Everything else loads after it: `parts.ts` (catalog, banners, data kinds), the Verbosity control, the event list, the component levels, the dialogs and the privacy requests. The banners and data kinds depend on `GET /logs/catalog`, so loading their chunk alongside that request adds no visible wait. Logging's group headings are the screen's own messages, not new `settings.group.*` keys, so the shared group map doesn't grow for every Settings page. The registry entry forwards through `body.ts` to the body, as Security's does.
- **The identifying banner shows when logging stops**: the latest deadline, or "until you turn it off" if any kind has no end. That's what `/logs` shows too.
- **Temporary verbosity.** The event list shows the saved settings. While a temporary level from the live log ("Detailed for 30 minutes") is on, a note says that more events are recorded right now than the list shows.
- **Expert** is a disclosure of its own for the Libraries filter, below Advanced, which holds the per-component levels.
- **Notifications' first-view limit is 45.1 KB** (runner, §2.26). The Logging registry entry adds about 81 B to the shared `screens` chunk, measured with the `body.ts` forwarder (191 B without it), and about 10 B of chunk re-splitting. Notifications goes from 44.994 to 45.045 KB on main plus the entry, and every other Settings first view grows about 0.11 KB while staying under 45 KB. Only Notifications' limit is raised. The runner has queued a structural fix that moves the registry titles out of the shared chunk. The gear icon stays.
- **Event labels are a follow-up** (runner). About 800 en and zh messages are needed. Until they exist, showing each event's stable id is acceptable. The lookup hook in `event-labels.ts` stays.
- **Review round (runner, from the #289 review):**
  - **When the state can't be read**, the screen shows a warning banner in the banners' place, with Retry. Without the catalog it can't say whether torrent details are being logged.
  - **On `/logs`**, a failed reload after Turn off now keeps the last known banner rather than hiding it.
  - **The data preset control** shows only what the server has: it's redrawn after every choice, so a cancelled, failed or pending choice never shows as selected.
  - **Leaving the screen** closes an open duration or delete dialog unanswered (`ask`'s signal), so nothing is sent.
  - **The event list's groups** open and close from the summary's click (Enter and Space fire it too), not from the native `toggle` event, which arrives later. The open state lives at module level, so it survives the list remounting during a resync.
  - **Sizes.** CI's size job on 4ea96c7d passed every entry: Alert route 45.98 KB (limit 46), Search results 43.28 KB (limit 43.3), Notifications 45.06 KB (limit 45.1). Built locally, `main` with #288 puts Alert at 46.00 KB already, and this branch measures 45.99 KB, so the branch doesn't grow it. The only increases against `main` are the Settings first views, about 0.06–0.08 KB from the registry entry (as ruled above), and the Logs route, about 0.9 KB from Turn off now. Logging parts measure 16.48 KB (limit 17.1).
