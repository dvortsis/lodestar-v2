# X-flakes-1105 decisions: the restart_wire and magnetico flakes

Both fixes are test-only. Neither race was in product code.

- **`restart_wire::no_restored_peer_is_sampled_before_its_deadline`: stray datagrams from other tests.**
  - **Cause:** this test's 40 peer sockets bind ephemeral loopback ports, and its `samples_received` counted every `sample_infohashes` query that reached them, whoever sent it.
    - Other tests in the same binary run at the same time with `sample_start_delay: Some(ZERO)` and contacts on fixed loopback ports:
      - `127.0.0.1:65530` in the routing table, for example `queued_drops_are_counted_without_a_permit`. This port is inside Windows' ephemeral range, 49152–65535.
      - `:40001`–`:40003`, offered by `prefix_tests.rs`. These are inside Linux's range.
    - Their `maintain` → `sample_tick` offers those contacts to the sampler and sends real queries to them.
    - When the OS hands one of those ports to a peer socket here, the first-start `all(n == 0)` check sees another test's query. That is the `actor.rs:3609` failure in #454's Windows job.
  - **Reproduced:** with one peer socket pinned to `:65530`, the full `lodestar-dht --lib` suite failed 15 of 15 runs at that line. With the fix it passed 15 of 15.
  - **Fix:** `samples_received` counts only datagrams whose source is the actor under test (`cfg.bind[0]`) in both runs.
    - The property is unchanged: no query from this node before the suppression ends or before a restored deadline, and each peer is sampled exactly once in run 1.
    - The `n == 1` check still fails if the filter matches nothing.
    - The run-2 `first_seen` record takes the same filter, so a stray query can no longer make a peer look sampled early.
  - **Not done, outside this slice's paths:**
    - `prefix_tests.rs`'s `sample_target` takes the first `sample_infohashes` from any source, so it has the same exposure. The runner is told.
    - Moving the other tests off fixed ports isn't done either. The filter makes this test correct whatever else is on the loopback.
- **`magnetico::tests::file_less_parents_stay_within_the_byte_budget`: out of disk, not timing.**
  - **Cause:** 500 rows with 3 MiB names, written in one transaction, made a 1.5 GB WAL. The close-time checkpoint then needs another 1.5 GB in the database file.
    - When the temp disk is short, SQLite drops the failed checkpoint silently and leaves the WAL behind.
    - `open` then correctly refuses the file as `NotQuiescent`.
    - How much disk is free depends on the other tests running in parallel and on a cloud session's fixed allowance.
  - **Reproduced:** with `TMPDIR` on a 2.5 GB tmpfs, the test fails with `open: NotQuiescent`. On 3.5 GB it passes.
  - **The test also never reached the byte budget.**
    - The read guards a name at 4096 bytes, so an over-limit name costs 8 bytes.
    - A file-less parent therefore costs at most about 4.3 KB, and 500 of them stay under 8 MiB.
    - What the old test exercised was the guard and the 500-parent cap (fresh self-review).
  - **Fix:**
    - **The original case is kept, with 32 KiB names.** That is still past the guard. It asserts the same as before: all 500 read, every batch within the budget.
    - **A second case tests the budget.** A first parent has 7,000 files of 1,100 bytes. They all fit, and leave 16,491 bytes of the 8 MiB budget. Then come 300 file-less parents.
      - File-less parents never reach the file-row check, so only the final pass over the kept parents can end the batch.
      - The test asserts the exact batch sizes, `[140, 161]`, and that no files were dropped.
      - With that final pass removed, the case fails: one batch of 301.
    - **Disk:** both fixtures together need about 40 MB.
    - **The fixture `build` checks its WAL** is gone or empty after close. That is the same test `quiescent` applies, so a fixture that couldn't be checkpointed fails as a fixture failure, not as an importer refusal. With the old 3 MiB names on the 2.5 GB tmpfs, it fails with that message.
