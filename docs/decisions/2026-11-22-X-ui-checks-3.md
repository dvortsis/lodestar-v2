# X-ui-checks-3: the pseudo-locale check (#1045)

Date: 2026-11-22. Decided by the build runner (shape approved for X-ui-checks-3); the details below are the slice's.

## Decisions

- **Message level.** `web/scripts/pseudo-locale.mjs` turns every message into a longer, accented look-alike wrapped in ⟦ ⟧ (about 35 % longer, `{placeholders}` kept). Every ASCII letter maps to an accented one, so a plain run of Latin letters on a screen did not come from the catalogue. Unit-tested in `web/scripts/pseudo-locale.test.ts`.
- **A separate build, run nightly and on dispatch only.** `scripts/pseudo-locale.mjs run` copies `web/` to a scratch folder, rewrites each feature's `messages/en.json` there (`vite.config.ts` merges those into `messages/en.json` on every build, so the sources are what must change), builds and serves it with `vite preview`. `web/messages`, `web/project.inlang/settings.json` and `web/build` are not touched. The `pseudo` Playwright project is opt-in (`--project=pseudo`) and has its own server and port (4174); a PR run never builds it.
- **The pseudo build never ships.** It is written to `$TMPDIR/lodestar-pseudo-<port>` (override: `PSEUDO_DIR`). The script refuses a folder inside the repository and one that contains it, and deletes only a folder that is missing, empty or marked as its own (all unit-tested). The scratch copy has its own `node_modules/.cache`, so the asset step's stamp never reaches the real tree. It is outside every path a release, the Docker image or packaging reads. The `pseudo` project serves only from that folder.
- **What the check fails on.** On every route in `e2e/support/routes.ts`, at 390 px and 1366 px: a page wider than its viewport; text clipped without an ellipsis or line clamp, sideways or down (screen-reader-only boxes excluded); and plain Latin letters in visible text, `aria-label`, `title`, `placeholder` or `alt`. The allowlist is short and commented in the spec, and each fixture entry is as narrow as the fixture: the product and client names, protocol names, hexadecimal with a digit, Intl-formatted units, times and dates, addresses and environment variable names, and the fixtures' own strings ("The Lantern Keeper", dotted release names, the exact titles "Show" and "Title 1"). The boot shell (`src/app.html`, static English by design, covered by `boot-shell.routes.test.ts`) and the legal notice (the server's English document) are skipped.
- **`web/playwright.config.ts` is in the slice's owns** for the new project only. `project.inlang/settings.json` is not.
- **CI.** A step in the existing nightly/manual `all-themes` job runs the project with its own report and output folders, `if: always()`, so an all-themes failure does not hide it. A pseudo failure fails that job, and the job's run summary counts both runs, so the tracking issue lists the pseudo specs that failed (titles start "pseudo: "). `if: ${{ !cancelled() }}` runs it after an all-themes failure but not after a cancel.

## Findings: hard-coded English the app still has

The check found two. They are in the spec's `KNOWN_GAPS`, so the nightly run reports new ones; a fix removes its entry and the check then guards it. The follow-up slice is **X-pseudo-text-gaps** (the runner adds its entry); this slice changes no app code. When it lands, it removes both entries from `KNOWN_GAPS`.

- **Relative times: callers do not pass the catalogue's "just now".** `web/src/lib/format/relative.ts` keeps an English fallback (`{ en: 'just now', zh: '刚刚' }`, "until W4 supplies it") and no caller passes `opts.justNow`, so the catalogue message is never used. Chinese users see Chinese; the pseudo build shows plain English.
- **Insights annotations insert the raw setting value into a translated sentence.** `Movement.svelte` passes the raw setting to `m.insights_overview_note_intensity({ level })` ("aggressive"), and the neighbouring `m.insights_overview_note_unknown({ kind })` does the same with the event kind. A fix looks the value up in the catalogue.

The Insights "hr" unit looked like a third gap but is not: `formatSpan` uses `Intl.NumberFormat` with `unitDisplay: 'short'`, which gives "hr" for English and 小时 for Chinese, like the other Intl-formatted times the spec allows.
