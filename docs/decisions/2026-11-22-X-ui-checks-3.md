# X-ui-checks-3: the pseudo-locale check (#PR)

Date: 2026-11-22. Decided by the build runner (shape approved for X-ui-checks-3); the details below are the slice's.

## Decisions
- **Message level.** `web/scripts/pseudo-locale.mjs` turns every message into a longer, accented look-alike wrapped in ⟦ ⟧ (about 35 % longer, `{placeholders}` kept). Every ASCII letter maps to an accented one, so a plain run of Latin letters on a screen did not come from the catalogue. Unit-tested in `web/scripts/pseudo-locale.test.ts`.
- **A separate build, run nightly and on dispatch only.** `scripts/pseudo-locale.mjs run` copies `web/` to a scratch folder, rewrites each feature's `messages/en.json` there (`vite.config.ts` merges those into `messages/en.json` on every build, so the sources are what must change), builds and serves it with `vite preview`. `web/messages`, `web/project.inlang/settings.json` and `web/build` are not touched. The `pseudo` Playwright project is opt-in (`--project=pseudo`) and has its own server and port (4174); a PR run never builds it.
- **The pseudo build never ships.** It is written to `$TMPDIR/lodestar-pseudo` (override: `PSEUDO_DIR`), and the script refuses any folder inside the repository (unit-tested). It is outside every path a release, the Docker image or packaging reads. The `pseudo` project serves only from that folder.
- **What the check fails on.** On every route in `e2e/support/routes.ts`, at 390 px and 1366 px: a page wider than its viewport; text clipped without an ellipsis (screen-reader-only boxes excluded); and plain Latin letters in visible text, `aria-label`, `title`, `placeholder` or `alt`. The allowlist is short and commented in the spec: the product name, protocol and unit symbols, hexadecimal, Intl-formatted times, fixture data, addresses and environment variable names. The boot shell (`src/app.html`, static English by design, covered by `boot-shell.routes.test.ts`) and the legal notice (the server's English document) are skipped.
- **`web/playwright.config.ts` is in the slice's owns** for the new project only. `project.inlang/settings.json` is not.
- **CI.** A step in the existing nightly/manual `all-themes` job runs the project with its own report and output folders, `if: always()`, so an all-themes failure does not hide it. A pseudo failure fails that job; the tracking issue's summary covers the all-themes run only, so it points at the run page for the pseudo result.

## Findings: hard-coded English the app still has
The check found three. They are listed in the spec's `KNOWN_GAPS` so the nightly run reports new ones; a fix removes its entry, and the check then guards it. They need a follow-up slice (the runner places it); this slice changes no app code.
- **The relative-time formatter prints "just now" in English** (a `<time>` element, Alerts and Insights).
- **The Insights time KPIs print the unit "hr" in English** ("≈ 25 hr").
- **Insights annotations insert the raw setting value inside a translated sentence** ("Intensity changed to aggressive"): the value is not looked up in the catalogue.

## Not done
- A project run together with another (`--project=pseudo --project=core`) has only the pseudo server; run it alone.
