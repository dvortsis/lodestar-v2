# S-insights-1 decisions (Insights overview story)

The `/insights` overview (architecture §10.9–10.9.4, §10.9.6; `docs/metrics.md` §6). No owner decision is reversed or loosened, no security or content-safety decision is weakened and no owner-set number changes. The choices below fill what the brief left to the slice; the runner flags them (`docs/owner-decisions.md` §2.19).

## Reading the data

- **No client arithmetic.** Every number shown is a response field through a `$lib/format` formatter. Sorting, choosing and bar geometry (`lengthPct`, flex-grow from a server share) are the only things done with a number. `components.test.ts` pins each rendered figure to a formatter applied to a field.
- **Stage strip → level** (a link that scrolls to the level's `<h2>` and focuses it): Discover → Movement, Fetch → Funnel, Understand → Segments, Index → Status, Serve → Serve.
- **Live updates:** `events.on('insights')` and its resync refetch the overview through a `latest()` slot, quietly (no placeholders, numbers change in place). The 30 s `crawler`-driven fallback in the brief is dropped, since #130 merged. A `crawler` event whose `paused` differs from the loaded status refetches the status and the overview.
- **Starting up:** `final_cohorts` belongs to the range, so a range with none makes one extra `range=all` request. Only when that has none either does the page show the `searching_crawling` scene and the live `crawler` counters. If that request fails the page shows its data as usual. A range-independent flag from the server would remove the request (follow-up). The `offline_idle` scene shows whenever `kpi.health.state` is `paused`, with a Resume button, and takes precedence.
- **Time zone:** buckets are UTC, so axes, tooltips and annotations use `range.tz` (always `UTC`) and the bar says so. The user's time-zone preference is not loaded app-wide yet; this changes when it is.

## URL

- `/insights?range=24h|7d|30d|all|custom&from=&to=&compare=1`. Defaults (`7d`, no compare) are left out; other parameters (`density`) are kept. An unknown range, a custom range without a valid `from < to`, or a `compare` that is not `1` is replaced (`replaceState`) by what it parses to, with no error. Range and compare changes push history entries.
- **Custom range:** two UTC-day inputs. `from` is the first day's start, `to` is the start of the day after the last chosen day (so both days are included). A server `400` with `field: from|to` shows on that input.
- **Compare with All:** the toggle stays, disabled, with "Not available for All"; the parameter is not sent.

## Layout

- **DOM order is the narrow order** (runner, 2026-10-23: tab order must match visual order, WCAG 1.3.2 and 2.4.3): status, exceptions, funnel, movement, segments, Serve, detail. Nothing is reordered with CSS `order`. Exceptions are full width at every size, because a funnel-before-movement DOM order cannot also put movement and exceptions in one row. Panels inside a level (funnel + losses, group + type) sit side by side from x-large.
- **Styles are route-only:** `overview/insights.css` (plain CSS on token variables, `ins-` class names so Tailwind and daisyUI never match them) ships in the route chunk. No new Tailwind utility is used beyond classes already in `main`'s CSS (`sr-only`, `absolute`, and those inside the shared primitives).
- **Funnel:** built in this folder (`LinkedBars`), since `HBarList` re-sorts and has no link. Segment bars use it too, for the same reason.
- **Loss bar:** one 100 % bar from `funnel_total.loss_share`, every segment `--data-1` separated by `--compbar-gap` (flex-grow = the server's share). The list below carries the identity (reason, count, share). §10.18's data slots mean file categories, so a non-category palette for loss reasons is a token gap.
- **Per-cohort view:** the latest 24 cohorts, newest first, as bars of `stages.harvested` with the searchable count beside. A cohort with `final: false` has a hatched bar (an SVG pattern in the bar's own colour) and the word "Incomplete". "Show all" reveals the rest; the table alternative always lists every cohort.

- **Funnel stage → page:** Harvested and Peer found → Discover, Metadata fetched → Fetch, Stored → Understand, Searchable → Index. Peer found could as well point to Fetch (no-peers losses); Discover is the stage that finds peers.
- **Failures:** a custom-range `400` shows on its field and a neutral line, not the "could not load" banner. A failed load is announced once, by the banner's alert role.

## Budget (owner, 2026-10-23)

- **Owner's reading of §10.1:** the Insights budget counts the first view. Its JS + CSS before any chart must be ≤ 45 KB gzipped. uPlot and the levels below the fold load lazily, near the viewport or at idle, behind fixed-height placeholders. **Runner's cap** (to stop creep): ≤ 65 KB gzipped for the whole page once everything has loaded, typical case.
- **Measured (PR #135, plain `npm run build`, gzipped):** first view **26.0 KB** (the overview chunk and its shared chunks, before any lazy chunk); the whole page **about 60–63 KB** typical (uPlot 22.0 KB JS + 0.7 KB CSS, the shared `keys` chunk 2.3 KB); **about 67 KB** worst case, with the rarely used custom-range form (1.4 KB) and the paused/starting scenes (1.3 KB). Method: the manifest's static closure of the overview chunk, then its dynamic imports, minus the files `/search` loads.
- **Below the fold, lazily:** movement (with uPlot), funnel, segments, Serve, the custom-range form and the paused/starting scenes. A chunk that fails to load shows an error with Retry in its place (and a page-level one for the overview chunk).
- **The route entry loads the overview as its own chunk**, so the app chunk's preload list for `/insights` stays short. **The search route must not move:** nothing this page imports may add Svelte runtime to chunks `/search` shares. Avoided here: `<svelte:element>`, `bind:` on inputs, array destructuring in templates, controlled `value`/`checked` on inputs, spread on elements. `/search` ends +110 B JS against main (39.55 vs 39.44 KB; total 82.02 vs 81.91 KB); Lighthouse on `/search` passes.
- **Size-limit entries** are for the runner to add (S-compare owns `.size-limit.mjs`): the Insights first view (45 KB) and the Insights total (65 KB).
- **Intensity control:** it holds the level the server last reported (reset on every status refetch, so a failed change snaps back) and keeps focus through a change; Compare is a pressed button, shown unpressed for All.

## Open questions and gaps

- **Search drill-through counts (§10.17):** segment bars count newly searchable torrents by event time, while `discovered:` filters by discovery date, so the Search total need not equal the bar. Each Search link is described by a visible note saying so. Open: should Search offer a `searchable:` window so the numbers can match?
- **Backend gaps:** per-stage loss breakdown; segment shares; harvest strategy, IP family and "resolved by"; a Serve series and searches per hour; the B11b exception kinds; a range-independent starting-up flag.
- **W7e:** `LineChart` annotations, a comparison band and the trend brush (annotations are listed under the charts meanwhile).
- **W8:** a span kind for `formatDelta`, so time-to-searchable Δs can show.
- **Tokens:** a non-category data palette for loss reasons.
- **How-to page (standards §4b):** the Insights page has no user-guide page yet; a follow-up docs slice (`docs/user/`, with screenshots once the docs capture exists) names it.
- **Glossary:** content-type labels (Movie, TV, …) as keys; they are `insights_type_*` messages meanwhile.
