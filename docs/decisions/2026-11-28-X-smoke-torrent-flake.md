# X-smoke-torrent-flake decisions (#1180)

- **The smoke test waits for the settled page before axe and the snapshot.** After the heading check, `smoke.test.ts` waits until the page holds no loading placeholder: no `[aria-busy="true"]` and no `[data-testid="skeleton"]`, with a 10 s deadline. Why: `toHaveScreenshot` only needs two identical captures 100 ms apart, and with animations disabled a skeleton doesn't move. So a page still loading passed as "stable". That's how `smoke torrent` at bp1366 came out 2 % off its baseline on #1177 when the same job passed on `main`. Axe now also checks the settled DOM, not a loading one.
- **`RouteCase.ready` names a route's own "loaded" condition** (`e2e/support/routes.ts`). It's for pages where the placeholder check alone could run before anything renders. The torrent page has no heading, so its `ready` waits for `detail-view` and for Technical details, whose placeholder is a bare skeleton. Settings gets its heading ("General") instead. The nightly `all-themes.test.ts` also reads `heading`, so it now waits for it too.
- **Every placeholder in the detail view is a loading state.** Each `aria-busy="true"` there is on a placeholder, and FileTree's is bound to `loading`. Parsed has no marker of its own while `/siblings` is pending, but Related shares that request, so Related's placeholder covers it. A probe of all 12 smoke routes found every page reaching zero placeholders, which makes the check safe as a default. Discover, alert-detail and torrent show placeholders at first; the rest render without them.
- **Baselines shouldn't change.** They were generated from settled pages, and the waits only make the capture later and more settled. CI's shots passing with no `--update-snapshots` is the proof. The nightly `all-themes.test.ts` takes the same key-screen shots without this wait. It's outside this slice, and it's raised with the runner as a follow-up (a shared settle helper for both specs).
