# X-test-blockers-1112 decisions

- **A WireGuard handshake that never completed is its own leak-test outcome: `fail wireguard_handshake_never_completed`** (meaning: check the VPN credentials, for example an expired PIA key). The tester's run failed with only generic lines although the kill switch held. Reason: the report has to say why.
  - **How it's detected:** gluetun stays unhealthy for the whole wait, and its VPN interface has received 0 bytes, read from `/sys/class/net/<if>/statistics/rx_bytes` by the capability-free probe container in gluetun's namespace. `wg show <if> latest-handshakes` would need `NET_ADMIN`, and gluetun may run WireGuard in userspace, where `wg` can't see the device. A counter that can't be read, or isn't 0, keeps the old `fail tunnel_healthy`: an unreadable counter is never read as "no handshake".
  - **It's still a failure, never a pass.** The final line stays `fail leak_test`, so start-block stops as before and passes the line on as it is. The tunnel-up checks that a dead tunnel can't answer (`ipv4_through_tunnel`, `tcp_literal_up`, `dns_up`, `tunnel_recovers`) report `skip`, never `ok`. Both kill-switch phases still run and judge their captures, so a real leak is still reported as a leak beside the handshake line.
  - The grammar's `fail <name>` lines can't carry prose, so the operator-facing wording ("WireGuard handshake never completed (check the VPN credentials)") lives in the name and the script's comment. Mapping step lines to sentences in `steps/run.py` is outside this slice.
- **The portable restart test reads the new copy's `app.serving` from the console or `lodestar.jsonl`, whichever shows it first.** On a saturated 4-vCPU Windows host the copy, at below-normal priority, served about 28 s after the restart, but its file log hadn't flushed by the 90 s deadline. What the test proves is unchanged: the old process exited with 80, the new copy's `app.serving` names the same port, `/healthz` answers there, and the old session still signs in (the same store). The 90 s deadline stays, with no fixed sleep. The earlier restart fixes, which are in the relaunch wait in `src/windows`, are untouched.
