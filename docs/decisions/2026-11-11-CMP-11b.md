## Corrections to `2026-11-11-CMP-11.md`
- **I1's wording overstated the loopback refusal.** CMP-11 refused `localhost`, `127.x` and all-numeric short forms, but read `0177` as decimal and let anything with an `x` through as a name. So `\\0177.0.0.1\…`, `\\0x7f.0.0.1\…`, `\\0x7f000001\…` and `\\0--1.ipv6-literal.net\…` were accepted. This file supersedes that bullet (below).
- **The size in its self-review section** was about 1,800 changed lines at merge, not 1,550.

## UNC loopback spellings (review I1)
- **Refused as well:**
  - any numeric label with a leading `0` and more than one digit (octal to Windows' address parser, and an unusual spelling of a decimal one: `\\192.168.001.20` is refused too);
  - any label `0x` followed by hex digits;
  - any name ending in `.ipv6-literal.net`, Windows' built-in name form for an IPv6 address.
- **Not decoded:** a spelling Windows might read as an address is refused rather than worked out, so no parser difference can let one through.

## A save path's kind matches the platform (review I2)
- **CMP-8b's adapter checks it before anything is sent** (`save_path_wrong_platform`):
  - behind the Windows gate, only a `WindowsPath`: a Linux `/downloads` would land on the current drive's root;
  - without it, only a `HostPath`.
- The gate is what marks a qBittorrent as Windows', so the check reads `gate.is_some()` rather than the host's platform. It holds wherever the configurator is built.

## Registration
- **On Windows, `configure::configurator("qbittorrent")` is the version gate** (`windows_qbittorrent::configurator`), so every configuration passes it: the guided path's plan and apply, and anything later. Elsewhere it's CMP-8b's adapter, unchanged.

## The manager says `guided_only` on Windows, pinned or not (review I3)
- **An installer artifact is refused as `guided_only` before the pin is looked at** (`manager.rs` `installable`). CMP-11 left it answering `awaiting_pin` while unpinned, which a screen could read as "Lodestar will install this once pinned". That isn't owner cq4's flow.
- The API's sentence and the wizard already map `guided_only` to the guided install, so nothing changes in `crates/api` or `web/`.
- `tests/manager.rs` checks `offer` and `install` on Windows with the shipped, unpinned catalogue.

## From #692's review (`rv-692-cfc09faa.md`)
- **N1: each place that logs a timeout at its bound is logged once,** and each one is tested by its own count:
  - the undo's release (`manager.rs` `release_now` from an undone first install): one `release`/`timed_out` line and no `rollback_failed`;
  - the pending release: one line, after it finally answers;
  - a restart's hand-over: one `handover`/`timed_out` line and none under `restart`.

  Mutation-checked: removing each guard fails its test.
- **N2: a restart or regenerate whose hand-over hangs leaves the companion stopped until the store answers** (or Lodestar shuts down). The live operation halts it, waits for the hand-over (which holds the slot so no removal can release under a late save), then starts it. The request itself isn't blocked, because it returns its pending handle. Starting the companion alongside the hand-over is left for a later slice.

## Nits
- **`windows_qbittorrent::configurator`** returns `None` for anything but qBittorrent, so it can't be registered for another companion.
- **`Windows.old`** (an earlier install and its profiles) is refused like `Windows`.
- **Documented, not refused:**
  - `X:\Users\Default\…`, the template profile, passes like any profile (its `AppData` and dot folders are still refused);
  - a drive root shared under another name than its folder's (`\\nas\C\Windows`) passes, because the folders after a share are checked as if the share were named after the root.
- **`last_refusal`** is one slot shared by the configurator's calls. Two plans run at once can overwrite each other's. The guided path runs one at a time.
- **`Supported::check`** reads the found version's `major.minor` once.
