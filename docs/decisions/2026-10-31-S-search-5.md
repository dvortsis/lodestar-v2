# S-search-5 decisions (table mode, column chooser, selection, bulk bar)

Search "table mode", "selection and bulk actions" and the toolbar's select mode (architecture §10.4), on top of the results list (`2026-10-24-S-search-2a.md`) and toolbar (`2026-10-24-S-search-3.md`). Items marked **(§2.19)** refine an owner decision and are for the runner to flag.

- **The view is a URL parameter of its own, `view=table`** (the list drops it), written by the toolbar the way `density` is: `goto` with `replaceState`, so Back still walks searches. `lib/state` doesn't need a field: W5's `writeUrl` keeps every parameter it doesn't own. A "View" segmented control (List/Table) sits beside Density.
- **Table mode is a real `<table>`, not the virtual list.** The scroll container is the table's own (`.rt-scroll`), so a narrow width scrolls the table, not the page. Rows are the compact height (`--row-height-compact`, 36 px, as `docs/design-tokens.md` says), whatever the density. Pages are kept non-virtual: the list's sentinel pattern (`IntersectionObserver` on a sentinel row, root = the scroller) asks for the next cursor page, and the panel's visible "Load more" and end line stay the fallback in both views.
  - The results grid has one shrinkable track below x-large (`minmax(0, 1fr)`), so a wide table can't widen the page.
- **Headers sort through W5's `setSort`, never client-side.** Only the columns the server sorts by (Size, Files, Discovered, §7) are buttons; the others are plain headers. A first press sorts largest/newest first, a second reverses it. `aria-sort` follows the URL's sort.
- **The column chooser** shows/hides and reorders (earlier/later buttons, no drag), is kept per browser in `localStorage` under `lodestar.search.columns`, and validated on read (unknown ids dropped, missing ones appended, Name never hidden, corrupt or unavailable storage means the defaults). Leechers is hidden by default. **Saved views are deferred:** a named set in the same store is possible, but the brief leaves it optional and the screen doesn't need it yet.
- **Selection** is a small store (`bulk/selection.svelte.ts`) of info hashes. `x` (the existing `results.select` default) or a checkbox selects; Shift-click extends a range; it survives appended pages and clears when `results.shown` (the query the rows answer) changes. The checkboxes show in select mode (a toolbar toggle, also turned on by the first selection), in both the list and the table. The count goes through the panel's existing polite region (§10.13).
- **Copy magnets and Export both use `POST /export` with `hashes`** (B10b, up to 10,000): the server builds the magnets (format `magnets`) and the CSV, so the UI has one magnet builder, the server's. Copy writes them newline-joined; Export downloads the file under the server's name. A failure keeps the selection and says so.
- **Compare** is enabled for 2–5 selected and navigates with `compareHref` (the current `density` goes along).
- **(§2.19) Send is deferred.** The OpenAPI document has no send-to-client endpoint (no `/clients`, `/downloads` or similar), so there is nothing to call and no partial/duplicate result to show truthfully. The bar leaves it out, not disabled, as the toolbar does for features without an API. It joins the bar when the endpoint lands.
- **Loading:** the table, the chooser and the bulk bar are lazy chunks. The selection store, the `x` command and the toolbar's two controls are small and load with the panel and toolbar.
- **`/api/v1` is repeated in `bulk/actions.ts`** because `lib/api` doesn't export its base path and its client only reads JSON; `lib/api/**` isn't this slice's to change.
- **(§2.19) Size limits, runner refinement (2026-10-31):** "Search results (lazy)" goes from 41.5 KB to 43.2 KB (+1.5 KB measured: the view switch, selection store, `x` key and announce) and "Results toolbar (lazy)" from 4.4 KB to 4.6 KB (+0.2 KB: the View and Select controls and their messages). Both stay under the 45 KB per-view cap (§10.1). First load is unchanged. New on-demand entries, at measured + 10%: table mode 6.5 KB, column chooser 3.4 KB, bulk bar 2.8 KB, row checkboxes 1.3 KB.
- **What the deferrals need:** Send needs an HTTP endpoint that sends selected hashes to the configured download client and reports per-torrent results (sent, duplicate, partial), as the client adapters already do (§12). Saved views need either a server API for named views or a decision to keep them as a named set in the same localStorage store (`lodestar.search.columns`), plus a UI to name and switch them.
