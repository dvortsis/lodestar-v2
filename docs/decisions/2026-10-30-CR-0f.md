# CR-0f decisions (PR pending)

Follow-up fixes from the CR-0 L2 review (#180, runner comment). They refine [CR-0](2026-10-25-CR-0.md); nothing here reverses an owner decision. The actor-refusal back-off and the pool's `max_lookups` (256) against the actor's cap (32) are unchanged and stay with CR-ADM.

## v0.5.1 release delta
Each line changes runtime behaviour and names its targeted test.

- **Bootstrap seeds skip only the special-range check (release blocker).** Behind fake-ip DNS (Clash, OpenClash, sing-box: 198.18.0.0/15) or DNS64/NAT64 (`64:ff9b::/96`) the configured router names resolve into ranges the CR-0 public policy refuses, so a fresh install without `dht-state.bin` never bootstrapped. The actor now sends its bootstrap find_node to an address that is one of the *resolved configured* routers through `lodestar_network_policy::allows_seed`. That still refuses port 0, unspecified, broadcast and multicast addresses and (without `allow_private`) scoped IPv6, and the subscribed blocklist still applies. Any other address, including one a router hands back, gets the full policy. A router reached this way may answer, but it isn't inserted into the routing table, so it is never routed to or advertised to other nodes. Tests: `fake_ip_and_nat64_seeds_pass_the_policy_learned_nodes_do_not`, `a_special_range_router_bootstraps_and_its_learned_nodes_get_the_full_policy` (a loopback router, also a special range, stands in for a fake-ip answer), `seeds_skip_only_the_special_range_check`.
  - **The exemption covers every special range, not only 198.18/15 and NAT64,** as the brief asked: the operator configured the name, and a split-horizon or local router is equally legitimate. The cost is that whoever controls the resolver can point a router name at a LAN address. The exposure is one find_node per router per bootstrap round, to the configured port only, and the answer's nodes and peers are still filtered. That's no wider than the DNS answer the operator already trusts.
- **`dht.bootstrap_unreachable` (Warn).** Written once when a bootstrap round ends with no router answering: every resolved router refused at send, none resolved, or all queries timed out. A response or an error reply counts as an answer and re-arms the warning, so a later outage is reported again. It carries counts only (`configured`, `resolved`, `refused`); no addresses. Not written when no routers are configured. Test: `every_refused_or_silent_router_warns_once_per_outage`.
- **Pausing cancels queued lookups instead of answering them.** `SetPaused(true)` now drops the reply sender of each queued, accepted request instead of sending an empty peer list. The pool treats an accepted request whose finders all dropped their completion unanswered as cancelled: it gives the attempt back and queues the key in the lookup backlog with no back-off, so a paused pool holds it and a resumed one asks again at once. Chosen over keeping the queue across the pause because the pool's `lookup_wait` timer (30 s) would still expire a long pause's queued work and consume its attempt, and because a dropped receiver is already CR-0's cancellation signal. An actor that shuts down mid-lookup gets the same treatment, which matches CR-0's "unavailable finders defer work without consuming attempts". Running lookups still finish and answer during a pause. Tests: `abandoned_admission_and_pause_leave_no_queued_ownership` (actor), `a_finder_dropping_accepted_work_on_pause_costs_no_attempt_or_back_off` (pool).
- **`dht_lookups_completed_total` excludes cancelled requests.** An owned request whose caller dropped the receiver counts only in the existing `dht_peer_cancelled_total`. `docs/metrics.md` still says the completed counter includes active cancellation; that contract line needs updating outside this PR's paths. Test: `cancelled_same_hash_retry_ignores_the_old_wire_response`.
- **Transaction IDs start in the lower half of u64,** leaving at least 2^63 tokens before CR-0's no-wrap exhaustion stops dispatch. Test: `transaction_ids_start_in_the_lower_half`.
- **More IANA special-purpose blocks are refused** for untrusted destinations: 192.31.196.0/24 (AS112-v4), 192.52.193.0/24 (AMT), 192.175.48.0/24 and 2620:4f:8000::/48 (AS112 direct delegation). Tests: `public_private_reserved_and_mapped`, `range_edges`, `scoped_ipv6_is_rejected_unless_local`.

## Tooling and tests only
- **`analyze_cr0.py` takes the outstanding-RPC limit from the preset:** Low 256, Balanced 1024, Aggressive 4096 (`Intensity::max_outstanding`), from `--intensity` or else `run.json` `settings.intensity`. Evidence without a preset is from the collector that always ran Balanced: it gets 1024 and the `intensity_assumed_balanced` issue. An unknown preset is an error. JSON nested too deeply to parse (`RecursionError`) is malformed evidence: an error for `run.json` and `samples.jsonl`, an invalid observation for `result.json` and `disk.jsonl`.
- **The two dual-stack actor tests skip on a host without IPv6,** printing why, instead of panicking.
