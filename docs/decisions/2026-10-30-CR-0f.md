# CR-0f decisions (PR pending)

Follow-up fixes from the CR-0 L2 review (#180, runner comment). They refine [CR-0](2026-10-25-CR-0.md); nothing here reverses an owner decision. The actor-refusal back-off and the pool's `max_lookups` (256) against the actor's cap (32) are unchanged and stay with CR-ADM.

## v0.5.1 release delta
Each line changes runtime behaviour and names its targeted test.

- **Bootstrap seeds may use fake-ip and NAT64 addresses (release blocker).** Behind fake-ip DNS (Clash, OpenClash, sing-box: 198.18.0.0/15) or DNS64/NAT64 (`64:ff9b::/96`, and the RFC 8215 local-use `64:ff9b:1::/48`), the configured router names resolve into ranges the CR-0 public policy refuses, so a fresh install without `dht-state.bin` never bootstrapped. The actor now checks a query to one of the *resolved configured* routers with `lodestar_network_policy::allows_seed`: the full public policy, plus those two rewritten-name ranges and nothing else. Loopback, private, link-local, CGNAT, metadata and every other special range, port 0, multicast and scoped IPv6 stay refused for seeds too, and the subscribed blocklist still applies. Any other address, including one a router hands back, gets the full policy. A router reached through these ranges may answer, but it isn't inserted into the routing table, so it is never routed to or advertised to other nodes. Tests: `seeds_add_only_fake_ip_and_nat64`, `fake_ip_seeds_pass_the_policy_other_special_ranges_and_learned_nodes_do_not`, `a_nat64_seed_passes_the_policy_and_asks_for_ipv6_nodes`, `a_fake_ip_router_bootstraps_and_its_learned_nodes_get_the_full_policy`.
  - **Narrower than "skip the special-range check".** The brief allowed exempting the seeds from that check altogether. Only the two ranges a resolver rewrites public names into are needed for the failure, and exempting the rest would let a poisoned resolver or a typo in `dht.bootstrap` send find_nodes to LAN, loopback or cloud-metadata hosts every re-bootstrap round. Keeping them refused leaves CR-0's endpoint policy otherwise intact. A local router still works with `allow_private`, as before.
  - **Seed find_nodes ask for their own family's nodes (BEP 32 `want`: `n4` on IPv4, `n6` on IPv6).** A router answers in the family the query arrives in, and through NAT64 that's IPv4, so an IPv6 family used to get only IPv4 nodes it can't use. Test: `a_nat64_seed_passes_the_policy_and_asks_for_ipv6_nodes`.
  - **NAT64 needs an IPv6 DHT bind.** The default bind is IPv4 only, and on an IPv6-only host that socket reaches nothing whatever the policy says. This slice doesn't change the default bind.
- **`dht.bootstrap_unreachable` (Warn).** Written once when a bootstrap round ends with no router answering: every resolved router refused or throttled at send, none resolved, or all queries timed out. A response or an error reply counts as an answer and re-arms the warning, so a later outage is reported again. It carries counts only (`configured`, `resolved`, and of the last attempt `refused` by policy or socket and `throttled` by the query budget); no addresses. Not written when no routers are configured. Test: `every_refused_or_silent_router_warns_once_per_outage`.
- **Pausing cancels queued lookups instead of answering them.** `SetPaused(true)` now drops the reply sender of each queued, accepted request instead of sending an empty peer list. The pool treats an accepted request whose finders all dropped their completion unanswered as cancelled: it gives the attempt back and queues the key in the lookup backlog with no back-off, so a paused pool holds it and a resumed one asks again at once. Chosen over keeping the queue across the pause because the pool's `lookup_wait` timer (30 s) would still expire a long pause's queued work and consume its attempt, and because a dropped receiver is already CR-0's cancellation signal. An actor that shuts down mid-lookup gets the same treatment, which matches CR-0's "unavailable finders defer work without consuming attempts". Running lookups still finish and answer during a pause. The pipeline pauses the pool before the DHT over separate channels; if the actor's drop is seen before the pool's own pause, the pool asks again, the paused actor refuses, and the key waits the ordinary refusal back-off (CR-ADM's subject) with no attempt used. Tests: `abandoned_admission_and_pause_leave_no_queued_ownership` (actor), `a_finder_dropping_accepted_work_on_pause_costs_no_attempt_or_back_off` (pool).
- **`dht_lookups_completed_total` excludes cancelled requests.** An owned request whose caller dropped the receiver counts only in the existing `dht_peer_cancelled_total`. `docs/metrics.md` is amended to match (a shared-file edit the runner allowed). CR-0 soak evidence counted this metric under the old meaning (`analyze_cr0.py` treats it as a core counter), so a comparison across this change must say so. Test: `cancelled_same_hash_retry_ignores_the_old_wire_response`.
- **Transaction IDs start in the lower half of u64,** leaving at least 2^63 tokens before CR-0's no-wrap exhaustion stops dispatch. Test: `transaction_ids_start_in_the_lower_half`.
- **More IANA special-purpose blocks are refused** for untrusted destinations: 192.31.196.0/24 (AS112-v4), 192.52.193.0/24 (AMT), 192.175.48.0/24 and 2620:4f:8000::/48 (AS112 direct delegation). Tests: `public_private_reserved_and_mapped`, `range_edges`, `scoped_ipv6_is_rejected_unless_local`.

## Tooling and tests only
- **`analyze_cr0.py` takes the outstanding-RPC limit from the preset:** Low 256, Balanced 1024, Aggressive 4096 (`Intensity::max_outstanding`), from `--intensity` or else `run.json` `settings.intensity`. Evidence without a preset is from the collector that always ran Balanced: it gets 1024 and the `intensity_assumed_balanced` issue. An unknown preset is an error. JSON nested too deeply to parse (`RecursionError`) is malformed evidence: an error for `run.json` and `samples.jsonl`, an invalid observation for `result.json` and `disk.jsonl`.
