# X-gs3-nits decisions (follow-ups to GS-3, #973)

Supersedes one sentence of `docs/decisions/2026-11-16-GS-3.md` (the members-walk bound, below). That file is left as it was, per this folder's README. No behaviour changes except that an unknown `collapse` value is now parsed in one place.

- **The members walk's cost, stated for the walk the code does** (`collapse.rs` `members`, with `count.rs` `Matcher::seek_to`). GS-3 said counting `others` exactly takes "O(min(group, matches)) per page for a group on it". That is true for one group, but a page doesn't walk its groups one at a time. Each chunk of the ranked walk (64–1,024 hits) hands its `k` undecided groups to one walk, per segment. Their `title_identity` postings are merged in doc order against one query cursor that only moves forward. Each step either advances a group's list past a member or seeks it to the query's next match, and a list meets each query match at most twice. So with `m` the query's matches in the segment (before deletes and ranges, which are checked only where a member lands):
  - steps = O(Σᵢ min(|gᵢ|, m)), which is at most **O(min(Σ group sizes, k × m))**;
  - the query cursor itself passes over its matches at most once per walk;
  - each step is also a heap operation over the `k` lists, O(log k).

  The other two places that count are unchanged and were stated correctly. The exact groups count (`exact_groups_capped`) visits every match once, O(matches), with no group-size term. The estimate's single members walk covers at most `HT_SAMPLE` = 1,024 drawn groups, under the same bound with `k` ≤ 1,024.
- **`collapse` is parsed through `CollapseMode`** (`crates/api/src/dto/search.rs`), with a `FromStr` that runs serde's own deserializer. So the spellings accepted, the OpenAPI enum (already generated from `CollapseMode` for the `GET` parameter) and the values the error names come from one type. `CollapseMode::ALL` lists the modes for the message, and a unit test checks that `ALL`, `as_str` and serde agree.
  - **The request field stays a string** (`SearchRequest.collapse: Option<String>`). Typing it as `Option<CollapseMode>` would let axum's query and JSON extractors reject a bad value with their own error, not the API's `{ "error": { "code", "message", "field" } }` shape that `sort`, `tz` and the other parameters use. Parsing it in the handler keeps `unknown_collapse` the same 400 as `unknown_sort` (tested by GET and POST). The OpenAPI document doesn't change.
  - The message is unchanged: `Unknown collapse "bogus": use group or none.`
- **Test:** the bounded-scroll test now asserts its first cursor page has a next page before checking members against it, so it can't pass on a single-page result.
