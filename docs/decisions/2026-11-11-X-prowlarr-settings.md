# X-prowlarr-settings decisions (Prowlarr plugin editable settings and consent-gated registration)

Slice X-prowlarr-settings, assigned by the runner on 2026-11-11 to close the gap `2026-11-09-CMP-5g.md` records: the Prowlarr/Jackett plugin (SRC-7, `2026-11-02-SRC-7.md`) kept its settings fixed and the binary didn't register it, so CMP-5g-2 could hand over qBittorrent only. It covers architecture §18.7 and §18.9 and owner decision §2.49. The code is `crates/sources-plugins/src/prowlarr.rs`, one registration in `crates/lodestar/src/services.rs`, and their tests.

## Editable settings
- **`config_editable` is true.** `check_config` runs `Config::from_json`'s rules and gives `Config::to_json`'s form; `config_json` is that form for the running settings, or `None` before setup, so there's nothing to compare a saved form with.
- **One saved form:** `{"agents", "manager", "url"}`, with the address trimmed and without its trailing slash, and the agent count always written (2 when not sent). Saving the saved form again gives the same text, so `restart_required` clears once Lodestar has restarted on it (the binary test checks it).
- **The address goes through the SSRF guard's download-client policy,** as SRC-7 set: http(s) with a host, no user name, password, query or fragment, never link-local, metadata or unspecified addresses (`169.254.0.0/16`, `fe80::/10`, `fd00:ec2::254`, `0.0.0.0`, `::`). LAN, loopback and single-label names stay allowed, since the manager is usually a companion on this machine or the LAN (§18.10). Names are resolved and checked again at connect time, and redirects aren't followed, by the egress SRC-5 builds from `endpoints()`.
- **Bounded before parsing:** the settings at most 4 KiB (`MAX_CONFIG_BYTES`), the address at most 2 KiB (`MAX_URL`). `PATCH /sources/{id}` already caps a settings document at 16 KiB.
- **The API key stays a credential.** An `api_key` in the settings is refused with "the settings don't match the form", and every refusal names the rule, never a value. The key is saved through `PATCH /sources/{id}/credentials` (SRC-4), sealed, and is never in `config_json`, `check_config`'s output, the schema, a `Debug` string, an error or a log line (tests scan each, and the binary test scans the responses, the log and the database file).
- **`SourcePlugin::endpoints` now returns the configured host.** SRC-7 had the inherent `Prowlarr::endpoints` but not the trait method, so the pipeline would have read the manifest's empty list and the plugin couldn't have reached its own address. Registration made that matter.

## Registration behind the consent gate
- **Registered at every start, built from `sources.config.prowlarr`** (`Prowlarr::at_start`). Settings that are missing or refused leave it unconfigured: it fails "needs setup" and its egress reaches nothing, as the torrent cache does (SRC-13b).
- **It stays off.** Its manifest is off by default and Account class, so it registers disabled (SRC-4). Turning it on needs a stored API key, and this build refuses every class but None anyway (`consent_text_approved`, X-consent-gate-052), so it stays off until the Account credentials dialog ships (X-consent-gate-lift). One turned on by an older build is switched off at the start. The binary test saves an address and a key and checks the gate still refuses, before and after a restart.
- **In fixture mode** it's registered the same way. Plugins get no egress there, and it can't be turned on.
- **Not a change to what's shipped turned on:** `docs/plan/2026-11-06-v052-feature-manifest.md` lists the plugin as "not registered" for v0.5.2. From this PR it's registered but can't run, like the torrent cache. Whoever writes the next release's manifest should move its row.

## The key and the address apply together (CMP-5g's open risk)
- **The API key is read once, when Lodestar starts, beside the address** (`KeyAtStart`). Each run reads the stored key again and stops with "needs setup: the API key changed since Lodestar started; restart Lodestar to use it" when it differs, or when there was none (or it couldn't be read) at the start. It never sends a key saved after the start.
- **Why:** `2026-11-09-CMP-5g.md` hands over the companion's key first, then its address, and both apply at the next start, but the companion gate restarts the plugin on every health flip and SRC-7's plugin re-read the key each run. So until a restart the companion's key could go to your own, older address. That file left this slice to close it, "for example by making the address and key apply together, or by holding the plugin until the restart". This does both: the key and the address it's sent to always come from the same start, and a changed key holds the plugin until the restart.
- **The trade-off:** a key you correct yourself also needs a restart now, where before it applied at the plugin's next start. The message says so. A saved address already needed one, so a first setup (address and key) still takes one restart. A key removed since the start fails "no API key is stored", as before.
- **What it doesn't cover:** a hand-over that stops between its two writes (a crash, or CMP-5g's `key_not_confirmed` case) still leaves the companion's key beside your own address at the next start. CMP-5g logs both, and accepted them as low severity.
- **`Prowlarr::new` keeps SRC-7's behaviour** (each run uses the key stored then) for the fixture contract tests; the binary builds only through `at_start`.
