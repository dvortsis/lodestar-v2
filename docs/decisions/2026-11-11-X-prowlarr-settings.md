# X-prowlarr-settings decisions (#658; Prowlarr plugin editable settings)

Slice X-prowlarr-settings, assigned by the runner on 2026-11-11 to close the gap `2026-11-09-CMP-5g.md` records: the Prowlarr/Jackett plugin (SRC-7, `2026-11-02-SRC-7.md`) kept its settings fixed and the binary didn't register it, so CMP-5g-2 could hand over qBittorrent only. It covers architecture §18.7 and §18.9 and owner decision §2.49. The code is `crates/sources-plugins/src/prowlarr.rs` and its tests. **The registration is deferred** (below).

## Editable settings
- **`config_editable` is true.** `check_config` runs `Config::from_json`'s rules and gives `Config::to_json`'s form; `config_json` is that form for the running settings, or `None` before setup, so there's nothing to compare a saved form with.
- **One saved form:** `{"agents", "manager", "url"}`, with the address trimmed and without its trailing slash, and the agent count always written (2 when not sent). Saving the saved form again gives the same text, so `restart_required` clears once Lodestar has restarted on it.
- **The address goes through the SSRF guard's download-client policy,** as SRC-7 set: http(s) with a host, no user name, password, query or fragment, never link-local, metadata or unspecified addresses (`169.254.0.0/16`, `fe80::/10`, `fd00:ec2::254`, `0.0.0.0`, `::`). LAN, loopback and single-label names stay allowed, since the manager is usually a companion on this machine or the LAN (§18.10). Names are resolved and checked again at connect time, and redirects aren't followed, by the egress SRC-5 builds from `endpoints()`.
- **Bounded before parsing:** the settings at most 4 KiB (`MAX_CONFIG_BYTES`), the address at most 2 KiB (`MAX_URL`). `PATCH /sources/{id}` already caps a settings document at 16 KiB.
- **The API key stays a credential.** An `api_key` in the settings is refused with "the settings don't match the form", and every refusal names the rule, never a value. The key is saved through `PATCH /sources/{id}/credentials` (SRC-4), sealed, and is never in `config_json`, `check_config`'s output, the schema, a `Debug` string or an error (tests check each), and the plugin has no log calls.
- **`SourcePlugin::endpoints` now returns the configured host.** SRC-7 had the inherent `Prowlarr::endpoints` but not the trait method, so the pipeline would have read the manifest's empty list and the plugin couldn't have reached its own address. Registering it will make that matter.

## Registration deferred to X-prowlarr-register (runner, 2026-11-11, on #658)
- **The brief's step 2 (register it in `services.rs` behind the consent gate) isn't in this PR.** Registering it makes the Legal Notice's §2 untrue: it says Account sources are "None is built yet", and its "This version has:" inventory doesn't list Prowlarr. `crates/lodestar/tests/legal_facts.rs` (`registered_sources_and_consent_classes_match_section_2`) caught it. The notice is owner-approved and versioned, so its wording needs the owner. The runner chose to land the settings here and move the registration, with the notice change, to a follow-up, X-prowlarr-register.
- **What the follow-up builds on:** `Prowlarr::at_start(saved, credentials)` builds the plugin from `sources.config.prowlarr` and the key stored at that moment. The plugin is Account class and off by default, so it registers disabled (SRC-4). This build refuses every class but None (`consent_text_approved`, X-consent-gate-052), so it would stay off until the Account credentials dialog ships. The first version of this PR had a registration and a binary test (settings saved, refused hostile ones, gate refusing, nothing leaked, `restart_required` clearing after a restart), which X-prowlarr-register can bring back from commit `9e7285e5`.
- **For the next release's manifest:** `docs/plan/2026-11-06-v052-feature-manifest.md` still lists the plugin as "not registered", which stays true until X-prowlarr-register lands.

## The key and the address apply together (CMP-5g's open risk)
- **The API key is read once, when Lodestar starts, beside the address** (`KeyAtStart`). Each run reads the stored key again and stops with "needs setup: the API key changed since Lodestar started; restart Lodestar to use it" when it differs, or when there was none at the start. It never sends a key saved after the start.
- **Why:** `2026-11-09-CMP-5g.md` hands over the companion's key first, then its address, and both apply at the next start, but the companion gate restarts the plugin on every health flip and SRC-7's plugin re-read the key each run. So until a restart the companion's key could go to your own, older address. That file left this slice to close it, "for example by making the address and key apply together, or by holding the plugin until the restart". This does both: the key and the address it's sent to always come from the same start, and a changed key holds the plugin until the restart.
- **The trade-off:** a key you correct yourself also needs a restart now, where before it applied at the plugin's next start. The message says so. A saved address already needed one, so a first setup (address and key) still takes one restart. A key removed since the start fails "no API key is stored", as before.
- **`restart_required` doesn't show a changed key** (self-review I1). It compares saved settings only (`config_pending`, `crates/pipeline/src/control.rs`), so after a key change, including a hand-over to the same address you already had, the source shows `restart_required: false`. Only its health error says to restart. That contradicts `2026-11-09-CMP-5g.md`'s "after a hand-over the Prowlarr source shows `restart_required`" in the same-address case. **For the runner:** a fix is for `config_pending`, or a sibling flag, to also cover a credential changed since the start for a plugin that pins its key. That's in `control.rs`, outside this slice.
- **A key that couldn't be read at the start** fails every run with its own message ("couldn't be read when Lodestar started; restart Lodestar"), not as a changed key.
- **What it doesn't cover:** a hand-over that stops between its two writes (a crash, or CMP-5g's `key_not_confirmed` case) still leaves the companion's key beside your own address at the next start. CMP-5g logs both, and accepted them as low severity.
- **`Prowlarr::new` keeps SRC-7's behaviour** (each run uses the key stored then) for the fixture contract tests; X-prowlarr-register is to build only through `at_start`. Its start-up read of the saved settings should fail the start on a store error, as the other start-up reads in `services.rs` do, rather than leave the plugin silently unconfigured (self-review P3).
