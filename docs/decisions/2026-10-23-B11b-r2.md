# B11b decisions, part 2 (stage pages, export, overview additions, events)

The five stage pages, `GET /insights/export.csv`, the overview's Compare deltas and digest helpers, `yield_below_baseline`, and the `insights` event (architecture §9, §10.9.2–§10.9.6, §10.17; `docs/metrics.md` §7.5, §7.7). Part 1 is `2026-10-23-B11b.md`. No owner decision is reversed or loosened, no security or content-safety decision is weakened and no owner-set number changes; the refinements below are the runner's to flag (`docs/owner-decisions.md` §2.19).

## Stage pages
- **Typed responses, one per page** (`DiscoverResponse` … `ServeResponse`), each `{range, updated_at, stale, kpi, trend[], <sections>}` and `previous: {kpi, range, trend}` with Compare. Every §6.8 metric is a named field; one with no counter yet is `null`, and `docs/metrics.md` §7.7 names the counter it waits for. `previous`'s snapshot fields (DHT nodes, queue, searchable now) are null: a snapshot has no previous period.
- **Read like the overview:** the boundary (`compacted_before_day`) and the rows in one read transaction; compacted days from the day tables plus stragglers, the rest hour by hour (`RollupBy::All`, one seek per hour). Fetch's funnel is the overview's own cohort read, sealed-day cache included. A per-stage cache beside the overview's, keyed the same way plus the stage and `reason`; the snapshot fields are read for every request.
- **`reason`** is checked on every page (a §6.4 name, else `400` with `field: "reason"`) but only Fetch reads it: it filters `kpi.lost`, the lost trend, `losses` and the funnel's loss maps to that reason. Fetched counts and the funnel's stages aren't filtered, since a reason only qualifies a loss. `losses[].share` stays the share of all losses, so a filtered row still says how big that reason is.
- **Gaps:** a trend count is null where no coverage row backs the bucket (crawl coverage for Discover, Fetch and Understand; index coverage for new searchable). Removals count as measured with either coverage dim, because deletes happen paused or not. Fetch, loss and block counts are also null before `funnel_events_since_hour`, bucket by bucket, and as totals when the window starts before it.
- **`trend[].searchable` on Index** is the bucket's last `SEARCHABLE` snapshot (a gauge), null with none, never summed.
- **`by_strategy`** is keys reported by harvest strategy (metric 1's key), by event time: volume, not yield. Yield by strategy needs a strategy dimension on cohorts (follow-up).
- **The DHT's reply ratio** comes from a new `InsightsSource::stage_snapshot` (null by default), which the binary fills from the DHT's stats (`services.rs`). It's the ratio since start, as `/metrics` has it; a windowed rate needs a history (follow-up, with `nat_saturation`).
- **Budget, measured in release** on a year of rollups at B11a's density, compacted as a running store keeps it (30 days hourly): every page at `7d&compare=1`, `30d&compare=1` and `all` answers in ≤ 28 ms (Discover `all` 28 ms, Fetch 20 ms, Understand 12 ms, Index 10 ms, Serve under 1 ms). A year still hourly (between an upgrade and the first compaction, which runs 10 minutes after start) reads `all` in up to 220 ms on Discover and 90 ms on Index and Understand: stage pages have no sealed-day cache. That state lasts minutes, so only the overview is held to 50 ms there; the test reports the stage pages' times.

## Export
- **The rows are the panel's JSON** (`overview_response` / `stage_response`, the same cache entries), serialized and turned into CSV generically: a field per column, nested objects as `parent.child`, sorted, `period` first. So the CSV can't disagree with the chart, and a new field shows up in both.
- **Each panel declares its columns,** so an empty panel (no exceptions, a range with no data) still has its full header; a key beyond them (an unknown loss reason) is added. A test holds the header of an empty range equal to a populated one's, panel by panel.
- **Times:** `at`, `cohort` and `since` get an ISO-8601 `…_utc` column from `civil_from_days` (H. Hinnant's algorithm, `pub(crate)` for B11c), no new dependency.
- **With `compare=1`,** panels that have a previous period (the trends, the overview's segments) add its rows with `period` = `previous`.
- **Escaping:** #115 merged, so `export::csv_cell` became `pub(crate)` (one word) and is called for every text cell; numbers come from typed JSON numbers and are never escaped. CR and LF are among the controls `csv_cell` writes as `\u{…}`, so a cell never holds a raw line break.
- **Panels without rows yet** (`by_ip_family`, `trackers`, `top_queries`) aren't offered; they become panels when their counters exist.

## Overview additions (B11c reads them)
- **`kpi.new_searchable_delta`, `kpi.yield_delta`** (ratio points), **`kpi.time_to_searchable_p50_delta_s`, `…_p95_delta_s`:** current less previous, null without Compare or when either side is null. **`previous.segments`:** the previous period's segments, same shape and Adult rule.
- **`segment_movers(current, previous, n)`:** rows of `by_group` and `by_content_type` by |Δ| (largest first), ties by key, then list; a key missing on one side is 0 there; rows that didn't move are left out (a mover moved). `pub(crate)`; B11c calls it.
- **`overview_response(&ApiState, OverviewQuery)`:** the handler's body, which the handler, `export.csv` and the `insights` event call.
- **`yield_below_baseline`:** the brief's "final cohort hours of the last 24 h" are almost never final (a cohort stays open for the 72 h retry horizon unless every hash resolves), so the exception compares **the newest 24 cohort hours final by age (72–96 h ago)** with the 7 days of cohort hours before them. It fires below 75% of the baseline's yield (an error below 50%), when the recent hours harvested ≥ 500 keys and the baseline ≥ 3,500, so a quiet node doesn't raise it. Computed whatever the range, like the other exceptions.
- **Still waiting for a counter:** `nat_saturation` (a reply-ratio history), `ephemeral_ports` and `port_unreachable` (socket counters), `scrape_bans` (#48's `SCRAPE_REQUESTS`, not on `main`), `parser_confidence` (a confidence rollup), `disk_projection` (free space), `network_path` (a path probe).

## The `insights` event
- **`EventSources.insights`** holds the API state; a poller beside `poll_crawler` builds the default `7d` overview every 30 s (`EventsConfig::insights_every`) while anyone listens, and publishes its stage strip and `updated_at`. Nothing is built while nobody listens. `InsightsStages.fetch`, `.index` and `.serve` are nullable, as §7.5's.
- **A client showing another range refetches** its own overview or stage page on each event: the event carries only the default range's strip.

## Visibility
- B11a's rules and no more: Adult is left out entirely of every per-type or per-group list (Understand's lists, Index's `removed_by_type`, their CSVs) while hidden; totals count it (the allowed count leak). No page or CSV lists torrents. Tracker rows, when they exist, carry `scheme://host:port` only (`TrackerHealth.key`). The cache keys keep the Adult setting.
