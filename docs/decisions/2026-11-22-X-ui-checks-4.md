# X-ui-checks-4: five fixture screenshots and their regeneration flow (#PR)

Date: 2026-11-22. Decided by the build runner (step 0 approved); the details below are the slice's.

## Decisions

- **Five screens, one theme.** `e2e/ui-checks/fixture-screens.fixture.test.ts` runs in the `fixture` project (read-only) against a real `lodestar serve --fixture` server: `/search?q=lantern`, `/discover`, `/alerts`, one torrent's page and `/settings/general`. Each is checked loaded (no `aria-busy`, no error banner), axe (serious or critical WCAG 2.2 AA) and a full-page Riverstone-light baseline at 1366 px. The clock is frozen at the fixture's own `anchor`, the crawler status pill is masked, and the existing tolerance (`maxDiffPixelRatio` 0.001) is kept.
- **axe coverage.** `axe.fixture.test.ts` scans `/insights` and the first-run wizard, none of these five, so all five are scanned here and nothing twice.
- **Insights dropped for Alerts.** Insights was tried first. Its page differs between two runs on the same server (its height moved by 100 px or more between runs), so it cannot hold a baseline. Alerts, with the fixture's three saved searches, did not move over four runs.
- **Regeneration with the marker.** `web/e2e/.update-snapshots` on a same-repo pull request now also builds the fixture binary and runs `--project=fixture --update-snapshots`. The `changes` job outputs `marker`; `fixture-build` and `fixture` run on a pull request only with it; `fixture` uploads `snapshot-baselines-fixture`; `commit-baselines` downloads both artifacts and runs its existing path, PNG-header, size and symlink guards over each (the same regex, still only `*-snapshots/*-linux.png`); its permissions and branch guard are unchanged. A regenerating run fails `e2e-ok`, as before.
- **`e2e-ok` and an ordinary pull request.** With no marker the fixture job is skipped, and a skipped fixture result passes `e2e-ok` exactly as before; only `failure` or `cancelled` is red (a comment in the job says so). The fixture job stays out of `ci-ok`.
- **`web/e2e/README.md`** gets one short paragraph on the fixture baselines.
- **Baselines come from CI.** Local runs produce PNGs for the machine's fonts; none is committed. The first push of this PR carries the marker, CI generates the five PNGs and the workflow commits them, then the marker is removed.
