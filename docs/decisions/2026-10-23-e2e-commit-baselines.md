# E2E commit-baselines decisions

The owner asked for the best-practice way to get W9's regenerated screenshot baselines past the session proxy (2026-10-23: "Let's go with whichever way is best practice").

- **CI commits the baselines to the PR branch.** No session downloads them any more. GitHub stores Actions artifacts on Azure blob hosts, which the cloud sessions' network policy denies. Allowlisting the one host seen (`productionresultssa9.blob.core.windows.net`) isn't enough, because GitHub spreads artifacts across many storage accounts. Allowing `*.blob.core.windows.net` would let a session send data to any Azure storage account.
- **The write token sits in a job that runs no PR code.** This follows GitHub's guidance never to give a write token to a job that runs untrusted code.
  - `e2e` keeps the workflow-wide `contents: read`. It installs and runs the PR's code, and uploads the `snapshot-baselines` artifact.
  - `commit-baselines` alone has `contents: write`. It checks out the PR's head branch, downloads the artifact into `$RUNNER_TEMP`, and copies in only files that match `<…>-snapshots/<name>-linux.png` and start with the PNG signature. Any other path, or one containing `..`, fails the job. It then commits and pushes to the PR's head branch.
- **Same-repo PRs only, and never `main`.** The job runs only for `pull_request` events whose head repository is this one: a fork's token is read-only, so a fork can't be served this way. It refuses an empty branch name, `main` or `refs/heads/main`. The branch ruleset on `main` (§2.22) is a second guard.
- **A push from the session re-runs CI.** Pushes made with `GITHUB_TOKEN` start no new workflow runs, so the bot's commit can't loop. The session pulls with `--no-rebase`, removes `web/e2e/.update-snapshots` and pushes, and that push re-runs CI against the committed baselines. No empty commits are needed.
- **The git pathspec uses `:(glob)`.** Without it, `web/e2e/**/*-snapshots/` needs at least one folder between `e2e/` and the snapshot folder, so the top-level `web/e2e/smoke.test.ts-snapshots/` would be skipped. This was checked in a scratch repository.
- **Action pins:** `actions/download-artifact` is pinned to `37930b1c2abaa49bbe596cd826c3c89aef350131` (v7.0.0), the major that pairs with `upload-artifact` v7.0.2. upload-artifact keeps the folder hierarchy after the first wildcard, so the artifact's root is `web/e2e/`.
- **Who made the change:** the owner's session made it, at the owner's request. Autonomous slice and runner sessions are stopped by their permission check from adding a workflow that holds a write token. A fresh review and `/security-review` check it before merge.
