# X-purge-rederive decisions: a purge re-derives what the purged source decided

Slice session, 2026-11-24. Spec: architecture §18.1, §20.5 and §20.9; `docs/decisions/2026-11-05-X-source-adult.md`; `docs/decisions/2026-11-24-ENR-G.md`; the runner's brief `briefs/X-purge-rederive.md` (2026-11-24T20:40Z) and the review notes it came from (rv-1117, rv-1117b). Baseline: `main` at 182d49fe.

## Decisions
- **A purge re-derives a torrent that only the purged always-adult source made Adult.** An always-adult source (X-source-adult) makes every torrent it finds Adult. Before this, the purge's Torrents stage cleared the source's bit on a torrent others also found and left the stored type alone, so a torrent Sukebei alone made Adult stayed Adult, and hidden, after Sukebei was purged. Now the same step marks it for the backfill (`parser_ver = 0`) when no always-adult finder is left and it's stored Adult. The backfill derives it as it derives any torrent: detection, your Is adult or Not adult correction, then your classification rules. So your Is adult still wins, a torrent detection or a rule calls Adult stays Adult, and one that becomes Adult that way is judged as adult by the core, as any relabelled torrent is (§20.9).
  - **The generation moves in the same transaction** (`class_gen`, the §20.9 guard ENR-G used for the Claims stage). A backfill batch, or the writer's adult step, that read the torrent's old sources would otherwise store it Adult again over the mark. It moves for every such torrent, marked or not: one not enriched yet has nothing to mark, but a batch in flight for it still has to rerun.
  - **The running writer starts another pass** (`PurgeStep::rederive`, read by `Control::purge_step`), as ENR-G's Claims stage already did, so no restart is needed.
- **The store learns which sources are always adult from the pipeline** (`Store::set_adult_mark`, as the writer already does). `Control::purge_step` sets it on the Sources connection before each step. A connection that was never told marks nothing, which is today's behaviour. This is the one change outside the brief's owns (`crates/pipeline/src/control.rs`, about 10 lines), told to the runner before it was written; no other active slice owns that file.
- **What the child-safety core decided stays.** The purge never touches a hold (tombstone, quarantine, the floor's list) or a torrent's flag marks, and the derivation after it only adds marks (`set_enrichments_at` ORs them in). So a hold the Adult-only core gave an item while the source made it adult stays held, and a flagged torrent stays flagged. Nothing here loosens the floor.
- **The Claims stage moves the generation only when it changed a row** (rv-1117b nit). It used to set `marked` for every record-shaping claim it deleted, even when the torrent had no record to mark (not enriched yet). Now only an UPDATE that matched a row counts, so a purge that marks nothing leaves the generation, and in-flight backfill batches aren't sent round again for nothing. A torrent with no record is still derived: the backfill picks up every torrent without one.
- **Plain feed purges: kept as they are, not re-derived.** Measured and reasoned:
  - **What a plain source decides in a derivation: nothing.** A torrent's derivation reads its sources in exactly two places: the always-adult mask (`source_adult::correction`), handled above, and the identification title (`identify::stored_title`), which skips claims from a torrent's own finders. A purged source's own claims are already gone by the Torrents stage, so clearing its bit can't change which other claims count. Re-deriving every kept torrent of a plain feed would therefore produce the same record.
  - **What it would cost.** Every torrent the feed found that another source also found: in a typical setup with the DHT running, nearly every torrent the feed found. Enrichment runs at about 17,300 torrents/s in a tight loop (`docs/decisions/2026-11-05-RP-UC.md`, release build, 4 vCPU): about a minute of writer time per million torrents, and about ten at ten million. Each re-derived torrent is also written to `reindex_log` (`enrich_rows`), so the live indexer reindexes every one of them: for a large public feed, close to a whole-catalogue reindex, for no change.
  - **So:** not done. If a plain source ever comes to decide something in a derivation, the place to add it is the same Torrents-stage mark, scoped to the torrents that decision touched.
- **The consent check at ingest has a race test** (rv-1117b should-fix). `crates/pipeline/tests/adult_enrich.rs::consent_withdrawn_between_the_check_and_the_write_stores_nothing` withdraws consent on another connection between ingest's early check and its write (from `mark`, which runs between them when the batch earns a hold) and checks nothing is stored. With ingest storing through the unchecked `put_claims_at` it fails, so it pins that ingest uses the consented write.

## For the owner (§2.19)
- **Plain feed purges keep today's behaviour** (no re-derivation), for the reasons and numbers above. It loosens nothing: nothing a plain source decided is left behind.
