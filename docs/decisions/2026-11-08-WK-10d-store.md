# WK-10d (store): floor holds for workers' reports

The store half of WK-10d's floor-drop tombstones, its own PR because WK-10d would otherwise pass 1,500 lines (runner, 2026-11-08T05:41Z). WK-10d's runtime PR builds on it: the coordinator's sink records a worker's `Lost(Blocked)` reports through it. These are content-safety calls, and the runner took the stricter option (2026-11-08T05:19Z, §2.33; it flags them to the owner after the merge).

## A worker's floor report is a permanent tombstone
- **`Store::tombstone_from_worker(hashes, worker, at)`** writes a tombstone per hash under the rule `worker-floor:<worker id>`. This covers a floor drop a remote worker reported: CS-1a, CS-1b, CS-8a or a hash list, reported as `Lost(Blocked)`, whose torrent the coordinator never sees. The key is then never claimed, fetched or stored again. That's the local rule "never fetched again" (owner-decisions §2 item 16; #599's runner conditions).
- **It never renames an existing row** (`INSERT … ON CONFLICT (hash) DO NOTHING`). Above all a local floor row (CS-1a/1b/8a) keeps its rule, so WK-13's purge-by-worker, which deletes by rule, can never remove a real floor tombstone. The store's batch write (`filter::write`) replaces rows, which is why it isn't used here.
- **No migration:** `tombstones.rule` is `TEXT NOT NULL` with no check, so the worker's id rides in the rule.
- **Why not an in-memory refusal for a few days** (WK-10d's first proposal): it would be lost on a restart, which loosens a content-safety property. The runner rejected it.

## Floor holds everywhere, except WK-13's purge
**Worker-floor rows are floor holds everywhere, except WK-13's purge-by-worker.** `FLOOR_RULES` stays the filter's own three rule ids, since `filter/src/core.rs` asserts on it. Instead:
- `WORKER_FLOOR_PREFIX` (`"worker-floor:"`) and `is_floor_hold(rule)` (re-exported from the crate);
- one SQL fragment, `floor_hold_sql(col)`, built in one place and used by every guard: `(col IN ('CS-1a', 'CS-1b', 'CS-8a') OR col LIKE 'worker-floor:%')`.

Where it applies:
- **`purge_filter`:** an expiring adult hold replaces any tombstone except a floor hold.
- **The snapshot purge** (`snapshots.rs`, the expired-adult-hold insert): the same guard, so a snapshot keeps what the live store keeps.
- **`hold_rank`** (a rollback's carry of holds): a worker-floor row ranks 2 with the floor, so it wins over a weaker row in the copy, even a later one.
- **Releases:**
  - `release` and `release_many` leave a worker-floor tombstone in place;
  - `release_rules` skips a `worker-floor:` rule;
  - `release_rule_hashes` and `release_rows` never touch one already, since they name list rules and quarantine rows.

  So no user action removes a worker's report one by one. **The only way out is WK-13's purge-by-worker:** it deletes a removed worker's rows by rule, which is the remedy if a worker turns out to be bad (its damage is availability, not safety).

## A finding: the floor's own rows can be released today
No path in the store or the API refuses releasing a CS-1a/1b/8a tombstone. `Store::release` deletes any tombstone, and the review queue's Release change calls it. That's harmless for those rules, because the floor refuses the key again when it's next seen: the hash lists before a fetch, and CS-8a at prepare. It isn't harmless for a worker's report, which nothing here can decide again, so only worker-floor rows are refused. This PR leaves the floor's own rows as they are. The runner decides whether to tighten them.

## For WK-13 (trust but verify)
- **Purge-by-worker must also delete that worker's `worker-floor:<id>` tombstones,** by rule. `release_rules` won't do it, since it skips those rules on purpose; WK-13 adds its own delete.

## Tests
- `filter::tests::a_workers_floor_report_is_a_floor_hold`:
  - a local CS-8a row is never renamed;
  - a second report changes nothing;
  - an expiring adult hold doesn't replace a report;
  - no release removes one (by hash, many, or by rule);
  - the floor's own rows are released as before.
- `snapshots::tests::purge_for_restore_carries_the_holds`: a live worker-floor row outranks the copy's later, weaker row.
- `snapshots::tests::the_quarantine_purge_matches_the_live_one`: an expiring adult hold over a report leaves the report, in the live purge and the snapshot purge alike.
- All three fail if the shared SQL fragment stops matching `worker-floor:` (checked).
