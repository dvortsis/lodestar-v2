# S-settings-2 decisions

**Scope: Language & region only (runner, 2026-10-31).** The other four screens (Integrations, Notifications, Trackers, Insights & digest) need server work that does not exist yet, so they move to S-settings-2b after a backend slice. The server needs:
- **Settings sections plus CRUD** for `integrations` (download clients, Torznab/*arr), notification channels with event routing, `trackers` (list, scrape on/off, cadence, health) and `insights` (digest schedule and channels, query logging, retention). Secrets use `writeOnly` fields as the form engine expects.
- **`POST /settings/test` kinds** for Torznab and each notification channel (ntfy, Discord, email, webhook). Today it accepts only `download_client`.
- **A clear-usage-data endpoint** for the destructive "Clear usage data" action (§10.10.7).
`GET /digest/preview` already exists; its preview mount point waits for S-insights-3.

**Language & region is a hand-built body on the form engine, in instant mode.** Preferences apply at once with Undo (§10.10.1), so it uses `createSettingsForm({ mode: 'instant' })`. It shows only the `region` group of `preferences` (`language`, `time_zone`, `first_day_of_week`), so it does not repeat Appearance or Keyboard. A tiny `LanguageScreen.svelte` loads `LanguageForm.svelte` (the form) when the screen opens.
- **Widgets.** `language` is a select (Automatic, English, 中文) and `time-zone` is a text input with the browser's IANA names as suggestions; both are registered from the screen. The server's `x-auto` is dropped for these fields because the engine's Automatic switch cannot turn off for an empty string in instant mode (its "clean and equal to auto" rule closes the control straight away). Automatic is the empty value instead. The time-zone widget checks a name with `Intl.DateTimeFormat` before it reaches the form: an unknown or half-typed name shows an error and is never saved, which keeps instant mode from saving a partial name. The engine should handle that case; flagged for the runner.
- **Applying the language.** A saved language is applied to the UI with `initLocale` while the screen is open. **Follow-ups outside this slice's paths:** apply the saved language at boot (`routes/+layout.ts` still calls `initLocale(null)`), and read `time_zone` and `first_day_of_week` where dates and calendars are formatted (§10.12; the digest uses the time zone too).

**Messages.** The screen's own title, purpose and error live under `settings_screen_*`, which the generator leaves out of the server-key map. The `settings_preferences_*` label, help and option keys and `settings_group_region` are in the settings feature's `messages/{en,zh}.json`, so the generated `form/message-map.ts` picks them up. `message-map.gen.ts` now breaks an entry that would pass the 100-column print width after the colon, as prettier does; without it the generated file failed `prettier --check` and its up-to-date test once a long key existed.

**Size gating.** The Language screen's first view includes its form and the engine (it loads at once), and the "screen extras" entry stops at the form, so extras stay at their baseline. No limit was raised. Measured numbers are in the PR.
