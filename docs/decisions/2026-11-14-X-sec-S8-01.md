# X-sec-S8-01 decisions (#869)

S8-01 (important), data folder file modes. The detail stays with the runner (`docs/security/v1/README.md` §5); this file records only what the code now does.

## What the code does
- **A data folder Lodestar creates is owner-only on Unix (0700).** `crates/lodestar/src/data_dir.rs` (`ensure`) creates any missing parents with the default mode and the folder itself 0700. So every store, index and snapshot file under it is closed to other users, whatever mode each file gets.
- **No process-wide umask.** Outputs and companion files are written for other apps' users to read, for example Unraid containers under other user IDs. A global umask would break them.
- **An existing folder is never changed.** If its group or others have any access, the start logs one warning that names the folder and the safe mode (`chmod 700`). The user guide (3.7, "Keep the data folder owner-only") gives the command. A missing folder created by another process meanwhile counts as existing.
- **Files outside the data folder that hold the same data:**
  - **Backups:** `lodestar backup --to <folder>` already writes a new 0700 folder. The store copy in it is set to 0600 once written, and the other files are created 0600. Nothing changes there.
  - **Everything else:** every other store, snapshot, rollback and index path sits inside the data folder (the store, the index, the pre-migration snapshots, rollback's kept copy and `vacuum`'s staged copy all derive from it), so the folder's mode covers them.
- **Windows is unchanged.** The installed service's folder is already limited by its ACL. A non-default folder isn't ACL-checked, which `update/layout.rs` already documents.
- **The store crate isn't touched.**

## What the packaging does today (checked before choosing)
- **Docker image** (`packaging/docker/Dockerfile`):
  - it starts as root only to apply PUID/PGID, then hands `/data` to PUID:PGID (default 65532) and drops root (`privdrop.rs`);
  - the image ships `/data` empty, owned by 65532, created with `mkdir -p`, so its mode is 0755;
  - a new named volume copies that mode, and a bind mount keeps the host's.
- **Unraid template** (`packaging/unraid/lodestar.xml`): `/data` is a bind mount of `/mnt/cache/appdata/lodestar`, with PUID 99 and PGID 100. Docker creates a missing host folder as root with 0755, and the start then hands it to 99:100.
- **So 0700 locks nobody out.** Lodestar's user always owns the folder, because the start chowns it to PUID:PGID. Unraid's appdata backup plugin runs as root.
- **The systemd unit isn't affected.** It already creates the folder owner-only.

## The runner's answers (2026-11-14)
- **The two earlier creators now use the same helper:** `privdrop.rs` (`chown_data_dir`, the PUID path) and `update/layout.rs` (the supervisor's `Bin::open`) call `data_dir::ensure` instead of `create_dir_all`. Only those creation calls changed. Neither path ever changes an existing folder's mode; the PUID path still only changes its owner.
- **The image ships `/data` as 0700** (`install -d -m 0700 /out/data` in `packaging/docker/Dockerfile`).
  - A new named volume copies it.
  - Bind mounts and existing volumes keep their mode and get the warning at start.
  - The user guide's command tightens them.
