# M-settings-engine-2 decisions

- **Server labels load per section, not with the engine.** `message-map.gen.ts` writes one map per settings section (`form/message-maps/<section>.ts`) plus `group` for the group headings, and `message-map.ts` holds only the dynamic-import loaders. `SettingsForm` awaits its fields' sections (and `group`) through `loadMessages` before it renders anything, so a raw key or field name never flashes; a return visit renders at once. The reason is the owner's 45 KB route cap (§10.1): the single map had the first view at about 43.1 KB, and the next four screens would have gone over. A map that fails to load leaves its keys missing, which show as the field's name, as before. A new section's messages need no code: regenerate.
- **Automatic snaps back only when the value changes to the automatic one.** In `SettingField.svelte` the re-arm used to fire whenever a clean field's value equalled `x-auto`, which closed the switch straight after a user turned it off on an empty text. It now remembers the last value and re-arms when the value changes to the automatic one and the field is clean: Discard, Undo, Use theirs and a server update. Turning Automatic off keeps the value and stays off, including after the save that follows in instant mode.
- **Language & region has its `x-auto` back.** This supersedes the workaround in `2026-10-31-S-settings-2.md` (the spec's `auto` dropped in `screens2/LanguageForm.svelte`). The language and time-zone fields show the engine's Automatic switch again; the screen's tests turn it off first.
