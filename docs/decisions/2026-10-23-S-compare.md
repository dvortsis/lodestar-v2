# S-compare decisions

The Compare page (`/compare?h=a,b,c`, §10.6) over `POST /compare` (B13).

- **Refinements of §10.6, for the runner to flag (§2.19):**
  - **Columns from x-large for two or three torrents, from xx-large for four or five.** Names wrap badly in five 1024 px columns. Below the switch the attribute-first list is used. The list is also what the brief's "narrow widths" ask for.
  - **A row each for Seeders and Leechers** (not one "Seeders / Leechers" row). Each number then has its own row header and glossary term, and its own `data-testid`.
  - **No virtual scroller for the file lists.** The server sends at most 2,000 rows a list, and only an opened section renders them. `content-visibility: auto` skips off-screen rows, so a 2,000-row list scrolls smoothly with no extra JavaScript. `VirtualList` pulled `{#await}`/`ResizeObserver` runtime code into the chunk every page loads, and `/search` has about 0.5 KB of Lighthouse bytes left.
  - **Actions are a row in the table** ("Actions", first row under the headers), not part of the column header, so a column header's accessible name stays the torrent's name.
- **The attribute order** is the `ATTRIBUTE_ORDER` constant in `model.ts` (brief step 4). Other keys follow, by key. The row headers use `compare_attr_<key>` messages; an unknown key shows the key itself in Mono.
- **Letter badges** A–E in request order, used in the column headers, the narrow list, the composition table and the diff.
- **Disclosure defaults:** every diff section is collapsed; its rows render only once it is opened.
- **Stale comparison:** the last good answer stays on screen while the next request is in flight, and stays with a warning banner if that request fails with `network` or 5xx. The 400 codes and the 404 replace it with the fix-it list, since the old columns no longer match the URL.
- **Loading:** a skeleton of nine rows after 300 ms; nothing before that. `aria-busy` is set from the start.
- **The page loads as its own chunk** (`+page.ts` imports `Compare.svelte`), and the populated view (`Body.svelte`: both layouts, labels, formatters, the diff) loads beside the request. SvelteKit lists every route node's chunks in the entry that every page loads, so a statically imported feature grows `/search`'s bytes (§10.1 headroom, W9 decisions). The route's own initial JS + CSS is small; the lazy chunks are fetched at once on the first visit, so the size-limit entry counts only the first part. The PR reports both.
- **Copy magnet** is local (`copy-magnet.ts`): the Clipboard API, then a hidden textarea with `execCommand('copy')`, then a selected read-only field with "Press Ctrl+C to copy" (⌘C on a Mac). The runner promotes one shared helper to `lib/` once S-detail's exists (§10.11's "two places" rule).
- **Choose state** is EmptyState's markup written out (`StateScene` `empty_state_explore`, title, text, link to Search). `EmptyState` uses `<svelte:element>` for its heading level, which adds about 0.4 KB to the runtime every page loads. A cheaper `EmptyState` (an `{#if}` per level) would let Compare switch back.
- **Feature-local message stand-ins** (`TODO(S-detail)`): `compare_group_images|documents|archives`, `compare_type_<content type>` and `compare_dominant_share`. They move to the shared keys when S-detail lands them.
- **Route size budget:** `.size-limit.mjs` gets an `own(route)` helper and four entries (Compare, Discover, Alerts, Alert) at 15 KB each. 15 KB is the runner's proposal (§2.19), not an owner number.
- **Backend follow-ups for B13's owner:** `CompareTorrent` has no `magnet` (Copy magnet fetches `GET /torrents/{hash}`), no `flags` (so no backfill marker), no `seeders_approx` and no `last_scrape_at`.
