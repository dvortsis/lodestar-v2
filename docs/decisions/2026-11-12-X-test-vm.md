It is separate from the Terraform fleet (`infra/akamai/terraform`, `infra/fleet`), whose shared state backend is unresolved (`docs/operations/fleet-backend-investigation.md`). Nothing here changes the fleet, the watchdogs, IAM or GitHub OIDC.

**What those decisions are.** Both loosen the "agents only read" rule in `.agents/skills/lodestar-fleet/SKILL.md`, so they were asked first, as `CLAUDE.md` requires. Budget: at most $100 for each cloud.
1. **Claude may run commands inside the two named test machines**: one Linode labelled `claude-dev-<yyyymmdd>` and one AWS Windows instance created by `Deploy-AwsWindows.ps1`. That covers builds, tests, Docker, VPN and kill-switch checks, and bounded DHT crawls, until each machine is deleted. It covers no other machine, and no IAM, Terraform state, account settings, watchdog or OIDC change.
2. **Claude holds a Linode write token** to create, check and delete the Linux test machine and its firewall. The owner chose it over creating the machine by hand.
   - The token's scopes are Linodes and Firewalls read/write, Account, Events, Images and VPCs read-only, everything else none.
   - It lives only as a network secret on the owner's personal cloud environment `lodestar-cloud-test` (the proxy injects it, so no session ever sees it), not on the Default environment the build sessions use.
   - Linode tokens can't be limited to one machine. So `infra/dev-vm/devvm.py` changes or deletes only resources labelled `claude-dev-`, refuses a second VM, and deletes only when the exact label is typed back.
   - The AWS side is unchanged: the owner provisions and terminates Windows with their own MFA.
   - The owner revokes the token at teardown (Cloud Manager → API Tokens).

**Runner's calls under §2.26, flagged to the owner under §2.19:**
- **Linux machine type `g6-dedicated-4`** (4 dedicated vCPU, 8 GiB, 160 GB, $0.108/h), not the plan's shared `g6-standard-4`.
  - Dedicated CPU has no steal from neighbours, so crawl and bench numbers repeat. 8 GiB matches the plan's Main.
  - Linode stops charging at the monthly price, here $72. A VM forgotten for a whole month stays under the owner's $100 cap for this environment.
- **Outside both reapers' scope on purpose.** The legacy watchdog matches `lodestar-*` labels with `lodestar` and `test` tags; this VM is `claude-dev-*`, tagged `claude-dev`. The watchdog would delete it at 48 h mid-test, and its deletion path is unproven anyway. Cleanup is `devvm.py delete`, which verifies a 404, plus the owner's revocation of the token. The monthly cap bounds the cost if both are missed.
- **Firewall: inbound DROP, with TCP/22 only from the owner's current `/32`.** No UI port and no DHT listener is public. The UI is reached over `ssh -L`, as in the fleet plan (ground rule 7). `devvm.py set-admin-ip` moves the `/32` when the owner's address changes, and LISH is the way in out of band.
- **The host key is pinned before first contact** (the fleet's OP-2 pattern): `devvm.py` generates the ed25519 host key, puts it in the user data, deletes the local private copy, and records the fingerprint. The user data also holds the owner's public key, and nothing secret beyond the host key. That private key stays readable through the metadata service while the VM exists, which is accepted: it lives only as long as the VM.
- **Disk encryption is on, and backups are off.**
- **The toolchain comes from upstream:** Docker's apt repo, Node 22 from nodejs.org checked against its SHASUMS, rustup, and Claude's native installer. An 8 GiB swap file covers release builds with LTO.
- **Claude Code on the VM runs under the owner's own login, in `tmux`, through Remote Control**, so it shows in the owner's Claude app. Only outbound HTTPS is used, and no cloud credential goes onto the VM.
- **PIA credentials are typed by the owner on the VM** into `infra/pia-bridge/vm/pia-wireguard.sh`'s flow. They never go in chat, git, user data or a session environment.
- **Crawls on this VM are exploratory leads, never CR-SPEC evidence,** under the cloud test plan's ground rules (`docs/plan/2026-11-08-cloud-test-plan.md`). Rule 5, metadata only, nothing identifying leaves the VM, applies unchanged.
