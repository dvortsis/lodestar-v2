# X-test-vm decisions

An interactive, disposable test machine for each platform, so Claude sessions can build, test and run bounded, VPN-isolated DHT crawls on real Linux and Windows hosts. It is separate from the Terraform fleet (`infra/akamai/terraform`, `infra/fleet`), whose shared state backend is unresolved (`docs/operations/fleet-backend-investigation.md`). Nothing here changes the fleet, the watchdogs, IAM or GitHub OIDC.

**What those decisions are.** Both loosen the "agents only read" rule in `.agents/skills/lodestar-fleet/SKILL.md`, so they were asked first, as `CLAUDE.md` requires. Budget: at first $100 for each cloud, replaced at 16:58Z by $50 for each cloud over the whole testing period.
1. **Claude may run commands inside the named test machines**: Linodes labelled `claude-dev-<yyyymmdd>[-<role>]` (one at first, at most three after the later decisions below) and one AWS Windows instance at a time, created under the `lodestar-claude-testvm` user. That covers builds, tests, Docker, VPN and kill-switch checks, and bounded DHT crawls, until each machine is deleted. It covers no other machine, and no IAM, Terraform state, account settings, watchdog or OIDC change.
2. **Claude holds a Linode write token** to create, check and delete the Linux test machine and its firewall. The owner chose it over creating the machine by hand.
   - The token's scopes are Linodes and Firewalls read/write, Account, Events, Images and VPCs read-only, everything else none.
   - It lives only as a network secret on the owner's personal cloud environment `lodestar-cloud-test` (the proxy injects it, so no session ever sees it), not on the Default environment the build sessions use.
   - Linode tokens can't be limited to one machine. So `infra/dev-vm/devvm.py` changes or deletes only resources labelled `claude-dev-`, refuses a fourth VM (`MAX_VMS = 3`) and any type outside its list, and deletes only when the exact label is typed back.
   - The AWS side was at first the owner's own; from 06:42Z Claude creates and deletes the Windows instance as `lodestar-claude-testvm` (above).
   - The owner revokes the token at teardown (Cloud Manager → API Tokens).

**Runner's calls under §2.26, flagged to the owner under §2.19:**
- **Linux machine type `g6-dedicated-4`** (4 dedicated vCPU, 8 GiB, 160 GB, $0.108/h), not the plan's shared `g6-standard-4`.
  - Dedicated CPU has no steal from neighbours, so crawl and bench numbers repeat. 8 GiB matches the plan's Main.
  - Linode stops charging at the monthly price, here $72. A VM forgotten for a whole month stays under the owner's $100 cap for this environment.
- **Outside both reapers' scope on purpose.** The legacy watchdog matches `lodestar-*` labels with `lodestar` and `test` tags; this VM is `claude-dev-*`, tagged `claude-dev`. The watchdog would delete it at 48 h mid-test, and its deletion path is unproven anyway. Cleanup is `devvm.py delete`, which verifies a 404, plus the owner's revocation of the token. The monthly cap bounds the cost if both are missed.
- **Firewall: inbound DROP, with TCP/22 only from the owner's current `/32`.** No UI port and no DHT listener is public. The UI is reached over `ssh -L`, as in the fleet plan (ground rule 7). `devvm.py set-admin-ip` moves the `/32` when the owner's address changes, and LISH is the way in out of band.
- **The host key is pinned before first contact** (the fleet's OP-2 pattern): `devvm.py` generates the ed25519 host key, puts it in the user data, deletes the local private copy, and records the fingerprint. The user data also holds the owner's public key, and nothing secret beyond the host key. That private key stays readable through the metadata service while the VM exists, which is accepted: it lives only as long as the VM.
- **Disk encryption is on, and backups are off.**
- **The toolchain comes from upstream:** Docker's apt repo, Node 22 from nodejs.org checked against its SHASUMS, rustup, and Claude's native installer. An 8 GiB swap file covers release builds with LTO.
- **Claude Code on the VM runs under the owner's own login, in `tmux`, through Remote Control**, so it shows in the owner's Claude app. Only outbound HTTPS is used, and no cloud credential goes onto the VM.
- **PIA credentials are typed by the owner on the VM** into `infra/pia-bridge/vm/pia-wireguard.sh`'s flow. They never go in chat, git, user data or a session environment.
- **Crawls on this VM are exploratory leads, never CR-SPEC evidence,** under the cloud test plan's ground rules (`docs/plan/2026-11-08-cloud-test-plan.md`). Rule 5, metadata only, nothing identifying leaves the VM, applies unchanged.

**Runner's calls under §2.26, flagged to the owner under §2.19:**
- **The real-dump leg runs on its own VM, `claude-dev-<yyyymmdd>-import`** (`g6-dedicated-4`, 160 GB), so it never overlaps the crawl's measurements.
  - `devvm.py` also lists `g6-dedicated-8` and `g6-dedicated-16` for a larger restore; the account's limit refused both, so neither was used.
  - **Real dump data is the owner's private data:** only numbers leave the VM, never torrent names, file names, infohashes or row contents. Errors that could carry row data go to root-only files. The dump, the restored database and the Lodestar store built from it are deleted on the VM before the VM is deleted.
  - **A full restore didn't fit** (about 190 GB and 25 h projected), so the leg imported the first 1,000,000 torrents in the importer's own read order (infohash ascending for Bitmagnet), with every file row for each of them.
- **The 1 GiB worker (`g6-nanode-1`, Lane K) gets a 256 MiB swap file and no build toolchain.** Test VMs are created without Linode's default swap disk (`swap_size: 0`), so the swap the plan sets is the only swap.
- **The AWS connector's sign-in lasts 12 h by default.** A long-lived access key would remove the limit, but it is a standing secret, so it wasn't proposed. Windows lanes are planned to finish, teardown included, inside one sign-in (`infra/dev-vm/windows.md`).
  - **Correction, 2026-11-14:** the 12 h is a default, not a fixed limit. AWS Sign-In's *sign-in session duration* can be set on the IAM user, up to 90 days. Access tokens still last one hour and are refreshed, and no long-lived credential is created.
  - The owner asked for Claude to stay connected for testing without repeated logins, adding: "I don't use AWS for anything else, so I'm not worried".
  - It is set on `lodestar-claude-testvm` only, whose permissions are unchanged.
  - It ends early when the owner disconnects the connector or deletes the stack.

**Spend for the whole testing period:** Linode $6.50, AWS about $6 (estimated; Cost Explorer lags). Both well inside the $50 caps. All test machines were deleted and verified gone by 2026-11-14T02:35Z.
