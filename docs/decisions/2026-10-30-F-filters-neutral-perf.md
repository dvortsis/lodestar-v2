# F-filters-neutral-perf decisions

Neutralize terms now fit the owner's budget: under 50 µs per torrent at 10,000 rules (`docs/owner-decisions.md` §1.6, architecture §20.8). No semantics change and no owner number changes. The budget gate now holds the neutralized case too.

- **Where the time went (profiled, not guessed).** The `budget` test's neutralized case (the mixed set and Neutralize entries for `web`, `webrip`, `hevc`, `mkv` and `sample`) ran at 132 µs on CI's `main` (reference-runner µs; mixed without them: 39 µs). Callgrind on its 512 torrents, judged once per pass, counted about 1.34 M instructions per judgment, against 0.46 M for the same rules without the entries. 51% went to `rules::matches`, the keyword entries' check, which tokenizes the name and every path with the core's normalizer:
  - **A new tokenizer per text.** `normalize::tokens` built a `Tokenizer` for each text, so each one set up and freed its 512 word plans, and every word missed the plan cache. That alone was about 60% of the check.
  - **Each path read whole**, though a torrent's files share their folders.
  - **Each entry's keyword tokenized again for each torrent**, and the Neutralize key worked out again for each one that applied.
  - The query-side neutral checks (`live`, `neutralized`, `neutral_token`) cost little. Precomputing neutral keys per rule, or a per-torrent neutral bitmap, wouldn't have helped.
- **The fixes, all exact:**
  - **One tokenizer per thread, shared by the core and keyword entries** (`normalize::with_tokenizer`). The core already reused its own one across torrents. A tokenizer's tokens never depend on what it read before (`same_tokens_when_reused`), so sharing one only means the core's pass now hits the plans the keyword pass just made. It falls back to a new tokenizer if the thread's is in use or gone.
  - **Paths read in one pass, each folder once** (`normalize::paths`). A path's folders are read up to just after the last `/` and paused, then each file in that folder resumes from there. Each path still gets the tokens of its joined text, which isn't quite what the core's per-segment read gives: a spelled-out run (`a/b/c`) goes on over a `/` in one text, and the pause keeps it. The split is exact under NFKD, which reorders only runs of combining marks, and a `/` ends any run; and with the token cap, which counts from the text's start. `paths_read_as_their_joined_text` checks it against the reference tokenizer: look-alikes, single letters on both sides of a `/`, more folders than the four it keeps, and texts past the cap. All of the name's and paths' tokens go in one buffer.
  - **Entries prepared once per list** (`OverrideList`). `Engine::overrides` is now an `OverrideList`. It reads and changes as a `Vec<Override>` through `Deref`/`DerefMut`, and keeps each entry's keyword tokens and Neutralize hash and key, worked out on the first torrent after a change. Every change goes through `DerefMut`, which drops them, so they can't go stale. Assigning a `Vec` now takes `.into()`. Nothing outside `crates/filter` sets the field (`load.rs` collects into it).
  - **Two smaller ones:** a spelled-out run's end is checked inline (`flush_spelled`), and a word's tokens reserve their room once.
- **Result.** About 0.51 M instructions per judgment with the entries, against 0.46 M without (+10%, down from +190%). On this VM, run back to back, the neutralized case reads 1.08 to 1.11 times the mixed set (base: 3.4 to 5.0 times). The numbers are in the PR. With CI's 39 µs for the mixed set, that's about 43 µs on the reference runner. The cases without neutralizing are unchanged: within 0.5% in instructions, and within noise in time.
- **The neutralized case is now held** by the `budget` gate, like the core, 1%, 10% and the mixed set (it was reported, not held: `2026-10-30-F-filters.md`, P-2). The 50 µs budget is unchanged.
- **Equivalence.**
  - `released_entries_match_the_reference` (4,000 cases) compares the entries that apply to a torrent with a reference that works the old way: keyword tokens per torrent, and each text read whole by a new tokenizer. It uses random Neutralize and Override lists (several-word Overrides, expired and shadowed entries) and torrents with spellings, look-alikes, letter-for-number swaps, spelled-out letters, invisible characters and padding files. It then changes the list and compares again, which checks that a changed list never leaves stale entries.
  - Two hand-made bugs, a pause that drops a spelled-out run and a list that keeps stale entries, each make it fail.
  - The semantics, property and reference-matcher tests pass unchanged at `PROPTEST_CASES=4000`, and so does `the_floor_is_untouched`. The floor (CS-1a, CS-1b, CS-8a) is judged before any of this, as before.
