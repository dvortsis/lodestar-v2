# S-keys decisions

Keyboard remapping and the shortcut sheet (§10.16, §10.10.8, §10.13). Refinements the runner flags to the owner (§2.19): none loosen an owner decision.

- **Command ids follow the server.** W9's `list.next`, `list.previous`, `magnet.open`, `magnet.copy`, `client.send`, `row.select` and `shortcuts.open` become `results.next`, `results.previous`, `detail.open_magnet`, `detail.copy_magnet`, `detail.send`, `results.select` and `help.shortcuts`. The ids the server stores (`DEFAULT_SHORTCUTS` in `preferences.rs`) are the persisted contract, and nothing had registered W9's ids yet. `keys.test.ts` reads `preferences.rs` and fails if the eight single-character entries of `DEFAULT_KEYS` and the server's list differ. `search.focus`, `detail.open` (Enter), `dismiss` (Esc) and `palette.open` (mod+k) keep their ids: the server's list leaves out all but `search.focus`.
- **The per-viewer cache is `localStorage` `lodestar.shortcuts`,** `{shortcuts, shortcut_keys}`. Boot applies it synchronously so the key that woke the shell sees the user's mapping, then replaces it with the server's. Every read and write is in try/catch; the server stays the source of truth.
- **Letters are stored in lower case,** and Shift plus a letter is refused ("Use a key without Shift"). The registry folds case, so a stored `J` would act as `j`.
- **`+` can't be a shortcut key.** `normalizeCombo` splits on `+`, so the registry can't hold it; the editor refuses it. The server accepts it, so another client could store it: boot catches the registry's error, ignores that entry and logs once. A registry fix is for the keys owner.
- **A clash offers Swap or Cancel.** Swap gives the other action this action's old key, so the eight keys stay unique, as `check_shortcuts` requires. Reset onto a default another action now holds asks the same way. A collision with a non-remappable single-key command that is registered only warns.
- **The Keyboard screen saves with Save and Cancel** and `if_revision`, because `web/src/lib/features/settings/form/` isn't on `main`. It sends only the unlocked fields that changed. On `stale_revision` it reloads and lays this tab's edits over the new values per action, then says so. Save and Cancel are never disabled (§10.10.5): Save with nothing changed does nothing and says "Nothing to save.", so keyboard focus is never lost. A 409 `read_only` reloads and shows a banner. It moves onto `createSettingsForm` and the `'shortcuts'` widget when M-settings-form lands (a follow-up for S-settings-1 or the polish slice). `ShortcutsField` is controlled and engine-free, so the adapter is thin.
- **The settings event refetches.** `events.on('settings')` for `preferences` runs the same fetch-and-apply, which covers other tabs and devices.
- **The palette toggle PATCHes `{shortcuts}` without `if_revision`** (one field, last write wins), toasts, and changes nothing locally on failure. It lives in `toggle.ts`, loaded on use, to keep `boot.ts` small.
- **The link to `/settings/keyboard` is provisional.** It answers 404 until S-settings-1's route finds the screen.
- **`screen.ts` shape (proposal for S-settings-1's screen registry):** `{ id: 'keyboard', group: 'preferences', title: () => string, load: () => import('./KeyboardScreen.svelte') }`, as the default and a named export.
- **Key names for assistive technology.** `Kbd` shows the key; a visually hidden name replaces symbols (`/` is "Slash", `?` is "Question mark"). Text, not colour, marks everything: "Off" tags, conflict and error lines carry an icon and words.
- **Sheet layout.** Active commands are grouped by section; commands from other scopes follow under "On other screens". Registry conflicts show as warning banners naming both commands.
- **Styling in `shortcuts.css`.** The global sheet is at 19.82 of 20 KB, so the feature uses `@reference` and `@apply` in one CSS file that ships with its lazy chunks, and no new utility class in markup beyond what the build already emits. Words that are Tailwind utilities (`invisible`) are kept out of the source, since the scanner reads comments too.
- **Schema gaps (reported, not worked around):** `SettingsPatch` is generated as `Record<string, never>`, so the PATCH bodies are cast; `SettingValue.value` is `unknown`, so boot and the screen narrow it at runtime. The server's 422 for a shortcut clash names the action in its message and not in `field`, so the screen finds the row by the leading action id.
- **`boot.ts` is 1.79 KB gzipped against the brief's 1.5 KB target (accepted by the runner).** About 0.25 KB is Vite's preload map for the sheet import. It imports no `lib/shell` file, so the search route's first load is unchanged. Boot fetches the saved mapping when the shell's stream is first live, or after 10 s if the stream is neither live nor stopped (blocked); the sign-in screens leave the stream `stopped` and ask nothing. `settings` events and stream resyncs both refetch.
