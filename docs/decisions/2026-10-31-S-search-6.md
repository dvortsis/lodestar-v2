# S-search-6 decisions: live banner, zero-result recovery, Cards density

Part 3 of 3 of the M5 "Search completion" backlog. Spec: §10.4 "States" and the results toolbar. Code: `web/src/lib/features/search/{live,cards}/`, mount edits in `results/ResultsPanel.svelte` and `toolbar/`.

- **The live banner polls; it does not listen.** `/events` has no query-scoped feed (`torrents` counts the whole index, and `alerts` is for saved searches), so `live/live.svelte.ts` re-runs the query shown with `limit: 1` (runner, 2026-10-31):
  - at most every 30 s, only while the tab is visible, and never while a request is out (a newer one aborts the old);
  - paused while the list is scrolled more than two screens down. S-search-5's selection joins through the `paused` check in `LiveHost.svelte`;
  - "N new results" shows only when both totals are exact (`total_approx` false on the shown answer and on the probe) and the probe's total is larger. With approximate totals it says nothing rather than guess. The client only subtracts two server totals; it counts nothing itself;
  - Show reloads the list from the top (`results.retry()`, then scroll to the top and focus the first row, since the button has gone). The list never changes before then;
  - the announcement goes through the panel's existing polite region and fires at most once per 30 s. A new query clears the count.
- **Zero-result recovery stays as S-search-2 built it** (each filter removable through the AST, plus "Clear all filters"); the "Removing X gives N" counts are deferred.
- **Cards** is a third value of the existing `density` parameter (`appearance` already allows `cards`). The list stays one virtual list: rows are `cols` cards, `cols` (1–3) follows the list's own width (280 px minimum per card), and the same hit data, testids (`result-{hash}-…`) and Row actions are used. `active` stays an index into the hits, so j/k and the drawer follow work unchanged. Enter or a click opens a card. Cards load on demand (`cards/CardList.svelte`).
- **Both lazy parts load through `live/extras.ts`**, so the panel carries one dynamic import. "Search results (lazy)" still grew by about 0.25 KB from the mount lines (see the PR for the limit decision).
- **Avoid the word "card" in `web/`:** Tailwind scans the whole `web/` tree and daisyUI's `.card` component adds about 1 KB to the global sheet. Classes are `cd-*`, prose says "tile".

## Deferred (backend needed; the runner is queuing a slice)

- **Per-clause counts** for "Removing `trackers:>=3` gives 1,240": `/search` or `/parse` must return a count per removable top-level clause. The client must not compute counts, so it does not fan out N searches.
- **Cold start** banner states beyond the existing `searchable_torrents` threshold: an index-state endpoint. (The Index rebuilding banner already reads the shell's `rebuild` snapshot, S-search-2.)
- **An exact live count:** a query-scoped feed (the B9 percolator) that says how many new torrents match the query shown, so polling can go.

## Review round (self-review by a fresh Opus reviewer)

- **Cards navigation is per tile.** The roving item is the tile; arrows, j/k and focus/click move `active`, an index into the hits, so `c`, `o`, `x`, hover prefetch and the drawer follow act on the right torrent. The panel's `hashOf` prefers the nearest `[data-hash]` (a Cards tile carries its own), and `returnFocus` goes to the tile.
- **Tiles show the row's facts** except the composition bar, the raw name, "resolved via" and matched files, which need more height than a tile has (the suspect-swarm warning, flag badges, trackers and backfill are kept).
- **`results.reload()`** is new in the store: the current query again from the top, whatever failed before. Show uses it, because `retry()` loads the next page after a failed "Load more".
- **The banner's count is hidden from its live region** (`aria-hidden`); the throttled announcement says it and the Show button's name carries the count.
- **Known gap:** after Show the panel's `active` index is not reset (the list's focus moves to row 0). A follow-up can reset it through the store.
