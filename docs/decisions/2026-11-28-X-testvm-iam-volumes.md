# X-testvm-iam-volumes decisions (#1169)

The owner's answers to owner-queue items 31 and 33 (`docs/owner-decisions.md` §2.88, 2026-11-28Z): the test-VM policy requires `Purpose=X-test-vm` on test volumes, and the test user may delete its own test volumes, scoped like its terminate permission. No owner decision is loosened. The owner applies the reviewed policy in AWS (a stack update of `lodestar-claude-testvm`); this PR makes no cloud calls.

- **`RunOnlyEncryptedBoundedVolumes` now requires all four tags the delete checks** (`aws:RequestTag/Project=Lodestar`, `Environment=Test`, `Purpose=X-test-vm` and `LaunchedBy=${aws:userid}`), plus the instance statement's `aws:TagKeys` list. Item 31 names only `Purpose`. Requiring `Environment` and `LaunchedBy` too is the runner-call refinement: it makes every volume the user launches one the delete can reach, and the delete's `LaunchedBy` test then trusts only a value IAM set. (Without it, a caller-chosen `LaunchedBy` could only make its own volume undeletable, not reach anyone else's, since tags can be set only at launch.) Both runbooks already tag the volume with all of them, so a correct launch is unaffected. Refinement under §2.19, for the runner to flag.
- **New statement `DeleteOnlyOwnLodestarTestVolumes`:** `ec2:DeleteVolume` on `volume/*` in `us-east-1`, only when `ec2:ResourceTag/Project=Lodestar`, `Environment=Test`, `Purpose=X-test-vm` and `LaunchedBy=${aws:userid}`. It mirrors `ManageOnlyOwnLodestarTestInstances`, minus `ec2:InstanceType`, which a volume doesn't have. No `ec2:DetachVolume`, `ec2:CreateVolume`, `ec2:ModifyVolume` or snapshot deletes, so an `in-use` volume stays the owner's to remove.
- **Why `LaunchedBy` can't be forged, for instances and now volumes:**
  - `${aws:userid}` is a policy variable IAM fills in from the caller's own credentials (the IAM user's unique id); the request can't set it.
  - Every `RunInstances` statement that creates a taggable resource (instance, volume) requires `aws:RequestTag/LaunchedBy` to equal it, so a launch tagging either with any other `LaunchedBy` is refused.
  - `ec2:CreateTags` is allowed only with `ec2:CreateAction=RunInstances`, i.e. only as part of a launch, which those statements already constrain. There's no later `CreateTags`, and no `ec2:DeleteTags`, so a tag can't be added to, changed on or removed from an existing instance or volume, including the owner's.
  - So the only volumes the user can delete are ones it launched itself. The owner's fleet volumes share `Project=Lodestar`, but carry no `Purpose=X-test-vm` or this user's id.
- **Limit that stays (unchanged from the terminate statement):** every test lane signs in as the same user, so one lane could delete another lane's leftover volume. The runbooks say to delete only the volume whose id the lane took at launch (step 3), never one the tag check finds.
- **Runbooks (`linux-aws.md`, `windows.md`, step 7):** a root volume found `available` after termination is now deleted by its id, then checked by id until gone (10 min deadline), and reported to the runner without the id. A refused delete, an `in-use` or `error` volume, or one still `deleting` at the deadline still goes to the runner and the owner. `DeleteOnTermination=true` (#1162) stays the primary path; this is the backstop.
- **Tests:** `infra/dev-vm/tests/test_aws_policy.py` pins the new and changed statements and adds a test that the launch's volume tags and the delete's conditions match. The brief's `owns` didn't list it; it's the policy's pinning test, which fails on any policy change, so it's edited here and named in the PR. The policy is about 5,430 of IAM's 6,144 characters.
