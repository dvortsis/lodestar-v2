# SRC-17: provenance, Show unverified and the Source facet

- **"Show unverified" asks for `verified:yes,no`, not `verified:no`.** `verified:no` alone would hide the verified results; the toggle's job is to let unverified ones in beside them. Turning it off removes the clause and keeps a `verified:yes` the user typed. The checkbox reads the query's AST, so the strip shows the chip and Back undoes it.
- **Verified is a toggle with a count, not a term facet.** The server's `verified` facet lists `yes` (selected by default) and `no`; a yes/no pair would let a user build `verified:no` alone (unverified only) from the rail, which the brief's "Show unverified" does not ask for. The runner can ask for the flag-style facet instead.
- **A second or negated `source:` clause is left as typed** and its values are disabled in the rail, as `facets/toggle.ts` does for its fields, so a click never widens an AND into an OR.
- **"Some details are private" is a separate note,** not a source in the "Found by" line: `withheld` is also set when a public source's private claim is dropped.
- **The toggle and the Source facet sit in the facet rail,** under Type, as one component (`SourceFacets`, one mount line in `FacetRail.svelte`). The rail is where every other filter lives and it already works in the three hosts (rail, left sheet, staged bottom sheet). The toggle shows the server's count of unverified items (the `verified` facet's `no`); the client computes nothing.
- **The Source facet is include-only.** Exclusion has no clear meaning for "who found it". Values are plugin ids, labelled with `source_names`, with "Mainline DHT" shortened to "DHT" on the client. A partial `source` facet (index still filling) gets a note.
- **Private sources are never named to a non-admin.** The server folds them into the facet's `other` bucket and sets `provenance.withheld`; the UI shows "private source" with a lock icon and nothing else. The admin session's private sources show "private" (icon + text). No API fields were added.
- **Claim differences are information, not a warning.** A feed's tidied title nearly always differs byte for byte from the verified name, so name, size and file-count differences are listed in plain words under "Claims that differ", with sizes and counts through `$lib/format`.
- **The Unverified badge** (icon + text, warning tone) is drawn on a result when `hit.verified === false` and in the drawer when `provenance.verified` is false. The server reports `verified: true` today, so neither shows yet.
- **Mount lines outside the owned folders:** `FacetRail.svelte` (SourceFacets), `ResultRow.svelte` (badge) and `DetailView.svelte` (Provenance), one line each plus an import. The result card (`Card.svelte`) takes the same badge.
- **Size budgets (§10.1, runner §2.26).** The feature adds bytes to size-limited entries that the baseline on `main` met: Facet rail (lazy) +1.21 kB over, Detail drawer and `/t/[hash]` +2.7 kB over, Search results (lazy) +0.49 kB, Alert route +0.51 kB, Settings entries +15 to +142 B, Search cards +40 B. The badge is drawn by hand (not `ui/Badge`, which imports all four status icons) to keep it small. Lazy-loading `Provenance` from the drawer was tried and made it worse (its own chunk counts against the drawer), so it is eager. The limits in `.size-limit.mjs` are not this slice's file; the runner decides the raise.
