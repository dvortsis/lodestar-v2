# X-polish-1031d decisions

Optional findings from the #290 and #292 reviews. Nothing is loosened: a classification re-queue stays pending in as many cases as before, and past the cap it marks more torrents, never fewer. No schema, wire, setting or log-event change.

- **`classify.requeue_pending` is capped at 64 distinct query texts** (`crates/api/src/filters.rs`, #290 O1). Below the cap it stays deduped, one entry per text. Adding a 65th distinct text replaces the list with one full re-mark, stored as the JSON string `"all"` rather than a list item, so no query text can be read as it or clear it. 64 keeps the value a few KiB at most, read and rewritten under the store lock on every rule change. It's far above what an admin changes between starts with search off, and past it marking everything costs less than remembering every text. While the full re-mark is pending, each push is covered by it and adds nothing, and clearing a single text leaves it. With search on, a rule change still marks its own matches at once. The full re-mark is cleared only by `resume_requeues` at a start with search on. It runs the existing path for torrents the index hasn't reached, `Store::mark_unenriched_after`, from id 0, so every row in `torrent_parsed` is marked. It clears only after that call returns, with no shutdown and no rule change (`class_gen`) since it began, the same terms as a text entry. With search off, or after a stop, it stays. The call is one store call under the store lock, like the watermark path; it runs at most once per start and only after the cap was passed.
- **The soak report's memory columns say what they measure** (`docs/soak/tools/analyze_cr0.py`, #292). "Peak RSS (MiB)" is renamed "Peak working set (MiB)", since in Docker mode it's the cgroup working set, page cache included. A "Peak private (MiB)" column comes from `private_bytes` and reads unknown when the rows don't carry it. The JSON keeps `rss_max_mib` for older consumers and adds `private_max_mib`. The "RSS change" column is unchanged, since the brief named only the peak. Committed evidence reports aren't regenerated.
