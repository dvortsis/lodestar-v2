# SRC-10a decisions (Nyaa RSS plugin)

Slice SRC-10a of `docs/plan/2026-11-01-v06-sources.md`. It covers architecture §18.1, §18.2 (rank 8), §18.7 and §18.9, and owner decisions §2.28 Q2 and Q7. The code is `crates/sources-plugins/src/nyaa.rs`, its fixtures in `fixtures/nyaa/` and `tests/nyaa.rs`. It copies SRC-7's pattern and maps the typed output of SRC-8's `rss` parser; it parses no text itself.

## Q2: the ToS and robots check
**HOLD: the check is not done. Until the runner records it (or the owner decides a grey case), nothing may register or enable this plugin.** Merging the code is safe because no slice wires it; the wiring slice must wait for this.

- **Basis: Nyaa publishes this feed for programs to read.** Plan §5 Q2 records that "Nyaa and AnimeTosho publish RSS for this purpose". The feed (`https://nyaa.si/?page=rss`) is linked from the site's own pages, and Sonarr, Radarr and Prowlarr poll it routinely. The plugin reads that one URL and nothing else.
- **Not verified live in this session.** The cloud proxy refused `https://nyaa.si/robots.txt` (CONNECT 403), so neither the site's robots.txt nor its terms page could be read. The check above rests on the plan's record and the feed being offered publicly. **Runner: please confirm** from a session that can reach nyaa.si before this merges. If either document forbids automated feed access, this is a grey case and goes to the owner (§2.28 Q2).
- **Politeness:** one request per poll, at most every 5 minutes (§18.1), with the limiter's back-off after a 429 or 5xx. No query, no `&magnets`, no `.torrent`, no view page.
- **Sukebei is not here** (Q7). It is SRC-10e. The parser matches only Nyaa's own namespace URI (SRC-8), so a Sukebei feed isn't read as Nyaa's.

## Consent, endpoints, caps
- **Consent class: External** (§18.7, SRC-4): a public web service, a toggle plus the endpoint list shown. Risk Medium (§18.2 rank 8). Off by default.
- **Endpoint: `https` `nyaa.si`**, fixed in the manifest. `Nyaa::endpoints()` is `Endpoints::manifest`, so egress reaches that host only, public addresses only, over https, with DNS through the proxy when one is set. There is no setting for an address.
- **No settings and no credentials.** The config schema is an empty object; the form has nothing to fill in.
- **Poll interval: 5 minutes, the §18.1 floor.** Users can slow it, never speed it up (a test checks this). Why not slower: the home feed holds 75 items, and (an estimate, not measured) Nyaa uploads at most a few hundred an hour, so a 5-minute poll catches everything and a 15-minute poll could drop items at peak. I expect Nyaa's RSS cache is no faster than this, but haven't measured it.
- **Other caps:** one request per 5 s per host, burst 1 (it is one host and one feed, so this only matters after a back-off); back-off 60 s up to 6 h, as for Prowlarr. These are performance numbers, the runner's call (§2.26).
- **Distribution: `Singleton`** (§19.5: Nyaa runs on exactly one instance).
- **Parser caps:** SRC-8's `LIMITS` with `max_items` 300 (4 × Nyaa's 75) and `max_bytes` 4 MiB (a real page is about 100 KiB). Tighter than the defaults, not looser.
- **Errors:** every failure (a 429, a 5xx, a transport error, a redirect, a page that isn't a feed) is retried at the next poll and never ends the plugin. There is no setup or credential to get wrong. The plugin returns only when asked to stop or when the pipeline is closed.

## Mapping
- **Key:** the parser's, from `nyaa:infoHash` or a magnet. An item with neither is skipped by the parser. A repeated hash in one page is emitted once (the first).
- **Every field is a claim at Low confidence,** unverified, through SRC-2's emitter.
- **Reference:** the item's `guid` (the view page). The `.torrent` link is dropped and never requested. Sizes outside 1 B to 1 PiB and dates before 2001-07-02 or more than a day ahead are dropped, as for Prowlarr.
- **Not kept:** description, comments, uploader (§18.7: no profiles of people), and **seeders, leechers and downloads.** The brief lists seeders and leechers, but `Claims` (`crates/sources/src/claims.rs`, not this slice's) has no field for them. A feed's swarm counts are also stale by the time they're read, and the crawler measures swarms itself. **Follow-up for the runner:** if the owner wants them stored as claims, `Claims` needs the fields first (SRC-2's area).
- **Category and flags use external-ID claims,** the only open-ended claim field `Claims` has:
  - `nyaa-category:<id>`, the id as Nyaa states it (`1_2`);
  - `content-type:<type>` when the id maps (below);
  - `nyaa-flag:trusted` and `nyaa-flag:remake` when Nyaa says `Yes`. §18.2 names the "trusted/remake flags" as what the feed gives, so they are kept, as claims and as Nyaa states them, never as a profile of anyone. A `No` is not recorded.
  - **Follow-up:** these scheme names are this slice's choice. Whoever reads claims into the content type (SRC-2/pipeline) should treat `content-type:` as a hint only, or the runner can rename the schemes in one place (`to_found`).

## Category map
Values are `ContentType::as_str` names (`crates/classify/src/content.rs`).
Nyaa's ids are `<main>_<sub>`. The main category decides, except Software.

| Nyaa category | `content-type` claim |
|---|---|
| 1_1 Anime – AMV | `video` |
| 1 Anime (other subcategories) | `tv` (best guess: most anime is episodes; the classifier has the last word) |
| 4 Live Action (all) | `video` (movie or show isn't known from the category) |
| 2 Audio | `music` |
| 3 Literature | `ebook` |
| 5 Pictures | `images` |
| 6_2 Software – Games | `game` |
| 6 Software (other) | `software` |
| `0_0`, unknown or malformed | none (the `nyaa-category` claim stays) |

## Fixtures
- **Hand-written, not recorded.** This session had no way to reach nyaa.si. They follow the shape SRC-8's golden tests use for Nyaa's feed (element order, the `nyaa:` set, `-0000` dates, a CDATA description), with made-up titles (Big Buck Bunny, Sintel, Tears of Steel) and hashes. Links use nyaa.si paths with made-up ids. Replace them with scrubbed recordings when one is available; the tests don't change.
- **Cases:** a normal page (two polls), an empty feed, a cut-off feed, a DTD, a 200 page that isn't a feed, an item with no hash, a repeated item, a 429 with `Retry-After`, and a 503. The over-the-cap feed is generated by the test (400 items) so no large file is committed.
- **No fuzz target added** (the brief said to extend SRC-8's if there is one; `fuzz/` isn't an owned path, so this is a deliberate departure). SRC-8's `fuzz/fuzz_targets/rss.rs` already covers the parser, and `fuzz/` isn't in this slice's owned paths. `to_found` is covered by a property test; it maps typed fields and parses nothing.

## Known gaps (follow-ups, not this slice)
- **Silent failure:** a 3xx or 404 from nyaa.si is dropped without a trace, and the limiter counts it as a good answer. A moved domain would look like an empty feed. Surfacing it needs plugin health (SRC-14).
- **Repeats:** every poll re-emits the page's ~75 items. A cursor or `If-None-Match` needs the plugin KV store, which the plugin kit doesn't give yet.
