# X-wk15-nits decisions (follow-up to WK-15, #585)

Non-blocking points from the review of #585 (runner's call, 2026-11-07). These are docs and arithmetic only; no behaviour changes. This file supersedes one sentence of [`2026-11-07-WK-15.md`](2026-11-07-WK-15.md), as the decisions README asks, rather than editing it.

## Marginal gain mostly under-counts
- **This supersedes "the view can only under-count"** in WK-15's "Marginal gain (Q12)" section. Marginal gain **mostly under-counts**: keys still in flight and leases restored across a restart aren't counted.
- **Three narrow paths can over-count instead:** a key keeps its finder although another worker found it too.
  - **(a) A busy batch claim.** In `LeaseAuthority::claim_batch` (`crates/cluster/src/leases.rs`), a key waiting for a re-grant counts as a new lease for admission. If the admission allows no more, the claim is answered `Busy` before `claim` runs, so the waiting lease's finder isn't cleared.
  - **(b) A paused or draining worker's claims.** The cluster server denies them before they reach the authority (`ClusterServer` grant path, `crates/cluster/src/server.rs`: draining, or paused since WK-14). That worker's sightings never clear another's finder.
  - **(c) Leases that straddle the start of counting.** A lease granted before `LeaseEvents::serving` keeps its finder. If it ends after counting starts, it counts marginal with no matching `granted`. That happens only around the start of serving: once per run, while workers are allowed.
- **These stay as they are.** Each is rare and small, and closing (a) or (b) would change claim semantics that WK-0 and WK-14 decided. The `marginal` field's doc and the metric contract now say "mostly under-counts".

## Keys refused as blocked
- **Keys the local intake refuses as blocked** (held, or matching the filter's hash floor) are claimed and then lost at once, so the harvest is counted once (§20.3, §20.5.2). They count as the built-in worker's granted, marginal and lost, just as the funnel counts them as harvested and then lost.

## Saturating sums
- **`discover_workers` sums remote workers' rediscovered and dropped with `saturating_add`,** as the rest of the file does, rather than a plain `+` on `u64`.
