# NOS-2a decisions (PR pending)

Routed, guarded raw TCP connect in `crates/integrations/src/net.rs` (`connect_tcp_routed`) with an in-house SOCKS5 client handshake in `net/socks.rs`. Plan: `docs/plan/2026-11-06-v08.md` NOS-2a, Q-r15; §12, §18.4, §18.6.

- **A new function, not a changed `connect_tcp`.** `connect_tcp` and `connect_tcp_with` are untouched and keep the direct route, so email keeps today's behaviour and the slice lands inactive (Q-r15). `connect_tcp_routed` takes the resolver, policy, `Route`, an optional kill-switch and one timeout, and returns its own `TcpRouteError` rather than growing `NetError`, so no existing `match` on `NetError` changes.
- **The kill-switch is a trait in `integrations`, not `sources`' `RouteState`.** `integrations` can't depend on `crates/sources`, so `KillSwitch` has two methods (`is_up`, `went_down`) and an impl for `watch::Receiver<bool>`; NOS-2b adapts `PluginEgress`'s `watch::Receiver<RouteState>` to it in `crates/sources/src/egress.rs`. It's checked before any lookup, races the whole attempt (biased toward the switch), and is checked again before the stream is returned. A closed channel counts as down, so a lost switch fails closed. After hand-over, the stream's owner keeps it under the switch, as `PluginEgress` does for HTTP bodies.
- **The proxy's `BND.ADDR` is checked for form, not against the policy.** The plan says the guard checks "the proxy's reported address". RFC 1928's reply carries the address the proxy bound for its outbound socket, not the destination; many proxies report `0.0.0.0` or their own LAN address. Checking it against the destination policy would refuse working proxies and add no protection, since it says nothing about where the proxy connected. The guard instead checks the destination before anything is sent: a resolved and checked address with `SocksDns::Local`, or a literal address and the plainly-local-name rule with `SocksDns::Proxy`, the same as the HTTP route (§12). Runner's call (refinement of a plan line, not of an owner decision).
- **One method offered.** The greeting offers user name and password when a login is configured and "no authentication" otherwise, so a proxy can't downgrade a configured login. A reply naming another method is `NoAcceptableMethod`.
- **Exact reads, no `io-util`.** The handshake reads the 5-byte reply prefix, learns the reply's length from it (at most 262 bytes), and reads exactly the rest with the socket's readiness API, so no tunnelled byte is consumed and the crate's tokio features don't change. The race uses `poll_fn` for the same reason (no `macros` feature).
- **Strict replies.** Version 5, reserved byte 0, a known address type, and a name of 1 to 255 printable ASCII bytes; anything else is `Malformed`. RFC 1929's login reply accepts version 1 or 5 (some proxies echo 5); only status 0 succeeds.
- **No fallback on any route.** A bind address that's gone, an interface that's missing, a destination with no address in the bound family, or an unreachable proxy is `NetError::Connect`; nothing connects directly instead. With several SOCKS destinations, a proxy refusal (`REP` ≠ 0) moves to the next; any other failure ends the attempt.
- **Shared edits:** one `[[bin]]` in `fuzz/Cargo.toml` for `socks_reply` (assigned to NOS-2a in the plan's shared-files list) and its row in `fuzz/README.md`.
