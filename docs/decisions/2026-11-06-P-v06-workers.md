# P-v06-workers decisions (planning: remote workers v1)

Planning slice P-v06-workers, 2026-11-06. The plan is `docs/plan/2026-11-06-v06-workers.md`. Docs only: these are planning choices the runner accepts or changes in review. The questions marked **owner** in the plan's §5 (Q1, Q2) aren't decided here.

## Slicing
- **22 `WK-*` slices, about 14,150 lines, every one ≲ 800 lines** (plan §4). Build-plan P4 said "about 6 PRs"; that counted the two merged cluster PRs and four large ones. The ≲ 1,500-line bar and the multi-session rules (owner §2.24) split them further. The ids are `WK-*` because `W0`–`W9` are taken in `runner/slices.yaml`.
- **The first slice unifies the lease tables (WK-0), before any wiring.** The inventory found two `LeaseTable`s: `ClusterServer`'s and the pipeline's `Coordinator`'s. Wiring remote workers onto both would let one key be granted twice and break §19.3's exactly-once. WK-0 also gives `server.rs` an inbound sink and a send/broadcast API, so no later slice edits it.
- **Codecs live where their types live.** `Results`, `Counters` and the filter snapshot go in `crates/pipeline/src/wire/`, because the pipeline already depends on the store, classify and filter types they carry; `crates/cluster` stays free of them. The have-filter and `Assign` codecs go in `crates/cluster`. The spool's format goes in `crates/pipeline` so the fuzz crate reaches it.
- **Docs and packaging don't gate WK-G** (WK-18, WK-19). The v0.6 tag needs them, so the critical path is nine merges, not eleven.

## Scope (runner's calls, each a plan §5 question)
- **v1 places only the DHT and fetch and prepare on workers** (Q9). Source plugins stay on the coordinator until P5's placement work, which also brings politeness token leases. §19.8's global-politeness check becomes "no capped plugin is ever placed on a worker" in v1. This follows build-plan P5, which already places plugin placement later.
- **No signed `Update` offers in v1** (Q13). They need the §18.10 catalogue (Track K). Version skew is refused cleanly.
- **Raw info archive isn't sent from remote workers** (Q8). It would break the ≤ 3 KB median, and `pieces` is never sent (§19.4). Flagged to the owner (§2.19).

## Store
- **One migration, `torrent_worker`, rows only for remote workers** (plan §3, Q10). Purge-by-worker and quarantine (§19.4, §19.7) need provenance, and none is stored today. A single-machine install writes no row. It takes the next free number in the §0.7 queue (V15 is reserved for CR-3).
- **No holder column on `fetch_queue`.** A coordinator restart starts a new lease epoch, so every old token is stale; keys are re-granted. Results spooled across a restart are handled by Q7's rule (grant-then-commit if unstored and unheld), so a 24 h spool isn't thrown away after an update.
- **The worker dimension is a `dim` code** in the existing rollup tables, not a column.

## Numbers and defaults (runner, §2.26)
- **Worker fetch-pool cap 50,000 keys** (Q5), about 34 MiB at the soak's ~690 B per key, inside an estimated 190–200 MiB worker breakdown; measured in WK-10 before it's fixed. The 200k default would take about 132 MiB on its own (soak r3 verdict).
- **The 256 MB RSS gate is measured at 10M stored, and 50M is reported** (Q6). The have-filter grows with the corpus (12.5 MB at 10M, 62.5 MB at 50M, twice that during a swap). If 50M breaks 256 MB, the options go to the owner, because the number is the owner's (§1.6.5).
- **Outbound bytes queued to the coordinator capped at 8 MiB** (WK-7). The session queue of 256 messages could otherwise hold 256 MiB of 1 MiB frames.
- **The cluster port isn't bound until workers are allowed** (Q3). A tightening; the default number stays 8091.
- **The local worker keeps direct calls on the one lease table** (Q4), sharing the lease, fencing and accounting code but not the `Link`. A refinement of §19.2's "one code path", flagged to the owner (§2.19).
- **The protocol freezes at 1.0 when WK-G merges** (Q11).

## Found while inventorying
- **The Unraid worker template passes the join token in an environment variable** (`LODESTAR_TOKEN`), which V6-cluster2 ruled out (file or stdin only). Loosening that is the owner's (Q2). WK-2 builds the file and stdin forms either way.
- **The have-filter is hashed with `RandomState`,** so a copy can't answer on another machine. WK-3 makes it deterministic with a per-filter seed.
- **`crates/pipeline/src/have.rs` is also owned by CR-5** (Track C, unmerged). The runner orders WK-3 against it.
