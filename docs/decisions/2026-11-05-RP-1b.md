# RP-1b decisions: MW-2@2 and FK-2@2, the guards RP-1's precision corpus found missing

Slice RP-1b (runner brief, 2026-11-05T08:58Z). It builds the two §20.6 guards that `docs/decisions/2026-11-04-RP-1.md` ("Known gaps") recorded as `gap` lines. The versioning is RP-0's (`docs/decisions/2026-11-04-RP-0.md`).

## The versions
- **MW-2@2 and FK-2@2 are new versions, each `narrows` against version 1.** Each matches what version 1 matches, minus the packs its guard passes. Version 1's code is kept as `packs::mw2_v1` and `packs::fk2_v1` (`Code::Fn`), because an install may still have it applied. Version 2 is the `Ctx::matches` arm, so the guard runs only after version 1's checks have matched. Each version has a changelog entry in its pack's `CHANGELOG.md`.
- **On an existing install, both are pending, in shadow, until accepted.** Accepting a `narrows` version is weakening (owner §1.8.8), so RP-3's acceptance flow (#478) asks for the password. The brief intends this. A fresh store records both at version 2.
- **The per-rule golden now covers every version whose code is kept** (`rules_match_as_their_version_says`), so a kept version's code can't drift either. On the golden set, MW-2@2 and FK-2@2 match exactly what version 1 matches, because the set has no production or episode pack.

## MW-2@2: the music-production guard
MW-2@1 still matches unless **all** of these hold:
- **The classifier calls the torrent Music.** Video lures are untouched.
- **Every executable is an `.exe` or `.msi`, and there are at most 2** (`MAX_INSTALLERS`). That allows an installer plus a 64-bit twin or an uninstaller. A script, shortcut, screensaver or `.jar` (`.bat`, `.cmd`, `.vbs`, `.lnk`, `.scr`, `.pif`, …) is never a plug-in installer, so any of them keeps the torrent held.
- **There are enough sounds.** At least 2 files (`MIN_SOUNDS`) are audio or preset files, those files are more than half of all files, and there are at least twice as many of them as installers. With 1 installer that means at least 2 sounds; with 2 installers, at least 4.
- **It has a production layout.** Either it holds a preset or instrument file (`PRESETS`: `.fxp`, `.fxb`, `.vstpreset`, `.aupreset`, `.h2p`, `.nmsv`, `.nki`, `.nkm`, `.nkb`, `.nkc`, `.nkx`, `.nkr`, `.ncw`, `.exs`, `.sfz`, `.sf2`, `.adg`, `.adv`, `.rx2`), or at least 2 audio files sit inside a sample folder. A sample folder is a folder whose name has a whole word from `SAMPLE_DIRS`: samples, presets, patches, multisamples, oneshots, loops, kicks, snares, hats, hihats, claps, cymbals, toms, percussion.
- **Plug-in binaries (`.vst3`, `.dll`) never count as sounds or as the layout.** The brief names them as plug-in structure, but they're code, so they can't vouch for a pack. They only count toward the total number of files. As a result, code beside a single sample is still held.
- **Why so tight:** this guard must not become a way to slip malware past MW-2. A lone `setup.exe` with one `.wav` is still held, even inside `Samples/`. So is an album with an installer (no layout), an installer beside a `.bat`, three installers, and plug-in code standing in for the sounds. Each has a must-match example in `malware/corpus.txt` and a unit test (`mw2_music_production_guard`). The thresholds of 2 follow the evidence: RP-1's two precision items, a VST collection and a drum-sample pack, each have two samples and one installer.
- **Residual risk:** an attacker who knows the guard can build a Music torrent with two samples in a `Samples/` folder beside one `setup.exe`. That defeats MW-2 alone. MW-1 (double extensions), MW-3, MW-4 and MW-5 don't read this guard and still apply. The malware pack has no content inspection, so no name-and-file guard can be stricter without failing real sample packs.

## FK-2@2: the short-episode guard
FK-2@1 still matches unless **all** of these hold:
- **There are at least 3 video files** (`MIN_EPISODES`).
- **Every video is named `<series> SxxEyy …`.** The marker is a whole word `sNNeNN` with 1 to 3 digits in each part. Every file has the same series words before the marker, those words aren't empty, and no season and episode appears twice. Seasons may differ. Non-video files don't count.
- **Every episode is at least 8 MiB** (`MIN_EPISODE_BYTES`), and the largest is at most twice the smallest. A real HD short of a minute or more is larger than 8 MiB, and a fake is usually far smaller. Similar sizes are what an episode set looks like.
- **What is still flagged:** a single tiny HD file, two episodes, a set of 2 MiB "episodes", a set whose sizes differ more than twofold, mixed series, a repeated episode, a video without a marker, and markers without series words. Each has a must-match example in `fakes/corpus.txt` or a unit test (`fk2_short_episode_guard`).
- **Bounded by `MAX_FILES`**, as every pack rule reads the files (`Ctx::files`). FK-2 is a flag, the lightest action.

## Corpus and precision
- **The two `gap` lines are gone, and `known_gaps_are_listed` now pins an empty list.** Four new precision items were added. For MW-2: a Kontakt-style strings library (`.nki` beside wav samples and an installer) and a VST3 synth (an `.msi`, a `.vst3`, `.fxp` presets and a loop). For FK-2: a 720p cartoon season of three ~20 MiB episodes with a subtitle.
- **`the_rp1b_guards_let_their_items_pass`** puts each rule back at version 1 and checks that every one of its precision items is then held by that rule and by nothing else. That's 4 items for MW-2 and 2 for FK-2. So the guard is what lets them pass, not missing evidence.
- **Precision** (`tests/rp1b_guards.rs`, printed with `--nocapture`):
  - **Release-parser golden corpus (317 names, with the files a torrent of each kind carries):** MW-2@2 and FK-2@2 hold none of them. That's 100% precision on lawful names.
  - **With a lure added to each name:** for MW-2, an installer beside the media; for FK-2, every video shrunk to 30 MiB. Version 2 holds exactly what version 1 holds: 260 names for MW-2, 214 for FK-2. The guards open no hole on real release names.
  - **Pack corpora:** MW-2 holds 9/9 must-match examples and passes 6/6 must-not-match ones. FK-2 holds 9/9 and passes 5/5. The precision items pass 7/7 for MW-2 and 5/5 for FK-2.
- **Unaffected:** the child-safety core, MW-6 and every other pack rule. Their goldens are unchanged.

## Touched outside the brief's list
These are test fixtures that pinned "every rule is at version 1". No behaviour changed.
- **`packs/manifest.rs`:** the built-in manifest's version lists for MW-2 and FK-2 ("their versions"), and the golden test.
- **`packs/upgrade.rs`:** the test `unseeded_and_seeded_resolve_to_today`, which now expects MW-2 and FK-2 pending (`narrows`) on a seeded store.
- **`crates/api/tests/pack_overrides.rs`:** its fixture now serves and records a manifest with MW-2 at version 1 only (`at_v1`), the base its override tests start from. The every-rule loop now reads each rule's base from the manifest (FK-2's is 2).

## Budget
- **The guards run only after version 1's own checks have matched.** Those are the classifier's `executable` reason in a media torrent for MW-2, and its `tiny-video` reason for FK-2. Each guard is then one pass over the files the rule already reads, so a torrent neither rule would match pays nothing extra.
- **Local runs of the release `filter budget` test were too noisy to separate a difference.** On the same host, `main` itself failed two of three runs on drift and busy checks, with calibrated mixed results of 46.7–56.4 µs. This branch passed one run at **47.6 µs calibrated mixed** (45.3 µs with 4 overrides, 45.4 µs neutralized), under 50 µs. CI's `filter budget` job decides. The budget isn't raised.
