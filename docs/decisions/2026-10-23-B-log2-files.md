# B-log2 decisions, part 2 of 2: log files, downloads, the archive and deletion

Architecture §12.1, §10.10.7, §10.10.12, and `2026-10-23-B-log2.md` (part 1). No owner decision is reversed or loosened, and no security or content-safety decision is weakened. The refinements the runner flags to the owner (§2.19) are marked **(§2.19)**.

- **Which folder:** the one the file opened in this run. If file logging hasn't opened, the configured `file_folder` only if it's an existing directory (not a link) that, on Unix, belongs to Lodestar's account and isn't group- or world-writable; otherwise nothing is listed, with the reason (`not_opened`, `not_a_folder`, `not_private`, `unreadable`). The API never creates or changes the folder.
- **Names are untrusted** (the request path, the history cursor, `index.json`). A name is accepted only if it's at most 64 bytes and exactly `lodestar.jsonl` or `lodestar-YYYYMMDDTHHMMSS.mmmZ[-N].jsonl[.gz]` (`N` from 2, no leading zero), is parsed into a typed value that every path is built from, must be in the folder's listing as a regular file, and is opened with `O_NOFOLLOW` (on Windows a reparse point is refused) and checked to be a regular file by its handle. A refused or unknown name is `404 log_file_not_found` and is never echoed.
- **`index.json` is untrusted input** that supplies only flags by a validated name. An entry naming anything else, or with the wrong types, only loses its badge. **An index that exists but can't be read (or is a link) makes every file count as having details and an opt-in (§2.19: fail-closed badges)**, and `GET /logs/files` says `index_readable: false`. A missing index is an empty one.
- **`GET /logs/files`:** `{folder, state (on|off|stopped|unavailable), reason, index_readable, files: [{name, size, from, to, details, opt_in, current, compressed}]}`, newest first. `details` is `details || opt_in`. `from` is the first line's time (at most 64 KiB read, decompressed), cached by name, size and modification time; `to` is a rotated file's stamp, or the current file's last line written this run (else its modification time). Links named like logs aren't listed.
- **`GET /logs/files/{name}?format=jsonl|text&redact=true|false`:** always decompressed; the current file up to its last whole line at open. `redact` defaults to true when the file has details (or the index is unreadable). Headers: `application/x-ndjson` or `text/plain; charset=utf-8`, `Content-Disposition: attachment; filename="<stem>[-redacted].<jsonl|txt>"` from the typed name, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`. A download holds one of the 2 file reads for its length; `close()` ends it.
- **What "redact" does (§2.19: a download transform only).** Lodestar never rewrites a log file; deleting is how details leave the disk. Each line is parsed and rewritten through today's rules, with the same function history masks with:
  - `hash` (in hex), `name`, `path`, `url`, `query`, `peer` and `filter_changes` values read `[hidden]`; a `peer` beside a `hash`/`name`/`path` field is peer activity; a `ref:` value stays (torrents read `[hidden]` rather than this run's `ref:`, so another run's hashes aren't linked to this run's references);
  - **`client` values read `[hidden]` too** (runner's decision, §2.19: a shared log mustn't carry the admin's own addresses), which is stricter than Private; `size`, `error` and `label` stay;
  - lines of an opt-in event are dropped (for an event this build doesn't know, any line carrying `filter_changes`);
  - untyped messages and values go through today's `url::scrub_text`; an unknown field kind is hidden;
  - the setup token reads `[redacted]`;
  - a line that doesn't parse, or is over 1 MiB, becomes `[unreadable line]`: redacted output never passes bytes it couldn't parse.

  `redact=false` serves the file's own bytes (JSONL), or each parsed line in text with the console's escaping (an unparseable line escaped). `format=text` is the console's text format, with `repeated` as its suffix.
- **`GET /logs/archive.zip?format=&redact=`:** every listed file converted as above (`redact` defaults to true when any file has details), streamed through an in-house zip writer on `flate2` (deflate, CRC-32, data descriptors; no new crate). **No zip64:** a member stops at 4 GiB less 64 MiB uncompressed, or where the archive's offsets would pass 32 bits, ending with a `[truncated …]` line; no member starts past 3.75 GiB, and the files left out are named in a last `archive-incomplete.txt`. With files of at most 1 GiB, only an unusually large folder meets either.
- **`DELETE /logs/files`** (`{"which": "all" | "details"}`, same-origin JSON, no password: Destructive, §10.10.7):
  - it runs **as a job on the `log-rotate` worker**, after any compression queued before it, so a file being compressed can't come back as `.gz` once deleted; each name's `.gz` goes too, then the `.part` leftovers and the names' index entries;
  - **the current file is never touched mid-write:** when it's to go, it's rotated first under the writer's lock and the rotated name is deleted with the others. "All" also takes every rotated file present when the job runs that isn't newer than that rotation, so a rotation between the listing and the job leaves nothing older behind. With file logging off or stopped there's no writer, and the deletion runs where it's asked, under the same checks;
  - "details" is `details || opt_in`, or every file with an unreadable index;
  - **files that aren't regular (a link with a log's name) are skipped and reported**, never followed;
  - the response is `{deleted, bytes, skipped: [{name, reason}]}`; it logs **`logging.files_deleted`** (new, not required; count and size only, §2.19), and the ring isn't touched.
- **Windows:** std opens files sharing delete, so a download holding a file open never makes rotation, pruning or delete fail; a test holds that on Windows CI.
- **A disk-full stop stays stopped until a restart** (B-log1). A follow-up could reopen the file once space is back.
- **A compressed file is never inflated past 1 GiB + 64 MiB for a download or the archive,** the bound history reads by (part 1, round 1): a hostile `.gz` in the folder ends there.
- **`redact=false` serves the file's own bytes, setup token included.** The token is one-time: setup consumes it before any session exists, and only a signed-in session can download, so a raw download can only carry a spent token. Redacted output, history and the stream show it as `[redacted]`.

## After the self-review
- **`close()` ends a download whose client stopped reading:** the reader stops waiting for room when the source closes and lets its read go, and the body ends with an error, never as if the file ended there. (A client that holds its connection open without reading still keeps the server's graceful shutdown waiting on that connection, as it would for any long response; that is `services.rs`'s, and the PR names it.)
- **The archive names every file that isn't whole in it,** in `archive-incomplete.txt` with the reason: left out at the size limit, couldn't be opened (deleted meanwhile, or unreadable), or cut short (a corrupt `.gz` ends its member with an `[unreadable …]` line and the archive goes on). A rotated `.jsonl` compressed since the listing is read as its `.gz`, for a download too.
- **A deletion waits for the rotate worker however long the compressions before it take,** and never runs beside them. It runs elsewhere only when the folder has no worker, so nothing compresses in it. The current file, rotated for a deletion, isn't compressed first.
- **With no writer in the folder, the current file is moved aside under the writer's lock** (to a rotated name) and deleted as one, so a writer opening meanwhile starts a new file rather than writing to one that's going. Its index entry stays under the current file's name until that's written again, so the next current file may show "Contains torrent details" when it has none: the badge fails closed.
- **"All" never sweeps a file rotated after the request,** even when rotating the current file fails.
- **`index.json.part` is left to the index's own save,** which truncates it.
- **One load of lines from a gzip member or window holds at most a line per 32 bytes of its length** (no line Lodestar writes is shorter); more makes the file unreadable (runner's suggestion after part 1).
