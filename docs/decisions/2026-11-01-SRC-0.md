# SRC-0 decisions (plugin contract v2)

Slice SRC-0 of `docs/plan/2026-11-01-v06-sources.md`. It covers architecture §18.1, §18.4 and §18.9.

- **The v2 manifest fields live in `Policy`, beside `Manifest`.** `SourcePlugin::policy()` returns it, and its default is `Policy::STRICT`. Politeness caps, the JSON-schema config, `distribution` and default schedule windows all go there.
  - Why: `Manifest` is built as a static struct literal in `pipeline/src/dht.rs`, `lodestar/src/services.rs` and several tests. A new field would break every one, and the DHT plugin had to stay unchanged.
  - A plugin that declares nothing gets the strictest settings: coordinator only, no full scrapes, one request per host every 10 s, polls at most every 15 min, and back-off from 30 s to 6 h. Approved by the runner, 2026-11-01.
- **Caps are hard.** `Policy::limits(&UserLimits)` takes the stricter side of every part: the longer poll and request interval, the smaller burst, the smaller daily scrape quota, and the longer back-off floor and ceiling. `Limits::within` is the check, and a property test covers any caps against any user settings.
- **One exception to the owned paths:** a single line in `crates/pipeline/src/lib.rs` (`kit: lodestar_sources::Kit::default()`) at the `SourceCtx` literal. Approved by the runner, 2026-11-01.
  - `SourceCtx` gains `kit: Kit`, which holds the plugin's `PluginState` and `HostLimiter`. `Kit::default()` is in-memory state on `Policy::STRICT` caps.
  - SRC-1 and SRC-4 replace it with the store-backed state and the plugin's own policy, using `Kit::new`.
- **The discovery event is `Found` with two new boxed options:** `claims` and `provenance`. A bare DHT key pays two null pointers and nothing else. `Discovery` and its literals are unchanged.
  - The event has no `network` field yet. Keys are still `InfoHash`, and the network tiers (§18.6) add it with their own key types.
- **Claims are bounded at the contract boundary.** The `Emitter` clamps every event's claims and provenance before it leaves the plugin.
  - The limits: name 1 KiB, files 10,000, path 4 KiB, trackers 64, IDs 32, description 64 KiB, publisher 256 B.
  - Clamping trims; it never rejects. It doesn't replace the child-safety filter, which still runs on every claim before storage (§18.7, §20.1).
- **`PluginState` is async** (it returns `BoxFuture`), so the store-backed version can go through the writer. It offers get, set, remove and compare-and-set.
  - Both implementations enforce the same limits: keys 1–128 B, values ≤ 64 KiB, ≤ 1,024 keys per plugin. A plugin that passes against `MemoryState` then fits in `source_state` (SRC-1).
- **The per-host limiter is GCRA** (a token bucket of `burst` refilled one per `interval`). In any span of time `t`, one host gets at most `burst + t / interval` requests.
  - Back-off after the n-th consecutive failure is drawn from `[full/2, full]`, where `full = min(max, base × 2^(n−1))`. The jitter is splitmix64, seeded per limiter.
  - The limiter tracks at most 1,024 hosts and forgets idle ones first. Forgetting an idle host loses nothing, because its bucket is full again.
- **"Blocked by source"** applies on 401, 403, or a 429/503 that carries `Retry-After`. Nothing goes to the host until the block ends: the source's `Retry-After` (delta-seconds, capped at 24 h), or the back-off ceiling when it gave none.
  - **Refinement:** "until the next window" is read as that time. Schedule windows are a separate gate, which the scheduler applies (see below).
  - A 429 or 5xx without `Retry-After`, or a transport error, backs off instead. Any other answer, 404 included, resets the back-off.
- **The daily full-scrape quota** is per host over a rolling 24 h. A quota of 0 never grants.
- **Schedule windows** are minutes since local midnight, and a window may wrap past midnight. Turning the clock into a minute of the day belongs to the scheduler (SRC-4/SRC-14), not to this crate.
- **`Fetch` is the HTTP seam.** SRC-5 implements it with reqwest and the plugin's egress. Plugins send only through `Client<F>`, which takes the host's token, sends, and feeds the answer into the back-off. No client is built here.
- **`testing` is always compiled** (it doesn't sit behind the `testing` feature, which stays the crawler simulator's), so plugin crates can use it from their own tests.
  - `FakeCtx` wires a `SourceCtx` to channels. `Running::stop` measures the time from the shutdown request to the plugin's return against `STOP_WITHIN` (1 s), within a 10 s deadline.
  - The fixture layout (`NNN.http` + `NNN.body`, replayed in order and matched strictly, with `finish()` reporting skipped or unmatched exchanges) is documented in the module docs for SRC-7 to build on.
