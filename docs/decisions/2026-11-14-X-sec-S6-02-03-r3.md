# X-sec-S6-02-03 decisions (part 2b: the store side of worker reports)

The store side of cluster worker-report hardening, for held finding S6-02 (blocking; surface M8-SEC-6, the cluster). The detail is held under `docs/security/v1/README.md` §5, so this file says only what the code now does. Parts 1 and 2a are `2026-11-14-X-sec-S6-02-03.md` and `-r2.md`.

## Worker floor reports (WK-10d)

- **The stored check and the hold are one write.** `Store::tombstone_from_worker_unless_stored` reads whether the store has anything under each key (a stored torrent, an item awaiting verification, an import candidate) and writes the `worker-floor:<id>` row only where it has nothing, in one write transaction. A failure part way writes nothing. The floor writer uses it.
- **A worker's report holds its key for 7 days.**
  - This is the owner's choice (owner, 2026-11-14), kept as one constant: `WORKER_FLOOR_HOLD_SECS` in `crates/lodestar/src/cluster/serve.rs`.
  - The floor writer deletes `worker-floor:` rows older than that when it starts, and hourly after (`Store::expire_worker_floor`). It uses the tombstones' existing `at` column, so there's no schema change.
  - A local floor row, a list's or a user's is never touched, and the prefix match is exact.
  - A key let go is judged again in full on its next fetch: every remote result is judged again by the main node's own filter before it's stored, and a floor hit there holds the key under the main node's own rule. A new worker report holds it again too. Nothing is released without that judgement.
- **A revoke deletes that worker's reports, in the same step as the revoke.**
  - This is the owner's choice (owner, 2026-11-14). `Workers::revoke` calls `Store::purge_worker_floor` along with forgetting the reports not yet written.
  - It matches the rule exactly, so another worker's reports and every hold the main node made itself (local floor, list, user, adult) stay. A key that loses its last hold this way is judged again on its next fetch.
  - It runs under the floor writer's lock, so a batch already being written can't put a row back, and the worker's later reports are refused. A delete that fails is tried first by every later flush until it lands, counted and logged as a failed write. The revocation stands either way.
  - It's WK-13's purge-by-worker, limited to these rows.
- **A worker's report gives way to any other hold.** This is the runner's call (`docs/owner-decisions.md` §2.33): no key becomes unheld without a main-node judgement. A rule that takes a report's place can be released by that rule's own release path, as any hold under it can. A worker-floor row lasts only its hold time, so a hold that doesn't expire takes its place:
  - **Filter holds:** a filter rule's tombstone (ingest, refile, `hold_claims`, a list's or a user's) replaces a worker-floor row on the same key (`filter::write`).
  - **Adult holds:** an expired adult hold's tombstone replaces a worker-floor row too, in `Store::purge_filter` and in a rollback's purge. Only a local floor row (CS-1a/1b/8a) stays over it.
  - **Rollback merge:** `hold_rank` orders the local floor, then a kept hold, then an adult hold, then any other, and a worker-floor row last. Any hold that doesn't expire wins over it. This supersedes the `hold_rank` bullet of `2026-11-08-WK-10d-store.md`, which ranked it second. The local floor's rows keep the top rank.
  - No release removes a worker-floor row, as before. A worker-floor row never replaces another row: it's written with `ON CONFLICT DO NOTHING`.

- **The built-in worker's held set follows.** When a report expires or its worker is revoked, `FloorReports` takes the key out of the pipeline's in-memory held set (`HeldSet::remove_released`), unless the store still holds it under another rule or a report not yet written holds it. The main node's writer then judges the key's next fetch in full instead of refusing it outright. A store that can't answer leaves the key held.

## Lease queue (part 1 follow-up)

- **The waiting order's compaction keeps one place per waiting key.** A key that leaves and is parked again no longer keeps two places.
- **Clarification of part 1:** a worker with no lease cap is still bound by `MAX_PENDING_PER_WORKER`, as well as `MAX_PENDING` and the backlog.
