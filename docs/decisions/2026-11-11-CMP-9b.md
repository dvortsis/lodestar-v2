# CMP-9b decisions

The companion chip "Needs X · Set up" in Sources (plan `docs/plan/2026-11-06-v06-companions.md` CMP-9b; architecture §10.10.8, §18.10). None loosens an owner or security decision. Items marked _runner_ are the runner's answers of 2026-11-11 (§2.26, flagged to the owner under §2.19).

- **The state is the server's.** The chip reads the Sources API's `companion_need` (`{companion, state}`, CMP-10): `missing` shows "Needs X" with **Set up**; `unhealthy` shows "X isn't responding" and points to Settings → Companions (restart lives there), with no Set up. A companion id the chip doesn't know reads as "a companion program". The chip builds no install request of its own.
- **Set up opens CMP-9a's install dialog in place** (_runner_), so the user stays on Sources. It uses `InstallDialog.svelte` and `CompanionsStore` exactly as they are (no change in `settings/companions/`): the offer is read, the dialog shows it, nothing is fetched until Install is pressed, and the request carries only the offer's version and SHA-256. A refused offer or install shows the existing plain-words sentence (`failureWords`), never the code. Pressing Set up again after a refused offer reads a fresh offer.
- **After an install** the row reads the Sources list again and focus goes to the row's name (the chip is gone by then). A companion just installed may not be reported healthy yet, so while the chip is still shown it says "X is starting. Checking again." and the screen reads again every 3 s, up to a minute, until the server stops reporting the need. The screen's own live region says "installed" (it outlives the chip, so it is heard).
- **A dialog closed mid-install** keeps the flow mounted and Set up shown as working until the install answers: a refusal is then shown on the chip, and no second install can start meanwhile.
- **Loaded on demand.** `SourceRow` imports the chip only for a source with a `companion_need`, and the chip imports the install flow only when Set up is pressed.
- **Mount lines** (shared edits, _runner_): `onrefresh={load}` in `SourcesScreen.svelte`; in `SourceRow.svelte` the lazy chip block, an optional `onrefresh` prop, and a focus target on the row's name.
