# S-wizard decisions: first-run wizard, part 1

Part 1 of the slice (§10.10.10, §3 "Cold-start reality", §12.2): the shell at `/welcome` and steps 3, "How it works", 4, 5, 8 and 9. Part 2 adds 6, 7 and the rule-pack step.

- **Part 2 slots.** `wizard/steps.ts` lists the steps in order and names where the rest go (`SLOTS`): **6 Import from bitmagnet** and **7 Download client** after Storage & retention, and the **rule-pack step** (§20.6, packs pre-checked) after them, before Updates. Adding one is a new entry in `STEPS` and a loader in `WizardPage.svelte`; nothing else moves. Part 1 shows no placeholder for them, so a visitor never sees a step that can't be used. Progress numbers count the steps shown (3, 4, …), so the list has no gap until those steps land.
- **`/welcome` keeps the auth check and replaces the links page.** `WelcomePage` still does the setup-required, signed-out, retry and no-focus-steal handling, and renders the wizard once signed in. The page heading is now "Finish setting up", with each step's own heading below it. The old "Go to Search / Review settings" links moved to the Done step, which is where the brief wants them.
- **Steps 1 and 2 are listed as done** (they happen in `/setup`), using the existing `auth_setup_step_*` messages.
- **Progress** is `{ step, done, skipped }` in `sessionStorage` (`lodestar.wizard`), wrapped in try/catch, so a reload resumes and blocked storage only loses the resume. Anything unreadable starts at the first step. Nothing else in the app reads it.
- **Chunks.** The first view is the shell, the progress list and the page's auth check. Each step is its own dynamic import, loaded when it opens; the three form steps share the Settings engine's own lazy parts. If a chunk fails to load the shell says so and offers a reload (a failed module can't be retried). Their sizes are gated by a second entry, "Wizard steps (on demand)".
- **The engine is used as it is.** Steps 4 and 5 are `SettingsForm` (no save bar, no leave guard, no ⌘S) with `SettingField`s, so previews, validation, locks and errors are the engine's. **Save and continue** calls `form.save()`; it moves on after a save or when nothing changed (no request). A refused, conflicting, invalid or unreachable save leaves the step where it is with the engine's error summary or notice; the server's value stays the saved one and nothing is shown as saved. **Skip** never touches the form: no request, and the staged edit is dropped with the step.
- **Intensity** shows `crawler.intensity`. **Storage & retention** shows `storage.archive_raw` and `storage.mmap_mib`: the schema has no retention field yet (the only one, `insights.query_retention_days`, belongs to query logging). A retention field joins the list when the server adds one.
- **Updates (step 8)** uses the engine's form for `updates.mode` but a hand-built radio group, since the Settings screen for Updates isn't merged and its labels don't exist. Off, Check and notify, Install automatically; the server's current value is the only one selected (Off by default); "Container image updates" appears only when it is the current value, never as a choice. The step says plainly that checking contacts GitHub (§12.2). A value set by `LODESTAR_UPDATES` shows locked (disabled, with the variable named). "Fixes only is labelled recommended" (§10.10.10) is not implemented: the brief says to preselect nothing beyond the current value, and `updates.level` isn't part of this step.
- **Network check (step 3).** Reads `GET /network/check` every 5 s while `reachable` is `null`, one request at a time (the next read is scheduled when the last answer arrives), until it knows or 12 minutes have passed (the server measures for 10). It stops when the step unmounts and aborts the request in flight. **Retest** is the 30 s-limited `POST`; a `429 rate_limited` shows "You can retest once every 30 seconds" with the server's `Retry-After` when it sent one, and keeps the last answer. When the port isn't reachable the step lists the router port forward and the VPN case, and says Lodestar works either way.
- **"How it works"** is a static inline SVG of four numbered boxes with arrows, `aria-hidden`, and the four stages as an ordered list, which is its text equivalent. It sets the §3 expectation: the index grows over days and weeks. No numbers are quoted, since §3's are rough estimates.
- **The wizard changes no content-safety setting in part 1.** Only `crawler.intensity`, `storage.*` and `updates.mode` are ever sent.
- **Sizes.** The `/welcome` first view has its own entry at measured + 10%; the step chunks have one. No other entry is touched (Alert, Search results, Alerts and the Results toolbar are not changed by this slice; their sizes were checked before and after).
- **Messages.** `wizard_*` in `features/wizard/messages/{en,zh}.json`, both filled.
