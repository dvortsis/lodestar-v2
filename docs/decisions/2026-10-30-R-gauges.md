# R-gauges decisions

Storage and cache size gauges for `v0.5.1-rc.2` (owner's ruling on #189, step 5). The series are listed in `docs/metrics.md`, "Storage and cache sizes".

- **Sampled off the scrape path.** A task stats `lodestar.db`, `lodestar.db-wal` and walks `data/index` every 60 s on a blocking thread; `/metrics` reads atomics. Sampling is file metadata only: no query, no connection, no lock the writer or indexer holds. It changes nothing in the DHT, sources, peer wire, sampler, endpoint policy or pipeline lifecycle (build-plan §0.4).
- **Each size fails on its own.** A failed read keeps that size's last value and adds one to `storage_sample_errors_total`. `storage_sampled_seconds` moves only on a sample that read all three, so a stale timestamp shows failing samples. A missing WAL or index root is 0, not an error; a missing database is an error.
- **The whole index root.** `search_index_bytes` counts every version directory under `data/index`, so a rebuild's second copy shows as disk growth. The walk follows no symlinks, skips files a merge removes mid-walk, and gives up past 100,000 entries.
- **Shutdown never waits on a sample.** The sampler stops first in `Handles::shutdown`; a sample under way is left on its blocking thread.
- **Caches reported.** The serving index's `file:(…)` id-set cache (the 8 MiB budget, entries and retained bytes), its browse cache of per-segment tops (entries only: it is bounded in entries and keeps no byte estimate), and the result cache's existing entry and byte estimates by kind. These are read at scrape time: each is one short lock on a cache only searches use. The have-filter and hot columns already had `have_bytes` and `hot_columns_bytes`.
- **No detail cache series.** The detail caches are in the browser (the drawer's), not in the process.
- **No SQLite page-cache series.** The page cache is per connection, and the store sets no `cache_size`, so each connection is bounded by SQLite's default (2,000 KiB). Reading what one holds (`sqlite3_db_status`, or `PRAGMA` reads) needs each connection, the writer's included, which this slice must not touch. With a handful of connections it is a fixed few MiB, not a ramp.
- **Collector.** The Linux collector keeps only allowlisted series in its snapshots, so the new names join its allowlist as optional (`STORAGE`), not required: a sample from a build without them still counts. The Windows collector keeps the whole `/metrics` text, so it needs no change.
