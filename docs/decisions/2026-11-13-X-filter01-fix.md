# X-filter01-fix decisions

- **FILTER-01 (blocking, content safety; the child-safety core) fixed (Track Q, detail held).** The fix is the owner's choice, given by message (`docs/owner-decisions.md` §2.70). Its detail is held under `docs/security/v1/README.md` §5 until a release with the fix is published.

## Calls
- **The core reads a torrent whole, within a work budget** (§20.5, §20.8): its name and every file path, padding files' included, in both readings (§20.4). The tokenizer meters the work as it reads (bytes, words, characters, tokens, files and path segments, each new word or character counted once per torrent, so a torrent costs the same whatever the thread read before). A torrent past the budget is held as too large to judge under **CS-0a**, before any other layer reads it. A cheap check before reading holds one whose least cost is already past it. Runner, approved by message.
- **CS-0a is locked** (§2.70): on always, no exception, no CSX-5 entry or *Always allow* passes it, and its quarantine never expires (`KEPT_RULES` in the store). Releasing one needs the effect warning and the admin password, every time, through the admin session only; the torrent is judged again when it's next seen. It isn't part of the floor: the hash-list paths (`FLOOR_RULES`, worker floor reports) don't read it.
- **A per-character cache for non-ASCII text** in the tokenizer, with tokens identical to before (checked against the verbatim reference for every character). Runner, approved by message.
- **Your rules and the packs keep reading up to 1,000 files** (`MATCH_FILES`), as before. Runner: not widened here.
- **Pairing a term with a nearby one** reads a sorted index per text, built once for every rule, with no hashing.

## Numbers (build VM, release)
- **Budget:** 9,000,000 units, each about a nanosecond on the reference runner.
- **The core at the budget:** 2–10 ms for every input shape measured, adversarial ones included (`budget_worst_case`, 26 shapes; its bound is 15 ms scaled, for noise on this host).
- **Within the budget:** 10,000 files with paths of up to 120 bytes, and a 4 KB name, in Latin, CJK, Cyrillic or Arabic; typical seasons of 11,500–12,700 files.
- **§20.8 gate:** about +2 µs per torrent against `main` measured in the same session.
- **The whole engine at the core's budget:** up to about 97 ms per torrent (invisible characters between letters), 30–33 ms for decomposing and combining characters. That's the packs' and your rules' own reading, outside the core's meter.
