# UX-start decisions (PR number to be added)

The UI no longer assumes a six-hour wait (owner §2.77, `2026-11-15-owner-no-start-wait.md`, CR-0w #1134). The pill, Overview's first hour and the wizard show progress.

## Decisions
- **No uptime fallback** (runner, 2026-11-27). The UI is embedded in its own server, so a UI never runs against an older server. `stats.sampling_blocked` absent or null means sampling isn't blocked. `STARTUP_SUPPRESSION_S` and the derived `WINDOW_CLEAR_S` are gone; the stored-rate window now clears `START_GRACE_S` (15 min) plus the two reported hours after the start. Tested for set, null and absent.
- **"Starting"** shows only inside a start's grace while the DHT has no routing nodes (`crawler.dht_nodes === 0`, with the grace's `warming` overlay, so a DHT that loses its nodes later is a stall, not "Starting"; null means off or not reported, which isn't joining) or `sampling_blocked` is set (the 10 s start hold, or the crash-loop guard's `dirty`, up to a minute). Every reason reads the same: sampling begins once the DHT has joined. `locked` is no longer named.
- **"Warming up" is a new pill kind** (runner grant, 2026-11-27). It shows for a start inside `START_GRACE_S` while the crawler has stored nothing since the start (`crawler.stored === 0`), with "{found} harvested · {stored} stored". It ends at the first stored torrent, or after the grace, when the stall rules take over; a stall always wins. The rule is the pill's, so the plan's "first hour" isn't promised: nothing waits an hour, and a restart of an established index warms up for the same few minutes. The steady state stays "Working · N torrents".
- **The restart-record pill reason is removed** (`restart_record` and `shell_status_record_help`): `invalidate_failed` no longer waits (CR-0w). Nothing else used them.
- **Overview, first hour:** while no completed cohort exists (`startup === 'yes'`), nothing is searchable yet, nothing needs attention and the crawler isn't paused (cohorts finalize late, so `startup` alone can last days), the page shows the starting scene with the pipeline (nodes found, harvested, metadata fetched, stored, from the live `crawler` event) in place of the KPI row and charts. Everything switches to the normal page at the first completed cohort. The title no longer promises "within minutes"; the body says the index grows over days and weeks.
- **Wizard:** `wizard_how_cold` (en, zh) drops the wait and says the index grows over days and weeks. Steps after "How it works" show the same live counts (`LiveCounts.svelte`, from the `crawler` event).
- **Samples:** the pipeline's counts come from the live `crawler` event (`dht_nodes`, `harvested`, `fetched`, `stored`), not `/stats`, which has none of them since start.
- **Words:** new glossary terms `warming_up` and `routing_nodes` ("DHT nodes", a snapshot). "Harvested" stays the word for keys.
