# ENR-7 decisions (detail API adult-enrichment section and drawer interest)

Slice ENR-7 (runner brief, 2026-11-05T15:45Z). Spec: plan `docs/plan/2026-11-04-v06-rulepacks.md` §4.3 (ENR-7; Q2, Q4, Q11, Q15), architecture §18.6, §18.7, §20.9, and `2026-11-05-ENR-1.md` ("What is sent and when", and the rate limit it hands to this slice). The section's fields are ENR-0's (`2026-11-04-ENR-0.md`).

- **`GET /torrents/{hash}` gains `adult_enrichment`** (`dto::torrents::AdultEnrichment`): `scene_title`, `studio`, `released` (`YYYY`, `YYYY-MM` or `YYYY-MM-DD`, as ENR-0 stores it), `performers` (names only, Q4) and `performers_truncated`, `source` (`id`, `name`, `plugin`) and `link`. Not the scene id, not the kind (the classification already carries it), never an info hash, file name or anything ENR-0 doesn't store.
- **Absent, never null or empty, unless all of these hold** (`skip_serializing_if`, `nullable = false` in the schema), so the API never says whether a match exists:
  - "Show adult content" is on (Q11). It's read **once per request**, so the 404 `adult_hidden`, the section and the lookup always agree.
  - The caller is the admin session (`Viewer::Admin`). **Stricter than the brief (runner's call, §2.19):** a `Viewer::Public` caller never gets it, with no preference rule that lets it. The source behind a match is Account class, which §18.7 already withholds from any public caller, and the route is session-only today. A later slice that opens the route to keys would have to decide this again.
  - The torrent could be adult: classified Adult, or found by an always-adult source (the mask the host passes). **Stricter than the brief (runner's call, §2.19):** a torrent classified Not adult after it was matched doesn't show its old match, as ENR-1 pins a kind only on adult items. This also keeps the section behind the preference for a torrent the 404 `adult_hidden` doesn't cover.
  - The torrent isn't held back: not `HIDDEN`, not `private_source`, and no swarm hash with a tombstone or quarantine row (`held_among`). Such a torrent returns what it returned before, with no section. A tombstoned one is gone, so it's the same 404 as before.
  - The chosen match didn't come through a private source.
- **Which match** (ENR-1's rule, `pipeline::enrich::stored_match`): the first by source id of the sections that name a kind, failing that the first section, so the drawer shows the match that pins the kind. If that match is from a private-source claim, nothing is shown: it isn't swapped for another, which would disagree with the pin.
- **The link** is the match's claims' `external_ref`, kept only when it's an `https` URL whose host is exactly one of the matching source's own manifest endpoints (`https://host`, from `ops.sources()`), with no user info or port, printable ASCII without `"'<>\^`{|}` and at most 2,048 bytes. Anything else drops the link and keeps the rest. With no pipeline served the endpoints are unknown, so no link is shown. A plugin whose pages live on another host than its API (`api.theporndb.net` vs `theporndb.net`) must list that host in its manifest endpoints for the link to show; that's ENR-4's to decide.
  - **Runner follow-up: nothing sets `external_ref` yet, so the link is null until it does.** ENR-1's runtime emits `Claims { adult, ..Claims::default() }`, and `Lookup::Match` (`crates/sources/src/enrich.rs`) has no field for the scene's page (`stashdb::Match::link()` builds it). The fix is in the ENR-1 contract, outside this slice: a `link` beside the match in `Lookup::Match`, which the runtime writes to `provenance.external_ref` (ENR-0 allows it beside a section). The API side here already checks and shows it. Building the URL in the API from the scene id would need each plugin's page URL here, which belongs with the plugin.
- **Drawer interest** (`DrawerInterest`, `crates/api/src/torrents.rs`). The API depends on no pipeline type: the host wraps ENR-1's `Interest::opened` in a closure and passes the always-adult mask (`AdultSources.0`). The detail handler offers the torrent's id only when the section's conditions above hold (preference on, admin, not held back) and the row could pass `adult_enrich::check`: classified Adult or found by an always-adult source, and not BEP 27 private or a partial import, which the gate always refuses. The gate still decides everything; this only keeps sure refusals out of the 64-item queue.
  - **Same answer either way.** The offer is made after the response is built and is a non-blocking `try_send`; a refused offer is dropped with no log line, so neither the body nor the timing tells a caller whether it was taken.
- **Rate limits (runner-flagged §2.26 choice):** two token buckets on a clock the caller can supply (`DrawerInterest::with_clock`), integer tokens, remainder kept between refills.
  - **Per client: 10 at once, then one every 30 s.** A person opening a page of results gets them looked up first; a script gets two a minute. A client is its address (`ClientIp`, which follows the trusted proxy's `X-Forwarded-For` when proxy auth is on), or its IPv6 /64, so rotating addresses in one network buys nothing.
  - **Overall: 30 at once, then one every 20 s,** so at most 4,350 user-interest lookups a day across every client. Interest skips the runtime's background cap of 5,000 a day (ENR-1), so a service sees at most about 9,350 lookups a day from one install. The runtime's own pacing (1 s between lookups, one request a second per host) still applies on top.
  - **Bounded memory:** at most 1,024 clients tracked; when full, clients whose bucket has recovered are forgotten, and newcomers otherwise share one overflow bucket.
  - A token is taken from both buckets or neither. A full runtime queue still spends the tokens: the item waits for the background.
- **The slot is a router extension, not an `ApiState` field.** Adding a field would touch about 45 `ApiState` literals in other slices' tests and the host. The handler reads `Option<Extension<DrawerInterest>>`; the host mounts it with `router(state).layer(Extension(interest))`. None is mounted until the host slice wires a plugin (ENR-4/ENR-5 and the host). The shared hunk is one line in `crates/api/src/lib.rs`: `pub use torrents::DrawerInterest;`.
- **Not done here:**
  - `docs/metrics.md` §7.2 doesn't list the section: it isn't a metric, and the contract doc isn't this slice's. The OpenAPI document describes it.
  - Host wiring (`crates/lodestar/**`): building `DrawerInterest` from `Interest` and the always-adult mask, and the `.layer(Extension(...))` line.
- **Tests** (`crates/api/tests/adult_enrichment.rs`, unit tests in `torrents.rs`): the section present with the preference on and the key missing with it off (and 404 `adult_hidden` with no section text); matched items not classified Adult (Not adult, and always-adult-source finds) have no key with the preference off, and a Not adult one has none with it on; a hidden, a held (quarantined) and a private-source item, a private-source claim, and a private claim ahead of a public one get none; an always-adult find and a partial import show theirs; a link on another host is dropped and the rest kept; two matches show the kind-pinning one; an API key, a bearer key and no credentials get nothing; interest is offered only with the preference on and only for items the gate could pass (including an always-adult find, never a partial import); the admin-and-preference check refuses a key or feed token (unit test, since the route's guard stops them first); the per-client limit (burst, refill on the controlled clock, another client unaffected, one IPv6 /64 counted once) and the overall limit hold; taken and refused answers are byte-identical; the link check's refusals (scheme, host suffix and prefix tricks, user info, port, quotes, spaces, length); the client map's bound and overflow. No fixed sleeps.
