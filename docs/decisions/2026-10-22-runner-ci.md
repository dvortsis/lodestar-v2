# Runner: faster CI and per-PR decision files (#90)

The owner asked for whatever reduces queue time (2026-10-22). Every PR ran all 26 jobs, 10 of them fuzz targets, plus macOS and Windows test suites and an arm64 image build, even for docs-only or web-only changes. A dozen approved PRs were waiting 30–60 minutes for runners.

- **CI runs what a PR's files need** (`.github/scripts/ci_changes.py`, run by a `changes` job in `ci.yml`).
  - **Rust jobs** (fmt, clippy, openapi drift, Linux and Windows tests) run only when a crate, `bench/`, `fuzz/`, a Cargo manifest or lockfile, the toolchain or the workflow changes. Web and docs PRs keep their own workflows (`web.yml`, `e2e.yml`).
  - **The size and search-latency gates** run when a crate `lodestar-bench` builds changes. **The filter budget** runs when a crate `lodestar-filter` builds changes. **The importer test** runs when a crate `lodestar-sources-importers` builds changes. Each follows the workspace's path dependencies transitively.
  - **Each fuzz target** runs when a crate it builds changes, and all of them run when anything under `fuzz/` changes.
  - **macOS tests** run on every push to `main`, nightly, and on a PR labelled `full-ci`. Windows stays on every Rust PR, because it's a primary platform (§11).
  - **Main, nightly, manual runs and the `full-ci` label** run everything, so nothing goes untested for more than a day. Adding any other label does nothing and doesn't cancel a run in progress.
  - **Dependencies:** a gate follows the crates its job builds, transitively. Dev-dependencies count only for the crate a job tests with `cargo test -p`, because cargo never builds a dependency's dev-dependencies. `web/src/lib/api/openapi.json` counts as Rust, since the drift job checks it against the DTOs.
  - **Skipped jobs show as skipped.** The runner treats skipped as passing. `main` has no branch protection today; if it's ever added, require an aggregate job, because a skipped matrix job keeps its unexpanded name (`test (${{ matrix.os }})`) and would never report under its expanded one.
- **The arm64 image build** runs on a PR only when the Docker packaging, the lockfile, the toolchain or `release.yml` changes, or with `full-ci`. The amd64 smoke build still runs on every Rust or web PR. Tags and the nightly always build both, and `publish` checks both results explicitly.
- **Decisions are recorded one file per PR** in `docs/decisions/`, instead of appending to `docs/architecture.md` §16, which made almost every PR conflict with the others. §16 keeps everything recorded before this and is closed to new entries. CLAUDE.md, `runner/standards.md`, `runner/README.md` and the build plan point here.
