# X-un1-nits decisions

These are the nits from the fresh review of #762 (UN-1, runner-state `reviews/rv-762-885c7717.md`). They refine `docs/decisions/2026-11-12-UN-1.md`.

## Usenet poll timing (`prowlarr.rs`, `UsenetPolls`)
- **A Usenet indexer counts as polled only after a 200 whose results were all sent.** Only then does it wait `USENET_POLL_EVERY` (an hour) before the next request. Before this change, it was marked polled before the request.
- **A failed page is asked for again on the next poll, 15 minutes later.** That covers a timeout, a 5xx, a page over `USENET_PAGE_BYTES`, and a page that `USENET_POLL_ITEMS` (4,096 per poll) cut short. In the last case, the results that weren't sent come back on the next poll, as that constant's doc says.
- **At most `USENET_DAILY_HITS` = 48 API hits per indexer in any 24 hours, retries included.** That's 24 for hourly polls and as many again for retries.
  - Past the bound, the indexer waits until its oldest hit is a day old.
  - An indexer that fails every time gets at most 48 hits a day, half the torrent schedule's 96.
  - An indexer that never fails gets 24.
- **Memory:** the state holds at most `MAX_INDEXERS` entries of at most 48 instants each. An entry is removed once it has no hit in the last day and no successful poll in the last hour.

## The hold counter (`UnverifiedStats::held`)
- **Usenet hits are counted the way BitTorrent hits are.**
  - A hit from the floor or the core counts as `held`, though no hold is written for a usenet key (UN-0's gap).
  - Any other rule's hit, on either network, counts as `dropped`.
  - The field's doc now says so. UN-1 had counted every usenet hit as `held`.

## The intake's defensive refusal (`lib.rs`, `claimable`)
- **A usenet find never reaches the claim step, whatever path brings it there.** That includes the `retried` branch.
  - Such a find is refused and counted as `refused`, so its 20-byte writer-map key never goes to the coordinator, the pool or peer finding as an info hash.
  - Today no path sends a usenet find to the retry channel: touches skip it, and the verification cursor is BitTorrent only. The check keeps it that way.

## The `usenet` switch is off the settings form (runner, UX call under §2.26)
- **`CONFIG_SCHEMA` no longer lists `usenet` until UN-3 makes usenet items sendable.** Turning it on would spend the indexers' daily API hits on items nobody can see or send.
- **The key still works:**
  - `Config::from_json` reads it, off by default;
  - `to_json` writes it only when it's on;
  - Jackett still refuses it.
- **UN-3 puts it back on the form.** No user-facing text changes, and nothing changes in `web/` or the OpenAPI spec: the form is built from the schema at run time.
