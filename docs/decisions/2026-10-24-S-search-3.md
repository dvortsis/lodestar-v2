# S-search-3 decisions (the results toolbar and paging)

The search page's results toolbar and cursor paging (architecture §10.4, §10.13, §10.15), on top of the results list (`2026-10-24-S-search-2a.md`) and the facet rail (`2026-10-24-S-search-2b.md`). This is the last v0.5 slice. Items marked **(§2.19)** refine an owner decision and are for the runner to flag.

## The toolbar

- **It loads with the results panel and shows once there is a query.** The page imports it in the same batch as the panel, so both paint together. Its count line keeps its height while the count is out, so nothing moves when the count arrives. The e2e specs measure CLS at 1366 and 390 px.
- **Count:** the rows' count from the results store, formatted as `docs/metrics.md` "Result count" says: `formatCount` ("1,284 results"), or `formatCompact` with "≈" when `total_approx` is set ("≈ 2.4M results"). No matches reads "0 results".
  - It's visual only. 2a's polite region still announces the count, once per answered query (§10.13).
- **Sort:** a native select (the `Select` primitive, 32 px).
  - The options are the sorts W5 keeps in the URL (§7): Relevance, then discovered, size and files, each both ways ("Newest discovered", "Oldest discovered", "Largest", "Smallest", "Most files", "Fewest files").
  - A bare field in a pasted link (`sort=discovered`) shows as its descending option, which is the server's default order.
  - It writes through W5's `setSort`, so each change is a history entry and Back undoes it.
  - The server's swarm sorts (seeders, leechers, trackers, seen) aren't offered, because W5 doesn't accept them yet. They can be added with swarm health in the UI (M4).
- **(§2.19) Density:** Comfortable/Compact (`SegmentedControl`), as the `density` URL parameter the rows already read.
  - It **replaces** the history entry instead of pushing one. It's a view parameter, not a search, so Back walks searches.
  - Comfortable is the default and drops the parameter.
- **Save search:** `POST /saved-searches` exists, so it's in. It opens the alerts' `SaveSearchDialog` (`features/alerts/README.md`), loaded on the first press with Bits UI's overlay code.
  - The dialog gets the shown query and sort, and its name field has a visible label. The channels it already has (In the app, RSS feed) come with it.
  - It stays on the search page and toasts, rather than opening the new alert.
- **Every write puts the URL back on /search first** (`ensureSearchPath()`, `query/path.ts`). A change made with the drawer open closes it, instead of navigating to the detail page.
- **Deferred, and not shown as disabled placeholders:**
  - Group versions: M7, with version groups;
  - Export: B10b;
  - select mode: S-search-5.
- **Breakpoints (§10.15):** one line that wraps. The count comes first; the sort, density and Save controls wrap below it on narrow screens. Under `pointer: coarse` the primitives grow to 44 px targets.

## Paging

- **The sentinel was already there** (2a: VirtualList's load-more row calls `results.loadMore()` as it scrolls near the end).
- **Added below the list:** a visible "Load more torrents" button, the fallback for the keyboard and AT, and an "End of the results" line after the last page. Both are one control's height, so the swap moves nothing.
- **One request either way.** The store ignores a second `loadMore` while one is out, whether it comes from the sentinel or the button, and the latest query still wins.
- **Focus:** the button keeps focus while a page loads (`loading` uses `aria-disabled`). When it goes, focus moves to what replaced it: the end line after the last page, or Retry when the page fails. Retry hands focus back to the button. The check runs before the DOM changes, while the old control still has focus.
- **No announcement per page (§10.13).** The list's own "Loading more torrents…" status (VirtualList, `lib/ui`) is the only cue.

## The v0.5 gate's path

- **`e2e/search-keyboard.fixture.test.ts`** runs search → results → drawer → copy magnet with keys only, against the real binary (`lodestar serve --fixture`), as the other fixture specs do. The G-v05 gate reuses it.
- **At 1366 px the facet rail comes before the results in the tab order**, with a stop per value. The spec's Tab loop allows 300 presses. A skip link to the results would shorten this path; it's a candidate for the gate's review, not added here.
