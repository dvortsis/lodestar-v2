# B-log1 decisions (logging core)

Architecture §12.1, §10.10.7, §10.10.12, §12, §13 and owner's decisions §2.11 and §2.19. No owner decision is reversed or loosened, and no security or content-safety decision is weakened. The refinements the runner flags to the owner (§2.19) are marked **(§2.19)**.

- **A new crate, `crates/log` (`lodestar-log`) (§2.19, §13 layout).** It holds the catalogue types, `log_event!`, the per-event switch and counter, the data kinds and the typed wrappers. Every crate's call sites need them, and a macro other crates call can't live in the binary. It depends on `tracing` only, for its fallback. The binary's runtime is `crates/lodestar/src/logging/`.
- **Typed events bypass `tracing` (§2.19).** `log_event!` checks the event's `AtomicBool`, bumps its `AtomicU64` counter, and only then evaluates the fields and hands a `Record` of raw typed values to the binary's sink. `tracing`'s field visitor can't hand a layer the raw value, and each output needs it to render by its own switches. Without a sink (tests, tools) the record goes to `tracing` with only the Private kinds shown, and torrents as `[hidden]`, because there's no run key. Untyped lines (Libraries, and the first-party lines the follow-up sweep converts) still flow through `tracing` behind the reloadable filter, into the same outputs.
- **Undeclared fields don't compile.** `catalogue!` makes each event a module with one function per declared field, each taking only wrappers of its kind. A field the event didn't declare, a value of the wrong kind, or a label built at runtime (`Label` takes `&'static str` only) is a compile error. Doc tests hold all three. The CI check doesn't need a rule for it.
- **A `System` component (§2.19).** §12.1's list has none for the process's own events: start, stop, crash, settings and logging itself. `system` is added. `Libraries` holds no catalogued event.
- **Verbosity presets and `default_on`.** A preset turns on every event at or above its level. An event declared `default_on: false` (a high-volume one) joins at Detailed. Required events are on at every setting and pass every output's level. `filters.change_detail` is on only while its opt-in is; no preset or override turns it on.
- **Timers are deadlines (§2.19).** Each is an `i64`: `0` off, `-1` until turned off, else Unix seconds, on while it's ahead. Nothing is saved when one passes. `follow` sleeps until the next deadline, re-applies the section, and logs the required `logging.kind_switched` with `state=expired`. `follow` also wakes at least once a minute and writes a heartbeat (`alive_at`) into the files' `index.json`. At start, a deadline that passed after the previous run's last heartbeat, while Lodestar was stopped, is reported as expired the same way, once. The data preset has one deadline (`data_until`) for its identifying kinds. Per-kind overrides carry their own, and so do the opt-ins (`peer_activity_until`, `change_details_until`) and the timed verbosity (`temporary_until`). `check` refuses `-1` and more than 24 hours ahead (plus five minutes for the round trip) for the opt-ins and the timed verbosity. Identifying kinds may be `-1` or up to 24 hours ahead. The UI sets deadlines from the server's clock, which `GET /logs/catalog` reports as `now`.
- **The opt-in field is `change_details_until`, not `filter_changes_until`.** The registry's test holds that no settings field names filtering state (§20.7), and this one only times a log opt-in. The kind is still `filter_changes` in the catalogue.
- **Peer activity is a rendering rule (§2.19).** A peer address in a line that also names a torrent (hash, name or path; a reference counts) shows only with the peer activity opt-in on, which is enough by itself, as its warning says. A peer address on its own shows only with peer addresses on. The console never gets peer activity.
- **References** are the first 32 bits of HMAC-SHA256 under a 32-byte key from the OS RNG (`getrandom`) at each start, held in memory only. Without the RNG, torrents show as `[hidden]`.
- **URLs.** `Url` (and `Url::request` for a request target) always removes userinfo, fragments, the values of credential-like query names (`apikey`, `token`, `passkey`, `key`, `password`, `sid`, `session`, `sig`, `uid`, `user`, `info_hash`, `peer_id` and any name containing `key`, `token`, `pass`, `secret`, `auth`, `sess` or `sig`), and any path or query value that looks like a passkey or a hash (16 or more letters and digits with a digit). Magnet links are never shown. Untyped lines get the same treatment, and lose their whole query string. Runs of 32 or more hex digits, or 32 base32 characters, are hidden.
- **`Error`** shows its type's name, or a fixed kind, and its message only for types marked `PlainError`. `DeliveryError` is marked: its messages are fixed texts and numbers. `io::Error` shows its `ErrorKind` only, since its message can name a path.
- **Example lines are in the preview (§2.19).** `Section::preview` returns `examples` (each event the staged choices turn on, data-carrying ones first, up to six, as the console and the file would show them). They're rendered from a made-up hash, name, path, tracker URL with a passkey, and documentation addresses (RFC 5737). The estimates are `console_mib_per_day`, `file_mib_per_day` (each event's rate since start × the output's average line × 24), and `file_days_kept`. The warnings are `identifying_kinds`, `peer_activity`, `filter_changes` (the owner's wording) and `verbose_logs`.
- **The rate per hour** is each event's count since start × 3600 / max(uptime, 60 s).
- **Console.** Text, or JSON as an option. Its kinds are the file's within Private, or the file's without the opt-ins with "same as the file". Text keeps the catalogue's message, then `field=value`. The setup token is written bare, right after the message (`… enter setup token ABCD-…`), as `tests/serve.rs` reads it.
- **The file** is `<file_folder>/lodestar.jsonl`, one JSON object per line: `ts`, `level`, `component`, `event` (or `target` for an untyped line), `msg` and `fields`, each field `{"kind", "value"}`. Untyped lines' fields are `"kind": "untyped"`.
  - It opens at `follow`'s first apply. The 2,000 lines (2 MiB at most) before that are kept, rendered on the defaults (Private), and written when it opens. Any beyond that are counted in `logging.startup_dropped`.
  - The file rotates at the size limit, or once it has been current for the maximum age. The rename runs under the writer's lock; a background thread gzips and prunes (count, age, total cap). A failed rotation keeps appending and retries after a minute.
  - A full disk (`ENOSPC`, `EDQUOT`, `StorageFull`) stops file logging until a restart. The required `logging.disk_full` goes to the console, and Lodestar keeps running.
  - `index.json` beside the files records, per file, `details` (an identifying kind or an opt-in was on while it was written) and `opt_in`. It's written atomically, and follows renames and deletions.
- **The panic hook replaces the default one.** It logs `app.crash` with the location only. The default hook would print the panic's message, which can hold a name or a path, to the console. A panic while that thread is inside the runtime writes one fixed line straight to stderr instead, so it can't hang on the runtime's own locks.
- **Log files are the owner's only:** the logs folder is created 0700, and files, rotations and `index.json` 0600 (Unix). The folder is the one the file first opened in until a restart, even if the file is turned off and on again.
- **Aliases.** `LODESTAR_LOG` and `config.toml`'s `log` set `verbosity`, `components` and `libraries`. A bare level is the verbosity (`warn` is Warnings). In a filter string, the default level is the verbosity, `lodestar*` directives are component levels (by the target table in `logging/mod.rs`), and everything else is the Libraries filter. With no Libraries directive, Libraries is `warn`. An unknown `lodestar_*` target is ignored. Set by the environment, all three fields are read-only. The `libraries` field refuses Lodestar's own targets.
- **The saved-key move.** A saved `settings.general.log_level` becomes `settings.logging.{verbosity,components,libraries}` at `Registry::load`, in one transaction that also deletes it. A key already saved under the new name wins. The section's revision isn't changed.
- **`GET /logs/catalog` reads `lodestar_log` globals,** so `ApiState` gets no new field: the registered catalogues, and the status the runtime publishes at each apply. Without a runtime it reports the Private defaults and no outputs. A runtime a test builds for itself never publishes, so tests can't disturb each other's switches.
- **First-party targets are an explicit list, `logging::TARGETS`,** mapping each first-party crate (and `lodestar::subscriptions`, `lodestar::floor`, `lodestar_api::auth`) to its component, for the untyped lines' levels and the aliases.
- **The CI check enforces an explicit path list (§2.19).** It covers `crates/log/`, `crates/integrations/src/`, `crates/lodestar/src/logging/` and the swept files. A listed path that's missing fails, and the check's own test runs it on the tree. One exemption is named in the script: `lodestar-log`'s fallback forwards to `tracing`.
- **Narrow canary limits (§2.19).** None weakens the canary as a whole:
  - **No swept event carries a hash, name, query or peer address yet.** Those lines are in the deferred files (pipeline, search, fetch, DHT, `api.request`). Run 2 checks that no other kind's fixture value appears, but can't yet check that the switched-on kind does. `logging::tests` holds each kind's rendering per output, peer activity included.
  - **The list refresh that logs a subscription's URL runs on its own minute,** so run 2 checks only that no passkey appears.
  - **Run 4 is two servers:** B12's key and proxy changes each take the password, and the per-address bucket holds five attempts, so keys, feed tokens and the proxy user have their own Full-plus-opt-ins run.
- **Private holds for typed events now, and for every line after B-log1b.** Deferred plain `tracing` lines are scrubbed of URLs, queries, passkeys and hash-like runs, but not of names, paths or error text. For example, `pipeline/writer.rs:233` logs a path and `search/rebuild.rs:1032` an error. `pipeline/lib.rs:391` logs filter notes, which can name rule terms, at every setting. The follow-up sweep converts them.
- **Integration call sites now take `&'static str` method names,** so a client's RPC method can be a label.

## After the runner's review (round 1)

- **The CI check scans every crate.**
  - It checks every `crates/*/src/**/*.rs` file outside tests, and every crate's manifest (a dependency renamed from `tracing`).
  - The `#[instrument]` and error-field rules apply everywhere now. The `#[instrument]` rule covers every spelling, `cfg_attr` included, and refuses `err` and `ret`.
  - The plain-macro rules skip only the files in `NOT_YET_SWEPT`. That list may only shrink: a listed file with no plain macro left, or a missing one, fails the check.
  - The scripts are among `ci_changes.py`'s Rust triggers. This replaces the earlier explicit list of enforced paths (§2.19).
- **Libraries keep a default level.** A Libraries filter with no bare level gets `warn` first, in both the alias and the applied filter, so `hyper=debug` never turns off every other third-party crate's warnings.
- **`lodestar=<level>`** sets every component, as it did before the section existed.
- **Text never drives the terminal.** Control characters and the bidirectional overrides are escaped in console text (values are quoted whenever they hold one) and in JSON lines, which stay valid JSON.
- **URL scrubbing, three additions:**
  - userinfo is found on the raw authority, so a password holding `#` or `?` is removed whole;
  - passkey-like runs between `.`, `:`, `,`, `=`, `+` and `~` go too (`/dl/<passkey>.torrent` keeps `.torrent`);
  - untyped text also loses `lsk_…` and `lsf_…` keys, `Bearer …` and the value after any credential-like name and `=` or `:`.
- **`Debug`** of `Value`, `Record` and `Peer` names kinds, never values.
- **The log folder and files:**
  - files are opened with `O_NOFOLLOW` and set to 0600 even if they existed;
  - the folder is made 0700, and tightened when it's Lodestar's own;
  - a folder anyone can write to without the sticky bit is refused;
  - another account's folder that isn't private logs `logging.folder_shared`;
  - on Windows the folder gets an owner, SYSTEM and Administrators ACL, inherited by its files (`integrations::secret::restrict_dir_acl`), since it holds the first-run setup token;
  - `file_folder` must be an absolute path, and its default is the absolute `<data>/logs`.
- **Rotation:** rotated files are pruned even when compressing one failed. The current file stops taking lines at the folder's total cap (`logging.over_cap`) until a rotation succeeds.
- **The panic hook** is safe inside `open_file` and `apply` too.
- **Unraid templates and the systemd unit no longer set `LODESTAR_LOG`.** Any set value makes verbosity, components and Libraries read-only in the app, and `config.rs` counts even an empty value as set, so the variable is left out rather than shipped empty. It still works when added.

**For B-log1b (recorded, not built here):**

- **No event logs the key, token, proxy and sign-in flows yet,** so the canary can't fail on them. Add positive controls (a line that must appear) when `api.request` and `auth.*` land.
- `auth.setup_token` is declared, but `services.rs` still logs the token as a plain line.
- **Remaining raw lines:** `api/src/auth.rs`, `pipeline/lib.rs:391` (filter notes), `pipeline/writer.rs:233` (a path) and `search/rebuild.rs`.
- **A hot-path bench and padding before the DHT and fetch sweep.** High-volume events stay `default_on: false` until B-log2's flood folding.
- **A test that every workspace crate is in `TARGETS`.**

## After the runner's review (round 2)

- **B7's suggestion builder is swept here** (a scope exception: B7 merged, and `crates/search/src/suggest/titles.rs` isn't in B-log1b's paths). Its two lines are now `search.suggest_titles_rebuilt` (a count) and `search.suggest_titles_failed` (the error's type only), in a new `lodestar-search` catalogue.
- **Windows log folder, matching Unix:**
  - only a folder Lodestar creates gets the owner, SYSTEM and Administrators ACL, applied with `icacls … /L` so a link is never followed to its target;
  - Lodestar records that it did this (`"restricted": true` in the folder's `index.json`), so the next start knows the folder is its own;
  - an existing folder's ACL is never changed (a chosen `D:\Downloads` keeps Users' access to its contents). It logs `logging.folder_shared`, and file logging stays on;
  - if icacls fails on a folder Lodestar just created, file logging stays off (fail closed). The reason is appended to `%SystemRoot%\Temp\lodestar-service.log`, the file M6-win's service and installer use, as well as going to the console. The line names no path.
- **M6-win's files join `NOT_YET_SWEPT`** (`windows/{ports,priority,service}.rs`): M6-win merged while this PR was open, `windows/**` isn't this slice's, and B-log1b sweeps it. `main` had no list before this PR, so this doesn't grow one. The service still installs its own subscriber, so its typed events take the no-sink fallback until B-log1b wires the runtime there.
- **`NOT_YET_SWEPT` can only shrink:** CI fetches the pull request's base branch and fails if the list names a file the base's copy doesn't (`log_lint.py --base`).
- **More ways round the CI check are refused:**
  - a macro through any path with a `tracing` segment (`crate::tracing::warn!` after `pub use tracing;`, `tracing::log::warn!`);
  - a `use` of `tracing` itself, or of its macros, `instrument`, `log` or `*`, in any `use` tree (`use {tracing::warn}`, `use ::{tracing as t}`, `use tracing::{self as t}`);
  - a dependency on the `log` crate, outside dev-dependencies.
- **URL userinfo** runs to the last `@` before the first `/` after an `@`, so a raw password holding `/` goes whole. An `@` in a path hides the host with it.
- **`scrub_text`** also handles quoted values (`password: "x"`, `{"x-api-key": "x"}`, `token='x'`), space around the separator (`token = x`), any whitespace after `Bearer`, and names containing `credential`.
- **U+2028 and U+2029 are escaped** in console text and JSON lines, and `Client`'s `Debug` hides the address.

**For the docs follow-up:** `docs/operations.md:26` and `packaging/docker/README.md:72` should say that setting `LODESTAR_LOG` makes those Logging settings read-only.

## After the runner's review (round 3)

- **A URL in free text isn't cut inside its userinfo:**
  - `scrub_text` first takes the userinfo off the run up to a hard stop (whitespace, `"`, `<`, `>` or a backtick);
  - only after the authority does it trim at the usual URL characters;
  - so a raw password holding `,`, `'` or `)` (`(https://u:p,w@host/x)`) goes whole.
- **An ambiguous userinfo shows nothing more:** when the userinfo's `@` comes after a `/`, `?` or `#`, the URL shows as `scheme://[redacted]` and nothing after it, rather than text that may not be the host. Examples: `https://u:pa/ss@host/x`, `https://registry.example/@scope/pkg`, `?q=a@b`.
- **"Just created" comes from the creation itself (Windows):** the parent is made with `create_dir_all`, then the folder with a non-recursive `create_dir`. `AlreadyExists` means an existing folder, so one planted in between is never restricted or marked.
- **B2c's `system/{address,restart}.rs` join `NOT_YET_SWEPT`** (21 lines), for the same reason as M6-win's files: B2c merged while this PR was open, and `system/**` is outside this slice's paths. B-log1b sweeps them, `app.restart` included.
- **B9's percolator is swept here** (a scope exception the runner asked for: B9 merged while this PR was open, nothing owns its files now, and they're new code, so they don't join `NOT_YET_SWEPT`).
  - `crates/lodestar/src/percolator.rs` now logs `alerts.search_unreadable`, `alerts.announce_failed`, `alerts.run`, `alerts.found`, `alerts.pruned`, `alerts.prune_failed`, `alerts.watermark_failed` and `alerts.run_failed`.
  - `crates/search/src/percolate.rs` now logs `search.percolate_search_failed`.
  - They carry saved-search ids, counts, a flag and error types only: never a query, a search's name, a torrent name or an error's text.
  - The run summary no longer lists alerts per search. Its test now matches the new lines, and still checks that no name or query appears.
- **The `log` dependency rule** also catches `log.workspace = true`, `log.version = …` and `"log" = …`.
- **`scrub_text`** also removes:
  - the credentials after `Authorization:` whatever the scheme (`token ghp_…`, `Digest …`);
  - quoted values that hold escaped quotes;
  - names containing `jwt`, `pw` or `cookie`;
  - values after a URL-encoded `%3D` or `%3A`.

**For B-log1b (recorded, not built here):**

- **A shared Windows helper for `%SystemRoot%\Temp\lodestar-service.log`.** It should open the file with `FILE_FLAG_OPEN_REPARSE_POINT` and refuse a reparse point, and both the log folder's `service_log` and M6-win's `log_refusal` should use it.
- **`log_lint.py --base` fails open** if `main`'s `NOT_YET_SWEPT` is ever rewritten in a form `listed_in` can't parse. It should fail closed instead.
- **`EXEMPT` additions aren't checked against the base** the way `NOT_YET_SWEPT` additions are.
