# RP-DEF decisions: rule packs on by default (PR to be numbered)

Owner §2.39 (packs on by default, reviewed in the setup wizard, opt-out), built as `docs/decisions/2026-11-04-X-legal-docs.md` fixes it ("`RP-DEF` owns" and "Existing installs are offered, not flipped"). Ships in v0.5.2. **Supersedes `docs/decisions/2026-10-31-S-wizard.md`** on the rule-pack step's "at least one pack on means a stored choice" rule and on "the wizard only turns packs on".

- **The fresh marker.** `lodestar_store::PACKS_FRESH_KEY` (`packs.fresh = 1`) is written by `schema::migrate` in the transaction of the first migration it applies to a store at schema version 0, the one that creates `settings`. No new table and no new migration: an existing store never gains the row, and a crash after that transaction (part-way through creating the store, or between create and seed) leaves the marker for the next start. `lodestar import` creates its store through the same `Store::open`, so an imported store served afterwards is seeded fresh.
- **Consumed by `upgrade::ensure_seeded`**, which `Pipeline::start` calls before the first filter read (`seed_packs` stays the fallback; `start_packs` plays no part). One transaction (`Store::apply_pack_defaults(true, …)`): an on row for every pack without a switch row, both applied-version rows at every rule's **current** version (`upgrade::current_record`, so nothing is pending), the RP-0 seeded marker, `packs.defaults = 1`, and the fresh marker deleted. A pack that already has a row keeps it: a row is a choice (only reachable when an earlier build wrote one over a fresh store, a downgrade in between; then the packs switched on record their rules as `set_pack_switch` does, merged per readable applied row).
- **An existing store** (no fresh marker, no `packs.defaults`) gets RP-0's version seeding as before, then one transaction (`apply_pack_defaults(false, …)`): an explicit off row for every pack without one, and `packs.defaults = 1`. Filtering is unchanged and nothing flips. `ensure_seeded` returns `Some` only when filtering changed (a fresh seeding or RP-0's seeding), so the API reloads its engine only then.
- **`load::pack_switches` keeps reading no row as off.** An Undo to a rule set from before RP-DEF (`replace_rule_set` deletes every switch row) returns to that set's off state; `packs.defaults` stays set, so nothing re-seeds. A pack a later build adds (RP-UC's `unauthorised-copy`) reads as off on any store seeded before it, until turned on.
- **No accept route or UI.** New rules in a pack already on stay in shadow (RP-0) until RP-3 and RP-6.
- **Wizard (§2.19 refinement, flagged to the owner).** The step shows each pack as the server has it: on a fresh install all five are on and checked. There is no "stored choice" rule any more; the explicit reviewed marker is the step's own `done` in the wizard's progress, as for every other step. Continue sends only what changed: a checked pack that is off (an existing install, offered with a line saying so) goes through `applyPacks` (preview → plain apply, which records its current versions); an unchecked pack that is on goes through the weakening flow **in the wizard**, in the Filters screen's own change dialog loaded through the flows' door: the server's effect warning, then the password set in `/setup`. We reuse that dialog rather than building a second password field, so the password handling, rate limit and focus rules stay in one place. A cancelled or refused turn-off leaves the pack on, says so, and keeps the step not done. Skip sends nothing. Per-rule opt-out stays in Settings → Filters & Safety, and the step says so.
- **Copy.** Wizard en/zh: the lead says packs are on by default and what turning one off asks for; `wizard_packs_stored` and `wizard_packs_on` are removed. Settings → Filters & Safety and `docs/user/` had no "off until chosen" sentence on `main`; chapter 1's list of facts gains one bullet saying packs are on by default on a new install.
- **Outside the brief's listed paths** (tests and fixtures of owned code): `crates/store/src/rules.rs` (`apply_pack_defaults`, the marker's one write path, beside RP-0's `seed_pack_versions`), `crates/filter/tests/pack_upgrade.rs` (its stores now model an install from before RP-DEF), the wizard's `PartTwo.test.ts`, `PackStep.door.test.ts`, `testing/server.ts` and `web/e2e/wizard.keyboard.test.ts`.
