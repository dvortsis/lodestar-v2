# B11c decisions (digest rendering and preview)

`GET /digest/preview` and the pure `digest::render` (architecture §10.9.7, §10.14, §20.9; `docs/metrics.md` §3, §6.2, §6.4, §7.8). No owner decision is reversed or loosened, no security or content-safety decision is weakened and no owner-set number changes; the refinements below are the runner's to flag (`docs/owner-decisions.md` §2.19).

## What it is

- **A renderer over the overview, nothing more.** `digest::digest(state, period)` is one `insights::overview_response` call (`24h` or `7d`, `compare=1`) and `render(&OverviewResponse, DigestPeriod, now) -> Digest`. Every count, rate, Δ, share and percentile is the server's own; movers come from `insights::segment_movers`. "Show adult content" is applied by the overview builder, so a hidden Adult never reaches a digest (counts only, never a name, as B11a's visibility notes say).
- **`generated_at` is the overview's `updated_at`,** so the context line's generation time and the numbers agree, and the renderer never reads a clock.
- **JSON only.** The HTML is never served as `text/html` from the app's origin. S-insights-3 shows it only in `<iframe sandbox srcdoc>` (no `allow-scripts`, no `allow-same-origin`) and the text in a `<pre>`.

## Escaping and links

- **One builder escapes by default.** `Html::text` escapes `&`, `<`, `>`, `"` and `'`; `Html::raw` takes only `&'static str`, so a string built at run time can't reach the output unescaped. Attribute values are `text()` of a link path the module built from constants and a validated `target`.
- **Untrusted strings are cleaned before they are printed** (segment keys, exception kinds, a health reason, a loss reason not in the table): C0/C1 controls, DEL, bidi formatting characters (U+061C, U+200E/F, U+202A–E, U+2066–9) and also U+2028/2029 are removed (a **refinement**: the brief lists the first two groups; line separators would break a plain-text line the same way), then the string is cut to 64 characters with `…`. A string that cleans to nothing prints `(blank)`.
- **A link needs `^[a-z_]{1,32}$` as its target** and a known fix kind (`stage`, `settings`); anything else has no link and no path in the text.
- **No `<style>` and no colour.** The only inline style is `text-align:right` on number cells.

## Text and limits

- **Text ≤ 4,000 bytes** (ntfy's message and Discord's description are 4,096). Fields are cut at 64 characters and the lines are fixed, so only the exceptions can grow; if they would not fit, the last ones are replaced by "And N more in Insights." The HTML (≤ 96 KiB, the email part) has no such cap in practice and drops its exceptions only if it ever exceeded the limit. Subject ≤ 120 characters (ntfy's title is 120).
- **Formatters** are private Rust copies of `formatCount`, `formatPercent` (f = 0 and 1, with the `<`/`>` edges), `formatDelta` (count, percent f = 1, and seconds in `formatSpan`'s unit), `formatSpan` and `formatDate`, plus `formatDateTime` for the context line (a **sixth**: the period needs hours, and §3's table has the `en` example). Each reproduces §3's `en` examples and the web client's own rows (tests).
- **Dates and times are UTC,** the server having no time-zone database. The user's `preferences.time_zone` comes with the sender follow-up.

## Wording (§10.14, `docs/ui-glossary.md`)

- **Labels** are §6.2's (Searchable torrents, New searchable, Yield, Time to searchable, Health) and the glossary's (`searchable`, `harvested`, `yield`, `incomplete`). Loss reasons use plain names ("No peers", "Timed out", "Too large", …); the glossary has none yet, so these are this slice's.
- **Each known exception kind has one fixed sentence** (`index_lag`, `cohort_stalled`, `yield_below_baseline`); an unknown kind gets "Needs attention: <kind>" with its value when the unit is one the module knows (`s`, `torrents`, `ratio`).
- **Severity is a word** ("Warning", "Error"), never colour.

## Left to the sender follow-up (not here)

`NotificationKind::Digest`; absolute links from a configured public address; the user's time zone and the 03:00 local schedule; "Show adult content" read at send time; an HTML part (the email channel builds its own HTML from `Notification.body` today); the settings section (S-settings-2) and B9's channel bits; and the zh catalogue (no server-side message catalogue exists).
