# WK-18 decisions

How each template follows owner decision wkq2 (§2.47): `LODESTAR_TOKEN` is accepted for the first join only, is ignored afterwards with a warning, and is never logged. The token is single-use, name-bound and valid for 15 minutes. `crates/lodestar/src/cli/worker.rs` already does this; the templates only match it.

- **Compose (`packaging/docker/compose.worker.yml`).**
  - Sets `LODESTAR_JOIN` and `LODESTAR_TOKEN`, with a comment to remove the token after "joined".
  - Shows `--token-file` commented out as the alternative. It replaces `command:` (not adds a second one), and a token file always tries to join, so the comment says to restore `command: ["worker"]` and delete the file after the first join. It says to chown the file to the container user.
  - Disables the image health check (it asks a web UI a worker doesn't have); the Unraid template passes `--no-healthcheck` for the same reason.
  - Publishes only the DHT port, as host `6882/udp` to container `6881`, so a worker can share a machine with the main Lodestar. There is no cluster port and no web UI.
  - There is no separate spool setting: the spool is the `spool/` folder inside `/data`, so one volume covers both.
  - No other secrets.
- **Unraid (`lodestar-worker.xml`).** The token field stays masked and now reads "First start only, remove after". It is `Required="false"` because the user clears it after the first start, and a required field would force them to refill it. The Overview still says "Requires Lodestar v0.6" as the validator wants.
- **Placeholders only.** The examples use an obvious placeholder token and a private example address.
- **WiX moves to a follow-up slice, WK-18w (runner's call).** Three findings from the brief's step 3:
  - `--token-file` always joins and the CLI never deletes the file (`read_join_token_file` only opens it). A service started with it would try to join on every start, so deleting the file and dropping the flag can't be left to the CLI.
  - The WiX source is in `packaging/windows/` (`main.wxs` and the `.ps1` helpers), not `packaging/wix/`.
  - A "Join an existing Lodestar" mode changes `main.wxs`'s features, UI and service, which is more than one include line.
- **Design for WK-18w.**
  1. A one-shot custom action, run as SYSTEM, writes the token to a file only SYSTEM and Administrators can read.
  2. It runs `lodestar worker --join <url> --token-file <file>` once.
  3. It deletes the token file, on success or failure, since the token is single-use.
  4. It installs the service as plain `lodestar worker`, with no token on the command line or in the service's environment.
  It needs Windows CI to build and test, so it isn't built here.
