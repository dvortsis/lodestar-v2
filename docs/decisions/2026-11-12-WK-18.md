# WK-18 decisions

How each template follows owner decision wkq2 (§2.47): `LODESTAR_TOKEN` is accepted for the first join only, is ignored afterwards with a warning, and is never logged. The token is single-use, name-bound and valid for 15 minutes. `crates/lodestar/src/cli/worker.rs` already does this; the templates only match it.

- **Compose (`packaging/docker/compose.worker.yml`).**
  - Sets `LODESTAR_JOIN` and `LODESTAR_TOKEN`, with a comment to remove the token after "joined".
  - Shows `--token-file` commented out as the alternative. A token file always tries to join, so the comment says to remove both the file and the `command:` after the first join.
  - Publishes only the DHT port, as host `6882/udp` to container `6881`, so a worker can share a machine with the main Lodestar. There is no cluster port and no web UI.
  - There is no separate spool setting: the spool is the `spool/` folder inside `/data`, so one volume covers both.
  - No other secrets.
- **Unraid (`lodestar-worker.xml`).** The token field stays masked and now reads "First start only, remove after". It is `Required="false"` because the user clears it after the first start, and a required field would force them to refill it. The Overview still says "Requires Lodestar v0.6" as the validator wants.
- **Placeholders only.** The examples use an obvious placeholder token and a private example address.
- **WiX: not in this PR** (pending the runner's answer). The CLI doesn't delete a token file, so the "file deleted after the first join" step needs a custom action outside the CLI that can't be built or tested here.
