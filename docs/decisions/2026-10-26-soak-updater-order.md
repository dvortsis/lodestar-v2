# Updater persistence ordering decisions (local slice)

- **Serialize mutation through persistence.** Keep the engine's updater mutex held through `Bin::write`, including its rename/fsync sequence. A check completion can no longer persist a pre-pause clone after a successful pause save, and these writes cannot collide on the shared temporary filename. This refines architecture §12.2 without changing update trust, policy or installer scope.
- **Preserve best-effort persistence semantics.** Memory remains the source of truth during the process lifetime. A filesystem error still leaves the state effective in memory but potentially lost at restart; this change does not claim durable success after failed I/O. Disk writes were already synchronous; readers now wait for a state write to finish. No mutex is held across an await.
- **Exercise the ordering boundary.** A private persistence callback permits a regression to hold an old check save immediately before disk I/O, verify mutation exclusion, start a competing pause and then release the writer. The test checks the file, memory and reopened engine, plus later check and pause-clear saves. Channel waits have ten-second deadlines and use no fixed sleeps.
- **Unix execution is required.** This engine is Unix-only; formatting it on Windows is not compilation or a runtime concurrency test. Run the new regression and the full updater engine tests on Linux after actual collector completion.
