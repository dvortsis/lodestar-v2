# X-sec-S6-02-03 decisions (part 2a: worker pauses)

This is the fix for held finding S6-08 (important; surface M8-SEC-6, the cluster), and it closes the part of S6-02 that concerns pauses. The detail is held under `docs/security/v1/README.md` §5, so this file says only what the code now does. Part 1 is `2026-11-14-X-sec-S6-02-03.md`.

## Architecture §19.6, WK-14 and WK-10d

- **The sweep forgets a worker only when none of its certificates stands.**
  - While a renewed certificate stands, a session whose own certificate lapsed is ended with `Shutdown`, so the worker reconnects with the renewed one.
  - The worker's state (a pause or drain included) and its leases are kept, and its reconnect lists the leases.
  - Once no certificate is left on record unrevoked and unexpired, the worker's leases are taken back and it's forgotten, as before (`CoordinatorTls::worker_stands`).
- **Every session start asks whether its worker is paused.**
  - `Workers` gives the cluster a pause source when it opens (`ClusterHandle::set_pause_source`).
  - The cluster installs it on the server serving now, and on every server it starts, before that server serves anyone.
  - A session starts paused if the source says so, whatever the server remembered.
  - The source is read before the fleet lock, because it takes locks of its own.
  - If an admin's resume lands between that read and the session taking the fleet lock, the session starts paused. It errs on the safe side; the next session or another resume clears it.
- **A new server's saved pauses fail closed.**
  - A row that doesn't parse is read as paused (`Saved::maybe_paused`). The one exception is JSON that says `"paused": false`.
  - A store whose rows can't be read stops the server from starting (`StartError`, step `pauses`). It's never read as "nobody paused".
- **Pauses that aren't saved rows still apply everywhere.**
  - **Held in memory only:** a row `Workers` can't read, or a paused row the planner has no room for. The row itself is left untouched, so its settings survive a downgrade and upgrade.
  - **Retried:** a floor-budget pause whose save failed. The follower saves it again, at most every 5 s, until it lands.
  - Both kinds are applied to every server and every session like saved pauses. An admin's resume or revoke ends either.
- **Supersedes:** in `2026-11-08-WK-10d.md`, a failed floor-pause save no longer lasts only "until a restart". It's retried as above.
