# G-m5b decisions: the M5 design-review pass (PR pending)

Part 2 of the M5 exit gate (architecture §10.17, §14 M5 row). The report is `docs/review/2026-11-01-m5-design-review.md`, with its screenshots in `docs/review/m5-shots/`.

- **Result: 7 blocking, 10 important, 11 polish.** B4 (the `/logs` heading used `text-h2`, which isn't a token) and P1 (About's "Stable· Released") are fixed in this PR as one-line changes with no effect outside their own screen. B1–B3 and B5–B7 gate M5 and go to fix batches FX-1 to FX-4. The other findings go to FX-5 and FX-6 (and the non-blocking parts of FX-1 to FX-4).
- **How the review ran: re-use the suite instead of new mocks.** A local-only Playwright config re-ran the existing route, states, smoke and keyboard specs against the OpenAPI mock. A temporary auto fixture screenshotted each test's final state and measured it: page overflow, elements past the viewport, clipped text, and targets under 24 px (44 px in a touch-emulation pass). That's 2,110 captures, plus 80 under touch emulation, plus the committed smoke and states baselines. Projects: 360, 1024 and 1920 (dark) on every route spec; 1920 light, 360 dark, 1024 dark, `rosewood-light`, `dracula-dark`, Compact and reduced motion on smoke, states and the table, bulk and Insights specs. Neither the fixture nor the config is committed: the brief asks for the report and its screenshots only, and the harness's own snapshot policy keeps the repository small.
- **Severity follows the brief strictly.** Breaking a §10 rule is blocking even when the fix is small. That covers the §10.19 illustration layout (B2), the §10.10.1 save model for Preferences (B3), the token contract (B4), the §10.2 touch-target rule (B5), and the glossary, a contract doc (B6: raw enum values as labels, one of them contradicted by help text; B7: "hashes" and "peers" where the glossary bans them). Decisions on record that differ from §10 are listed in the report as recorded deviations, not findings: the Insights narrow order at every width (`2026-10-23-S-insights-1.md`), the Search empty state loading after first interaction, and Compare's hand-written empty state.
- **B3 supersedes an interim note.** `2026-10-23-S-keys.md` kept Save/Cancel on the Keyboard screen "because the settings form isn't on `main`". It is now (`2026-10-30-S-settings-reconcile.md`), so §10.10.1's instant-apply-with-Undo rule applies to Keyboard like the other Preferences screens. FX-3 (Opus) implements it.
- **Fix the primitives, don't add new ones.** B2 goes to `lib/ui/feedback/EmptyState.svelte`, which Alerts, Discover and Logs already use. It gets the §10.19 ranges and copy-first DOM order, and an `{#if}` per heading level instead of `<svelte:element>`, so Compare, which `2026-10-23-S-compare.md` kept off it for that reason, can use it again. B1 goes to `lib/ui/overlays/Popover.svelte` (viewport cap and collision padding), not to the Syntax popover alone.
- **The Connecting glyph (I2) refines `2026-10-30-F-status.md`.** That file chose dots for `connecting`, and it collides with the overflow menu's glyph beside it. FX-5 changes it; the runner flags this as a refinement to the owner (owner-decisions §2.19).

B5's global coarse-pointer rule is FX-2's (app stylesheet, scoped to standalone controls so links inside text are untouched). Each other batch deletes the feature-level copy in its own files once FX-2 has merged; the report lists which batch removes which.
