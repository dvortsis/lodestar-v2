# S-updates-5: the Roll back dialog follows `rollback.restores_store`

Code: `web/src/lib/features/settings/updates/**`.

- The confirm dialog's text follows `rollback.restores_store` (B-update-6, #330):
  - `true`: the app restarts on the previous version, data returns to its state from before the update, and changes since are lost. The torrent count sentence is shown only in this case.
  - `false`: the app restarts on the previous version; data and settings stay as they are. No loss is claimed, so no count is shown.
  - absent or `null` (the check didn't run): the app restarts on the previous version, with no claim about data and no count.
- The field never shows or hides the Roll back button; `rollback.available` alone does.
- If an `updates` event refreshes the status while the dialog is open and the field changes, the dialog is closed unanswered and asked again with the new text (the shared dialog takes fixed text). Confirm still sends only `{confirm: true}`; Cancel and Esc send nothing.
- Replaces the S-updates-4 hedged sentence ("if the update changed how data is stored…"). en and zh. No server, API or schema file changed.
