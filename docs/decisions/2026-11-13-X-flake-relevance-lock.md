# X-flake-relevance-lock decisions (#826)

- **Cause: copying the shared fixture while another test runs the tool on it.** `bench/tests/relevance_sets.rs` shared one data directory between tests. Some tests ran `relevance --data-dir` on it while others copied it (`copy_of`, through `std::fs::copy`). On Windows `fs::copy` is `CopyFileExW`, which opens each source file without write sharing (long observed, though Microsoft doesn't document it). Opening a tantivy reader opens `.tantivy-meta.lock` for writing, in `index/v…/` and in its `files/` sub-index (`MmapDirectory::acquire_lock`, then a blocking `LockFileEx`). If the copy has the file open at that moment, the open fails with os error 32 (`ERROR_SHARING_VIOLATION`). `MmapDirectory` returns that open error at once as `LockError::IoError`, with no retry; only contention for the lock itself waits. That gives "Failed to acquire Lockfile … os error 32" (#824, `test (windows-latest)`). Linux and macOS have no share modes, so they never show it.
- **Not the cause: two tool runs at once.** Two `relevance` processes on the same directory don't conflict. Both open the lock file with Rust's default share mode (read, write and delete), and the second one's blocking `LockFileEx` waits for the first instead of failing. So the first reading ("concurrent tool processes") was wrong about who conflicts. Serialising only the tool runs wouldn't have fixed it.
- **Fix: the tool never runs on the shared directory.** `fixture()` now builds a pristine directory that is only ever copied. Every test runs the tool on its own `copy_of` it. Copies taken at the same time only read the files, so they share fine. Every test and every assertion is kept, and nothing waits or sleeps.
- **The tool is unchanged.** A real user could hit the same error by copying a data directory while scoring it on Windows. The fix there is a retry with a deadline around `SearchIndex::open` in `bench/src/bin/relevance/data_dir.rs`. It isn't made here because no user path calls for it yet. It's offered to the runner as a follow-up.
