# B2c decisions (/system, restart, HTTP-address timer, licences)

`GET /system`, `POST /system/restart`, the HTTP-address keep-or-revert timer and the generated licence inventory (architecture §10.10.6, §10.10.9, §10.10.13; owner's decision §2.12). No owner decision is reversed or loosened. Items marked **(§2.19)** refine an owner decision and are for the runner to flag.

## /system

- **Reached through a `SystemApi` trait as an `Extension`,** layered in `Services::run` beside the event hub, not an `ApiState` field. That field would touch every test's `ApiState` literal, which four open PRs are changing. Without the extension, every route answers `503 system_unavailable`.
- **One request feeds About, the Overview and General.** The update status isn't in it: About reads the update engine's signed check (§12.2, B-update).
- **Null, never 0, for anything not measured:**
  - memory (Linux `MemTotal`, or a cgroup v2 limit when lower) and free space (`rustix::fs::statvfs`) are null on Windows until M6;
  - `cold_bytes` and `logs_bytes` are null until `<data>/cold` or `<data>/logs` exists;
  - `integrations` is null until download clients and channels are stored; `updates` until B-update; `companions` and `workers` until v0.6.
- **Connections give counts and states, never URLs.** The DHT is on, paused or off. Sources are counted without the DHT, and blocklist subscriptions with the last check. Each row names the Settings screen it links to.
- **`diagnostics.changed`** lists every field whose source isn't `default`, as `section.field` with its source and no value. `logging` and `recent_errors` are null until B-log1.
- **`restart_required`** joins each section's `restart_required` as `section.field`.
- **Directory sizes** are measured on the blocking pool and cached for 60 s. The database's size counts `-wal` and `-shm`.
- **The store schema** is read on the API's read-only connection (`max(version)` of `schema_migrations`). `cli::util::schema_version` is private to `cli`, which this slice doesn't own.
- **`fixture`** is true while serving `lodestar serve --fixture`, from B16's `fixture::active()` (the one accessor added beside `OFFLINE`).

## Build info

- **`build.rs` sets `LODESTAR_BUILD_*` for `env!`,** with empty meaning unknown:
  - the commit from `LODESTAR_COMMIT`, else `git rev-parse HEAD`;
  - the date from `SOURCE_DATE_EPOCH`, else the commit's date, never the time of the build;
  - the channel from `LODESTAR_CHANNEL`, `dev` by default (an unknown value builds as `dev` with a warning);
  - the target and `rustc -V`.
- **Git is only asked** when the checkout itself has `.git` (a directory, or a worktree's file, whose git directory is then watched), so a source tree unpacked inside another repository never reports that repository's commit.
- **`LODESTAR_COMMIT` must be a 7 to 40 character hex hash** before it's passed to `git log` or embedded; anything else is ignored with a build warning.
- **It reruns only** when those variables change, or git's `HEAD`, `packed-refs`, `refs/heads` or `refs/tags` changes. Each is watched only if it exists, because a missing path would rerun the script on every build.
- **`ui_build_id` is read from the bundle's `_app/version.json` in `build.rs`,** the same file `web.rs` embeds. `web.rs`'s asset table is private to it, and a second `include!` would embed the UI twice.
- **Follow-ups:**
  - P-release (#92) sets `LODESTAR_COMMIT`, `LODESTAR_CHANNEL` and `SOURCE_DATE_EPOCH` in `release.yml`;
  - the Docker packaging passes them through, and sets `LODESTAR_DEPLOYMENT`, `LODESTAR_IMAGE_TAG` and `LODESTAR_IMAGE_DIGEST`. The Dockerfile isn't changed here.

## Deployment

- **`LODESTAR_DEPLOYMENT` wins:** `docker`, `unraid`, `windows_service`, `windows_portable`, `systemd` or `tarball`. Otherwise Lodestar detects it: Docker by `/.dockerenv` or `/proc/1/cgroup`, systemd by `INVOCATION_ID`, else `tarball` on Linux and `unknown` elsewhere.
- **The image tag and digest** come from `LODESTAR_IMAGE_TAG` and `LODESTAR_IMAGE_DIGEST`, reported only under Docker or Unraid.
- **These variables aren't settings,** so they stay out of `config::ENV_VARS`, like B12's `LODESTAR_PROXY_AUTH`.
- **Follow-ups that set the hint:** Unraid's template, the MSI (`windows_service`) and the portable zip (`windows_portable`).

## Restart

- **It answers first.** `POST /system/restart` (session, same-origin JSON) returns `202 {"estimated_seconds", "restarting": true}`. The restart is requested when the response body is dropped: after hyper has written it, or when the client went away first.
- **`estimated_seconds`** is this run's measured time from the start of `Services::start` (which every entry point runs, M6-win's service included, so `started_at` is right there too) to the listener binding, rounded up, at least 1. Before that's measured it's 5.
- **`main.rs`'s `serve` races the stop signals with `Restart::requested()`.** Both take the same graceful shutdown. A signal wins, even one arriving during a restart's shutdown, so `docker stop` is never answered by a re-exec.
- **Unix: `reexec`.** It calls `CommandExt::exec` on `current_exe()` with the same arguments, in safe std. The PID is kept, so PID 1 survives, and descriptors close on exec. If the exec fails, `serve` returns an error and the process exits non-zero, so the restart policy takes over. Logs are written synchronously today; B-log1's file sink flushes there once it lands.
- **`estimated_seconds` leaves out the graceful shutdown** (final commit, DHT state), so the dialog's "about N seconds" is a lower bound.
- **After an in-place upgrade** Linux names the running binary `<path> (deleted)`. The re-exec then runs what's installed at `<path>`, or `/proc/self/exe` (the running image) if nothing is there.
- **The re-exec runs as the user PUID/PGID dropped to,** so the binary and any `--config` file must be readable by that user. The image's are.
- **A temporary fixture** (`lodestar serve --fixture` without a folder) can't restart: its folder, with `auth.json` and `seal.key`, is deleted when the process ends, and a re-exec would build a new fixture with a new key and token. `restart.available` is false there, and the hint says why.
- **Windows: `available: false`, `method: "manual"`,** with a hint. Asking anyway gets `409 restart_unavailable`. M6 must wire:
  - **As a service:** M6-win's `windows/service.rs` `serve()` races `system::Restart::global().requested()` with its stop channel. It then stops with a service-specific exit code (1, or a dedicated code M6 picks), so the SCM recovery action the MSI configures (`FailureActionsOnNonCrashFailures`, #92/#98) starts it again. Then it reports `method: "service"`, `available: true`.
  - **Portable:** after the graceful shutdown, start a new copy with the same arguments, then exit. The new copy retries the data-directory lock for a few seconds.
  - **B-update's supervisor** (§12.2) may replace the re-exec with a supervised relaunch. It keeps `requested()` and the method enum.

## The HTTP-address keep-or-revert timer

- **A `Record { kind, previous, new, state, deadline }`** is stored as JSON at `system.keep_or_revert.<kind>` in the store's settings table. That's outside `settings.`, so the registry never reads it and no migration is needed. `previous` is `"reset"` when nothing was saved, else `{"saved": value}`. Only `http_bind` is wired.
- **Recorded on save.** A follower on the registry's `network` section compares the address and its source with what it last saw.
  - A change writes `awaiting_restart`.
  - A second change keeps the original `previous`, the address that worked.
  - A change back to `previous` drops the record.
  - An address set by `LODESTAR_HTTP_BIND` is read-only, so it never arms the timer. A record already pending is left untouched while the variable is set, so a user who recovered with it and later removes it gets the timer back for the bad saved address, instead of binding it with none.
- **Armed at start, before the registry loads** (`system::address::prepare`, one line in `Services::start`).
  - If the effective bind is the pending one, Lodestar binds it at once. Then `bind` (which replaces the bind line) stores `awaiting_confirmation` with a deadline 5 minutes after the listener binds.
  - The stored deadline survives a restart or a crash, but is never more than 5 minutes away at start: a deadline stored under a clock that has since gone back (no RTC, or a local-time RTC put right by NTP) would otherwise sit hours or years ahead.
  - A record whose address was changed outside the app (`lodestar settings set`) is dropped.
- **Kept** by `POST /system/address/keep` (session, same-origin). Any request that reaches this process came in on the new bind, whatever its `Host` says. B12's proxy sessions count once B12 merges, because the guard decides.
- **`POST /system/address/revert`:**
  - awaiting confirmation, it saves `previous` and restarts once the answer is out;
  - awaiting the restart, it just undoes the save.
- **Reverted when the deadline passes.** `previous` is saved back through the registry (`null` for `reset`), the `settings` event goes out, it's logged at WARN, and the process restarts. `/system`'s `address_change` shows `reverted` with both URLs for the rest of the run.
- **Generic over what it reverts:** a later kind only adds its `Kind` and how its revert applies.
- **(§2.19) Revert on bind failure.** A pending address that fails to bind reverts at once and binds `previous`, so a mistyped address can't crash-loop a container.
- **(§2.19) A deadline already past at start reverts before binding.** Both start-time reverts save through a registry loaded only for that, before the server's own loads. So the running values match the bound address, and nothing is reported as waiting for a restart. If that save fails, the record stays (the next start tries again) and this run binds `previous` anyway.
- **(§2.19) Where the server can't restart itself** (Windows until M6), an expired timer still saves `previous`. It applies only at the next restart, and `/system` shows `reverted` with `network.http_bind` in `restart_required`. M6's service restart closes that gap.
- **A revert is due by either clock:** the stored wall-clock deadline, or the window measured on the monotonic clock from when this run armed it. A wall clock that goes back can't hold a revert off, and one that jumps ahead (or a suspend) is noticed within 30 s, since the timer never sleeps longer.
- **A record that can't be stored** is logged at ERROR, and `/system`'s `address_change.stored` is false: the protection then lasts only until the process ends. Keep fails (500) rather than leave a stored record that would revert the kept address at the next start. Writing the record in the settings save's own transaction would need a registry change, which `settings/**` (not this slice's) would have to make.
- **If the start-time revert can't be saved,** the record notes the address served instead (`serving`), and `lodestar healthcheck` probes that one, as the "UI on …" log line names the address actually bound.
- **A second instance started by mistake** runs `prepare` before it fails on the index lock, and can act on the record. That's an edge case, left for the instance-lock work.
- **If a revert's save fails at expiry,** the timer tries again every minute. Where the server can restart, it restarts, so the start-time revert takes over.
- **Interaction with B12's proxy auth (carry-forward b):** not wired, because a proxy change can't lock out a cookie session today (#112's decisions). When a proxy-only mode lands (M-security-settings or a B12 follow-up), it adds a kind:
  - take `Auth::proxy()` before `PUT /auth/proxy` applies;
  - on expiry call `Auth::set_proxy(previous)`, with no password, since the user already confirmed.

  `LODESTAR_PROXY_AUTH=off` stays the recovery that needs no UI.

## Crawler saves publish `settings` (carry-forward a)

- **`POST /crawler/pause`, `/crawler/resume` and `PATCH /crawler`** save through `settings::save_and_announce` (now `pub(crate)`) with a one-section batch. They publish `{section: "crawler", revision}` when the section changed. A no-op pause changes nothing, so it publishes nothing.
- **Refusals map to the same `ApiError`** as before (`SettingsFailure.error`), so the `ops_crawler_*` goldens are byte-identical.

## Licences (`web/licenses/`)

- **Rust:** `.github/scripts/licenses.py` runs `cargo metadata --locked --filter-platform <t> --no-default-features --features lodestar/web` for `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl` and `x86_64-pc-windows-msvc`. The list is kept in sync with `release.yml` (#92) by a comment. It walks normal dependency edges from `lodestar` and writes `rust.json`: name, version, SPDX expression, repository, targets, and licence texts deduplicated by SHA-256. `--check` fails on drift and on the allowlist. The `openapi` job runs it with its tests.
- **npm:** a Vite plugin (`web/scripts/licenses.ts`) takes the client build's Rollup module graph, reads licences from `package-lock.json` and texts from each package, merges `rust.json` and `overrides.json`, and fails the build on a disallowed or missing licence.
  - It emits `licenses-<sha256:12>.json`.
  - It exports the file's URL from `virtual:licenses` for S-about.
  - Dev serves the same document.
  - First-load size is unchanged, because nothing imports it yet.
- **`allow.json`** is exactly §2.12's list. Its `refused` list only changes the wording of the error: anything not allowed fails.
- **(§2.19) Proc-macros count as shipped** (`proc_macro: true`): they generate shipped code.
- **(§2.19) The overrides file is `web/licenses/overrides.json`,** not §10.10.13's `licenses.overrides.json`, because the Docker web stage copies only `web/`. Besides `missing` and `extra`, it has:
  - `texts`: a crate borrowing its repository's licence text (eight tantivy sub-crates);
  - `notices`: the files copied in, which are `LICENSE` and `brand/LICENSE.md`.

  A `missing` entry is pinned to a version, so a bump fails until it's reviewed again.

- **(§2.19) A shipped component with no licence text is an error,** unless a reviewed file under `web/licenses/texts/` supplies one through a version-pinned `texts` entry (`file`), because §10.10.13 promises each component's full text. Two need one:
  - `htmlescape` ships no text, so its MIT branch is used, with the holder from its `authors`;
  - `@iconify-json/ph` (Phosphor) ships no LICENSE, so the text is MIT with "Phosphor Icons" and no year, since the package states none.
- **(§2.19) Lodestar's own crates** are left out of the third-party list. They're shown as Lodestar's own, under AGPL-3.0-or-later, and still checked.
- **(§2.19) `cargo metadata` resolves features for the whole workspace,** so the list is a little wider than what ships: 5 extra crates against `cargo tree -e normal`. Listing too much is the safe side.
- **No licence outside the allowlist was met** on any shipped target. Some crates pass only through an allowed `OR` branch, for example `Unlicense OR MIT`. `Apache-2.0 WITH LLVM-exception` passes through its base. `htmlescape` ships no licence text anywhere; it gets a reviewed text (above).
- **Only regular files inside a package's folder are read** as licence texts. A `license-file` that leaves the folder (`..`, an absolute path) or goes through a symlink is refused and reported, so a crafted crate or package can't copy another file (a registry token, say) into the public inventory.
- **A `WITH` exception on the refused list fails,** even when its base is allowed (`Apache-2.0 WITH Commons-Clause`); an allowed `OR` branch still passes.
- **Every reviewed override is pinned to a version:** `missing` entries and every `texts` entry, the tantivy ones included. Only the donor a `from` names is unpinned. An `extra` whose package drops its licence field is flagged.
- **Repository links are http(s) only;** anything else is written as `""`. npm's `owner/repo` and `github:owner/repo` shorthands become GitHub URLs.
- **`rust.json` is regenerated** whenever `Cargo.lock` changes. `RUST_ALSO` also matches `web/licenses/`, the script and its fixtures, `LICENSE` and `brand/LICENSE.md` (both embedded), so CI runs the check when any of them changes.
