## Safety and correctness
- **Singleton fencing by assignment epoch.** The token-lease TTL is a relative duration on the worker's monotonic clock, shorter than the heartbeat timeout minus one beat. So a cut-off worker stops sending before its replacement starts.
  - The fleet cap holds anyway, because every token comes from one bucket.
  - Nothing remote runs before PL-2: PL-4 and G-v08 depend on it.
  - Remote placement stays off (`cluster.remote_sources`) until G-v08 passes (Q-r8).
- **The coordinator trusts nothing in a worker's `Finds`** beyond its active assignment and epoch:
  - the source id and the private flag come from the assignment;
  - batches from quarantined, purged or revoked workers are refused;
  - credentials in `Assign` are redacted and zeroized.
- **Purge-by-worker covers a plugin's finds** (runner's call: §19.4 requires the purge, so stating the limit isn't enough).
  - **One migration, PL-8:** `find_worker`, with rows only for remote finds. The last writer wins, as it does for claims, and the table holds no names.
  - This is the smallest change that lets purge tell a worker's claims from the same source's claims written elsewhere.
- **Worker RSS** (owner §1.6.5, runner review I2). §5.5 shows the budget:
  - plugins and companions add at most 27 MiB, and the pool cap drops by 10,000 keys while they're assigned;
  - the totals are 226.5 MiB steady and 251.5 MiB during a filter swap at 10M stored;
  - a worker's response-body slot is 8 MiB, against 16 MiB on the coordinator, so a plugin that needs more stays on the coordinator;
  - G-v08 re-runs WK-G's `worker_rss` bench with plugins and companions assigned.
- **Prowlarr's units spread only over workers that host its companion** (runner review I8): PL-3 and CW-1.
- **Credentials on workers** (Q-r6, a stricter refinement of §19.5's "sealed per worker"):
  - account credentials from the coordinator are held in memory only;
  - companion credentials made on a worker stay in CW-3's sealed on-disk file, which is its own Opus slice because it's an on-disk format.
- **External's endpoint acknowledgement counts per worker** (Q-r10). That's stricter than §19.5, which names only Restricted and Overlay.
- **Third-party adult claims go to the owner as Q-o4** (runner's call: content safety).
  - **Recommended:** hide only, pending local detection; never the CS-5 child-safety path or tombstones; never a mainstream title on its own (§1.8.12); never a torrent another source found.
  - **Residual risk:** anyone with a free key can hide an unverified release.
  - ADH-0 waits on `ext:owner-v08-q4` and on WK-7 and WK-9, whose pipeline files it shares. If the answer is no, ADH-0 is dropped.
  - Today it would have no effect: only Sukebei emits `content-type:adult`, and Sukebei is always-adult already.

## Protocols
- **Lemmy is pulled, not pushed** (Q-r1). ActivityPub push needs a public inbox, and the UI/API port stays LAN-private (§19.2).
  - Because Lemmy then contacts a third party, its consent class moves from None (§18.7) to **External**, which is stricter.
  - **The cursor** is the newest local post id, never `published`, with bounded paging.
- **Nostr events are verified:** the id is recomputed from NIP-01's canonical form, the BIP-340 signature is checked, and failures are dropped (Q-r2).
  - **New dependency** `k256` (`schnorr` only, pure Rust), approved in NOS-1's brief. `sha2 =0.11.0` is added to `crates/sources-feeds` in NOS-0; it's already in the lockfile.
  - **The `since` cursor is clamped** against future-dated events and overlapped, with dedupe by event id.
- **NOS-3 is Opus, not P6's [S]:** it manages up to eight relay connections at once.
- **The transport is split.**
  - **NOS-2a:** a routed, guarded TCP connect with an in-house SOCKS5 handshake in `integrations::net`. It's a shared prerequisite of P-v07's IRC-0, and lands early and inactive (runner's call, Q-r15).
  - **NOS-2b:** the WebSocket client.
- **Narrower options where the plan is silent:** no NIP-09 deletions (Q-r3), no keys from `.torrent` links in Lemmy posts (Q-r12), Lemmy API v3 only (checked by path and shape, not by software version).
- **No remote companion installs** from the coordinator (Q-r13): a runner's call, flagged to the owner (§2.19).
