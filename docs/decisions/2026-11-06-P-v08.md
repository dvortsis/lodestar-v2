# P-v08 decisions (plan the v0.8 epic)

Planning slice P-v08 (runner brief, 2026-11-05T23:55Z). It slices `E-v08` (build-plan P6) in `docs/plan/2026-11-06-v08.md`. Docs only. Every choice below is the planner's recommendation; the runner accepts or changes it when it adds the slices to `runner/slices.yaml`. Questions for the owner are listed, not decided.

- **Two tracks.** Placement on workers (PL-*, CW-*) depends on `E-v06-workers` and `E-v06-companions`. Nostr, Lemmy and the adult-claim change (NOS-*, LEM-*, ADH-0) touch none of their files and can start once the soak verdict holds (plan Q-r5). So v0.8's length is set by the v0.6 epics, not by the protocols.
- **Sibling plans not landed.** Neither `docs/plan/2026-11-06-v06-workers.md` nor `docs/plan/2026-11-06-v06-companions.md` was on `main` at 2026-11-06T00:00Z. The plan names ten interface points (§3, I1–I10) and marks the affected paths provisional. The runner reconciles them when the siblings land.
- **One protocol bump.** PL-0 fixes every v0.8 wire shape (plugin assignments with an epoch, `Finds` with state writes in the same batch, token leases, companion health), so later slices don't share `proto.rs`. Reason: parallel slices with disjoint owns.
- **Singleton fencing by assignment epoch,** and **token-lease TTL on the worker's monotonic clock, shorter than the heartbeat timeout minus one beat** (15 s timeout today). A cut-off instance stops sending before its replacement starts, and its late finds are dropped. Nothing remote runs before PL-2: PL-4 and G-v08 depend on it, and remote placement stays off until the gate. Reason: §19.8 failover within one heartbeat timeout without doubling a source's rate (§19.5).
- **Remote placement off by default** (`cluster.remote_sources`) until G-v08 passes (Q-r8). Reason: a partly built v0.8 never moves a source off the coordinator.
- **Credentials on workers** (Q-r6, stricter refinement of §19.5's "sealed per worker"): account credentials in memory only, over mTLS, re-sent on reconnect; companion credentials made on a worker stay sealed there, never sent to the coordinator.
- **External's endpoint acknowledgement counts per worker** (Q-r10, stricter than §19.5, which names only Restricted and Overlay). Reason: requests leave from that worker's IP.
- **Lemmy is pulled, not pushed** (Q-r1). ActivityPub push needs a public inbox, and the UI/API port stays LAN-private (§19.2). Lemmy then contacts a third party, so its consent class moves from None (§18.7) to **External**: stricter. Push would be the owner's call, since it opens a port.
- **The coordinator trusts nothing in a worker's `Finds`** beyond its active assignment and epoch; source id and private flag come from the assignment. Credentials in `Assign` redact and zeroize.
- **Nostr's `since` cursor is clamped** against future-dated events and overlapped, with dedupe by event id.
- **NOS-3 is Opus**, not P6's **[S]**: it manages up to eight relay connections. **The WebSocket transport is split** into NOS-2a (a routed, guarded TCP connect with an in-house SOCKS5 handshake in `integrations::net`) and NOS-2b (the WebSocket client).
- **Nostr events are verified:** id recomputed from NIP-01's canonical form, BIP-340 signature checked, failures dropped (Q-r2). New dependency `k256` (`schnorr` only, pure Rust), to be approved in NOS-1's brief. No new crate for WebSockets: `tokio-tungstenite` and `tokio-rustls` are in the tree.
- **Adult claims from any source, stricter only, scoped to items only claiming sources found** (ADH-0, Q-r4). This extends X-source-adult (`docs/decisions/2026-11-05-X-source-adult.md`), which deliberately didn't read `content-type:adult`. Without the scope, one signed Nostr event or Lemmy post could hide a mainstream torrent the DHT stored, against owner §1.8.12. So the claim never reclassifies a stored torrent another source found. Lemmy's `nsfw` flags and Nostr's adult tags (or a content warning naming them) produce it; spoiler and violence warnings don't.
- **Narrower options built where the plan is silent:** no NIP-09 deletions (Q-r3), no keys from `.torrent` links in Lemmy posts (Q-r12), no remote companion installs (Q-o2), Lemmy API v3 only.
- **No migration** (§4): pins, allowances and per-worker consent in `settings` rows that fail closed; cursors in `source_state`.
- **Not in E-v08:** Anna's Archive and LibGen (owner §2.38); overlay plugins themselves (v1.1+); DAT files and direct JSON API plugins (P-v07 Q15, Q-r9).
- **For the owner** (not decided here): Q-o1 the terms position for Nostr relays and Lemmy instances (user lists, starting empty; Nostr suggestions only after a recorded check; no Lemmy suggestions), Q-o2 remote companion installs (recommended no), Q-o3 approving the per-worker consent wording. New conditions `ext:owner-v08-q1` and `ext:owner-v08-q3` gate NOS-3, LEM-1 and PL-7b.
- **`runner/slices.yaml` and `runner/dashboard.yaml` are not edited** (brief step 3). The runner adds the 22 slices, their `placement` rules and the two conditions after review.
