# S-settings-2b decisions (Trackers, Integrations, Notifications, Insights & digest)

- **Trackers is generated** (`sections: ['trackers']` in the registry, no body). **Per-tracker health is not shown:** no settings endpoint exposes it (`GET /insights/index` carries `trackers` as rolled-up reported state). `Screen.extra` is the slot where a health panel mounts when something serves it.
- **Integrations, Notifications and Insights are hand-built bodies on the engine** (`screens2/*Screen.svelte` over one `SectionScreen.svelte` loader and one `GroupedForm.svelte`), because each needs something the generated shell can't hold: the shell makes `x-danger` fields read-only (`query_logging`), has no place for a test button after a group, and the schema's list shapes fall back to the JSON input. `GroupedForm` keeps the generated look (groups, Advanced, restart banner) and gives each screen a snippet after each group.
- **Two list shapes get small widgets, registered per form** by setting the spec's `widget` to a name `GroupedForm` registers (the engine's schema reader can't express them, and `schema.ts` is not this slice's): `integrations.clients` (cards) and `integrations.default_client` (a select over the staged clients' ids), and the enum arrays `digest_channels` and `route_*` (checkboxes, with options named in `screens2/channels.ts` in the schema's order). Both are the engine's own `SettingField`, so label, help, menu, conflicts and errors are unchanged.
- **A client's password is not staged.** The staged `clients` value would be written to the sessionStorage draft and the Undo batch, and the draft rules (§10.10.5) forbid secrets there; the engine only excludes `writeOnly` specs. So the card holds a typed password only for **Test connection**, and saves it with its own request: `GET /settings/integrations` for the current list and revision, then `PATCH` with that list and `password` on the one client, `if_revision` set. **Remove a secret** for a client is the same with `""`, after the confirmation (§10.10.7). Both need the client saved first (the server keeps a password only for a saved id); an unsaved card says so. The field menu's Remove stays the engine's for the Torznab key and the notification secrets. **Refinement for the runner/owner to see (§2.19):** setting a client's password is a separate "Save password" action, not part of Save.
- **Whether a password is set** comes from `SettingValue.secrets_set` (`<id>.password`), which the engine's `FieldState` doesn't carry. The card list reads it with its own `GET /settings/integrations` on mount and whenever the saved value changes. A follow-up could expose `secrets_set` on `FieldState` and drop the extra request.
- **Tests post the values on screen** (`POST /settings/test`): a secret that wasn't replaced is left out, so the server uses the saved one for the saved server only (part b). A client test sends `id` when the server has that client. Results are plain text (our sentence from `ok` and `version`, or `error.message`); a transport error shows the API error's message or a fixed line. Nothing secret is logged or placed in a URL.
- **Privacy dialog:** a `privacy` gate on the Insights form, asked only when `query_logging` is being turned on (turning it off asks nothing). It says what is recorded, where it stays, and the retention in days as staged; Cancel keeps nothing saved, focus starts on Cancel. **Clear usage data** is its own button in a Danger zone: `GET /usage`, a dialog with the exact count (no size, as part b decided), `POST /usage/clear {confirm: true}` only on the confirm; with nothing logged it says so and asks nothing.
- **The digest preview** mounts at `<div data-slot="digest-preview">` after the digest group; S-insights-3 fills it.
- **Engine polish (item 4):** `SettingField.setAutomatic` resets `editing` when Automatic turns on, since the text box unmounts without a `focusout`.
- **Copy:** all strings are `settings_screen_*` (not server keys) except the server's own labels, help, keywords and `settings_group_*`, which the generator turns into the four new per-section maps. zh is filled for all of them.

## Size (runner decisions §2.26, 2026-10-31) and how it was held
- **Lazy parts.** The client cards, the channel checkboxes, the per-group test button, the Clear usage panel and the Privacy dialog load after the screen paints (`screens2/Lazy.svelte`, `LazyWidget.svelte`, `widgets.ts`, `privacy.ts`). The four navigation icons load as one module (`screens2/icons.ts`) through a new optional `Screen.iconLoad`, with `shell/NavIcon.svelte` showing the gear until it arrives. This is the scoped exception to the registry: the one new field, one small component in the shell, and the four entries for these screens. Nav titles stay eager.
- **A hand-built screen's purpose is its body's line**, so the three hand-built entries carry no eager `purpose` (Trackers, which is generated, keeps its).
- **Gates.** `.size-limit.mjs`: the first-view gates now count the group map plus the screen's own map (`bodyMaps`), and for a generated screen the largest generated section's map by gzip size, instead of the largest of any section (the optional #264 polish item). The four new maps have their own entry ("Settings connection messages", limit 4.3 KB) and the lazy parts another ("Settings connection screens", 12.9 KB), each at measured + 10%; the existing "Settings messages" limit is unchanged. No limit was raised.
- **Stray CSS.** A bare `card` token in sources makes Tailwind emit daisyUI's `.card` rules into the global stylesheet (+0.15 KB of the 20 KB CSS budget). The screens' sources, tests and comments avoid it; the same goes for `rounded-lg`, `sm:grid-cols-2` and `gap-x-6`, which the app doesn't otherwise use.
- **Numbers (main → branch, gzipped):** Settings section 42.33 → 43.62; Language first view 43.25 → 44.13 (+0.88: group map +0.23 for the 11 new headings, registry titles +0.13, the longer preload list of the registry chunk about +0.45, the rest small shifts; accepted by the runner); Appearance 28.37 → 29.03; Keyboard 35.50 → 36.15; Integrations 44.24, Notifications 44.99, Insights 44.64 (new); connection messages 3.87 and connection screens 11.68 (new); CSS 19.89 → 19.89.
- **Deferred text.** `GroupedForm` has no restart banner of its own (none of the three hand-built sections has a restart-required field; Trackers, which does, uses the shell's form). Notification help and label texts were shortened to hold Notifications under 45 KB.
