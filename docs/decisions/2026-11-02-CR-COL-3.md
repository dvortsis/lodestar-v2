# CR-COL-3 decisions: the collector and analyzer keep and judge the crawler gate evidence

Implements `docs/decisions/2026-11-02-CR-SPEC.md` (#375, `8b0037bf`) in `docs/soak/tools/` (`docs/build-plan.md` Track C step C0a). No crate code changes. `analyze_cr0.py` is unchanged, and CR-0's collector flow (`--run-kind cr0`, the default) keeps its phases, windows and stop rules; its tests and rehearsals still pass. One change reaches it: its snapshots now go through the same label allowlist and series cap, so a CR-0 counter whose label value is outside the documented enums is dropped. Every value today's binary renders is in them.

## What it adds
- **`linux/collect.py --run-kind ab|comb|comparator`** collects a CR-SPEC segment. Outside `--rehearsal` the warmup is fixed at 60 min and the window at 6 h (`ab`) or 24 h (`comb`, `comparator`); `ab` needs `--treatment adm|utp|route`. Every run also needs `--spec-commit` (rule 7.2).
- **`analyze_cr.py`** (new, beside `analyze_cr0.py`) judges the evidence: `segment`, `effect`, `route-baseline`, `gate` and `checkpoint1`. It imports the label enums, switch list and T_open rule from `collect.py`, so the two can't drift apart.
- **`collect.py note`** writes a host-activity entry (rule 6.11).

## Retention (rule 6.10, §8)
- **Allowlisted names and label values.** `LABELLED` lists each gate series's label keys, in rendered order, with the only values it may carry, taken from `docs/metrics.md` and checked against a live `lodestar serve` scrape (`fetch_attempts_total{transport}`, `fetch_family_*{family}`, `fetch_admission_*`, `dht_peer_permit_returns_total{boundary}`, `dht_sample_suppression_reason{reason}`, and so on). Any other label set, an extra label or a reordered one is dropped. Label-free gate series must carry no labels. CR-0's series keep their old generic check.
- **Histogram buckets including `+Inf`,** plus `_count`, `_sum` and `discovery_to_searchable_dropped_total`.
- **A cap of 512 series per snapshot.** The allowlist renders about 180. A capped snapshot is flagged (`series_capped`), and the analyzer treats it as missing evidence.

## §8's rows and their sources
- **Clocks (D1a):** each row's `time` and `elapsed_seconds` are now read together. `run.json` records the NTP state at start, and `result.json` records it at the end.
  - **Sources, in order:** `chronyc tracking` (its system-time offset), then `timedatectl` (with `timesync-status`'s offset), then the kernel's `ntp_adjtime`. The kernel is also the fallback when `timedatectl` reports sync but gives no offset (ntpd under systemd), and it works inside a container.
  - **The kernel's offset** is the larger of `|timex.offset|` (ns with `STA_NANO`, otherwise µs) and `esterror`. ntpd puts jitter in `esterror` and timesyncd leaves it at 0, so `esterror` alone could pass the 1 s check without measuring anything (runner's review).
  - **When the kernel says unsynchronised,** the offset is unknown, and the segment is invalid. `run.json` also records the monotonic origin and boot ID for `note`.
- **Configuration identity:**
  - **Switch states:** from `docker inspect`'s environment, or `/proc/<pid>/environ` natively. Only the seven `LODESTAR_DHT_*` switches, `LODESTAR_INTENSITY` and two paths are read.
  - **Witness:** the paths are reduced to `host_mounted` (a bind mount holds the witness directory) and `outside_data_dir`.
  - **Effective preset and pause state:** from the settings API (`/api/v1/settings/crawler`, with its source). If the API isn't answering yet at launch, the collector retries at every scrape until it does, and records when (`read_at_elapsed`).
- **Settings and Insights need a login.** API keys reach only search, Torznab and feeds, so the collector logs in with `--password-file`. The password and the session cookie stay in memory and are never written. Because the login goes over plain http, the collector refuses a `--url` that isn't loopback or private, and a password file readable by group or others (runner's review). The later crate option: export the effective preset and pause state in `/metrics`, so no login is needed.
- **No `config.toml`.** The collector refuses to start a Lodestar CR-SPEC run when Lodestar was given `--config`, when its data directory holds a `config.toml`, or when it can't tell. Docker mode checks with a `HEAD` on the container's archive endpoint; native mode checks through `/proc/<pid>/root`. The reason: switches set in a config file would be invisible to it. `run.json` records `config_file: absent`, and the analyzer treats anything else as missing identity.
- **Network counters (rule 7.1):** from `/proc/<pid>/net/dev` (non-loopback) and `/proc/<pid>/net/sockstat`. Docker mode reads them through `--proc-root` (the host's `/proc`). If they can't be read, they're absent and published as "not available".
- **Public IP:**
  - **When:** a reference check at the first scrape, then one at each boundary scrape (t_s, every hour boundary, the end). A failed check is retried at each scrape until 90 s past its boundary.
  - **Source:** one lookup to `--ip-echo-url` (default `https://api.ipify.org`), with no proxy.
  - **What's kept:** the address stays in memory. Evidence records only `reference`, `unchanged`, `changed` or `failed`.
- **Imports (rule 5.5):** at each boundary scrape, the collector reads `/insights/events` from process start to now and keeps counts only: `import_started`, `import_finished`, `intensity` changes, pauses, `truncated`.
- **The comparator's count (rule 5.4), fixed here before the rehearsal as the spec asks:**
  - **The query:** `SELECT count(*) FROM torrents`, run by `psql -X -q -A -t -v ON_ERROR_STOP=1` through a Docker exec in bitmagnet's Postgres container (`--postgres-container`) at every scrape.
  - **Read-only:** the session gets `PGOPTIONS=-c default_transaction_read_only=on`.
  - **Recorded:** the query is written to `run.json`.
  - **Comparator mode:** it doesn't read `/metrics` or `/healthz`, and its `ws` is the container's `StartedAt` + 60 min (rule 1.2).
- **`note`:** stamps UTC and the collector's elapsed time (same boot, from the recorded monotonic origin) and appends to the private `activity.jsonl`. The fixed categories, plus `other` for a plain note. Its text is never published.
- **No rates while a window is open (rule 6.11):** for CR-SPEC kinds, `status.json`'s `latest` drops `values`, `net` and the API results, and shows progress and window state only. `analyze_cr.py segment` reports no rates until `result.json` exists.
- **Host checklist (rule 6.5):** `--checklist auto_update=excluded|not_applicable`, `--checklist backup=…`, and `--next-run ITEM=<UTC>` for excluded items.

## Stricter readings, listed for a spec follow-up
Where CR-SPEC leaves a choice open, this slice takes the stricter one, as the brief asks. None loosens a rule.
1. **D6 and the DHT's pre-report default.** For about a second after start, `/metrics` reads `dht_sample_suppression_seconds 0` with reason `off`, before the restart check reports. This was seen on a live scrape, and it would fake an immediate T_open. A zero counts only when the reason isn't `off`, or once the process is at least 6 h old (`open_eligible`, shared by both tools).
2. **A failed scrape inside the window is missing evidence.** All its series are absent (rule 6.6).
3. **Observation must begin within 180 s of process start.** The gap rule runs from process start, not from the collector's first scrape. So do drift, identity, counter resets and host activity ("between process start and the window's end", rule 6.5).
4. **A cumulative series that disappears is a counter reset.**
5. **Imports:** `import_started` voids a segment as well as `import_finished`. An `intensity` annotation voids it. A pause annotation, or `paused` at any boundary, invalidates it as an interruption. The preset and pause state are checked at every boundary, and a boundary without that check is missing evidence.
6. **The public IP** needs a reference before t_s, and an `unchanged` check within 90 s after every boundary. A failed check is missing evidence.
7. **Reconciliation with a zero numerator** passes only if samples plus dropped are also 0. Coverage with no samples is "not measured".
8. **The permit identity (rule 5.1)** is followed from process start to the window's end, not only inside the window.
9. **Arm-switch time (rule 2.3)** is measured from the earlier segment's last scrape to the next process start, which overstates it slightly. The earlier segment must have stopped cleanly (`--stop`: exit 0, signal delivered).
10. **Docker runs must mark both checklist items `excluded`.** `not_applicable` is accepted only natively.
11. **Blocks:** an outcome needs exactly 2 or 4 valid blocks, ABBA then BAAB alternating. Otherwise the result is `not_decidable`.
12. **Settings identity:** a `LODESTAR_INTENSITY` that disagrees with the settings API's effective preset is missing identity.
13. **A permit-identity stretch** runs from its first non-zero scrape to the scrape that reads 0 again, not to its last non-zero scrape.
14. **Rule 2.2's spacing** takes a Lodestar process as running until 90 s after the later of its window's end and its last scrape, which covers the collector's stop path.
15. **Scrape gaps (rule 6.6)** are measured between usable scrapes. A failed scrape doesn't close a gap, so a long `/metrics` outage during the warmup counts too.
16. **A CR-SPEC run refuses to start without a readable boot ID**, so host-activity notes can always be placed.
17. **Checkpoint 1 checks its inputs:**
    - It refuses rehearsal inputs, reports that aren't the named treatments, and outcomes that aren't final (`not_decidable`, `not_estimable`, `inconclusive_run_blocks_3_and_4`). Rule 6.9 follows the outcomes.
    - It leaves out a comparator that isn't valid or that breaks rule 2.2's spacing against the A/B segments. Rule 5.4 makes 2.2 a comparator check, and D7 keeps void runs out of every analysis.
    - Without the comparator's worst-hour ratio, the worst hour isn't projected, so the result can't be "on track".
18. **The route experiment's "no opportunity"** is decided only over 2 or 4 paired valid blocks, like any outcome (rule 6.1).
19. **Rule 7.1's series are published per hour as well as over the window:** resources, packets/s, bytes, sockets, connects/s and the mechanism deltas.

## Interpretations (not stricter, just fixed)
- **The effect fit's time variable** is each window's UTC midpoint in hours, from the block's earliest midpoint. Segments voided as `no_opportunity` leave the fit and don't invalidate their block (rule 5.3).
- **Checkpoint 1's CR-0 worst-hour ratio** comes from `analyze_cr0.py`'s baseline hourly `writer_stored_total` (stored rate, rule 6.9). With either ratio missing, the worst hour isn't projected, so the projection isn't "on track".
- **Fetch latency isn't exported**, so it isn't reported (rule 5.2: "where it's exported").
- **Rehearsals** may shorten the warmup, the hours (`--hour-seconds`) and the sample interval. They're recorded as rehearsals. `gate` refuses them, and `effect` marks them.

## Not covered by the binary, for the runner
- **Switch states from `config.toml` are invisible to the collector.** It sees only the environment and the settings API, as §8 specifies. The runbook must set crawler switches by environment.
  - A gauge `dht_switch{name}` (1 when on, 0 when off, one label per switch in `SWITCH_ENV`) would let the analyzer check the effective state directly.
  - I'd add it in a crate slice, but no rule needs it today.

## Rehearsal
Run on the slice's own sandbox; the result is in the PR description and the message to the runner.
- **Its own fresh data directory.** On a fresh directory, a resumed restart keeps the first start's 6 h gate, which lifts at first start + 6 h on the wall clock. So the measured segment is the resumed start after that, as segments 2–4 of a block are.
- **The IP echo was a local stub** over plain http, which only a rehearsal allows.
- **The sandbox has no NTP daemon or UDP egress.** D1a's check therefore fails there, correctly, and the DHT can't bootstrap, so the counts are 0.
- **The permit-identity check on a healthy CR-ADM run** (rule 5.1) still needs the first experiment-host rehearsal.
