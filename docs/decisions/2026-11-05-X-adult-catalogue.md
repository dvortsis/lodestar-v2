# X-adult-catalogue decisions (one manifest catalogue)

Slice X-adult-catalogue (runner brief, 2026-11-05T18:50Z), #494's follow-up for gap 4. It builds on `2026-11-05-X-source-adult.md`; nothing there is changed.

- **One catalogue of every compiled-in plugin** (`crates/sources-plugins/src/catalogue.rs`). `catalogue::manifests()` returns the `&'static Manifest` of each plugin in the crate, registered or not (ThePornDB and StashDB, on hold, included), and `catalogue::always_adult()` the ones with `always_adult`. Each entry is the plugin's own `MANIFEST` const, the one its `SourcePlugin::manifest` returns. To make that possible, every plugin's `MANIFEST` (and `SUKEBEI_MANIFEST`) is now `pub(crate)`; the torrent cache's was already `pub`. No plugin needed a new accessor. Only this crate's plugins are listed, so an always-adult plugin must live in `sources-plugins`; the pipeline's own sources (the DHT, the enrichment runner) aren't always adult.
- **The torrent cache's entry has no endpoints.** Its plugin adds the configured caches as `endpoints`; the catalogue lists `torrent_cache::MANIFEST`, the same manifest with none. The catalogue is for a manifest's fixed fields (`id`, `kinds`, `always_adult`, and so on). Egress never reads endpoints from it.
- **The catalogue can't miss a plugin.** Two unit tests in `catalogue.rs` fail when a module in `lib.rs` is neither listed nor named in an explicit `NOT_PLUGINS` list (just `catalogue` today), or when a module's count of plugins in its file and any file nested under it (each `fn manifest(&self)`, a `SourcePlugin` or an `AdultEnricher`) differs from its entries (Nyaa and Sukebei share `nyaa.rs`). `tests/manifests.rs` builds every plugin and checks each entry equals the manifest that plugin reports.
- **`lodestar import` masks from the catalogue** (`adult_sources` in `crates/lodestar/src/cli/import.rs`). It used to name Sukebei alone, so a second always-adult plugin would have been masked in the pipeline and not on import. It now matches the store's registered rows by plugin id against `catalogue::always_adult()`. Behaviour is unchanged today (Sukebei is the only one), and a disabled or purged source still contributes no bit, as before (SRC-14b, owner flag gap 3).
- **One manifest-safety test over the catalogue** (`crates/sources-plugins/tests/manifests.rs`): no manifest is both `Kind::Enrichment` and `always_adult`, ids are unique, and the always-adult set is exactly Sukebei, so a new always-adult plugin has to change that test on purpose. It replaces `tests/tpdb.rs`'s scan of the source text for `Manifest { … }` literals; tpdb keeps its own check through the trait. ENR-5 (#506) already kept only `tests/stashdb.rs`'s own assertion; its comment now points at `tests/manifests.rs`.
