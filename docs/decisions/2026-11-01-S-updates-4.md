# S-updates-4: Roll back on the Updates screen, plain words for install failures

Code: `web/src/lib/features/settings/updates/**`, `web/e2e/settings-updates.keyboard.test.ts`.

- **Roll back button** sits in a Danger zone section at the end of the screen (§10.10.14, §10.10.7), a bordered section with a warning icon and a danger button, as the log files screen does. It shows only when `rollback.available` and `rollback.to_version` are set and no install step is live. Its label names the previous version ("Roll back to 0.5.0"); for the image's own version (`to_version: image`) it says "the container image's version". When it isn't available the screen shows nothing (the one reason line the screen has, for automatic installs, is a different control).
- **Confirmation** uses the existing `ask` dialog (Cancel is the initial focus; Cancel and Esc send nothing). It says the app restarts on the previous version and, only if the update changed how data is stored, that data returns to the snapshot and later changes are lost (§12.2: the store is restored when the update migrated it; the API doesn't say whether this one did). The button names the action ("Roll back to 0.5.0"). It adds the torrent count from `rollback.lost_torrents` (formatted; 1 and 0 have their own sentences), or says the count can't be given when it is null. Only the "Roll back" action sends `{confirm: true}`.
- **Answers:** `202` takes the returned status; the restart then shows through the `updates` SSE path as for a switch. `409 rollback_unavailable` reads `ApiError.reason` and shows one plain sentence per reason (`not_supervised`, `image_mode`, `busy`, `no_previous_version`, `snapshot_missing`; any other reason gets "The server gave no reason."). `409 updates_unavailable` says there is no update engine. Anything else is a generic "didn't start". No retries.
- **install_failed** words: the SSE `error` code maps to a sentence for `download_mismatch`, `download_too_large`, `download_io`, `no_artifact`, `redirect_refused`, `stage_failed`, `no_space`, `bad_overlay`, `timeout`, `network`, `blocked`, `http_status`, `too_large`, `bin_unavailable`, `rebuild_running`, `trust_damaged` and `not_current` (the codes B-update-5, 5b and the engine's install path give); any other code gets "Something went wrong while installing." The code itself, a URL or a host is never shown. The `install_failed` message now reads "The install failed. {reason} The running version carries on."
- **Refinement of an earlier decision:** S-updates-3 showed the raw stable code in the failed-install message; that is replaced, as #318's follow-up asked. It loosens no owner decision.
- After a manual rollback (history reason `manual`) the status card says "You rolled Lodestar back to {version}" instead of the failed-update sentence.
- Messages are in en and zh. No server, API-client or schema file changed.
