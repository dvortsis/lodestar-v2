# X-followups-1105 decisions (this PR)

Review follow-ups from SRC-17a (#462) and RP-2 (#465). No owner decision changes.

- **The plugin-name cache is single-flight with a 5 s back-off (`NAMES_RETRY`, a new number, the runner's call).** One slot per pipeline holds a `OnceCell` for the names and a `tokio::sync::Mutex`. The listing runs as a detached task that holds the mutex until `sources()` answers, so concurrent first requests wait for one call (which takes the store's writer lock), and a request dropped mid-listing (its client gone) doesn't let the next start a second one beside the first's blocking job. Why: a pipeline whose `sources()` kept failing took the writer lock once per search.
- **A failed listing is kept for 5 s.** Requests in that window get the empty map, as a failed request did before: an admin sees sources by plugin id rather than display name, and a public caller sees no source. The cost is that one failure now covers 5 s of requests rather than one; 5 s keeps that to a moment while capping the lock at once per 5 s.
- **A search with no viewer does no provenance work.** Discover Newest (`search_get`, no viewer) neither lists the plugins nor reads the source catalogue. A successful response is byte for byte the same (`discover_newest.txt` golden). The one difference: a store error reading the catalogue can no longer fail it, since it isn't read.
- **A pack override's filter note logs as kind `pack_override`, rule 0.** `pipeline.filter_rule_skipped` took "pack override <ID> fails closed: unreadable" as `other`; it now gets the kind `docs/metrics.md` names. Its id is a pack rule's (`MW-1`), not a number, and the event's `rule` field is a number, so it logs as 0 rather than changing the event's schema; the Insights exception `filter_rows_unreadable` names the row.
