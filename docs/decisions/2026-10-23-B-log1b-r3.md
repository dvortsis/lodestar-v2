# B-log1b decisions, part 2b of 4: the `lodestar` crate, filters and the bounded shutdown

Architecture §12 and §12.1, owner's decisions §2.11 and §2.19, the B-log1 and B-log2 decision files, M6-win's "Logging under the service", and parts 1 and 2a (`2026-10-23-B-log1b.md`, `-r2.md`). No owner decision is reversed or loosened, and no security or content-safety decision is weakened. The refinements the runner flags to the owner (§2.19) are marked **(§2.19)**.

- **Swept here:** `services.rs` (the rest of it), `system/address.rs`, `system/restart.rs`, `windows/{ports,priority,service}.rs`, `fixture.rs`, `insights.rs`, `main.rs` (B-update #128 has merged and no B-update PR is open) and `filter/lists.rs`. `NOT_YET_SWEPT` keeps 8 files, all part 4's (pipeline and search).
- **Where the events live:** the binary's own catalogue (`logging/events.rs`), as the earlier swept modules' do; `filter/lists.rs`'s one event in a new `lodestar-filter` catalogue (`crates/filter/src/log_events.rs`), registered in `logging::CATALOGUES`.
- **Addresses the operator must open are `Listen`** (a label: shown at every setting), so a Private console still tells a headless operator where to go: the address timer's lines, `app.serving`, `fixture.public`. The friendlier `http://<this host's address>:…/` form is gone from the lines (§2.19); `Listen` prints the bind address.
- **Paths are `Path`** (hidden under Private): the data folder in `app.serving`, `service.starting` and the fixture's lines; the executable in `app.reexec` (the carry-forward: never inside a message); a fixture's manifest.
- **Errors show their kind only.** Store, join and `SystemError`s by type name; I/O by `ErrorKind`; text errors (`String`s from `to_string()`, which can hold a path) by a fixed kind. `fixture` and `main`'s commands also print the error to stderr for the person who ran them, through `url::scrub_text` (an import's database URL can carry a password); that's the terminal, not a log output.
- **Insights** logs counts and fixed step names only (`insights.step_failed {step}`), never a query from the query log. Unknown metric names come from the store, so they're counted, not named.
- **`filters.ip_lists_broad`** carries the coverage as a whole percentage (`Size`).
- **Windows** (`windows.ports_low` and friends): the port warning's numbers are fields (family, available, reserved, needed, the socket count and the `netsh` fix's start and count), the message the advice: the `netsh` command to run as administrator (with `<family>`, `<fix_start>` and `<fix_count>` naming the fields), the `excludedportrange` check, and lowering the crawler's intensity or `max_sockets` (when `fix_count` is 0, the only fix). The old line's full sentences move to `logs.event.windows.ports_low.help` for S-logs. The priority lines keep PowerShell's text out.
- **`app.restart` is now emitted** (required) when a restart is asked for, and **`app.stop`** (required) at the end of `Services::run`, with `clean` (whether every service stopped in order and the server returned no error; a forced drop alone still reads `clean=true`, and `app.shutdown_forced` says connections were cut). Whatever the serve future returns, the save and `app.stop` run before `run` returns its error. Its line comes after the fold summaries (the runtime flushes them before it, B-log2). Messages other slices' tests read keep their words, lower case included: `app.stopped_cleanly` "stopped cleanly" (`tests/system.rs`), `app.restart` "restart requested" (`tests/system.rs`), `app.stopping` "shutting down" (`tests/windows_service.rs`).
- **The Windows service's logging is the runtime** (runner's decision 7). `windows/service.rs` calls `settings::log::init_with_writer` with `windows::logfile::Console`, which writes the runtime's console text to `<data>\logs\lodestar.log` (kept, with its rotation: one line per record, never split across a rotation), and the JSONL file opens through `follow` in the same logs folder, as everywhere else. `lodestar.log` now holds the console's lines (Private kinds, the setup token right after `enter setup token`), where the M-auth docs send people. Its own `tracing` subscriber is gone. A test builds a runtime on that writer and finds the setup token's line in `lodestar.log` and the event in `lodestar.jsonl`.
- **The bounded graceful shutdown (§2.19: 10 s).** When the signal fires, after `hub.close(); jobs.close(); logs.close();`, a 10 s timer (`SHUTDOWN_GRACE`) races the serve future (`tokio::select!`, the signal shared through a `watch`; no new dependency). If the timer wins, `app.shutdown_forced {waited_s}` is logged and the serve future dropped; then `events.close()` and `handles.shutdown()` run as before.
  - **What dropping axum 0.8's serve future does** (read in `axum-0.8.9/src/serve/mod.rs`): the accept loop and the listener go; the tasks it already spawned for connections (`tokio::spawn` in `handle_connection`) run on, detached, until the runtime ends. They hold the router's state (`Arc` clones), nothing `handles.shutdown()` waits on: the pipeline stops through its own handle and `search.stop()` through a shared one. The process ends after `run` returns, which drops them.
  - **Tests** (`crates/lodestar/tests/shutdown.rs`, the real binary): a 48 MiB rotated log file (0700 folder, 0600 file) is seeded; opening the log file compresses it, so the test waits for its `.gz` and downloads that name (streamed inflated, still 48 MiB), with `redact=false` by a client that reads only the first 4 KiB, and the signal waits until its receive queue has stopped growing (read from `/proc/net/tcp`, so this case runs on Linux; sent earlier, closing the logs source can end the download before anything blocks); `SIGTERM`; the process exits 0 after 9–25 s (the 10 s bound), the file has `app.shutdown_forced` before `app.stop`, and `app.stopped_cleanly` (the state was saved). With no stalled client, the file has `app.stop` and no `app.shutdown_forced`: it didn't wait the bound.
- **The canary's positive controls:** run 1 now finds `app.hot_columns`, `app.serving`, `app.stopping`, `app.stopped_cleanly` and `app.stop` in the console and the file.
- **Not reached by the canary,** each covered by its module's tests or the shutdown test: the address timer's lines (B2c's tests drive them), the Windows lines (Windows CI), `fixture.*` (`tests/fixture.rs`), `insights.*` failures (they need a failing store), `app.import_progress` (the bitmagnet importer test).
