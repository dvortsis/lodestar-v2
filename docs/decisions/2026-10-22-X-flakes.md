# X-flakes decisions (#88)

- **The NRT budget is a bench gate, not a unit test.** §3's "new torrent → searchable < 5 s" was asserted in `crates/search/tests/index.rs` with a 5 s deadline, which Windows CI missed whenever parallel tests starved the indexer. The test is now `the_live_indexer_follows_the_store`: it checks only that the indexer follows the store, with a deadline that only stops a hang. `search-bench` measures the budget: after the latency tables it runs a live indexer at its production settings (`LiveConfig::default()`, poll 500 ms, commit 2 s) over the whole corpus. It stores 10 torrents one at a time, times each until the index counts it, and `--gate` fails when the slowest takes over 5 s. CI's `search latency (§3)` job runs it at 200k torrents. A reused `--dir` grows by those 10 torrents per run.
- **Rebuild waits fail on a stall, not a deadline.** `crates/search/tests/rebuild.rs` waits for a swap by watching `Serving::progress()`. It fails at once on `Failed` (with the error), when the progress hasn't changed for 60 s, or after 10 minutes in all. A fixed 30 s wait was a time budget: Windows CI runs that suite in 40–70 s.
- **Two test hooks in production code, no behaviour change:**
  - `ServingConfig::hold_before_start` (doc-hidden, like `hold_before_finish`): a rebuild holds before its first step, so a test reads the progress it resumed from before the thread can add a step.
  - `rename` is `rename_with(.., std::thread::sleep)`: the unit test passes its own wait, clears the blocker during the first retry's wait on the same thread, and checks the backoff without sleeping.
- **The fake uTP peer's sockets linger.** A dropped `FakePeer` keeps its UDP socket (two handles: the receive socket and its `try_clone` for sending) open while its connections linger (`Config::linger`, 5 s). Tests reuse one peer per configuration rather than binding one per case.
- **A test that needs "nothing answers uTP here" holds the port.** `falls_back_to_tcp_when_utp_goes_unanswered` aims uTP at a TCP-only fake peer's port. Windows hands out ports in sequence, so another test's uTP peer could take that UDP port number, answer the SYN and fail the fetch at once (`early eof`) rather than letting it time out. The test now binds a silent UDP socket on the same port for its lifetime.
- **`res:<digits>` is read as `<digits>p`** before the release parser sees it, so `res:360` and `res:360p` both mean `480p`, which is where the parser files 360p. `fuzz (query)` found it: the bare form kept `360p`, which re-parses as `480p`, so the round-trip failed on `main` whenever the fuzzer reached it. The 64-byte limit applies to that stored form: 64 digits used to pass it, then render as 65 bytes with their `p` and fail to parse back (also found by `fuzz (query)`). Both spellings are now refused at 64 digits. An empty part of a list (`res:720,`) is refused, as for every other key.
- **A live indexer error never ends its thread.** A commit error used to return from the indexer thread for good, so the index silently stopped following the store while the server kept serving it. That's what hung `each_commit_reports_once_with_its_count_and_watermark` on Windows (PR #90): no indexer progress for 22 s on an idle runner, most likely a transient sharing violation on a commit. Now every error is counted (`IndexStats::errors`, already in the metrics and status page), kept as text (`last_error`), logged and retried. An error while stopping, such as a failed last commit, is what `stop()` returns.
  - **Each retry opens a fresh writer from the committed watermarks,** as after a crash. Uncommitted work is read from the store again; store errors take the same path.
  - **A commit can fail after reaching the disk** (its reader reload, say). The reopened writer then starts past torrents that were never reported. So the indexer tracks the last id it reported. After a reopen it refreshes the reader and reports any gap, counted the way the swap counts one (`stored_between` and `adult_between`). That's what makes every torrent reported once.
  - **Backoff** starts at the poll interval and doubles up to 30 s. A successful commit resets it, and so does catching up with nothing pending, so a commit that keeps failing backs off instead of retrying every couple of seconds, while errors hours apart each start fresh. It wakes at once on stop.
  - **Known gap:** if a commit fails after reaching the disk and the indexer is stopped during the backoff that follows, neither the indexer nor a swap reports those torrents. It's a skip, never a double report, and rare: stopping in that window, after that kind of failure.
  - **`search_indexed_total` counts at commit,** so torrents read again after an error count once. A gap's torrents count when they're reported. Its help text says so, and the errors metric's help now names commit errors too.
- **The live indexer's tests fail on an error or a stall, not a budget.** `eventually` fails at once, with the error, when the indexer reports more errors than the test expects or its thread has ended. It also fails when indexed, commits and errors haven't moved for 30 s. A 5-minute hang guard remains only as a backstop. Two tests inject one failing commit, before and after it reaches the disk (`#[cfg(test)]` counters in `LiveConfig`). They check that every torrent is indexed, counted and reported once.
- **uTP WSAENOBUFS: the cause isn't established.** The fix removes the only socket build-up the test itself caused. If it recurs, look at system-wide UDP ephemeral-port use on the runner (other tests and processes binding UDP ports) rather than at this test.
