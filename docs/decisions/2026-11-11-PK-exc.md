# PK-exc decisions

Two Insights exceptions from architecture §10.9.2 level 5 ("FUSE/network path", "ephemeral-port pressure") and §11, per `docs/plan/2026-11-06-m6-gap-audit.md` §4.3 and plan Q11. Additive only: no migration, no schema bump, and older clients still parse the response.

## The contract
- **Two new `InsightsException.kind` values:**
  - `data_filesystem`: the data folder is on Unraid's user share, another FUSE filesystem or a network filesystem (`fsdetect::FsReport::is_risky`).
  - `ephemeral_ports`: on Windows, the dynamic port range leaves fewer ports than `windows::ports::needed(max_sockets)`.
- **Two new optional fields carry the detail,** left out of the JSON for every other kind:
  - `filesystem` (`DataFilesystem`): `kind` is an enum, `unraid_user_share`, `fuse` or `network`. It also carries `path` and `fs_type`.
  - `ports` (`PortPressure`): `family` is an enum, `ipv4` or `ipv6`. It also carries the range, reserved, available, needed and `max_sockets`, and the fix's `fix_start` and `fix_count`, both null when no range is large enough.
  - A client that predates them ignores them; the API test checks the old field set still reads both kinds.
- **Typed fields, never free text** (runner, 2026-11-11). There is no ready-made command string: the client builds `netsh int <family> set dynamicport tcp start=<fix_start> num=<fix_count>` from the fields.
- **A new fix kind, `guide`,** with the targets `data_folder` (guide §2.2) and `windows_ports` (guide chapter 4), per Q11.
  - Today's UI and the digest offer no link for a fix kind they don't know, so nothing breaks.
  - Until PK-ui lands, the Insights screen shows the generic "Needs attention: data_filesystem" (or `ephemeral_ports`), with no fix link.
  - The digest words both kinds in this PR, but has no guide link yet.
- **`unit` gains `ports`** (`ephemeral_ports`'s `value` is the ports left). `data_filesystem` has no number: `unit` and `value` are null.
- **Severity:**
  - `data_filesystem` is an error on a network filesystem, where unreliable locking can damage the database, and a warning on FUSE, which is slow but not unsafe.
  - `ephemeral_ports` is a warning.
- **One `ephemeral_ports` exception, for the worse family,** on purpose. Both families usually share the same cause (Hyper-V's reservations), and a second entry would repeat the same advice. If the other family is narrow too, it shows at the next hourly check after the first is fixed.
- **`since`** is when this process first found the exception. It is kept across hourly re-checks while the exception is still found, and reset if the exception clears and comes back.
- **The `ephemeral_port_pressure` KPI in `stages.rs` stays `None`,** as the brief says.

## How it's checked
- **At most hourly** (`HOST_RECHECK_S`, in `crates/lodestar/src/insights.rs`), from the overview request that finds the last check an hour old. A clock set back makes the check due at once, rather than holding it off for as long as the clock went back.
- **One check at a time, with no lock held across I/O:**
  - The request that claims the check runs it on its blocking thread, before it takes the store's lock.
  - Concurrent requests get the last answer at once and never start a second check. Before the first check ends, that answer is empty.
  - A check that panics frees its claim and is tried again an hour later, not on every request.
- **Re-tried after a minute** (`HOST_RETRY_S`) instead of an hour when the port check couldn't run yet, because the socket count isn't set (`ports::ready`). `services` sets it before Insights exists, so this is a guard rather than a path taken in normal runs.
- **All of one check's `netsh` calls share a 10 s budget** (`NETSH_BUDGET`). A check makes four calls: the dynamic range and the exclusions, for each family. Past the budget, the call running is killed and the rest count as unreadable. So a hung `netsh` holds the claiming request for at most about 10 s, never for good. The start's log check shares a budget the same way.
- **Where the inputs come from:**
  - The data folder is the parent of `Follow.db`, which is `Config::db_path()`, so `<data>/lodestar.db`.
  - **The port check uses the socket count the fetch pool runs with** (runner, 2026-11-11). `services.rs` calls `ports::set_max_sockets` right after `settings.effective_config`, so saved Settings for intensity and `max_sockets` count, not just the config file. The call is 0 without a pipeline. The pool's size changes only at a restart, which sets it again.
  - `ports::pressure()` re-reads `netsh` for both families. It returns the worse family's warning (`ports::worst`, a plain function tested on every OS), with ties going to IPv4.
- **The wiring is tested with an injected port probe** (`Insights::set_host_probe`). The real `ports::probe` reads the process-wide socket count, which only `ports.rs`'s own test touches, so parallel tests can't race on it.
- **Still on the file's value: the start-up log line `WINDOWS_PORTS_LOW`.** `windows::startup` (`windows/mod.rs:65`) reads `max_sockets` from `Config::load`, the file and the environment, before Settings are open. So when saved Settings differ from the file, the line can name a different socket count than Insights does, or warn when Insights doesn't.
  - It is left as is, because `windows/mod.rs` belongs to PK-win-restart (runner, 2026-11-11).
  - Insights and the digest, which the user acts on, are right. The log line is a one-off at start.
  - A later slice that owns `windows/mod.rs` can drop the start-up check's own count and log from `pressure()` once `services` has set it.

## Files outside the owns (runner, 2026-11-11, approved shared edits)
- **`crates/lodestar/src/services.rs`:** the one `ports::set_max_sockets(…)` call after `effective_config`.
- **`crates/api/src/digest.rs`:**
  - the test helper's `InsightsException` literal gains `filesystem: None, ports: None`;
  - `alert()` gains two arms, so the email digest words the new kinds plainly, never "Needs attention: data_filesystem." The ports sentence includes the `netsh` command built from the typed fields.
  - Its test checks each kind's sentence and that neither raw kind appears.
- **`web/src/lib/api/openapi.json` and `schema.d.ts`:** regenerated with `cargo run -p lodestar --bin openapi` and `npm run api:types`, never edited by hand.

## Q11's wording, refined (the runner's UX call, §2.19)
- **Q11's "Move the data folder to a pool path" is used only for Unraid's user share,** where a pool path exists.
  - FUSE and network filesystems get "Keep it on a local disk, ideally an SSD" (and, for a share, "send only backups to it"), as `fsdetect`'s warning already says.
  - The Unraid sentence names the step: setting the template's host path to a pool path such as `/mnt/cache/appdata/lodestar`.
- **The ports sentence counts the rest of the PC.** `needed` includes the 2,048 ports kept for other programs, so it reads "Lodestar and the rest of this PC need about …".
- **Lowering the intensity says where and that a restart is needed:** the fetch pool's size applies at restart.

- **9p counts as a network filesystem**, so a WSL2 or Docker Desktop mount of a Windows drive is flagged. The sentences therefore say "a network or shared-folder filesystem", not "a network share" (runner's review, 2026-11-11). This covers the digest and `fsdetect`'s warning. The fixed start-up log line in `logging/events.rs` is outside PK-exc and still says "network filesystem".

## For PK-ui
- **Render both kinds** from `filesystem.kind` and `ports`:
  - `unraid_user_share`: "move the data folder to a pool path such as `/mnt/cache/appdata/lodestar`";
  - `fuse` and `network`: "keep it on a local disk". Call `network` "a network or shared-folder filesystem", in `en` and `zh`, since it covers 9p mounts from WSL2 and Docker Desktop;
  - `ephemeral_ports`: the `netsh` command built from `ports.family`, `fix_start` and `fix_count`, to run in an administrator Command Prompt. When the fix fields are null, say "lower the crawler's intensity in Settings, then restart Lodestar" instead. The digest's sentences in `digest.rs` are a model for both.
- **`fs_type` is a detail,** not for the sentence.
- **Map `fix.kind: "guide"`** to the guide pages above.
