# SRC-15c decisions (Sources: Account dialog, generated config forms, purge counts)

Slice SRC-15c, architecture §18.7, §18.8, §10.10.7, owner decision §2.49. It builds on `2026-11-06-SRC-15b.md` and the API of `2026-11-07-X-sources-api-spec.md`.

## What ships

- **The Account dialog** is the Account branch of `ConsentDialog.svelte`, so it uses SRC-15b's lazy entry.
  - It shows the §2.49 Account text verbatim. `dialogs.test.ts` now renders it and compares it with `consent-approved.fixture.ts`, as for the other three classes.
  - Fields come from `credential_spec`: label, kind and required. A `secret` is a masked, write-only input, never prefilled or read back; a `username` is plain text. A field whose name is in `credentials` shows "Saved" and isn't required again. A stored credential has a Remove button (`null` through the same route).
  - Typed values go to `PATCH /sources/{id}/credentials` once. They are emptied from component state whether it succeeds or fails, and the dialog never repeats a typed value in a message.
  - Then it sends `enabled: true` (no `consent`: an Account source has no acknowledgement) and shows the server's answer. The gate stays closed in v0.5.2: the server refuses and the dialog shows its sentence, "Your details were saved" above it. There is no client-side bypass.
  - An Account source's switch now always opens the dialog when turned on (SRC-15a kept it disabled).
- **The generated config form** (`config-form.ts`, `ConfigDialog.svelte`, opened by "Settings…" on a row whose `editable` lists `config`).
  - Supported: string (enum, minLength, maxLength), integer and number (minimum, maximum), boolean, and arrays of strings or of flat objects of those (minItems, maxItems, uniqueItems). Everything else is named in the dialog with "edit through the API" and nothing is sent for it.
  - The client checks the same bounds as the server before sending; the server's `invalid_config` sentence is shown as well.
  - **The API doesn't return saved settings values** (`Source` has no `config`). The form starts from each setting's default and a save replaces the settings; the dialog says so. Follow-up for the API: return the saved `config`, so the form can start from it.
- **The purge count**: the purge dialog calls `GET /sources/{id}/purge/preview` when it opens (session only, no body) and shows torrents, claims, unverified items and kept counts above the password. Loading, failed (with Retry; the purge stays possible) and unsettled states are handled. An enabled source shows "these counts can grow".

## Size

Runner's call, §2.26; flagged per §2.19 (2026-11-07T03:38Z). The owner's first priority is the smallest, fastest UI, so opening Consent or Purge doesn't also download the settings form.

- `ConfigDialog.svelte` is a third lazy entry of `dialogs-root.ts`, loaded by a dynamic `import()` at the point of use. The build manifest shows it as its own chunk.
- `web/.size-limit.mjs`: `sourcesConfig` and `sourcesAllLater` (the first view still excludes all three); a new entry "Sources config dialog (on demand)" at **6 KB**, which counts only what the form adds beyond the dialogs chunk (the shared dialog and field modules belong to the dialogs entry); "Sources dialogs (on demand)" raised **37 → 40 KB**.
- Measured, gzip: dialogs 36.2 kB before, **37.95 kB** after (Account fields, purge counts); config dialog **4.79 kB**; the Sources first view 30.68 kB of 30.9 kB (unchanged).
