# X-sources-low decisions

Three low findings from the runner's security pre-audit of `main` at 63a2c6df. None was reachable at the time; each tightens behaviour before more plugins are wired. Each is the runner's call (`docs/owner-decisions.md` §2.19). They refine SRC-5's egress (`docs/decisions/2026-11-02-SRC-5.md`) and the arr webhook (ARR).

- **L1. An endpoint list is keyed on origin: scheme, host and port.** `Endpoints::check` compared the host alone, so under `NetPolicy::download_client()` (loopback and LAN allowed) any port on the configured Prowlarr or download-client host passed: another service on the same machine was reachable through the plugin. Now each entry is `(scheme, host_key, port)`, with the scheme's default port when the URL names none, and a request must match all three.
  - **`only_hosts` is replaced by `only_origins(&[url])`,** which takes the address the user entered, not a bare host, so the port and scheme come with it. Removing the old method makes every caller fail to compile rather than silently keep the host-only rule. The four callers move: Prowlarr (its base URL), download clients (the client URL), torrent caches (the cache address as sent), full scrape (the scrape URL). Each plugin's tests now check that its own requests pass its list and another port doesn't (`Endpoints::permits`, the list's DNS-free check made public for that).
  - **Manifest hosts are on their scheme's default port only** (`https` → 443, `http` → 80). No manifest declares a port today.
  - **Tightening, accepted:** a user-entered address used to allow either scheme on its host. Now `http://tracker:6969` doesn't admit `https://tracker/`, so a redirect that upgrades it to https would be refused. No plugin follows redirects today (their fetches report one rather than follow it), so this changes nothing yet. The user enters the https address instead. Torrent caches are https-only already.
- **L2. A cross-origin redirect keeps only an allow list of headers.** `send_following` dropped four named credential headers, missing StashDB's `ApiKey` and anything a later plugin names. On any hop that changes origin it now keeps only `Accept`, `Accept-Language`, `Content-Type`, `Content-Length` and `User-Agent`, none of which can carry a credential, and drops every other header the request set. Headers dropped stay dropped if a later hop comes back to the first origin. An allow list rather than a per-request sensitive list, so a plugin that forgets to mark a header can't leak it.
- **Paths outside the brief's `owns`, for the runner to accept:** the four callers' `endpoints()` and their doc comments (`crates/sources-plugins/src/{prowlarr,clients,full_scrape,torrent_cache}.rs`), their endpoint tests (`crates/sources-plugins/tests/`), `crates/sources-plugins/README.md`, and in `egress.rs` the `Origin` type, `Endpoints::manifest`, `only_origins` and `permits` beside `check`. Keying on the port can't be done without them: the callers passed a bare host.
- **L4. The arr webhook's title cleaner uses the shared set.** `clean_title` had its own, narrower list of format characters. It now removes `lodestar_metainfo::hidden_char`: controls, every Unicode Cf character (U+00AD, U+061C, U+180E, U+FFF9–FFFB among them), U+2028/2029 and the tag characters U+E0000–E007F. Whitespace is still folded to one space first, so U+2028/2029 become a space, as other whitespace does.
