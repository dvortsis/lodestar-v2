# FX-6-I9 decisions

M5 design review finding I9: brushing the Size histogram wrote `size:1073741824..4294967295` into the query bar while the chip said "1.00 GiB to 4.00 GiB".

- **The canonical printer writes byte bounds in IEC units** (`KiB`, `MiB`, `GiB`, `TiB`), the largest one that divides the value exactly, else plain bytes. It wrote `KB`/`MB`/`GB`/`TB` before, which the parser already read as 1024-based; the new spellings match §10.12's one formatter. Counts (`files:`, `year:` …) keep plain numbers.
- **New syntax `a..<b`: a range whose top stops short of `b`.** The brush's upper bound is one byte short of a unit on purpose: histogram bins are `[lo, hi)` and query ranges are inclusive (`web/src/lib/features/search/facets/bins.ts`), and `brushOfRange` relies on it to light the right bins. Moving the bound to `4GiB` would add torrents of exactly 4 GiB and light the next bin, so the brush is unchanged and the printer says `size:1GiB..<4GiB` instead. The AST is the same (`hi` = 4 GiB − 1); only its text changed. One-sided bounds do the same with the existing forms: `size:<16GiB` for `hi` = 16 GiB − 1, `size:>4GiB` for `lo` = 4 GiB + 1 (was `size:>=4294967297`). `..<0` and an empty `..<` are errors; arithmetic is checked, so `u64` edges can't overflow. `docs/query-language.md` gains the form; this file adds it to §8.
- **No stored text breaks, no migration.** Saved searches keep the text as sent plus the AST as JSON, and run from the AST; filter rules, unless-queries and allow-list entries store canonical text that is re-parsed, and the parser still reads the old spellings; the percolator runs ASTs; Insights' top queries group `query_log` text, which nothing writes in production yet, and its overview cache is in memory; URLs holding old text still parse to the same AST. Nothing compares stored text with freshly printed text. One caveat: a rule, override or exception saved with `..<` text is skipped by an older binary after a downgrade, since it can't parse the form; nothing needs migrating.
- **The e2e mock printer is unchanged.** `web/e2e` checks the facet rail against a TypeScript stand-in for `/api/v1/parse` that prints bytes; it tests the AST edits, not the server's text, so no web file changes in this PR.
