- **D4. How G1–G3 are tested.**
  - **G1 runs the real binary** with the DHT on a loopback port and no bootstrap nodes, so it contacts nobody. It asserts the whole `/api/v1/sources` list and each entry's default `enabled`.
  - **G2 and G3 at the pipeline:** two pipeline tests pin `PipelineConfig::default()`.
  - **G2 and G3 in the binary:** `crates/lodestar` has no library target, so the binary's own guard reads its sources. Any line that names `adult_enrichers` or `verify_unverified` fails it until the manifest says the feature ships. A real-binary test also shows that a `[sources] verify_unverified` key stops the start.
  - **Why read the sources:** the binary builds its `PipelineConfig` across `config.rs` and `services.rs`, and a refactor of either just to expose it for a test would touch files the slice doesn't own. The guard catches exactly the change that matters, a line that wires either field.

- **D7. On `409 notice_required` the collector stops loudly.**
  - **Before:** each settings or Insights check that got the 409 was recorded as "unavailable".
  - **Now:** a 409 whose code is `notice_required`, from the login or from any session route, raises `NoticeRequired`. That is neither an OSError nor a ValueError, so the checks that record gaps don't catch it.
  - **How it ends:** the run finalises with reason `collector_error`, an event-log note naming `notice_required`, and a message on stderr. Its exit code is 1.
  - **Other 409s** stay "unavailable", as before.
  - **Why the existing reason:** `analyze_cr0.py`'s `STOP_REASONS` is outside this slice's paths. A dedicated `notice_required` reason would need that file changed too, so the note carries the cause instead.
  - The change was kept small because X-soak-screen-polish also owns `collect.py`.
