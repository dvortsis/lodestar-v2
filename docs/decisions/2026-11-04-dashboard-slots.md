# Dashboard worker slots (#416)

**Owner request (2026-11-04):** "Also visualize what each of the slots is working on. Ensure the runner keeps the underlying document up to date." The dashboard shows one card per worker slot.

- **The runner keeps the slots in `state.json` on `runner-state`, not in `runner/dashboard.yaml`.** The runner already pushes that file on every wake with no PR, so keeping the list current costs it nothing. Putting it in `dashboard.yaml` would have forced a runner PR on every launch and finish. The runner's review of #416 asked for this; it keeps the owner's request, since the runner still maintains the document.
- **Shape:** `slots: {updated, items: [{slot, slice, role, agent, doing, since?, status?}]}`. `role` is `build|review|docs|soak|other`, `agent` is `claude|other`, `doing` is one plain sentence for a non-technical reader, `status: "idle"` marks a slot kept but empty. Any slot number from 1 to the limit with no item shows as idle.
- **The number of slots is `limits.phase_total` in `runner/slices.yaml`,** not a second copy of an owner-set number. At most 64 rows are ever drawn, and an entry above the limit is reported, not drawn.
- **The connector joins each entry with its slice's title, state, model and PR from GitHub** (`plan_slots`), and reports a problem instead of hiding it: an unknown or already-finished slice, a slot listed twice, the same slice in two slots, a bad slot number, a role or agent outside the set, values that are not strings, a missing, invalid or future `updated`, `items` that is not a list, an open slice PR in no slot, and a list older than 24 hours. Staleness depends on the clock, so it shows on the live dashboard but does not fail `npm test`.
- **Also in #416:** one timed-out older page of closed pull requests no longer fails every tool; the plan is built from the pages that returned and reports "Merge history incomplete". A GitHub server error is retried once after a short random wait, and never for pages 2 and up, so a cold refresh stays near the free plan's subrequest limit (see the connector README). The `soak` block of `dashboard.yaml` moved from r3 to r4.
- **No owner number or security decision changes.**
