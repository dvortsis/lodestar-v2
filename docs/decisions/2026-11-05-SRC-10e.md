# SRC-10e decisions (Sukebei variant of the Nyaa plugin)

**HOLD: nothing may register or enable this plugin until the Q2 terms and robots check is recorded, and the forced-Adult consumer (see OPEN below) has landed (plan §5 Q2, owner §2.28).** The check is owed by the runner or the owner (this slice's sandbox had no route to sukebei.nyaa.si). It must confirm, and record here:
1. the site's terms of use and `robots.txt` as they read today, for `/?page=rss` on `sukebei.nyaa.si`;
2. whether a general-purpose index polling the public feed every 5 minutes fits those terms. If that is grey, it goes to the owner;
3. that the feed's shape matches the fixtures (`nyaa:infoHash`, `nyaa:categoryId`, `nyaa:size`), which were hand-written and never recorded.

Slice SRC-10e of `docs/plan/2026-11-01-v06-sources.md` (§4), the owner's answer to Q7 (written): "Allowed as a variant of the Nyaa plugin: off by default, External consent, every item forced into the Adult category, hidden unless 'Show adult content' is on." Spec: architecture §18.2, §18.7, §20.9.

- **A variant, not a setting.** `Sukebei` sits in `crates/sources-plugins/src/nyaa.rs` beside `Nyaa` and shares its run loop, parser limits and mapping. It is its own plugin with the id `sukebei` (never renamed), so the user switches it on and off on its own, its finds carry its own source id, and Nyaa's manifest and tests are unchanged.
- **Manifest:** `External` consent, `enabled_by_default: false`, risk Medium, discovery over BitTorrent. One endpoint, `https://sukebei.nyaa.si`, and egress is narrowed to it (`Endpoints::manifest`). No settings, no credentials, no user-entered address.
- **Policy:** the same as Nyaa's: a poll at least 5 minutes apart (a user can slow it, never speed it up), one request per 5 s to the host, back-off 60 s to 6 h, `Singleton`.
- **Adult is forced at mapping time** (`to_found_adult`). Whatever category the feed gives (or none, or an unknown one, or no other claim at all), the find has exactly one `content-type` claim and it is `adult` (`ContentType::Adult.as_str()`). The feed's own category stays as the `nyaa-category` claim.
- **OPEN, blocks enabling: the forced claim has no consumer yet (review finding).** Nothing outside this crate reads a `content-type` claim. The pipeline stores claims as opaque data and classifies from the name and files only (`crates/pipeline/src/unverified.rs`, `worker.rs`). So today a Sukebei item with a clean name is **not** stored as Adult and would surface with "Show adult content" off. That falls short of owner Q7. The fix is outside this slice's paths: a source-level "always adult" signal that the pipeline applies as an Is-adult correction at confidence 100 (the existing `Correction` path in `lodestar-classify`). **Runner: it needs its own slice, and SRC-10e's plugin must stay unregistered until it lands**, together with the "doesn't surface when Show adult content is off" test, which also belongs there. It is not covered by anything here.
- **Visibility is not the plugin's job.** The plugin sets nothing that would bypass the adult preference, and a test checks every find is an ordinary one (no `interest`, no `private_source`, no peers, files or trackers). That is not a visibility test.
- **The feed's namespace.** NyaaV2 derives the `nyaa:` URI from the site address, so Sukebei declares `https://sukebei.nyaa.si/xmlns/nyaa`. SRC-8 assigned this one-line addition to SRC-10e (`2026-11-02-SRC-8.md`): `SUKEBEI_NS` in `crates/sources-feeds/src/rss.rs` (outside the brief's owned paths, taken from that decision) with a parser test. The fixtures use that URI. HOLD item 3 also covers it.
- **The filter applies in full.** The plugin has no skip path around the pipeline: finds go to the same intake as any plugin's, where the child-safety core and floor judge the hash and the claimed name before storage (SRC-2, `crates/pipeline/tests/unverified.rs`). `sukebei_blocked` carries a blocklist-style hash through the plugin and asserts it arrives as an ordinary adult find with no bypass flag. **Only partly met:** no end-to-end test through the real filter. That needs `lodestar-pipeline` as a dev-dependency of this crate, which this slice doesn't own. The cross-plugin injection test is SRC-G's (`tests/safety.rs`); **runner: add SRC-10e to SRC-G's deps**, which don't list it today.
- **Nothing but the feed is fetched.** No `.torrent`, no view page; the replayer fails any other request.
- **Fixtures** are hand-written and synthetic: clean made-up titles, made-up hashes, and the README's scrub grep finds only size strings. No real adult titles. Cases: `sukebei_rss`, `_empty`, `_429`, `_5xx`, `_blocked`.
- **Q2 (ToS and robots): not checked.** See the HOLD above. The plugin is off by default and is not registered by this slice.
