# SRC-10e decisions (Sukebei variant of the Nyaa plugin)

**HOLD: nothing may register or enable this plugin until the Q2 terms and robots check is recorded (plan §5 Q2, owner §2.28).** The check is owed by the runner or the owner (this slice's sandbox had no route to sukebei.nyaa.si). It must confirm, and record here:
1. the site's terms of use and `robots.txt` as they read today, for `/?page=rss` on `sukebei.nyaa.si`;
2. whether a general-purpose index polling the public feed every 5 minutes fits those terms. If that is grey, it goes to the owner;
3. that the feed's shape matches the fixtures (`nyaa:infoHash`, `nyaa:categoryId`, `nyaa:size`), which were hand-written and never recorded.

Slice SRC-10e of `docs/plan/2026-11-01-v06-sources.md` (§4), the owner's answer to Q7 (written): "Allowed as a variant of the Nyaa plugin: off by default, External consent, every item forced into the Adult category, hidden unless 'Show adult content' is on." Spec: architecture §18.2, §18.7, §20.9.

- **A variant, not a setting.** `Sukebei` sits in `crates/sources-plugins/src/nyaa.rs` beside `Nyaa` and shares its run loop, parser limits and mapping. It is its own plugin with the id `sukebei` (never renamed), so the user switches it on and off on its own, its finds carry its own source id, and Nyaa's manifest and tests are unchanged.
- **Manifest:** `External` consent, `enabled_by_default: false`, risk Medium, discovery over BitTorrent. One endpoint, `https://sukebei.nyaa.si`, and egress is narrowed to it (`Endpoints::manifest`). No settings, no credentials, no user-entered address.
- **Policy:** the same as Nyaa's: a poll at least 5 minutes apart (a user can slow it, never speed it up), one request per 5 s to the host, back-off 60 s to 6 h, `Singleton`.
- **Adult is forced at mapping time** (`to_found_adult`). Whatever category the feed gives (or none, or an unknown one), the find has exactly one `content-type` claim and it is `adult` (`ContentType::Adult.as_str()`). The feed's own category stays as the `nyaa-category` claim. §20.9 lists the source's own category as a strong signal, and the classifier has the last word on the adult kind. Every other claim keeps Nyaa's bounds and Low confidence.
- **Visibility is not the plugin's job.** "Show adult content" off hides `type:adult` items from search, facets and Discover (§20.9). The plugin sets nothing that would bypass that. A test checks every find is an ordinary one: no `interest`, no `private_source`, no peers, no files or trackers.
- **The filter applies in full.** The plugin has no skip path around the pipeline: finds go to the same intake as any plugin's, where the child-safety core and floor judge the hash and the claimed name before storage (SRC-2, `crates/pipeline/tests/unverified.rs`). `sukebei_blocked` carries a blocklist-style hash through the plugin and asserts it arrives as an ordinary find with no bypass flag. **Not done here:** an end-to-end test through the real filter. That needs `lodestar-pipeline` as a dev-dependency of this crate, which this slice doesn't own and the brief didn't approve; the cross-plugin blocklist injection test is SRC-G's (`tests/safety.rs`, README).
- **Nothing but the feed is fetched.** No `.torrent`, no view page; the replayer fails any other request.
- **Fixtures** are hand-written and synthetic: clean made-up titles, made-up hashes, and the README's scrub grep finds only size strings. No real adult titles. Cases: `sukebei_rss`, `_empty`, `_429`, `_5xx`, `_blocked`.
- **Q2 (ToS and robots): not checked.** See the HOLD above. The plugin is off by default and is not registered by this slice.
