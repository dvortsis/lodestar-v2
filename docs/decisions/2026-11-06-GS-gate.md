# GS-gate decisions

GS-gate, 2026-11-06. Turns the §3 index and store size budgets into a required CI gate before the v0.7 producers (GS-0, GS-2, RX-1, ENR-11) land, as `docs/plan/2026-11-05-v07-m7.md` Q10 asks.

- **`ci-ok` needs `size-budget`.** Until now the size job ran but sat outside `ci-ok` with the timing budgets, so a red size check didn't block a merge. It now blocks: a producer that takes the torrent index over 512 B per torrent turns `ci-ok` red. The timing budgets (search latency, filter) stay out, for the hardware reason the workflow comment gives. The size budget doesn't share that reason: it measures bytes on 50k seeded synthetic torrents, so the result agrees across runners within about 0.2 B per torrent rather than depending on the runner's hardware.
- **No new path filter.** The size job already runs when `changes` sets `bench`, which `.github/scripts/ci_changes.py` computes from every workspace crate `lodestar-bench` builds. That closure already holds `lodestar-search`, `lodestar-classify`, `lodestar-store`, `lodestar-pipeline` and `bench/` itself, so `crates/search/**`, `crates/classify/**` and `bench/**` are covered with no change to the script. A PR touching none of them skips the job, and `ci-ok` counts a skipped job as passing.
- **The gate fails closed.** `size-report` already failed on an error. It now also fails, with or without `--gate`, when a measured value is zero, negative or not finite, when the torrent index holds a different number of documents than the torrents generated, or when the file index is empty or holds more files than were generated. Any of those would otherwise read as small and pass the budget.
- **The job summary says why.** `size-report --summary PATH` appends a Markdown table with each part, its measured value, its budget and its result. CI writes it to a file under `$RUNNER_TEMP`, and an `always()` step copies it into the job summary, since each step has its own `$GITHUB_STEP_SUMMARY`. When no report exists (setup, build or crash), that step says so instead. A failure to write the summary fails the run. Only being over a budget needs `--gate` to fail; everything else above fails without it too.
- **Budgets unchanged.** `STORE_BUDGET` 1,024 B, `BLOB_BUDGET` 600 B, `INDEX_BUDGET` 512 B and `FILE_INDEX_BUDGET` 800 B are the owner's §3 numbers. This slice only enforces them. The runner may tune them under owner-decisions §2.26; a slice may not.

- **`dir_size` does not recurse (follow-up, X-gs-gate-polish).** The gate sums the files directly in the index folder and in `files/`. A new subdirectory under a measured folder is not counted, so a producer that adds one escapes the budget. Reviewers of GS-2 and RX-1 must watch for new subdirectories. Making `dir_size` recurse isn't a small change: the file index is a subdirectory of the torrent index, so recursing would count it twice and move the measured numbers. Budgets are unchanged.
