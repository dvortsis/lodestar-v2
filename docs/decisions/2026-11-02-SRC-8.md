# SRC-8 decisions (RSS 2.0/Atom parser with the `nyaa:` namespace)

Slice SRC-8 of `docs/plan/2026-11-01-v06-sources.md`. It covers architecture §18.2 (rank 8 Nyaa RSS, rank 13 AnimeTosho) and §18.9. The parser feeds SRC-10a (Nyaa) and SRC-10b (AnimeTosho). It holds to the safety bar SRC-6 set (`docs/decisions/2026-11-01-SRC-6.md`).

- **`rss::parse_each(body, &Limits, emit)`** is a pure function from bytes to items, in `crates/sources-feeds/src/rss.rs`. It reads RSS 2.0 `<item>`s and Atom `<entry>`s, in the same document if need be. `rss::parse` collects the items with the default caps.
- **SRC-6's building blocks moved into `crates/sources-feeds/src/common.rs`, unchanged, and both parsers use them.** That's the caps (`Limits`, `LIMITS`), `Summary`, `Skipped`, `Stop`, `Hashes`, `external_ref`, title cleaning, hash and magnet parsing with the zero-hash rejection, `merge`, RFC 2822 dates, the body preamble (byte cap, UTF-8 prefix, BOM) and the entity resolver.
  - `torznab` re-exports the public ones, so its API is the same and its tests pass unchanged.
  - Two additions:
    - `rfc3339`, for Atom's dates;
    - `Stop::Namespaces`, described below.
- **The caps are SRC-6's (`LIMITS`), with the same stop-or-skip split.** These are the additions:

  | Cap | Default | Over it | Why this value |
  |---|---|---|---|
  | `MAX_NS` | 32 tracked bindings in scope | stop (`Namespaces`) | A real feed declares 2–6 namespaces on its root. Lookups scan this stack, so it bounds the work per element |
  | `MAX_CATEGORY` | 16 B | ignore the value | Nyaa's ids are `1_2`. Only ASCII digits and `_` are kept |
  | namespace URI length | `max_attr_len` | treated as an unknown namespace | No URI we know is that long, so it isn't decoded or copied |

  The other per-field limits trim as SRC-6's do:
  - the title is cut to 1,024 B, with control characters and the bidi controls removed (the same set as `torznab`);
  - a reference over 2,048 B is dropped.
- **Names are matched by namespace URI, not prefix.**
  - RSS elements are those in no namespace, Atom's are in `http://www.w3.org/2005/Atom`, and Nyaa's are in `https://nyaa.si/xmlns/nyaa`.
  - Any prefix bound to Nyaa's URI works. A `nyaa:` prefix that is unbound, or bound to another URI, is ignored.
  - A default namespace other than none or Atom takes the RSS elements out of RSS.
  - quick-xml's `NsReader` isn't used. Its lookups scan every binding in scope, and it records every declaration. A root with 500,000 `xmlns:` attributes, followed by a million elements, would then cost about 10¹¹ steps.
  - The parser tracks only the bindings that can change a lookup: a known URI, a default namespace, or a prefix that shadows a tracked one. Those are capped at `MAX_NS`. Declarations of unknown URIs on fresh prefixes cost nothing, and a test checks 10,000 of them.
  - Every element's attributes are scanned for declarations without quick-xml's duplicate check, which is quadratic. That keeps the scan linear. A duplicate declaration just shadows the earlier one.
  - `xmlns:="…"` and `xmlns:p=""` aren't valid declarations (Namespaces in XML 1.0) and stop the parse (`Malformed`).
  - An attribute that doesn't parse during that scan stops the parse (`Malformed`), on any element. `torznab` ignores a bad attribute on an element it doesn't read. A namespace that can't be read would mis-resolve the whole subtree, so skipping it isn't safe.
- **The Nyaa URI is matched exactly.** NyaaV2 derives the URI from the site's own address, so Sukebei and self-hosted instances declare other URIs and aren't read as Nyaa. That keeps Q7's Sukebei question with the owner (plan §5). If the owner says yes, SRC-10e adds Sukebei's URI here, which is a one-line change.
- **Fields kept:**

  | Field | From |
  |---|---|
  | title | RSS or Atom `title` |
  | guid | RSS `guid`, or Atom `id` |
  | link | RSS `link`, or Atom's link with no `rel` or `rel="alternate"` |
  | published | `pubDate` (RFC 2822), or Atom's `published`, else `updated` (RFC 3339; the fraction is dropped) |
  | seeders, leechers, downloads | `nyaa:seeders`, `nyaa:leechers`, `nyaa:downloads` |
  | size | `nyaa:size`: binary units B, KiB … PiB as Nyaa writes them, or a bare byte count. Digits and one point only, so there's no `inf`, `NaN` or exponent, and the value is below 2⁶³ |
  | category | `nyaa:categoryId` |
  | trusted, remake | `nyaa:trusted`, `nyaa:remake` (`Yes`/`No`), the flags §18.2 names for Nyaa |

  - **The enclosure's `length` isn't used as the size.** In RSS 2.0 it's the size of the linked file, which is the `.torrent` and not its content. Torznab is different (Prowlarr puts the content size there), so `torznab` keeps using it.
  - **Not kept:** `description`, `nyaa:comments`, the category name, and any `author` or uploader. Under §18.7 there are no profiles of people. `trusted` is the item's flag as Nyaa states it, not a profile.
- **The info hash comes from `nyaa:infoHash`, else the first magnet.** Magnets are searched in this order: an Atom link `href`, the RSS `link`, the enclosure URL (RSS, or Atom `rel="enclosure"`), then the `guid`.
  - The rules are SRC-6's:
    - v1 is 40 hex digits or 32 base32 characters, and v2 is 64 hex digits;
    - a hybrid magnet gives both;
    - all-zero hashes are invalid;
    - an `infoHash` that is present but invalid, or empty, skips the item (`bad_hash`), even when a magnet is good;
    - an item with neither is skipped (`no_hash`).
  - RSS has no Usenet items.
- **References go through SRC-6's `external_ref`.** User info, fragments and credential-style query parameters are removed, and magnets are dropped, together with their `tr` passkeys. With Nyaa's `&magnets` option the `link` is a magnet, so only the `guid` (the view page) is kept.
- **Fuzzing:** `fuzz/fuzz_targets/rss.rs`, with seeds in `fuzz/seeds/rss/`. The first byte picks tight caps, as for `torznab`. CI's fuzz matrix finds the target itself.
  - A local run went 1.18 M executions in 71 s with no findings.
- **Golden fixtures were written for the tests, in the shapes Nyaa and AnimeTosho serve.**
  - Nyaa's RSS, with and without `&magnets`: element order, the `nyaa:` set, `-0000` dates and a CDATA description.
  - AnimeTosho's RSS (a magnet enclosure) and an Atom feed.
  - They use made-up titles and hashes and `.example` hosts. No third-party content was copied (launch brief).
- **Size:** about 520 production lines in `rss.rs` against the plan's ~450. The difference is the namespace tracking, which the URI-matching rule needs.
