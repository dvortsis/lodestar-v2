# X-web-hygiene-1107 decisions (2026-11-07Z)

Test hardening and one small UI fix; no owner decision touched.

- **FieldMenu keyboard focus.** Same pattern as X-menu-keyboard-focus: `SettingField` marks the first open as a keyboard open when the click has `detail === 0` and hands that to `FieldMenu`, which passes `autofocusFirst` to `Menu` and drops it when the menu closes (so the reset lives in the lazy chunk). A pointer open is unchanged. No keyboard e2e spec reaches the field menu, so the coverage is component tests in `SettingField.test.ts` (keyboard open focuses the first item; a pointer open does not). `Menu.svelte` needed no change.
- **#594 nit 1.** The pointer-after-keyboard e2e now waits for the menu itself to hold focus before its negative check, so `not.toBeFocused()` cannot pass early.
- **#594 nit 2.** `overlays.test.ts` gains the negative case: with `autofocusFirst` off, the first item is not focused.
- **search-facets uncheck flake.** `uncheck()` on `facet-type-movie` once reported that the click did not change its state. Cause: after the check, the rail re-renders from the new `/facets` answer, and the uncheck could hit the checkbox that re-render then reset. The spec now waits for the `/facets` response for the new query and for the Clear button, which renders only once the server's data marks the value selected (so the rail has re-rendered), then unchecks and asserts the new state. No sleeps.
