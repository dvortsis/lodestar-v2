# X-sec-S1-18 decisions (#998)

S1-18 and S1-19 (both low), surface 1, the DHT reply path. The detail stays with the runner until the fix has merged; this file records only what the code now does.

## S1-18: streamed peers are budgeted per source
- **Each source has a fixed share of a streaming session.** A session still remembers at most 32 distinct peers (`STREAM_SEEN`). One source (a responder's IPv4 /24 or IPv6 /48, as `limits::source` keys it) now adds at most `STREAM_SOURCE_SHARE` = `STREAM_SEEN / 4` = 8 of them, so at least four sources share a session. The rest of a source's peers are ignored and not counted.
  - **Loopback has no share,** the same rule `limits.rs` uses for its per-source buckets: no packet from off the host carries a loopback source, and a local test network runs many nodes on it. The 32-peer cap still holds for it.
- **A peer dropped because the caller's channel is full stays unseen,** so a later reply can still deliver it. It's still counted as backpressure.
- **Where:** `Stream::offer` and `stream_source` in `crates/dht/src/node/stream.rs`; the actor passes the responder's source at its one call.
- **Unchanged:** `STREAM_BATCH`, `STREAM_QUEUE`, `STREAM_SEEN`, the metric series, and `dht.streaming_peers` (off by default).
- **One metric's meaning is restated** (`docs/metrics.md`, approved by the runner): `dht_peer_stream_backpressure_total` counts drops at the moment of backpressure; a peer dropped past the held-back batch may be offered again later, so it can be counted more than once.

## S1-19: a request ends on values only when its sources send enough between them
- **The new end condition (the runner's call, refining CR-LOOKUP-END's end rule):** a request ends on values when it holds at least `ENOUGH_VALUES` distinct values and the sum, over sources, of `min(distinct values the source sent, ENOUGH_VALUES / VALUE_RESPONDERS)` reaches `ENOUGH_VALUES`. With today's constants, each source counts for at most 4, so it takes at least two sources (4 + 4, or 3 + 3 + 2, for example) and 8 distinct values in all.
  - A source sending values another source sent first still counts them, so a second network corroborating the same swarm counts as before. A source repeating one value counts it once.
- **Where:** `Actor::has_enough_values`, using `SentBy` in `lookup/values.rs`, which holds at most 4 values per source and lives with the request. The separate list of value-carrying networks (`value_nets`) is gone.
- **Unchanged:** `ENOUGH_VALUES = 8`, `VALUE_RESPONDERS = 2`, the leg convergence rule (`closest_answered`), and `dht.lookup_end` (off by default).
