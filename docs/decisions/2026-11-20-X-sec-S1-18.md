# X-sec-S1-18 decisions

S1-18 and S1-19 (both low), surface 1, the DHT reply path. The detail stays with the runner until the fix has merged; this file records only what the code now does.

## S1-18: streamed peers are budgeted per source
- **Each source has a fixed share of a streaming session.** A session still remembers at most 32 distinct peers (`STREAM_SEEN`). One source (a responder's IPv4 /24 or IPv6 /48, as `limits::source` keys it) now adds at most `STREAM_SOURCE_SHARE` = `STREAM_SEEN / 4` = 8 of them, so at least four sources share a session. The rest of a source's peers are ignored and not counted.
  - **Loopback has no share,** the same rule `limits.rs` uses for its per-source buckets: no packet from off the host carries a loopback source, and a local test network runs many nodes on it. The 32-peer cap still holds for it.
- **A peer dropped because the caller's channel is full stays unseen,** so a later reply can still deliver it. It's still counted as backpressure.
- **Where:** `Stream::offer` and `stream_source` in `crates/dht/src/node/stream.rs`; the actor passes the responder's source at its one call.
- **Unchanged:** `STREAM_BATCH`, `STREAM_QUEUE`, `STREAM_SEEN`, the metrics, and `dht.streaming_peers` (off by default).

## S1-19: a request ends on values only when each source holds its share
- **The new rule (the runner's call, refining CR-LOOKUP-END's end rule):** a request ends on values when the sum, over sources, of `min(values the source holds, ENOUGH_VALUES / VALUE_RESPONDERS)` reaches `ENOUGH_VALUES`. With today's constants, at least two sources must each hold 4 distinct values.
  - A value counts for the source that sent it first (`Values`, from X-sec-S1-17), so a second network repeating values already held no longer counts. That replaces CR-LOOKUP-END's corroboration-by-repetition rule.
- **Where:** `Actor::has_enough_values`, using `Values::spread`; the separate list of value-carrying networks (`value_nets`) is gone.
- **Unchanged:** `ENOUGH_VALUES = 8`, `VALUE_RESPONDERS = 2`, the leg convergence rule (`closest_answered`), and `dht.lookup_end` (off by default).

## Tested
- `stream.rs`: a source adds at most its share, loopback has none but the session cap holds, a peer dropped for backpressure comes again, and a property test that the cap and the shares hold and the caller never gets a peer twice.
- `lookup/values.rs`: `spread` counts each source up to its share.
- `lookup_end_tests.rs`: 8 + 1 and 8 + 3 don't end a request and 4 + 4 does; a second network counts only its own values; a property test that two networks end a request exactly when each holds 4 of its own; the existing end tests updated to the new rule.
