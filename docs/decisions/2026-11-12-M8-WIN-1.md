# M8-WIN-1 decisions (#777)

- **Service mode watches the installed MSI service; it never launches or stops it.** `cr0-soak.ps1 -ServiceName Lodestar` attaches to the service process, records its PID and start time on every sample, and leaves it running. Reason: G-v1-windows is the owner's soak of the MSI in service mode (plan OQ3), which the child-process collector could not measure.
- **The CR-0 build record is not used in service mode; the evidence binds to the service's binary instead** (runner, 2026-11-12). The collector hashes the executable named by the service's ImagePath (SHA-256 and file version, never the path) at attach and on every sample. The upgrade record carries the hash before and after. The analyzer's `build_binding` check fails if any sample's hash differs from the attach hash, and the upgrade check fails unless the after-upgrade hash equals it and differs from the before hash.
- **What is lost against the CR-0 build record:** no check that the binary was built from a named source commit, and no check that the embedded UI's `index.html` hash matches the build. `-Commit` is recorded but not verified. Those facts come from comparing `service_image_sha256` with the RC's published checksums, which the runner does when it reads the report. The CI MSI smoke (`release.yml`, `/healthz`) covers the embedded UI.
- **A restart can't be proved from the samples alone.** A restart ends the collector's loop before it takes another sample. So `service_restart` passes only if the run finished (`baseline_window_complete`, `service_detached`), every sample has a service identity, and PID, start time and the `start_time_seconds` metric stayed constant. An unfinished or aborted run fails it.
- **Order: upgrade first, then the 24 h soak on the RC, then uninstall** (plan OQ3 leaves the order open). The soak thus measures the upgraded service. "Kept" data after a default uninstall counts as clean, as the user guide says the uninstaller leaves it; `REMOVE_DATA=1` is the other accepted policy.
- **A service attached after its start-up pause has ended starts the baseline at the first sample.** A first sample with `dht_sample_suppression_seconds` 0 counts as "ended", or the baseline would never start. A restarted service may pause for up to 6 h, so the run is about 32 h.
- **`MEMORY_FIT` and its numbers are unchanged;** a test asserts them. Old evidence without the new fields reports `absent`, not `fail`; an unreadable `lifecycle.json` fails.
- **Shared edit:** `docs/soak/tools/test_cr0_collector.ps1` gains tests for the attach path, `Get-SoakServiceIdentity`, the image path and hash, and `Save-SoakLifecycle` (runner-approved).
- **Not run here:** `pwsh` is not available in the build container, so the PowerShell and its tests have not been run.
