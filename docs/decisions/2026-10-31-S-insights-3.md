# S-insights-3 decisions

No owner decision is reversed or loosened, no security or content-safety decision is weakened and no owner-set number changes. The refinements below are the runner's to flag (`docs/owner-decisions.md` §2.19).

**Print layout.** `features/insights/print/PrintReport.svelte` and `print.css` load after the overview mounts (a dynamic import from `Overview.svelte`, one added effect and one mount line), so neither is in the route's first load; the new entry "Insights print layout (on demand)" gates them. Printing hides the top bar, the context bar's controls, the stage strip, loss reasons, cohorts, the second trend chart (harvested), annotations, serve, segments and detail links. What stays: a title and context line (range, compare, time zone: the bar's information as text), the status KPIs with Δs, exceptions, the funnel, the "newly searchable" trend, and a footer with the page URL and generation time (read when printing starts). With the fixture, the report is one page on A4 and on Letter at default margins (checked with `page.pdf`), using `zoom: 0.8` on the page. Dropped, because they do not fit one page: loss reasons, cohorts, the harvested trend, segments, serve and detail links; the first four are on screen under the same headings, and the stage pages carry the detail.

**Forced light.** The theme compiler has no print tokens. While printing, `PrintReport` sets `data-theme="riverstone-light"` and clears the inline custom-theme variables on `<html>`, then restores both afterwards (`beforeprint`/`afterprint` and the `print` media query's change event). Colours stay tokens; no hex. The trend charts are drawn in SVG from tokens, so they re-colour with the theme; they draw again from the new tokens on the print-time resize.

**Digest preview.** `features/insights/digest/DigestPreview.svelte` is mounted in the existing slot through the screen's `Lazy`. It loads on a **"Preview digest" button**, not when the screen opens: no request and no render until someone asks, and the first view of the screen stays unchanged. It first reads the *saved* `insights` section (`GET /settings/insights`) to say the digest is off (and how to turn it on) instead of previewing one that will not go out, then calls `GET /digest/preview?period=<saved period>`. The plain text is shown in a focusable, scrollable `pre` with the mono font; the subject is a text line. **The HTML version is not shown at all**: nothing can inject markup, and the text version carries the same numbers. The help text says the preview uses saved settings, not unsaved edits.

**Sizes.** `InsightsScreen`'s first view stays at 44.4 KB against its 45 KB limit (+0.03 KB for the lazy import); the preview chunk is left out of every Settings first view (`insightsDigest` in `.size-limit.mjs`) and has its own entry: 1.71 KB, limit 1.9 KB. Print: 1.47 KB, limit 1.62 KB. No existing limit changed.
