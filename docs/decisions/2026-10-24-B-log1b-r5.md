# B-log1b decisions, part 4 of 4: pipeline, search, the DHT and fetch

Architecture §12.1, owner's decisions §2.11 and §2.19, B-log1's "Narrow canary limits", and parts 1–2c (`2026-10-23-B-log1b.md`, `-r2.md`, `-r3.md`, `2026-10-24-B-log1b-r4.md`). No owner decision is reversed or loosened, and no security or content-safety decision is weakened. The refinements the runner flags to the owner (§2.19) are marked **(§2.19)**.

- **The sweep is done.** `pipeline/{control,dht,lib,worker,writer}.rs` and `search/{index,live,rebuild}.rs` are converted, one crate per commit, and `NOT_YET_SWEPT` is empty. Every first-party line goes through the catalogue.
- **The pipeline's events** stay in its existing `lodestar-pipeline` catalogue.
  - **Fetch keys are `Torrent`** (`pipeline.lease_missing`, `pipeline.prepare_failed`).
  - **The expired snapshot's path is `Path`** (`pipeline.snapshot_expired`).
  - **Errors are their kind.** The store's error by variant (`sqlite`, `codec`, `corrupt` and so on), the pipeline's by variant, I/O by `ErrorKind`. A plugin's error by its type.
  - **The DHT's sockets are counted** (`pipeline.dht_started {sockets}`), not listed.
  - **Filter notes (§2.19).** `pipeline.filter_rule_skipped` carries what was skipped (`rule`, `override`, `exception`, `always_allow`, `class_rule`), its id and why (`no_longer_parses`, `unreadable`), at every setting. The note's text is never logged.
    - The notes are strings made in `filter/src/load.rs`, which this slice doesn't own. The pipeline reads the five known forms back.
    - A form it doesn't know logs `other` with id 0, so a later loader whose note named a term would still log nothing of it.
    - Follow-up for the filter's owner: return the kind and id typed.
  - **The snapshot purge's problems are counted** (`pipeline.snapshot_purge_problems {count}`). Their text, made in the store, names paths and error text.
  - **`pipeline.prepare_failed` is Debug and `default_on: false`** (it was a `warn`). It follows each fetched torrent that doesn't prepare (malformed or refused metadata), so its peak is the fetch pool's success rate: at the 2,000 a second Build 3 takes for `get_peers`, 1% of them is 20 a second. At (d)'s cost that's about 0.02% of a core, well under 1%, but about 490 MiB a day, over the file's daily share. Off by default, it joins at Detailed.
- **The search index's events** stay in its existing `lodestar-search` catalogue.
  - **An index version is its schema and tokenizer numbers** (labels), and a renamed folder is `Path`.
  - **Errors are their kind.** Tantivy's text can carry query terms, and the lock errors name the index's folder. The file index's search error is `tantivy`.
  - **`search.enrichment_unreadable` carries the torrent's row id** (`Size`).
- **`dht.key_harvested`** (`lodestar-dht`, new) carries `torrent` (`Torrent`), `source` and `peers` (a count). It's logged where a harvest is counted, in `harvest_hash`: new sampled or `get_peers` keys, every announce and every finished lookup.
  - **Trace, off by default, per part 1's verdict:** 35,000 keys a second from samples would cost 40% of a core and 830 GiB a day.
  - **`dht.harvest_summary`** (Info, on) replaces it. Every 60 s the actor's maintenance tick writes what was harvested since the last summary, by source, and the keys dropped because the pipeline was behind. Nothing is written for a minute with nothing harvested.
- **`fetch.failed`** (`lodestar-peer-wire`, new) carries `torrent` (`Torrent`), `peer` (`Peer`), `error` (the failure kind: `unreachable`, `timed_out`, `refused`, `encryption_failed`, `invalid`, `oversize`) and `attempt` (the transport, `tcp` or `utp`). It's logged for each transport's failed try in `fetch_via`.
  - **Trace, off by default, per part 1's verdict:** 20,000 failures a second would cost 23% of a core and 480 GiB a day.
  - **A peer beside a torrent is peer activity:** it's in the file only with that opt-in and never on the console. `logging::tests` holds this per output for both new events.
  - **`fetch.failed_summary`** (Info, on) gives the fetches that failed since the last summary, by their final kind: a uTP try that fails before a TCP success isn't counted, and a blocklisted address (never contacted) isn't either. Its counters are atomics in `peer-wire`, counted once in `fetch()`. Whichever failed fetch first finds a minute gone swaps them out and writes the summary, so there's no timer and no lock.
    - **Its clock is monotonic** (seconds since the first failure), so a stepped wall clock can't stretch or stall the window.
    - **With no failures there's no summary,** so a quiet spell is folded into the next one; `seconds` says how long it covers. The counts are taken whether or not the summary is on, so turning it on starts fresh.
- **The DHT actor and the fetch loop never block on logging while the events are off** (the default). `log_event!` is the event's striped counter (a relaxed load and store on the thread's own stripe) and a relaxed load of its switch; no field is evaluated. The fetch summary adds an `Instant` read and a relaxed `fetch_add` per failed fetch, and none of these waits.
  - **At Everything,** a line runs `Runtime::record` on the caller's thread. It takes the runtime's fold, ring and file mutexes, each held only to push or write that one line. A rotation's rename happens inline; compression is on its own thread.
  - So at Everything the actor can wait briefly on a mutex another thread holds while writing a line, never on another task. Everything is the diagnostic setting, and the summaries carry the counts at every other.
- **`tracing` is now unused in `crates/pipeline` and `crates/search`.** Their manifests aren't this slice's; dropping the dependency is a follow-up for their owners. `fuzz/Cargo.lock` (not built `--locked`) lacks `lodestar-log` under `lodestar-dht` until it's next refreshed.
- **Narrow canary limits (replacing B-log1's first bullet).** Run 2 can't show a switched-on kind's value for these:
  - **Hashes and peers:** the events carrying them are the crawler's (`dht.key_harvested`, `fetch.failed`, `pipeline.lease_missing`, `pipeline.prepare_failed`), and the canary runs with the DHT off, so it never fetches.
  - **Paths:** they're carried by start-up lines (`app.serving`, the fixture's, `pipeline.snapshot_expired` from the first purge) and by `app.reexec`. Start-up lines are written before the saved switches apply. `app.reexec` comes after `app.stop`, when the file is closed.
  - **Names and queries:** no event carries them.

  `logging::tests` holds each kind's rendering per output, peer activity included, and run 2 still checks that no other kind's value appears.
