# B10a decisions

CRUD for user items, collections and saved searches (`/api/v1`, tag `library`). No owner decision is changed.

- **Lists are bare arrays** where the brief shows them (`GET /collections`, `GET /user-items/labels`, `GET /saved-searches`); paged lists are objects (`items` + `next_cursor`, `entries` + `next_after`).
- **Collection paging** uses `?after=<position>` and returns `next_after` (null on the last page), because a position is the store's own cursor.
- **Counts follow `?hidden=`.** `GET /collections`, `GET /collections/{id}` and the labels endpoint take `hidden` (default false, as search). Write responses (`POST/PATCH` on a collection, add, remove, reorder) count with `hidden=false`.
- **Reorder with entries the client can't see.** The list must name every entry shown by default once, and may also name filter-hidden ones. Adult-while-hidden entries and filter-hidden ones it didn't name keep their slots. Without this, a collection holding a hidden Adult torrent could never be reordered (`stale_order` forever).
- **Remove by hash skips** hashes that are unknown, not in the collection or not shown, so a withheld torrent's presence isn't revealed.
- **Store `Invalid` → `422 invalid_value`.** The field is picked from the store's rule text (labels, note, name, query → `q`, sort); the message repeats the rule, never the value.
- **`note: ""`** (or only whitespace) is a `422` on `note`; only `null` clears it.
- **Saved search `alert` and `rss` are required** on create; `channels` start at 0 and are never changed by the API.
