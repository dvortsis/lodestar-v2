# ENR-8 decisions (#508): detail drawer, adult-enrichment section

Slice ENR-8 (runner brief, 2026-11-05T19:17Z). Spec: plan `docs/plan/2026-11-04-v06-rulepacks.md` §4.3 (ENR-8; Q4), `2026-11-05-ENR-7.md` for the field shape.

- **One component, `detail/adult/AdultEnrichment.svelte`, mounted from `DetailView.svelte`**, which the drawer and `/t/[hash]` share, so one mount covers both. It is a lazy chunk, imported only when the detail has `adult_enrichment`; for everyone else (public viewers, Show adult content off, no match) the chunk is never requested.
- **Text only.** Every value (studio, date, scene title, performer names, the source's name) is rendered as text. The date is shown as the API sent it (`YYYY`, `YYYY-MM` or `YYYY-MM-DD`). Performers are a plain list of names, with a note when `performers_truncated`. The source reads "Matched by <name>", using the source's display name.
- **The link** shows only when it is an absolute `https` URL (`adult/link.ts`) with no user info, control characters or bidi controls, and opens in a new tab with `rel="noopener noreferrer"`. The API (ENR-7) already limits it to the matching source's hosts and sends null today; this is the second check.
- **Messages** are in `detail/adult/messages/{en,zh}.json`, keys `detail_adult_enrichment_*` (the message merge's part-folder rule, so the section never edits the shared detail catalogue, as `provenance/messages/` does; `detail_adult_*` already holds the "Adult, and Show adult content is off" state).
- **Size.** New on-demand entry "Detail adult-enrichment section (on demand)" (1,631 B, limit 1,700 B); the section is left out of "Detail sections (on demand)".
- **Size-limit raise (runner's call, §2.26, 2026-11-05; flagged to the owner).** The one dynamic import in `DetailView.svelte` costs both first views more than their headroom. Detail drawer 27,980 B → 28,033 B (limit 28,000 → 28,064 B); `/t/[hash]` 21,795 B → 21,849 B (limit 21,840 → 21,904 B). The chunk's file name alone is about 25 B gzipped, so no loader fits in the 20 B left. It can't live elsewhere: the other detail sections' files are other slices' paths, and a loader in a lazy section would load late or not at all on the first view. The section's own chunk has its own entry (1,530 B, limit 1,700 B).
- **Untrusted text.** Values go through `showBidi` and sit in the shared `ls-detail-facts` grid, which wraps long runs. A link with user info is refused. The truncation note shows even with no names listed, and blank names are skipped.
