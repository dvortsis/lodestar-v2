# M-auth: setup-token and sign-in flows (2026-10-22)

Decisions made while building the web side of §12's auth (slice M-auth). None changes an owner decision.

1. **Setup is two steps on one page.** §10.10.10 lists the setup token and the admin password as wizard steps 1 and 2. The server takes both in one `POST /setup`, so step 1 only checks the token's format and step 2 sends both. A `bad_token` answer returns to step 1 with the field focused. The remaining wizard steps (3–9) are on `/welcome`, after the session exists.
2. **The token parser is paste-tolerant.** It accepts any case, any or no separators between the groups, quotes, full-width characters (NFKC) and a whole pasted log line, and sends the canonical `XXXX-XXXX-XXXX-XXXX`. More than one distinct token in the paste is refused rather than guessed.
3. **Password strength only advises.** Under 10 characters or over 1,024 bytes of UTF-8 blocks (the server's limits). Anything else is accepted. The hint says "weak" for repeats, keyboard or alphabet runs and the most common passwords; 16+ characters is "strong" whatever it's made of, so a passphrase is never discouraged.
4. **The 429 countdown defaults to 12 s.** The server's limiter refills one attempt every 12 s and sends no `Retry-After`; the client uses the header when it's there (capped at 15 minutes) and 12 s when it isn't. The countdown digits are hidden from screen readers; the wait is announced once, and "You can try again now" when it ends.
5. **`next` is a same-origin path or `/`.** It must start with a single `/`, contain no backslash or control character, resolve to this origin, and not be `/login`, `/setup` or `/api/…`.
6. **The sign-in and setup pages check `GET /auth` on load.** Setup already done goes to `/login`; a signed-in visitor of `/login` goes on to `next`; `/login` on a fresh instance goes to `/setup`. If the check fails, the form shows and the submit reports the problem.
7. **"Sign in" / "Sign out"** are the UI words (the server's messages say "log in"; the UI never shows them).
8. **Where the token is:** Docker `docker logs lodestar`, Unraid Docker tab → Lodestar icon → Logs, Windows `%ProgramData%\Lodestar\logs` (§11 data folder, §12.1 log file; both planned for Windows), Linux `journalctl -u lodestar`.
