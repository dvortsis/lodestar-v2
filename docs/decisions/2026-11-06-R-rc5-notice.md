# R-rc5-notice decisions (#539)

**Text-only corrections to the Legal Notice on `release/v0.5.1`, raised to version 3** (owner, 2026-11-06, directly to the runner: "No, do the text-only rc.5 (a)"; `docs/owner-decisions.md` §2.48 on `main`). The owner's review of version 3 on `main` found four slips that version 2 shares. This PR corrects them for what the v0.5.1 build does, raises `NOTICE_VERSION` to 3, and changes nothing else.

- **What changed and why:** `docs/releases/v0.5.1-rc5-delta.md`. Every sentence was checked against this branch's code: `crates/dht/src/node/peers.rs` (`TTL`, refreshed on re-announce), `crates/lodestar/src/settings/logging.rs` (`file_folder` default `<data>/logs`, settable only through the settings API: the field has no `config.toml` path; `event_log_errors` is a field no code reads, and no Event Log writer exists, so the Event Log isn't named), `crates/lodestar/src/windows/service.rs`, `logging/file.rs` and `windows/temp_log.rs` (start and logging failures go to `%SystemRoot%\Temp\lodestar-service.log`, paths and account names only), `packaging/systemd/lodestar.service` (console output to the journal), `crates/lodestar/src/config.rs` (no restart witness on this branch), `crates/lodestar/src/cli/backup.rs` (unchanged files). The Settings web screens are unavailable on this release, so the log-folder sentence names the settings API, not a screen.
- **Not changed:** the source inventory (this release has the DHT, tracker swarm counts and the Bitmagnet importer only), the backup and credentials sentences (already corrected for this build by LEGAL-1r), the filters paragraph, sections 1, 3, 4, 6, 7 and 11.
- **`NOTICE_VERSION` is 3 (runner, 2026-11-06, §2.33; flagged to the owner under §2.19).** X-legal-docs' rule: a substantive change raises the version, an editorial one doesn't. The runner ruled it substantive: rc.4 users accepted a notice that said everything stays in the data folder, and the corrected §9 asks things of the user. Both cases are set out in `docs/releases/v0.5.1-rc5-delta.md`. The stored field is unchanged (`auth.json` `notice_version`), so an rc.4 install sees the corrected notice once at sign-in; `tests/legal.rs` runs the gate against the constant. **Follow-up on `main`:** `NOTICE_VERSION` there becomes 4, constant and version line only, so `main` stays above every number a build has shown.
- **Operator guidance §4** gains the owner's sentence on what not to send the maintainers. Its other sections already match this build (LEGAL-1r).
- **Gates:** `cargo test -p lodestar-api` on this branch (`legal::` and `tests/legal.rs`); the two notice copies are identical; no other file changes.
