# X-narrow-states-2 decisions

Follow-ups from X-narrow-states (#1080), from the UI review of 2026-11-13 (P9, P12). The runner's calls are in its message of 2026-11-23Z (§2.26, UX). Each is flagged to the owner, who can veto it (§2.19).

- **Alert detail (P9).** The list was a fixed-height card (`max(6 rows, 100dvh − 64 steps)`), so two matches left a blank band. It now ends where its rows end (rows at the row height, "since you last looked" marks pinned to 10 spacing steps with the text cut by an ellipsis, so the sum scales with the root font size), capped at the old maximum. A list with more to load keeps the full height. `e2e/alerts.routes.test.ts` checks 2 matches at 390 px: no band, no layout shift in the list.
- **Table (P9).** `.rt-scroll` had `min-height: 6 rows`, copied from the cards' virtual list. The table isn't virtual and is never mounted while loading (the panel shows its skeleton, and a refine keeps the previous rows), so the minimum held no space for anything. Removed. `search-table.routes.test.ts` checks 5 rows: no band, no layout shift. `ResultsPanel.svelte` and `results.css` are untouched.
- **Wizard progress (P9).**
  - **Numbering.** The architecture (§10.10.10) says the Legal Notice, the setup token and the admin password come first on `/setup`, then "the wizard runs nine steps", listed 1 to 9. Nothing says the three are unnumbered, and the shipped list already numbered the rest on from them (4 to 12) with the first three bare. Following the runner's rule, all twelve are numbered 1 to 12.
  - **Phone (below 640 px).** Each step is a status icon and its number; the current step also reads in full on its own line ("4. Network check · Current step"). Every step keeps its name and status for a screen reader. From 640 px the list reads in full, now numbered from 1.
  - **No "Step n of N" line.** The planned line (and its message key) cost the Welcome route 130 B, over its 16.5 kB limit with no raise allowed, so the current step is spelled out in the list instead; the numbers and the twelve marks carry the count. Welcome is 16.49 / 16.5 kB. Savings that paid for it: one list rendered from one array (the setup steps share the template), the message functions used directly instead of wrapped in arrows, and the visually-hidden rules inside the narrow media query only.
- **Wizard icons.** The pre-steps' check icons are no longer green: they share the list's one template with the other steps, whose done icon isn't coloured.
- **Filters in the sheet (P12).** `.fr { max-width: var(--rail-width) }` capped the groups at 264 px inside a sheet wider than that (up to 480 px for the left sheet, 639 px for the bottom one). Removed: the x-large rail is already held to 264 px by the results grid's first column (`results.css`, untouched). `search-facets.routes.test.ts` checks the 390 and 800 px sheets (the rail fills the sheet) and the x-large rail (≤ 264 px).
- **Discover.** A section whose group is `unavailable` with `reason: null` is hidden like a `needs_*` reason (it was an empty "Not available" shell). **Deferred, as a requirement for the slice that ships Rising:** decide Discover's layout from the response before the first paint, so Newest's width doesn't jump when a side section appears. The side column is out of the DOM until the answer arrives; with no section to show today nothing moves.
- **Size.** No `.size-limit.mjs` change. Alert route 45.93 / 46 kB, Welcome 16.49 / 16.5 kB, Facet rail (lazy) 18.85 / 18.86 kB, Search table mode 6.17 / 6.5 kB, Discover 42.12 / 43 kB, global CSS unchanged. A code comment containing the bare word "divider" made Tailwind emit DaisyUI's `.divider` into the global sheet (+162 B over its limit); the word is gone from new code.
- **Layout-shift checks.** The virtual lists place rows with `transform`, which the layout-shift API doesn't report, so the alert and table e2e also compare the region's height before and after a few frames and the fonts settling (`heightAfterSettling`), and check the gap below the last row isn't negative (a clipped row).
- **The phone stepper's exception to "icon plus text" (runner, §2.26; flagged §2.19).** Below 640 px a step that isn't the current one shows its icon and number, with its status in words only for screen readers. It holds on four conditions, each checked by the e2e "phone stepper" in `wizard.keyboard.test.ts` at 320 px:
  - **a)** The four icons differ in shape (a ticked circle, a skip arrow, an arrow in a circle, an empty circle), not only in colour. Measured against the page background in Riverstone light: done 4.84:1, current 10.70:1, to-do 4.84:1, skipped 4.84:1, all over the 3:1 non-text minimum.
  - **b)** Every step's text reads number, name and status ("5. How it works · Skipped"), the same as the wide layout.
  - **c)** From 640 px every step shows icon plus text; the 1024 px test checks it.
  - **d)** The current step is the visible text ("7. Storage & retention · Current step"); at 320 px it is not cut and the page doesn't scroll sideways.
- **Alert list scroll.** A narrow row's "discovered" fact can wrap onto a hidden line whose absolutely placed visually-hidden span escaped the row's clipping and added 5 px of scroll height at 320 px (7 px at a 20 px root font). The row cells now clip (`overflow: clip`), and the alert e2e runs at 320 and 390 px, with a 16 px and a 20 px root font, asserting no scroll and no clipped row.
- **What `heightAfterSettling` measures.** Only after the rows are visible, and with the web fonts blocked (the specs that count shifts block `**/fonts/**`) its font-settling part checks nothing; it is a regression guard for a size change after the first paint.
- **Sizes as measured** (`npm run size:ci`): Alert route 45.97 / 46 kB, Welcome 16.50 / 16.5 kB (no headroom: later wizard slices must pay with removals), Facet rail 18.85 / 18.86 kB.
