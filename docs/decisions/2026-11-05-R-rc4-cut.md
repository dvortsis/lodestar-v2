# R-rc4-cut decisions (rc.4 onto `release/v0.5.1`)

rc.4 = rc.3 (`bd9300dd`) + #434 + #433 + #442 + #432, each cherry-picked with `-m 1` from its merge on `main`. What went in and what tests it: `docs/releases/v0.5.1-rc4-delta.md`. #448 (`main` merge `e62a8b3b`) is taken as hunks, below. Each conflict and how it was resolved:

- **#434, `docs/user/appendix-b-settings-reference.md`.** `main`'s context has a paragraph about blocklist downloads and `HTTPS_PROXY`, a post-cut feature. Only #434's two THP paragraphs are taken; the blocklist one stays off the release branch. The guide text for THP is word for word #434's.
- **#433 and #442, `docs/soak/tools/**`.** Not taken: the collector and analyser run from `main`, pinned by revision, and aren't shipped. The release branch keeps its copies. The shipped binary needs none of them: it needs only the gauges, which these tools read from `/metrics`.
- **#433, `crates/search/src/index.rs`.** `segment_counts` applies cleanly, byte for byte. Its test sat in `main`'s `population_tests` module, which belongs to the post-cut field-population feature and doesn't exist on the release branch. The test moved, unchanged in what it asserts, to `crates/search/tests/index.rs` as `segment_counts_follow_each_commit_in_both_indexes`, building its four torrents with that file's existing `store_with`/`torrent` helpers instead of `population_tests`' `store(n)`. It uses only public API (`segment_counts`, `segments`, `writer`, `catch_up`, `commit`), so it's equivalent.
- **#433, `crates/lodestar/src/metrics.rs`.** The code hunks (`render_search`'s `segments` argument, `render_memory`) apply cleanly. The conflict is in the tests: `main`'s context includes `failure_labels_cover_every_kind`, a post-cut test the release branch doesn't have. #433's three new tests are taken as they are; that one isn't.
- **#433, `crates/store/Cargo.toml`.** #433 replaces `[lints] workspace = true` with the workspace's lints spelled out, so `unsafe_code` can be `deny` in this crate. `main`'s root lints include `chunks_exact_to_as_chunks = "allow"`; the release root doesn't, so that line is dropped and the crate's lints stay in step with the release root, as the file's comment asks. Same `unsafe_code` change as #433.
- **#432** and **#442's code** apply with no conflict: `crates/log/src/url.rs`, the proptest regressions, both `memstats.rs` and `thp.rs` (both copies) are byte for byte `main`'s.
- **#448** (X-mimalloc-override, `e62a8b3b`): only the musl-target `mimalloc` entry in `crates/lodestar/Cargo.toml` and the `Check malloc is mimalloc's` step in `release.yml`, as the brief says. Taken as hunks, not commits, since its commits mix in bench files; both apply cleanly and leave `Cargo.lock` unchanged. Its bench harness (`bench/examples/mem-cheap.rs`, `bench/Cargo.toml`) stays on `main`; its decisions file cites it there. #448 also changes `docs/metrics.md`: under `override`, SQLite's memory counts inside mimalloc's committed bytes in musl builds. Without that hunk, rc.4's `mem_*` rows would subtract SQLite twice for the musl image. **The runner decided (2026-11-05) to take that `docs/metrics.md` hunk as a third #448 hunk, beyond the brief.** It is docs only. Its link needs #448's decisions file, which comes too, as each other fix's does.
- **Version.** Nothing in the tree changes. rc.3 didn't bump any file either: `Cargo.toml` stays `0.5.1`, and the `v0.5.1-rc.4` tag supplies the suffix (`release.yml` checks the tag's `${version%%-*}` against `Cargo.toml`).
- **Generated files.** `openapi.json` and `schema.d.ts` don't change: no API type changed. `Cargo.lock` gains only `cty` (mimalloc's `extended` feature), as on `main`. `web/licenses/rust.json` gains `cty`'s entry, as #433 does.
