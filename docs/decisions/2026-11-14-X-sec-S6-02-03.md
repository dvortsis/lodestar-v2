# X-sec-S6-02-03 decisions (part 1)

Security fix for held findings S6-02 and S6-03 (both blocking; surface M8-SEC-6, the cluster). Their detail is held under `docs/security/v1/README.md` §5, so this file says only what the code now does. Part 1 covers the lease authority and the coordinator's floor-report writer. Part 2 covers the store side of S6-02 and lands after #857, which owns `crates/store/src/filter.rs` now.

## Leases (S6-03; architecture §19.3, §19.6; CLUSTER-02)
- **Keys waiting for a re-grant count against the cap of the worker that held them last.** `LeaseAuthority` keeps a count per remote worker of the waiting keys whose last holder it was. A worker's room for new leases is its cap less what it holds and what it has waiting. A key leaves the count when it's granted again, to anyone. The built-in worker is never counted.
- **A worker may take its own waiting keys back even with no room left.** Taking them back changes nothing, because they already count against its cap. Without this, a worker at its cap with no other target would wait for good.
- **The waiting queue is bounded:** `MAX_PENDING` is 262,144 keys, about 30 MB. A key that ends past it isn't granted again. It's reported lost as `Evicted` (funnel loss 8, "dropped from the full queue"), so the funnel still balances. A source that finds the key again claims it afresh.
- **A backlog holds back new keys.** While `PENDING_HIGH_WATER` (half of `MAX_PENDING`) keys are waiting, a remote claim for a key that isn't in flight is answered `Busy`. A remote claim for a waiting key still takes it, and the built-in worker isn't held back. This sits in the authority's `claim_batch`, next to the cap, rather than in `GrantAdmission`, so every admission path gets it.
- **Each remote worker has an allowance for keys it hands back unfetched.** Expiry, eviction, revocation, a reconcile and a self-drain all count. The allowance is an eighth of its lease cap per rolling hour, at least 1,024 and never more than the cap. With the default cap of 100,000 that's 12,500 keys an hour.
  - Past it, the key is dropped and reported lost as `Evicted`, and the worker rests for one lease TTL.
  - A lease marked fetched doesn't count, because its result is already in the coordinator's hands. The built-in worker doesn't count either.
  - **Trade-off:** an honest worker that goes away holding more than its allowance loses the excess keys. They would only come back from a source. That's the price of a bound that doesn't depend on trusting the worker.
- **Resting:** a worker that rests gets no new leases (its claims are answered `Busy`) and no re-grants.
  - A worker that says `Drained` rests for `REST_AFTER_DRAIN_SECS` (120 s). This matters for one that stops on its own (CLUSTER-05). One the admin drained stays draining until resumed anyway.
  - A worker past its allowance rests for a lease TTL.
  - A rest is never shortened. The admin's drain and pause work as before.
- **`evict` and `reconcile` keep their signatures.** They read the latest time any authority call was given. The server's tick calls `expire` every heartbeat, so that time is never more than a heartbeat old. This kept callers outside this slice's paths unchanged.

## Floor reports (S6-02, part 1; WK-10d)
- **A worker's floor report holds only a key that isn't stored.** When the writer flushes reports, a key already in the store is left as it is: stored, with no `worker-floor:<id>` tombstone. The coordinator's own filter judged that torrent when it was written, because every remote result is judged again there (`writer::rejudge`). The report still leaves the pending map and still counts in `cluster_floor_reports_written_total`.
- **This supersedes the "Delete, then tombstone" bullet of `2026-11-08-WK-10d.md`.** The floor writer no longer calls `Store::delete_torrents`. A key not yet stored is held as before: refused to every claim, and written as a `worker-floor:<id>` tombstone.
