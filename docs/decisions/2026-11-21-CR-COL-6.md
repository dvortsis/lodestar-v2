# CR-COL-6 decisions

Slice session, 2026-11-21. It adds stage 3's treatments to the collector and analyzer (`docs/soak/tools/`): CR-HINT-FIRST, then X-sampler-cooldown-split, each stacked on the winners so far. These are r5.1's stages, item 3 (`docs/decisions/2026-11-20-path-to-100-cr-spec.md`). It is CR-COL-5's own follow-up (`docs/decisions/2026-11-20-CR-COL-5.md`, "Follow-ups"). CR-SPEC's rules don't change: the fit, the +5 % margin, validity, no peeking and two blocks per outcome are as they were.

- **Who decided:** choices marked "runner" are the runner's calls. The rest are the slice session's, for the runner to confirm.

## The treatments

- **`--treatment hint` (switch `hint_first`) and `--treatment split` (switch `sampler_cooldown_split`)** join `TREATMENT_SWITCHES` and `STACKED`. Like `lc`, both need `--winners`, and the stacking checks are CR-COL-5's, unchanged:
  - the control is exactly the named winners;
  - the treatment's own switch can't be among them;
  - every switch must be recorded.
- Both switches have been recorded in `SWITCH_ENV` since CR-COL-5, so the collector's run.json needed no change. A segment run with an older collector that didn't record them fails `configuration_identity_recorded`, as for `lc`.

## CR-HINT-FIRST's mechanism (rule 5, treatment arm only, void on failure)

- **The checks.** Over the window:
  - `hint_first_marks_hashes`: `dht_hint_first_marked_total`'s delta is above 0.
  - `hint_first_lookups_sent`: `fetch_hint_lookups_total`'s delta is above 0.
  - `hint_ignored_within_keys`: `fetch_hint_ignored_total`'s delta doesn't exceed `fetch_hint_keys_total`'s. When it does, the check's detail carries both counts and says the marks are coming from somewhere unexpected: another source, the switch off, or a private or interactive key (#1003's definitions).
  - Each failure voids the segment, as A1's check does.
- **The control arm isn't checked:** with the switch off the series are exported and stay 0, and nothing says they must not move.
- **The report (`hint_first`), in every segment:**
  - the five counters' deltas;
  - `dht_hint_first_skipped_total` and `fetch_hint_t1_left_total` by reason;
  - the hinted grants (`fetch_admission_grants_total{class="hinted"}`);
  - the peak of the `fetch_hint_t1_waiting` gauge;
  - `absent` for what the binary doesn't render.
- **CR-ADM in the control (runner, 2026-11-21).** #1003's screen shows the T1 tier does little without coordinated admission. So if the named winners don't include `coordinated_admission`, the effect report carries one plain warning (`warnings`, `HINT_WITHOUT_ADM`). It never changes the verdict: a test shows the outcome and τ are the same with and without it.
- **Names** are #1003's, as the runner approved them (docs/metrics.md, "Hint-first (CR-HINT-FIRST, 2026-11-21)"), read from its branch since #1003 hasn't merged.

## X-sampler-cooldown-split's mechanism (rule 5, treatment arm only, void on failure)

- **When the table has filled.** The sampler's table is `dht_sample_cooling` + `dht_sample_inflight`, which stays at most 200,000 (`restart::MAX_ENTRIES`). It has filled at the first window scrape where:
  - that sum reaches 200,000, or
  - `dht_sample_spill_slots` is above 0, since the filter is allocated only when the table first fills.
- **The check, `spill_slots_used_once_table_fills`:** the spill gauge is above 0 at some scrape from then on.
- **A table that never filled in the window wasn't exercised.** The report reads `spill_check: not_exercised`, no check is added, and the segment keeps its verdict. That isn't a failure.
  - **Nor is a table first seen full at the window's last scrape** with no spill there. A cooldown moves out only when the next node needs a place, so there was no later scrape in which to see a spill. `table_filled_after_seconds` still says when it filled.
- **When no treatment segment exercised the split,** `effect --treatment split` says so: `split_not_exercised_b_segments` counts the B segments that weren't exercised, and when that's all of them the report carries a warning. As with a route block that had no opportunity, the outcome then says nothing about the split once the table is full. The verdict doesn't change.
- **Why the exact 200,000:** a nearly full table at some scrapes isn't a full one, and a lower threshold could void a segment whose sampler simply never needed to spill. A table full enough to spill shows spill slots, which count as filled whatever the sum reads at that scrape.
- **The control arm isn't checked:** with the switch off the gauge stays 0.

## Rule 6.4's report for split (reported, never decided on)

- **In every segment** (`sampler_split`), both arms alike:
  - the sampler-full time, the window delta of `dht_sample_full_seconds_total`;
  - the three worst hours of stored per minute (`metadata_new_verified_total{origin="network"}`, from the numerator's hourly rows), worst first;
  - the peak spill slots and table entries;
  - when the table filled, and `spill_check` in a split segment's treatment arm;
  - the restart gate beside sampler-full time (`restart_gate`: the suppression reason at start and at the window's open, and the suppressed seconds), as X-sampler-cooldown-split's decisions file asks after a restart;
  - `absent`.
- **`effect --treatment split`** lists them per arm (`sampler_split_by_arm`). `effect --treatment hint` lists the tier's counts per arm (`hint_first_by_arm`).
- The gain is still decided only on the numerator (rule 6.2).
- Restarts inside a block aren't expected (the runner, 2026-11-20). Where one happens, `restart_gate` shows the gated time beside sampler-full time.
- **The segment's Markdown** gains a "Hint-first" or "Sampler split" section in its own treatment's segments: whether it's on, the counts or the sampler-full time and spill check, and what's absent.

## The allowlist and missing evidence

- **The collector keeps the new series with fixed label enums:**
  - `dht_hint_first_skipped_total{reason=responder|full|rejected}`;
  - `fetch_hint_t1_left_total{reason=full|aged}`;
  - `fetch_admission_grants_total`'s `class` gains `hinted`;
  - the other six hint series and the split's two have no labels.
  - An unknown label value is dropped, never a crash; a test sanitizes rendered text with one.
- **Required series (rule 6.10), by treatment:**
  - **hint:** the eight hint series in both arms of a hint segment, plus `fetch_admission_grants_total{class="hinted"}` when coordinated admission is on. #1003 renders the hinted grants whatever the switches, but T1's grants only count under coordinated admission, so the requirement follows CR-ADM as the other admission series' does.
  - **split:** the split's two series, `dht_sample_cooling` and `dht_sample_inflight`, in both arms of a split segment.
  - **Every other run** reports them when present and lists them under `absent` when not: never a crash, never a verdict change.

## Tests and the rehearsal

- **`test_analyze_cr_col6.py`.** It writes segments as the collector writes them (test_analyze_cr's `Sim`):
  - **hint:** valid; no marks (void); marks but no lookups (void); more ignored than taken (void, with its note); as many ignored as taken (valid); the control arm unjudged; missing series in each arm; hinted grants required only under CR-ADM.
  - **split:** spilled; a full table without spill (void); a table that fills mid-window without spill (void); not exercised; full only at the last scrape (not exercised); spill slots alone showing the table filled; the control unjudged; rule 6.4's report and the restart gate in both arms; missing series in each arm.
  - **effect:** the CR-ADM warning; the not-exercised warning when no B segment spilled; both leave the outcome unchanged.
  - **Every other run:** the series listed absent in `utp` and `lc` segments; each stage-3 treatment reporting the other's series unjudged.
  - **The rest:** the sanitizer; the effect's warning and per-arm reports.
- **Mutation checks during the slice:**
  - skipping the hint checks fails 4 tests;
  - always passing the spill check fails 2;
  - dropping either treatment's required series fails 6;
  - dropping either warning fails 1;
  - treating a fill at the last scrape as exercised fails 1;
  - `ignored < keys` for `ignored <= keys` fails 1.
- **Unchanged:** the stage-1 golden (`fixtures/cr_col5_stage1_golden.json`) and CR-COL-5's stage-2 rehearsal.
- **The rehearsal:** `RehearsalTests` runs a synthetic stage 3 for each treatment.
  - Each has two blocks, ABBA then BAAB about 12 h out of phase, with 5 minutes between arms. The control has CR-ADM and the lookup-cost pair on as the earlier winners.
  - Every segment goes through `analyze_cr.py segment --winners`, then `effect --treatment hint|split --winners`.
  - In the run for this PR, all sixteen segments and all four blocks were valid. Each outcome was `win`, effect +0.070 (95 % CI +0.060 to +0.080, df 3), with `control_switches` = coordinated_admission, lookup_end, preset_slots, safe_restart, and no warning.
  - The split's sampler-full seconds read 720 in each A segment and 36 in each B, as written.
  - It's synthetic data: it shows the tooling works end to end, not any effect.
