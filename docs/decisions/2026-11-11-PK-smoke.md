# PK-smoke decisions

The M6 exit smoke on every packaged artifact: setup by token, the crawler out of its setup hold, an imported fixture, a search that finds it. Brief: runner, 2026-11-11; plan `docs/plan/2026-11-06-m6-gap-audit.md` rows 85-88 and 120, Q1.

- **One shared helper, `packaging/smoke/flow.py`** (Python standard library only, so it runs on Linux and Windows runners): `fixture`, `setup`, `crawler`, `search`. The three smokes call it, so the flow is the same everywhere.
- **Setup goes through the wizard's own API:** `GET /legal/notice`, then `POST /setup` with the token read from the server's own log and the notice version. The token is printed only as `XXXX-XXXX-XXXX-XXXX`. The password is random, never printed, and kept with the session cookie in a temp folder that the caller removes.
- **"Crawler running" is two fields, not a log grep:** `GET /stats` has `paused: false` (the fetch pool leaves the setup hold when setup completes), and, where DHT is on, `/metrics` has `lodestar_source_up{source="dht"} 1` (the socket is bound). Neither needs a peer or a network fetch (Q1). The Docker and Linux smokes turn DHT on; the Windows smokes keep it off, as they already did, so the runner's network is left alone.
- **The fixture** is a three-torrent Magnetico database made by `flow.py fixture` (the `torrents` and `files` tables and the `files.torrent_id` index `lodestar import` checks). `lodestar import start --source magnetico` needs the server stopped, so each smoke stops it, imports, starts it again, and searches for the word the three names share until all three are found.
- **Every wait is a condition loop with a deadline** of at least 10 s (the helper enforces the floor). No fixed sleeps.
- **Where it runs:**
  - Docker: new steps in the `smoke` job: setup and crawler right after the `/healthz` check; import (a `docker run --rm` of the same image as the same account on the same data folder), `docker start`, search and a second clean stop after the existing stop step. The existing three-container checks are unchanged.
  - Tarball: `packaging/linux/smoke.sh` keeps its checksum, static-link, fixture-refusal, `/healthz`, UI and SIGTERM checks and adds the flow, with a second SIGTERM check.
  - MSI and zip: `Test-Flow` in `smoke.ps1`, on the zip's `lodestar.exe` and on the installed `lodestar.exe`, each with its own temporary data folder. The MSI's service data folder, its ACL checks, Restart now, Repair, upgrade and uninstall steps are untouched, so nothing is weakened. The service's own setup by token already happened in the existing Restart now check.
- **`release.yml`: smoke steps only.** Additions only (no line removed); the `Container logs` step now redacts the setup token, since it printed the first-run token before. Build, sign, minisign, attest, publish, permissions and `environment:` are not touched. The pull-request trigger already lists `packaging/**` and the workflow itself, so the smoke jobs run on this PR.
- **Verification:** `bash -n` and `shellcheck` (warning level clean; one pre-existing SC2016 info). The Linux smoke ran locally against a tarball made from a debug build, minus the static-link and fixture-refusal checks that a dynamic debug binary can't pass: all of the new flow passed. PowerShell was not run or parsed here (no `pwsh` in the session); braces and parentheses balance and CI's Windows job is the proof.
