# PK-smoke decisions

The M6 exit smoke on every packaged artifact: setup by token, the crawler out of its setup hold, an imported fixture, a search that finds it. Brief: runner, 2026-11-11; plan `docs/plan/2026-11-06-m6-gap-audit.md` rows 85-88 and 120, Q1.

- **One shared helper, `packaging/smoke/flow.py`** (Python standard library only, so it runs on Linux and Windows runners): `fixture`, `setup`, `crawler`, `search`. The three smokes call it, so the flow is the same everywhere.
- **Setup goes through the wizard's own API:** `GET /legal/notice`, then `POST /setup` with the token read from the server's own log and the notice version. The token is printed only as `XXXX-XXXX-XXXX-XXXX`: the helper, the tarball smoke's failure logs, the Docker `Container logs` step and the Docker steps' failure paths all redact it, and the Windows failure path does too. The password is random, never printed and never kept; only the session cookie is kept, in a temp folder that the caller removes, and the Docker steps' folders are removed by the `Container logs` step.
- **"Crawler running" is two fields, not a log grep:** `GET /stats` has `paused: false` (the fetch pool leaves the setup hold when setup completes), and, where DHT is on, `/metrics` has `lodestar_source_up{source="dht"} 1` (the socket is bound). Neither needs a peer or a network fetch (Q1). Every smoke turns DHT on for the flow (the Windows flow on its own port, 16881), so "crawling" includes the DHT socket being bound on every artifact (Q1). With DHT on, the server under test does reach the public DHT, as the Docker smoke's containers already did. The existing Windows service and `Test-Serve` checks keep DHT off, as before. A warn-only step (`flow.py crawler --dht`) waits up to 20 s and logs whether the routing table grew above 0 nodes; it never fails a job (Q1).
- **The fixture** is a three-torrent Magnetico database made by `flow.py fixture` (the `torrents` and `files` tables and the `files.torrent_id` index `lodestar import` checks). `lodestar import start --source magnetico` needs the server stopped, so each smoke stops it, imports, starts it again, and searches for the word the three names share until all three are found by name.
- **Every wait is a condition loop with a deadline** of at least 10 s (the helper enforces the floor). No fixed sleeps.
- **Where it runs:**
  - Docker: new steps in the `smoke` job: setup and crawler right after the `/healthz` check; import (a `docker run --rm` of the same image as the same account on the same data folder), `docker start`, search and a second clean stop after the existing stop step. The existing three-container checks are unchanged.
  - Tarball: `packaging/linux/smoke.sh` keeps its checksum, static-link, fixture-refusal, `/healthz`, UI and SIGTERM checks and adds the flow, with a second SIGTERM check.
  - MSI and zip: `Test-Flow` in `smoke.ps1`, on the zip's `lodestar.exe` and on the installed `lodestar.exe`, each with its own temporary data folder. **Refinement (runner to flag, §2.19):** on the MSI the flow does not go through the service. The plan says the server to stop is the service, but an import run as an administrator would put files owned by that account into the service's ACL-checked folder, which the Repair, upgrade and uninstall checks below depend on. The service's own setup by token and Restart now are already checked by the existing steps. The MSI's service data folder, its ACL checks, Restart now, Repair, upgrade and uninstall steps are untouched, so nothing is weakened. The service's own setup by token already happened in the existing Restart now check.
- **`release.yml`: smoke steps only.** Additions only (no line removed); the `Container logs` step and two failure paths now redact the setup token, since they printed the first-run token before, and the one-off import container runs with `--network none`. Build, sign, minisign, attest, publish, permissions and `environment:` are not touched. The pull-request trigger already lists `packaging/**` and the workflow itself, so the smoke jobs run on this PR.
- **Verification:** `bash -n` and `shellcheck` (warning level clean; one pre-existing SC2016 info). The Linux smoke ran locally against a tarball made from a debug build, minus the static-link and fixture-refusal checks that a dynamic debug binary can't pass: all of the new flow passed. PowerShell was not run or parsed here (no `pwsh` in the session); braces and parentheses balance and CI's Windows job is the proof.
