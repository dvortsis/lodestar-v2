# X-ui-plan-r5 decisions (#996)

This slice writes the plan-level findings of the 2026-11-13 UI review (`docs/review/2026-11-13-ui-ux/`, mostly part 4) into `docs/architecture.md` §10 and `docs/ui-glossary.md`. The runner placed the findings in `docs/decisions/2026-11-14-runner-ui-review-placement.md`. The proposals that change §10 were accepted under owner decision §2.69 item 17 (`docs/decisions/2026-11-13-runner-owner-queue.md`). This PR is docs only. The screens that build on it are the later Track U slices.

## What §10 now says
- **D1: the reader (§10.0).** The UI's reader is the §2.14 reader: someone who can install an app from the Unraid app store but doesn't know the DHT, the query language or Lodestar's terms. The section gives four rules: plain words first, syntax second; essentials first, detail on request; explain in place; the safe choice is the one shown. §10.9 and §10.10, which each named their own user ("the self-hoster", "an owner at 2 a.m."), now point to it. Why: part 4 found that each section had imagined its own, mostly expert, user, and that this caused most of its other findings.
- **D2: §10.4 is reordered around words and clicks.**
  - The order is typed words, then filters clicked, then natural phrasing as the bridge, then syntax as the expert layer.
  - Natural phrasing is a visible, labelled button. Its chips are offered unasked when the text reads as phrasing and plain search finds little.
  - The query bar's placeholder is a plain-words example.
  - Field codes in autocomplete and the Builder show glossary labels first.
  - The zero-result state offers a corrected clause ("Did you mean `seeders:>5`?") and never advises "fewer words" when the user typed a filter.
  - Why: item 17.2 accepted the reorder. The rescue and the visible button are part 4's own reading of D2 (U8, U9), which X-zero-rescue builds.
- **D3 and D4, written into §10.4 here.**
  - The facet rail's default groups are now Type, Resolution, Size, Seeders, Language, Year and Discovered (U10). Source, Verified, Extension and Trackers reporting move under More filters. Junk stays at the foot as "N hidden · Show".
  - The Comfortable row has two tiers (U11). Choice facts stay on the row, with availability as one fact in words ("512 seeders"). Leechers, trackers reporting, the backfill marker, v2 and hybrid move to Table mode and the drawer.
  - Discovered's Custom range gains typed From and To dates (U15). The Seeders presets work as plain clauses while counts are unavailable (I6).
  - Why: item 17.2 accepted "reorder Search around words and clicks, with new default facets and row facts" as one proposal. X-row-rail builds these defaults and depends on this slice, but it owns no part of §10. Leaving §10.4's old lists in place would have had it build against the plan.
- **D6: Settings has a "start here" (§10.10.1, §10.10.3).**
  - The Overview reads Needs attention, then Start here, then Changed from default.
  - Start here has one row each for the download client, notifications, updates, backups and the admin password, each with its state in words and one action.
  - It also lists any first-run step the user skipped, which is U1's non-conflicting part (X-settings-find).
  - The list only links to screens, and the full navigation is unchanged.
  - Updates shows "Off · Choose", so nothing is chosen for the user (§2.13).
- **D8: a help section (§10.14.1, new).**
  - Every screen has a Help link to its guide chapter.
  - There's a `/help` landing with search, task chapters and "Something's wrong" (04 §6d).
  - The first use of a glossary term on each screen gets a "What's this?" popover.
  - New primitives HelpLink and TermHelp are added to §10.11.
  - The popover text is its own message key per term (`help.term.<key>`), written under `user-docs`. It isn't copied from the glossary, whose definitions are written for developers.
  - A screen's Help link opens its chapter in the in-app `/help`, which fetches nothing. Only `/help`'s links into the full guide on GitHub leave the app: they open in a new tab, as About's links do, and nothing is fetched until the user follows one (§1.2.3).
  - X-help builds it.
- **D10: "≈" and binary units are explained once (§10.12).** A one-line note explains them the first time an account sees them, and dismissing it is saved per account. After that, a "What's this?" popover explains them.
- **D11: Search's empty state is the home (§10.3, §10.4 States).** It shows one line each for health in words, what's new, alerts with new matches and recent searches, plus two plain-word examples and a quiet Syntax guide link, in place of three syntax examples. The five destinations stay. X-shell-home builds it.
- **The rule behind U12: typed units (§10.12).**
  - A size the user types now means what was typed. `GB` counts in 1,000s and `GiB` in 1,024s, for `size:` and `largest:`. The display stays IEC, and there's no units preference (item 17.6).
  - `piece:` stays 1,024-based, because piece lengths are powers of two: `piece:16MB` read as 16,000,000 bytes would match nothing.
  - **Only the user's own text echoes the typed unit:** the active-filter chip and the `/search?q=` URL. The echo doesn't pass through `formatBytes`, and every measured size stays IEC, so `docs/metrics.md`'s "never SI" holds.
  - **Stored query text is always canonical, in bytes or IEC units** (the runner's call on #996's review). This covers §20 filter rules and their `unless` queries, allow entries and alerts (already AST JSON in bytes). Every release reads it the same way, so a rollback can't widen a hide rule by about 7%. FX-6-I9 staged its own printer change to avoid exactly this. Single-letter forms (`1.5G`) follow the same rule. Why: §20 rules use the query language (architecture §20.2), so decimal text stored in a rule would mean something else to an older parser.
  - **X-units-typed's scope:** the parser accepts typed units; the printer writes canonical stored text; the UI and URL echo the typed unit. It also needs a test that a rule saved after the change matches the same set when the previous parser reads it. It changes `docs/query-language.md` and, for typed input only, the rule `docs/decisions/2026-11-01-FX-6-I9.md` states ("every parser version reads both spellings as 1024-based"). The runner fixes that slice's owns and adds `/security-review`.
  - Why decimal: part 4's case is that most people mean 1,000s when they write GB, and 10 GB and 10 GiB differ by 7%. If "GB" kept meaning 1,024s, "accept GB as typed" would change only the echo and leave the 7% surprise in place.
- **The rule behind U17: "alert" is the only noun (§10.8, §10.14, glossary).** The action is "Create alert" on Search's toolbar, the Alerts page and the palette. The glossary gains `alert` and `create_alert`, and "saved search", "Save search" and "New alert" join its words not to use. The API's `saved-searches` route and the developer sections outside §10 keep their names. X-alert-noun and X-alert-noun-text change the words the user sees.
- **The rule behind U33: `o` asks first (§10.13, §10.16).** A single key that launches another program asks on first use: "Open, and don't ask again" or "Cancel". The answer is saved per account, and Settings → Keyboard can turn the question back on. Today that's only `o`. `s` doesn't ask: it sends to a client the user has already set up. Single-key shortcuts stay on by default (item 17.8). X-client-handoff builds it.
- **§10.10.10's step list now matches the wizard as built** (`web/src/lib/features/wizard/steps.ts`). The Legal Notice, the setup token and the password come first, in that order, on `/setup` (§2.38). Then nine steps run: network, how it works, intensity, storage, download client, rule packs, blocklists, updates, done. The import step waits for the in-app import (B-import-server-2). Why: the old list had no rule-pack step (§2.39) and no blocklist step (§2.9), though those are the steps that keep the wizard at nine. A plan that says "the nine steps stay" has to list the right nine.
- **Consistency edits elsewhere in §10:**
  - the §10.10.8 Overview and Keyboard rows;
  - the §10.10.9 `preferences` list, which gains the open-magnet answer and the dismissed note;
  - §10.5's Summary facts, which gain backfill, v2 and hybrid, the facts the row now hands to the drawer;
  - plain-word examples that don't depend on the fixture's names.
- **The glossary also gains** `size_binary` and `size_typed`, so the popovers and the typed-units rule use one wording.

## Owner decisions that win over a finding
- **U1 and D7, the three-step setup with a checklist, stay declined.** It conflicts with §2.9 (the wizard offers blocklist subscriptions), §2.13 (the wizard asks the update choice) and §2.39 (the wizard shows every rule pack checked). §10.10.10 keeps all nine steps and now says why. Only the non-conflicting part goes ahead: Done links to the Overview's Start here list, which carries the skipped steps.
- **The Updates row on Start here doesn't preselect anything** (§2.13: updates are off until the user chooses, because checking contacts GitHub).
- **Help links don't fetch anything by themselves** (§1.2.3: the system is offline by default).
- **No new facet goes against §2.37 Q4 (no performer facet) or §2.66** (versions grouped, no third-party images).

Nothing in this PR reverses or loosens an owner decision, weakens a security or content-safety decision, or changes a number the owner set.

## Flagged to the owner (§2.19)
- **"GB" typed in a search now means 1,000³ bytes, where it meant 1,024³.** This is the runner's reading of "accept GB as typed" (item 17.6). Stored text stays canonical, so stored queries and filter rules keep their match sets across upgrades and rollbacks.
- **A hand-written `/search?q=` link, bookmark or API call that uses GB reads about 7% smaller after it.** These are ordinary searches, not stored rules, and the URL is the state (§10.3).
