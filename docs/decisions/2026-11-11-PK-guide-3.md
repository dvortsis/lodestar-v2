# PK-guide-3 decisions

User guide for Windows updates, rollback and Restart now (`docs/user/04-install-on-windows-and-linux.md` §4.8, Appendix B). Where the brief and the code on `origin/main` (f05fe580) disagreed, the guide follows the code. Calls marked "runner" are the runner's to confirm.

- **Windows never installs by itself, so the install window doesn't apply.** `update/windows/check.rs` (module docs, lines 18-24; `incapable()`) treats Install automatically as Check and notify, and `policy::install_now` (`update/policy.rs:271`) ignores the window and the wait. The guide says the window holds back automatic installs only and that **Install now** skips it. The brief's "what happens outside the window" has no Windows behaviour to describe.
- **Install now isn't withdrawn while updates are Off or paused.** `policy::install_now` has no mode or pause check, and `check.rs` `install_now_while_off_still_installs` pins it. What Off or a pause does is take back an Install now that is still waiting for the helper (`docs/decisions/2026-11-11-X-win-upd-window.md`). The guide says that, and gives the real reasons the button is missing (`cannot_install`, `check.rs:905`; `portable::cannot_install`, `portable.rs:238`).
- **The web page has no Restart now button yet.** `web/src` never calls `restartSystem`; `SectionForm.svelte` shows only "N changes apply after a restart." The server side is built (`POST /system/restart`, `GET /system` estimate and hint). The guide marks the button **(planned)**, points to `Restart-Service` and Ctrl+C meanwhile, and describes the built behaviour: the service's pause of about a day (`windows/service.rs:351`, including the first start after an upgrade, `docs/decisions/2026-11-08-PK-win-restart.md`), the estimate of the last start plus 60 s, SCM events 7024 and 7031, and the portable relaunch. Runner: tell me if a Restart now button is due before G-m6, and the guide changes in a line.
- **Manual Roll back isn't available on Windows** (`check.rs` reports `rollback.available=false`, `not_built_yet`). The guide says automatic rollback only, and to install the older MSI by hand.
- **Event Log facts.** Service, source `Lodestar`, WARNING, ID 4 while a rollback holds the store (`windows/service.rs:151`, `event_log_text`). Helper, source `Lodestar update helper`, ERROR, ID 900, when it refuses or can't finish an install (`update/windows/helper.rs:1476`). The guide says "Error, event ID 900" for a failed rollback; the rollback's halt event is `rollback.rs:641`; `helper.rs:803` is the "installed but still the old version" failure.
- **Numbers.** Health hold 60 s within 5 min (`helper.rs:91-93`); portable probation 5 min and 3 attempts (`portable.rs:84-87`); default window `03:00-05:00`, wait 3 days (`config.rs:460`).
- **Layout.** The new section is 4.8; Check your understanding moves to 4.9 (no new question: Appendix A is outside Owns). Troubleshooting rows are in the section, so `06-troubleshooting.md` is untouched.
- **Figure.** `windows-update-status-illustration.svg` is an illustration of the status card, listed in `SHOTLIST.md`.
- **Review fixes (fresh Opus self-review).** The guide now says what the code does, not what §10.10.14 and §12.2 describe:
  - **No Windows update history or rollback banner.** `check.rs:1090` returns an empty history. An MSI rollback shows the `install_failed` notice (`check.rs:1006-1022`), and a portable rollback shows nothing on the screen.
  - **The MSI service's probation is Running for 60 s within 5 min** (`helper.rs:1587-1601`). The full self-test is portable only (`portable.rs`).
  - **The first in-app update after a hand-installed MSI can't roll back** (`rollback.rs:725`, `previous_msi` finds nothing: the helper caches only MSIs it installed, `2026-11-09-PK-win-upd-3.md:72`). The guide recommends a backup before every update. Runner: confirm that's acceptable for G-m6, or have the helper keep the installed MSI.
  - **A failed version is skipped**, so Install now refuses it (`policy.rs:275`): the guide says wait for the next release and report it.
  - **Progress steps are Downloading, then Installing only** (`check.rs:1222,1247`).
  - **`appendix-a-answers.md` is outside this slice's Owns,** so the fifth check question was dropped and that file is unchanged.
- **Spec drift for the runner** (the guide follows the code): §10.10.6's Restart now button and dialog aren't built; §12.2's always-available manual Roll back is `not_built_yet` on Windows; §12.2 puts the previous MSI in `<data>\updates`, but it is in `Program Files\Lodestar\updates`; the §12.2 self-test isn't applied to the MSI service.
- **Second review (runner, #708 at 1443a549).** The portable build has no `lodestar.log`; it logs to its console and `data\logs\lodestar.jsonl` (`logging/file.rs:31`), and a failed restore prints to the console (`portable.rs:1157-1163`). The brief's path was wrong, so the code wins. Windows asks for no restart: the helper runs `msiexec /qn /norestart` (`msi.rs:200-201`) and finishes exit 3010 at the next boot (`helper.rs:819-826`). Events 7024 and 7031 come only from Restart now (exit code 80). A rollback paused for retry (`RollbackPending`) writes no event 900. Going back by hand needs the pre-update backup. The in-app "didn't install" notice's advice to run the installer clashes with the guide's "don't install the failed build by hand"; the runner is routing that as a code follow-up.
