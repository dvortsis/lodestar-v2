# X-filter01-rejudge decisions

The re-judge that X-filter01-fix (#843) left as a follow-up, the store's hold precedence for kept holds, and the review nits from X-filter01-hardening (#855). Every hold stays fail-closed. The detail of the fix stays held under `docs/security/v1/README.md` §5.

## Calls
- **The core has a version** (§20.5): `CORE_VERSION` in `lodestar-filter`, now 2. It goes up whenever a change to the core could judge a stored torrent differently, so a later core fix reuses it. 1 is the core before it read torrents whole; a store that records no version was judged by that one. Runner, by message.
- **The store records the version its torrents were judged by** in `settings` (`filter.core.judged`), and a pass under way records its version and the last torrent id it finished (`filter.core.pass`, `filter.core.after`). No schema change and no migration: these are plain settings rows. The marker only rises, so a downgrade judges nothing again and leaves the marker as it was.
- **The writer runs the re-judge in the background** (`crate::core_rejudge`), beside the enrichment backfill: 256 stored torrents per batch, in id order. Its place is written after each batch's holds commit, so a restart resumes there; one between the two judges that batch again, which holds nothing twice. A batch whose classification rules changed under it is judged again. A store error waits out the backoff, as the backfill does.
- **What it applies:** each stored torrent is judged as ingest judges it: on detection's own classification, so a Not adult correction or rule never takes it out of the Adult-only core checks, and as Adult too where an Is adult correction, rule or always-adult source says so, the stricter verdict kept (an adult hold when only that reading holds it). A decision that holds the torrent back is applied whatever rule made it, and so is any core decision; the packs' and your rules' marks have their own re-evaluation (§20.3). A held torrent is deleted and its hashes are quarantined or tombstoned, marked for intake first, as the backfill's holds are.
- **Fail-closed:** a torrent whose file list won't read, or whose judging panics, is held under CS-0a, never left shown. Only a store failure (not a row's own) stops a batch.
- **A CS-0a hold is never judged again from its sealed name.** The re-judge reads stored torrents only, never quarantine rows. The stand-in re-judge, which does read sealed names, counts a kept row as kept and never releases it.
- **Kept holds outrank every other hold** (§20.7). In a rollback's merge, a kept hold ranks above the floor's own rules, and a quarantine write replaces a kept row only with another kept hold. So no `+adult` or stand-in hold can take a CS-0a row's place, and no release by rule can then free it. Runner, by message.
- **The meter's second read is a strict bound** (§20.8): a path read twice is charged its own first read plus every word and character it holds as if the caches were cold. So the core's second read can never cost more than the meter counted. Runner, by message.
