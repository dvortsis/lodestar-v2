# X-filter01-rejudge decisions

The re-judge that X-filter01-fix (#843) left as a follow-up, the store's hold precedence for kept holds, and the review nits from X-filter01-hardening (#855). Every hold stays fail-closed. The detail of the fix stays held under `docs/security/v1/README.md` §5.

## Calls
- **The core has a version** (§20.5): `CORE_VERSION` in `lodestar-filter`, now 2. It goes up whenever a change to the core could judge a stored torrent differently, so a later core fix reuses it. 1 is the core before it read torrents whole; a store that records no version was judged by that one. Runner, by message.
- **The store records the version its torrents were judged by** in `settings` (`filter.core.judged`), and a pass under way records its version and the last torrent id it finished (`filter.core.pass`, `filter.core.after`). No schema change and no migration: these are plain settings rows. The marker only rises, so a downgrade judges nothing again and leaves the marker as it was.
- **Only what the earlier core couldn't read whole is judged again** (runner, §2.33). A cheap check with the real tokenizer (`read_whole_by_v1`) finds the torrents within the earlier core's caps: at most 1,000 files, no padding file, and at most 128 tokens in the name and every path, in both readings. Their judgment stands, and only the marker moves on. Every other stored torrent is judged again, and one that can't be read is held.
- **Torrents the earlier core couldn't read whole stay visible under its judgment until the pass reaches them.** The pass runs first after start, before the enrichment backfill, the import-candidate refile and the unverified sweep. Measured in memory on the build VM, it takes about 11 s per million stored, with 2% past the caps (`rejudge_rate`). A store on disk, sharing the writer with ingest, takes longer. Hiding them from every output until they're re-judged is deferred to the owner, as a slice of its own.
- **The writer runs the re-judge in the background** (`crate::core_rejudge`), one batch per turn between ingest batches: 256 stored torrents per batch, in id order. Its place is written after each batch's holds commit, so a restart resumes there; one between the two judges that batch again, which holds nothing twice. A batch whose classification rules changed under it is judged again. A store error waits out the backoff, as the backfill does.
- **What it applies:** each stored torrent is judged as ingest judges it: on detection's own classification, so a Not adult correction or rule never takes it out of the Adult-only core checks, and as Adult too where an Is adult correction, rule or always-adult source says so, the stricter verdict kept (an adult hold when only that reading holds it). A decision that holds the torrent back is applied whatever rule made it, and so is any core decision; the packs' and your rules' marks have their own re-evaluation (§20.3). A held torrent is deleted and its hashes are quarantined or tombstoned, marked for intake first, as the backfill's holds are.
- **Counts are logged, never names or hashes.**
  - `pipeline.core_rejudge_started` fires when the pass starts or resumes on a run, with its totals so far.
  - `pipeline.core_rejudge_done` fires at the end: the torrents found past the caps and judged again, how many are now held, and how many of those couldn't be judged at all.
  - The totals are kept with the pass's place, so they add up across restarts.
  - The events' labels in the logging screen are a follow-up outside this slice; until then the screen shows their ids.
- **A rollback or restore judges its torrents again** when the copy's marker is older. A rollback never carries the store's marker into the copy, so the pass runs on the next start. An import is judged at ingest by today's core.
- **Fail-closed:** a torrent whose file list won't read, or whose judging panics, is held under CS-0a, never left shown. Only a store failure (not a row's own) stops a batch.
- **A CS-0a hold is never judged again from its sealed name.** The re-judge reads stored torrents only, never quarantine rows. The stand-in re-judge, which does read sealed names, counts a kept row as kept and never releases it.
- **Kept holds outrank every other hold** (§20.7). In a rollback's merge, a kept hold ranks just under the floor (its own rules, then a worker's floor report) and above every adult or other hold, and a quarantine write replaces a kept row only with another kept hold or a floor hold. So no `+adult` or stand-in hold can take a CS-0a row's place, and no release by rule can then free it. Runner, by message.
- **The meter's second read is a strict bound** (§20.8): a path read twice is charged its own first read plus every word and character it holds as if the caches were cold. So the core's second read can never cost more than the meter counted. Runner, by message.
