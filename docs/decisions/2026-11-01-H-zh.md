# H-zh decisions

- **zh auto-select is now on for complete catalogues.** With every en key translated, zh coverage is 1.0, above the 0.95 gate (`AUTO_LOCALE_COVERAGE`, `docs/architecture.md` §10.14). Browsers that prefer zh-CN or another zh tag now get Chinese without choosing it. This is a user-visible change: a zh-preferring browser that used to see English now sees Chinese. An explicit language choice still wins. Runner ruling under `docs/owner-decisions.md` §2.26; the gate itself is unchanged.
- **Natural phrasing size limit raised from 1.64 KB to 1.75 KB** (`web/.size-limit.mjs`). The zh strings for the natural-phrasing messages are inlined into that on-demand chunk, adding about 60 B gzipped. The zh text was trimmed without dropping meaning; the rest is the budget increase. Runner ruling, §2.26.
- **Locale tests now stub the coverage gate** (`web/src/lib/i18n/locale.test.ts`). The gate tests use known coverage values instead of the live catalogue, and a new test checks that zh-CN auto-selects at full coverage.
- **The fallback probe no longer uses a fallback key.** The catalogue has no untranslated key left, so the rendered test checks the zh path. The en fallback guarantee is enforced by `web/scripts/messages.zh-complete.test.ts`, which fails on any missing zh key.
