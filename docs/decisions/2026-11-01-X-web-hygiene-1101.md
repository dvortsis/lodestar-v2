# X-web-hygiene-1101: CSS headroom, a guard that can't pass vacuously, chunk-load catches

Runner brief, 2026-11-01. Follow-ups from #302 and #304. No owner decision changes.

## CSS entry: 19.93 KB -> 19.29 KB gzip

Tailwind scanned `web/scripts/*.test.ts` and `*.test.ts` files for class names, so sample strings in
tests became real utilities: `!mt-[2px]`, `!inset-x-15`, `bg-[#fff]`, `w-[13px]`, `size-11`,
`space-y-11`, `gap-15`, `p-12`, `line-clamp-3`, `leading-5`, and the words `stat` and `stack`,
which pulled in daisyUI's `.stat*` and `.stack*` component CSS (~0.4 KB gzip together).
`src/app.css` now has `@source not "../scripts"` and `@source not "../**/*.test.ts"`.
Nothing in a non-test file used any removed rule (checked by grep), so no rendered pixel changes.

Also gone: `bg-primary/50`, `hover:bg-primary`, `duration-150`, `gap-x-16`, `gap-x-px`, `grid-cols-12`, `h-8`, `h-96`, `m-3.5`, `opacity-95`, `p-11`, `top-20`, `w-4`, `w-64`, `[mask-type:alpha]`, `stats-horizontal/vertical`. The biggest contributor was daisyUI's `.stat`/`.stack` blocks; the rest are single utilities.

- Limit: `CSS` entry 20 KB -> 19.65 KB (measured 19.32 KB after merging main, plus the 0.3 KB headroom floor). Never raised.
- Measured twice after two builds: identical.

## Guard

`modulesIn()` in `web/scripts/first-load.mjs` threw nothing when the chunk graph was missing, so
the first-load guard could pass without checking. It now throws when the client manifest exists but
the graph doesn't (no build at all still returns `[]`). Test in `first-load.test.ts`.

## Chunk loads

Failed-chunk handling uses the repo's two-argument form `.then(ok, () => {})`, so only the import
failing is swallowed; an error thrown by the registered callback (e.g. a duplicate key id) still
surfaces. Silent (shortcut registration or a user action that does nothing without its chunk):
`DetailHostBody.svelte`, `detail/commands.ts` (`c`/`o`), `ResultsPanel.svelte` (detail commands),
`RowActions.svelte` (copy magnet), `routes/t/[hash]/+page.svelte`, `auth/session.svelte.ts`
(refetchRegion), `AlertsListPage.svelte`, `AlertDetailPage.svelte`, `routes/search/+page.svelte`.
With the existing error toast: `shortcuts/boot.ts` (toggle single keys).

`detail/commands.ts` and `RowActions.svelte` would better show `detail_magnet_unavailable` as a
toast, but importing the toast and message there grows the "Detail sections (on demand)" entry
by 130 B past its 34.5 KB limit (headroom is under 50 B), so they stay silent here. A follow-up
that makes room in that entry can add the toast.

Not changed (follow-up slice; each needs its own failure state or a size check):
`DetailView` (Contents, Parsed, ErrorState), `DetailHost`, `Live.svelte` (FilterStrip, bar.css),
`FacetsHost`, `CardList`, `ResultsPanel` (Table, BulkBar, RowPick, RowActions, `live/extras`,
`bulk/ops`, the `$lib/keys` + `./commands` pair), `RowActions` (Menu), `StateScreen`, `Chrome`
(Toaster, ErrorView, CommandPalette, progress), `Shell`, `SettingsForm` (`events.svelte`),
`Overview.svelte` and `routes/+layout.ts` (keys, i18n boot).
