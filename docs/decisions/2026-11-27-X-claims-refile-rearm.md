# X-claims-refile-rearm decisions (#1138)

Slice session, 2026-11-27. Spec: architecture §20.5 and §20.9; `docs/decisions/2026-11-27-X-purge-index-shapes.md` (#1135) and its review; the runner's brief `briefs/X-claims-refile-rearm.md` (2026-11-27T10:52Z). Baseline: `main` at 3bfe7246.

- **A refile that reports `rederive` re-arms the writer.** `ClaimsRefiled::rederive` was ignored at both pipeline call sites, so a held-back answer's canonical title (ENR-10) stayed the record's effective title until the backfill next started from the top (a restart, a purge or a version change). Both sites now raise `Ctx::reenrich`: the refile sweep (`unverified::refile_step`, which also reports it as `Step::rederive`) and ingest's drop of a source's earlier claims when its next find hits your rule (`drop_source_claims`). One helper, `rearm`, so the two can't drift. The writer's refile sweep built its `Ctx` without the flag, so it now passes `reenrich` as ingest's does (`writer.rs`, granted by the runner 2026-11-27T10:55Z).
- **`drop_one` and `mark_claims_unenriched` move the classification generation** in the transaction that makes their change, when a row they touch could have supplied a served answer or doesn't decode (`shaped_or_unreadable`), as the purge's Claims stage and the refile do. A backfill batch on another connection that read the old answer, or the old terms, is then refused (§20.9) and runs again, instead of writing the title back over the mark. Plain feed claims leave the generation, so a refresh or expiry of claims that shape nothing doesn't make every in-flight batch run twice. `drop_claims_outside` moves it once per transaction, however many rows shaped.
- **`mark_claims_unenriched` logs for the index in its transaction.** Each torrent whose row `shaped_or_unreadable` gets a `reindex_log` entry beside the mark, so the index drops an answer the new terms no longer let it serve at its next pass, and a crash after the commit still leaves it logged. Nothing is collected in memory: the source's rows are streamed through the `(source_id, …)` index and each logged row is inserted as it's read. It decodes every one of the source's rows inside one write transaction, where it used to be a single `UPDATE`; that's a longer writer stall for a large source, but it runs once per terms change.
- **A terms change writes the new terms record in the same transaction** (found while doing this slice; the runner chose the fix, 2026-11-27T10:56Z). `identify::record_terms` used to mark first and write the record after, in two transactions. A backfill batch that read the generation after the bump and the terms before the write saw "redistributable" under a current generation, wrote the title back, and the torrent was never derived again. `Store::mark_claims_unenriched(source, record)` now takes the record and writes it (`TERMS_KEY`) with the marks, the log entries and the generation, so a batch reads either the old terms under the old generation, and is refused, or the new terms. A failure writes none of it, and the old record still reads as redistributable, so the next call marks again, as before. The plugin-state write is shared with `compare_and_set_plugin_state` (`put_state`), so the key limit holds on this path too.
- **Re-arming after a terms change.** `record_terms` returns whether it marked anything; the identify runtime raises the writer's backfill flag when it did. The flag reaches the runtime by `IdentifySource::with_reenrich` (the host passes `PipelineConfig::reenrich`, as the writer's other jobs get it), a builder rather than a new argument to `IdentifySource::new`, which ten plugin test suites outside these owns call. A host that calls `record_terms` itself when it registers a plugin raises the flag on `true` (its doc says so); no host does yet, and `crates/api` (outside these owns) only calls it in tests, where the `bool` is unused.
- **`identify_sweep` reads the details section once.** `Claims::into_identification` takes the claims and returns the section, its confidence and the ids, with the same test as `Claims::identification`; `Store::served_identifications` uses it, so `served_identifications_and_record_shapes_agree_on_every_shape` still holds the served rule and the shape rule together.
- **#1135's decisions heading** now names its PR: `# X-purge-index-shapes decisions (#1135)`.
- **The identify runtime's own drops re-arm too** (the self-review's finding; the runner extended the grant, 2026-11-27T11:31Z). A refresh that no longer matches (`drop_claims`) and the retention sweep (`sweep_expired`) mark the torrents they touch, now move the generation and log for the index, and raise the flag through the same `IdentifySource::rearm` as a terms change, so a dropped or expired answer's title leaves the record at once.

## Tests
- `crates/store/tests/unverified.rs`:
  - `a_backfill_batch_that_read_an_answer_is_refused_after_it_leaves`: for a drop, an expiry and a terms change, a batch on a second connection reads the generation and the claims, waits on a channel (30 s deadline) while the main connection makes the change, then writes and is refused; the mark stays. Plain claims leave the generation.
  - `a_terms_change_logs_and_marks_together_or_not_at_all`: the answer's torrent is logged, a plain claim's and another source's aren't; an injected `reindex_log` failure rolls back the marks, the terms record and the generation.
- `crates/pipeline/tests/unverified_details.rs::a_refile_that_holds_back_an_answer_rearms_the_backfill`: at both sites, the flag is raised, the record keeps the title until the backfill runs, and loses it when it does.
- `crates/pipeline/src/writer.rs::a_refile_that_holds_back_an_answer_starts_the_backfill`: the writer's own refile sweep raises its flag.
- `crates/pipeline/src/identify.rs::a_batch_between_the_marks_and_the_record_cant_write_the_title_back`: a test-only hook in `record_terms`, right after the marks, runs a backfill batch on a second connection (channels, 30 s deadlines). It reads the new terms, so the title doesn't come back. With the record write moved back after the marks, the same batch reads the moved generation and the old terms and stores the title for good: the test fails.
- `crates/pipeline/tests/identify.rs`: `tightened_terms_start_the_backfill` (the runtime raises the flag on a terms change), `a_stale_claim_is_refreshed_and_a_miss_drops_it` and `the_runtime_sweeps_its_expired_claims` (it raises it on a refresh drop and an expiry, and not before), and `tightened_terms_take_the_title_back` checks `record_terms`' return.
- `crates/search/tests/enrichment.rs::a_refiled_answer_leaves_the_record_and_the_index`: after a refile reports `rederive` and the backfill pass runs, neither the record nor the index has the canonical title; the torrent stays indexed.
- **Mutations**, each reverted alone, each killed: the refile sweep's re-arm, ingest's re-arm, the writer's `Ctx` flag, the runtime's flag on a terms change, a refresh drop and an expiry, the expiry's, the drop's and the terms change's generation bump, the terms change's log entry, and the terms record written after the marks.
