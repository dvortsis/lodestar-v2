# X-ui-checks-2: overlay timings and radius, status pill states, the phone alert-and-Send flow (#PR)

Date: 2026-11-22. Decided by the build runner (split of `X-ui-checks`).

## Decisions

- **Overlay timings and radius.** A dialog and a bottom sheet are read on `/dev/ui/overlays`: computed animation name and duration while open and while leaving, and the four corner radii (16 px on a dialog, 16 px on a bottom sheet's top corners). The sheet values come from `docs/design-tokens.md` (§6 `--radius-sheet` 16 px; §9 `--duration-drawer-in` 300 ms and `--duration-drawer-out` 200 ms). The dialog's fade is an implementation choice in `web/src/lib/ui/overlays/overlays.css` that the tokens don't spell out: it reuses `--duration-fast` (150 ms) in and `--duration-drawer-out` (200 ms) out, and the spec now holds it there. The exit is read from an `animationstart` listener, because the panel is removed when the 200 ms exit ends. The right-hand drawer and popovers are not measured.
- **Rebuild and paused states.** The rebuilding and idle pill states and the Search banner already have specs. This part adds the paused pill and the failed-rebuild pill, on a desktop and a phone width. On a phone the words are screen-reader text, so those cases check the pill's accessible name and that it fits the viewport. The stale Insights banner already has `insights-stages.routes.test.ts`.
- **Phone alert-and-Send.** One touch spec at 390 px: Alerts list, one alert, Open in Search, tap a row, Send to the client, confirmation. The spec goes by Open in Search. Tapping an alert row opens the torrent page directly (`/t/<hash>`); that path to Send is not walked here and is left out on purpose.

## Not done

- **The layout-shift (CLS) check is dropped,** as the runner decided. Review 03 listed it; nothing here measures layout shift.
