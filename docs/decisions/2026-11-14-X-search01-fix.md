# X-search01-fix decisions

- **SEARCH-01 (blocking, search; the indexer's document builder) fixed.** Its detail is held under `docs/security/v1/README.md` §5 until a release with the fix is published. This file says only what the code now does.

## Calls
- **A torrent's extensions are gathered in one pass** (architecture §8, the `ext` field). `distinct_extensions` keeps each extension once, in the order first seen, and looks up what it has seen in a set. The cost of building a document's extensions follows the number of files, whatever their names are.
- **At most 1,024 distinct extensions are indexed per torrent** (`MAX_EXTS`), the first in file order. An extension is at most 10 ASCII letters and digits, so the `ext` field of one document holds at most about 10 KB of terms.
- **What a search sees:** nothing changes for a torrent with up to 1,024 distinct extensions, which is every ordinary one. For a torrent with more, `ext:` at the torrent level finds it by the first 1,024 only. The file index still carries every file's extension, so a search inside files is unaffected.
- **No schema change and no rebuild.** Documents written before this hold the same terms unless they had more than 1,024 distinct extensions; those keep what they have until they are next written.
- **Why 1,024** (runner's call to confirm, §2.19): far above any real collection's variety, and small enough that one document's field stays a few kilobytes. It is not an owner-set number.
