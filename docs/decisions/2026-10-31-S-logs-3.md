# S-logs-3 decisions: Logging event labels, console format labels, catalog refresh

Follow-ups from #289 and #294 to Settings → Logging (§10.10.12, §12.1).

- **Event names and help.** Every event in the server's catalogue (`logs_catalog.txt`, 196 events) has a plain name and one line of help, in en and zh.
  - They load as their own chunk, `event-names.ts`, when the event list or the data kinds mount. Logging's first view doesn't carry them. The chunk is gated on its own: measured 10.73 KB, limit 11.8 KB (measured + 10%).
  - Lookup is by event id. A test checks that the server's `label_key` and `help_key` are always `logs.event.<id>.label` and `.help`, so the id is enough.
  - An event the client doesn't know, or one shown before the chunk arrives, shows its id and no help.
  - A vitest test reads the golden catalogue and fails if an event has no name or help in either language, or if a name has no event.
- **Console format labels** are back in Logging's label map: "Plain text (text)" and "JSON lines (json)". Runner decision (§2.26, brief S-logs-3): that map's limit goes from 0.86 KB to 0.95 KB (measured 0.89 KB). No other limit changed.
- **Catalog refresh.** The catalog reloads when the tab becomes visible again and on the 30 s tick (every tick, not only after a deadline or an error). A reload never starts while another is in flight; changes made on this page still reload directly. A failed reload keeps the last catalog and sets only the error, so the banners follow #289's rules.
