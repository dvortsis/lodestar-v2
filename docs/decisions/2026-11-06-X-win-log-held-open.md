# X-win-log-held-open decisions

Slice X-win-log-held-open: the Windows service's `lodestar.log` (`crates/lodestar/src/windows/logfile.rs`) when another program holds it open. It covers architecture §12.1 (rotation) and matches the JSONL file sink in `crates/lodestar/src/logging/file.rs`.

- **A failed rotation waits 60 s before it's tried again.** On Windows the rename at the 16 MiB cap fails while a program holds the file without `FILE_SHARE_DELETE` (a log viewer, say). Before this slice, every following record closed the file, tried the rename and reopened it. Now a failed rename sets a retry time `ROTATION_RETRY` (60 s) ahead, and records go on into the current file until then. This is the same value and meaning as `logging/file.rs`: only a successful rename clears the wait, and each failed attempt starts a new one. Once the reader lets go and the delay has passed, the next record rotates first.
- **Records still land whole and in order.** The retry never drops or splits a record. The file is closed only for a rename attempt, so at most once per 60 s while it's held.
- **Hard ceiling: twice the cap (runner's call, §2.26).** `logging/file.rs` stops writing lines when a file that can't rotate reaches the folder's total cap. `lodestar.log` has no total-cap setting, so the ceiling mirrored here is twice the per-file cap (32 MiB): a record that would take a non-empty current file past it is refused with an error, until a rotation succeeds. A rotation moves the whole current file to `lodestar.log.1`, so either file can reach the ceiling and the folder holds at most four times the cap (64 MiB). Before this slice there was no bound at all once a rename failed: records went on into the current file however large it grew. Below the ceiling the bound is the cap plus what 60 s of writes adds per failed attempt; the service's console log writes far less than 16 MiB a minute, so the ceiling only matters when a reader holds the file for many minutes. Records refused at the ceiling are the only ones lost, as at the JSONL sink's cap. The runner may pick another ceiling under §2.26; it is one constant expression (`LogFile::ceiling`).
- **Tests use a test clock, not sleeps.** `write_record_at` takes the time, so the tests step past the 60 s without waiting. Platform-neutral tests make the rename fail with a non-empty folder at the rotated name. The `cfg(windows)` test holds the file with `share_mode(FILE_SHARE_READ | FILE_SHARE_WRITE)` and runs in CI's `test (windows-latest)` job.
