# PK-win-upd-1 decisions: Windows update check and notify

On Windows, the service and the portable build now check for updates and notify, as Linux does (architecture §12.2; plan `docs/plan/2026-11-06-m6-gap-audit.md` §2.3, §4.3, Q13). Install and Roll back wait for PK-win-upd-2, PK-win-upd-3 and PK-win-portable-upd. The code is in `crates/lodestar/src/update/windows/`, `layout.rs` and `mod.rs`. Calls marked "runner" are the runner's under §2.19; the owner can veto them.

## The check
- **It reuses the Unix pieces unchanged.** `update::window`, `update::policy`, `update::check` (the source, the hop allowlist and the request), `trust_file` and `lodestar_update::check` now compile on every OS. The Unix `engine` doesn't: it's built around overlays, the supervisor and installing. `windows::check::Notifier` runs the same schedule as the engine: every 6 hours plus a random minute, a manual check at most once a minute and one at a time, a corrected clock noticed within 15 minutes. It uses the same `updater.json` and `skipped` formats, the same `updates` events and the same `/updates` DTO.
- **No overlays on Windows,** so the trust floor is the embedded statements alone. A missing `trust.json` is rebuilt from them. A damaged one is never overwritten and blocks installs (`trust_damaged`), as on Unix.
- **Writes are acknowledged only once they're written** (temporary file, flush, rename): a skip or a pause is acknowledged only after that. On Windows a power cut right after can bring back the previous file (see the layout table). A check's times that can't be written stay in memory (`check_not_saved`). An `updater.json` that can't be read is never overwritten by a check, only by a pause or resume (`updater_unreadable`). Windows has no "held in process" state: nothing installs automatically there, so a failed pause has nothing to hold.
- **History is empty on Windows,** so `POST /updates/history/clear` answers the status unchanged.

## How the install kind is detected (fail safe)
- **The MSI:** the process runs as a service's virtual account (whose SID starts with `S-1-5-80-`, from `whoami`, read once) and is `%ProgramFiles%\Lodestar\lodestar.exe`. The MSI installs only there (`main.wxs` `WrongInstallFolder`).
- **Portable:** not a service account, not under `%ProgramFiles%`, `Start Lodestar.cmd` beside the executable, and the data folder that launcher sets (`<exe folder>\data`).
- **Otherwise unknown.** Paths are compared case-insensitively, with either separator and without a `\\?\` prefix. Nothing comes from the data folder.
- **Artifacts (runner):** `select` returns the MSI for the MSI, the portable zip for portable, and nothing for an unknown kind. It never guesses. Releases are shown only when they have this installation's artifact for this build's target. With an unknown kind, any MSI or zip for the target counts. So an unknown kind is still notified, and a release without a Windows build (a Linux-only fix) isn't shown on Windows. A build for a target the manifest doesn't ship sees nothing.

## `/updates` on Windows (runner)
- **`unavailable` is null**, where it used to be `"windows_helper"`. `windows_helper` stays in `UpdatesUnavailable` for clients and older servers, so there's no contract change and nothing to regenerate.
- **`capability.reason` and `rollback.reason` are `not_built_yet`.** The Updates screen already words that reason ("Self-updating isn't built into this version yet."). A dev build names `dev_build` first, and an unreadable `skipped` names `skipped_unreadable`.
- **`policy::Reason::NotBuiltYet`** is a new value, so that `mode: auto` behaves as Check and notify through the same `Block::Capability` rule. `capability.reason` is a string in the DTO, so `openapi.json` doesn't enumerate it and nothing is regenerated. The DTO's doc comment listing reasons (`crates/api/src/dto/updates.rs`, outside this slice) doesn't name `not_built_yet` yet.
- **Install answers `409 install_unavailable` and Roll back `409 rollback_unavailable`,** both with reason `not_built_yet`. Skip and pause work, so a skipped version stays hidden after PK-win-upd-2 lands.
- **The service holds `<data>\bin\.lock` for its whole run** (it's `<data>\bin`'s one writer). While another process holds it, nothing is fetched or written (`bin_unavailable`), and every later check, skip or pause tries to take it again. A relaunched portable copy that starts before the old one has let go therefore isn't left without updates for its whole run. PK-win-upd-2's helper must take the lock before it writes, which it can do only once the service has stopped.

## The Windows layout (`layout.rs`)
| Guarantee | How | Rests on |
|---|---|---|
| No reparse points | `<data>\bin` and every file in it are opened with `FILE_FLAG_OPEN_REPARSE_POINT` and refused by the handle's own attributes, so there's no gap between check and open | code |
| `bin` can't be swapped after the check | `Bin` holds the folder open without `FILE_SHARE_DELETE` while it lives, so it can't be renamed, deleted or replaced by a junction | code |
| `<data>` itself | the configured folder, as on Unix. Only the service's default folder is checked for reparse points at start; a folder set with `--config` or `LODESTAR_DATA_DIR` isn't | `windows::acl` (default folder only) |
| Atomic replace | a new temporary file (`CREATE_NEW`, never through a link), flush, then `std::fs::rename`. std can't flush a folder and NTFS writes its log lazily, so a power cut right after can bring back the previous file: atomic, but not guaranteed to survive power loss | code |
| One writer | `.lock`, an exclusive `LockFileEx` lock (`File::try_lock`, std 1.89), held open without `FILE_SHARE_DELETE` so it can't be renamed away | code |
| Owner-only access | new files inherit the data folder's protected DACL: SYSTEM, Administrators and `NT SERVICE\Lodestar` only | the MSI's folder ACL (`secure-datadir.ps1`), checked by the service at every start (`windows::acl`) |

- **Owner-only access isn't set from code.** Win32 ACL calls need `unsafe`, which the workspace forbids. `windows::acl`'s PowerShell route (create with the final ACL, check SDDL) could cover the portable build's `bin`. The runner was asked whether to do that in a follow-up. For the service, the MSI already sets the folder's ACL. **Residual:** the portable build's folder has whatever ACL the place it was unpacked to gives it. Its update files hold no secrets (the trust state is signed public data). Another user who can write there could at most hide notifications (`skipped`, `updater.json`) or delete `trust.json`, which is rebuilt from the embedded floor.
- **Unix is unchanged.** The Unix layout and its tests are as before, now under `cfg(unix)`.

## Owns approved during the build
- **`crates/lodestar/src/update/policy.rs`:** the `Reason::NotBuiltYet` variant, its code and its doc comment, nothing else (runner, 2026-11-08).

## Untrusted input (Q13's boundary, ahead of the helper)
- **The notifier reads three files from the data folder:** `updater.json`, `skipped` and `trust.json`. Each is capped at 256 KiB (`trust.json` at its own cap), parsed with unknown fields refused, and opened as itself, never through a link.
- **They're trusted only for the schedule and what's shown.** The trust state is verified against the embedded keys and raised to their floor before it's used.

## Follow-up
- **The four status helpers** (`release_infos`, `blocked`, `mode_name`, `level_name`) are copies of `engine.rs`'s. `engine` is Unix-only, so making them `pub(crate)` wouldn't reach Windows (runner, 2026-11-08). A follow-up moves them to a module both compile.

## More follow-ups
- **The API's descriptions** in `crates/api/src/updates.rs` and `dto/updates.rs` still say `updates_unavailable` means "a fixture or Windows". They don't list `not_built_yet` among the rollback reasons, and they give `windows_helper` as the example. Those files are outside this slice; fixing them regenerates `openapi.json` and `schema.d.ts`. Told to the runner.
- **The Updates screen has no rollback wording for `not_built_yet`** (`rollbackReasons` falls back to "unknown"). It's reached only by a direct `POST`, since the button is hidden. It's the web owner's.

## For PK-win-upd-2 and PK-win-portable-upd
- **`windows::check::select`** gives the artifact to download. An unknown kind gets none: install must refuse it.
- **RC and nightly MSIs share a `ProductVersion` with their release** (`MAJOR.MINOR.PATCH`; `2026-11-08-PK-manifest.md`). Windows Installer treats them as the same version, so the helper needs its own handling for them.
- **`not_built_yet` is one constant,** `windows::check::NOT_BUILT_YET`. It's used by `incapable` and by the Install and Roll back answers.
- **`skipped` entries are exactly `{version, reason}`** (`pending::Skip`). The Windows reader refuses anything else, so write that shape.

## Tests
- **On every OS** (`update::windows::check`):
  - install-kind detection (MSI, portable and unknown, with odd spellings);
  - artifact selection: MSI, portable, unknown, a missing artifact, no target, the Linux target;
  - what each kind is offered;
  - the `/updates` contract: no `unavailable`, `not_built_yet`, nothing eligible under `auto`, and Install and Roll back refused;
  - a validly signed manifest for another channel refused;
  - nothing published yet;
  - skip and pause saved and surviving a restart;
  - a second writer holding `.lock`, then taken once it's free;
  - failed writes (each step) not acknowledged;
  - a damaged or oversize `skipped` named and kept;
  - the 64-entry trim;
  - a damaged `trust.json` named and kept;
  - an unreadable `updater.json` kept until a pause;
  - the schedule's first check, and none with updates off;
  - `updater.json` read compatibly with the Unix engine.
- **On the Windows CI job:**
  - `update::layout::windows_tests`: a junction refused in place of `bin`, a state file or `.lock`; file symlinks never read, locked or written through; atomic replace with a failed rename leaving the old file; a second writer blocked; the folder pinned while open; an oversize file is damage.
  - `tests/update_windows.rs`: the real binary's `/updates`, Install and Roll back answers, and its `.lock` held against a second writer.
