# X-pipeline-1101 decisions

- **The enrichment backfill retries a store error after a backoff instead of stopping until the next start (#282).** This supersedes the line in `docs/architecture.md` §16 (M3 decisions, "Background backfill in the writer") that says the backfill stops after an error.
  - **Why:** a transient error (`SQLITE_BUSY` past the busy timeout, say) left every row still to enrich unenriched until the next restart, so imports and outdated records missed the re-index until then.
  - **How:** it shares the candidate refile sweep's backoff (`writer::Backoff`). It waits 5 s after the first error in a row, doubling up to 300 s, then tries the same batch again from where it left off. A persistent error still costs one attempt every 5 minutes at most, so it doesn't spin. While it waits, the writer loop's backfill branch is disabled, so shutdown isn't delayed.
  - `lodestar_writer_enriched_total` is unchanged. Each failed attempt still counts once in the writer's error counter and logs `pipeline.enrichment_failed`.
- **Refetches and the funnel (B-refetch-funnel, IMP-5): already correct on `main`.** A refetch writes no cohort row, no `FUNNEL_EVENTS` and no `STORED`, whether it's fetched or lost. `refetches_stay_out_of_the_funnel` (`crates/pipeline/tests/pipeline.rs`) proves it, so no code changed. Only its comment was corrected (#274).
