# X-shell-home decisions

Slice session, 2026-11-23Z. Brief and rulings: the runner's brief of 2026-11-22Z and its go message (§2.26 UX calls, flagged to the owner under §2.19). Findings: P5, P6, U27, D11 and 02 §4d of the 2026-11-13 UI review. Spec: §10.3, §10.4.

- **Status pill words (U27).** crawling → "Working", idle → "Ready", stalled → "Needs attention", unknown and connecting → "Connecting…" (one word for both, so the first frame and the first snapshot read the same). "Needs attention" is the glossary's own term (`needs_attention`), so its wording wins. Paused, Reconnecting, Server busy, Rebuilding, Index rebuild failed, Starting and Restart needed are unchanged: they already say what is happening. The count stays ("Working · 2.2K torrents"). **No rate is added:** there is no trustworthy hourly figure, and the pill must not compute one. The fleet text keeps its slot after the count for WK-17. Announcements are unchanged: one polite region that speaks on a change of state, not on every poll.
- **Palette button (P5).** A keyboard device shows the keys it answers to ("⌘K" on Apple platforms, "Ctrl K" elsewhere); a touch device (`pointer: coarse`) shows a magnifier, since there is no ⌘ there. Decided once at first render, so the bar never changes size. The accessible name is "Search and commands"; the dialog's own title stays "Command palette".
- **Overflow menu (P5).** Items are unchanged: Import and Backup have no Settings screen yet, and the Syntax guide waits for `/help/syntax` (X-help). **Page shift:** opening the menu sets `overflow: hidden` on `<body>` (Bits UI's scroll lock). Where the browser shows a classic scrollbar, the lock removes it and the page moves by its width. The fix is in the shared `ui/overlays/Menu.svelte` (turn the lock off for this menu) or a `scrollbar-gutter` rule in `app.css`, which counts against the global CSS limit. Both are outside this slice, so the shift is deferred to the runner's call. The headless browser used in CI has overlay scrollbars, so no test here can show the shift.
- **Search home (P6, D11).** The empty state is its own component, `search/home/Home.svelte`, loaded in the same `Promise.all` as the results panel and passed to it, so it is in the first frame. It says what Lodestar is and what to type, shows a health sentence from the pill state, and lists recent searches and up to five saved ones. The health line has its own reserved height, so the late status never moves anything. **No privacy claim** ("nothing leaves this computer") is made on the home: the crawler talks to the network and some sources send queries out, and privacy wording is the owner's call. Its messages are in `search/home/messages`; the old `search_results_empty_{title,title_unknown,lead,saved}` keys are removed (`search_results_empty_focus` is still used by the index-state banner).
- **Recent searches (02 §4d).** One store: `search/assist/recent.ts`, now with `clearRecent()`. Home and the query bar's suggestions share it. They stay in this browser only. "Clear recent searches" on the home forgets them, and `signOut()` (every sign-out path, the palette's included) clears them too. A session that expires (401) is not a sign-out and keeps them.
- **Out of scope, left as they were:** "Clear all" showing in browse mode (the results panel), the empty rail at desktop and the blank band at 390 px (the facet host and grid; not the empty state's own layout).
