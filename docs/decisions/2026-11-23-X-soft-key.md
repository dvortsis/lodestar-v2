# X-soft-key decisions

The runner launched this slice on 2026-11-23 for the cloud-test lane (X-test-vm), under the owner's 06:09Z rule. X-test-vm's on-only `SOFT_TIMEOUT` screen is its strongest single-switch lead so far, but the fleet tooling couldn't run it as an A/B because there was no `soft` treatment key. This slice adds the key. It changes no crawler code and no switch default.

## The key
- **`soft` turns on `soft_timeout`** (`LODESTAR_DHT_SOFT_TIMEOUT`, CR-SOFT-TIMEOUT #1091) and nothing else. It's listed wherever the keys are:
  - `block-lib.sh`'s `TREATMENT_KEYS`, `STACKED_KEYS` and `switches_of`;
  - `rules.py`'s `TREATMENTS` and `STACKED`;
  - the collector's `TREATMENT_SWITCHES` and `STACKED`, so analyze_cr's `--treatment` takes it;
  - the runbook's key table (§3.3.1).
- **`soft` is stacked,** like lc, hint and split. It runs on top of winners (`TREATMENT=soft WINNERS=adm`) or alone against the shipped defaults (no winners, or `[]`). A stacked segment is analysed with `--winners`, which may be an empty list. start-block refuses `soft` as a winner of itself (`stacking_winner_is_treatment`).

## Owns widened to `scrub.py` (the runner's call, 2026-11-23)
- `infra/fleet/steps/vm/scrub.py` keeps its own `TREATMENT_KEYS`, `STACKED_KEYS` and `WINNER_NAMES`, and `test_block.py` pins them to block-lib's. Without `soft` there:
  - copy-off drops `treatment: soft` from the evidence;
  - copy-off never passes `--winners` to analyze_cr for a soft block, so every segment reads `analysis_failed`.
- The runner widened the slice's Owns to include the file. `soft` is added to all three tables. `soft_timeout` is also added to scrub's `SWITCHES`, so a report's `identity.switches` keeps the switch. `sample_backoff_escalate` was already there.
- **Tests pin it:**
  - copy-off keeps `treatment: soft`;
  - copy-off passes `--winners` with `coordinated_admission` for `TREATMENT=soft WINNERS=adm`, and an empty list with no winners;
  - scrub keeps both `soft_timeout` and `sample_backoff_escalate` in `identity.switches`.
- The winners length test in `test_block.py` now uses 8 entries, one more than the seven keys.

## The soft report (analyze_cr)
- **What it reports.** For a soft segment, `soft_timeout` gives CR-SOFT-TIMEOUT's pair over **sampling minutes only**: `soft_per_hour`, `late_per_hour`, `late_per_soft`, and `soft_per_peer_query` (soft ÷ `dht_queries_sent_total{purpose="peer_lookup"}`). It also gives the raw counts, `sampling_minutes`, `stalled_minutes` and `absent`. `effect --treatment soft` adds `soft_timeout_by_arm`, each valid segment's fields by arm, in the same way as `split`'s per-arm report (CR-COL-6). The Markdown report gets a "Soft timeout" section.
- **What a sampling minute is (the slice's reading, flagged to the runner).** A scrape interval counts as sampling when two things hold:
  - the start suppression (`dht_sample_suppression_seconds`) reads 0 at both of its ends;
  - sampler-full time (`dht_sample_full_seconds_total`, rule 6.4's) didn't grow in it.

  Every other interval is stalled. A stalled interval is left out whole, along with its counts. This is the brief's "unstalled" time, where X-test-vm measured about 23.9 stored/min. If sampler-full time is absent, stalled can't be told from sampling, so every unsuppressed interval counts as sampling, and `absent` names `sampler_full_seconds`.
- **Reported, never decided on.** There's no check, no required series and no warning. An absent counter reads `absent`, and a ratio with a zero denominator reads `null`, never 0 or an error. The verdict and the fit are the same with or without the report.
- **Only for `soft`.** Segments and effects of other treatments carry no soft report, and their output is byte-identical to before (the golden effect tests). A segment's view gets `soft_timeout` only when its report has it.
- **The collector keeps both counters** (`collect.SOFT`, in `KEEP`). They were missing from the allow-list, so before this change they read "not collected". Neither is required, because binaries from before #1091 don't export them.

## Tests
- **The fleet** (`test_block.py`):
  - rules accept `soft` alone, with `["adm"]` and with `["adm", "lc"]`, and refuse it with itself as a winner;
  - start-block refuses `TREATMENT=soft WINNERS=adm-soft`;
  - the arms differ only in `LODESTAR_DHT_SOFT_TIMEOUT`, with and without `adm`;
  - scrub keeps `treatment: soft`;
  - the existing tests keep block-lib, rules, scrub, the collector and the runbook's table equal.
- **The collector** (`test_collect.py`): the mapping, `STACKED`, and both counters kept but not required.
- **The analyzer** (`test_analyze_cr_soft.py`), on segments written as the collector writes them:
  - both arms;
  - a stall in which the soft rate runs ten times faster, which never reaches the report;
  - absent series;
  - no soft report for hint, split or utp segments, or for hint or split effects;
  - the per-arm effect report, with the verdict unchanged.
