# B-log2 decisions, part 1 of 2: ring buffer, flood folding, `/logs/stream`, history

Architecture §12.1, §10.10.7, §10.10.12, §16 (B4 decisions, "Logging plan", "Review fixes (runner review of PR #86)"), and the B-log1 and B12 decision files. No owner decision is reversed or loosened, and no security or content-safety decision is weakened. The refinements the runner flags to the owner (§2.19) are marked **(§2.19)**. Part 2 (the files, downloads, the archive and deletion) has its own file.

- **Every line has an id `<epoch>-<seq>`.** The epoch is 16 hex digits from the OS RNG, made when the runtime is built; the sequence is given under the ring's lock as the record goes in, so the ring is always in sequence order. Typed, untyped, start-up buffered and fold-summary lines all get one. **The file's JSON lines gain `"id"`** (additive; older lines have none). History joins the ring to the files by it, and a stream's cursor is the same id. The console's lines carry no id.
- **The ring (§12.1's "In-memory ring buffer"):** at most 5,000 records and 4 MiB accounted, the oldest first out when either bound is reached. **An entry accounts for its owned string bytes (the message and target of an untyped line, owned field names and every text value) plus 160 bytes, plus 48 per field.** One entry accounts for at most 16 KiB: longer values are cut with `…` and the line is marked `truncated` (ring, stream and history only; the file keeps the whole line).
  - **What it holds:** every record that passed its switch (or, untyped, the `tracing` filter), whatever the file's level and whether file logging is on, **rendered once under the live mask** (the file's) into structured fields `(name, kind, shown value)`, with `shown`, the kinds that rendered as values (a peer beside a torrent counts as peer activity), and the line's opt-in. **No raw value is kept,** so nothing hidden can be recovered or probed by a filter later. The file line is written from the same entry.
  - **The setup token never enters it (§2.19: the setup token withheld from API outputs):** `auth.setup_token`'s token, and the word after `setup token ` in the plain start-up line `services.rs` still writes, are `[redacted]` in the ring's copy. The file keeps them.
  - **Cost:** a push is the insert, the evictions and the `allowed` check under one mutex. Streams are woken through a `watch` only while one is open. Readers clone `Arc`s out 256 at a time and filter outside the lock.
- **Purge when a kind or an opt-in turns off (§2.19: removal plus in-place rewrite).** `Runtime::apply` takes the kinds whose switch turned off (a save, or a deadline through `follow_with`) and, under the ring's lock, sets `allowed` first, **removes** the lines of an opt-in that turned off (`filters.change_detail`, and any line where a peer showed beside a torrent), and **rewrites** every other field of those kinds to `[hidden]` (a hash shown in hex becomes its `ref:` under this run's key). A record rendered under the old mask that arrives later is checked against `allowed` as it goes in and purged the same way, and the file gets the purged line. Streams get a `purge` frame. Every API read also treats a kind whose deadline has passed as off, before `follow` re-applies.
- **Flood folding (§2.19: per-output identity).** Each output folds by the line exactly as it shows it, without its time and id (the event or target, level, message and every field as rendered), held as a 64-bit keyed hash (`RandomState`). So two searches with queries off fold on a Private console and stay apart in a file that shows queries, and no output learns anything about what it hides. The file and the ring share one table (their masks are equal).
  - **Window:** 10 s from the first occurrence. The first line is written at once; identical lines inside the window are counted, not written; a window that ends with a count gets **one summary**: the source's level, component, event (or target) and message, no fields, and `"repeated": {"count", "seconds", "first"}` (`first` is the first line's id; the console has no ids, so its summaries omit it). In text: `… (repeated 1,204 times in 10 s)`. The next identical line after the window starts a new one.
  - A timer thread (`log-fold`, every 250 ms) writes summaries whose window ended; all pending summaries are written before `app.stop`'s line.
  - **Never folded:** required events, the runtime's notes about itself, and summaries. Event counters still count every occurrence.
  - **Cap:** 1,024 keys per table; ended windows are flushed first, and if it's still full a new line passes unfolded, never dropped.
  - Tests that count identical lines turn folding off (`Runtime::set_folding`, tests only); the window isn't widened.
- **`LogSource` (crates/api).** The routes reach the binary through a trait layered as `Extension(Arc<dyn LogSource>)` in `Services::run`, like `SystemApi`. It embeds the api crate's `Transport` (stream slots, the read limit, the shutdown switch), so `close()` ends every stream and refuses new ones with `503 logs_unavailable`. Without a source every `/logs` route but the catalogue is `503`.
- **`GET /logs/stream`:** `level` (minimum, default `trace`), `components` (comma-separated, `unknown_component`), `text` (case-insensitive substring of at most 200 characters, matched against the line as shown, after masking); each at most once. **Cursor:** `Last-Event-ID`, else `?after=`, else the newest record. Another epoch's id is `resync {reason: restarted}`, one before the ring's oldest `expired`, a malformed or future one `malformed`, each followed by live. **Backpressure:** 16 frames to the socket and at most 256 matching records waiting; past that one `resync {reason: lagged, skipped, evicted}`, then on from the newest. **A resume more than 256 matching lines behind is `lagged` too:** the 256-record bound holds from the first look, and the lines stay in `GET /logs`. Frames: `retry: 5000`, `event: line` with `id:`, `event: resync`, `event: purge` (`{kinds, through}`), and a comment every 15 s. **Caps:** 2 per session and 8 in all, `429 too_many_streams` with `Retry-After: 5`. The session key is counted as `/events` counts it since #126: a hash of the valid session cookie, or of the trusted proxy's user and client address. **It ends with its session:** on its own clock, whatever lines are flowing, each heartbeat re-runs the guard's own check (`auth::logged_in`) on what let it in, the cookie or the proxy header from the same TCP peer.
- **`GET /logs`, history (§2.19: current-mask history).** `level`, `components`, `text`, `since`, `until` (RFC 3339 UTC), `limit` (default 200, at most 1,000), `cursor`. Newest first: the ring, then the current file read backwards, then the rotated files by their names' times. A file line with this run's id at or above the ring's lowest covered sequence is skipped (it's in the ring or was purged from it); lines without an id are older than any with one. File lines are shown **through the live mask in force now**: a field whose kind is off reads `[hidden]` (a `ref:` already written stays), a peer beside a torrent follows peer activity, lines of an opt-in that's off are left out, untyped text is re-scrubbed with today's URL rules, an unknown field kind is hidden, and the setup token reads `[redacted]`. Text matching runs after masking.
  - **The cursor** is base64url (≤ 512 bytes): a version, the epoch, a fingerprint of the filters (SHA-256 of the filter, `since` and `until`), and the position (a ring sequence, or a validated file name, an uncompressed offset and a fingerprint of the current file's first line so it's found again after a rotation). Another run's or another filter's cursor, or any field that fails its check, is `400 bad_cursor`.
  - **Bounded work:** at most 2 file reads at once across history and (part 2) downloads, else `429 logs_busy` with `Retry-After: 2`; **at most 64 MiB read or inflated per request**, after which a page comes back partial with `more` and a cursor, never an error. Lines over 1 MiB, or not the file's JSON shape, are skipped and counted in `unreadable`.
  - **Rotated files are now gzip in members of about 1 MiB of whole lines, with a last empty member whose header lists every member's offsets.** Any gzip reader reads the file as one stream; history starts at the member it needs, so paging back through a file inflates each member once, never O(n²). At the 1 GiB file maximum, the current file is read backwards in 64 KiB blocks, a page in a rotated file costs about a member, and the index lists up to 2,700 members. A file without the index (written by B-log1's build, or one whose index fails its checks) is read in 4 MiB windows, each a pass from its start: at the default 16 MiB that's at most four passes; at 1 GiB one page can inflate the whole file once. **That is the read cap's one exception:** such a file's length and a window are inflated whole before the cap is checked. **(§2.19: the rotated files' on-disk format changes,** additively: any gzip reader still reads them whole.)
- **`Applied::status()` gains the live output's row** (enabled, level `trace`); the kinds' `live` column is unchanged.
- **Distinct-line floods aren't folded:** a hash per DHT harvest is a new line each time. **For B-log1b:** its high-volume events stay `default_on: false`, and its bench decides. When B-log1b logs the setup token as `auth.setup_token`, retire the plain-line special case (`entry::redact_setup_token`'s use on untyped lines; history's on messages stays for older files).
- **Signing out doesn't end a stream by itself:** `POST /logout` clears the browser's cookie but doesn't revoke it (M-auth), so a stream ends within a heartbeat of a password change, "Sign out other sessions" or the session's expiry, as `/events` does.
- **A purge's removals aren't evictions:** the ring remembers the highest sequence its bounds evicted, so a cursor just behind a removed line isn't `expired`, and history's seam is the lowest sequence the ring still covered at its last look (lines evicted during a walk are read from the files).
- **History is never a 500 for a file:** a folder that can't be listed has no files, and a file that can't be read is counted in `unreadable` and passed over. While a rotated file is being compressed, its `.jsonl` and `.jsonl.gz` are one file, read once.
- **Every history page takes one of the 2 file reads,** even one the ring answers alone: the source decides where a page ends only as it reads.
