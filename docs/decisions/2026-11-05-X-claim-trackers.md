# X-claim-trackers decisions

Slice session, 2026-11-05. Runner brief X-claim-trackers, from the review of #491 (X-fuzz-cache-1105). Architecture §12 (the SSRF guard), §18.2 enrichment #3, §18.5 and §18.7. It tightens SRC-13's tracker rule and the pipeline's claim-tracker check; the runner approved it under §2.33 and flags it to the owner under §2.19. Nothing is loosened.

- **Why.** Nothing dials, emits or returns a claimed tracker today: no magnet link includes one and no endpoint returns one. The moment a feature adds `&tr=` from claims, or sends claimed trackers to a client, a tracker on the user's own network becomes a client-side SSRF: the user's torrent client dials it from inside the LAN. Two gaps would have let one through:
  - `torrent_cache::public_tracker` kept `http://localhost/announce`, `udp://localhost:6969/…` and `http://foo.localhost/`: `net::check_url` judges IP literals only, and RFC 6761 `localhost` names resolve to loopback.
  - Feed and plugin claims passed the pipeline's `tracker_url`, a text check, so `udp://192.168.1.1:80/announce` or `http://127.0.0.1/` was stored.
- **One shared guard: `lodestar_integrations::net::public_tracker_url(raw) -> Option<String>`** (`crates/integrations/src/net/tracker.rs`, next to `check_url`). It parses with the `url` crate and returns the serialisation, the address as judged, which is what's stored. It refuses:
  - schemes other than `http`, `https` and `udp` (so `wss`, which `tracker_url` used to accept, is now dropped from claims: no tracker scraper or client path uses claimed `wss` trackers, and the brief names the three);
  - any user name or password;
  - a literal address that `classify` doesn't call public (private, CGNAT, loopback, link-local, metadata, unspecified, multicast, broadcast, documentation and the rest), in every spelling the `url` crate normalises (`127.1`, `0x7f.1`, `2130706433`) and the IPv4-mapped, compatible, NAT64 and 6to4 forms, through `check_url` with the notification policy and no private opt-in;
  - local names, after lower-casing and IDNA mapping (`ⓛocalhost`, `ＬＯＣＡＬＨＯＳＴ`, `%6Cocalhost`, `t。local`) and with trailing root dots: `localhost` and `*.localhost` (RFC 6761), as the brief asks;
  - **and, beyond the brief, single-label names and the special-use LAN domains** `*.local` (mDNS, RFC 6762), `*.home.arpa` (RFC 8375) and `*.internal` (ICANN's private-use TLD), plus `*.localdomain`, `*.localdomain4` and `*.localdomain6` (Red Hat-family systems map `localhost.localdomain` to loopback in `/etc/hosts`, and it's a common search domain) and any name whose last label is all digits or starts with `0x` (`127.0.0.1..` is a name to url 2.5.8, not an address, but a looser IPv4 parser could read it as loopback; the URL standard's "ends in a number" rule; both from `/security-review`). A dotless host such as `http://router/announce` is completed with the LAN's search domain, and the other three exist only inside a network, so each reaches the same place `localhost` does. No public tracker uses one. This is a tightening, so it's the runner's call (§2.19).
  - **`udp`'s host is judged as the same host over `http`**, as #491 did: `udp` isn't a special scheme to the URL standard, so its host is opaque (not lower-cased, decoded or IDNA-mapped). A host that doesn't parse that way is refused.
  - **Only hostname characters** (runner review of #500): after IDNA, the judged host must be ASCII lower-case letters, digits, `-` and `.`, or a bracketed IPv6 literal. The `url` crate keeps `,`, `;`, `_` and other characters in a domain, so `http://127.0.0.1,t.example/announce` or `http://localhost,t.example/a` passed, and anything that later splits a tracker list on `,` or `;` would get `http://127.0.0.1`. Those are refused now.
  - **A `udp` URL is stored with the host that was judged** (runner review of #500), not its opaque spelling: `udp://T.Example:6969/a` and `udp://%74.example:6969/a` are kept as `udp://t.example:6969/a`, and `udp://t%E3%80%82example` (an ideographic full stop) as `udp://t.example`. A reader that doesn't decode could otherwise see one label holding a `%` where the guard judged two. So every stored host is lower-case letters, digits, `-` and `.`, or an IP literal. In the claims path, where only a claim already in that form is kept, such spellings are dropped; in `torrent_cache` they're stored in the judged form.
  - **The output reads back as itself** (it's checked), so `public_tracker_url(&kept) == Some(kept)`.
  - **No other reader finds another host in it** (fresh review of this PR, blocking): the kept form has no `@` anywhere, and nothing but host and port between `://` and the first `/`. `udp` isn't special, so the `url` crate keeps `udp://t.example:6969?@192.168.1.1:80/announce` as written, with no `/` before the `?`; libtorrent-style parsers end the authority at the first `/`, take `t.example:6969?` as user info and dial `192.168.1.1:80`. Such a URL is now refused. Refusing `@` everywhere also refuses a few legal public URLs with `@` in the path or query (`http://t.example\@127.0.0.1/…`, stored as `http://t.example/@127.0.0.1/…`); no tracker needs one, and some parsers take the last `@` as the end of user info.
  - It's DNS-free. A public name that resolves to a private address stays the dialing client's concern, as it is for any tracker, and Lodestar never dials claimed trackers.
- **Caps stay where they were.** The guard has none of its own. `torrent_cache::public_tracker` keeps `MAX_TRACKER_URL` (512) and its query, fragment and passkey rules on top of the guard. `tracker_url` keeps `claims::MAX_TRACKER` (2048) and its text checks. Ports are whatever the `url` crate accepts (0–65535), as before.
- **`torrent_cache::public_tracker` delegates to the guard.** #491's canonical storage stays: it returns the guard's form. SRC-13c edits `Config` in the same file; only `public_tracker`, its doc and its test are touched here.
- **`unverified.rs` `tracker_url` calls the guard in one added line**, as the brief asks (ENR-1b owns the file): a claim is kept only when `public_tracker_url(t) == Some(t)`, so the text stored is exactly the form that was judged. A claim the `url` crate would rewrite (`HTTP://Tracker.Example/announce`, `http://tracker.example` with no path, `http://t.example\@127.0.0.1/…`) is dropped rather than stored as written, because another parser could read its raw text as a different host. Storing the rewritten form would need a second hunk in `store_claims`; dropping is not free: it drops every claim with a default port (`https://tracker.example:443/announce`, `http://open.example:80/announce`) or no path, both common in public tracker lists and magnet `tr=` parameters. No feed emits claimed trackers yet, so nothing is lost today, but **follow-up for ENR-1b (asked through the runner): switch `store_claims` to `.filter_map(|t| public_tracker_url(t))` under the length cap**, so the canonical form is stored instead. `tracker_url`'s doc comment still names `wss` and says the check is text-level; it's left for ENR-1b to update with the file, to keep this hunk to one line. `lodestar-pipeline` gains a dependency on `lodestar-integrations`, a workspace crate the binary already links; no cycle.
- **Existing rows aren't migrated.** Claimed trackers already stored aren't dialed, emitted or returned by anything, so a row stored under the old check is inert. The refile sweep doesn't re-judge trackers. **No read-side filter is added:** no code reads claimed trackers for output today (no endpoint, no magnet builder), so there's nowhere to put one yet. Whoever adds the first reader for output must apply `public_tracker_url` there; that also covers the old rows.
- **Tests.**
  - `crates/integrations/src/net/tracker.rs`: a table of every refused class, including the #491 review's quirks (backslash, tab and newline, `@`, `%40`, `127.1`, `0x7f.1`, IDNA, `ⓛocalhost`, `[::ffff:127.0.0.1]`, `[::127.0.0.1]`), and of the canonical forms kept. Property tests (4,096 cases each) check that the guard never panics, that a kept tracker is a fixed point, that it never parses (re-read, `udp` as `http`) to a host the test's oracle calls non-public (`classify`, plus the local-name rules written out again in the test: the same list as the guard's, since that list is the specification, but not the guard's code), that the stored host is the judged one and holds only hostname characters, and that a naive reader (authority up to the first `/`, host after its last `@`) finds the same host as the `url` crate, over arbitrary text and over generated URLs with IPv4 spellings in decimal, hex and octal, IPv6 and its embedded forms, userinfo, `%40`, backslashes and tabs.
  - `crates/pipeline/tests/claim_trackers.rs`: `tracker_url` keeps public trackers and drops the brief's examples and non-canonical spellings. The existing `the_description_and_publisher_are_judged_and_trackers_validated` passes unchanged.
  - The `verified_claims` fuzz target now re-reads every kept tracker from its stored text and asserts that its host isn't a literal `classify` calls non-public, nor a `localhost` name (the #491 review's polish item 3), that it holds only hostname characters, and that a `udp` tracker's stored host is the one judged. The file's trackers it compares against are read the same way (`udp` hosts as they read over `http`). `fuzz/Cargo.toml` gains `lodestar-integrations` (a workspace crate) for `classify`; no new third-party crate.
