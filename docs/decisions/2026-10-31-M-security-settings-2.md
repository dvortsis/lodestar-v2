# M-security-settings-2 decisions (part 2: API keys, feed tokens, trusted proxy sign-in)

Settings → Security, part 2 (§10.10.7, §10.10.8's Security row, §12), on part 1's password confirmation. No owner decision, security decision or owner-set number changes. Refinements the runner flags to the owner (§2.19) are marked **(§2.19)**.

- **Both new sections load right after the first paint (runner, §2.26).** Each section's heading is in the first view; its body loads by dynamic import after mount, with a skeleton meanwhile (`Later.svelte`), as the Settings connection screens' parts load, so it stays out of the first-view gate without costing the user a click. A body that can't load says so and offers Try again.
- **API keys and feed tokens** (`security/Keys.svelte`): the list (name, kind, public prefix, status with an icon, scopes, created and last used), New, Regenerate and Revoke. No API-key UI existed to reuse. A revoked or expired key shows no actions, because the server can't regenerate it (B12's 409 `key_inactive`).
- **A refusal that isn't the password's closes the dialog.** A 400 on another field or a 409 (`too_many_keys`, `key_inactive`) shows at the name or scopes field, or in the section's result line ("Nothing was changed. …"), as the proxy section does, so the password isn't blamed and no login-bucket try is spent on retrying.
- **Create and Regenerate need the password; Revoke asks a plain question (§2.19; runner: accepted, as B12 decided).** The brief puts every risky key action behind the password dialog, but B12 decided revoking and deleting don't need it, since they only take access away, and `POST /keys/{id}/revoke` takes no password. A password the server never checks would be theatre, so Revoke asks "Revoke …?" with Keep it as the safe default and sends nothing on Keep it or Esc. Deleting a key isn't offered: revoking keeps the record of what existed, and the brief didn't ask for it.
- **New keys** take a name (1–200 characters), a kind and, for an API key, at least one scope (Search API is ticked to start). A feed token reads every feed: choosing one saved search and an expiry are left for later, since the brief didn't ask for them and the API defaults are the plain choice.
- **A secret is shown once and kept nowhere.** It goes from the create or regenerate answer straight into the reveal dialog's props (`reveal.ts`, `Reveal.svelte`), never into component state, storage, a draft, a URL or the console, and the dialog is unmounted when closed (Done, Esc or ✕). The dialog's code loads before the password is asked for, so if it can't load nothing is sent and no secret is made that can't be shown. Copy writes to the clipboard in the click and says Copied, or says to select and copy by hand. The field is focused and selected on open.
- **Trusted proxy sign-in** (`security/Proxy.svelte`, `GET`/`PUT /auth/proxy`) is the screen's "auth mode": `/auth` only says whether the instance is set up and signed in, so there's no other mode to choose. The section says plainly what the header does, that anything at a trusted address can sign in as anyone, recommends leaving it off, and lists B12's three safe-setup rules (don't publish the port, trust the proxy's fixed IP on a user-defined network, never trust the bridge gateway alone).
- **Loosening is named, not just confirmed.** Turning it on, or while it's on adding a trusted address, changing the user header, or adding to or emptying the allowed users, shows a warning on the screen before saving, and the password dialog's title and text say what changes ("Anything at … will be able to sign in as any allowed user, without a password"). Every save needs the password, as the server does. Turning it on with no trusted address is refused before anything is sent. A value the server refuses (400 with a field other than `password`) closes the dialog and shows at its field, so the password isn't blamed.
- **`LODESTAR_PROXY_AUTH=off` is shown as locked, with its source.** `forced_off` shows an info banner naming the variable, and the switch is disabled and labelled as the saved setting. The addresses, header and users stay editable, so the settings can be fixed while the variable keeps proxy sign-in off.
- **One leave guard for the screen (§2.19).** Part 1's restated leave rule is now the pure `securityLeave()` (`security/leave.ts`); `leave.test.ts` imports the engine's `leaveDecision` and checks the two agree over dirty × bypass × type × from × to. `guard.ts` registers each part with typed input (Change password, New key or token, Trusted proxy sign-in): the first part still on screen decides for all of them, so leaving asks once, names every part with something typed ("Leave without saving?"), and Discard clears them all. If the question's code can't load, the navigation goes ahead with `location.assign` (#285's review). Nothing reaches the engine's sessionStorage draft.
- **Expired session mid-flow:** as part 1, a 401 `login_required` closes the password dialog and the API client takes the user to sign in; no secret is revealed.
- **Sizes.** The key manager, the proxy section and the reveal dialog load after the first view (`Later.svelte`) and have their own entry, "Settings security keys and proxy (on demand)", at measured + 10%. No existing limit was raised and no Settings registry entry was added. Three choices keep other pages from growing, each because the import would move shared code between chunks and add bytes to routes that don't use it:
  - **(§2.19)** the key dates go through `security/date.ts`, which uses `formatDate`'s options and the display time zone, instead of importing `$lib/format` (as `format/shared.ts` already avoids importing the locale module). The reason is the re-split: imported from this on-demand chunk, `$lib/format`'s shared module is reached by an entry that doesn't reach its number formatters, so Rollup splits the format chunk every route loads in two, and five routes (Discover, Alerts, Alert, `/t/[hash]`, Search cards) went over their limits by 10–70 B. Runner: accepted. `date.test.ts` checks it matches `formatDate` across locales and zones;
  - `Choice.svelte` and a plain `<textarea>` use the classes of `$lib/ui/fields`' Checkbox, Toggle, Radio and Textarea instead of importing them, which split them out of the engine's controls chunk;
  - `Later.svelte` uses `{#if}`, not `{#await}`, whose runtime split out of Svelte's shared chunk.
    The size gate's shared "body imported statically" check now skips imports _from_ Security's later parts (they load only from the body, so their imports of it are of code already loaded), and a new check fails the gate if anything imports those parts statically, so their code can't leave the first-view gates unmeasured (runner: accepted provisionally, for the reviewer to verify).
