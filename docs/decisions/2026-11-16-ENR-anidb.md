# ENR-anidb decisions (AniDB titles dump and HTTP API parser and plugin)

Slice ENR-anidb (`runner/slices.yaml`, API lane brief, 2026-11-16). Spec: architecture §18.2 (enrichment plugin 6, AniDB / AniList) and §18.7; plan `docs/plan/2026-11-05-v07-m7.md` (ENR-anidb row, the caps line "AniDB ≤ 1 per 2 s with its client registration", the dependency line "ENR-anidb … use the existing `quick-xml`", Q4, Q5 and Q12); the owner's Q4 answer (`docs/owner-decisions.md` §2.47: "AniDB: a registered client, at most 1 request every 2 s, interest-only"). ## Terms of use and rate limits (owner §2.28), checked 2026-11-16

- **How it was checked:** AniDB's wiki (the HTTP API Definition and API pages) refused automated fetches on 2026-11-16 (a browser check in front of `wiki.anidb.net`). A web search that day quoted the HTTP API Definition page directly for the registration rule and the ban for using the API to download AniDB. The 2-second spacing, the cache-a-day rule and the dump's once-a-day rule weren't quoted there: they are the rules AniDB clients document (and the plan's Q4 number), and the plugin keeps to them. No request was sent to AniDB. **For the runner:** a person should re-read the HTTP API Definition page before the plugin is switched on, and this file is amended if it differs.
- **What they say, and what the plugin does:**
  - **Every client must be registered** and send its registered client name and version on every request. **Lodestar has no registered client.** None is built in or invented: the name and version are the user's (or, once registered, the project's), stored in the SecretStore as two required credentials (`client`, `clientver`). Without both nothing is sent. **Open question for the owner, through the runner:** register a Lodestar client with AniDB (a user account's "Add client" page) and decide whether to ship it as the default. Asked on the PR.
  - **"The API should not be used to download AniDB"; clients that try are banned.** So there is no background walk (`TERMS.background_walk: false`): only items you open (Q4's "interest-only"), at most `DAILY_RECORDS` = 100 records a UTC day (kept in the plugin's state, so a restart doesn't reset it), each record cached in memory for a day. Clients report bans after a few hundred requests a day; 100 stays well under.
  - **At most one request every 2 s** (Q4's number; AniDB's rule). `HostRate::every(2 s)`, no burst, and the runtime's `min_interval` is 2 s too. After a 429 or 5xx the host limiter backs off from 10 minutes to 6 hours, longer than other plugins, since AniDB bans clients that keep asking.
  - **Cache heavily; don't ask for the same anime more than once a day.** `RECORD_TTL` is a day; ENR-10's runtime keeps the resulting claims for their retention.
  - **The titles dump** (`anime-titles.xml.gz`) is published for matching titles locally, to be fetched **at most once a day**. The time of the last attempt is written to the plugin's state **before** the request, so a failed, interrupted or restarted fetch still counts, and a clock set back restarts the wait from now rather than holding the plugin for ever. A dump in memory is used for 7 days.
  - **`<error>Banned</error>`** holds the plugin a day without sending anything; any other `<error>` holds it an hour.
  - **No title search over the HTTP API**, so the dump is required (below).
- **Licence:** AniDB publishes no licence that lets its data be passed on, so `redistribute: false`.

## Terms (ENR-terms)

`anidb::TERMS`:

- **`background_walk: false`:** the API rules forbid downloading AniDB, and Q4 says interest-only.
- **`redistribute: false`:** no licence to pass the data on; answers stay in Lodestar's own UI and never rename what search, Torznab and export serve.
- **`retention: Retention::DEFAULT`** (180 days): the rules ask clients to cache and set no shorter limit.
- **`attribution`: "AniDB", linking `https://anidb.net`:** the data's source, credited beside its answers.
- **`adult_marker_required: true`, `adult` from the record's `restricted` attribute** (AniDB's 18+ flag): `restricted="true"` → `Some(true)`, `"false"` → `Some(false)`, absent → `None`, anything else spoils the record. The runtime refuses a marked or unmarked answer (`a_restricted_anime_is_marked_adult`, `terms_tests::anidb_terms`). The dump carries no marker; it is only used to find an id, never as an answer.

## No title leaves the install (Q5)

- **1.** The dump (`https://anidb.net/api/anime-titles.xml.gz`) is fetched under the once-a-day rule, with only a `User-Agent` naming the project. **2.** The query's title is folded (lower case, letters and digits, other runs one space) and looked up in an index of the dump's main, official and synonym titles; short titles and unknown types are left out (they name too many things). No title, or a title two anime share, is no match and nothing more is sent. **3.** For the one anime it names, `http://api.anidb.net:9001/httpapi?request=anime&client=…&clientver=…&protover=1&aid=…`: the id and the client, nothing else. **4.** The record must agree (`choose`): its type with the query's kind, one of its titles with the query's, its years with the query's year.
- **Plain HTTP.** AniDB serves its HTTP API only over `http` on port 9001. The id and the client name travel unencrypted; `SENDS` says so. The dump is fetched over `https`. The egress lets exactly those two origins through (`only_the_two_endpoints_are_permitted`).
- **Never** the hash, the raw name, the files, or anything about the user or install.

## Off by default, Account class

- **The manifest:** `anidb`, Enrichment, Consent `Account` (it can't run without the client credentials), endpoints `https://anidb.net` and `http://api.anidb.net:9001`, `enabled_by_default: false`, never always-adult, never finds private. `AniDb::need` uses the declared credentials, so one alone never enables it.
- **Kinds: Movie and TV**, as AniList: AniDB's `Movie` is a film; `TV Series`, `TV Special`, `OVA`, `Web` and `Other` a series; `Music Video` and unknown types never match.
- **No host wiring**, as ENR-14 left it: library code listed in the catalogue, wired with the slice that lifts the consent gate.
- **Confidence** 85 with a matching year, 65 without: the title match comes from AniDB's own list and the record is checked, but a folded title is weaker evidence than Wikidata's search.
- **The answer:** `anidb:<aid>`; the main title as canonical; official and synonym titles as alternatives with BCP 47 languages (`x-jat` → `ja-latn`, `x-zht` → `zh-latn`, `x-kot` → `ko-latn`, `x-tht` → `th-latn`, others lower-cased when well formed, else `und`); no genres (AniDB's tags include adult ones, left for a later slice with a fixed map); the query's year, else the start year.

## The parser (`sources-feeds/src/anidb.rs`)

- **On `quick-xml`** (already in the tree, as the plan says), with the feed parsers' shared attribute and title rules (`common.rs`). **`flate2`** (already pinned in the workspace, pure-Rust backend) is added to `sources-feeds` for gzip: AniDB gzips both answers.
- **Gzip bombs:** at most `max_compressed` bytes in (dump 16 MiB, record 4 MiB) and `max_bytes` out (dump 64 MiB, record 16 MiB); the inflater is wrapped in `take(max + 1)`, so no more is ever produced (`a_gzip_bomb_never_inflates_past_the_cap`). A body that isn't gzip is read as is, within the same cap.
- **No DTD or entity expansion:** `<!DOCTYPE` stops the parse; only character references and the five XML entities resolve; an unknown entity spoils the anime.
- **Structural caps** stop the parse: depth (dump 4, record 8), elements (2,000,000 / 500,000), anime (200,000 / 1), titles in the answer (1,000,000 / 128). **Field caps** spoil the anime: attributes (4 / 8 per element, 64 bytes each), text 1 KiB, language tags 16 bytes. Titles past 128 per anime are passed over and marked `truncated`.
- **Strict shape:** the root must be the one asked for (or a record's `<error>`), one root only; a repeated record field, an element inside a field, a title without a type, a bad id (1–10 digits, no leading zero, fits `u32`) or a `restricted` that isn't `true`/`false` spoils it. Only ids, titles, type, start and end years and the marker are kept; creators, characters, descriptions, tags, ratings, episodes and pictures are passed over unread.
- **`Page::whole`** is the one rule: an answer is used only when it was read to its end with nothing spoiled, so a broken dump builds no index and a broken record is an error, never a miss. A whole dump with even one spoiled entry is refused (strict: a skipped entry could make another anime's shared title look unique).
- **Tests:** golden synthetic answers, every cap, hostile documents, property tests over any bytes (plain and gzip) and generated dumps (`crates/sources-feeds/tests/anidb.rs`), and the `anidb` fuzz target.

## Before it can be switched on

- **A registered client** (the owner's question above), or the user's own, entered in the source's credentials.
- **Real recordings** of the dump and a record, replacing the synthetic fixtures, by the slice that lifts the consent gate; the parser is fixed for any shape they differ in.
- **A person's re-read of AniDB's HTTP API rules**, which refused automated fetches here.
- **The Legal Notice** gains AniDB's line then, by the owner (§2.33).
