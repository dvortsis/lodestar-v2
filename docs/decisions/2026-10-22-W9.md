# W9 decisions: app shell

Architecture §10.3, §10.13, §10.16 and §10.19 are followed. These choices clarify what they leave open.

- **The shell is about 12 KB of the 45 KB search-route budget (§10.1).** Measured with `npx size-limit`: 44.5 KB, before any search UI. To get there:
  - the API client, the event stream, the status pill, the toaster, the command palette, the overflow menu, the connection states and the shell's own commands load after first paint (`requestIdleCallback`, 1 s at most) or on first use;
  - the five icons the top bar needs are drawn as plain `<svg>` (`Glyph.svelte`), because `unplugin-icons` components spread attributes and pull that helper (about 1.4 KB gzipped) into the first load; lazy chunks still use `~icons`;
  - the compass is inline markup using the `--brand-*` tokens;
  - the nav has no icons (text and an underline, as §10.3 describes).
  - Search and later slices have what is left. Anything they import statically that the shell already loads costs nothing extra; the shell's lazy chunks are never counted against them.
- **Navigation collapses below `x-large` (1024 px)**, not at `large`. Five links, the status pill and two buttons do not fit at 640 px with words. The collapsed form is a disclosure under the bar (`aria-expanded`, `aria-controls`, Esc closes and returns focus), not a sheet, so it needs no dialog code and nothing traps focus (§10.13).
- **The status pill shows the state and the server's torrent count, not a rate.** §10.3's "Crawling · 1.2k/h" needs a rate the `crawler` event does not carry, and the client must not derive one (standards §4). The pill reads "Crawling · 1.2M torrents". `docs/metrics.md` (Ingest rate, line 169) specifies "Crawling · 1.2K/h", new stored torrents over the last full hour. **Backend follow-up:** add a server-computed ingest rate to `CrawlerEvent` (the `ingest_per_hour` the Insights contract already names); the pill then swaps `shell_status_torrents` for a `formatRate` message. States: crawling (fetches running or queued), idle, rebuilding (server progress as "N of M"), failed, and, from the stream itself, connecting, reconnecting, busy and unknown (shown with no stale numbers).
- **Server unreachable is a full page only if nothing answered.** After the stream has answered once it is a banner above the page, so someone mid-task keeps their place. A failed stream is not enough on its own, because a proxy or antivirus tool can hold back just the stream: the shell also counts any successful REST response (`onSessionOk`) and, when the stream fails first, probes `GET /api/v1/auth` (any answer under 500). Only a failed stream plus a failed probe shows the full page.
- **Screens with no chrome:** `/login`, `/setup` and `/welcome` render without the top bar and open no stream (§10.19: lockup, not chrome). `chrome.ts` is the list; M-auth adds to it if its routes move.
- **401 hand-off:** the chrome installs M-auth's `installAuthHandlers()` (it owns W5's single `onLoginRequired` slot): first run goes to `/setup`, otherwise `/login?next=<path>` with `next` validated by `features/auth/next.ts`. The shell has no handler of its own. The stream's own 401 triggers it once the stream starts, so first-run detection needs no extra request.
- **Keyboard registry (`lib/keys`).**
  - A command is `{ id, title, section?, keys?, scope?, allowInInput?, when?, keywords?, palette?, run }`; a default key comes from `DEFAULT_KEYS[id]` (§10.16).
  - Two commands on one combo in one scope are reported and **neither fires** until one moves.
  - A text field, select or contenteditable only receives a command that sets `allowInInput` *and* has a Ctrl/Alt/Meta combo or Escape; bare characters never fire while typing.
  - Bare characters also stay quiet inside a dialog or menu, and `setSingleKeys(false)` turns them all off (WCAG 2.1.4). `remap(id, combos)` rebinds.
  - Enter and Space never fire on a focused link, button, menu item, option, tab or switch (§10.13 activation) unless the command sets `onControl`; Shift+letter is not the bare-letter command; `remap` reports the conflicts it creates.
  - `list()` is the data the S-keys shortcut sheet needs (title, section, effective keys, active).
- **Focus after navigation:** when the path changes (not the query, not the first load), focus moves to `<main>`. The skip link does the same.
- **Density** is kept in nav links (it is URL state, §10.3). The shell has no theme or density switch; the Appearance slice adds it. The illustration variant follows the `color-scheme` the pre-paint script sets.
- **Test harness:** the OpenAPI mock leaves `getEvents` pending by default (the shell opens the stream on every page). Specs that need events serve a real stream (`e2e/support/events-server.ts`).
- **Overflow menu targets** (`/settings/import`, `/settings/backup`, `/logs`, `/help/syntax`, `/settings/about`) are provisional paths for slices that do not exist yet; they show the 404 state until those land.
- **The chrome loads after the page paints.** `Shell.svelte` (in the root layout) holds only `<main>`, the connection states and a slot with the top bar's height; `Chrome.svelte` (skip link, top bar, palette, toaster, stream) is imported on mount, so the page's first paint never waits for it and nothing shifts. The toaster loads with the first toast. The overflow menu loads on hover, focus or press. The skip link therefore appears a moment after load.
- **A static first-paint shell in `web/src/app.html` makes LCP independent of the JS chunks (§10.1).** With `ssr = false` nothing painted until the Svelte runtime, kit and app chunks had run, and the runtime chunk is global (every feature's use of Svelte features lands in it), so LCP grew with the whole app: with the lazy chrome it was about 2.67 s against the 2.5 s budget, while the same tree with no chrome measured 2.44 s. `app.html` now paints, from HTML and the already-inline CSS: the skip link, the top bar's brand and five destinations (real `<a href>`s, which kit's router takes over) and, on `/search`, the page heading. Mobile `lhci` after the change: **LCP about 1.5 s, CLS 0, about 101.6 KB** (limits 2.5 s, 0.02, 102,400 B); desktop passes too.
  - **Hand-over:** `Shell.svelte` moves `#boot-header` into its own header slot and removes `#boot` in the same task as the mount, so nothing moves; the chrome replaces it with the full bar after the first frame. A small inline script marks the current destination and shows the heading on `/search`.
  - **Where it is dropped before first paint:** `/login`, `/setup`, `/welcome` (no chrome there) and any `zh*` browser language (the markup is English only; the app's own text appears at mount). This is a stopgap until the locale setting exists: when it does, the script (or the markup) must follow it.
  - **Drift guard:** `e2e/boot-shell.routes.test.ts` loads the page with the app's scripts blocked and checks the static shell, then compares the header, brand, menu button, each destination and the heading box by box (≤ 1 px, at 1366 and 390 px) with the app once it has taken over, checks `#boot` is gone, and checks CLS stays under 0.001. It caught a real mistake while it was written (blocking the stylesheet).
  - **Costs to know:** the markup duplicates the bar's links and brand (the test is what keeps them in step); the menu button is inert for the moment before the chrome loads; the static heading is only for `/search` and exists to give today's stub page a first paint. Search's real LCP will be its results, so that slice should check LCP again.
- **To stay inside the 102,400-byte budget the chrome's heavier parts wait for the first interaction, or 30 s after load:** the key shortcuts (the first key press is replayed once they exist; typing is not), the event stream and the status pill, the connection states and the toaster. The 401 redirect (M-auth's `installAuthHandlers`) installs as soon as the chrome mounts. The pill therefore appears after the first interaction.
- **`web/src/app.html` no longer preloads the UI font.** A preload competed with the scripts and CSS that paint the page. The font is fetched at the first layout of text and swaps in (`font-display: swap`); CLS stays 0 on today's screens. Re-check CLS when Search lands.
- **Why lazy loading alone was not enough:** code in lazy chunks still puts the Svelte runtime features it uses into the shared chunk every page loads, and the `lhci` simulation counts a lazy chunk's size whenever it loads inside the window (about 17 ms per KB gzipped). Per-module Svelte chunking (`advancedChunks`) made it worse (74 chunks, LCP 6.4 s), so `vite.config.ts` is unchanged.
- **Headroom: the first-load budget has about 0.8 KB left (about 101.6 KB of 102,400 B).** The limit is an owner number and stays. If a later slice needs room, move these deferred pieces behind the first interaction first, in this order: the toaster (already lazy; load only on the first toast), the stream and pill, the key shortcuts, the connection views. The 401 redirect stays at chrome mount.
- **The deferral is safe for access:** the skip link, `<main>`, the banner and the navigation landmark come from `app.html` and the shell's own markup, so they exist before any key press (`boot-shell.routes.test.ts` asserts the landmarks with the app's scripts blocked). The auth redirect starts when the chrome mounts, not at the deferral.
- **Owner permission:** the owner allowed the `web/src/app.html` edit for the static first-paint shell on condition that the 2.5 s LCP budget holds (2026-10-23).
- **A metric-matched fallback font, so the font swap cannot become a late LCP candidate.** In CI the static heading painted at 1.5 s in the system fallback, then Atkinson loaded and the same heading came out a few percent larger (text box 1029 against 980). That is a new, larger LCP candidate, and Lighthouse's simulation put it at 2.67 s (limit 2.5 s) although the first paint was unchanged. The same happens locally with a fallback whose text box is a little smaller than Atkinson's. `tokens.css` now puts `'Atkinson Fallback'` (a local Arial/Liberation Sans/Helvetica, `size-adjust: 106%`, ascent 105%, descent 32%) between Atkinson and `system-ui`, so the fallback's text box is larger than Atkinson's in both directions and the swap only shrinks text. `boot-shell.routes.test.ts` fails if that stops being true in the CI container. Mobile `lhci` locally with that fallback: LCP about 1.5 s, CLS 0, 101,884 bytes. A font preload with `font-display: block` was tried and rejected: it moved LCP to 2.2–2.5 s. Side effect: characters Atkinson's Latin subset lacks (Greek, Cyrillic) now fall back to the scaled Arial before `system-ui`; CJK still reaches the named CJK families, since Arial has no glyphs for it. `docs/design-tokens.md` §8 and `docs/architecture.md` §10.2 are updated to match.
- **Focus survives both swaps, by identity.** The static skip link and bar links are replaced twice (Shell's own skip link at mount, the full bar when the chrome arrives), and kit resets focus to `<body>` after it hydrates. Shell now records which stop had focus (the skip link, or the `data-testid` the static and full bars share; the brand has one now) and focuses the same stop on the new element, only while focus is still on `<body>`. A spec Tabs onto the skip link, the brand and two destinations before load and checks each one keeps focus through both swaps.
- **The boot script mirrors the app's locale rule.** `app.html` walks `navigator.languages` like `resolveLocale` (exact tag, then primary subtag; first covered locale wins) and drops the English shell only when that is not English. The covered locales are baked in by `scripts/messages.ts` (today only `en`, since zh is at 0.35 of the 0.95 gate), so a zh browser, which gets the English app, keeps the fast static paint, and `['ja', 'zh-CN']` will not flash English once zh is covered. `boot-script.test.ts` runs the real inline script against that rule. The locale setting is not read yet (the Appearance slice adds it); the script has to follow it then.
- **The first key press.** Ctrl/Cmd+K is taken in a non-passive listener and opens the palette directly (the browser would otherwise use it for the address bar while the registry is still loading). A bare modifier press is not "the first key". Other first keys are replayed to the registry only.
- **Static links have the focus ring and 44 px targets** of the full bar (they had none).
- **Headroom, CSS:** CSS is 19.82 of 20 kB gzipped, as tight as the bytes (101,884 of 102,400). A later slice that adds CSS or bytes must move a deferred piece out first, in the order above.
- **The error screen cannot depend on its own chunk.** Kit loads `routes/+error.svelte` with every route, so it is a stub that fetches `ErrorView.svelte` (and through it the illustrations) only when something failed. If that fetch fails too (typically because the server has gone), the stub shows plain markup: the heading, the status code, "Go to Search" and, outside a 404, "Try again". Chrome also preloads the screen at the first interaction. Specs abort the screen's chunks and check both a 404 and a failed navigation (500).
- **Mac:** the first-key palette shortcut is Cmd+K on a Mac and Ctrl+K elsewhere (Ctrl+K in a Mac text field deletes to the end of the line), the same rule as the registry.
- **`npm run messages` rewrites `src/app.html`** (it bakes the covered locales into the boot script), as `npm run themes` does for the pre-paint script. Run it and commit the result when a catalogue's coverage crosses the 0.95 gate.
