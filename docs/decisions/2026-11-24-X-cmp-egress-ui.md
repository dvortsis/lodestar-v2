# X-cmp-egress-ui decisions

Settings → Companions gets the route editor, the restart answer, "where it runs" from the server and live SOCKS5 warnings (architecture §18.10, §10.10.8; `2026-11-12-X-cmp-egress-api.md`; `2026-11-11-CMP-9a.md`; `2026-11-11-X-cmp-egress-prelaunch.md`, "Residuals"). No API change. None of these decisions loosens an owner decision or weakens a security decision. The runner flags the refinements to the owner (§2.19).

- **The editor is a panel on the row, behind "Change route", shown only where `egress` isn't null.** So only a companion Lodestar runs here that takes a route has it.
- **Refinement (self-review): and only once it's installed.** The server gives an installable companion that isn't installed yet `runs: lodestar` and a route, but refuses a change to it with `409 not_installed`, after the password check. Offering the editor there would cost an admin-password try every time for a certain refusal. A refreshed row that loses its route, or stops being installed, closes the editor and its unsaved choice. The panel says the current route in words and whether it is the companion's own (`from: saved`) or copied from the source it serves (`from: source`, which becomes its own at its next start). A `setting: null` row says the route can't be read and the companion stays stopped; it never says "direct".
- **Refinement: the current route shows inside the panel, not on the row.** The Companions first view sits at its 33 kB cap (§10.1). Putting the route's words on every row would cross it; inside the lazily loaded panel they cost the first view nothing.
- **Only `direct` and `socks5` are offered.** `interface` and `bind_address` are named when they are the current route, but the select starts on "Choose one" for them, so a save never sends one (the server would refuse it `route_unavailable` anyway). The proxy field asks for `host:port` and says no user name or password: the request has no field for one.
- **Refinement (self-review): no "who looks up names" choice.** A companion's SOCKS5 launch is always `socks5://<proxy>`, so the proxy resolves names whatever `dns` says (`crates/companions/src/manager.rs` `launch_env`). Offering "this computer" would promise something that doesn't happen on the control that keeps its traffic on the VPN. The editor always sends `dns: proxy`, which says what happens.
- **qBittorrent is offered SOCKS5 too.** The API doesn't say which route kinds a companion can follow, so the editor doesn't guess: the server refuses it `409 cant_follow_route`, and the editor says so in words. A field for the kinds it follows would be an API follow-up.
- **There was no Sources route control to reuse.** The web UI doesn't edit a source's route yet (`patch_source` takes `egress`, but no screen sends it). So the editor is new and stays in this feature, and its form follows the Templates panel's route select. The password step reuses the shared confirmation every risky change uses (`security/confirm.ts`'s `confirmWithPassword`, as Outputs does). It is loaded on Save, so the first view carries none of it. The password lives only in that dialog's field, cleared before the request goes.
- **The restart warning comes before the save, twice:** under the form, and as the password dialog's body ("Saving restarts {name} on the new route. It stops until it's back."). The button is "Save and restart".
- **The answer never says "applied":**
  - `restarting: true` says it is restarting on the new route, takes the row the server returns, and watches `health` exactly as Restart does (`CompanionsStore.watch`).
  - `restarting: false` says the route is saved and used at its next start, followed by a sentence for `not_restarted` (`not_wired`, `busy`, `restart_failed`, and a generic one for a code nobody here knows). The code itself is never shown.
- **Each refusal has its own sentence, and each says nothing was saved:** `unknown_companion`, `takes_no_route`, `not_installed`, `busy`, `cant_follow_route`, `route_unavailable`, `bad_body`, and `invalid_egress` by its `field` (`egress.proxy`, `egress.dns`, or the route as a whole). The field is named, never the value, and the server's own text is never shown. `not_wired` (409, nothing saved) has one too. These close the password dialog and show on the row, so the sentence stays if the row, read again afterwards, has no route any more (`not_installed` and `takes_no_route` can mean the list was out of date) and the editor closes. After a save, focus goes to the companion's name, as after an install or a removal.
- **Password refusals stay in the dialog, in this screen's words:** `bad_password`, `confirm_required` and the `rate_limited` lock-out (with the dialog's own countdown), and a signed-out session closes it as everywhere else.
- **"Where it runs" comes from `runs`.** The install confirmation's fixed sentence (CMP-9a) is replaced by one per value: `lodestar`, `own_container`, and `not_here` followed by the refusal in words. `yours` reads as `lodestar` there, since the dialog says what installing does, and an install puts a companion you ran yourself under Lodestar. The setup flow behind a source's companion chip passes no `runs`; an install there is always Lodestar's, so it reads as `lodestar`. Refinement: the row itself doesn't repeat the sentence, which would cross the first view's cap; its refusal line already says why a companion can't be set up here.
- **The route note is gone.** CMP-9a's fixed "a companion's route is copied from the source when it first starts" now comes from `egress.from`, in the panel.
- **SOCKS5 warnings follow Prowlarr's route, live.** They warn and never refuse; the server decides:
  - on Prowlarr's row while its saved route is SOCKS5: email notifications connect directly (MailKit), a FlareSolverr pairing leaves directly, and per-indexer proxies bypass the route;
  - on Prowlarr's row while SOCKS5 is chosen in its editor and not saved yet ("If you save a SOCKS5 proxy for Prowlarr"), gone again when another kind is chosen or the panel closes;
  - on FlareSolverr's row, only the pairing warning, while Prowlarr's saved route is SOCKS5.
  They no longer show for a companion with no SOCKS5 route.
- **Size (§10.1; runner's calls under §2.26, 2026-11-24T13:02Z).** The runner flags the raises to the owner.
  - `Route.svelte` stops the Companions first view (32.98 of 33 kB) and has its own entry, "Settings companions route editor (on demand)", capped at 6 kB (measured 5.3 kB: mostly its sentences). "Settings companions parts (on demand)" leaves it out, so nothing is counted twice.
  - Both entries stop at Security's password dialog, which "Settings security parts" already measures.
  - "Settings companions parts (on demand)" 29 → 29.5 kB and "Sources companion chip and setup (on demand)" 27 → 27.5 kB, for the install dialog's "where it runs" sentences (measured 29.2 and 27.3 kB).
- **Tests:** `route.test.ts` covers the editor hidden when `egress` is null and before an install, `saved` and `source`, an interface route named but not offered, an unreadable route, the body sent (route, `dns: proxy` and the password only), `restarting` true and false with each `not_restarted` code, each refusal (and one whose refreshed row lost its route), `invalid_egress` by field without the value, a wrong password, the lock-out, a session that ended, Cancel, focus after a save, and the SOCKS5 warnings saved, live and off. `companions.test.ts` covers "where it runs" for each `runs`. No e2e spec was touched.
