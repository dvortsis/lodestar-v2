# WK-17 decisions (Insights per-worker breakdowns, Marginal gain, fleet pill)

Architecture §19.7 and §10.9; builds on [WK-15](2026-11-07-WK-15.md). No API change.

## Fleet pill

- **Text:** the pill adds ` · N workers · X/h` after its torrent count (`1 worker` for one; the rate uses the compact formatter, and is left out when `stored_per_hour` is null). `fleet: null`, a failed request or no answer yet adds nothing.
- **Paused and offline** counts are in the visible text, each only when above zero: ` · 3 workers · 1 paused · 2 offline · 4.2K/h`. This refines the first rule (they stayed out of the visible text, in a tooltip or description) at the runner's call (UX, §2.26): with Settings → Workers (WK-16) not built yet and the pill linking to Insights, a user with 2 of 5 workers offline would otherwise see "3 workers" and no sign of trouble. The visible text is the link's accessible name, so there is no tooltip and no extra description (a tooltip would be read twice and would remount the link when the first answer arrives). The text isn't in the polite announcement, so a poll never re-announces.
- **Polling** (`workers/fleet.ts`): once at mount, then at most every 60 s, only while the tab is visible. Hiding the tab stops the timer and aborts a request; showing it polls at once if the last poll is over 60 s old. Unmount aborts and removes the listener.
- **Bundle:** the pill is already a lazy chunk, so the first-load set is unchanged: Total first load 85.75 kB before and after.

## Names

- Insights never names a worker. `GET /workers` (admin-only) is fetched lazily by the breakdown, only when `by_worker` is present. A failure (a non-admin's 403) leaves no names. Worker 0 is "This server"; any id without a name is "Worker <id>". Only id and name are kept; no address or token.

## Breakdown and Marginal gain

- Tables on Discover and Fetch, rendered only when `by_worker` is non-empty (nothing, not even a heading, otherwise). Fetch's note says the loss-reason filter doesn't narrow it. No compare column.
- **Marginal gain ≈** (Discover): count and share of that worker's `granted` (whole percent, "—" when granted is 0). Definition shown: "Keys a worker found that no other worker claimed while they were in flight. It mostly under-counts, and the latest hours fill in as leases end." plus the hint "Workers on different networks usually add more." No recommendation logic.

- **The share is computed in the client** (marginal ÷ granted, whole percent): the brief asks for it and the API has no share field (runner's brief, WK-17). A marginal above granted (a server inconsistency) shows "—", not a clamped 100%.
- **A failed poll keeps the last fleet** so the pill's link doesn't remount (focus) on a blip; before any answer nothing is added. The fleet text shows only in the states that show the torrent count.
- **Axe on the new sections:** no e2e fixture carries `by_worker` and this slice can't touch e2e, so WK-G's workers spec should cover `insights-workers` and `insights-marginal`. Tables have captions and `th scope=col`.
- **Stage pages growth:** the first version used `{#await import()}`, which pulled Svelte's await-block runtime (+462 B gz) into the stage set. The breakdown now loads with an `$effect` and `import()` (the Chrome/TopBar pattern), only when `by_worker` is present. What's left is the import site and its preload map (about 290 B). The on-demand "uPlot" entry now also includes the breakdown.
- **Axe (WK-G's spec):** run axe on `insights-workers`, `insights-marginal` and on the pill with a fleet present (the visible text, including paused and offline).
