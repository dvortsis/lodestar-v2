# WK-17 decisions (Insights per-worker breakdowns, Marginal gain, fleet pill)

Architecture §19.7 and §10.9; builds on [WK-15](2026-11-07-WK-15.md). No API change.

## Fleet pill
- **Text:** the pill adds ` · N workers · X/h` after its torrent count (`1 worker` for one; the rate uses the compact formatter, and is left out when `stored_per_hour` is null). `fleet: null`, a failed request or no answer yet adds nothing.
- **Paused and offline** counts are in the tooltip and in an `sr-only` span inside the link ("3 working, 1 paused, 2 offline."), never in the visible text. They aren't in the polite announcement, so a poll never re-announces.
- **Polling** (`workers/fleet.ts`): once at mount, then at most every 60 s, only while the tab is visible. Hiding the tab stops the timer and aborts a request; showing it polls at once if the last poll is over 60 s old. Unmount aborts and removes the listener.
- **Bundle:** the pill is already a lazy chunk, so the first-load set is unchanged: Total first load 85.75 kB before and after.

## Names
- Insights never names a worker. `GET /workers` (admin-only) is fetched lazily by the breakdown, only when `by_worker` is present. A failure (a non-admin's 403) leaves no names. Worker 0 is "This server"; any id without a name is "Worker <id>". Only id and name are kept; no address or token.

## Breakdown and Marginal gain
- Tables on Discover and Fetch, rendered only when `by_worker` is non-empty (nothing, not even a heading, otherwise). Fetch's note says the loss-reason filter doesn't narrow it. No compare column.
- **Marginal gain ≈** (Discover): count and share of that worker's `granted` (whole percent, "—" when granted is 0). Definition shown: "Keys a worker found that no other worker claimed while they were in flight. It mostly under-counts, and the latest hours fill in as leases end." plus the hint "Workers on different networks usually add more." No recommendation logic.
