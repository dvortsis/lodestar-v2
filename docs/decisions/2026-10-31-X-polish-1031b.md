# X-polish-1031b decisions

Optional findings from the CR-1a-H (#246) and CR-1a-S (#252) reviews, a guard for #255's bug class, and #245's docs follow-up. No schema, wire or setting changes.

- **The hint table's capture order is bounded at every capture, not only at the tick** (`hints.rs`, CR-1a-H). `capture` compacts `order` once it passes 4 × `HINT_CAPACITY` (80,000 entries): it drops the entries of used or replaced hints. Live entries are at most 2 × the cap, so at least 2 × the cap captures pass between compactions: amortised O(1). `retain` keeps the time order the TTL prune relies on. Before this, a burst between ticks could grow it without limit.
- **`send_failed` is tested** (`hint_tests.rs`, `a_failed_hinted_send_falls_back_and_counts_send_failed`): an IPv6 hint sent through an IPv4 stand-in socket counts one `dht_hint_fallbacks_total{reason="send_failed"}` and one send error. The guard isn't restricted, since no query went out, and ordinary routing drives the leg at once. This supersedes "Not covered by a test: `send_failed`" in `2026-10-30-CR-1a-H.md`.
- **The first-batch clear in `Pool::back_off` is removed as dead code** (`crates/sources/src/pool.rs`, CR-1a-S O3). A batch that adds a peer makes its key ready, and a ready key leaves only by a fetch start or a loss, which both clear the clock. So a back-off never finds one. This supersedes the "A back-off clears the key's first-batch clock" line in `2026-10-31-CR-1a-S-2.md`: a retry's clock still starts at its own first kept batch, because none survives to the back-off. The brief placed this in `actor.rs`; it's in the pool, and the runner was told.
- **`docs/metrics.md` says the two arms of the screen's "first fetch ms" measure different things.** Off is the lookup's run time to its answer, over every answered lookup. On is the time to the first batch plus the pool's wait to a fetch start, over the requests and keys that got that far. `fetch_stream_first_fetch_seconds_total` now reads "first streamed batch", as its help text does, and adds that the clock starts only on a batch that added a peer.
- **`openapi.json` has a component-name guard** (`crates/api/src/openapi.rs`). `document()` now merges a list of module parts, and `no_two_modules_register_one_component_name_differently` fails when two parts define one name with different schemas. Before #255, the later one replaced the earlier without a sound. A type shared by several modules still passes. `the_guard_catches_a_collision` proves the check fires. Limit: two same-named types inside one module's `ApiDoc` collapse before the test sees them. The latent pairs `Channel` and `Mode` (`lodestar` settings vs `dto/system.rs`) aren't in the spec today, so nothing is renamed.
- **The user guide tells readers to check their content filter settings after a restore or rollback** (§3.7, #245). Rules, the override list, exceptions and *Always allow* return to the backup's, and a release made since is undone (`2026-10-30-F-rollback-holds.md`). There are no v0.5.1 release notes yet, so there's no line to add there.
