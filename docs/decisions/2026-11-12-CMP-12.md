# CMP-12 decisions

FlareSolverr, opt-in only: its catalogue entry, its detection and health adapter, and Prowlarr's indexer proxy once you switch it on. Owner §2.47 (Q21 yes, opt-in only); plan `docs/plan/2026-11-06-v06-companions.md` §4 CMP-12 and §5 Q21; architecture §18.9, §18.10. None of these loosens an owner decision or a security decision. The runner flags the ones marked **(refinement)** to the owner (§2.19).

## Off unless you switch it on
- **The catalogue entry is `opt_in: true` and only a `challenge_solver`,** which the loader already enforces for anything that names FlareSolverr (CMP-0). No default role (download client, indexer manager, VPN route) names it, so no default install set or requirement reaches it.
- **Not in the default detection sweep (refinement).** `detect::auto_detect` keeps probing qBittorrent, Prowlarr and gluetun only. FlareSolverr has a detector and a health adapter in the registry, but only `flaresolverr::find` probes for it, on its fixed targets (loopback `8191`, then `flaresolverr:8191` in a container), and a caller runs it only once you've switched it on. The plan (line 164) has the container name joining the default sweep; keeping it out is the stricter reading of "never detected into use by default", and a FlareSolverr that's running but switched off is never even looked for.
- **`Switch::Off` is the default.** The pairing writes to Prowlarr only with `Switch::On`, and only with consent for Prowlarr's target (an install receipt or your confirmation, CMP-8b's rule).

## Detection and health
- **`GET /`** must answer `200` with `msg` exactly `FlareSolverr is ready!` (upstream `src/flaresolverr.py`, `index_endpoint`). The `version` is kept only in `Version`'s strict grammar (a leading `v` is dropped); anything else is "no version", not "no FlareSolverr". The `userAgent` is passed over, never read.
- **Health is `GET /health`** answering `200` and `{"status": "ok"}` (`health_endpoint`). Anything else is unhealthy; nothing answering is unreachable, as for the other adapters.
- **Untrusted input:** both bodies go through `CompanionHttp` within `Limits::PROBE` (5 s for the whole exchange, 64 KiB) and the bounded JSON reader; a key with an escape or given twice refuses the answer. No credential is sent: FlareSolverr has none.

## Prowlarr's indexer proxy
Checked against Prowlarr's API v1 (`IndexerProxyController`, `ProviderControllerBase`, `FlareSolverrSettings`, `TagController`).
- **Which proxy is Lodestar's:** named `Lodestar FlareSolverr`, implementation `FlareSolverr`, and tagged `lodestar-flaresolverr`. All three, or it's yours. Yours are never changed or removed, your own FlareSolverr proxies included. A proxy of yours that has only the name makes switching on fail (`indexer_proxy_name_taken`) rather than adopt it; switching off leaves it alone.
- **Switching on:** creates the tag if it's missing, then the proxy (`host` FlareSolverr's address, `requestTimeout` 60, upstream's default; `tags` Lodestar's only). If Lodestar's proxy is already there but differs (FlareSolverr moved, extra tags), it's updated in place. A plan made after a successful apply is empty.
- **Switching off:** `DELETE` of Lodestar's proxy. The tag stays, because your indexers may carry it. A `404` counts as done.
- **Lodestar tags no indexer (refinement).** Prowlarr sends an indexer through a FlareSolverr proxy only when the two share a tag, so the proxy alone routes nothing. You add `lodestar-flaresolverr` to the indexers that need it. This keeps the choice of which sites get FlareSolverr yours, which matters because some sites' terms forbid it (Q21). CMP-9a's screen says so; this slice adds no UI text.
- **The address is local only:** `SolverAddress` is loopback or a container name on Docker's network, built from a detected or installed target. A URL you entered is refused (`flaresolverr_not_local`).
- **Plan, then apply,** as CMP-8b's adapters: the plan reads `/api/v1/tag` and `/api/v1/indexerproxy` and writes nothing; apply re-reads, does only the listed steps still needed, and logs each by name (`indexer_proxy.tag`, `.add`, `.update`, `.remove`), never a value. The API key goes only in the sensitive `X-Api-Key` header.
- **`adapter::Method::Delete`** and `ProbeRequest::delete()` are added for the removal, with its arm in `CompanionHttp` (shared edit, asked of the runner).

## Egress
- **The pairing leaves directly** (`docs/decisions/2026-11-11-X-cmp-egress-prelaunch.md`, residuals): Prowlarr reaches FlareSolverr on loopback or Docker's network, and FlareSolverr goes direct, so an indexer it solves for doesn't follow Prowlarr's route. `Pairing::notes` gives the reason code `flaresolverr_egress_direct` for every pairing that's switched on, for the screen that shows it (CMP-9a). This slice doesn't refuse the pairing on a SOCKS5 route: you switched it on knowingly, and the screen carries the note.

## FlareSolverr's port
- **Internal only by default.** Its one port (`api`, 8191) is `internal`: a generated compose service or Unraid template publishes nothing unless you ask.
- **Never on your network.** FlareSolverr's API fetches any URL it's given and has no sign-in, so a LAN publish would be an open proxy. The templates now refuse it (`lan_refused`), as they already did for gluetun's control port (shared edit in `compose.rs`, asked of the runner); a loopback publish is allowed.
- **Native:** upstream listens on every address by default (`HOST=0.0.0.0`). `flaresolverr::NATIVE_BIND` (`HOST=127.0.0.1`) is what a launch profile must set. This build has no native launch profile for FlareSolverr, so the manager refuses a native install (`Refusal::NoProfile`) until one exists; adding it is a follow-up for the runner to place.

## Pins
- **Unpinned, `TODO(CMP-13)`.** The entry's Linux x86_64 and Windows x64 artifacts (Q15) and its `ghcr.io/flaresolverr/flaresolverr` image have `pin: null` and `digest: null`, like every other entry today, so the manager and the templates refuse it as awaiting its pin. Pinning it needs a FlareSolverr recipe in `tools/companion-pins/upstream.py` (FlareSolverr publishes no signatures: `Unsigned`), which is CMP-13's file. The catalogue is written in the pin tool's layout, which its test checks.
