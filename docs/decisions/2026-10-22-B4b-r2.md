# B4b-r2 decisions (event stream visibility follow-ups)

Follow-ups from #87's review. These refine `2026-10-22-B4b.md` (§9's `/events`, §20.9).

- **While Adult is hidden, `max_id` is the newest id that isn't Adult.** Torrent ids are sequential, so with the overall maximum, `max_id(n) − max_id(n−1) − added(n)` counted the hidden Adult torrents. `Indexer::catch_up_counted` now returns a `CatchUp { added, adult_added, max_visible_id, replayed }` (exported, replacing B4b's tuple). `Committed` gains `max_visible_id` (0 when every new torrent was Adult). The swap takes it from the new index: the highest id in `(visible, last]` without `type:adult`. The hub keeps a visible watermark beside the overall one and sends it while hidden. After Adult is turned off, an event's `max_id` can therefore be lower than one sent while it was on; it's still the newest id the client can find.
  - **What it leaves:** the newest hidden torrents no longer show. Hidden Adult whose ids fall between two visible ids still show in that difference, because any real, sequential id sent alongside an exact `added` reveals the gaps. Closing that fully means sending no `max_id` while Adult is hidden. That was left out: a client using `max_id` to search for what's new (`id > X`) would lose it, and what leaks is a count of hidden torrents to a signed-in user who can turn Adult on anyway. Raised with the runner for a decision.
- **Events that reveal Adult are withheld once it's hidden.** A `torrents` event is tagged in the ring when it was made while Adult was shown and says more than the hidden version would have, meaning its count included Adult or its `max_id` is past the visible watermark. Each event is checked when it's handed to a client, replayed (`Last-Event-ID`) or live. While Adult is hidden, a tagged event becomes `resync {reason: "visibility"}`, one for a run of them, so the client refetches rather than replaying counts that included Adult.
  - **Checked at hand-off, not at subscribe:** this also covers a reconnect that subscribed just before the setting changed.
  - **Tagging over a broadcast `resync` on every toggle:** turning Adult off costs nothing when no client holds such an event.
  - **The other direction:** events made while hidden are replayed unchanged after Adult is turned on. They undercount, but reveal nothing.
  - **What it can't reach:** frames already queued to a socket, up to 16 per client plus TCP buffers, were checked when Adult was still shown.
- **`ResyncReason` gains `visibility`** (`openapi.json`, `schema.d.ts` regenerated).
- **The swap's report is tested end to end.** `ServingConfig` gains a test-only (`#[cfg(test)]`) `hold_at_swap` point, after the old live indexer stops and before the new index's last catch-up. Torrents stored there, classified in the same transaction as the pipeline's writer does, are announced only by the swap's own report, so `the_swap_reports_its_adult_torrents` checks its `adult_added` and `max_visible_id` exactly.
