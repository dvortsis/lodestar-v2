# NOS-2b decisions (PR pending)

The plugin WebSocket client: `crates/sources/src/ws.rs`, its connector on `PluginEgress` in `egress.rs`, and a transcript replayer in `testing.rs`. Plan: `docs/plan/2026-11-06-v08.md` NOS-2b; §18.1, §18.6, §18.9, §12. It lands inactive: nothing calls it until NOS-3.

- **The connector is `WsConnect`, implemented by `PluginEgress`.** A session takes the plugin's HTTP path in the same order: the endpoint policy (URL rules and host list), the kill switch and the source's stored state (`admit_route`, split out of `admit` unchanged), then NOS-2a's `connect_tcp_routed` on the route the HTTP client was built for, under a `RouteSwitch` adapter over the egress's `watch::Receiver<RouteState>` (NOS-2a's decision). Failures are counted in the plugin's existing `EgressCounters`; no new counter. `PluginEgress::new`'s signature is unchanged; the factory sets the route after building, so `egress_tests.rs` is untouched.
- **An open session stays under the kill switch** (`EgressWatch`), as a streamed body does (`EgressBody`): a published outage ends it at once, and on a checked route it re-probes every `BODY_REPROBE`. Unlike the body, a probe in progress is kept across dropped waits, because a session's wait is dropped whenever a frame arrives first; otherwise steady traffic would cancel every probe. The switch only acts while the plugin waits on `recv`, `send` or `close`, which a plugin's loop always does; a route that went down and came back while nobody waited (the egress's trip count moved) ends the session too, and so does one that drops during the connect or TLS handshake. Closing while the route is down sends nothing. Each open session probes a checked route on its own (as each streamed body does); NOS-3, with several relays open at once, should share one probe per egress.
- **The host list keys `wss` on its own.** `Origin::of` accepts `wss` (port 443 by default) with the same host key as `https`; a `wss` entry lets no HTTP through and an `https` entry no WebSocket. `Endpoints::manifest` accepts `protocol: "wss"`. A `wss` URL is checked with the guard's DNS-free rules on the same origin over `https`, since `net::check_url` knows only `http(s)`. `Endpoints::permits` dispatches on the scheme. Runner's call (an extension of the §12 host list to the new scheme).
- **Caps.** A message, and so a frame, is at most 128 KiB (131,072 bytes) each way, reading the plan's "128 KB" in binary as the rest of the code base does (`MAX_BODY`, cluster's frame cap); runner's call, flagged. No extension is offered; a server that answers with one (`Sec-WebSocket-Extensions`) is refused, because tungstenite leaves that check (RFC 6455 §4.1) to its caller; it does check `Sec-WebSocket-Protocol`. The upgrade's answer is bounded by tungstenite's own check (64 KiB of headers) and the connect timeout, so no wrapper. A message over the cap that the plugin sends is refused locally and the session goes on; one the server sends ends it.
- **Timers.** Ping every 60 s (a plugin may ask for less, down to 30 s, so a plugin can't ping a relay hard); idle timeout 150 s by default (two missed pings plus slack), held to 2 × ping ..= 600 s, reset by any frame received, pongs included; a send that can't be written within the idle timeout ends the session too. Connect timeout 15 s by default (1 to 60 s), covering lookup, connect, proxy handshake, TLS and the upgrade. Close waits at most 2 s for the close frame. Runner's calls: the plan names an idle and a connect timeout without numbers.
- **Back-off is `Reconnect`,** a helper the plugin's loop drives: `http::backoff_delay` (`[full, 1.5 × full]`, never below the base nor above the max) from the plugin's own back-off with `floors::BACKOFF_BASE` applied, and a failure count that resets only after a session stayed up 300 s, so a server that accepts and drops keeps the back-off growing. NOS-3's own caps (30 s to 1 h, one connection per relay per 30 s, Q-r11) go on top in NOS-3.
- **TLS** is rustls on ring with `rustls-platform-verifier`, the verifier the plugin HTTP client and IRC use; `Roots::Only` exists for tests (`EgressFactory::with_roots`; public because the loopback integration test needs it). The connector is kept only once it builds, so a platform verifier that fails to load is tried again on the next connect. TLS failures map to fixed strings, because rustls' error text can carry the certificate's names. No `WsError` names a URL, address, certificate name or payload; `WsMessage`'s `Debug` prints lengths only.
- **Dependencies.** No crate new to the lockfile. `lodestar-sources` adds direct dependencies on `tokio-tungstenite =0.30.0` (`handshake`, as `crates/cluster`), `tokio-rustls =0.26.6`, `rustls =0.23.46` and `rustls-platform-verifier =0.7.1` (as `crates/sources-irc`), and `futures-util =0.3.34` (`sink`, `std`, as `crates/cluster`) for the stream and sink traits tokio-tungstenite's API needs. The plan's "no new crate" is read as none new to the tree; runner's call.
- **The replayer** (`WsReplayer`) plays one `.ws` transcript per connect, in order: the plugin's sends matched exactly and in order, the server's messages, and an end (close, error, idle, kill switch), or a refused connect or upgrade (`REFUSED-DOWN` for one the kill switch refused). The caps hold as on a real session, and a recorded idle timeout takes the session's idle time on the test clock. `finish` reports every mismatch and unplayed step, as the HTTP replayer does.
- **Not wired into `Kit` yet.** `crates/sources/src/plugin.rs` isn't this slice's file; NOS-3 (or a shared one-line edit it claims) adds the plugin's `WsConnect` to its kit. Shared edit here: `crates/sources/src/lib.rs` gains `pub mod ws;` and one re-export line (assigned to NOS-2b in the plan).
