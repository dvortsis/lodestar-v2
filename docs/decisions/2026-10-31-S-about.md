# S-about decisions

Settings → About (§10.10.13, §10.19), built from what `GET /system` and `GET /updates` serve today. Nothing here reverses or loosens an owner decision; the refinements below are the runner's to accept (§2.19).

- **One request feeds the screen.** `GET /system` gives the version, build, channel, data formats, installation, data sizes, connections and the diagnostics inputs. The update summary reads `GET /updates`, and **Check now** is `POST /updates/check`: the one signed check (§12.2), never a separate request. If `/updates` fails, only that section says so.
- **Stale-tab check.** The tab's build id is SvelteKit's `version` (`kit.version.name`, the same string as `_app/version.json`); the server's is `build.ui_build_id`. They are "stale" only when both are known and differ, so the stub page (null) never raises the banner. The check lives on About only. **The spec also wants it on every page load; that belongs in the app shell, which this slice doesn't own, so it is left as a slot** (runner to schedule). `isStale` in `about/logic.ts` is the function to reuse.
- **Slots for what the API doesn't serve yet:** the embedded release notes of the running version (only the newer release's `notes_url` shows; **All release notes** links to the repository's releases page), **Download diagnostics** (no endpoint; the text says so), the per-installation "how to update" commands, the next automatic install time, worker and companion versions. Each is a line to add when its API lands.
- **Uptime is not shown as a row.** "Started" shows the start time relatively with the exact time on hover, which says the same. About uses `formatCount` beside `formatBytes` and `formatDateTime`, as every other Settings screen does, so the shared `format` chunk keeps its shape.
- **The tab's build id is `__SVELTEKIT_APP_VERSION__`, not `$app/environment`'s `version`.** Same value (`kit.version.name`). About would be the only app code importing `$app/environment`, which adds an export to the shared runtime chunk and renames its minified exports, growing Alerts, Alert, Logs, Detail and Insights (reviewer's finding).
- **The body loads through `about/body.ts`,** as Security's and Logging's do, so its preload list stays out of the registry chunk. That brought the entry's cost on other Settings first views from ≈ 190–200 B to ≈ 90 B.
- **Links to other Settings screens show only while that screen exists** in the registry (`screens`). Until Updates (S-updates) lands, "Update settings" and a connection whose screen is missing show as plain text.
- **Privacy (§12.1).**
  - The version block and the diagnostics block are plain text built in `logic.ts`. The diagnostics hold versions, platform, deployment, data formats, the logging preset and the names and sources of changed settings. They never hold a setting's value, the data directory, a path, the time zone, or a torrent.
  - They are shown in the page before **Copy diagnostics** or **Report a problem** can use them. **Report a problem** expands inline (no dialog library) with exactly the text that goes into a prefilled GitHub issue URL; the link opens only when the user follows it. Past 6,000 characters the URL carries no body: the text is copied to the clipboard and the plain issue page opens.
  - Copying uses `copyText` (plain-HTTP LAN works); when neither path works, the text stays visible with "Select the text and press Ctrl+C".
- **Links.** Built from the build's `repository`, accepted only as a plain `https:` URL (no credentials, query or hash), so a fork links to itself and a hostile value never becomes a link. Source for this version is the exact tag on stable and beta, the commit otherwise. All external links open in a new tab with `rel="noopener noreferrer"` and "(opens in a new tab)" for screen readers.
- **Licences and credits.** Lodestar's AGPL-3.0-or-later notice, the fonts, icons and brand credits are in the first view as text (about 0.2 KB). The open-source component list is its own part (`Licences.svelte`), loaded when **Show open-source components** is pressed; it fetches the build's content-hashed `licenses.json` (`virtual:licenses`), is searchable, and shows the first 100 matches. Showing each licence's full text is a slot (the document carries the texts by SHA-256).
- **Parts load on demand.** `Diagnostics.svelte` and `Licences.svelte` load on a button press; the navigation icon and the purpose line (`about.ts`, for the filter) load as the registry's other lazy modules do. A part that fails to load shows the one error line and the button stays.
- **Lockup.** The horizontal lockup follows the theme's mode, read once when the page opens; a theme change happens on Appearance, so About is rebuilt on return.
- **Size gates** (`web/.size-limit.mjs`). The About first view and the parts are gated as the other hand-built screens are; the parts also stop at the body's chunk, as Security's later parts do, because they share its modules. `about/body.ts` joins the body forwarders. New entries: "Settings about parts (on demand)" 3.44 KB (measured 3,124 B + 10%) and "Settings about icon and purpose (on demand)" 0.39 KB (measured 349 B + 10%). No existing limit was raised. - **Registry tests.** `shell/screens.test.ts` and `shell/SettingsShell.test.ts` list the navigation; each gains "about" / "About" at the end of the System group. Outside this slice's folder; approved by the runner.
- **Slots the review found, left for later (each is a line to add):** a copyable data directory; Lodestar's full licence text, the palette credits and brand notices from `licenses.json` (`lodestar.texts`, `credits`, `notices`); a **Report a problem** entry in the Help list itself (today it sits beside the diagnostics, behind **Show diagnostics**); the Syntax guide link under Documentation; a skeleton for the loading state; the lockup follows the theme mode after mount, so it can flash light first (reuse `$lib/shell/theme-mode.ts` when the shell exposes it).
- **The stale-tab banner is only the second line of defence.** A tab left open across an upgrade asks for About's old hashed chunk, which no longer exists, so About may fail to load before it can say so. **The app-shell check on every page load is the real fix**, and should be scheduled, not treated as optional.
- **Server-supplied links.** The release notes link (`notes_url`) goes through the same plain-`https:` check as the repository (`httpsUrl`). A failed **Check now** keeps the last status and shows its own error; a refused repeat press (once a minute) reads as "try again in a minute".
- **Outside this slice's folder, approved by the runner on review (flag if not):** `e2e/shell.routes.test.ts` gains a `getUpdates` override in the overflow-menu test, because that test now lands on a real About screen. The two registry tests above are the other edit.
- **Messages.** `settings_about_*` in `about/messages/{en,zh}.json`. zh is filled for all keys. They are plain Paraglide messages (no form-engine map): About has no form fields.
