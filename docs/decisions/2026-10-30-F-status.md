# F-status decisions

- **The pill reads progress, not only liveness.** It adds two states, `starting` and `stalled`, on top of the crawler stream. `stalled` applies when the API names a reason (`kpi.health.reason`, `stale.reason`, or an exception of kind `writer_stalled`, `cohort_stalled` or `index_lag`), or when the Insights `ingest_per_hour` is 0 with the crawler working (fetches active or pending) and `uptime_s` at least 8 h. `ingest_per_hour` is the last full UTC hour, which can start two hours back, so 8 h = the 6 h suppression plus two hours makes the reported window lie wholly after it. Fetching that never reaches the store counts as a stall, so the fetch rate plays no part. A null rate is unknown, never a stall. The client compares and never computes a rate (`runner/standards.md` §4). An `index_lag` stall gets its own wording (storing works; search trails).
- **Startup suppression is a client constant for now.** Nothing in the REST API exposes the remaining sampling suppression (`dht_sample_suppression_seconds` is a metric only), so the pill compares the API's `uptime_s` with 6 h. `starting` shows only while uptime is under 6 h and nothing is flowing yet; a young crawler that is storing shows `crawling`. This narrows the brief's literal "while uptime is under 6 h" so a healthy young install is not labelled "Starting"; the runner flags it to the owner (§2.19). A real API field would replace the constant.
- **Polling.** The pill asks cheap `GET /stats` every 60 s while the tab is visible (and when it becomes visible). It asks the Insights overview (a rollup query) at once when fetching is 0 or the index lags past 30 s, and otherwise every 5 minutes, because a writer can stall while fetches still count. It does not ask while paused. A null fetch rate (first minute) is not treated as odd.
- **Insights overview** shows a stalled banner above the stage strip for the server's own `writer_stalled` or `cohort_stalled`, and for the pill's `no_progress` verdict (which needs `uptime_s`, so it comes from the shell). An `index_lag` has its own exception, and a stale banner already covers a writer stall, so neither adds a second warning.
- **uTP.** `transport.utp` is labelled "not active yet" in the settings messages (label and help); uTP has no runtime effect until CR-4. The Rust schema carries no label text, so no shared-file change is needed.
