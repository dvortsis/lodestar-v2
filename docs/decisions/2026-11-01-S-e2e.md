## What this slice adds

- **`states.test.ts`** joins the `bp*` matrix projects (`testMatch` in `playwright.config.ts`): the not-found state, axe in every project, a baseline in Comfortable only (Compact would repeat the same pixels). 14 new baselines, all in the matrix; none in the PR-run `sample-*` or `core` projects, none added to nightly.
- **`support/settings-fixture.ts`** (the backend's golden settings index plus a General section) wired into the `settings` smoke route. `settings-smoke-fixture.routes.test.ts` (`core`) checks the field renders. The Settings baselines change on purpose; the `.update-snapshots` marker is in this PR and only Settings images (and the new `state-not-found` ones) should differ.

## Still open

- The fixture-backend specs (`*.fixture.test.ts`) match no project and run only by hand; the fixture CI job is not wired here.

## App gaps, for follow-up (no app code changed here)

- `data-illustrations="false"` is set on `<html>` (`appearance/prefs.ts`) but nothing reads it: `StateScene.svelte` still renders the picture. The Show illustrations toggle does not hide illustrations.
- Nothing honours `Save-Data` (no `navigator.connection.saveData` or header check). §10.19 requires illustrations hidden under it.
- Once both exist, a spec can set `illustrations: false` through `getSettings` and emulate `Save-Data` and assert `[data-testid="state-screen"] img` is absent. No `test.fixme` was added: it would only assert what the app does not do.
