# X-watch-open-fstat decisions

Follows #1104's review: `Folder::open` (`crates/lodestar/src/watch.rs`) checked the watch folder's **path** and then opened it, so a parent swapped in between made the checks describe another folder. Checks now describe the folder that was opened. Behaviour, error kinds, catalogued events and messages for a normal folder are unchanged; no check is loosened.

- **Unix: one open, then everything through the handle.** The path check (`folder_problem`) still runs first, so its reasons (`not_absolute`, `missing`, `link` and the rest) come out as before. The folder is then opened `O_DIRECTORY | O_NOFOLLOW` as before, and its type and the data-directory rule are checked again through that handle: the folder's real place is found by `..` from the handle (`fstatat(fd, "../../…")`, device and inode, at most 1,024 levels), never from a path. The data directory is opened and walked the same way; if it can't be opened, the path check alone decides, as it did. A walk that fails is `unreadable`. The listing (`Dir::read_from(fd)`), each entry's type and shape (`fstatat(fd, name, AT_SYMLINK_NOFOLLOW)`) and the `added/` and `failed/` checks and creation now go through the handle too; reads, renames and removals already did. Why: a check made through the handle is about the folder that's read, whatever the path names later.
- **Windows: identity re-checks, since there are no handle-relative calls without `unsafe`.** The folder is still held open without delete sharing, so it can't be renamed or deleted during the poll. After it's held, the path checks run again and the path must still name the held folder by volume serial and file index (`same-file`, already a dependency). That's checked again after `added\` and `failed\` are held, after each listing and after each read. A mismatch stops the poll as `unreadable`, or leaves the file for a later poll (`wait`). What's left: a parent junction pointed elsewhere and back again between two of those checks. Only a folder layout the operator made allows that, and the operator sets the path (the finding is low).
- **Parent links are still followed, as before.** The rule is unchanged: only the folder's own entry, `added/`, `failed/` and the files can't be links. A parent swapped for a link after the open changes nothing for that poll. The next poll opens the path again and follows it.
- **Where the race tests live.** `Folder` is private, and the binary opens the folder again on every poll, so the swap-after-open tests are unit tests in `src/watch.rs` (Unix and Windows). `tests/watch.rs` adds a served-binary test: a folder swapped for a file and then for a link is refused with each reason, and the other folder is never read or written.
