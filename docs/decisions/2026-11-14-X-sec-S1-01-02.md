# X-sec-S1-01-02 decisions (#PR)

Security fixes S1-01 and S1-02 (both important) in the DHT node (`crates/dht`). This file says what the code now does (`docs/security/v1/README.md` §5).

- **S1-01: transaction ids are now unpredictable.** Each outgoing query's id is a keyed permutation of a per-process counter (`node/tids.rs`): an 8-round Feistel network over 64 bits with keyed SHA-256 rounds (the crate's existing `sha2` dependency; no new dependency), cycle-walked into the lower half of the range. Two properties are kept by construction: an id is never reused within the process (the counter never repeats and the permutation is a bijection), and every id stays below the sampler's proof-token bit (CR-0d). The key is drawn at start from the actor's RNG, the same source as the `announce_peer` token secrets: production seeds it from the OS, and only the deterministic simulator (`testing` feature) seeds it from a fixed value. Plain random ids were not used because they could collide with an id still outstanding. Cost: about 16 single-block SHA-256 calls per query on average (a few microseconds), small next to the send.
- **S1-02: the external-address vote counts same-family voters by /48.** A report of our address counts only when the reporter reaches us over the same family as the address it reports (a v4-mapped reporter is an IPv4 one); other reports are ignored. The voter unit is now an IPv4 /24 (unchanged) or an IPv6 /48 (was /64), because one site is commonly given a whole /48. Window (32), quorum (5) and the more-than-half rule are unchanged. The reachability check's networks (`UnsolicitedFrom`) stay /24 and /64. The `docs/architecture.md` §16 entry on reachability and the external address is updated to match (at the runner's request; the file is outside this slice's `owns`).
- **S1-02: a BEP 42-valid responder id is not required to vote.** Considered and declined: a valid id can be generated for any address at no cost, so requiring one doesn't make a voter any harder to obtain, while it would drop every non-compliant honest node from the vote and could leave it short of quorum on networks where few nodes comply.
- **Tests state the invariants in general terms:** ids distinct and below the proof bit over a long run, no pattern between consecutive ids, the permutation inverts (property test); a cross-family report isn't counted, many hosts across one /48 count once, honest reports of either family converge, and a property test over random voter sets checks that the address changes only with a same-family majority of distinct voter units.
