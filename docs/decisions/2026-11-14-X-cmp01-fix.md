# X-cmp01-fix decisions

- **CMP-01 (important, companions; detection and requests on loopback) fixed in part.** Its detail is held under `docs/security/v1/README.md` §5 until a release with the fix is published. This file says only what the code now does. The rest is the follow-up below, which has to land before the first managed pin (the runner's condition).

## Calls
- **One loopback address a port** (architecture §18.10; plan `2026-11-06-v06-companions` Q12). `CompanionHttp` sends a loopback target to `127.0.0.1`. It tries `::1` only when nothing listens on `127.0.0.1` and the request is a bare probe: a `GET` with no header and no body, which is what `ProbeRequest::new` builds and what detection and the health check send.
- **The first address to answer on a port keeps it.** That address is remembered for as long as the `CompanionHttp` lives, and every later request to the port goes to it alone, a bare probe included. A failure that only follows an accepted connection (an over-long answer, an unreadable one) counts as an answer on `127.0.0.1`; on `::1` only an answer does.
- **So a request that carries anything goes only where a probe already found the companion.** Any header (a key, a cookie) or body makes a request not bare, whatever its values: a session cookie travels as a plain header, so the rule doesn't depend on the value being marked secret. Before any probe, such a request stops at `127.0.0.1`.
- **A companion that listens on `::1` only still works:** a probe finds it there, and its requests follow.
- **What changes for a hand-run companion:** one that moves from `127.0.0.1` to `::1`, or back, while Lodestar runs isn't found again until Lodestar restarts. Managed companions are bound by Lodestar, so they don't move.
- **Container and entered-URL targets are unchanged.**

## Tests
- `crates/companions/tests/detect.rs`: `only_a_bare_probe_looks_on_ipv6_loopback` and `the_first_loopback_address_to_answer_keeps_the_port`, against real listeners on both loopback addresses of one port. They need `::1`; where it can't be bound they say so and, on CI, fail, as `loopback_falls_back_to_ipv6` already does.
- `crates/companions/src/detect/mod.rs`: what counts as bare, that a port's address is remembered once, and what shows a listener, without sockets.
- **Not run where they were written:** the build container has no IPv6 at all, so the two integration tests ran only on CI. The unit tests ran locally.
