# X-cmp01-fix decisions

- **CMP-01 (important, companions; detection and requests on loopback) fixed in part.** Its detail is held under `docs/security/v1/README.md` §5 until a release with the fix is published. This file says only what the code now does. The rest is the follow-up below, which has to land before the first managed pin (the runner's condition).

## Calls
- **One loopback address a port** (architecture §18.10; plan `2026-11-06-v06-companions` Q12). `CompanionHttp` sends a loopback target to `127.0.0.1`. It looks on `::1` only when nothing listens on `127.0.0.1` and the request is a bare probe: a `GET` with no header, no body and no query, which is what detection and the health check send.
- **`127.0.0.1` keeps a port for good.** Once it has answered on a port, every later request to that port goes to it alone, a bare probe included, for as long as the `CompanionHttp` lives. A failure that only follows an accepted connection (an over-long answer, an unreadable one) counts as an answer.
- **A port found on `::1` is remembered as that only until `127.0.0.1` answers.** Each later bare probe still asks `127.0.0.1` first, and an answer there takes the port. The health check probes every second, so a companion that starts listening on `127.0.0.1` has the port within about a second.
- **A request that carries anything goes only where a probe found the companion.** Any header (a key, a cookie), body or query makes a request not bare, whatever its values: a session cookie travels as a plain header, so the rule doesn't depend on the value being marked secret. Before any probe, such a request stops at `127.0.0.1`. With the port remembered on `::1`, it goes to `::1`.
- **A companion that listens on `::1` only still works,** within one `CompanionHttp`: a probe finds it there, and its requests follow.
- **The memory is each `CompanionHttp`'s own.** Lodestar builds three today (the health watch, the guided path and the managed path), and each starts with none.
- **Container and entered-URL targets are unchanged.**

## What this leaves, stated as behaviour
- **While nothing has answered on `127.0.0.1` for a port, whatever first answers a bare probe on `::1` is taken as the companion there,** and requests that carry something go to it until a bare probe finds `127.0.0.1` listening. For a managed companion, which Lodestar binds to `127.0.0.1`, that is the time between its start and its first answer, plus up to one health probe.
- **After a restart, a hand-run companion on `::1` only is not found by a request that carries something until a bare probe has run on the same `CompanionHttp`.** Detection and the health check send one; a guided step that begins with a keyed request does not.
- **A hand-run companion that moves from `127.0.0.1` to `::1` while Lodestar runs** isn't found again until Lodestar restarts.

## Tests
- `crates/companions/tests/detect.rs`, against real listeners on both loopback addresses of one port, each held for the whole test:
  - `only_a_bare_probe_looks_on_ipv6_loopback`;
  - `ipv4_loopback_keeps_the_port_once_it_has_answered`;
  - `ipv4_loopback_takes_a_port_found_on_ipv6`.
  They need `::1`; where it can't be bound they say so and, on CI, fail, as `loopback_falls_back_to_ipv6` already does.
- `crates/companions/src/detect/mod.rs`: what counts as bare, how a port's address is remembered and replaced, and what shows a listener, without sockets.
- **Not run where they were written:** the build container has no IPv6 at all, so the three integration tests ran only on CI. The unit tests ran locally.

## Follow-ups
- **Tie a managed companion's requests to the supervised process** (runner; before the first pin): a request that carries a credential goes out only while the supervisor holds the child it started on that port. It needs the supervisor (`crates/companions/src/supervise/**`, `manager.rs`), outside this slice's owned paths.
- **A `127.0.0.1`-only `CompanionHttp` for the managed path, and one shared instance** (runner; with the slice above): managed companions never listen on `::1`, so their client shouldn't look there; and one instance for the watch, the guided path and the managed path would let a probe by any of them serve the others. Both need `crates/lodestar/src/companion_wiring.rs` and `companions.rs`, outside this slice's owned paths.
- **The exact-input regression test** lands after the release with the fix (`docs/security/v1/README.md` §5).
