# CR-0d decisions (design, PR pending)

Phase 1 of CR-0d: the crash-safe restart protocol that lets a restart skip CR-0's 6 h sampling suppression when, and only when, the node can prove it knows every BEP 51 restriction still in force. The contract is the master plan's "CR-0d" entry (`2026-10-30-master-plan.md`, Part A3). It replaces nothing in `2026-10-25-CR-0.md` while the switch is off. No code is written until the runner OKs this design and CR-0f (#200) is on `main`.

## 0. Terms
- **Restriction (obligation):** an endpoint we must not send `sample_infohashes` to before a deadline. It's the sampler's `Cooling { until }` entry (the remote's `interval`, clamped to 60 s–6 h; `UNSUPPORTED_BACKOFF`; `SAMPLE_TIMEOUT_BACKOFF`), or an in-flight sample at shutdown (§3).
- **Horizon `H`:** `sampler::MAX_INTERVAL + query_timeout` (21,604 s by default). It's today's suppression length, and no restriction can last longer. An in-flight sample at its latest possible reply gets at most `MAX_INTERVAL`.
- **Resume:** start sampling with no start delay. The restored restrictions are seeded into the sampler as `Cooling` entries.
- **Suppress:** today's behaviour. No samples until `H` after this run's start. Every check failure leads here, and the reason is recorded (§5).

## 1. On-disk format

### 1.1 Files
All files except the witness live in the data directory, next to `dht-state.bin`:

| File | Written | Purpose |
| --- | --- | --- |
| `dht-restart.bin` | Only at a clean shutdown | Snapshot: the restriction table |
| `dht-restart.mark` | At the start of every run (dirty), and as the last step of a clean shutdown (clean) | The marker. Only a clean marker lets the next start resume |
| `<witness dir>/<dir_id hex>.gen` | At the start of every run, before the dirty marker | Witness: the last generation that ran, kept **outside** the data directory, so a restored backup can't roll it back (§1.5) |

`lodestar backup` doesn't copy any of these files, or `dht-state.bin`. Its list of files is explicit, and stays that way (the same reasoning as `bin/trust.json`: a restore must never bring back an older proof).

### 1.2 Container (the same for all three files)
```text
magic    8 bytes   "LDSRSNAP" | "LDSRMARK" | "LDSRWITN"
version  u32 LE    1
len      u32 LE    length of body; snapshot ≤ 8 MiB, marker and witness ≤ 4 KiB
body     len bytes canonical bencode dictionary (strict decode, as in state.rs)
sha256   32 bytes  SHA-256 of magic‖version‖len‖body
```
The file is invalid, and the run suppresses, if any of these is wrong: the magic, the version (`version`), the length, the trailing bytes, the checksum, canonical bencode, an unknown or missing key, or a field out of range (`corrupt`). SHA-256 is already in the workspace (`sha2`). A CRC would catch a torn file, but not a marker that pairs with a different snapshot.

### 1.3 Bodies
**Marker** (`dht-restart.mark`):
- `state`: `"clean"` or `"dirty"`;
- `gen`: u63, the run generation (§1.4);
- `dir_id`: 16 random bytes, created on the first run with the switch on. It names this data directory;
- `dir_path`: SHA-256 of the canonicalised data-directory path;
- `ids`: SHA-256 of the node's virtual ids, sorted and concatenated;
- `run_id`: 16 random bytes for this run;
- `at`: the wall clock when it was written, as Unix ms;
- clean only: `snap`, the SHA-256 of the whole `dht-restart.bin` file, and `state_bin`, the SHA-256 of `dht-state.bin` as written in the same shutdown.

**Snapshot** (`dht-restart.bin`):
- `gen`, `dir_id`, `ids` and `run_id`, matching the clean marker;
- `at`: the capture time, as wall-clock Unix ms;
- `horizon`: `H` in seconds when written;
- `r4`: concatenated `ip(4) port(2 BE) remaining(4 BE)`;
- `r6`: concatenated `ip(16) port(2 BE) remaining(4 BE)`.

`remaining` is in whole seconds, rounded **up**, from `at`. So each restriction's wall-clock deadline is `at + remaining` (the brief's clock policy). Entries are sorted by address, with no duplicates and `0 < remaining ≤ horizon`; anything else is `corrupt`. Addresses are normalised as the sampler normalises them (`network_policy::normalize`, so IPv4-mapped addresses become IPv4).

**Witness** (`<dir_id hex>.gen`): `gen`, `dir_id`, `dir_path` and `at`.

### 1.4 Generations
- Every run with the switch on claims `gen = previous + 1` at start, before it sends anything. The previous value is the clean marker's `gen`, or the dirty marker's, or 0.
- Its clean shutdown writes the snapshot and the marker with that same `gen`.
- Resuming needs `snapshot.gen == marker.gen == witness.gen`, a clean marker, and a witness that didn't advance since the marker was written. A witness ahead of the marker means a restore (`generation`). A missing witness means `no_witness`.

### 1.5 Witness location
- **Rule:** the witness must resolve (after canonicalisation) outside the data directory. If it doesn't, the run is treated as having no witness and suppresses (`no_witness`).
- **The setting is `dht.restart_witness_dir`.** The per-platform defaults:
  - **Windows MSI (service):** `C:\ProgramData\Lodestar-witness\`. The MSI's data directory *is* `C:\ProgramData\Lodestar` (`packaging/windows/README.md`), so a witness under it would be inside the data directory and could never work. The sibling folder is created by the MSI with the same SYSTEM/Administrators-only ACL as the data folder (`main.wxs`, a shared edit named in the PR).
  - **Windows portable:** `%LOCALAPPDATA%\Lodestar\witness\`.
  - **Linux native:** `$XDG_STATE_HOME/lodestar` or `~/.local/state/lodestar`, and `/var/lib/lodestar-witness` under systemd.
  - **Docker:** `/var/lib/lodestar-witness` in the container layer, not under `/data`. The Dockerfile creates it owned by 65532 (as it does `/data`). The PUID/PGID hand-over in `crates/lodestar/src/privdrop.rs` (the image has no shell entrypoint; the binary does the chown) must cover this directory too, so it stays writable after the remap. Both files are named in the Phase 2 PR.
- **Consequence on Docker (runner decision, flagged to the owner):** the witness lives as long as the container does. A `docker restart` or a host reboot resumes, but recreating the container (which every image update does) loses the witness and suppresses. A follow-up adds an optional state volume to the Unraid template (option C below).
- **Backups (to go in the user docs):** a restore is detected only when the backup unit excludes the witness. Back up the data folder itself (`C:\ProgramData\Lodestar`, `/data`, the Unraid appdata share), not its parent. A backup of all of `C:\ProgramData` that is restored wholesale also restores the witness, so that restore isn't detected. `stale` still catches it when the backup is older than `H`.

### 1.6 Atomic write (`write_atomic`)
1. Create `<name>.tmp` in the same directory (`create`, `truncate`), write the whole container, then `sync_all`.
2. Rename it over `<name>`. On Windows, use `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`. Today's `std::fs::rename` doesn't set write-through, so Phase 2 adds it to the new module only.
3. Fsync the directory on Unix. On Windows, write-through stands in for it, as `cli/util.rs::sync_dir` already records.

Start removes stale `*.tmp` files and never reads them.

| Crash point | What a later start sees | Why it's safe |
| --- | --- | --- |
| Before or during step 1 | The old file, plus a torn `.tmp` that's ignored | The old file is still self-consistent |
| After step 1, before the rename is durable | The old file or the new one, each whole | Both are valid states of this protocol (§2) |
| After step 3 | The new file | — |

A torn or mixed final file can't pass the SHA-256 check. It gives `corrupt`, which means suppress.

## 2. State machine
The protocol runs inside `actor::run`, before the event loop and after it. With the switch on:

| # | Step | Crash after this step and before the next → next start |
| --- | --- | --- |
| S0 | Start: take the clock readings (`wall0`, `mono0`) | Nothing written. Outcome as for the previous run's files |
| S1 | **Load:** read the marker, snapshot, witness and `dht-state.bin`; delete `*.tmp` | Nothing written. Same as S0 |
| S2 | **Validate** (§2.1); choose Resume or Suppress(reason); compute this run's `gen = G+1` | Nothing written. Same as S0 (still nothing sent) |
| S3 | **Witness ← G+1** (atomic) | Witness G+1, marker clean G → `generation` → **suppress** (safe; it costs one 6 h window) |
| S4 | **Marker ← dirty G+1** (atomic), then delete `dht-restart.bin` | Dirty → **suppress** |
| S5 | **First send** (the bootstrap find_nodes). Samples start now on Resume, or after `H` on Suppress | Dirty → **suppress** |
| S6 | Run. The restriction table is in memory, keyed by `Instant` | Dirty → **suppress**, whatever the crash (kill -9, panic, power loss) |
| S7 | **Shutdown requested: quiesce.** Set `sampling_closed`. `sample_tick` and `try_query(Purpose::Sample)` refuse from now on | Dirty → **suppress** |
| S8 | **Settle or record:** every in-flight sample becomes a restriction with `until = now + query_timeout + MAX_INTERVAL` (§3.2). No waiting | Dirty → **suppress** |
| S9 | The event loop exits; no packet is sent after this. `dht-state.bin` is saved (atomic, plus a directory fsync, the existing `State::save` with one added step); its SHA-256 is kept | Dirty → **suppress** |
| S10 | **Snapshot ← table** (atomic): live entries only, `remaining = ceil(until − now_mono)` | Dirty → **suppress** |
| S11 | **Marker ← clean G+1** with `snap` and `state_bin` (atomic). This is the commit point | Clean G+1 → **resume**, with the snapshot it names |

Crashes *between* S2 and S3, and the S3 crash points before the rename is durable, leave the previous clean marker in place. That's still safe: S5 hasn't happened, so this run sent nothing and the previous snapshot is still the complete record. This is why the dirty marker must be durable **before** the first send, and why S3 and S4 come before the bootstrap.

**S3/S4 failure** (an I/O error):
- If a clean marker existed and the run can't make it dirty or delete it durably, **this run sends no samples** (`invalidate_failed`). Otherwise a crash later in the run could leave an old clean proof in place.
- If no clean marker existed, there's nothing to invalidate. The run suppresses as usual and just won't resume next time.
- Routing, passive service and lookups are unaffected either way.

**S9–S11 failure:** logged with the step, and counted (`dht_restart_persist_errors_total{step}`). The marker stays dirty, so the next start suppresses.

### 2.1 Validation (S2): the first failure wins and suppresses
1. `first_start`: no marker at all. This covers first installs, the first run after the switch is turned on, and upgrades from v0.5.x. The owner's choice stands: the first start stays suppressed.
2. `corrupt` or `version`: any of the three files fails §1.2 or §1.3, or the snapshot is missing.
3. `dirty`: the marker isn't clean. The last run crashed, was killed, or failed in S9–S11.
4. `data_dir`: `dir_id` or `dir_path` differs between the files, or from this data directory.
5. `node_identity`: `ids` differs from the ids this run will use (`initial_ids` after loading `dht-state.bin`). For example, a new external IP made BEP 42 regenerate them, or `dht-state.bin` is gone.
6. `foreign_run`: `dht-state.bin`'s SHA-256 differs from the marker's `state_bin`. Another writer ran on this data directory after the clean stop: an older Lodestar build that ignores these files, or a run with the switch off that couldn't delete the marker (§5.2). Old builds suppress for 6 h and save `dht-state.bin` every 10 min, so any run that could have sent a sample has rewritten that file.
7. `snapshot_mismatch`: `marker.snap` ≠ SHA-256 of the snapshot, or the `gen` values disagree.
8. `no_witness` or `generation`: the witness is missing, unreadable, foreign, or isn't exactly `marker.gen`.
9. `clock_backward`: `now_wall < marker.at`.
10. `stale`: `now_wall − marker.at > H`. Every restriction would have expired, so the snapshot proves nothing useful. A long gap is also where restore and clock errors hide, and suppressing then costs nothing compared with today.

Only if all ten pass: **Resume**. Each entry gets `left = (snapshot.at + remaining) − now_wall`. Entries with `left ≤ 0` are dropped. The rest are seeded as `Cooling { until: now_mono + left }`.

## 3. Obligation semantics
### 3.1 Key
A restriction belongs to the **remote endpoint**: the normalised `SocketAddr`, the same key as the CR-0 sampler. It doesn't belong to the sample target or the node id. The target is random per query and BEP 51's `interval` is about re-querying the node. Node ids aren't authenticated and could be rotated to dodge a restriction.

### 3.2 Values
- **Cooling:** `until`, unchanged. The remote's interval is clamped to 60 s–6 h; `UNSUPPORTED_BACKOFF` and `SAMPLE_TIMEOUT_BACKOFF` are 6 h.
- **In flight at S8:** `now + query_timeout + MAX_INTERVAL` (= `now + H`).
  - This bounds every outcome. A reply could arrive up to `query_timeout` after it was sent, and would set at most `MAX_INTERVAL`. A timeout sets `SAMPLE_TIMEOUT_BACKOFF` = `MAX_INTERVAL` from the timeout.
  - S8 doesn't wait for replies: it adds no latency to shutdown (Docker's 10 s stop budget, and the B-log1b shutdown work). The bound is conservative, and the in-flight count is small.
- **Restored entries** keep their deadline. A new reply can't arrive for them, because the sampler refuses to sample those endpoints until they expire. They're written again at the next shutdown if they're still live.

### 3.3 Clock
- **In the run:** monotonic `Instant`, as today, so wall-clock steps during a run can't shorten a restriction. Linux `CLOCK_MONOTONIC` stops during suspend, which only lengthens real-time cooldowns.
- **Across a restart:** wall-clock deadlines (`at + remaining`), converted at S10 and back at S2.
- **A backward step between runs** suppresses (`clock_backward`). On its own it would only lengthen restrictions, but it shows the clock can't be trusted, and the brief requires suppression.
- **A forward step larger than what's left of the horizon** suppresses as `stale`.
- **Known residual (accepted by the runner):** suppose the wall clock is wrong but steady for a whole run, then corrected forward by `e` before the next start, where `e` is less than what's left of the horizon. The restored restrictions are then shortened by `e`. A clock wrong only at the start of a run and corrected during it does no harm, because S10 converts with the shutdown-time clock. No local check can see a steady offset, and there's no NTP check. A test documents the residual.

### 3.4 Size and pruning
- **Table:** the sampler's existing table, which already holds both cooling and in-flight entries, bounded by `MAX_KNOWN = 200,000`. Restored entries count against the same cap. The table is complete by construction: a sample is sent only after `reserve` creates an entry, and `reserve` refuses when the table is saturated.
- **File:** at most 200,000 × 22 bytes ≈ 4.4 MiB, with an 8 MiB cap. A file over the cap, or with more entries than `MAX_KNOWN`, is `corrupt`.
- **Pruning:** S10 writes only live entries, and S2 drops expired ones. The sampler's existing `prune` (1,024 per tick) retires restored entries like any others.
- **Load cost:** one sequential parse, O(n log n) to insert into the expiry index, done before the event loop.

## 4. Pause and resume (CR-0f)
- **A pause isn't a shutdown for this protocol.**
  - The process keeps the authoritative table in memory. The marker stays dirty, and nothing is written.
  - `SetPaused(true)` already stops `sample_tick`, and in-flight samples still settle through `maintain`.
  - Restrictions keep expiring during a pause.
  - Unpausing doesn't restart the 6 h window or clear restrictions. CR-0f's pause changes only touch the peer-request queue (dropped replies, no lost attempt) and bootstrap seeds. They don't touch the sampler.
- **A start in the paused state** (`Config.paused`) still runs S1–S4 before the first send. Bootstrap may send even while paused.
- **A shutdown while paused** goes through S7–S11. S7 is already true, and S8 records whatever is still in flight.
- **An in-process restart of the DHT source** (`DhtSource::run` ending and starting again) is an ordinary stop and start. The old actor commits at S11, and the new one validates at S2 against the same witness. This is the commonest case where the switch pays off.
- **Ordering with CR-0f:** `pipeline/control.rs` pauses the pool before the DHT. That doesn't affect this protocol, because sampling is the DHT actor's alone.

## 5. The switch
### 5.1 Name and plumbing
- **App config:** `[dht] safe_restart = false`, with the environment variable `LODESTAR_DHT_SAFE_RESTART`. It takes effect at start. It isn't in the Settings UI in this slice: it's a release-delta item, and stays out of v0.5.1 unless the delta review says otherwise.
- **Library:** `lodestar_dht::Config.restart: Option<RestartConfig { witness_dir }>`. `None` means off.
- **Ignored with `sample_start_delay: Some(..)`:** the protocol then behaves as off. The fixtures keep their explicit override.
- **Ignored with `state_path: None`:** off, because there's no data directory.

### 5.2 Off behaviour (default)
- **Today's behaviour, plus one safety step.** Suppression is `H` from every start, and the protocol never writes `dht-restart.*` or the witness.
- **The safety step:** if `dht-restart.mark` exists, the off-run deletes it durably (unlink, then a directory fsync) before its first send.
  - Without this, a run with the switch on, then one with it off, then one with it on again, would let the third run trust a marker that knows nothing of the second run's samples. `foreign_run` (§2.1 rule 6) is a second line of defence.
  - If the delete fails, the off-run sends no samples (`invalidate_failed`), the same rule as S3/S4.

### 5.3 Metrics and events
New metrics go in `docs/metrics.md` (a shared-file edit, to be named in the Phase 2 PR):

| Name | Type | Meaning |
| --- | --- | --- |
| `dht_sample_suppression_reason{reason}` | gauge, 1 for this run's reason | One of `off`, `first_start`, `corrupt`, `version`, `dirty`, `data_dir`, `node_identity`, `foreign_run`, `snapshot_mismatch`, `no_witness`, `generation`, `clock_backward`, `stale`, `invalidate_failed`, or `resumed` |
| `dht_restart_obligations_restored` | gauge | Live entries seeded at S2 (0 when suppressed) |
| `dht_restart_obligations_pending` | gauge | Restored entries not yet expired |
| `dht_restart_obligations_refused_total` | counter | Sample candidates refused because a restored restriction applied. This is the evidence that restrictions are honoured |
| `dht_restart_obligations_honoured_total` | counter | Restored entries that expired with no sample sent to them before their deadline. It equals `restored` once all have expired |
| `dht_restart_persist_errors_total{step}` | counter | I/O failures at `witness`, `invalidate`, `state_bin`, `snapshot` and `marker` |

- **Kept:** `dht_sample_suppression_seconds` stays. It reads 0 from the start of a resumed run.
- **New typed event `dht.restart_check` (Info):** `mode`, `reason`, `gen`, `restored` and `dropped_expired`. Counts only, no addresses. It's defined in `crates/dht/src/log_events.rs`, which is outside the owned paths (as CR-0f's was), with the logs catalogue golden regenerated.
- **Separate event `dht.restart_persist_failed` (Warn):** `step` and the error kind.

## 6. Test plan
No fixed sleeps anywhere:
- the persistence module takes a `Clock { wall_ms(), mono() }` seam;
- actor-level tests use `tokio::time::pause` and explicit instants, as the sampler tests already do;
- any wait on a condition has a deadline of at least 10 s.

1. **A crash at every step:**
   - **Seam:** a `#[cfg(test)]` fail point in `write_atomic` and in the S-sequence. The named points are: after the tmp write; after the tmp fsync; after the rename; after the directory fsync; and between S3/S4, S9/S10 and S10/S11.
   - **Two outcomes at each point.** "Stop here" leaves the files exactly as they are. "Lost unsynced write" models a power cut by restoring the pre-rename file and leaving a torn tmp.
   - **Check:** a fresh load gives exactly the outcome in the §2 table.
   - **One true kill -9 test:** a subprocess re-runs the test binary with `LODESTAR_TEST_ABORT_AT=<point>`, calls `abort()`, and the parent then validates.
2. **Loop:** load → resume → send a sample (to a fixture node) → crash → load. This must suppress (`dirty`) and never resume. Then a clean stop → load → resume, with the crashed run's restriction lost but suppression covering it, 100 iterations, randomised step.
3. **Clock skew, using the seam:**
   - backward 1 ms and 1 day → `clock_backward`;
   - forward within the horizon → resume, with deadlines shifted as specified;
   - forward beyond `H` → `stale`;
   - a wall-clock step during a run doesn't change the written deadlines;
   - the §3.3 residual is pinned by a test that documents it.
4. **Corrupt, truncated and foreign files:**
   - bit flips at every byte offset of a small snapshot and marker (each gives `corrupt`);
   - truncation at every length;
   - a wrong magic, version 2, oversize, duplicate or unsorted entries, `remaining = 0` or `> horizon`;
   - files from another `dir_id`, another path or other node ids;
   - a property test: arbitrary bytes never resume and never panic;
   - a `cargo fuzz` target for the decoder, because this parses untrusted input.
5. **A backup restored:**
   - copy the data directory at clean G, run G+1 cleanly, restore the copy → `generation`;
   - restore with the witness removed → `no_witness`;
   - a run with the switch off, or an "old binary" that only rewrites `dht-state.bin`, between two on-runs → `foreign_run`;
   - a witness directory inside the data directory → `no_witness`.
6. **Honouring restrictions:**
   - In-crate deterministic replay: restore 1,000 restrictions with mixed deadlines, drive `maintain` in paused time, and assert that no `sample_infohashes` reaches a restored endpoint before its deadline. `refused_total` must be above 0 and `honoured_total == restored` at the end.
   - A **CR-SIM** scenario does the same end-to-end once the CR-SIM harness is on `main`. If it isn't there when Phase 2 opens, the in-crate replay is the gate, and the CR-SIM scenario is listed as a follow-up for the runner.
7. **Switch off:**
   - byte-for-byte today's suppression (the existing `sample_restart_suppression…` test keeps passing);
   - a leftover marker is deleted before the first send;
   - an undeletable marker means no samples.
8. **Pause:** a pause doesn't write anything; a shutdown while paused commits; a paused start invalidates before bootstrap.

## Runner decisions (2026-10-30)
1. **The witness: option A, as written.**
   - **Why:** the owner-approved master plan requires "restored backup ⇒ full suppression". Only a witness outside the restored unit can detect a restore of a backup taken while Lodestar was stopped, which is what Unraid's appdata backup does. In practice that's a rollback after a bad update within 6 h; older restores are caught by `stale`.
   - **Option B is rejected.** No witness, relying on `stale`, would loosen the owner's rule, so it would need the owner.
   - **Option C is a follow-up:** an optional state volume in the Unraid template.
   - **The runner flags the Docker cost to the owner:** image updates suppress; restarts and reboots resume.
   - **Phase 2 details:** the Docker witness directory is covered by the PUID/PGID hand-over, and the backup guidance goes in the user docs, as §1.5 says. The runner assumed the MSI witness would sit under `%ProgramData%\Lodestar\`. That folder is the MSI's data directory, so §1.5 uses the sibling `C:\ProgramData\Lodestar-witness\` instead.
2. **The §3.3 forward-clock residual is accepted.** It needs a wrong clock held steady for a whole run, it's bounded by what's left of the horizon, and no local check can see it. The documenting test stays; there's no NTP check.
3. **No shutdown grace.** S8 records in-flight samples as `now + H` without waiting. That's conservative, and keeps Docker's 10 s stop budget.
