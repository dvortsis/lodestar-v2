# CR-0d decisions (design, PR pending)

Phase 1 of CR-0d: the crash-safe restart protocol that lets a restart skip CR-0's 6 h sampling suppression when, and only when, the node can prove it knows every BEP 51 restriction still in force. The contract is the master plan's "CR-0d" entry (`2026-10-30-master-plan.md`, Part A3). It replaces nothing in `2026-10-25-CR-0.md` while the switch is off. No code is written until the runner OKs this design and CR-0f (#200) is on `main`.

Revision 2 answers the Opus protocol review of `007f607a`, which found it sound with changes. Each finding's ID (B1, I1–I7, P1–P6) is cited where it's addressed.

## 0. Terms and the safety invariant
- **Restriction (obligation):** an endpoint we must not send `sample_infohashes` to before a deadline. It's the sampler's `Cooling { until }` entry (the remote's `interval`, clamped to 60 s–6 h; `UNSUPPORTED_BACKOFF`; `SAMPLE_TIMEOUT_BACKOFF`), or an in-flight sample at shutdown (§3).
- **Horizon `H`:** `sampler::MAX_INTERVAL + query_timeout` (21,604 s by default). It's today's suppression length, and no restriction can last longer. On disk it's always **`H_s = ceil_s(MAX_INTERVAL + query_timeout)`**, in whole seconds. That's what the `horizon` field holds, what rule 9 compares, and what bounds `remaining`, `gate` and `left` (N6).
- **Gate:** a blanket deadline before which no sample is sent to anyone (N1, §2).
- **Resume:** start sampling with no start delay. The restored restrictions are seeded into the sampler as `Cooling` entries.
- **Suppress:** today's behaviour. No samples until `H` after this run's start. Every check failure leads here, and the reason is recorded (§5).
- **Disabled:** no samples at all until a condition clears (`locked`, or `invalidate_failed` until it lands; §2).

Revision 3 answers the reviewer's re-check of `c5e1d9b3` (N1–N7).

### 0.1 Safety invariant
1. **Every run that doesn't resume sends no sample before `start + H`.** Here `start` is the moment the run takes the lock (S0), because until then another holder may have been sampling.
2. **Every clean commit records every restriction its run knows, plus a blanket `gate` covering what its run didn't know (N1).**
   - A suppressed run's gate ends at its own `start + H`.
   - A resumed run carries forward the gate it inherited.
3. **A resume requires `now_wall − marker.at ≤ H`,** and a clean marker whose generation the witness confirms. The resumed run then honours both the restored restrictions and the restored gate.
4. **So the only samples that can go unrecorded are those of a run that then didn't commit.** That run's earlier clean marker was invalidated, by the dirty marker or by the witness (N5), before its first sample, so the next start suppresses.
   - The suppressed run's own gate then covers those samples for the rest of their horizon, even if it stops cleanly within minutes.
   - The witness chains runs together, so a rolled-back data directory can't skip one.

Each rule below either keeps this invariant or is listed as a residual where it can't (§8).

## 1. On-disk format

### 1.1 Files
All files except the witness live in the data directory, next to `dht-state.bin`:

| File | Written | Purpose |
| --- | --- | --- |
| `dht-restart.lock` | Created once; never deleted or written | The exclusive OS lock (B1, §2.2) |
| `dht-restart.mark` | Overwritten **in place** at the start of every run (dirty, or `off`); replaced atomically at the end of a clean shutdown (clean) | The marker. Only a clean marker lets the next start resume |
| `dht-restart.bin` | Replaced atomically, only at a clean shutdown | Snapshot: the restriction table |
| `<witness dir>/<dir_id hex>.gen` | Overwritten **in place** at the start of every run, before the marker | Witness: the last generation that ran, kept **outside** the data directory (§1.5) |

`lodestar backup` doesn't copy any of these files, or `dht-state.bin`. Its list of files is explicit, and stays that way (the same reasoning as `bin/trust.json`: a restore must never bring back an older proof).

### 1.2 Container (the same for the marker, snapshot and witness)
```text
magic    8 bytes   "LDSRSNAP" | "LDSRMARK" | "LDSRWITN"
version  u32 LE    1
len      u32 LE    length of body; snapshot ≤ 8 MiB, marker and witness ≤ 4 KiB
body     len bytes canonical bencode dictionary (strict decode, as in state.rs)
sha256   32 bytes  SHA-256 of magic‖version‖len‖body
```
The file is invalid, and the run suppresses, if any of these is wrong: the magic, the version (`version`), the length, the trailing bytes, the checksum, canonical bencode, an unknown or missing key, or a field out of range (`corrupt`). SHA-256 is already in the workspace (`sha2`). A CRC would catch a torn file, but not a marker that pairs with a different snapshot. The snapshot is hashed as it streams to disk, with no second pass (P4).

### 1.3 Bodies
**Marker** (`dht-restart.mark`):
- `state`: `"clean"`, `"dirty"` or `"off"` (written by a run with the switch off, §5.2);
- `gen`: u63, the run generation (§1.4);
- `dir_id`: 16 random bytes that name this data directory (lifecycle in §1.4);
- `dir_path`: SHA-256 of the canonicalised data-directory path;
- `ids`: SHA-256 of the node's virtual ids, sorted and concatenated. At S11 this is the ids saved to `dht-state.bin` at S9, not those at start, because BEP 42 can rotate them mid-run (`actor.rs` ~1242; P2);
- `run_id`: 16 random bytes for this run;
- `at`: the wall clock when it was written, as Unix ms, rounded up. At S11 it's read *after* S10's wall reading, so `snapshot.at ≤ marker.at` holds whenever the clock doesn't step back, including when both reads fall in one Windows clock tick (~15.6 ms; N4);
- clean only: `snap`, the snapshot's container checksum (its trailing SHA-256, which covers every other byte of the file, so it names the file exactly and needs no second pass), and `state_bin`, the SHA-256 of `dht-state.bin` as written at S9.

**Snapshot** (`dht-restart.bin`):
- `gen`, `dir_id`, `ids` and `run_id`, matching the clean marker;
- `at`: the capture time, as wall-clock Unix ms, rounded up (I4);
- `horizon`: `H_s` when written (N6);
- `gate`: whole seconds from `at`, rounded up, with `0 ≤ gate ≤ horizon`. No sample may go to anyone before `at + gate` (N1, §2);
- `r4`: concatenated `ip(4) port(2 BE) remaining(4 BE)`;
- `r6`: concatenated `ip(16) port(2 BE) remaining(4 BE)`.

**Entry rules:**
- `remaining` is in whole seconds, rounded **up**, from `at`. So each restriction's wall-clock deadline is `at + remaining` (the brief's clock policy).
- Each of `r4` and `r6` must be a whole number of entries (10 or 22 bytes each).
- Entries are sorted by address, with no duplicates and `0 < remaining ≤ horizon`.
- Port 0 is rejected, and so is an IPv4-mapped address in `r6`. The writer normalises before writing (`network_policy::normalize`), so a mapped address there means the file wasn't written by us (P3).
- Anything else is `corrupt`.

**Witness** (`<dir_id hex>.gen`): `gen`, `dir_id`, `at`, and `path`, the canonical data-directory path in full, as UTF-8. A data directory whose canonical path isn't UTF-8, or is too long for the 4 KiB body, has no witness (`no_witness`). The witness dir is local and locked down, and the full path is what lets N7's copy rule and the orphan cleanup work.

### 1.4 Generations and `dir_id`
- **Generation:** every run with the switch on claims `gen = max(marker.gen, witness.gen) + 1` (P1), with 0 for a missing or unreadable file. The run's clean shutdown writes the snapshot and the marker with that same `gen`.
- **Resuming needs** `snapshot.gen == marker.gen == witness.gen`, and a clean marker. A witness ahead of the marker means a restore (`generation`). A missing witness means `no_witness`.
- **`dir_id` (P1):**
  - It's stored in the marker in every state, in the snapshot, and as the witness file's name and body.
  - **When the marker decodes, its `dir_id` is kept,** even if `dir_path` no longer matches (a move). That run suppresses (`data_dir`) and records the new path.
  - **A new `dir_id` is generated:**
    - when there's no marker that decodes (`first_start`, `corrupt`, `version`); or
    - **when the witness for this `dir_id` names another `path` (N7).** That's a copied data directory, or a moved one. Either way this run suppresses (`data_dir`). Without a fresh id, two copies on one host would keep overwriting one witness and suppressing each other for ever. A move gains nothing by keeping its id, since it suppresses once either way.
  - **Orphan cleanup:** at S3, once the new witness is durable, the run deletes `*.gen` files in the witness dir that meet either condition:
    - its `path` equals this data directory's but its `dir_id` doesn't (an earlier id of this directory);
    - its `path` no longer holds a decodable marker carrying that `dir_id` (a moved, copied-then-reset or deleted directory).

    It scans at most 256 entries. A witness for an unmounted drive's data directory may be deleted; that directory then gets `no_witness` once, which is safe.

### 1.5 Witness location
- **Rule:** the witness dir must resolve outside the data directory, after canonicalising both paths, so following symlinks. If it doesn't, or it can't be written (a read-only root filesystem, for example), the run has no witness and suppresses (`no_witness`). The failure is counted and shown on the status page (§5.3).
- **The setting is `dht.restart_witness_dir`.** The per-platform defaults:
  - **Windows MSI (service):** `C:\ProgramData\Lodestar-witness\`. The MSI's data directory *is* `C:\ProgramData\Lodestar` (`packaging/windows/README.md`), so the witness can't go under it. The MSI creates the sibling folder with the same SYSTEM/Administrators-only ACL as the data folder (`main.wxs`, a shared edit named in the PR).
  - **Windows portable:** `%LOCALAPPDATA%\Lodestar\witness\`.
  - **Linux native:** `$XDG_STATE_HOME/lodestar` or `~/.local/state/lodestar`, and `/var/lib/lodestar-witness` under systemd.
  - **Docker:** `/var/lib/lodestar-witness` in the container layer, not under `/data`. The Dockerfile creates it owned by 65532 (as it does `/data`). The PUID/PGID hand-over in `crates/lodestar/src/privdrop.rs` must cover this directory too, so it stays writable after the remap. The image has no shell entrypoint: the binary does the chown. Both files are named in the Phase 2 PR.
- **Consequence on Docker (runner decision, flagged to the owner):** the witness lives as long as the container does. A `docker restart` or a host reboot resumes, but recreating the container (which every image update does) loses the witness and suppresses.
- **Backups (I2; this goes in the user docs):**
  - A restore is detected only if the witness is never backed up, or restored, together with the data.
  - Back up the data folder itself (`C:\ProgramData\Lodestar`, `/data`, the Unraid appdata share), not its parent.
  - Two kinds of restore also roll the witness back, so they aren't detected: a restore of all of `C:\ProgramData`, and a whole-machine or volume snapshot (VM, ZFS, btrfs, Proxmox). This is a residual (§8). `stale` still catches it when the backup is older than `H`.

### 1.6 Writes
There are two write paths. Neither relies on `unlink`, and neither relies on `cli/util.rs::sync_dir`, which swallows errors (I6). The workspace forbids `unsafe`, so `MoveFileExW(WRITE_THROUGH)` isn't available. The design therefore never relies on a Windows rename being durable for safety.

**`overwrite_in_place` (invalidation: the dirty or `off` marker, and the witness bump):**
1. Open the existing file for writing, without truncating it, and write the new container at offset 0.
2. `set_len` to the new length.
3. `sync_all` (fsync, or FlushFileBuffers on Windows). This flushes file data on every platform and doesn't depend on any directory entry.
4. If the file doesn't exist yet, create it, write it and `sync_all` it. On Unix, also fsync the directory, and propagate any error from that.

| Crash point | What a later start sees | Why it's safe |
| --- | --- | --- |
| Before step 1 | The old record | Nothing has been sent yet (§2) |
| During steps 1–3 | The old record, the new one, or a torn mix | A torn mix fails the SHA-256 check (`corrupt` → suppress) |
| After step 3 | The new record | — |
| A new file whose directory entry is lost (Windows power cut) | No file | `first_start` or `no_witness` → suppress |

**`write_atomic` (commit: the snapshot and the clean marker):**
1. Create `<name>.tmp`, write it while hashing, and `sync_all` it.
2. Rename it over `<name>`.
3. On Unix, fsync the directory and propagate any error.

On Windows a power cut can lose the rename. That only ever leaves the older file, which at commit time is the dirty marker, so the next start suppresses. Start removes stale `*.tmp` files, under the lock (§2.2), and never reads them.

## 2. State machine
The protocol runs inside `actor::run`, before the event loop and after it. With the switch on:

| # | Step | Crash after this step and before the next → next start |
| --- | --- | --- |
| S0 | **Lock:** take `dht-restart.lock` (§2.2), without blocking the event loop. Read the clocks: `wall0`, then `mono0` (I4). This moment is the run's `start` for suppression and the gate | Nothing written. Same outcome as the previous run's files give |
| S1 | **Load:** read the marker, snapshot, witness and `dht-state.bin`; delete `*.tmp` | Nothing written. Same as S0 |
| S2 | **Validate** (§2.1); choose Resume or Suppress(reason); `gen = max(marker.gen, witness.gen) + 1` | Nothing written. Same as S0 (nothing sent yet) |
| S3 | **Witness ← G+1** (`overwrite_in_place`); then clean up orphans (§1.4) | Witness G+1, marker clean G → `generation` → **suppress** |
| S4 | **Marker ← dirty G+1** (`overwrite_in_place`) | Dirty → **suppress** |
| S5 | **Sampling may start.** The event loop and routing have run since process start (N3). **The first sample is gated:** it needs S3 or S4 durable, and also `start + H` on Suppress, or the restored gate on Resume | Dirty → **suppress** |
| S6 | Run. The restriction table is in memory, keyed by the monotonic clock | Dirty → **suppress**, whatever the crash (kill -9, panic, power loss) |
| S7 | **Shutdown requested: quiesce.** Set `sampling_closed`. `sample_tick` and `try_query(Purpose::Sample)` refuse from now on | Dirty → **suppress** |
| S8 | **Record in flight:** every in-flight sample becomes `Cooling { until: now + H }` with a fresh token, and goes into the expiry index. Its old transaction token is retired, so a late reply or timeout fails `complete()` and can't shorten it (P6). No waiting (runner decision 3) | Dirty → **suppress** |
| S9 | The event loop exits; no packet is sent after this. Save `dht-state.bin` with the existing `State::save`, plus a Unix directory fsync with errors propagated. Keep its SHA-256 and the ids it saved | Dirty → **suppress** |
| S10 | **Snapshot ← table** (`write_atomic`). Read `mono`, then `wall` (I4); `at = ceil_ms(wall)`; `remaining = ceil_s(until − mono)`, live entries only; **`gate = ceil_s(max(0, gate_until − mono))`** (N1, below) | Dirty → **suppress** |
| S11 | **Marker ← clean G+1** with `snap`, `state_bin` and the S9 `ids` (`write_atomic`). Its `at` is `ceil_ms` of a wall reading taken now, after S10's (N4). This is the commit point. Then release the lock | Clean G+1 → **resume**, with the snapshot and gate it names |

**`gate_until` (N1).** It's held on the monotonic clock:
- a **suppressed** run: `mono0 + H`, its own suppression end;
- a **resumed** run: `max(inherited gate deadline, own suppression end)`. A resumed run has no suppression of its own, so this is just the inherited gate. The `max` rule also covers a run that resumes late after a lock wait (N3);
- in either case, a deadline already past gives `gate = 0`.

So a short suppressed run that stops cleanly passes its unexpired suppression on, and the next resume keeps blocking every sample until the original `start + H`.

**Why the early steps are safe.** A crash between S0 and S4 leaves either the previous clean marker or an invalidated one. The previous clean marker is still a complete record, because no sample can be sent before S5.

**When S3 or S4 fails** (an I/O error; I1):
- **Either one landing is enough.** If S3 lands, the witness is ahead of the old clean marker, which no longer validates. If S4 lands, the marker is dirty.
- **`invalidate_failed`** applies only when a clean marker existed and both S3 and S4 failed. Then **no samples** are sent. Routing, passive service and lookups carry on.
- **Retry:** the actor retries S4 then S3 every maintenance tick, backing off exponentially from one tick to at most 60 s. Once one lands, sampling is allowed, but still only after `start + H` (suppress mode).
- **Shown to the user:** while sampling is disabled, the status/health surface shows the reason (§5.3). `dht_sample_suppression_seconds` never reads 0: it shows what's left of the window, and at least 1.
- **If no clean marker existed,** there's nothing to invalidate. The run suppresses as usual.

**When S9–S11 fails:** the failure is logged with its step, and counted (`dht_restart_persist_errors_total{step}`). The marker stays dirty, so the next start suppresses.

**Commit time (P4):**
- The commit is S9–S11: about 4.4 MiB at 200,000 entries, three fsyncs and two renames.
- Its target is 2 s on an SSD. The time is recorded in a `dht.restart_commit` event (`ok`, `duration_ms`, `entries`), and the next start's `dht.restart_check` reports `previous: clean | dirty`.
- A data directory on a spun-down array disk can take longer than Docker's 10 s stop. If the stop kills the commit, the marker stays dirty and the next start suppresses, which is safe.

### 2.1 Validation (S2): the first failure wins and suppresses
1. `first_start`: no marker at all. This covers first installs, the first run after the switch is turned on, and upgrades from v0.5.x. The owner's choice stands: the first start stays suppressed.
2. `corrupt` or `version`: any of the three files fails §1.2 or §1.3, or the snapshot is missing.
3. `dirty` or `off_run`: the marker isn't clean. The last run crashed, was killed, failed in S9–S11, or ran with the switch off.
4. `data_dir`: `dir_id` or `dir_path` differs between the files, or from this data directory, or the witness for this `dir_id` names another `path` (N7, §1.4).
5. `node_identity`: `ids` differs from the ids this run will use (`initial_ids` after loading `dht-state.bin`). For example, `dht-state.bin` is gone.
6. `foreign_run`: `dht-state.bin`'s SHA-256 differs from the marker's `state_bin`. Another writer ran on this data directory after the clean stop, such as an older Lodestar build that ignores these files. CR-0-era builds suppress for 6 h and save `dht-state.bin` every 10 min, so any such run that could have sent a sample has rewritten that file (see I5 in §8).
7. `snapshot_mismatch`: `marker.snap` ≠ SHA-256 of the snapshot, or the `gen`, `dir_id`, `ids` or `run_id` values disagree.
8. `no_witness` or `generation`: the witness is missing, unreadable, foreign, or isn't exactly `marker.gen`. A torn or corrupt witness counts as `no_witness`, not `corrupt`: rule 2 covers only the marker and the snapshot.
9. `horizon_changed`: `snapshot.horizon ≠` this run's `H_s`, because `query_timeout` changed (I3, N6). Clamping to a smaller `H` would shorten restrictions, so it isn't done.
10. `clock_backward`: the clock order `snapshot.at ≤ marker.at ≤ now_wall` doesn't hold (I3).
11. `stale`: `now_wall − marker.at > H`. Every restriction would have expired, so the snapshot proves nothing useful. A long gap is also where restore and clock errors hide, and suppressing then costs nothing compared with today.

**Only if all eleven pass: Resume (I3, I4).**
- `now = floor_ms(wall0)`;
- for each entry, `deadline = snapshot.at + remaining·1000`, using `checked_add`. An overflow is `corrupt`;
- `left = deadline − now`. Entries with `left ≤ 0` are dropped. Because of rule 10, `left ≤ remaining ≤ H`; it's still clamped to `H` as a guard that never shortens a valid entry;
- `until = mono0 + left` (`Instant::checked_add`; an overflow is `corrupt`), using the same `mono0` read after `wall0`;
- the address goes through `normalize` once more before it's seeded (P3);
- **the gate (N1)** converts the same way: `gate_left = snapshot.at + gate·1000 − now`, rounded and checked like an entry, and bounded to `0 ≤ gate ≤ H_s`. If `gate_left > 0`, no sample goes to anyone until `mono0 + gate_left`, which becomes the inherited gate deadline.

Reading the clocks in this order, with these roundings, makes every conversion end later, never earlier: S10 reads `mono` before `wall` and rounds `at` up, and S2 reads `wall` before `mono` and rounds `now` down.

### 2.2 The lock (B1)
- **What it prevents:** two starts on one data directory both resuming from the same proof. That can be two processes, or, in-process, a dropped `DhtSource::run` future whose detached actor is still in S7–S11 while a new actor is in S0–S4. Without the lock they could also delete each other's `.tmp` files mid-write.
- **What it is:**
  - an exclusive, advisory OS lock on `dht-restart.lock`: `flock` on Unix and `LockFileEx` on Windows, through std's `File::try_lock`;
  - it's taken at S0 and held until S11 completes, or until the actor exits if the commit failed;
  - a run with the switch off takes it too, and holds it for its whole life (N2, below);
  - the OS releases it when the process dies, so kill -9 can't leave it stuck.
- **When it's busy (N3):**
  - the event loop and routing start at once; nothing waits on the lock;
  - `try_lock` is retried every maintenance tick, with I1's backoff from one tick up to 60 s, for as long as the run lasts;
  - while the lock is busy, the run touches **no** protocol files and sends **no samples** (`locked`);
  - **when the lock is acquired,** that moment is S0, and S1–S4 run normally. Resuming is allowed, because the run has sent no sample yet. The S1–S4 file work runs off the actor's thread (`spawn_blocking`) and posts its result back, so a slow disk can't stall routing;
  - an in-process predecessor finishing its commit typically frees the lock within P4's budget, so the next tick picks it up.
- **When the filesystem doesn't support locks** (an `Unsupported` error, as on some network shares): `locked` for the whole run, and nothing is retried. On-runs there never write a marker, so such data directories never resume, which is safe.
- **Runs with the switch off hold it too (N2).** An off-run takes the lock at start and holds it for its whole life, not just around its invalidation (§5.2). The rule is the same whether or not a marker exists. That also closes the race where an off-run starts before any marker exists and an on-run creates one alongside it.
  - **Busy:** `locked`, no samples, retried as above.
  - **`Unsupported`:** today's behaviour exactly. If a marker was carried over from a filesystem that had locks, it's overwritten as `off` without the lock, as a best effort.
  - **Lodestar already allows only one process per data folder:** the update supervisor refuses a second one (`update/supervisor.rs`). So the only observable change in off mode is that a second, concurrent process on the same folder doesn't sample.
- **Dependency:** std's `File::lock` family is stable from Rust 1.89, and the workspace's `rust-version` is 1.85. The runner raised it to 1.89 (runner decision 5), so `fs4` isn't needed as a direct dependency.

## 3. Obligation semantics
### 3.1 Key
A restriction belongs to the **remote endpoint**: the normalised `SocketAddr`, the same key as the CR-0 sampler. It doesn't belong to the sample target or the node id. The target is random per query and BEP 51's `interval` is about re-querying the node. Node ids aren't authenticated and could be rotated to dodge a restriction.

### 3.2 Values
- **Cooling:** `until`, unchanged. The remote's interval is clamped to 60 s–6 h; `UNSUPPORTED_BACKOFF` and `SAMPLE_TIMEOUT_BACKOFF` are 6 h.
- **In flight at S8:** `now + H` (= `now + query_timeout + MAX_INTERVAL`).
  - This bounds every outcome. A reply could arrive up to `query_timeout` after it was sent, and would set at most `MAX_INTERVAL`. A timeout sets `SAMPLE_TIMEOUT_BACKOFF` = `MAX_INTERVAL` from the timeout.
  - The entry is a real `Cooling` entry in the expiry index under a fresh token, so neither a late `complete()` nor `abort()` can touch it (P6).
- **Restored entries** keep their deadline. A new reply can't arrive for them, because the sampler refuses to sample those endpoints until they expire. They're written again at the next shutdown if they're still live.

### 3.3 Clock
- **The seam (I7):** the actor and the sampler take time only from a `Clock` trait with `wall_ms()` and `mono()`. That means `actor.rs`'s direct `Instant::now()` calls, ~790, ~1149 and in `maintain`, and `now_secs`. Production uses std. Tests use a manual clock, so no test sleeps.
- **In the run:** monotonic time, as today, so wall-clock steps during a run can't shorten a restriction. Linux `CLOCK_MONOTONIC` stops during suspend, which only lengthens real-time cooldowns.
- **Across a restart:** wall-clock deadlines (`at + remaining`), converted at S10 and back at S2, with the read order and rounding in §2.1.
- **A backward step between runs** suppresses (`clock_backward`).
- **A forward step larger than what's left of the horizon** suppresses as `stale`.
- **A smaller forward step** is a residual (§8).

### 3.4 Size and pruning
- **Table:** the sampler's existing table, which already holds both cooling and in-flight entries, bounded by `MAX_KNOWN = 200,000`. Restored entries count against the same cap. The table is complete by construction: a sample is sent only after `reserve` creates an entry, and `reserve` refuses when the table is saturated.
- **File:** at most 200,000 × 22 bytes ≈ 4.4 MiB, with an 8 MiB cap. A file over the cap, or with more entries than `MAX_KNOWN`, is `corrupt`.
- **Pruning:** S10 writes only live entries, and S2 drops expired ones. The sampler's existing `prune` (1,024 per tick) retires restored entries like any others.
- **Load cost:** one sequential parse, O(n log n) to insert into the expiry index, done before the event loop.

## 4. Pause and resume (CR-0f)
- **A pause isn't a shutdown for this protocol.**
  - The process keeps the authoritative table in memory. The marker stays dirty, the lock stays held, and nothing is written.
  - `SetPaused(true)` already stops `sample_tick`, and in-flight samples still settle through `maintain`.
  - Restrictions keep expiring during a pause.
  - Unpausing doesn't restart the 6 h window or clear restrictions. CR-0f's pause changes only touch the peer-request queue (dropped replies, no lost attempt) and bootstrap seeds. They don't touch the sampler.
- **A start in the paused state** (`Config.paused`) still runs S0–S4 before its first sample.
- **A shutdown while paused** goes through S7–S11. S7 is already true, and S8 records whatever is still in flight.
- **An in-process restart of the DHT source** (`DhtSource::run` ending and starting again) is an ordinary stop and start, serialised by the lock. The old actor commits at S11, and the new one validates at S2 against the same witness.
- **Ordering with CR-0f:** `pipeline/control.rs` pauses the pool before the DHT. That doesn't affect this protocol, because sampling is the DHT actor's alone.

## 5. The switch
### 5.1 Name and plumbing
- **App config:** `[dht] safe_restart = false`, with the environment variable `LODESTAR_DHT_SAFE_RESTART`. It takes effect at start. It isn't in the Settings UI in this slice: it's a release-delta item, and stays out of v0.5.1 unless the delta review says otherwise.
- **Library:** `lodestar_dht::Config.restart: Option<RestartConfig { witness_dir }>`. `None` means off.
- **With `sample_start_delay: Some(..)`:** the protocol is off, but §5.2's invalidation still runs whenever `state_path` is set (I5). A fixture that samples early must never leave a clean proof behind.
- **With `state_path: None`:** off, and there's nothing to invalidate.

### 5.2 Off behaviour (default)
- **Today's behaviour, plus one safety step.** Suppression is `H` from every start, and the protocol never writes the snapshot or the witness.
- **The off-run's window starts when it takes the lock (C1, round-3 review).** Today the window counts from the actor epoch (`sample_tick`: `now − self.epoch`). An off-run that waited behind a resumed on-run for longer than `H` would then sample at once, inside restrictions the on-run still holds. So an off-run's suppression ends at `lock acquired + H`. On `Unsupported` it ends at the actor epoch `+ H`, exactly as today.
- **The safety step:** the off-run takes the lock at start and holds it until it exits (§2.2, N2). If `dht-restart.mark` exists, it overwrites the marker in place with `state: "off"`, keeping its `gen` and `dir_id`. It does this before its first sample.
  - Without this, a run with the switch on, then one with it off, then one with it on again, would let the third run trust a marker that knows nothing of the second run's samples. `foreign_run` (§2.1 rule 6) is a second line of defence.
  - **On failure** (the lock is busy, or an I/O error): no samples, retried every tick with I1's backoff (§2, §2.2). A busy lock reports `locked`; an I/O error reports `invalidate_failed`.
- **Unchanged:** the existing `sample_restart_suppression…` test keeps passing.

### 5.3 Metrics, events and status
New metrics go in `docs/metrics.md` (a shared-file edit, to be named in the Phase 2 PR):

| Name | Type | Meaning |
| --- | --- | --- |
| `dht_sample_suppression_reason{reason}` | gauge, 1 for this run's reason | One of `off`, `locked`, `first_start`, `corrupt`, `version`, `dirty`, `off_run`, `data_dir`, `node_identity`, `foreign_run`, `snapshot_mismatch`, `no_witness`, `generation`, `horizon_changed`, `clock_backward`, `stale`, `invalidate_failed`, or `resumed` |

| `dht_restart_obligations_honoured_total` | counter | Restored entries that expired with no sample sent to them before their deadline |
| `dht_restart_persist_errors_total{step}` | counter | I/O failures at `lock`, `witness`, `invalidate`, `state_bin`, `snapshot` and `marker` |

- **The two obligation counters are monitoring, not evidence (P5).** The proof that restrictions are honoured is the wire-level replay test (§6, item 6).
- **Kept:** `dht_sample_suppression_seconds` stays. It reads 0 from the start of a resumed run, and never reads 0 while sampling is disabled (I1).
- **Status page:** when sampling is disabled (`locked` or `invalidate_failed`), or when there's no witness, the status/health surface names the reason in plain words. If that needs a field in `crates/api`, it's a shared-file edit named in the PR (runner).

  - `dht.restart_commit` (Info): `ok`, `duration_ms` and `entries`;
  - `dht.restart_persist_failed` (Warn): `step` and the error kind.

## 6. Test plan
**No fixed sleeps anywhere (I7).** The actor and sampler run on the `Clock` seam, with a manual clock in tests. Any wait for a condition, such as a subprocess exiting, has a deadline of at least 10 s.

1. **A crash at every step:**
   - **Seam:** a `#[cfg(test)]` fail point in both write paths and in the S-sequence. The named points are: after the write; after `set_len`; after `sync_all`; after the rename; after the directory fsync; and between S3/S4, S9/S10 and S10/S11.
   - **Two outcomes at each point.** "Stop here" leaves the files exactly as they are. "Lost unsynced write" models a power cut: it restores the pre-write bytes, or the pre-rename file, and leaves a torn tmp.
   - **Check:** a fresh load gives exactly the outcome in the §1.6 and §2 tables.
   - **One true kill -9 test:** a subprocess re-runs the test binary with `LODESTAR_TEST_ABORT_AT=<point>` and calls `abort()`; the parent then validates.
2. **Loop:** load → resume → send a sample (to a fixture node) → crash → load. This must suppress (`dirty`) and never resume. Then a clean stop → load → resume. 100 iterations, with a randomised step.
3. **Clock skew, through the seam:**
   - backward 1 ms and 1 day → `clock_backward`;
   - `snapshot.at > marker.at` → `clock_backward`;
   - forward within the horizon → resume, with deadlines shifted as specified;
   - forward beyond `H` → `stale`;
   - a wall-clock step during a run doesn't change the written deadlines;
   - the §8 forward-clock residual is pinned by a test that documents it;
   - **rounding boundaries (I4):** an entry exactly at `left = 0`, at 1 ms, and at `H` is never seeded earlier than its true deadline.
4. **Corrupt, truncated and foreign files:**
   - bit flips at every byte offset of a small snapshot, marker and witness (each gives `corrupt`);
   - truncation at every length;
   - a wrong magic, version 2, oversize;
   - entries that are duplicated, unsorted, a partial length, port 0, IPv4-mapped in `r6` (P3), `remaining = 0` or `> horizon`;
   - files from another `dir_id`, another path or other node ids;
   - `horizon` ≠ current `H` → `horizon_changed`;
   - `at` near `u64::MAX` and `remaining` at `u32::MAX`: no panic, `corrupt` (I3);
   - property tests: arbitrary bytes never resume and never panic; and the seeding arithmetic with arbitrary `at`, `remaining`, `wall0` and `mono0` never seeds a deadline earlier than the true one and never panics (I3);
   - a `cargo fuzz` target for the decoder plus the seeding, because this parses untrusted input.
5. **A backup restored:**
   - copy the data directory at clean G, run G+1 cleanly, restore the copy → `generation`;
   - restore with the witness removed → `no_witness`;
   - a witness dir inside the data dir, directly or **through a symlink** → `no_witness`;
   - an unwritable witness dir (a read-only directory) → `no_witness`, with the status reason;
   - an "old binary" that only rewrites `dht-state.bin`, between two on-runs → `foreign_run`;
   - an off-run between two on-runs → `off_run`;
   - a fixture with `sample_start_delay: Some(ZERO)` between two on-runs → `off_run` (I5);
   - orphan cleanup removes only this data directory's old `*.gen` files (P1).
6. **Honouring restrictions (the evidence):**
   - **In-crate wire-level replay:** restore 1,000 restrictions with mixed deadlines, drive `maintain` on the manual clock, and capture every datagram sent. Assert that no `sample_infohashes` reaches a restored endpoint before its deadline.
   - **A CR-SIM scenario** does the same end-to-end once the CR-SIM harness is on `main`. If it isn't there when Phase 2 opens, the in-crate replay is the gate, and the CR-SIM scenario is listed as a follow-up for the runner.
7. **The lock (B1):**
   - two processes on one data dir: exactly one resumes, and the other reports `locked` and changes no file;
   - overlapping in-process actors (an old one held in S10 by a fail point while a new one starts) never both resume, and never touch each other's `.tmp`;
   - a busy lock doesn't hold up the event loop or routing, and is retried every tick. Once it's acquired, S1–S4 run and the run may resume (N3);
   - **concurrent off and on processes (N2):**
     - an off-run holds the lock for its whole life, so an on-run alongside it reports `locked` and writes nothing;
     - an on-run holding the lock makes an off-run alongside it report `locked`, with no samples;
     - this holds with a marker present and without one.
8. **Liveness (I1):**
   - S3 fails and S4 lands → suppress, not `invalidate_failed`;
   - both fail → no samples, and `dht_sample_suppression_seconds` stays above 0;
   - the failure then clears → the retry lands, and sampling starts at `start + H`;
   - the status reason is set while the failure lasts.
9. **Durability (I6):**
   - invalidation never unlinks;
   - an error from the Unix directory fsync propagates from both write paths, through an injected error;
   - on Windows CI, the crash table holds with the rename-loss outcome modelled.
10. **Ids (P2):** a BEP 42 rotation mid-run → the clean marker carries the rotated ids → the next start resumes; with the old ids → `node_identity`.
11. **In flight (P6):** after S8, a late reply and a timeout for the old token both fail `complete()`, and the `now + H` entry survives.
12. **Commit budget (P4):**
    - S9–S11 with 200,000 entries, on Linux and Windows CI;
    - the measured time is logged and reported in the PR;
    - the test asserts a loose 8 s ceiling only, so a slow runner doesn't make it flaky.
13. **Switch off:**
    - byte-for-byte today's suppression;
    - a leftover marker is overwritten as `off` before the first sample;
    - a marker that can't be overwritten means no samples until a retry lands.
14. **Pause:**
    - a pause writes nothing;
    - a shutdown while paused commits;
    - a paused start invalidates before its first sample.
15. **The gate (N1):**
    - for each of `dirty` (crash after a resume), `first_start`, `off_run`, `generation` and a torn witness: run a short suppressed run, stop it cleanly, and restart within `H`. The restart resumes, and no sample is sent to anyone before the original suppressed run's `start + H`;
    - a resumed run carries the inherited gate forward across a second clean restart;
    - `gate` outside `0..=horizon` is `corrupt`;
    - the gate's conversion is covered by the I4 rounding-boundary tests and by the I3 property test.
16. **Clock ticks (N4):** `snapshot.at` and `marker.at` read within one simulated 15.6 ms tick never give `clock_backward`.
17. **Off-run window (C1):** an off-run locked out for longer than `H` sends no sample until `H` after it takes the lock.

## 8. Residuals (accepted)
1. **Forward clock step between runs** (runner decision 2):
   - **When:** the wall clock is wrong but steady for a whole run, then corrected forward by `e` before the next start, where `e` is less than what's left of the horizon.
   - **Effect:** the restored restrictions are shortened by `e`.
   - **Why it's accepted:** a clock wrong only at the start of a run and corrected during it does no harm, because S10 converts with the shutdown-time clock. No local check can see a steady offset, and there's no NTP check. A test documents it.
2. **Snapshot-style restores (I2, runner):**
   - **When:** a VM, ZFS, btrfs or Proxmox snapshot, or a restore of a backup that includes the witness folder.
   - **Effect:** the witness and the data roll back together, and validation passes. Only restores older than `H` are still caught, by `stale`.
   - **What users are told:** the user docs say never to back up or restore the witness together with the data.
   - **Option C restated (runner):** an optional state volume is acceptable only at a path outside the backed-up appdata. It stays a follow-up.
3. **Builds that sample without suppression (I5, runner):**
   - **Why it's a residual:** the invariant assumes every other writer of the data directory suppresses and takes the lock. Two cases aren't caught by `foreign_run`:
     - a build that samples without suppression and crashes within 10 min (before its first `dht-state.bin` save);
     - an older build, which doesn't take the lock, running concurrently with an on-run (N2).
   - **Why it's accepted:** no released build does this. v0.5.0 was never tagged, and the owner's pre-CR-0 container is never restarted. Fixtures that sample early still run §5.2's invalidation (§5.1).
4. **Lock-less filesystems:** these always give `locked`, and never resume. That's safe, but such installs gain nothing from the switch.

## Refinements made in CR-0d-1 (the format and validation module)
These came out of writing the module and its fresh self-review. None loosens a rule; each either fixes the order a reason is reported in or refuses something the design didn't anticipate.
- **Reason order (§2.1).**
  - Rule 2's "the snapshot is missing" applies only behind a clean marker: a dirty or `off` marker reports `dirty` or `off_run` first. A crash during the very first on-run, which leaves a dirty marker and no snapshot, therefore reads `dirty`, which is what happened.
  - A snapshot whose `dir_id` differs from the marker's is rule 7 (`snapshot_mismatch`), not rule 4; rule 4 compares the files with this data directory.
  - Both changes affect only the metric label: every path still suppresses. A test pins the order with two faults at once.
- **Scoped IPv6 keys refuse the commit.** The sampler keys on the whole `SocketAddr`, including an IPv6 scope id and flow label. Writing an entry without them would restore it under a key the sampler never looks up. So a live entry with either set makes `capture` fail, and the marker stays dirty. Only `allow_private` fixtures (link-local peers) can reach this. CR-0d-2 may instead strip both from the sampler's keys; the refusal stays as the guard.
- **Orphan cleanup is narrower (§1.4).**
  - It deletes another directory's witness only when the witness is at least an hour old and that path has no marker, or has a readable marker with another `dir_id`.
  - A torn or unreadable marker, or a recent witness, is left alone. An hour-old witness can't belong to a run between its S3 and S4.
  - It reads paths named in witness files, which can hang on a dead mount, so CR-0d-2 runs it after S4, off the S1–S4 path.
- **Clock reads are taken by the module.** `Here::read` (S0: wall, then monotonic) and `capture_now` (S10: monotonic, then wall) take their readings in the required order (I4), and `stamp_after_capture` gives S11's marker time. `Here::read` also derives `dir_path` from `path`, so they can't disagree.
- **Other details:**
  - `snap` is the snapshot's container checksum (§1.3);
  - a witness *file* that is a symlink is unusable, as is a witness dir resolving inside the data dir;
  - a lock error other than `Unsupported` (for example `ENOLCK`) means the same as busy: no files touched, no samples, retried, counted as `persist_errors{step="lock"}`;
  - the sampler's `MAX_KNOWN` is now defined from the module's `MAX_ENTRIES`, so the two can't drift. Seeding in CR-0d-2 must insert every restored entry or suppress; it may never drop one to make room;
  - in code the field is `generation`, because `gen` is reserved in Rust 2024. The on-disk key stays `gen`.

## Refinements made in CR-0d-2a (the actor integration)
None of these loosens a rule. Each makes the runtime match the design where the design left a choice open, or keeps today's behaviour where the switch is off.
- **A filesystem without locks** (`Unsupported`): an on-run there reports `locked`, never writes a marker and never resumes. It samples as today, from the actor's epoch plus `H`, instead of not sampling at all. That's safe by §0.1(1): a run that doesn't resume sends nothing before its start plus `H`. Not sampling for the whole run would be a regression from today for such installs.
- **The driver lives in `node/proof.rs`,** beside the actor:
  - The lock is retried every maintenance tick, with backoff from one tick up to 60 s (N3).
  - The start work and every invalidation retry run on tokio's blocking pool and report back over a channel. A slow disk never stalls routing.
  - Tests run that work inline (`RestartConfig::inline_io`), because a pool thread's progress isn't ordered with tokio's paused clock.
- **An on-run doesn't rewrite `dht-state.bin`** (the periodic save) until S1 has hashed it. Otherwise the next start would see `foreign_run` when there was no other writer.
- **A run commits only if it held the lock and its invalidation landed.** Otherwise it saves `dht-state.bin` as before, and the next start suppresses.
- **The sampler** gets `restore` (never refused for capacity, keeping the later of two records), `seal_in_flight` and `restrictions`.
  - Restored and sealed records use a token space above the wire's transaction ids, so a late reply can never complete them (P6).
  - The restored records feed the refused and honoured counters.
- **The clock:** the actor already runs on `tokio::time::Instant` (CR-SIM), so the restart module seeds on that clock. The `Clock` trait supplies the wall clock, which tokio doesn't have.
- **The default witness dir, native only:** `$XDG_STATE_HOME/lodestar`, else `~/.local/state/lodestar`, and `%LOCALAPPDATA%\Lodestar\witness` on Windows. A configured `dht.restart_witness_dir` wins. The packaged defaults (Docker's `/var/lib/lodestar-witness`, the MSI's `C:\ProgramData\Lodestar-witness`) come in CR-0d-2b.
  - **Docker:** until then, a container with the default PUID resolves to `/home/nonroot/.local/state/lodestar`, in the container layer. A remapped PUID can't write there and reports `no_witness`.
  - **The MSI service:** it resolves to the service profile's `LOCALAPPDATA`, which is outside the data folder. Moving to 2b's folder costs one suppression.
- **Background jobs hold the lock too.**
  - The start job, every invalidation retry and the orphan cleanup each hold a share of the lock, so it outlives this run's file work.
  - A later run (an in-process restart) can't take the lock, or lose its temp files or witness, while one of them is still running.
  - At shutdown the commit waits up to 5 s for a start job or retry still in flight, and lands its result. That way a resume or invalidation that finished just then isn't lost. Any restrictions it restores are seeded before the table is captured.
- **A start job or retry that dies** (a panic on the pool) counts as a failed attempt and is retried with the same backoff. The run never sits stuck with no retry.
- **A witness bump that failed while the marker landed** is tried once more just before S10. Otherwise the next start would read `generation`, which is safe but costs a resume.
- **Errors carry their kind.** `dht.restart_persist_failed` has `step` and `kind` (for example `permission_denied`, `read_only`, `storage_full`), and lock errors log it too. A filesystem without locks logs `dht.restart_check` with mode `lockless`.
- **A restart within the clean stop's millisecond** reads `clock_backward` and suppresses (`marker.at` rounds up, `now` rounds down). That's safe, and no real restart is that fast.
- **What must land before the first sample (runner review of #216, B1).** An invalidation counts only if it reaches the earlier proof:
  - no marker, or one that can't resume (dirty, off): nothing needs to land;
  - a readable clean marker, with this run keeping its `dir_id`: the marker write or the witness bump;
  - a marker that exists but can't be read (an I/O error, a permission change): **only the marker write**. It may be a clean one, and this run's witness bump goes to a new `dir_id`'s file. The off-run treats it the same way and retries until it lands;
  - a clean marker whose directory was copied (N7, a new `dir_id`): only the marker write, for the same reason.
- **Smaller fixes from that review:**
  - wire transaction ids are refused at the sampler's proof-token bit, `2^63`. That's unreachable, but now explicit;
  - a dead start job's retry doubles its backoff, up to 60 s;
  - `try_lock` creates the data directory first, so a fresh install's first on-run starts.
- **A late invalidation is suppress mode, as §2 (I1) says.** The run keeps reporting `invalidate_failed`, samples nothing before its own start plus `H`, and its commit passes that window on as the gate.
- **Left as they are, and noted:**
  - Opening the lock file and the non-blocking lock call run on the actor's thread; neither waits on file contents.
  - The commit's writes run in the actor task at shutdown, as today's `dht-state.bin` save does.
  - A cleanup job hung on a dead network mount can delay process exit, because the runtime waits for blocking tasks.
  - The witness dir is created `0700` on Unix.
  - The commit's `dht-state.bin.tmp` is removed at S1.
- **Follow-ups:**
  - The systemd default `/var/lib/lodestar-witness` (§1.5) goes with 2b's packaging. Until then, a systemd install uses `$XDG_STATE_HOME` or `~/.local/state` of its service account, or `no_witness`.
  - A CR-SIM scenario (`crates/sources/tests/sim`) for restored restrictions is a follow-up for the runner. In this PR, the in-crate wire-level replay is the gate (§6, item 6).
- **The status reason (I1):** 2a shows it through the `dht_sample_suppression_reason` gauge, the suppression seconds (never 0 while sampling is blocked) and the Warn event `dht.restart_persist_failed`. The `GET /stats` field `sampling_blocked` and the status pill's wording go in CR-0d-2b (runner decision): services.rs, ops.rs, the crates/api DTO, the regenerated openapi.json and schema.d.ts, and zh strings or the documented fallback. **I1 is fully met only once 2b lands.**

## Refinements made in CR-0d-2b-1 (packaging witness defaults)
- **`LODESTAR_DHT_WITNESS_DIR`** sets the witness dir from the environment, ahead of the file and the native default. Packaging uses it. It and `LODESTAR_DHT_SAFE_RESTART` are in `config::ENV_VARS`.
- **Docker:**
  - The image creates `/var/lib/lodestar-witness`, mode `0700`, owned by 65532, in the container layer, and sets the variable.
  - `privdrop.rs` hands that directory to `PUID:PGID` with a new, narrow `chown_witness_dir`: the directory and the regular, singly-linked `.gen` files directly in it, opened `O_NOFOLLOW` and changed through their descriptors. Nothing else changes: no other names, no links, no subdirectories, never the filesystem root.
  - The data dir's `looks_like_data` guard can't apply, because the witness dir holds no `lodestar.db`. The narrow scope replaces it.
  - A directory holding any name that isn't `*.gen` is left alone entirely. That stops a mistyped variable (`/etc`, a share) from being handed over. The proof only ever writes `<dir_id>.gen` there, in place.
  - A problem is logged as the Warn event `system.witness_dir_left`, with a kind (`link`, `not_dir`, `root`, `foreign`, `open`, `chown`), and never stops the start: the run then has `no_witness`, which is safe. A hand-over logs `system.witness_dir` (Info).
  - The folder is in the container layer, so an image update starts without a witness and suppresses once (said in the Docker README).
- **systemd:** `StateDirectory=lodestar lodestar-witness`, with the variable set. `DynamicUser`'s `/var/lib/private` keeps the two as siblings.
- **The Windows service:** `%ProgramData%\Lodestar-witness`, made private with the data folder's own `acl::secure_dir` at service start. This happens only when `safe_restart` is on and neither the file nor the variable chose a dir.
  - **Runner refinement:** it's done at runtime, not in `main.wxs`. It's the same ACL machinery, there's no installer change, and nothing is created while the switch is off. The runner's conditions, all met:
    1. It's never inside the data folder. A data folder set to `%ProgramData%`, or to the witness path itself, means the run has no witness (kind `inside_data`, `service::within`).
    2. If `secure_dir` refuses the folder, the run has no witness (`no_witness`) and logs the Warn event `service.witness_refused`, whose kind is `create`, `inspect` or `not_private`. The cases include a reparse point, a link, not a folder, or an ACL that isn't private. Nothing ever falls back to a weaker ACL, nor to the native default in the service account's profile. `service::apply_witness_default` does it, tested with scripted `acl::Ops`.
    3. The 2b-2 user docs say the folder stays after an uninstall, like the data folder. That is harmless, and the folder is safe to delete. 2b-2 also adds `LODESTAR_DHT_SAFE_RESTART` and `LODESTAR_DHT_WITNESS_DIR` to `docs/operations.md`.
- **Path comparison on Windows:** `same_dir`'s normalisation now drops the `\\?\` verbatim prefix that `canonicalize` adds. That lets a folder that exists compare with one that doesn't yet.

## Deviations from the review, for its re-check
- **I6 (Windows durability):** the review asked for invalidation through `write_atomic` with `MoveFileExW(WRITE_THROUGH)`. The workspace forbids `unsafe`, and there's no safe wrapper in the lock.
  - So invalidation instead overwrites the existing file in place, then `sync_all`s it (§1.6). That is durable on every platform without depending on a directory entry, and it never unlinks.
  - Commit keeps the rename, because losing a rename there only ever leaves the dirty marker.
- **B1 (busy lock):** superseded by N3. The lock is retried every tick for the whole run, and the event loop never waits on it.
- **N2 (off-run lock):** the review asked that an off-run hold the lock for its whole life when it finds a marker. This design holds it in every off-run that can take it, marker or not. That closes the case where an on-run creates the first marker while an off-run is already running. In off mode the cost is only that a second, concurrent process on the same folder doesn't sample, and the update supervisor already refuses such a process.
- **N7 (copies):** a new `dir_id` is generated whenever the witness names another path, whether this directory is a copy or a move. Both suppress once anyway. The full path in the witness is what lets orphan cleanup remove the witness a move leaves behind.
- **B1 (dependency):** std's `File::try_lock` needs `rust-version` raised to 1.89 (§2.2). The runner approved it (runner decision 5).
