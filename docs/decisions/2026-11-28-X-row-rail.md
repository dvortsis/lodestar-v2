## Facet order and presets (U10, D3, I6)
- **Default order:** Type, Resolution, Size, Seeders, Language, Year, Discovered. **More filters** holds Source and Verified, Extension, Trackers reporting, and the flags and the rest, as before.
- **Seeders and Trackers presets are plain clauses with or without counts** (I6). Seeders: ≥ 1, ≥ 5, ≥ 50. **Trackers reporting: ≥ 1, ≥ 3** (this slice's choice; the plan gave presets only for Seeders). A server count shows beside a preset when the server lists it; otherwise none, never 0.
- **"Include never-scraped" stays out:** there is still no query clause for it (the `SwarmGroup` note). It's a follow-up.

## Typed dates (U15)
- **Rule:** From and To are whole UTC days, the same as the brush (`bins.ts` `wholeDays`): From is that day's first second, To its last. So **From = To is that single day**, and an **empty end is open**. Both empty removes the clause. A text that isn't a real day, or From after To, is not applied and says what to change (`role="alert"`). The fields show the clause's own days when it changes elsewhere (a brush, a preset).
- They show under **Custom**, and whenever the Discovered clause is a fixed span.

## The two-tier row (U11)
- **Facts removed from the row** (review U11: "Four unlabelled numbers and three terms of art per row"), each in the drawer: leechers (`detail-leechers`, Summary), trackers reporting N / M (Summary's "Trackers reporting"), the backfill marker (Summary's Backfill badge) and v2 / hybrid (TechnicalDetails flags and hash).
- **Availability is one fact in words:** "512 seeders", "1 seeder", "Never scraped" (the existing `never_scraped` text). It uses the same `_one` / `_other` message pattern as the file count and `formatCount`, so en and zh both read right. Compact keeps the arrow and the bare number (one 36 px line).
- **Badges, up to five** (runner, owner item 28): type (or the adult kind), resolution, Private, Imported, then v2 and Hybrid (technical, so the first into "+N"), then verification (Unverified, or Imported) and safety (suspect seeders). **Safety and verification never give way:** over five, one slot becomes a "+N" chip, every safety and verification badge stays, the rest fill the free slots in order. An adult torrent's kind also stays (content safety, §20). An imported torrent that is also unverified reads once, as the verification badge. Compact shows only the safety and verification badges.
- **The +N chip is a button that opens the drawer** (its click reaches the list's activation), which holds the rest.

## Click a badge to filter (02 §4c, §10.13)
- Type, adult kind, resolution, Private, Imported and v2 are real `<button>`s with a label ("Filter by Movie"), on Search rows only (the ones with row actions). Discover and Alerts rows show plain tags. Unverified, Imported (as verification), suspect and Hybrid aren't filterable (no rail facet for them, or filtering by them is the wrong default).
- **No nested buttons:** the row is a `div` in a `role="row"` grid, not a link or button, and its open target is the list's own activation (`VirtualList.onActivate`). Badge buttons are siblings of nothing interactive, and the click stops there, so it filters and doesn't open the row. RowActions does the same. No structural change was needed.
- **Tab order (§10.13):** the list is one tab stop with roving focus, so the badges are `tabindex="-1"` like RowActions. The keyboard route to the same filter is the rail and the query bar; in-row keys are X-rowactions-arrowdown's.
- **How it filters:** the row sends a window event (`ls-row-filter`, `{ facet, value }`) and `FacetsHost` applies the same edit as that value's click in the rail (`toggleValue`, then `search.setAst`), at once in every rail mode. Importing the search state into the row would have loaded it in Discover and Alerts, whose chunks share the row.
- **Touch target:** a badge button is the tag's height inside a fixed 64 px row, under the 44 px target. Same limit as RowActions' buttons; the rail's presets are the touch-sized route.
