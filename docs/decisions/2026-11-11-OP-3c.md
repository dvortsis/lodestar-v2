# OP-3c decisions (the cloud fleet runbook)

The runbook is `docs/operations/cloud-fleet-runbook.md`. It describes the code on `main` at 9e80e138 (OP-3b merged), not what the plan hoped for. Where the two differ, the runbook follows the code, and the differences are below for the runner.

## Where the runbook follows the code, not the plan
- **The operator's workflows are `operator-wake.yml`, `operator-apply.yml` and `operator-tripwire.yml`,** as the brief names them. The plan's kill switch (step 2) names `operator-injection.yml` instead of `operator-tripwire.yml`. OP-4 (#655) isn't merged, so every operator-side step is marked "after OP-4 merges". Until then, nobody can issue a `/fleet` command: `fleet.yml` accepts them only from the App's bot account.
- **The evidence goes only to the private bucket.** The plan says the scrubbed aggregates also go to the runner as a result comment. OP-3b's brief put them in the bucket only, and the code does that (`fleet/<run id>/copy-off-<vm>.json`). The runbook says the runner gets results through a reviewed PR.
- **The watchdog leaves firewalls.** Deleting a Linode at 48 h doesn't delete its firewall, as the test plan's 0a already says. Stop everything step 5 says to delete the firewalls by hand.
- **With the deny-all policies attached (Stop everything step 4), `fleet.yml` can't run `down` or the reaper either.** The plan's order puts teardown (step 5) after it; the runbook states the residual, so step 5 is by hand.

## The gluetun-stop drill
- **No committed step stops gluetun,** and none should: a step that cuts the tunnel on purpose would be a new kind of remote action. So the drill is manual, over the owner's own SSH, with host keys pinned from `fleet.json`.
- **Its commands are the committed ones:**
  - the container names from `compose.yaml` and `block-lib.sh` (`gluetun`, `lodestar`, `lodestar-collector-<segment>`);
  - the pinned probe image and its `--network container:… --cap-drop ALL` form from the leak test;
  - the block directory's `marker`, `outages` and `notes` from OP-3b.
- **It ends the segment** with `docker stop -t 120` on the collector, which then stops Lodestar itself (reason `operator_stop`). `copy-off` ends the block and copies the evidence. The test plan's 0d calls stopping gluetun "a different case… test it once, outside any block". The brief asks for it mid-block, on a test VM, so it also proves the outage watcher and copy-off. The runbook says never to run it on a block whose result matters.

## Choices
- **A developer and operations document, in the `user-docs` voice:**
  - plain, matter-of-fact, terms defined, the safe choice recommended;
  - not part of `docs/user/`, so github-docs' lint gate doesn't apply (OP-3's brief);
  - no screenshots, since none are real yet;
  - two Mermaid diagrams, each with a sentence before it and a text equivalent after.
- **Console paths are named as the plan names them.** Where the plan gives no exact control name (the App's Suspend, Cloud Manager's API Tokens), the runbook gives the place, not a guessed label.
- **No link line:** `docs/operations.md` doesn't index `docs/operations/` pages, so no shared edit was needed.
