# OP-3c decisions (the cloud fleet runbook)

The runbook is `docs/operations/cloud-fleet-runbook.md`. It describes the code on `main` (OP-3b and OP-4 merged), not what the plan hoped for. Where the two differ, the runbook follows the code, and the differences are below for the runner.

## Where the runbook follows the code, not the plan
- **The operator's workflows (OP-4, #655):**
  - Stop everything disables `operator-wake.yml` and `operator-apply.yml`, which hold the Anthropic key through `cloud-operator`.
  - It leaves `operator-tripwire.yml` on: it holds no secrets, and disables operator-wake itself on a trip (the runner's review of #668).
  - `operator-injection.yml` is OP-5's harness, which the plan's kill switch also disables. It's marked "after OP-5 merges".
  - The plan's step 2 lists `operator-injection.yml` but not the tripwire, which it predates.
- **The evidence goes only to the private bucket.** The plan says the scrubbed aggregates also go to the runner as a result comment. OP-3b's brief put them in the bucket only, and the code does that (`fleet/<run id>/copy-off-<vm>.json`). The runner has no AWS access. **The interim hand-off is the runner's call (2026-11-11Z):**
  - the owner fetches the file with `aws s3` and keeps it;
  - the runner asks, through the dashboard session, only for the summary lines it needs, and the owner pastes those there;
  - never the raw file, logs or credentials, and never in a PR, issue or comment.
- **The watchdog leaves firewalls.** Deleting a Linode at 48 h doesn't delete its firewall, as the test plan's 0a already says. Stop everything step 5 says to delete the firewalls by hand.
- **With the deny-all policies attached (Stop everything step 4), `fleet.yml` can't run `down` or the reaper either.** The plan's order puts teardown (step 5) after it. The runbook states the residual: step 5 is by hand, and clearing the record afterwards needs the policies detached first.
- **Switching `FLEET_LIVE` off is not a stop.** The reaper and the owner's dispatched `down` read it too, so a dry-run `down` would leave a live fleet running. The runbook warns against it; the plan doesn't mention it.
- **Every Stop everything step has its undo** (standards §5.8): the revoked tokens, the API key and the SSH key can only be replaced, so the runbook says that before step 4.
- **Only `Deploy.ps1` and `Destroy.ps1` share the fleet's Terraform state** (`terraform/lodestar.tfstate`, through `StateBackend.ps1`). The AWS Windows scripts keep their own state.

## The gluetun-stop drill
- **No committed step stops gluetun,** and none should: a step that cuts the tunnel on purpose would be a new kind of remote action. So the drill is manual, over the owner's own SSH, with host keys pinned from `fleet.json`.
- **Its commands are the committed ones:**
  - the container names from `compose.yaml` and `block-lib.sh` (`gluetun`, `lodestar`, `lodestar-collector-<segment>`);
  - the pinned probe image and its `--network container:… --cap-drop ALL` form from the leak test;
  - the block directory's `marker`, `outages` and `notes` from OP-3b.
- **It ends the segment** with `docker stop -t 120` on the collector, which then stops Lodestar itself (reason `operator_stop`). `copy-off` ends the block and copies the evidence. The test plan's 0d calls stopping gluetun "a different case… test it once, outside any block". The brief asks for it mid-block, on a test VM, so it also proves the outage watcher and copy-off. The runbook says never to run it on a block whose result matters.

## Choices
- **A developer and operations document, in the `user-docs` voice:**
  - plain, matter-of-fact, terms defined, the safe choice recommended;
  - not part of `docs/user/`, so github-docs' lint gate doesn't apply (OP-3's brief);
  - no screenshots, since none are real yet;
  - two Mermaid diagrams, each with a sentence before it and a text equivalent after.
- **Console paths are named as the plan and the code name them:** the variable, environment, secret, role, policy and Linode label names (labels end `-fleet`, from `apply.py`'s `deployment_id`). For the GitHub App's suspend and Linode's token revocation, the runbook names the action and the object, not a menu path the plan doesn't give.
- **No link line:** `docs/operations.md` doesn't index `docs/operations/` pages, so no shared edit was needed.
