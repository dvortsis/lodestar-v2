# X-cmp09-fix-2 decisions

The second of two PRs for CMP-09 (managed companion readiness): the credential clients outside the companions crate. The first, X-cmp09-fix (#887), covers the companions crate. This file says what the code now does (`docs/security/v1/README.md` §5).

## The loopback gate
- **One check in the network guard** (`crates/integrations/src/net/loopback_gate.rs`, used by `net.rs`): a process-wide `LoopbackGate`, set once with `set_loopback_gate`.
  - A second set is refused (`GateAlreadySet`) and leaves the first in place; nothing swaps it.
  - With no gate set, nothing changes.
- **What it checks:** whether a connection to a loopback address on a port may be made now. A port the gate refuses fails with the typed `NetError::NotReady`, before any byte is sent.
- **Where it runs:**
  - **Every request through a `GuardedClient`** (`send`, so `exchange`, `exchange_stream` and every hop of `send_following` too). If the port is refused and the destination is loopback, the request is refused. The destination counts as loopback if it's a literal loopback address (`127.0.0.0/8`, `::1`, mapped forms), a `localhost` name, or a name that resolves to loopback now.
  - **Every new connection a request makes** (the guard's resolver hook): a name that resolves to loopback is refused while a port that a request is sending that name to is refused.
  - **`resolve_tcp`,** and so raw TCP through `connect_tcp`, `connect_tcp_with` and `connect_tcp_routed`: refused the same way when the port is refused and an address is loopback.
- **What it leaves alone:**
  - ports the gate allows, which is every port Lodestar runs no companion on, and a hand-run companion's port;
  - the same port number on any non-loopback address;
  - a name a SOCKS5 proxy resolves, which never reaches this machine's loopback.
- **Clients:** every client built on `GuardedClient` gets the gate, which covers the Prowlarr source (sources egress) and the download clients, the managed qBittorrent entry among them.
- **Not chosen: a gate passed to each client's constructor.** That's about six files across four crates, and a new path could miss it. One check in the guard covers every caller, present and future.

## Lodestar's gate
- **`companions::start` sets it** (`crates/lodestar/src/companions.rs`, `ReadyPorts`).
  - A port that a companion Lodestar runs holds (`Bindings::managed`) is allowed only while `Bindings::ready`; every other port, always.
  - Serve starts the companions before the sources' egress and the pipeline, so the gate is set before any source or download client sends a request.
  - A later start in the same process (tests) keeps the first gate.
- **The companions' own loopback client opts out** (`GuardedClient::without_loopback_gate`, on `CompanionHttp`'s client for loopback and container targets).
  - It applies the managed-port rule itself, where a bare probe before a companion is ready is allowed, and so is its health check.
  - `CompanionHttp`'s client for entered URLs keeps the gate.
  - The opt-out is `#[doc(hidden)]`. A test (`only_the_companions_client_opts_out_of_the_gate`) fails if any other source file in the workspace calls it.
- **Not ready reads as unreachable** wherever errors are mapped: download clients (`ClientError::Unreachable`), notifications (a transient failure) and the companions' adapters (`AdapterError::Unreachable`). The update check and companion downloads already map unknown errors to a network failure.

## Tests
- **`crates/integrations/tests/loopback_gate.rs`,** its own test binary, since the gate is set once per process:
  - with no gate, a loopback request goes through;
  - set once, a second gate is refused;
  - on a refused port, nothing is sent: literal `127.0.0.1`, `::1` and another `127/8` address, `localhost`, a name that resolves to loopback, a name whose answer turns to loopback by the connection, and a redirect hop all fail with `NotReady`;
  - raw TCP via `resolve_tcp` is refused the same way;
  - another loopback port, and the same port on a LAN address, are untouched, and the opted-out client still reaches the port;
  - allowed again, everything goes through.
- **The opt-out's single caller** is checked by scanning the workspace's sources.
- **`crates/lodestar/src/companions.rs`:**
  - the start sets the gate (fails without the wiring);
  - the gate refuses a held companion port that isn't ready, and allows any other.
- Each new test fails with its part removed: the request check, the connection check, the raw TCP check and the wiring.
