# GS-5 decisions (Search: collapse toggle and +N others)

Spec: architecture §8 (collapse-by-group) and §10.4 (results toolbar, rows, table, cards); owner-decisions §2.66 item 2 ("Group versions" on by default once group data is ready, remembered per account and in the URL; ungrouped with a one-line reason while not ready); UI review 02 §5.1 (+N other versions in place, at most 5 rows, then Show all; the arrow keys; a Versions column). Builds on GS-3 (`docs/decisions/2026-11-16-GS-3.md`). Built by the runner's stand-in, so the shared-file lines below are the runner's own edits (`runner/standards.md` "Ownership").

- **Remembered per account: a new `preferences.group_versions` field (bool, default `true`, group `search`).** "Remembered per account" needs a server value; browser storage alone would be per device. The field sits beside `density` in the existing preferences section, with no new endpoint and no migration (an absent key reads as the default). **Refinement (§2.19):** the owner said per account; the field is how.
- **The URL wins, then the account.** `group=1` or `group=0` in the URL decides; without it the account's choice does. Turning the switch writes `group=1|0` explicitly, so a shared link groups the same way whatever the reader's default. The change is pushed like a sort, so Back undoes it.
- **First paint uses a browser cache of the account's choice** (`lodestar.groupVersions`), and the server's answer, read once per visit, corrects it. Each search is pinned to the choice it started with (`grouping.pin`, keyed by the query, sort, hidden, exact and browse), so a late answer applies from the next search, never under rows already painted, and the toolbar's switch shows what the rows were asked with. Saves go one at a time as single-field PATCHes (no `if_revision`, as the shortcuts toggle does), and a quick change of mind sends only the last choice; a failure leaves the URL and the cache holding the choice, silently.
- **While group data isn't ready** the server answers ungrouped with `collapse_unavailable`. The switch stays usable, and one line under the toolbar's controls says why (both switches, the wide one and the one in the narrow More popover, point at it with `aria-describedby`); the count then names torrents only. When grouping is off, nothing is said.
- **The count line** reads "128 groups · 412 torrents" when the rows are grouped, with ≈ and compact figures for an estimate (the groups and the torrents carry their own `approx`).
- **+N other versions opens in place, in the List view, as rows of the list** at its one fixed height (§10.1), so j/k and the arrows walk them. → opens the focused row's group, ← closes it; ← on a version closes its group and returns focus to the best row. The disclosure is a button inside the row (tabindex −1, `aria-expanded`), so a click toggles without opening the row. A grouped List is a `treegrid`: best rows are level 1 with `aria-expanded` when they have versions, group rows level 2; a group's load is said politely ("2 other versions shown", or that it failed). `x` selects torrent rows only, and with the drawer open j/k step over a group's Show all, loading, failed or empty line.
- **The in-place rows come from `GET /torrents/{hash}/siblings` (`other_versions`)**, the same title identity the server groups by, best first. That list is the work's versions, not only the ones matching the query, so it can differ from `others` (which counts query matches). **Show all** counts `others + 1` and appears when there are more than 5 rows, more than 5 versions, or a truncated list. Filtering the siblings by the query would need a new endpoint; recorded here as a known difference.
- **Show all opens the best version's drawer** until GS-4 builds Related; GS-4 should point it at Related's "other versions" directly. A failed load shows "Retry" on its row; Enter or a click retries.
- **A new query closes every open group** (`results.shown` changes); a new page of the same query keeps them.
- **Table and Cards** show one row per group (an open group stays the List's) with a numeric **Versions** column (`others + 1`, a dash for an ungrouped row), shown by default and arriving hidden for a column choice saved before it, as Raw name and Resolution did. A grouped card shows "+N other versions" first among its facts.
- **Sizes.** "+N other versions" comes with the results panel, so it paints with the first grouped rows. Everything opening needs (the rows, their logic and styles) loads on a group's first opening, as its own on-demand entry ('Search collapse rows (on demand)'), so a list nobody expands never fetches it; a press while it loads waits for the same load, and a failed load lets the next press try again. The switch is the Toggle primitive's markup without its two-way binding: the URL owns the value, and the binding would bring Svelte's bind runtime (about 1.2 KB) into the toolbar. The remaining growth raises the results, toolbar and cards limits to their measured sizes (runner §2.26), with the reason beside each in `.size-limit.mjs`.
- **Shared-file lines (runner):**
  - `crates/lodestar/src/settings/preferences.rs`: the `group_versions` field, its default and its `Field` entry; the settings goldens follow.
  - `web/src/lib/features/search/results/results.svelte.ts`: `collapse` in the query and its key, `collapse: 'group'` in the POST body (absent from the generated body type, as GS-3 left it), and the answer's grouping kept as `grouped`.
  - `web/src/lib/features/search/results/ResultsPanel.svelte`: the query's `collapse`, the lazy rows module, open groups' rows interleaved into the list, Enter/click and →/← for group rows, the treegrid attributes and the group announcements.
  - `web/src/lib/features/search/toolbar/ResultsToolbar.svelte`: the switch and the groups count.
  - `web/src/lib/features/search/table/{columns.ts,ResultsTable.svelte,ColumnChooser.svelte}` and `cards/Card.svelte`: the Versions column and the card's fact.
- **The default stays on.** If G-v07-scale fails the keyword p95 with collapse on, the default falls back to off and goes back to the owner (§2.66); that gate is not decided here.
