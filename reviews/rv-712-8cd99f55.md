## Important
1. **The partition scenario doesn't test token fencing** (scenarios.rs:86-129, M1).
   - The partitioned worker's results arrive at heal (:113-114), only after every key is stored and its lease has ended (:107). So they count as stale because no lease exists, not because a newer token holds the key. Intake that ignores the token passes.
   - Fix: `swarm.hold(1)` and `hold(2)` before the advance, then `wait_leased(3)` and wait until the new holders are fetching. Release worker 0 and heal while the new leases are live, assert stale ≥ 3 while `stored == 0`, then release 1 and 2.
2. **`fetch_violations` trusts the authority it should be checking** (testing.rs:1374-1377; the unit test at scenarios.rs:329-330 pins it).
   - Two different leases count as a hand-over at any time gap. So a coordinator bug that hands a live key to a second worker under a new token (an overwrite, or a re-grant leaving the key in `pending`) never shows as a violation.
   - Where harvested isn't recounted, the funnel still reconciles, so WK-G's exactly-once gate would inherit the blind spot. The brief asks for "outside a lease expiry".
   - Fix: in the different-lease case, also require a generation change or `b.at_ms - a.at_ms >= ttl`. Leave a hook for the drain/revoke hand-back marks the decisions file already plans.
3. **The kill scenario can't tell an early expiry from a correct one** (scenarios.rs:42-47, M2).
   - Base time never moves before the single `advance(ttl+1s)`, so any threshold up to the TTL passes.
   - Cheap to fix here, or put it in WK-G's notes: advance by ttl minus a margin, wait for `fleet().ticks` to rise by 2, assert `pending == 0` and the dead worker still holds 3 leases, then advance the rest.
