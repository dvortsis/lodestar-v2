## Important (non-blocking; fix in this PR if cheap, otherwise carry into CMP-11b)

1. **The UNC loopback refusal misses the octal, hex and IPv6-literal spellings of loopback.** `crates/companions/src/windows_qbittorrent.rs:682-694` (`loopback`) parses each octet with `str::parse::<u8>`, which reads `0177` as decimal 177. Anything with an `x` counts as a DNS name. I ran these against this head and all of them came back `Ok`:
   - `\\0177.0.0.1\share\x`: Windows' `inet_addr`/`getaddrinfo` read `0177` as octal, so this is 127.0.0.1;
   - `\\0x7f.0.0.1\share\x` and `\\0x7f000001\share\x`, the hex forms;
   - `\\0--1.ipv6-literal.net\share\x`, Windows' built-in IPv6-literal name for `::1`.

   The decisions file (I1) says it refuses "any all-numeric name Windows may read as an address", so it overstates what the code does. The impact is small: `$` shares (`C$`, `ADMIN$`) are already refused by the charset, and the doc admits that this machine reached by its own name passes. Still, the stated fix has a gap.

   **Fix (a few lines):** in `loopback`, return true when:
   - a numeric label has a leading `0` and is longer than one digit;
   - any label matches `0[xX][0-9a-fA-F]*`;
   - or the name ends in `.ipv6-literal.net`.

   Add those three cases to `windows_paths_refuse_hostile_inputs`.

2. **No check ties the save path's kind to the platform.** `SavePath::Host` can reach the Windows gate, and `SavePath::Windows` can reach CMP-8b's adapter on Linux or Docker (`crates/companions/src/configure/mod.rs:341-365`, `configure/qbittorrent.rs:323-328`). Nothing builds `Downloads` in production yet (I grepped: only tests), so nothing is reachable today. Once CMP-11b and the screen wire it up, though, a Linux `/downloads` written to a Windows qBittorrent becomes `<current drive>:\downloads`, which no path check covers.

   **Cheapest fix:**
   - `WindowsQBittorrent::plan`/`apply_plan` refuse `input.downloads` whose `save_path()` is `SavePath::Host` (for example `InputError::NotAbsolute` mapped to a refusal);
   - the ungated adapter refuses `SavePath::Windows`.

   Or record it as a CMP-11b must-do in the decisions file.

3. **The manager's refusal code for qBittorrent on a Windows host changes** from `no_platform` to `awaiting_pin`, and to `guided_only` once pinned. `Entry::installable` returns `AwaitingPin` before `manager.rs:715`'s installer check runs. The installer is still never fetched, so this is safe. But a screen keyed on `awaiting_pin` may read it as "Lodestar will install this once pinned", which isn't the cq4 flow. The decisions file doesn't mention it. Add a line there so CMP-9b and CMP-11b map both codes to the guided install on Windows. `manager.rs` is out of this slice's owns, so the fix isn't here.

## Owner flags (for the runner to raise)
1. **Until CMP-11b, there's no version check on Windows** (fallback (b)). qBittorrent on Windows is configured by CMP-8b's plain adapter. The installer is still never fetched, and paths, credentials and the hand-over are unchanged.
2. **Once CMP-11b registers the gate, configuration on Windows is refused** (`awaiting_pin`) until CMP-13 extends the catalogue format and pins the official installer. The current format can't express that pin, because the release folder is userdocs' GitHub folder. A working Windows flow needs both CMP-11b and CMP-13. This is fail-closed by design, but it affects ordering.
3. **(Refinement) The pin's version range** is the pinned version plus later patch releases of the same `major.minor`:
   - an older version is refused;
   - a newer minor version is refused until a Lodestar update;
   - qBittorrent on Windows offers its own update prompts, so users who accept a minor update are locked out of configuration until Lodestar's pin moves.
4. **(Refinement) A Windows save path takes no per-category paths.** Categories save under the save path.
5. **The Windows path check is as-typed:**
   - junctions the user made, this machine reached by its own name or a LAN address, and shares named differently from their root folder pass;
   - octal, hex and IPv6-literal loopback servers also pass (Important 1, unless fixed).
6. **The manager's Windows refusal code changes** from `no_platform` to `awaiting_pin`, and later `guided_only` (Important 3). The UI should treat both as "guided install".
