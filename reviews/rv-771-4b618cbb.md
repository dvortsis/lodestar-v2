## Blocking

### B1. The test can't tell masking from truncation: the IPv6 mask and the encoded-message drop are untested
- **Where:** `infra/akamai/terraform/tests/Test-DeployAwsWindows.ps1:138` (the fixture `$script:sgError`) and `:188-193` (the "masked and bounded" check).
- **Scenario:** once masked, the fixture's first line reaches exactly 200 characters at `... in account_[account] from [ip]`. The cut then removes everything after it: ` and 2001:db8::7`, the mid-line `` `e[31m `` and `Encoded authorization failure message: SECRETBLOB`. So these checks pass even when `Get-SafeAwsError` doesn't mask them:
  - `-not $line.Contains('2001:db8')`;
  - `-not $r.Out.Contains('SECRETBLOB')`;
  - the printable-ASCII check, for in-line control characters.

  `$line.Contains('[ip]')` is met by the IPv4 mask alone.
- **Shown by (emulated):** I deleted the IPv6 mask, and separately the `Encoded authorization failure message` drop. Every condition in the check still held both times.
- **Why it blocks:** `runner/standards.md` treats a missing test for new behaviour as blocking. The fixture's comment, the decisions file and the PR description all say these are covered.
- **The fix:** use two fixtures, or call the function directly.
  - **One short line** (well under 200 characters once masked) carrying the IPv6 address, a mid-line ANSI sequence, a mid-line CR, a non-ASCII letter (see B2) and the encoded message. Assert that `[ip]` appears twice, and that `2001:db8`, `SECRETBLOB` and `Encoded` don't appear.
  - **The existing long line,** kept for the cut.
  - **Simpler still:** move `Get-SafeAwsError` into `AwsCli.ps1`. `Assert-StubResolves` already dot-sources that file, so the test can then check a table of inputs and expected outputs directly, without starting a new pwsh for each case.

### B2. The "printable ASCII only" strip is case-insensitive, so some non-ASCII letters survive
- **Where:** `infra/akamai/terraform/scripts/Deploy-AwsWindows.ps1:84`: `$_ -replace '[^\x20-\x7E]', ''`.
- **Scenario:** PowerShell's `-replace` matches without case (`RegexOptions.IgnoreCase`). Under that option, .NET treats `[\x20-\x7E]` as also containing the characters that case-fold into it, so the negated class doesn't match them:
  - **Windows PowerShell 5.1 (.NET Framework)** lowercases each input character before testing it against the set.
  - **.NET 7 and later (pwsh 7.4)** add case equivalents to the set.

  Either way, U+212A KELVIN SIGN (lowercase mapping `k`) is kept, and so, in non-Turkish cultures, is U+0130 `İ` (lowercase mapping `i`).
  - In the Python emulation, `K İ ſ ı` all survive the case-insensitive strip and are removed by a case-sensitive one.
  - I couldn't run pwsh to confirm the exact .NET set.
- **Why it blocks:** the brief (item 4), the function's comment, the decisions file and the runbook line all say "printable ASCII". The test can't catch it, because its fixture has no such character. The risk is low: these are printable letters, not control or bidi characters, and every mask still applies, since the masks also match without case.
- **The fix:**
  - Use `-creplace '[^\x20-\x7E]', ''` at line 84.
  - Add `K` (U+212A) and `é` to B1's short fixture, and keep the test's `-cmatch '^[\x20-\x7E]+$'`.
  - The author can confirm the bug in one line with pwsh 7.4: `"$([char]0x212A)" -replace '[^\x20-\x7E]',''` returns `K`.
  - Using `-creplace` for the mask patterns is optional: there, matching without case only masks more.

## Optional
1. **`Deploy-AwsWindows.ps1:90`: an account ID split by punctuation isn't masked.**
   - `9999-8888-7777`, `9999 8888 7777` and `9999.8888.7777` pass through unchanged. A 13-digit run that contains an ID does too (emulated).
   - AWS CLI errors print IDs as 12 plain digits, or inside an ARN, which is masked whole. So this matches the stated rule ("12-digit account IDs"). A comment saying so would stop the next reader from wondering.
2. **`Deploy-AwsWindows.ps1:93`: a run of hex digits and colons longer than 39 characters isn't masked at all.**
   - For example, a full eight-group address followed by an unbracketed `:443` (emulated: left as it is).
   - The lookbehind stops the match from starting inside the run, and `{2,39}` together with the final lookahead stop it from matching the whole run.
   - AWS doesn't emit addresses like this for `DescribeSecurityGroups`. If you want it closed, mask any hex-and-colon run that contains `::` or at least seven colons, whatever its length.
3. **`Test-DeployAwsWindows.ps1:85-90`: the test clears five named variables,** but other credential sources stay in the environment:
   - `AWS_CONTAINER_CREDENTIALS_FULL_URI` and `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI`;
   - `AWS_WEB_IDENTITY_TOKEN_FILE` with `AWS_ROLE_ARN`.

   This is harmless in practice. Every call the deploy script makes passes `--profile lodestar-provisioner` or `--profile lodestar-admin`, and with `AWS_CONFIG_FILE` and `AWS_SHARED_CREDENTIALS_FILE` at `/nonexistent`, a real CLI stops with ProfileNotFound before it sends any request. Also, `Assert-StubResolves` checks only the first sandbox; later sandboxes are built the same way. For a belt-and-braces fix, null every variable whose name starts with `AWS_` (apart from the three set on purpose) instead of listing five.
4. **`Deploy-AwsWindows.ps1:94`: the 200-character cut often keeps only AWS's boilerplate.** With a realistic `UnauthorizedOperation` line, the cut lands at `...is not authorized to perform: ec2:DescribeSec` (emulated). The thrown message names the permission, so the human still learns what's missing. Dropping the `You are not authorized to perform this operation.` sentence would leave room for the useful part.
5. **`pia-wireguard.sh:85`: one comment line is about 115 characters long** after the edit. Reflow it to match the 80-column lines around it.
6. **For the runner, outside this PR:** the repo-wide check for 12-digit numbers found two more AWS placeholder account IDs in files this PR doesn't touch:
   - `123456789012` (AWS's documentation example) in `infra/akamai/watchdog/deployed/test_watchdog.py:35` and `:174`, and in `infra/aws/expiration-guard/deployed/test_guard.py:15`;
   - `000000000000` in `infra/aws/fleet-control/test_templates.py:223`.

   Every other 12-digit number is a byte size or a soak metric. None is a real account ID.
