### O1. Nothing in the Unraid template says why `VPN_INTERFACE` must stay `wg0`
- **Where:** `crates/companions/src/unraid.rs`, in the env loop, where every fixed variable gets the help text "Set by Lodestar." Golden: `tests/golden/unraid/*/my-gluetun.xml`, the `VPN_INTERFACE` Config.

  - The compose file warns about this ("Keep VPN_INTERFACE as it is: the rules name it."). The Unraid form doesn't.

### O2. The compose check reads as optional
- **Where:** `docs/user/03-keep-lodestar-safe.md:90`.
- **Evidence:**
  - The table says "To check the rules, run step 4's commands with `docker compose exec`…".
  - gluetun skips a missing post-rules file without a word. So a compose tool that accepts the file but ignores `configs.content` would start gluetun with no rules and no error. Some non-Docker compose implementations may do this.
  - The guide's claim that "older versions refuse the file" holds for Docker Compose's schema (`additionalProperties: false`). The decisions file doesn't say it was tested on an old version.
- **Fix:** make it a step: "Then check that gluetun loaded the rules: run step 4's commands with `docker compose exec` in place of `docker exec`."

### O3. The gluetun Overview covers a missing file, not a wrong one
- **Where:** `crates/companions/src/unraid.rs:271` (`POST_RULES_NOTE`).
- **Evidence:**
  - "Without the file, gluetun won't start" is true for a missing file.
  - An empty or wrong file starts gluetun normally, with no rules. For example, `wget -O` leaves a 0-byte file on an HTTP error.
  - The guide's SHA-256 check and the step 4 check catch this, but the Overview doesn't point to them.
- **Fix:** "…save Lodestar's post-rules file at the Post-rules path and check it, as the Lodestar user guide shows…"

## Checked and correct
- **The rules (1–3) in both families:**
  - **No ACCEPT.** `CONNMARK` is non-terminating; the other rules are DROPs.
  - **Where they sit:** OUTPUT positions 1–3, above gluetun's own `ESTABLISHED,RELATED` accept, so they apply before it.
  - **Inbound connections are covered.** Replies to connections that arrive through the tunnel (forwarded DHT port) leave by `wg0`, so they get marked too.
  - **Companions are covered.** They share gluetun's network namespace, so their traffic is OUTPUT there.
  - **IPv6 is mirrored.** The exemptions are link-local, multicast and hop limit 255, all bounded by rule 2 and gluetun's DROP policy.
  - **Unchanged:** the content is byte-identical to main's file (SHA-256 `26a485e3…`, as pinned in the guide).
- **The copies match:**
  - `crates/companions/src/gluetun-post-rules.txt` is byte-identical to `packaging/companions/gluetun-post-rules.txt`, LF only (`cmp`, `file`). `.gitattributes` pins both to `eol=lf`.
  - The compose inline block reads back as exactly the embedded text (test `every_gluetun_template_carries_the_rules_for_its_interface`).
- **The mount:**
  - **Unraid:** a `Type="Path"`, `Mode="ro"` bind at `/iptables/post-rules.txt`, which is gluetun's post-rules path.
  - **Compose:** a `configs:` entry targeting the same path, copied in as mode 0444. That's a root-owned file rather than a read-only mount, the same as the fleet VMs. Not a concern: root in gluetun already controls the firewall.
- **Fail-safe:**
  - **Unraid, missing host file:** Docker creates a directory at that path, and gluetun's read fails with "is a directory" before the VPN starts, so it fails closed. A missing or rootfs-only `/mnt/cache` also fails closed.
  - **Unraid, Path removed:** the gap is back. Only the guide's explicit undo step does this.
  - **Compose:** the rules are always inline. Docker Compose older than 2.23.1 rejects `content`, so it fails closed.
  - **A host without ip6tables** fails closed with `ip6tables is required`.
- **The existing-gluetun route** gets no `configs:` and no Post-rules Path. When `main` is gluetun, an ExistingGluetun route is refused (`GluetunSelf`).
- **Start order:**
  - **Compose:** `depends_on: gluetun: condition: service_healthy` (O3 of the decisions file).
  - **Unraid:** the routed companion's Overview names the gluetun container (a closed ContainerName, so the note stays fixed text plus a name) and asks for a wait of at least 30 s. The guide's steps (Advanced View, the lock icon, **wait**) match how Unraid works.
- **The YAML block writer:** it refuses `$` (compose interpolation), tabs, `\r`, control characters, an indented first line, and a missing or doubled final newline. Its unit test covers each case. `scalar()` returns `None` for `Block`, so a block can't come out inline.
- **The Overview overclaim is gone,** and a test keeps it out.

  - Changing the target path in `packaging/companions/compose/gluetun.yml` fails `packaging_snippets_match`.
  - No sleeps, no `#[ignore]`, nothing skipped.
- **The goldens and the packaging examples agree.** With digests masked, they differ only by the documented inputs (PUID, folders, loopback publishing).
