## Blocking

### B1. A negated Unicode class gets past the codepoint budget, so one accepted pattern costs about 0.4 s of case folding
- **Where:** `crates/search/src/regex.rs:346-367` (`Bounds::named_class`), called from `:433` (`Ast::ClassUnicode`) and `:474` (`ClassSetItem::Unicode`).
- **Cause:** `named_class` measures a class by translating its own text case-sensitively and counting the codepoints of the result, which is the class after negation. regex-syntax 0.8.11 folds case before it negates (`translate.rs` `unicode_fold_and_negate`, "we must apply case folding before negation"). For `\P{Any}`, the measured class is empty, so 0 codepoints are counted. The translator still walks all 1,114,112 codepoints of `\p{Any}` in `case_fold_simple`, because a class built from the table has `folded = false`. The budget the PR adds to bound exactly this walk counts nothing.
- **Failing input (measured, release build, this worktree):**
  - `r"\P{Any}".repeat(73)` (511 bytes): **accepted, 411 ms** in `parse`.
  - `r"\P{any}".repeat(73)`: accepted, 429 ms.
  - `r"[\P{Any}]".repeat(56)`: accepted, 293 ms.
  - `format!("abc|{}", r"\P{Any}".repeat(72))`: accepted, 356 ms, plan `"abc"`. So the pattern can also carry a real prefilter.
  - For comparison, one `\P{Any}` costs about 8.7 ms, and `\p{Any}` × 3 is correctly refused in about 25 µs.
- **Impact:**
  - The decisions file (`docs/decisions/2026-11-11-RX-0.md:30`) says "the worst accepted pattern now parses in about 8 ms". In fact it is about 50 times that.
  - RX-1 compiles `verify_pattern()` with `regex`, which runs the same fold again. The same file measured that as "as long again". A single query would then spend about 0.8 s of CPU before any index work, against §3's regex p95 < 500 ms.
  - This is the denial-of-service the slice's bound exists to prevent. The 1 s guard in the fuzz target does not catch it (about 0.4 s in release), and the property test's generator never produces `\P{...}`.
- **Suggested fix:**
  - In `named_class`, charge the class that is actually folded. When the AST item is negated (`ast::ClassUnicode::is_negated()`, which covers `\P{..}`, `\p{^..}` and `\p{x!=y}`), count the complement of the measured width (`1_112_064 - width`). Alternatively, always charge `max(width, 1_112_064 - width)`.
  - Perl classes are never folded (they are closed under folding), so they can keep the current count.
  - Add refusals to `refusals_have_stable_codes`:
    - `refused(&r"\P{Any}".repeat(3)) == ClassTooLarge`
    - `refused(r"[\P{Any}][\P{Any}][\P{Any}]") == ClassTooLarge`
  - Add `\P{..}` leaves and an `\P{Any}`-repeated seed (`fuzz/seeds/regex_plan/`), so the fuzzer starts at the edge.
  - Correct the "about 8 ms" line once the worst case has been measured again.

## Important

- **Where:** `fuzz/fuzz_targets/regex_plan.rs:16-22`.

## Nits

- **N1. Error detail format differs between paths** (`regex.rs:354`).
  - `named_class` maps errors with `e.to_string()`, which is regex-syntax's full multi-line message with the pattern slice and carets. Example: `\p{NotAProperty}` gives `"regex parse error:\n    \\p{NotAProperty}\n    ^^^^^^^^^^^^^^^^\nerror: Unicode property not found"`.
  - The main paths (`:282`, `:299`) use `kind().to_string()`, which is one line with no input in it.
  - The detail is bounded (512 bytes or less), but it echoes user text across lines into a user-facing message. Use `e.kind().to_string()` here too (`regex_syntax::Error` exposes `kind()` through its variants, or match `Error::Translate(e) => e.kind()`).
- **N2. `fuzz/Cargo.lock` is stale.**
  - The tracked fuzz lockfile's `lodestar-search` entry doesn't list `regex-syntax`.
  - CI doesn't pass `--locked`, so it rebuilds the lockfile silently and the fuzz job still passes (green on this head). The next session that builds fuzz will see a dirty file, though.
  - It's a shared file, so ask the runner whether to add the one-line lock update here or leave it for the next fuzz PR.
- **N3. The RX-1 notes don't cover Q10's marker term** (`docs/decisions/2026-11-11-RX-0.md:46+`).
  - Q10(a) (plan line 312) caps trigrams to a prefix of the name and adds a marker term on long names. The plan stays a superset only if RX-1 ORs that marker at the top of every plan.
  - One line in "For RX-1" would keep the plan sound under that option.

## Soundness analysis (no defects found)
- **The `Info` invariants hold for every rule:**
  - exact sets are supersets of the matches;
  - inexact prefix and suffix sets hold an affix of every match;
  - the plan is implied by every match.
- **Rules checked one by one:**
  - concat: cross of exact sets; prefix and suffix from an exact side; join grams from a suffix of 2 units or fewer × a prefix of 2 units or fewer;
  - alt: union, or OR of plans with unions of affixes;
  - repeat: `{0,1}` as alt with the empty string; `{0,n}` and `*` as any; `{n}` multiplied out for n ≤ 4; otherwise `x^{min(n-1,3)}` · (any if n-1 > 3) · `x+`;
  - Look as the empty string, which is a superset;
  - a class of more than 16 codepoints as any, which is sound;
  - `[^\s\S]` as an empty exact set, giving `Nothing`.
- **Weakening is sound:**
  - `cut` keeps shorter affixes;
  - an `and` over the cap drops conjuncts;
  - an `or` over the cap becomes `All`;
  - the fallback in `grams` (an AND over positions of an OR over strings) is implied by the per-string AND.
  - No path reads `prefix`, `suffix` or `plan` from an `Info` that is still exact (`concat` rebinds `x`/`y` after `inexact()`; `finish` handles exact).
- **Folding matches the analyzer.**
  - The sets enumerate the codepoints regex-syntax's own case-insensitive translation matches, and each is then mapped with `char::to_lowercase`.
  - That is exactly tantivy 0.27's `LowerCaser`: per-character `to_lowercase`, no final-sigma rule, applied to `NgramTokenizer(3,3)` codepoint windows. I checked this against the vendored source.
  - The multi-character lowercase case (`İ` → `i̇`) is consistent: `"İ".repeat(120)` plans `"i̇i̇i̇"`.
- **Mutation check:** I made the suffix `cut` keep the front units, which is unsound. `every_match_passes_the_plan` failed at once (`"\\d(?-i:[a-c])千ß$E"` matching `" ໑c千ẞE "`). The property test does catch soundness bugs.

## Security pass
- **Pattern length:** 512 bytes, checked before parsing.
- **Nesting:** limited by regex-syntax's nest limit of 16, which covers groups, classes, repetitions, alternations and concatenations. Verified that 15–17 levels of nested brackets, groups and `(?:…){n}` are refused with `regex_too_deep` in about 20 µs. The translation walk recurses (`info`), but only to a depth well under `MAX_HIR_DEPTH` (72), and has its own guard there.
- **Repetition:** one count is capped at 100 and nested counts multiply to at most 1,000; `a{4294967295}` and overflowing decimals are refused. Counts are never multiplied out past four copies.
- **Alternation:** 32 branches. Cross products are capped by `fits` (32 strings, 64 characters each), so nested alternation doesn't blow up. Examples: `(a|…|h)×28` takes 96 µs, `[a-p]×100` 300 µs.
- **Plan size:** capped at 256 nodes by sound weakening; the fuzz target and the tests assert it.
- **Class size:** bounded, except for negated Unicode classes (**B1**).
- **Panics:** no `unwrap` or `expect` on input paths, and no unchecked arithmetic on input (saturating or u64). `unreachable!` in `cut` can't be reached: with k = 0 the set has at most one string.
- **Error messages:** bounded; one path is multi-line and echoes the input (N1).
- **Flags:** only `i` is accepted. `u`, `x`, `s`, `m`, `U` and `R` are refused, so non-UTF-8 matching can't be switched on.
- **Look-around and backreferences:** refused as syntax errors.
- **Dependency:** `regex-syntax =0.8.11`, runner-approved and already in the lockfile; no new crate in the tree.
