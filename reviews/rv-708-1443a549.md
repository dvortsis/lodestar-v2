## Blocking

**B1. The portable build has no `data\logs\lodestar.log`.**
- **Where:** `docs/user/04-install-on-windows-and-linux.md:417` ("`data\logs\lodestar.log` records it") and `:429` ("If the portable rollback fails, read `data\logs\lodestar.log`").
- **Code:**
  - Only the service writes `lodestar.log`. The path is `crates/lodestar/src/windows/logfile.rs:33-36`, and the only caller is the service's console sink at `crates/lodestar/src/windows/service.rs:1112-1113`. The module docs also say it is the service's log (`logfile.rs:1-3`).
  - The portable copy logs to its console window and to `<data>\logs\lodestar.jsonl`. See `crates/lodestar/src/logging/file.rs:31` (`CURRENT = "lodestar.jsonl"`) and the defaults at `crates/lodestar/src/settings/logging.rs:463-465` (`file_enabled: true`, folder `data_dir\logs`).
  - A portable rollback that can't restore the store prints its reason to the console (`crates/lodestar/src/update/windows/portable.rs:1157-1163`).
- **Fix:**
  - Line 417: "the console window and `data\logs\lodestar.jsonl` record it."
  - Line 429: "read the console window, which says what stopped, and `data\logs\lodestar.jsonl`."
- The brief named this path, so tell the runner its wording was wrong. The code wins.

**B2. Windows doesn't ask for a restart.**
- **Where:** `04-install-on-windows-and-linux.md:391`: "If Windows asks for a restart to finish, restart when it suits you."
- **Code:**
  - The helper runs `msiexec /qn /norestart` (`crates/lodestar/src/update/windows/msi.rs:200-201`) from a SYSTEM scheduled task, so there's no prompt.
  - Exit 3010 is handled silently. The journal waits, and the helper finishes at the next boot (`update/windows/helper.rs:819-826`, and the module docs in `update/windows/rollback.rs:26-28`).
- **Fix:** "Sometimes Windows needs a restart to put the new files in place. Nothing asks you: the page stays on the old version. Restart Windows when it suits you, and the helper finishes the update at the next start."

**B3. Events 7024 and 7031 come from Restart now, not from every service restart.**
- **Where:** `04-install-on-windows-and-linux.md:438`: "Restart the service from **Services** (`services.msc`) instead. Each service restart also writes events 7024 and 7031 to the **System** log."
- Placed straight after the services.msc advice, this reads as if a normal restart writes them, and it doesn't.
- **Code:**
  - Restart now exits with the service-specific code 80 (`0x20000050`), so the SCM records a failure and runs its recovery action (`crates/lodestar/src/windows/service.rs:24-30,343-349`).
  - A services.msc or `Restart-Service` restart is a clean stop with exit 0 (`scm_code(0) == 0`, `service.rs:338-341`), so neither event is written.
  - The source is `docs/decisions/2026-11-08-PK-win-restart.md:34` ("each service Restart now logs SCM events 7024 and 7031").
- **Fix:** "Each Restart now of the service writes events 7024 and 7031 to the System log, which is normal."

## Important

**I1. The v0.5.1 note points to steps that aren't there.**
- **Where:** `04:350`: "[Section 3.5] has the steps."
- Section 3.5 has steps for Unraid and Compose only. For native installs it has one line (`03-keep-lodestar-safe.md:105-126`).
- **Fix:** "Take a backup first ([section 3.7](03-keep-lodestar-safe.md#37-back-up-and-restore))." Drop the "has the steps" claim, or point to `operations.md` §7.

**I2. Going back by hand needs a warning about the data format.**
- **Where:** `04:420`: "install that version's MSI by hand."
- The MSI allows downgrades (`packaging/windows/main.wxs:43`). But an older version refuses a store that a newer one migrated. The same chapter's rollback and the §3.5 warning say so.
- **Safe-choice fix:** add "If the newer version changed your library's format, the older one can't open it. Restore the backup you took before the update ([section 3.7](03-keep-lodestar-safe.md#37-back-up-and-restore))."

**I3. "The service stays stopped after a rollback" misses the retry case.**
- **Where:** `04:451`.
- A transient stop, `Outcome::RollbackPending`, writes no Event Log entry. It leaves the service disabled until the next boot or the next run of the task (`update/windows/rollback.rs:58-61,594`; `helper.rs:303`). Only a halt writes event 900 (`rollback.rs:640`).
- A reader who finds no Error 900 has no next step.
- **Fix:** add "If there's no Error 900, the rollback is waiting to try again. Restart Windows and the helper finishes it."

**I4. The recovery bullet undersells the event's steps.**
- **Where:** `04:425`: "The usual recovery is to install the previous version's MSI by hand. Read the event first."
- After a halt past step 1, the marker `<data>\bin\rollback.json` keeps the reinstalled service idle. The administrator then has to delete the marker and the journal and re-enable the service (`rollback.rs:690-700`, the `recovery()` text).
- Someone who only installs the MSI will see the service sit at event 4.
- **Fix:** "Follow the numbered steps in the event, in order: installing the MSI is one of them, not the whole fix."

The guide's row at `04:450` rightly says don't install the failed build by hand. Either the guide notes the clash in a clause, or a web follow-up gives rollbacks their own notice.
- **The SHOTLIST source for 4.8 should be a fixture capture.** The row says "Owner | Pending host capture" (`docs/user/images/SHOTLIST.md:19`). The Updates card is Lodestar's own screen, so the user-docs skill §4 has the Playwright capture supply it.
