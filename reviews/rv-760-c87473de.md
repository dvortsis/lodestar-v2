## The brief's checks
1. **Visibility.**
   - `detail_of` has one caller (`detail`), and `identified_section` is the only place `IdentifiedAs` is built.
   - The section is absent for a torrent that is HIDDEN, PRIVACY (private source, BEP 27 or remote-unverified), held (tombstone or quarantine on any swarm hash), stored Adult, or found by an always-adult source. That is stricter than ENR-7's `held_back`.
   - Claims through a private source and claims from finders are never answers. This matches `stored_title`.
   - A public viewer gets only `public == Some(true)` sources. Unknown and account-class sources are dropped without a trace.
   - The admin sees account-class answers, matching ENR-7's rule for Account-class services.
   - `chosen` is decided before the viewer filter, so it never promotes another answer.
2. **Stored text only.**
   - Nothing is judged at read time.
   - Alt titles are filtered by `language_ok` and non-empty, then cut to 32 × 512 B. Genres are cut to 16 × 64 B. Ids must pass `id_ok` (closed schemes only, so no unknown kind is invented), at most 32.
   - The canonical title is cut to 1024 B on a character boundary. Confidence is capped at 100, and a year outside 1–9999 is dropped.
   - Alternatives are bounded by the per-(torrent, source) claims key, so at most 64.
3. **Absent vs null.** `identified_as` is skipped when `None`. In the OpenAPI it is a plain `$ref`, not required and not nullable, the same as `adult_enrichment`. The DTO doc lists every absent case, and a drift-shape test pins this.
4. **`resolved_via`** is filtered through `ResolvedVia::ALL`, so `plugin` reads as null. No `detail_via_plugin` or `labels.ts` change.
5. **N6.**
   - The clamp is `[max(1 s, 2 × floored per-host interval) min 5 min, 5 min]`. `clamp` can't panic because the lower bound is capped at the upper one.
   - The bounds are documented in the constants and the decisions file. The test covers 0, 1 ms, the default, a pass-through value and a day.
6. **N7.** On timeout, `timed_out` records a transport failure on each manifest endpoint whose host is `Ready`. A host that is backing off or blocked isn't charged again. The unit test covers both.
7. **Tests.**
   - They cover the brief's list: present and absent, private source, Adult hidden with the detail, list and string caps, stable order, the OpenAPI, N6 and N7.
   - No fixed sleeps.
   - No Cargo.toml changed, so tokio `test-util` is not enabled on the `lodestar` package.
8. **Security.**
   - Output is serde JSON with `application/json`, so there is no HTML context server-side.
   - No new SQL in production code. The test's `UPDATE`/`INSERT` use bound parameters.
   - Errors go through `internal`, which hides their text.
   - The extra store reads (enrichment, swarm hashes, `held_among`) run only when an answer exists, and each is bounded.
   - Source ids and names appear only where provenance and ENR-7 already show them.
9. **Owned paths.** All changes are inside the brief's owns plus the allowed shared edits and the runner-approved test edit.

## Important
1. **The N7 call site has no test.** `crates/pipeline/src/identify.rs:749` calls `timed_out(kit, ...)` after the timeout, but the only end-to-end timeout test (`a_hung_lookup_times_out`) uses `Recorder`, whose manifest has `endpoints: &[]` (`crates/pipeline/tests/identify.rs:59`). `timed_out` is therefore a no-op there.
   - **Failure path:** a refactor that drops or moves the `timed_out` call, for example into the shutdown arm, still passes every test. Slow hosts would then never back off, which is the behaviour N3 is meant to build on.
   - **Fix:** a unit test in `identify.rs` that runs `one()` with the `Never` plugin (it has an endpoint) under paused time, or an integration variant with an endpoint, asserting that the kit's limiter shows `BackingOff { failures: 1 }` after the timeout.
2. **The `resolved_via` doc is wrong for the plugin case.** `crates/api/src/dto/torrents.rs:151` (and `openapi.json` / `schema.d.ts`) says "null when the name said it itself". It is also null when the record was resolved via a plugin (deliberately unlisted) and when the record doesn't decode.
   - **Failure path:** ENR-13 reads the contract, renders a null `resolved_via` as "Title from the name", and shows that on a torrent whose title came from TMDB. When the chosen answer's source is withheld, nothing else tells it otherwise.
   - **Fix:** document that null also covers a plugin-resolved title (see `chosen`) and an unreadable record, so the UI shows no method line rather than "from the name".

## Nits
1. **`chosen` can name the wrong answer for a while** (`crates/api/src/torrents.rs:833`). `chosen` is the current top answer with a canonical title, whenever the stored record says `Plugin`. If a surer answer arrives, or the answer behind the title is purged, before the backfill re-resolves, the marked answer's title differs from the one the record shows. That is exactly the mislabel the decisions file wants to avoid.
   - **Fix (cheap):** also require that the record's title equals the answer's `canonical_title`.
2. **The N6 floor uses `UserLimits::default()`** (`crates/pipeline/src/identify.rs:497`). That matches the kit the pipeline builds today (`pipeline/src/lib.rs`, also `UserLimits::default()`). If user per-host limits are later wired into enrichment kits, the floor must use the same limits, or a slower user rate brings back the "timed out in the token wait, charged a host that got no request" case. A one-line comment would help.
3. **Schema bounds are missing.** `confidence` (`dto/torrents.rs:171`) has no `maximum = 100`, and `year` has no 1–9999 range in the OpenAPI, although the code enforces both. Adding them is cheap.
4. **Bidi and control characters in served text.** The store accepts any UTF-8 in canonical, alternative and genre text. The clamp cuts but doesn't strip, the same as `name` elsewhere in the DTO. This is not an injection risk in JSON. ENR-13 must render these as text (no `{@html}`) with bidi isolation (`dir="auto"` / `<bdi>`), so a stored RLO can't reorder adjacent UI text. Worth a line in ENR-13's brief.
5. **The new DTOs `derive(Debug)` and print titles,** while the store's `Details` and `AltTitle` Debug impls deliberately redact them (titles "can name what a rule holds"). Nothing logs these DTOs today. A redacting Debug, or a note, would stop a future `tracing::debug!(?detail)` from leaking.
6. **No test that withholding the chosen answer leaves none chosen.** A unit test for a public viewer with the chosen answer from an account-class source and `resolved == Plugin` would pin the decisions file's "never promoted" claim. The path is unreachable through the route today, which is session-only.
