## Bounded runner correctness
- **Timeout:** `kill()`, then `wait()`, so the child is reaped. A `try_wait` error also ends the child.
  - On Windows, std's `kill` returns Ok for a process that has already exited, so there's no race between `try_wait` and `kill`.
  - If `kill` fails, the code skips `wait` and drops the handle. On Windows that only closes the handle (no zombie). On Unix it could leave a zombie, but kill can't fail on our own unreaped child.
- **Pipes:** all null, so nothing can fill and deadlock.
- **Clock:** `Instant` is monotonic (QPC on Windows), and the code uses `saturating_duration_since`. A wall-clock jump can't stretch or cut the bound.
- **Spawn failure:** returns `Err` at once without waiting. Both callers discard it.
- **A child that ignores kill:** neither SIGKILL nor TerminateProcess can be ignored. The one residual is a process wedged in a kernel driver, where the post-kill `wait()` is unbounded (see N3). That was already true before.

## Service path
- **Fixed arguments:** `/T kind /ID id /L APPLICATION /SO Lodestar /D <text>`. `kind` and `id` come from the `Refusal::event()` match. The text is one `Command::arg`, so Rust's MSVC-rules quoting keeps it a single argv entry. No shell or `.bat` is involved. The text always starts with "Lodestar's …", never `/`.
- **Timeout:** `EVENT_LOG_WAIT` = 10 s.
  - **Stop and shutdown:** the control handler (service.rs:~750-759) reports StopPending and ticks while stopping on its own thread. So a stop during the ≤10 s note is acknowledged at once. The main loop sees it right after the bound, in `idle_during_rollback` on the rollback path, or it ends with REFUSED on the refusal path.
  - The service can't hang Running for good any more, which was the defect this slice fixes (rv-702 N2).
