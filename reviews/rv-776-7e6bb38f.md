## Important
- crates/search/src/regex.rs:499 says the table is "as of Rust 1.99 (Unicode 16)". Rust 1.99's `char::UNICODE_VERSION` is (17, 0, 0), and 1.100's is (18, 0, 0). Unicode 16 is the version of regex-syntax 0.8.11's own fold table (`ucd-generate case-folding-simple ucd-16.0.0`), so the comment mixes the two up. It's a one-word fix ("Unicode 17"), and worth doing because the comment is the provenance a future regeneration relies on. It doesn't affect correctness: the table is a superset either way.

## Verified
1. Soundness
   - cased() is used only for cost estimation: in fold_cost (the table partition_point, `lo`/`hi` for the in-table span, the hit counts) and in fold_cost_of (the widening union). No matching path uses it.
   - The superset test is real and runs: `regex::tests::the_cased_set_covers_everything_regex_syntax_folds ... ok` on stable 1.100. It probes every codepoint up to U+1FFFF with regex-syntax's `case_fold_simple` and checks that nothing past that scan folds.
   - That test now compares a constant against the pinned regex-syntax (0.8.11 in Cargo.lock, unchanged), so it's deterministic across toolchains. A regex-syntax bump that folds something outside the table fails it.
   - `hi` (U+1E943) is at least regex-syntax's last fold key, because of the superset, so the `inside` span never under-counts. Past its last key, regex-syntax's SimpleCaseFolder::mapping returns early, which matches the model.
   - Fold images are themselves fold keys, so the widening bound holds.
2. Table
   - Regenerated independently with rustc 1.99.0 (std to_lowercase/to_uppercase over 0..=0x1FFFF, merged into inclusive ranges): 131 ranges, identical to CASED_RANGES, and nothing cased past 0x1FFFF.
   - On 1.100 the same scan gives 142 ranges: 41 more characters, at U+0277, U+027C, U+A7DD, U+A7E2, U+AB4B-AB4C, U+AB6C-AB6D and U+1DF40-1DF95, all below U+1E943, so `hi` would have stayed the same. This confirms the PR's explanation.

   - The `expect` on range ends can't fire, since every end is a valid char below the surrogates or in the supplementary planes.
   - `#[rustfmt::skip]` on the data table is acceptable.
