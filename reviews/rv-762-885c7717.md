## Review items
1. **Untrusted input is fine.**
   - Page bytes are capped at 2 MiB before parsing, and SRC-6 reads at most 1,000 items.
   - At most 100 results are kept per page and 4,096 per poll. `take_one` uses a CAS and never wraps.
   - Sizes outside 1..=1 PiB give no size. The date is range-checked with `saturating_add`, and `unix_now` uses `i64::try_from`.
   - The category is a `u32` written in decimal. `canonical_indexer` re-checks the id.
   - `holds_key` is bounded by `valid_key` (≤128).
   - There are no unwraps on input and no slicing at char boundaries.
   - The `usenet_polled` map holds at most `MAX_INDEXERS` entries.
   - The proptests cover hostile bytes and hostile title, GUID, size, date and category values.
2. **No secret is stored or logged.**
   - The link is dropped in `to_usenet`. `UsenetFind`'s Debug shows lengths only, and `Found` carries only the 32-byte hash.
   - The API key goes in a header; the tests assert no request URL holds it.
   - The end-to-end test scans decoded claims, the raw files of the store on disk and every log line (all pipeline, filter and integrations events on) for both keys, the poster and the link shapes.
   - No metrics labels or error strings were added.
3. **Content safety holds.**
   - Ingest judges every text: the name, and the details category alone and joined with the name.
   - The always-adult flag comes from `ctx.adult.has(source)` at ingest, and from `any(sources) || has(source)` on re-judge.
   - Any hold stores nothing.
   - The re-judge now checks the network before the 20-byte `try_from`, so usenet items are judged by their claims and kept when nothing matches.
   - Nothing becomes visible: search doesn't index `unverified_items`, `pending_keys_after` and the torrent cache filter to `Network::Bt`, and `promote` refuses usenet.
4. **The store is unchanged.**
   - The cap and eviction are UN-0's, in one transaction.
   - Writer batches of 256 stay under `MAX_USENET_BATCH` (4,096).
   - The cap's cost is measured and stated: about 110–130 ms per write at 1M.
5. **Off by default.** The schema default is `false`, `from_json` defaults it off and `to_json` writes it only when on. Jackett refuses the switch. The companion wiring keeps saved settings, so a re-save keeps `usenet`.
6. **The tests cover every case the brief lists.**
   - `wait_for` and `until` poll with deadlines of 10 s or more, and there are no fixed sleeps.
   - `start_paused` is in `sources-plugins`' dev-dependencies, as in its other test files. The `lodestar` package doesn't change.
   - The one `#[ignore]` is the requested measurement, which follows the repo's own practice.
7. **Ownership:** the files outside the brief's list are the runner-approved ones, plus `tests/claim_trackers.rs` (nit 6). Nearly 1,000 of the 2,565 added lines are fixtures and 950 are tests. I couldn't read the PR description under the no-network rule, so check its stated size reason yourself.
8. **The banned strings:** no 12-digit numbers, no model identifiers, and no local times. The `+0000` values in fixture `pubDate`s are RFC 822 feed data.

### Nits
1. **`prowlarr.rs` `Job::poll` and `usenet_due` (~L620, L650).**
   - `usenet_due` marks an indexer polled before the request is made. A timeout, a 5xx or a page refused as too big then waits a full hour, not the next 15-minute round.
   - When the poll's 4,096 runs out mid-page, the indexer is marked polled anyway. Its unsent results wait an hour, so `USENET_POLL_ITEMS`' doc "the rest wait for the next poll" is wrong for them. On an indexer posting more than 100 an hour they're lost.
   - **Fix:** mark the indexer polled only after a 200 that was fully emitted, or fix the doc and accept the loss as a known gap (the decisions file already notes the starvation).
2. **`unverified.rs` `UnverifiedStats::held` (~L174).**
   - The doc says "tombstoned or quarantined". A usenet hold is neither, and it counts a non-core rule hit as `held`, where the BitTorrent path counts that as `dropped`.
   - **Fix:** count non-core usenet hits as `dropped`, or update the field's doc to match.
3. **`lib.rs` intake, the `retried` branch (~L1568, L1645).**
   - No path sends a usenet find to `retry` today: touches skip it and verify is BitTorrent only. If one ever did, its 20-byte prefix would go to the coordinator and peer finding as an info hash.
   - **Fix:** add a cheap defensive check, `if d.found.is_usenet() { refused; continue }`, before the claim.
4. **`prowlarr.rs` `CONFIG_SCHEMA` description.**
   - The switch now appears in the generic settings form. A user can turn it on and spend their indexers' daily API quota (24 hits per indexer) on items they can't see or send until UN-3 and UN-4.
   - **Fix:** say so in the description (for example, "not shown or sendable yet"), or hide the property until UN-3. This is the runner's UX call.
5. **Turning the switch off leaves the stored usenet items** (up to 1M rows) until a source purge. Name it as a known gap or a follow-up (purge the tier on switch-off).
6. **`crates/pipeline/tests/claim_trackers.rs` isn't on the approved shared-edit list.** It's a test-only companion to the `store_claims` L3 check (+23 lines), so it's harmless. Note it in the PR's list of shared edits.
