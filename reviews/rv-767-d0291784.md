## Blocking

- Every new API test reads `always_adult` from a hand-built `FakeOps` (`crates/api/tests/identified.rs:111-113`, `crates/api/tests/adult_enrichment.rs:117-120`). Nothing checks that the real host `Ops` serves the manifest's value.

Every Sukebei source then reads as `Some(false)`, "known not always-adult". `adult_or_unknown` vouches for it, so with Show adult off the "Identified as" section shows third-party answers on Sukebei finds in both ENR-12 windows: before `adult_by_source` reclassifies them, and after a Not adult correction. That is the gap this slice exists to close, and it would reopen with CI green.
- **Fix (small, inside the owns):** add a test in `crates/lodestar/src/ops/tests.rs` on the real `Ops`. The existing `gated()`/`gated_fixture` pattern (around lines 993-1060), with a `Manifest { always_adult: true, .. }` plugin beside a `false` one, works. Assert that `GET /sources` (or `/sources/{id}`) serves `"always_adult": true` and `false` respectively. A unit test over the plugin catalogue's real manifests also works: every `lodestar_sources_plugins::catalogue::always_adult()` manifest maps to `always_adult == true`.

## Important

**I1. Brief requirement 1 ("assert or test that the two are equal") is met only by construction, not against `AdultSources::of`.**
- `Catalogue::always_adult_bits` (`crates/api/src/torrents.rs:315-323`) re-implements `AdultSources::of`'s rule. The tests only check it against hand constants:
  - the unit test `the_always_adult_mask_follows_the_manifests_and_fails_closed` expects `(1<<3)|(1<<7)`;
  - `identified.rs:496` gives the drawer `1 << 5` by hand.
- Nothing compares the two derivations. `lodestar-pipeline` is already a dev-dependency of `lodestar-api`, so a unit test can build both from the same `(SourceId, &Manifest)` pairs and assert `AdultSources::of(..).0 == catalogue.always_adult_bits()`.
- The union in the route (`torrents.rs:687`, `:721`) makes a disagreement harmless for "Identified as": it only adds hides. That's why this isn't blocking. ENR-14 will wire the real `DrawerInterest::new(AdultSources…)`, and this test is the brief's guard for that.

**I2. The decisions file doesn't name the non-plugin sources that will now always hide the section.**
- The fail-closed rule is correct: a store source row whose plugin isn't in the ops listing counts as always-adult. But in the real binary such rows exist besides "plugins this build doesn't run":
  - the pipeline's local upload source (`crates/pipeline/src/lib.rs:687`, `local_torrent::SOURCE`);
  - the import adapters (`crates/lodestar/src/cli/import.rs:685`, `:852`: bitmagnet and the others).
- Any torrent they found never shows "Identified as". That's safe, but the decisions file's table says only "Unknown plugin, or unregistered bit". Add one line naming uploads and imports, so ENR-13/14 don't read it as a bug and "fix" it by vouching for them.

## Optional

- **O1.** `#[serde(default)]` on `Source::always_adult` (`crates/api/src/dto/ops.rs:446`) defaults to the unsafe value.
  - Today it's harmless. No production code deserializes `Source`, and the detail route gets it from the in-process `OpsApi` as a Rust struct, whose literals must set the field.
  - If a remote `OpsApi` ever deserializes a listing (cluster, a proxy), an older peer would read as "not always adult". A comment saying so, or a test-only default, would prevent that.
- **O2. Pre-existing, outside this PR's scope:** `load` (`torrents.rs:568-590`) answers `adult_hidden` from the stored type only.
  - In the window before reclassification, with Show adult off, a torrent found only by an always-adult source is still served: its own name and files, with no "Identified as" and no adult section.
  - The brief forbids changing visibility here, and X-source-adult classifies new finds Adult at write time, so the window is narrow. It's worth a runner note, since it's the same window ENR-12 closes for the sections.
- **O3.** `adult_or_unknown` loops over all 64 ids per detail request. That's negligible, and `MAX_SOURCES == 64` makes it cover every bit of `u64`, so no id lies beyond the mask. Worth one assert or comment that it relies on `MAX_SOURCES == 64`, in case the constant ever changes.
