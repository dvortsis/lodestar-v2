## Findings

### Blocking
1. **I1's test passes with I1's fix removed.** Location: `crates/sources-plugins/src/prowlarr.rs:1540-1555` (`polls_stay_hourly_whatever_the_answers_latency`), with the jitter at `:1547`.
   - **Why it misses:** the jitter is `if round % 2 == 0 { MIN } else { ZERO }`. Every polled round (0, 4, 8, …) is even, so every poll lands at exactly `+1 min`.
   - So `now - done` is exactly 60 min each time. The old `< USENET_POLL_EVERY` check without slack also finds the indexer due, and the test counts 24 polls either way.
   - **Confirmed:** with `USENET_POLL_SLACK` set to `Duration::from_secs(0)` (M1), the whole suite passes.
   - Standards §"Blocking" lists "a missing test for new behaviour", and the slack is the new behaviour. Without a test, a later edit can drop the slack or tighten the check back to 60 min, and the 75-minute drift returns unseen. Under paused time the replayer's latency is 0, so the integration tests can't see it either.
   - **Fix:** make the offset of the polled rounds vary.
     - For example: `let jitter = if (round / 4) % 2 == 0 { MIN } else { Duration::ZERO };`. The poll at round 4 then lands 59 minutes after the one at round 0.
     - I checked this change: it passes with the slack and fails without it, with `left: 21, right: 24`, "hourly, not every 75 minutes".
     - The test's comment ("the grant is stamped, not the answer") claims more than a unit test can show. Rewording it to say the rounds' offsets vary would make it accurate.

### Important
1. **Nothing tests that a request never sent costs no hit.** Location: `prowlarr.rs:716` (`if ix.usenet && page != Err(Failure::NotSent)`), and the test at `prowlarr.rs:1558-1574`.
   - `a_request_never_sent_isnt_a_hit` tests `answer`'s mapping to `NotSent`, which is real.
   - Its second half calls `p.due(..)` 48 times without ever calling `hit`. Nothing is recorded, so it asserts only that an empty map stays empty. It reads as if it covers the wiring, but it can't fail.
   - **Confirmed:** with `hit` called on every outcome (M4), every test passes.
   - The decisions file states this as behaviour: "Only a request actually sent counts as a hit". If it regresses, a 12 h `Retry-After` block uses up the day's 48 hits again.
   - **Fix, either of:**
     - Move the decision into a small pure function, for example `fn sent(page: &Result<Vec<u8>, Failure>) -> bool`, used at `:716`, and unit-test it on `NotSent`, `Other` and `Ok`.
     - Add an integration case: a 429 with `Retry-After` on a usenet page, then assert how many times the indexer is asked after the block lifts.
   - In either case, drop or replace the vacuous `due` loop.

### Optional
1. **`granted` is taken before `gate_poll`, which can sleep through the unit's back-off.** Location: `prowlarr.rs:705`. Prowlarr's `POLICY` allows a back-off of up to 6 h.
   - **Scenario:** a usenet indexer recovers after a long 5xx back-off. The successful page is stamped `done` at the grant, hours before the answer, so it's due again on the very next round, 15 minutes later. That's one extra hit after each recovery.
   - Hits were already stamped before the gate in the earlier version, so the daily window's skew isn't new. Stamping `done` from the grant is new.
   - It's bounded by `USENET_DAILY_HITS`.
   - **Fix:** stamp `done` with `max(granted, answered - USENET_POLL_SLACK)`, or note the trade-off in the decisions file.
2. **The decisions file overstates the cadence.** It says whole pages come "every fourth round, hourly: 24 a day". With up to 7.5 min of slack, rounds whose offsets drift can bring polls as close as about 52.5 minutes apart: up to about 27 whole pages a day, still under the 48 bound. A short clause, such as "about hourly (never closer than 52.5 minutes)", would make it exact.
3. **`USENET_POLL_SLACK` is written as `15 * 60 / 2`, a copy of `min_poll_interval`.** Deriving it from `POLICY.caps.min_poll_interval / 2`, or a shared constant, would keep the two from drifting apart.
