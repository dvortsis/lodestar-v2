## Blocking

**B1. The data-directory refusal has no test.**
- Where: `bench/src/dataset.rs:251-256` (`check` → `Refused::DataDir`) and `:299-324` (`inside`).
- The problem: the brief's first rule is "Never a user's data directory". `inside()` has real path logic: it resolves the nearest existing ancestor of a folder that doesn't exist yet, handles relative paths, and follows symlinks through `canonicalize`. The self-review fix "`$LODESTAR_DATA_DIR` subfolders refused" depends on it. None of this is tested. `a_folder_that_is_not_a_dataset_is_never_written` only covers `NotADataset`. A regression in `inside` would let a build create and write a subfolder inside a live data directory with no test failing. My probes show it works today.
- Fix (no process-global env mutation needed):
  - a unit test of `inside` in `dataset.rs`: an existing subfolder; a subfolder two levels down that doesn't exist; a relative path; a sibling with a shared prefix (`data` and `data2`); a symlink into the data dir on unix;
  - and/or a test in `tests/dataset.rs` that runs `CARGO_BIN_EXE_size-report` with `.env("LODESTAR_DATA_DIR", …)` and `--dataset <data>/sub/ds`, then asserts a non-zero exit and that `<data>` is still empty.

**B2. `--gate` with `--dataset` failing closed is untested.**
- Where: `bench/src/bin/size-report.rs:759-763` (`full_ok`).
- The problem: the README and the decisions file promise that a `--dataset` run with `--gate` exits 1 unless the verdict is `pass`, "so a missing measurement can never read as a pass", and M8-PERF-3 will gate on that exit code. `verdict()` is tested, but the exit wiring isn't. Every `size_report(...)` call in `tests/dataset.rs` runs without `--gate` and asserts success.
- Fix: in `size_report_gives_every_size_figure_and_leaves_the_dataset_as_built`, run once more with `--gate` and assert exit code 1. The 1,200-torrent dataset is `incomplete` (unpopulated fields) or `fail` (small-scale sizes), never `pass`. That's one more subprocess on a dataset the test has already built.

## Important

**I1. The store schema version is recorded but never checked, and the re-index path migrates a complete dataset in place.**
- Where: `bench/src/dataset.rs:241` writes `store_schema`, and nothing reads it. `:355-362` turns a complete dataset that lacks this build's index folder back into a build, and `:377` then runs `Store::open(&db, …)`, which migrates the store.
- The problems:
  - If the store schema and the search schema both move between runs, the 10M "canonical store" figure is measured on a store migrated in place, not on one built by this build. The figure stops being like with like, and the "read-only once built" promise breaks.
  - If only the store schema moves, `size-report` fails inside `Store::open_reader` → `schema::check_current` with a store error. That's still fail-closed, but it isn't the brief's "refused, with a message naming both".
- Likelihood: low during M8, since plan §4.2 line 40 rules out migrations, but the dataset persists on the runner past 1.0.
- Fix: in `check`, compare the manifest's `store_schema` with `lodestar_store::latest_schema_version()` and refuse with a message naming both (or add it to the key). Never call `Store::open` on a dataset whose phase is `complete`.

**I2. An interrupted re-index leaves a dataset that can't be resumed.**
- Where: `bench/src/dataset.rs:355-362`.
- The problem: switching to a re-index sets `phase = "rollups"` in memory only, so the manifest still says `complete`. If the process dies partway through `index_all` (hours at 10M), the next open sees `complete` and an index folder that exists, so `verify_index` fails with "delete the folder to rebuild". The operator then throws away a 25 GB, multi-hour build that only needed its indexing resumed, and the indexer could resume from its committed watermark.
- Fix: `write_manifest(dir, key, "rollups", &totals)` when switching to the re-index, plus a test: stop the re-index with `build_until(.., Some(..))`, or truncate the new index to a partial commit, then reopen.

## Optional

- **O1. Free pages inflate the store figure.**
  - Where: `bench/src/dataset.rs:686-735` (`year_of_rollups`).
  - Building a year of hourly rollups and then compacting it leaves the freed pages in the file. On a 300-torrent dataset I measured `freelist_count` = 1,620 of 1,976 pages at 16 KiB, so about 26.5 MB of the 32 MB file is free space. At 10M that's about 2.7 B a torrent on the 1,024 B store figure: conservative and small, but an artefact of the build order.
  - Consider `PRAGMA incremental_vacuum` after compaction (the store uses `auto_vacuum = INCREMENTAL`), or report the freelist bytes.
  - While you're there, the dataset already holds exactly a year of rollups, so a reported "rollup bytes per year" row (owner §1.6.4, ≤ 50 MB) would cost almost nothing.
- **O2. Make the `off` refinement explicit for the owner.**
  - Where: `docs/decisions/2026-11-12-M8-PERF-1a.md:17` ("which still isn't a pass") and the PR description ("Neither status is ever a pass").
  - An `off` row doesn't stop the verdict from being `pass` (`verdict()`, and the test `a_verdict_passes_only_when_every_row_does`). Since this refinement is flagged under §2.19, say plainly that the row itself isn't a pass but the report can still pass.
- **O3. Refusal wording.** `bench/src/dataset.rs:151`: the refusal says "{dir} is $LODESTAR_DATA_DIR" for a subfolder too. "is in $LODESTAR_DATA_DIR" would be accurate.
- **O4. Row id style.** `bench/src/bin/size-report.rs:634-635`: `low_resource.switch.trigram_off` and `size.fields.group_key` use underscores, while the other ids are dash slugs. M8-PERF-3 will gate on these ids, so settle one style before then.
- **O5. Version pin.** `bench/Cargo.toml:23`: `serde_json = "1"`. Standards §2 says "pinned exactly". `crates/update`, `integrations` and `sources-plugins` use `"1.0.154"`, the version in the lock.
- **O6. Disk kind on cloud VMs.** `disk_kind` reports `hdd` on this container's virtio disk, which reports `rotational=1`. That's fine for the NVMe runner; a README note that VMs can misreport would help readers of the report.
- **O7. Concurrent builds.** Nothing locks a dataset folder, so two builds in one folder at once would interleave. A lock file, or a sentence in the README, would close that.
- **O8. Untested refusal paths.** `Refused::BadManifest` (an unreadable `dataset.json`, an unknown phase) and a leftover `dataset.json.tmp` (refused as `NotADataset`) have no tests.
- **O9. Dashboard entries.** `runner/slices.yaml` and `runner/dashboard.yaml` have no entries for `M8-PERF-1a` or `1b`. The PR correctly leaves them to the runner, which should add them.
