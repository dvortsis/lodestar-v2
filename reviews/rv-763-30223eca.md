## Important
1. **One line of the decisions file doesn't match the code.** `docs/decisions/2026-11-12-M8-NET-E2E.md:18` says the KRPC client runs "an iterative `get_peers` lookup from the bootstrap node, then `announce_peer` to the 8 closest nodes it found".
   - The code has no iterative lookup. `Network::closest` (`crates/crawler-sim/tests/e2e/net.rs:97-102`) sorts the test's own list of every node id. `Client::announce` (`net.rs:205-226`) then sends `get_peers` straight to those 8 nodes, followed by `announce_peer`. The module doc at `net.rs:1-5` describes this correctly.
   - Failure scenario: M8-CHAOS-1 builds on this harness. Its author reads the decisions file, believes the announce path tests lookup convergence under loss or latency, and draws the wrong conclusion when chaos never touches the client's announces. The client can't fail to find the closest nodes; it panics only if a node doesn't reply within 12 s.
   - Fix: reword line 18, e.g. "a `get_peers` (for the token) and `announce_peer` sent straight to the 8 nodes closest by XOR distance, worked out from the test's list of node ids, where a client's lookup would end". This is a docs-only fix and doesn't block.

- **The brief and the clock.** The test runs the production path in process:
  - 50 real `lodestar_dht` nodes on loopback UDP;
  - real TCP `FakePeer`s over the real peer wire (BEP 9/10);
  - the production `DhtSource` inside `Pipeline::start` with `PipelineConfig::default()` (default filter, `allow_private` added);
  - the real `Store` in a temp dir;
  - `Serving::open_or_rebuild` with `LiveConfig::default()` cadence (500 ms poll, 2 s commit; only the heap is 64 MiB);
  - `/api/v1/search` through `lodestar_api::router`, after a real setup and sign-in.

  Each hash's interval runs from the crawler's first BEP 51 sample harvest to the first `/search` poll that returns it. This is runner decision C, which the runner flags to the owner.
- **The interval is measured honestly.**
  - `dht.key_harvested` is emitted synchronously in `harvest_hash` (`crates/dht/src/node/actor.rs:924`) before `try_send` to the pipeline. `lodestar_log::emit` calls the sink inline (`crates/log/src/dispatch.rs:54-60`). So the start stamp is at or before the handoff.
  - The searchable stamp is taken after the response arrives. Both errors therefore lengthen the measured time.
  - Only the crawler samples, and `net.harvested_sample() == 0` is asserted.
  - If the crawler ever first saw a hash via `get_peers` or an announce, `seen` would suppress its later sample event. `sampled()` would then return `None` and the test would panic at `e2e_search.rs:207`. It can't mis-measure silently.
  - Harvest itself must happen within 30 s of serving (`e2e_search.rs:209`).
  - The bar is checked for every hash, on every platform. There's no `cfg`, `ignore` or environment switch.
  - The search deadline (40 s) is longer than the bar, so a miss reports how long it took.
- **Names, sizes and file counts.** Every one of the 16 is matched by name, hash, size and file count (`e2e_search.rs:250-256`).
  - Forged and orphan names contain the query word, so the negative checks mean something.
  - Forged: a `HashMismatch` failure is counted, and the hash is neither stored nor searchable.
  - Orphan: the hash is queued with at least 1 attempt, and neither stored nor searchable.
  - Writer `stored == 16` and search `total == 16`.
- **No fixed sleeps.** The only `sleep` is the 20 ms poll inside `wait::until` (`wait.rs:34`), which asserts a deadline of at least 10 s.
  - Each client query is a `tokio::time::timeout(3 s)` on receive, retried 4 times (12 s in all), so it's bounded and isn't a sleep.
  - The runtime isn't paused, so `tokio::time` is real time even with `test-util` on.
- **Teardown.** On the pass path everything stops:
  - `Pipeline::shutdown` stops the pipeline;
  - the API router is dropped before `Arc::try_unwrap(serving)` and `Serving::shutdown`;
  - each network `Node::shutdown` is awaited;
  - `FakePeer::drop` aborts its task (`crates/peer-wire/src/testing.rs:222-224`);
  - the client socket is dropped.

  All ports are ephemeral (`:0`). The test is order-free, with no goldens. Names and sizes come from a seeded SplitMix64; node ids and timing are real, and the decisions file states this.
