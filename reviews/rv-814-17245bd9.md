## Checked and correct
- **Gate.** `consent_text_approved` (`control.rs:605-610`) still returns false for External and Account.
  - `enable_decision` checks `approved` first, before purge, condition and password.
  - The start path (`switch_off_unapproved`) still switches off an unapproved class before `need_in_with`.
  - The matrix test and `safety.rs`'s property still pin "External and Account are refused whatever is sent".
  - None of these files changed: the Legal Notice copies, `crates/api/src/legal/notice.md`, `crates/lodestar/tests/legal_facts.rs`.
- **Password re-ask for Account.** `needs_password` now covers Account (`consent.rs:98-103`).
  - `need_with` uses `needs_password` only inside the `needs_ack` branch, which Account never enters, so `Need` results don't change.
  - `enable_decision` asks for the password only when a non-enabled source is enabled (`Some(true) if current != Enabled`). Every other path is unchanged.
  - The credentials route never enables (it can only disable). Priority, config and egress changes don't enable.
  - The API sets `password_confirmed` only after `auth::confirm_fresh_password` passes. That function is unchanged and existing; this PR adds no comparison of its own. A missing or empty password gives `confirmed = false`, so the request fails closed with `PasswordRequired`.
  - No password is logged or echoed. `SourceChange`'s Debug impl is unchanged.
- **Matrix oracle.** It now requires `&& password` for Account (`control.rs:2004`). That case would fail before the change, because an Account source with `api_key` and no password was allowed.
- **Undeclared names.** `check_declared` runs in the validation loop before `spawn_blocking`, before sealing and before the store write. A batch with one undeclared name stores nothing.
  - The name comparison is exact byte equality. `check_name` runs first and allows only `[a-z0-9_]` (≤ 64) or the two SOCKS5 names, so case, Unicode and whitespace variants can't arise. `API_KEY` and `""` are refused, which the unit test shows.
  - Removal skips the check, so a name stored by an older build can still be cleared. It still passes `check_name`.
  - The refusal text is a fixed string with no name and no value. `OpsError::BadCredential(r.to_string())` passes it through, and `credential_changes` already avoids serde messages.
  - Real callers are unaffected:
    - Prowlarr, StashDB and ThePornDB declare `api_key` (`prowlarr.rs:268`, `stashdb.rs:113`, `tpdb.rs:106`).
    - `companion_wiring`'s hand-over stores only `api_key`.
    - `ConsentDialog.svelte` sends only names from `credential_spec`.
- **`identify.rs` move to `need_in_with`.** It passes the plugin's `policy().credentials`, the same input `Control` uses.
  - For non-Account classes the spec has no effect.
  - For Account, the new rule is a subset of the old empty-spec rule:
    - With required names declared, every one must be stored.
    - With only optional names declared, a declared one must be stored.
    - In both cases the old rule took any non-egress name.
  - So it's identical or stricter, never looser. `check` stays as the empty-spec form, used only by tests.
- **Download clients.** `clients.rs` is Account with no spec and isn't registered in `services.rs`. With no spec, only the SOCKS5 pair can be stored now, and egress names never satisfy `credentials_held`. So it fails closed twice over (and the gate refuses it anyway). The decisions file describes this accurately.
- **`text_version(Account)` = 0.** `needs_ack(Account)` is false and `version()` is `""`. The unit test pins all three. The decision and its limit are documented accurately.
- **Test fixtures.** `Probe`, `Ticker`, `Gated` (Account only) and `StandIn` now declare `api_key`. `Probe` also declares 17 optional names, so the 16-credential cap stays reachable through declared names. That's 18 entries, over `check_spec`'s limit of 16. Nothing runs `check_spec` on test fixtures, and the extra names are what let the test reach the cap, so this is fine.
  - The new typo test in `crates/pipeline/tests/control.rs` refuses `apikey`, `api_key_` and `token` with `Undeclared`, checks that nothing was stored, and checks that an undeclared name can still be removed.
  - The new API test checks 400 `invalid_credentials`, no secret in the body, and nothing stored.
  - All of these fail without `check_declared`.
- **Test hygiene.** The diff adds no `#[ignore]` and no sleeps. The two ignored tests in the pipeline lib are the existing `writer.rs` measurements.
- **Generated files.** The `openapi.json` and `schema.d.ts` changes are exactly the two doc-comment changes, `patchSourceCredentials`'s summary and `password_required`'s description, in the tooling's formatting. I didn't regenerate them myself (disk, see below). They match the Rust doc comments word for word.
- **Decisions file.** It has no 12-digit numbers, no model identifiers and UTC times, and the referenced files exist. The files beyond owns match the runner-approved list. The owned files `adult_enrich.rs`, `lib.rs`, `crates/lodestar/src/ops.rs`, `consent_gate.rs` and `safety.rs` weren't touched, which is fine.
