## Blocking
1. **crates/sources-importers/src/bitmagnet/pg_tests.rs:40-45 and the `Fixture::new` CREATE DATABASE at :136-143: the quiescence flake is reduced, not fixed.** The root cause is right: an autoanalyze commits an xid, which moves `pg_current_snapshot()` in QUIET_SQL. But the fixture tables are not the only tables that get analyzed. Every fixture runs `DROP DATABASE IF EXISTS` and `CREATE DATABASE`, and its `drop_db` runs one more DROP. That churn modifies the shared catalog `pg_catalog.pg_database`, which crosses its analyze threshold (50 + 10% of rows) after a few dozen fixtures, about once per run. Then any autovacuum worker, in whichever database it visits, autoanalyzes `pg_database`. That writes `pg_statistic` under an xid, which moves the cluster-wide snapshot mid-read, so the read is refused with `NotQuiescent` again. `WITH (autovacuum_enabled = false)` can't reach a catalog.
   - **Evidence:** with `log_autovacuum_min_duration = 0`, the only autovacuum activity in the head runs was on `pg_database`: 51 analyzes and a number of vacuums, logged from inside the fixture databases. With the cluster's autovacuum off, failures went to 0/50.
   - **Fix (tested, test code only):** in `Fixture::new`, right after the CREATE DATABASE, add `a.batch_execute("ANALYZE pg_catalog.pg_database").await.unwrap();`. This resets the catalog's change counter, so one test's own churn never reaches the threshold. With it: 0/80 runs, and the log shows no autoanalyze at all (vacuums of `pg_database` still ran, so plain vacuum doesn't move the snapshot). It runs before `settle()`/`open()`, so its own xid is in the baseline. It could equally go in `settle()`. For a non-superuser, ANALYZE of a shared catalog is a WARNING and a skip, not an error. CI connects as `postgres`.
   - **Also:** update the decisions file (docs/decisions/2026-11-12-X-test-blockers-1112.md:8) so the recorded cause covers the shared catalog, and the "0 in 30 after" figure reflects the longer run.
   - It's one line, so I'd fix it in this PR rather than leave a flake that CI's default 60 s naptime only makes rarer.
