## Nits
1. **Two record attempts per look while a write keeps failing** (`check.rs:808-821`). While `result.json` still holds the kept answer, each look tries to record it twice and logs `update.state_unsaved` twice. Looks run at every status, so a failing disk doubles the log lines. Fix: skip the `result.json` answer when its id and outcome equal the kept one's.
2. **`get_or_insert` keeps the older of two failing answers** (`check.rs:820`).
   - If a kept answer X and a different fresh answer Y both fail, only X stays in memory. A hand-over after that loses Y.
   - It's contrived: two distinct ending answers in one process, with writes failing throughout.
   - Fix: say so in the residual, or keep the newer one (`*lock(..) = Some(answer)` in loop order).
