# Review: PR #662 X-flake-portable-restart @ 81fe7bb3 (fresh Opus)
VERDICT: MERGE. Nothing blocking.

## Root cause
Windows signals the process object only after it unmaps the old process's views. The old copy still has SQLite's -shm file mapped when the pipe reaches end of file, and SQLite's first opener truncates -shm. Waiting on the process object (WaitForExit) fixes the cause rather than masking it.

## Security
- The PID accepts only ASCII digits and a nonzero u32.
- PowerShell is found by absolute path through System32 and runs with -NoProfile -NonInteractive, CREATE_NO_WINDOW and null stdio. The token is removed from its environment. The watch is killed and reaped on every path.
- PID reuse is guarded by StartTime.
- It runs only on Windows, only on a relaunch, and before any runtime exists. spawn(), hand_over and hook are unchanged.

## Tests
- Unit tests with a fake clock and probe. Two mutations, both caught.
- The Windows test waits on a 120 s condition deadline.

## Nits, for follow-up X-flake-portable-restart-2
1. A slow PowerShell start counts toward the 30 s. Add a "started" marker before the wait.
2. Under Constrained Language Mode, `$old.WaitForExit()` is probably blocked, so the wait is silently skipped. Use `Wait-Process -InputObject $old`.
3. Write a stderr line when the wait is skipped.
4. The decisions file should note that the Windows CI job takes about 30 s longer.
