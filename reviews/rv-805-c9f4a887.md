## Security review
- Auth works. `auth::protected` gives the session guard. `same_origin_json` covers CSRF: cross-origin is 403 and a form post is 415. API keys, Bearer tokens and `remote-user` get 401.
- The admin password is checked first: 428, 401, and the shared rate limit apply.
- The body is `deny_unknown_fields`, so a kill-switch field, a fallback field or a credential field gets 422.
- `check_egress` is shared with sources and behaves the same. `interface` and `bind_address` get 409. The binary also refuses them itself.
- Refusal messages name the field, never the value. The password is redacted in `Debug`.
- Concurrency holds. The `routing` lock plus `Manager::busy` serialises route changes, and a removal race restores the previous route. I found no bypass of egress or leak protection. The failure mode is fail-closed.
- The password refinement tightens a rule, and `restarting` instead of `applied` is more honest. None of the six refinements loosens an owner or security decision.
