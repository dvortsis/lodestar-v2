## Non-blocking findings

- **N1. Nothing in CI checks that the service's account can actually write the event** (`crates/lodestar/src/windows/service.rs:924-946`, `packaging/windows/main.wxs:168-179`).
  - The decisions file says that registering the source as a `CustomSource` is what lets `NT SERVICE\Lodestar` write through `eventcreate`. That is plausible:
    - the values match what `eventcreate` itself creates;
    - the Application log's default security grants write to SERVICE (S-1-5-6).
  - But I couldn't verify it here (learn.microsoft.com is blocked in this session). `smoke.ps1` only reads System/SCM events, so nothing confirms that the "Lodestar" event shows up.
  - The write is best effort, so a failure here costs only the message, never the start.
  - Suggest a follow-up for the runner, since `smoke.ps1` isn't owned: after a forced refusal, check `Get-WinEvent -FilterHashtable @{LogName='Application'; ProviderName='Lodestar'; Id=3}`.
- **N2. Nothing bounds the wait on `eventcreate`** (`service.rs:946`, `.status()`).
  - The doc comment says "a refusal never waits on this for long", but nothing enforces that.
  - The service has already reported Running and the stop handler ticks on its own thread, so a hung `eventcreate` would only delay the refused exit or the idle wait.
  - It's unlikely in practice. A spawn plus `try_wait` loop with a deadline of a few seconds would make the comment true.
- **N3. The list of invisible characters is incomplete** (`service.rs:202-207`).
  - `is_control()` plus the listed ranges cover C0/C1, ZWSP to RLM, LS/PS, LRE to RLO and LRI to PDI, and BOM.
  - They miss other Cf characters: U+00AD, U+061C (Arabic letter mark), U+180E, U+2060 to U+2064 and U+206A to U+206F.
  - None of these can break the line, and the folder is admin-controlled, so this is polish only.
- **N4. `docs/legal/README.md`'s phrase-table row lists fewer writer patterns than the test checks.** The row omits .NET `Diagnostics.EventLog` and `WriteEntry`, which `legal_facts.rs` checks and the decisions file names.
- **N5. The decisions file's heading has no PR number.** `docs/decisions/README.md` asks for `# <slice> decisions (#N)`, so it should read `# X-event-log-notice decisions (#702)`.
- **N6. Some changed files are outside the `runner/slices.yaml` `owns` list:**
  - `crates/api/src/auth.rs`: a test-only change;
  - `crates/api/src/dto/auth.rs`: the OpenAPI example;
  - `crates/api/tests/legal.rs`;
  - `web/src/lib/api/openapi.json` and `schema.d.ts`: regenerated;
  - the decisions file.

  The brief explicitly allows "whatever golden, test or e2e files change because of the version" and the decisions file, so these are in scope. The runner may want to add them to the slices.yaml entry for the record.

## Security notes

**Privacy: every interpolated string is traced back to its source.**
- **The NotPrivate message (event 3, ERROR):**
  - The `dir` is `default_data_dir(env ProgramData)`, which is `%ProgramData%\Lodestar`.
  - It never comes from the config. `load()` returns `Err` only from `secure()` on that default folder (`service.rs:879-903`), so the path named is the folder that was refused.
- **The RollingBack message (event 4, WARNING):**
  - The `dir` is the configured `data_dir`: the config file or `LODESTAR_DATA_DIR`, both admin-controlled.
  - It is a folder path, which the notice allows. If an admin puts the data folder under `C:\Users\<name>\…`, that name appears in a world-readable log. The notice covers it ("folder paths").
- **Everything else in the text is fixed:**
  - `temp_log::NAME` is a `const`;
  - the event type and ID are `const`.
- **Error text never reaches the event:**
  - No `io::Error` text, ACL reason, SID, account or `icacls` text goes into it.
  - `why` and `rollback_refusal()` go to the temp log only.
  - The `Result` of `Command::status()` is discarded, not formatted.
- **Log injection:**
  - Control characters become spaces, and bidi and zero-width characters are removed. Unit tests cover the newline and U+202E cases.
  - The folder is cut at 260 chars on a char boundary (`char_indices`, so no panic).
  - It is passed as one argv element: Rust quotes it, and a path can't contain `"`, so no other `eventcreate` option can be injected. The text starts with "Lodestar's", not `/`.
- **The process call:**
  - It uses an absolute `%SystemRoot%\System32\eventcreate.exe`, so there's no PATH search;
  - `CREATE_NO_WINDOW` is set;
  - stdin, stdout and stderr go to null.
  - `SystemRoot` comes from the service's own environment, set by the SCM.

**Windows API use and the start path:**
- It makes no FFI calls: `unsafe` is forbidden in the workspace and `eventcreate` is used instead, so there are no handles or UTF-16 buffers to manage.
- Nothing in the new path can panic: no unwraps, and the slicing is on a char boundary.
- An Event Log failure is ignored (`let _ =`), so it never changes the exit code or stops the service.
- Restart failure actions are bounded (two restarts, then none, reset daily), so a persistent refusal adds at most a few events a day.

**WiX:**
- The keys go in the right place: `HKLM\SYSTEM\CurrentControlSet\Services\EventLog\Application\{Lodestar, Lodestar update helper}`, with:
  - `EventMessageFile` (`REG_EXPAND_SZ`) `%SystemRoot%\System32\EventCreate.exe`;
  - `TypesSupported` 7;
  - `CustomSource` 1.
- Both keys are `ForceDeleteOnUninstall="yes"`, which WiX 3 supports, so they're removed on uninstall.
- Major upgrades are handled by component reference counting.
- The KeyPath is a new value under the existing `HKLM\Software\Lodestar`.
- It needs no elevation beyond the per-machine MSI's, and it adds no new custom actions.
- CI's "MSI and portable zip (windows x86_64)" job passed on this head.
