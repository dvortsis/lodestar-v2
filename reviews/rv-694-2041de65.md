## Findings

### Blocking
None, provided the runner ratifies finding 1.

### Important
1. **`crates/search/src/retry_dir.rs`: a file outside the owns** (the brief owns only `index.rs`'s seam).
   - This is a process finding, not a runtime risk. All additions are `#[cfg(test)]`, so production delete and mmap behaviour is unchanged.
   - What it adds: a 220-line fault-injection test in a production source file, plus a test-only field and branch on the concurrency-sensitive wrapper.
   - Failure scenario: none at runtime. A later slice that owns `retry_dir.rs`, such as a delete-retry change, collides with test code it didn't expect.
   - Fix: the runner ratifies it and adds it to the slice's owns. Or, to stay inside the owns, make `open_wrapped` generic over the wrapped `Directory` and put a `#[cfg(test)]` faulting wrapper and this test in `index.rs`'s tests.

### Nit
2. **`.github/workflows/ci.yml:344-346`: stale comment.** It says "Only Windows refuses to delete a mapped file, so only there does tantivy's collection fail and retry". The decisions file and the test's own doc (l.4-11) record that windows-latest deleted mapped files (0 survivors). Reword to say the job checks GC and leak behaviour on Windows, and the fault test covers the failed-delete path.
3. **`crates/search/tests/windows_gc_stress.rs:503-507`: the test never asserts that readers held any lease.**
   - It prints `taken` but doesn't check it. If a regression made readers stall or skip, for example `wait_past` returning `done` early, the run would pass without any map held across a merge.
   - Observed: 958-960 leases out of 960 possible, even under 4x parallel load.
   - Fix: `assert!(taken >= COMMITS as usize)` or similar, which costs nothing.
4. **`crates/search/src/index.rs:690-691`: garbled doc.** "with each delete the fault is given the whole path of failing". Suggested: "with each delete fails whose full path `fault` returns true for".
5. **`crates/search/tests/windows_gc_stress.rs:28`: an over-long doc line** (rustfmt doesn't wrap comments).
6. **`.github/workflows/ci.yml:349-360`: the job doesn't set `CARGO_PROFILE_TEST_DEBUG: line-tables-only`.** The `test` job sets it. It would shorten the 9.7 min cold build and shrink the cache. Optional.

## Checks against the brief
- **A real §11 test.** It goes through the public API (`SearchIndex::open`, `Indexer`, `Lease`, `search`) on a real `MmapDirectory` behind `Retrying`:
  - 240 commits; 4 reader threads, each holding up to 4 leases across 1-24 commits;
  - held leases are re-paged and must return the same answers;
  - exact corpus counts, and per-torrent findability during the run and after settling;
  - merges must land (fewer than 24 segments; 2 per index locally);
  - after settling, no files outside `meta.json`'s live segments;
  - the mmap gauge must equal the live non-empty files.
  The failed-delete path itself isn't forced on windows-latest, since NTFS deleted mapped files there. The deterministic `delete_faults` test covers it on every OS (runner's call, recorded in the decisions file).
- **Bounded, with no fixed sleeps.**
  - `wait_past` is a condvar wait with a 60 s deadline.
  - `settle` loops on a condition with a 60 s deadline and does no sleeping.
  - `read_meta` polls with 1 ms pauses inside a 60 s deadline, which is a condition poll and allowed (standards §2).
  - Every failure message says what it saw, and there are no timing assertions.
- **Flake resistance.**
  - `retired_on_disk` reads only names during concurrent merges, never metadata, so a racing delete can't make it panic.
  - `leaks` stats files only after `Indexer::finish`, when no merge is running.
  - Readers take a lease only after the writer publishes a commit, and commit reloads the reader first.
  - The upper bound on the corpus count is the maximum possible, so it can't trip.
  - 4 concurrent runs on a 4-core box all passed (15-16 s each).
- **Runs on every OS, with no `cfg` gate.** The workspace `test` job also runs it on Linux and Windows.
- **The CI job.**
  - It reuses `mmap_retention` applicability: `needs({"lodestar-bench"}, tested=True)` covers `lodestar-search` and its dependencies, plus `full-ci`, `main` and nightly.
  - It's in `ci-ok`'s `needs`. `ci-ok` fails only on `failure` or `cancelled`, so a skip passes, the same as `mmap-retention`.
  - `timeout-minutes: 30` against 12.5 min measured cold is fine.
- **The minisign line is correct shell under `set -euo pipefail`.**
  - The left side of `||` is exempt from `-e`.
  - `apt-get update ... || true` can't abort the group.
  - The group's status is the final install's, so a failed install still fails the step under `-e`.
  - A first attempt with no package list only prints an "Unable to locate" line before the fallback runs.

## Mutation results

- **A: production `Retrying::delete` returns `Ok(())` without deleting** (lost files, a leak). The stress test fails at `windows_gc_stress.rs:370`: "after 2450 settling commits: leaked [{...segment files...}]", after the 60 s deadline. **Caught.**
