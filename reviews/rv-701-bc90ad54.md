- N2 (important): the storage-warning absence test proves little. web/src/lib/features/wizard/WizardPage.test.ts:~296-306 waits for `systemCalls > 0`, which is true as soon as fetch is called, then yields one microtask before it checks absence. In the `null` case the warning is null anyway, and in the `fail` case it is never set, so the test passes whether or not the handler has run. It is not a fixed sleep, so it is not blocking. It would be stronger to wait on a settled flag, or to assert that an earlier non-null warning is cleared.
- N3 (polish): only the IPv6 netsh command is tested with fix fields (components.test.ts, "gives the netsh command…"). Add an IPv4 case that asserts `netsh int ipv4 set dynamicport tcp start=… num=…`, so a regression in the family branch at Exceptions.svelte:37 is caught.

Some screen readers do not announce a live region that arrives with its content already in it. The heading gets focus on step entry, so the user still reads the banner in order. Rendering an empty status region at mount and filling it later would make the announcement reliable.
- N5 (polish): Exceptions.svelte:145 reuses `m.settings_about_new_tab()`, a Settings > About key, inside Insights. It works because paraglide messages are global, but it couples two features. A common key, or Insights' own, would be cleaner. `detail_adult_enrichment_link_external` shows the per-feature pattern.

- N7 (note): the "Wizard steps (on demand)" size is 53.58 kB against a 53.6 kB limit, 20 bytes of headroom. It passes, but the next wizard slice will need the runner's OK to raise the limit.
