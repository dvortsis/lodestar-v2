## Nits
- **`horizon_tests.rs:21`, `wide(i)`:** `0x0B00_0000 + (i << 8)` overflows `u32` once `i ≥ 16,056,320` (0xF5_0000), and `i << 8` drops high bits once `i ≥ 2^24`. The CI test stays below that: about 8.6M addresses at 100 a second for 24 h. The ignored release measurement does not: 200 a second for 24 h, and both 60 h runs. It relies on release wrapping, so addresses come round again after about 23 h at 200 a second (into 0/8 to 10/8 first). At scale 1 that doesn't matter, because those cooldowns ended long before. At scale 8 a returning address may still be cooling and is just skipped, while the frontier refill keeps the rate up. The published numbers hold, as the arithmetic below confirms, but the helper panics if someone runs the measurement on a debug build. Use `checked_add`, `u64`, or a two-level address.
- **The brief asked for more than 24 h simulated** (">24 h"). `a_day_at_r17s_rate_never_reaches_the_fallback` runs exactly 24 h (`horizon_tests.rs:264`, `1..=hours * 3600`). The filter is level from hour 6, so this changes nothing in substance, but `hours = 25` would meet the brief literally at about 2 s more.
- **Authority labels:** `horizon_tests.rs:81` and `:256` say "owner's brief items …". Briefs come from the runner. Unless the owner wrote this one, say "the brief" (CLAUDE.md: say who decided).
- **`sampler.rs:970` doc:** `spill_used` reads live cooldowns "as of the last prune" but also counts each insert since then. `Spill::live_count`'s own doc says this correctly ("as of the last sweep and every insert since").
- **The hard line is tested only at the unit level.** `at_the_fallback_the_sampler_waits_and_nothing_ends_early` covers it, and removing the check makes that test fail (see mutations below). The sampler-level proptest `no_node_is_sampled_in_cooldown` can't reach `FALLBACK` (8M) with its 1-to-5-place tables. Safety doesn't depend on the line, so this is acceptable, but a `#[cfg(test)]` override of the line would let the proptest cover it.

- **No cooldown is shortened, and no node is treated as free.** The never-shorter invariant doesn't depend on the new counter at all:
  - `insert` stores only into a slot that `Spill::live` reads as not live (free, or ended and unswept).
  - `sweep` clears only slots that are not live. Both use the same `live(slot, first)` predicate as before.
  - `store` (`sampler.rs:1320`) is the only new writer. It is reached only from `insert`, which picks a non-live slot, and from `restore`, which always fills a fresh slot: `Spilled::words` yields blocks in ascending order and `fill` restarts per block, so the `old != 0` branch can't overwrite a live restored slot.
  - Nothing is evicted, so the brief's lost-record case never arises. `contains` and `shares` are unchanged.
- **The ageing arithmetic, checked for off-by-ones:**
  - `count_live(first)` sums `ends[(first + k) & 4095]` for `k in 0..2881`. `live(slot, first)` is `(m − first) mod 4096 < 2881`, so the two cover exactly the same minute set, including slots that alias as live through wraparound. The proptest and `scan_live` therefore compare like with like.
  - A slot with minute `m` is live iff `now < base + m min`. Since `m = ceil(until)`, it is live until `until` at least.
  - `ends[]` stays exact: +1 on store, −1 for the overwritten ended word, −1 on sweep clear.
  - `live` is exact after every sweep, and inserts only add to it, so it is never low. It can be high by at most the slots that ended since the last sweep, which is under a tick (`prune` sweeps every maintenance tick, `actor.rs:3093`). That errs in the safe direction.
  - `u32` counts can't overflow: at most 2^23 per minute.
- **Hard line (`sampler.rs:251`):** it is checked before each move inside `make_room`, so one tick's budget can't carry the filter past `FALLBACK`. When it refuses, the cooldown stays in the table and the caller admits no one:
  - `next` returns `None`.
  - `reserve` only reaches `make_room` when the address held no record, because taking its record would have freed a place. So no record is dropped on refusal.
  - With the split off, `make_room` returns before the check (`!self.split`), so that path is byte-for-byte unchanged.
