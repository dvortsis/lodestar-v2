## Check 2: the applied row's lifecycle

- **`applied` exists only while the provenance is `generated`.**
  - It's written atomically with `generated`.
  - It's deleted atomically with the switch back to `pasted`.
  - Forget deletes it with everything else.
- **It's read only on the `Held::Pending` paths,** so a stray row couldn't block a `pasted` or fresh flow anyway.
- **After a successful hand-over,** it stays with `origin`, where `not_added` refuses everything until forget clears it.
- **A `generated` state with no `applied` row** can't be reached through the endpoints. If a store edit made one, `target_changed` points to forget, which always clears it. So nothing can block a user for good (see N7 on the message).
