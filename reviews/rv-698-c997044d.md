## Non-blocking

- **N1. A zero-delay yield in a test.** At `NeedChip.test.ts:283`, `await new Promise((r) => setTimeout(r, 0))` lets the code that follows the re-read run before a negative assertion about focus.
  - It is a single event-loop turn after a `waitFor` condition, not a timed guess.
  - Everything it waits for is microtasks (load, then `tick`, then focus), so it is ordering-safe on a slow runner.
  - Mutation M6 (always focus) kills it.
  - I don't count it as a fixed sleep. A reader applying the rule literally might, and a comment already explains why it's there.
- **N2. The `here?.contains(at)` branch is untested and in practice unreachable** (`NeedChip.svelte:121`; mutation M11 survived).
  - After a successful install, SetupFlow calls `onclose()` first, which unmounts the dialog.
  - Then `done = true` replaces Set up with the "starting" badge.
  - So focus is always on `body` by the time of the check. The branch is harmless defence.
- **N3. The row's own lazy import of the chip still has no `{:catch}`** (`SourceRow.svelte:138`; carried over from e687ae6c, not in this delta).
  - Svelte 5.57's await block rethrows inside its rejection handler when it has no catch (`svelte/src/internal/client/dom/blocks/await.js:118-121`).
  - So a failed chip chunk becomes an unhandled rejection in the console, and the row says nothing about the need.
  - The decisions file records this as a first-view byte trade-off: 31.05 of 31.1 kB. Ten other `{#await import()}` sites in `web/` follow the same pattern.
  - An empty `{:catch}{/await}` would silence the console error for a few bytes, if there's room. It's acceptable as is.
- **N4. Copy for the failed load.** After an upgrade, a browser may cache the failed module fetch, so pressing Set up again can fail the same way. Reloading the page is what fixes it, but the sentence ("Couldn't reach Lodestar. Nothing was changed.") doesn't say that. It's honest and harmless, so this is optional.
- **N5. A flake outside this PR.** One full `npx vitest run` had one failure, in `src/lib/features/compare/Compare.test.ts` (a `/compare` post-count assertion). That file passed 48 of 48 on its own. This PR doesn't touch it, so it looks like a load flake.
