Review of dvortsis/lodestar-v2#704 (PK-guide-2), head ad9c5567b383e3baa7bd8121c9cd10540855b1a8. Docs only. I checked every fact against the code on this head and against tag v0.5.1. ## Blocking

**B1. The Linux witness folder is newer than v0.5.1 and has no mark.**
- Doc: `04-install-on-windows-and-linux.md:235` says "The service has a second private folder, `/var/lib/lodestar-witness`, for the restart record". `:247` lists it as kept data and deletes `/var/lib/private/lodestar-witness`.
- Code: the unit's `StateDirectory=lodestar lodestar-witness` and `Environment=LODESTAR_DHT_WITNESS_DIR=...` (`packaging/systemd/lodestar.service:18,21`) were added after the tag. In v0.5.1 the unit has `StateDirectory=lodestar` only (`git diff v0.5.1 -- packaging/systemd/lodestar.service`).
- `docs/operations.md:44` already says `LODESTAR_DHT_WITNESS_DIR` is "Development only; unavailable in v0.5.1".
- `dht.safe_restart` is off by default (`crates/lodestar/src/config.rs:221`), so even on main the folder is empty unless that is turned on.
- Effect: the chapter tells the reader to install the v0.5.1 tarball. That reader is told about a folder that doesn't exist, and `rm -r` prints "No such file or directory" for it.
- Fix:
  - Mark the `:235` sentence **(newer than v0.5.1)** and say the folder stays empty unless the restart proof is turned on.
  - At `:247`, split the removal: `/var/lib/private/lodestar` always, plus `/var/lib/private/lodestar-witness` on newer than v0.5.1. Or say that v0.5.1 has only the first.

**B2. The port-in-use symptom is wrong for the Windows service and misquoted for Linux.**
- Doc: `06-troubleshooting.md` new row 2 says "On Windows or Linux the service keeps stopping, and the log says `binding 0.0.0.0:8090` with 'address in use'".
- Code, Windows service:
  - The bind error is `format!("binding {addr}: {e}")` (`crates/lodestar/src/system/address.rs:532`).
  - The service path drops that text on purpose. `crates/lodestar/src/windows/service.rs:753-758` (`// Its message can name a path: the kind only.`) logs only `SERVICE_FAILED`, which is "service: stopped on an error" with `error=serve` (`crates/lodestar/src/logging/events.rs:740-746`).
  - So `lodestar.log` never contains `binding 0.0.0.0:8090`.
- Code, Linux and the portable ZIP:
  - `command_failed("serve", …)` (`crates/lodestar/src/main.rs:242,418-428`) prints `serve: binding 0.0.0.0:8090: <OS error>`.
  - On Linux the OS text is "Address already in use (os error 98)".
  - On Windows (portable console) it is "Only one usage of each socket address (protocol/network address/port) is normally permitted. (os error 10048)".
  - Neither contains the quoted "address in use".
- Fix:
  - Linux: the journal shows `serve: binding 0.0.0.0:8090: Address already in use`.
  - Windows service: `lodestar.log` shows `service: stopped on an error` (with `serve`), so check the port directly with `netstat -ano | findstr :8090`.
  - Portable ZIP: the console shows `binding 0.0.0.0:8090` with "Only one usage of each socket address".
  - The rest of the row (netstat and Get-Process, `ss -ltnp`, `systemctl edit` with `LODESTAR_HTTP_BIND`, which exists in v0.5.1 too) is correct.

**B3. On v0.5.1 the log has the port fix as a template, not "the same command".**
- Doc: `04-install-on-windows-and-linux.md:294` says "Lodestar also logs it at start, and on v0.5.1 the log is the only place, with the same command". The steps then say "Copy the command from the exception" (`:304`, `:308`).
- Code: on both v0.5.1 and main, the start-up log is the `windows.ports_low` event.
  - Its message holds the template `netsh int <family> set dynamicport tcp start=<fix_start> num=<fix_count>`, with the numbers only as fields `family`, `fix_start` and `fix_count`.
  - `fix_count=0` means there is no command (v0.5.1 `crates/lodestar/src/windows/ports.rs:254-263`, `crates/lodestar/src/logging/events.rs:630-636` on this head).
  - v0.5.1 has no `ephemeral_ports` exception (`git grep ephemeral_ports v0.5.1` finds nothing), so a v0.5.1 user has no exception to copy from. They are left to assemble a command that changes the whole PC's network settings.
- Fix: replace "with the same command" with one or two sentences:
  - On v0.5.1, find `windows.ports_low` in the log (the service's `C:\ProgramData\Lodestar\logs\lodestar.log` in an elevated PowerShell, or the portable console).
  - Replace `<family>`, `<fix_start>` and `<fix_count>` with that line's `family`, `fix_start` and `fix_count` values.
  - If `fix_count=0`, there is no command: lower the intensity instead.

## Non-blocking

- **N1. Uninstall leaves the installer's log folders behind (`:150`).** The Temp log folders `C:\Windows\Temp\lodestar-secure-<guid>` stay after uninstall. Each install, Repair and `REMOVE_DATA` uninstall makes one (`packaging/windows/secure-datadir.ps1:42-52`, `remove-datadir.ps1:15-24`). They are admin-only, so this isn't harmful. It's worth one clause in "what stays behind".
- **N2. The crash-restart wording is ambiguous (`:126`).** "It then waits a day before it will restart it again" reads as if Windows restarts it after a day. In fact `ThirdFailureActionType="none"` with `ResetPeriodInDays="1"` (`main.wxs:117-119`) means it stays stopped and the failure count resets after a day. Suggested: "After that it stays stopped; the count starts again after a day."
- **N3. "Adds your account permanently" (`:136`) overstates it.** On main, Repair removes the installing admin's own entry (owner §2.52, `secure-datadir.ps1:19-25`), and 6.2 says so. "Until you fix it as in section 6.2" is more accurate and less alarming.
- **N4. The Linux removal leaves dangling links (`:247`).** It leaves `/var/lib/lodestar` (and on main `/var/lib/lodestar-witness`) as links to the deleted private folders. This is harmless; optionally add `sudo rm /var/lib/lodestar`.
- **N5. The hourly re-check is newer than v0.5.1 (`:294`).** "It checks again about once an hour" applies only to newer versions: v0.5.1 checks once at start (v0.5.1 `ports.rs:1-6`). On v0.5.1 the warning only goes away after a restart.
- **N6. The data-folder move doesn't say to keep ownership (`:279`).** "Copy the whole data folder" doesn't say to keep ownership. On Unraid or Docker, a copy that loses the PUID/PGID owner breaks the start. Suggest `cp -a` or `rsync -a` and a link to section 2.3.
- **N7. The Peer socket limit is an advanced field (`:325`).** It is `.advanced()` with auto value 0 (`crates/lodestar/src/settings/crawler.rs:99-107`). A reader may need to show advanced settings, and "empty" shows as auto/0. On v0.5.1 the Settings labels come from the registry's label keys, and I could not confirm they read "Crawl intensity" or "Peer socket limit". This path is reached from the newer exception, so it's low risk.
- **N8. One v0.5.1 warning wording differs.** v0.5.1's network warning says "network filesystem", not "network or shared-folder filesystem" (v0.5.1 `fsdetect.rs`). This is cosmetic.
- **N9. The uninstall removes any exclusion on the data folder (`:150`).** It runs `Remove-MpPreference` for the data folder on every uninstall (`main.wxs:253-254`), whoever added the exclusion. "Any Defender exclusion the installer added" is slightly narrower than what happens. Cosmetic.
- **N10. Some Windows service failures leave nothing to fix from the log.** 06 new row 1 says "Otherwise fix what the log names". For a `serve` error, the Windows service log names only the kind (`service.rs:753-758`), so there may be nothing to act on. This is a code limitation, not a doc error. It could point to running `lodestar.exe serve` once by hand, but that is out of scope here.
