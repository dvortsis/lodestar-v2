## Nits
1. `crates/lodestar/src/system/restart.rs:449`: the `WATCH_SCRIPT_LIMIT` doc still calls it "the watch script's own bound on its `Wait-Process`". It is now the loop's deadline, measured from `$t0` (`ready`), and each `Wait-Process` gets only what is left. Suggested wording: "The watch script's own deadline, from its `ready`".
2. `restart.rs:762-769`: `timed_out` takes a fresh snapshot of the log when it builds the timeline. A `ready` that lands just after the no-`ready` cap fired then shows as `ready +60.0 s, no answer at +60.0 s`. This is cosmetic and arguably more informative, so no change is needed. Mentioned only so nobody reads that line as a bug.
3. `restart.rs:636-644` (pre-existing): the bounded reader splits a line longer than 64 bytes into 64-byte chunks. A tail that happens to be exactly `exited\n` would count as a word. The real script never writes long lines, and stderr goes to null, so this can't happen today. The `long` case in `the_watch_log_reads_status_after_started_only` asserts only `started`. No action needed for this PR.
4. `restart.rs:542-545` (pre-existing, fail-safe): there is a small gap between `& $gone` (false) and `Wait-Process -Id {old}`. If the old process exits and Windows hands its id to a new process inside that gap, the script waits on the new process. Rust's 30/60/90 s clock still ends the wait, so the worst outcome is a refusal, never a copy that starts while the old one runs. PID reuse within microseconds is negligible in practice.

## Verified
- **1. Constrained Language Mode safety** (`restart.rs:528-552`). Every new construct is a cmdlet, an operator, a variable or a script block:
  - the bare string literals `'started'`, `'ready'` and `'timeout'`;
  - `$t0 = Get-Date`;
  - the `$gone = { ... }` script block, called with `& $gone`;
  - `New-TimeSpan -Start $t0 | Select-Object -ExpandProperty TotalSeconds`;
  - the subtraction from a literal and `-lt 1`;
  - `while` / `break`;
  - `Wait-Process -Timeout $left`, where binding converts a double to an Int32 (core types, allowed under CLM);
  - `Start-Sleep -Milliseconds 250`;
  - `exit 3` / `exit 0`.

  There is no `::`, no `[type]`, no method call and no member access; the unit test asserts all of these at `restart.rs:1703-1708`. `$left` is at least 1 before it is bound, so the rounded `-Timeout` is at least 1 and at most 750, inside Wait-Process's range.

  `Wait-Process` reports its timeout and "not found" through `WriteError` (non-terminating), which `-ErrorAction SilentlyContinue` hides even under `$ErrorActionPreference = 'Stop'`. Every cmdlet used after `ready` comes from the Management or Utility module, and both are loaded by the time `ready` prints, so the claim that `ready` follows the cmdlet load holds. The Windows CLM test (`restart.rs:1746-1826`) runs the real script under CLM and expects `started`, `ready`, then `exited` in order. That run exercises `New-TimeSpan`, the arithmetic and the `-Timeout` conversion. CI's windows-latest job passed on this head.
- **2. The token stays out of the watch, the timeline and the logs.**
  - `watch_command` still calls `env_remove(MARKER)` (`restart.rs:564`; test at `:1726`).
  - The script takes only two PIDs and a number.
  - `watch_timeline` formats only `Instant` offsets and fixed words (`:699-722`).
  - `wait_if_successor` prints only the note and the refusal.
  - The Windows test still asserts `!shown.contains(&token)` (`windows_service.rs:881`).
  - The new timestamped dump adds jiff times and fixed step names only. The setup token was already on the console before this PR, and the hand-over token is never printed.
- **3. The state machine** (`restart.rs:741-825`, reader at `:625-666`):
  - **`ready` never arrives:** the wait ends 60 s after the hand-over (`wait * 2`, `:818`). Tested with `(None, 60)`.
  - **`ready` after the hand-over:** the wait ends 30 s after `ready`, through `ready.max(go)`. Tested at 0, 10 and 50 s. A `ready` at 70 s is too late: the 60 s cap fires first.
  - **`ready` before the hand-over:** the wait runs from the hand-over (tested: exactly 30 s).
  - **`ready` before `started`:** ignored. Only the first `ready` counts (reader test `:1627-1651`).
  - **Garbage lines:** ignored, though each one uses one of the 16 line slots.
  - **A line longer than the bound:** cut into 64-byte chunks; at most 16 × 64 bytes are ever buffered.
  - **The script dies early:** `try_wait` returns a non-success status, the 2 s drain runs, and the check is skipped. A script that says `exited` and then fails is also skipped (tested).
  - **Exit code 3:** wins over `exited`, both inside the drain (`:781`) and in the main path (`:797`), and over no line at all (tested at `:1414-1430`).
  - **Interleaved stderr:** not possible, because the watch's stderr is `Stdio::null()` (`:567`).
  - **Arithmetic:** all elapsed-time maths uses `saturating_duration_since`. `watch_timeline` branches on `t >= go` before it calls `duration_since`. `wait * 2` is a constant 60 s and cannot overflow. Production passes `Instant::now`, which is monotonic (`windows/mod.rs:303,312`).
- **4. `WATCH_SCRIPT_LIMIT` = 750 s (`:457-461`).**
  - The script starts before `await_handover`, so the hand-over (`go`) comes at most `GO_LIMIT` + `EXIT_LIMIT` = 660 s after the script's start, which is no later than `ready`'s.
  - Rust gives up by `max(ready, go) + 30` s, and never later than `go + 90` s.
  - The script's own deadline is `ready + 750 s`. Whichever of `ready` and `go` comes later, that is always after Rust's deadline: the script can't say `timeout` before Rust would.
  - `wait_if_successor` kills the watch once the wait ends, so a script that runs longer does no harm.
  - 750 is far under Wait-Process's 32,767 s limit. The unit test asserts both bounds (`:1665-1673`).
- **5. The reused-PID check.** `$gone` (`:537-540`) is true when no process has the id, or when the process holding it started after this copy. It is checked before the first `Wait-Process` and after each one. `exited` prints only once `$gone` is true. Its meaning matches the -2 script: `-not ($since -gt $me)` meant "wait", and the check ran again after the wait. A test pins exactly one `-gt $me` and one `Get-Process -Id <old>`.
- **The condition on (c): nothing runs serving before `wait_if_successor` returns.** `windows/mod.rs` is untouched. `main` calls `windows::hook()` before `cli::parse()` (`main.rs:71`), and `hook` calls `wait_if_successor` before anything else except `record_program` (`windows/mod.rs:37-42`). This diff changes only pure functions in `restart.rs` and the test file. Both guards hold:
  - **The search index lock:** `lock_root` (`crates/search/src/rebuild.rs:557-580`) takes tantivy's non-blocking exclusive lock, which ends in `try_lock_exclusive` (`LockFileEx` on Windows). It retries for `LOCK_WAIT` = 10 s, then fails with `Error::Locked`.
  - **The HTTP port:** the bind (`system/address.rs:530`) is a tokio `TcpListener::bind`. mio 1.2.4 sets `SO_REUSEADDR` only under `cfg(not(windows))` (`mio/src/net/tcp/listener.rs:81-82`), so on Windows a port the old process still holds fails the bind.
- **6. Tests.**
  - Each new behaviour has a unit test: the wait from `ready`, `exited` believed before the watch ends, exit code 3's precedence, the timeline text, the reader's stamps, and the script's text and order.
  - **The claimed mutations are credible.** I ran 4 locally and each failed the restart tests (`25 passed; 1 failed` each time):
    - M1: the clock back on `started` (`ready.max(go)` → `started.max(go)`);
    - M2: exit code 3 no longer winning inside the `exited` drain (arm at `:781` removed);
    - M3: the no-`ready` cap at three times `wait` instead of twice;
    - M4: `exited` needing the watch's end (the post-drain `Ok(None)` → skipped).
  - **No fixed sleeps.** The `await_watch` tests use the `Fake` clock and sleep. `settled` and the reader loops use real deadlines of 10 s. The Windows tests use `recv_timeout` of 30–60 s and the existing `wait_for` (a condition poll with a deadline). There is no tokio `test-util`.
- **7. Scope and docs.** The diff touches exactly the three owned files. The decisions file and the PR body match the code, apart from Nit 1.
