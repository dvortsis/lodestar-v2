## Blocking

**B1. `infra/fleet/deployment_policy.py:124` refuses every real GitHub OIDC token, so none of the live roles can be assumed. That includes the new emergency teardown.**
`require_token_claims` raises when `"job_workflow_ref" in claims`. GitHub puts `job_workflow_ref` (and `job_workflow_sha`) on every Actions OIDC token. For a direct workflow, `job_workflow_ref` equals `workflow_ref`. Sigstore/Fulcio's "Build Signer URI" is taken from this claim for ordinary non-reusable workflows, which is good evidence that the claim is always present. The docs say it is "reusable-only" (`build_templates.py:53`, `fleet-control-bootstrap.md:7`, `infra/aws/fleet-control/README.md:17`). That is GitHub's description of what the claim means, not a statement that the claim is absent from direct-workflow tokens.

Failure path: `oidc_session` calls `require_token_claims` before STS (`apply.py`, after the JWT fetch). If the claim is always present, then `cloud-fleet`, `pia-delivery`, `cloud-operator` and `fleet-cleanup` all stop with "issued OIDC claims do not match". The owner's emergency path (`fleet-emergency-down.yml` → `emergency_cleanup.py`) replaces the removed `dispatch-down` and the reaper, so the PR's only GitHub teardown path would never work. It fails closed, but it is the kill path. `test_deployment_policy.py:190-193` asserts the wrong behaviour.

I could not check a live token, because the rules forbid network or JWT calls. The fix is correct whether or not the claim is present:
- Replace the clause with `claims.get("job_workflow_ref", env["GITHUB_WORKFLOW_REF"]) != env["GITHUB_WORKFLOW_REF"]`. This is stricter: it proves the job is not a reusable workflow.
- Add a positive test where the claim is present and equal, and a negative test where it differs.
- Correct the "reusable-only" wording in the docs.

**B2. `docs/operations/2026-11-10-fleet-backend-investigation.md:5` records a local time zone and place ("<a local IANA zone>").**
This breaks owner decision `docs/owner-decisions.md` §2.35 and CLAUDE.md ("New times in docs and records are UTC (Z). Never write a local time zone, offset or place"). The file is new, so the exception for old files doesn't apply. It also publishes the owner's location in a public repo. It's a one-line fix, for example "2026-11-10 to 2026-11-11 (UTC)". The owner may waive it, but under `runner/standards.md` it is a spec violation.
