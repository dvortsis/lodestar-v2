## Deviation judgment (item 2)
- **Right; accept it.** `torrent_claims` cascades with `torrents`, so an UPDATE that matches nothing at unverified.rs:1195 can only be a stored torrent with no `torrent_parsed` row yet. The backfill does select that torrent (`unenriched()`: `parser_ver IS NULL`), and a batch may already have read the purged claim.
- **The bump condition is correct.** The generation moves whenever a shaping claim, or a claim that doesn't decode, was actually deleted (unverified.rs:1191-1207). It doesn't move when only plain claims were deleted. So there is no needless bump, and there is a bump in every case that needs one.
- **The race is closed in every case, including a purge that deletes a shaping claim but marks no torrent.** Every guarded reader reads `class_gen` first, then rows and claims, then writes under `set_enrichments_at` (`enrich_stored_marking`, `adult_by_source`, `apply_matches`, `core_rejudge`, filters correction, and the writer's `stale_class`). A purge that commits after that first read is refused. One that commits before it is invisible to the read.
