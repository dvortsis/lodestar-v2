## Security (/security-review)
I found no exploitable issue.
- **Withheld rule (B13).** Both lookups apply `discover::shown(…, adult)` in the index before the window is taken. Every candidate then goes through `withheld(row, e, false, adult)` on the stored state before its tree is read (`compare.rs:565`).
  - The reference keeps `visible(.., hidden_ok=true, adult)`, as `other_versions` does. An Adult reference while Adult is hidden is a 404 that leaks no names (tested).
  - `truncated` and `same_file_capped` are computed only from confirmed visible hits. `*_partial` depends only on index state. No flag carries information about withheld torrents. `withheld_sharers_leave_no_trace` pins the window ordering: more than 1,000 withheld sharers, none of them in the response.
- **Untrusted input.** The only request input is the path hash, through the existing `parse_hash`. The signature and the (size, root) pairs come from the reference's stored tree, never from query text. `Node::Sig` is built from `sig_hex`.
  - The file-set cache key `pieces_root:<hash>:<n>` can't collide with user clause keys, which are `format!("{node:?}")`.
  - A hash collision on the cache key would only change candidates, and the stored-tree confirmation then drops them.
- **Bounds.**
  - At most 64 roots, each a file of at least 1 MiB.
  - At most 200 payload candidates and 1,000 same-file candidates. `TopIds` keeps the heap at the limit.
  - At most 21 confirmed hits before the loop stops.
  - One decoded tree at a time, under the reader lock per candidate. Payload candidates skip the tree decode unless the row's count and total match.
  - The token is checked before each search, during collection (and a stopped collection never returns its partial ids) and before each candidate.
- **Visibility elsewhere.** No change to what is visible elsewhere: the search crate only gains new functions, plus `TopIds` made `pub(crate)`. No new route, no logging of data, no new network egress, and CSP isn't touched.
- **Signature collisions.** The payload hash (fmix64 chain) is invertible and easy to collide on purpose. The size confirmation (`same_payload`) is what makes this safe, and it is tested by `a_signature_collision_is_never_confirmed`. The worst a crafted collision can do is cost up to 200 tree decodes for one request, which can be cancelled at each candidate.

## Important
- **I1. The stored-state withheld check in the new groups is untested** (`crates/api/src/compare.rs:565`). Mutation check: I replaced `withheld(&row, e.as_ref(), false, adult) || !pre(&row)` with `!pre(&row)`, and all 9 `siblings_payload` tests and the lib tests still pass.
  - The reason: every fixture sets HIDDEN and Adult before indexing, so the index's `shown()` already removes them.
  - The decisions file says candidates are dropped by the stored state "whatever the index says", and that is the defence for an index lagging a reclassification. As things stand, a refactor could remove it silently.
  - The fix is cheap: in the existing lib-test pattern (`a_signature_collision_is_never_confirmed`), pass `confirmed` a forged candidate list that includes a HIDDEN `Entry` and an Adult `Entry` from `corpus(..)`, and assert that both are dropped with `adult=false` and the Adult one kept with `adult=true`. `other_versions` has the same gap today; this is not this PR's.
  - Recommend fixing in this PR.
- **I2. The `same_file_capped` contract doc doesn't match the behaviour** (`crates/api/src/dto/compare.rs:36-39`, and so `openapi.json` and `schema.d.ts`).
  - The doc says the flag is true when "only this torrent's largest files were looked up … or more torrents shared them than were read".
  - The code (`compare.rs:264`, the runner's rule) sets it only when `same_file` already holds `MAX_SIBLINGS` hits. A 200-file v2 pack with 3 same-file hits gets `false`, although only 64 of its files were looked up.
  - GS-4, which will word this in the drawer, inherits the doc. Add "only once the list is full" to the doc and regenerate.
  - Separately, for the runner: the root cap (`Roots::Some { capped }`) is a fact about the reference's own file list, which the viewer can already see. Reporting it on its own reveals nothing about withheld torrents. Gating it on a full list means brief requirement 3's "cap the files considered and say so" is said only for torrents with 20 or more hits. Only `more` needs the gate, if anything does.
