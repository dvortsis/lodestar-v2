# C1: Palette table for the 24 theme families
**Model:** Opus (docs only). **Branch:** `slice/C1`. **Spec:** architecture §10.18 (theme collection, schema, gates).

Write `docs/themes.md`:
- **Per family, light and dark** (Riverstone included, for reference): `background`, `surface`, `text`, `primary`, `accent` and 6 `categorical`, in Riverstone's schema, as hex.
- **Community-inspired families** (Nord, Solarized, Gruvbox, Catppuccin, Rosé Pine, Tokyo Night, Everforest, Kanagawa, Dracula, One, Ayu): take values from each project's published palette. Cite the source URL and licence, and credit the authors. Choose categorical slots that keep pairwise ΔE_ok ≥ 5 where the palette allows; note where it doesn't.
- **Accessibility families** (High Contrast AAA, Okabe-Ito, Paper & Ink) and **Originals** (Tidewater, Sandstone, Moss, Ember, Lavender Field, Graphite, Sepia, Midnight OLED / Daylight): design the values to the descriptions in §10.18.
- **For each value set,** state the contrast of text on background and on surface. Flag any that will fail the compiler's gates.

A Haiku session (W1b) turns this table mechanically into `web/themes/*.json`, so keep one table per family in a consistent, parseable layout. Use one fenced YAML block per family with keys `light` and `dark`.

**Done when:** all 24 families × 2 modes are present, every value is a 6-digit hex, and sources and licences are listed.
