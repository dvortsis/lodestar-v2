## Build
One file per client in `src/clients/`, each with a `ClientKind` value, a `ClientConfig` variant and a `connect` arm.
1. **Transmission** (RPC over HTTP POST, JSON):
   - the `X-Transmission-Session-Id` handshake: a 409 carries a new id; retry once with it, never in a loop;
   - optional basic auth (credentials as `Secret`s, header marked sensitive);
   - `torrent-add` with `filename` (magnet) or `metainfo` (base64 .torrent), plus `paused`, `download-dir` and `labels` (RPC ≥ 16; check `rpc-version` from `session-get` and fall back without labels on older versions);
   - file selection with `files-unwanted` through `torrent-set`, following the README's add-paused, wait, deselect, start flow;
   - `torrent-duplicate` maps to `Rejected`;
   - `categories` returns labels only if the client has a source for them; otherwise `Unsupported`, with honest `Capabilities`.
2. **Deluge** (Web UI JSON-RPC at `/json`):
   - `auth.login`, then `web.connected` / `web.get_hosts` / `web.connect` to the first daemon if the Web UI isn't connected; cookie session as in the reference;
   - `core.add_torrent_magnet` and `core.add_torrent_file` with options (`add_paused`, `download_location`), `label.set_torrent` when the Label plugin is enabled (`core.get_enabled_plugins`), `core.set_torrent_options` with `file_priorities` for selection;
   - JSON-RPC errors map onto `ClientError`;
   - request ids are numbers you control; ignore any mismatched id.
3. **rTorrent / ruTorrent:**
   - rTorrent's **XML-RPC** over HTTP (SCGI through a web server's `/RPC2`), and ruTorrent's `httprpc` plugin (`/plugins/httprpc/action.php`) where it simplifies things. Pick one primary path, say why in §16, and implement it well.
   - `load.start`/`load.normal` (+ `load.raw_start` for .torrent bytes), `d.custom1.set` for the ruTorrent label, `d.directory.set`, `f.priority.set` + `d.update_priorities` for selection.
   - **XML parsing of untrusted input:** use `quick-xml`, the one new dependency approved for this slice. Pin it exactly at the current release, with `default-features = false`. Parse only the XML-RPC value subset you need, with a depth limit and a size limit (`read_limited`). No DTD or entity expansion: refuse any `<!DOCTYPE`. `<fault>` maps onto `Rejected`/`Auth` as appropriate. Add property tests: arbitrary bytes never panic, and nesting deeper than the limit is refused.
4. **Aria2** (JSON-RPC over HTTP at `/jsonrpc`):
   - the `token:<secret>` first parameter as a `Secret`, never logged;
   - `aria2.addUri` (magnet) and `aria2.addTorrent` (base64), with options `dir`, `pause`, `select-file` (1-based) for selection, applied at add time, so selection doesn't need the paused flow;
   - no categories: `Unsupported`.

## Tests (each client)
- Recorded fixtures in `tests/fixtures/<client>/`. **Record from the real client wherever you can install it in your session** (`apt-get install transmission-daemon deluged deluge-web rtorrent aria2`, or pip/tarballs). Record method and path only, never request bodies, as in the README. Where you can't run a client, build fixtures from its documented protocol, and say which and why in the PR and in each fixture's `recorded_from`.
- Cover: login ok/failed, session expiry with one re-auth, add magnet/file ok, duplicate, client refusal, selection (including `Pending`), oversized, truncated and HTML answers, and an unknown-method or version answer.
- Run the reference **no-leak test** pattern for each client: a TRACE subscriber over a full flow, asserting the password, token, session id and cookie appear in no log, `Debug` or error text.
- Unit tests for each parser; property tests for the XML-RPC parser.
