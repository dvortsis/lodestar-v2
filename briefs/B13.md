## Build
1. **`GET /torrents/{hash}/siblings`** ("Related", §10.5). Three groups, each with typed hit rows (the same row DTO search returns) and a reason:
   - **Other versions:** torrents with the same parsed title identity: normalized title plus year, and season/episode where present. Excludes the torrent itself, capped (e.g. 20), ordered by the search ranking's priors.
     - Define "same title identity" precisely in §16. Use the index's title field and an exact-term match, not a fuzzy search.
     - Clean the parsed title with the same normalisation search uses.
   - **Identical-payload clones** and **same file elsewhere:** these need `payload_sig` and per-file `pieces_root`, which arrive in M7 (§8, schema bump #2). Return the groups as `unavailable` with a reason (never empty-as-zero), typed now.
   - Must respect hidden torrents and Adult visibility. An unknown hash gives a 404 envelope.
2. **Batch detail for Compare: `POST /compare`** with 2–5 hashes (more is a 400 with `field`). It returns:
   - per torrent: the detail DTO fields Compare needs (name, effective title, parsed attributes, size, files, seeders/trackers/discovered where present, composition);
   - a `differs` map: for each parsed attribute, whether the values differ across the set, computed on the server. The client never computes it.
   - **composition on a shared scale:** the max total bytes, so the bars align;
   - **a file-list diff:** files only in each, and common files. Match by path plus size. Bounded: cap each list (e.g. 2,000 entries) with a `truncated` flag. Torrents with huge file lists must not blow memory: stream from the stored file-tree blobs.
   - A hash that's hidden, or Adult while hidden, is treated like an unknown hash. Say which in §16. Don't leak its name.
3. **`GET /discover`:**
   - **`newest`:** the newest searchable torrents, optionally per content-type tab (`?type=`), using the result-row DTO, paged by a B5a cursor.
   - **`rising`:** needs M4's swarm history (#48, not merged). Typed now and returned as `unavailable` with a reason until swarm fields exist. Leave a TODO naming the M4 continuation.
   - **`recently_resolved`:** ambiguous torrents whose resolution changed recently. Use what the store records (`resolved_via`, enrichment timestamps, `reindex_log`). If the store can't tell "recently resolved" without a migration, return `unavailable` and say in the PR what B8 (the M5 migration) should add.
   - Every section respects hidden torrents and Adult visibility (§20.9: excluded entirely).
4. **Contract:** typed DTOs registered in OpenAPI; the error envelope; the drift job passes.

## Tests
- Siblings: other versions found across title variants of the same work; different years and seasons are kept apart; self is excluded; the hidden and Adult-hidden cases; an unknown hash gives 404.
- Compare: 2 and 5 hashes; 1 and 6 hashes give 400; `differs` is correct; the shared scale; the file diff on the fixture trees, including truncation; a huge tree stays bounded; a hidden hash.
- Discover: newest is ordered and paged; the type tab; the shape of unavailable sections; Adult excluded when hidden.
- API goldens; unauthenticated gives 401.
