## Build
1. **Data: one call, `POST /compare` (`compareTorrents`), body `CompareRequest { hashes }`** in the order of `?h=`. `CompareResponse`:
   - `torrents: CompareTorrent[]` (request order): `hash`, `name`, `title` (null = not resolved), `content_type` (null = not classified), `size`, `files`, `seeders`, `leechers`, `trackers_reporting`, `trackers_checked` (each null = never scraped), `discovered_at`, `composition: CompositionShare[] { group, bytes, files, pct_bytes, pct_files }` (empty before classification), `attributes: { [key]: string | null }` (every key in `differs`; lists comma-joined).
   - `differs: { [key]: boolean }`, `scale_bytes` (the largest `size`), `file_diff: FileDiff { common: FileList, only: FileList[] }` with `FileList { count, files: DiffFile { path, size }[], truncated }`.
   - **Everything comparative comes from the server.** `differs` decides which rows say "differs"; never compare values yourself, and never mark a difference on size, files, seeders, trackers or discovered (the server doesn't, and §10.6 marks only parsed attributes). The bars use `scale_bytes` as CategoryBar's `max`. **Removing a column re-requests** with the remaining hashes: `differs`, `scale_bytes` and the diff all change, and the client must not recompute them.
   - Use a `latest()` slot keyed by the `h` list; ignore `isAbort` errors. **Missing from the backend, don't fake:** `CompareTorrent` has no `magnet`, no `flags` (so no backfill marker), no `seeders_approx` (even after #48) and no `last_scrape_at`. Show what exists; list each as a follow-up for B13's owner. Never add a local type for a missing field.
2. **URL state (§10.3):** `/compare?h=<hash>,<hash>[,…]`, the column order. Keep any other parameter (`density`) when you rewrite it. Removing a column pushes a history entry (Back restores it) with `goto(…, { keepFocus: true, noScroll: true })`. Fewer than two hashes sends no request: show the "choose" state. Don't validate hashes in the client beyond splitting on commas and dropping empties; the server answers bad ones.
3. **States, each designed (§10.4's table is the model):**
   - **Loading:** a skeleton at the final layout's heights (columns or list, whichever the width gives), `aria-busy` on the region; no skeleton flash for answers under 300 ms.
   - **Choose (fewer than 2):** EmptyState with one next step: "Select 2 to 5 torrents in Search, then choose Compare" and a link to `/search`; the illustration is `StateScene` id `empty_state_explore` from `$lib/shell/StateScene.svelte`.
   - **Error, by `ApiError.code`:** `compare_count` (2–5), `duplicate_hash`, `bad_hash` (all `field: "hashes"`): say what's wrong and offer the hash list with a Remove button each (the same column controls), so the user can fix the URL without typing it; `torrent_not_found` (404): "One of these torrents isn't available. It may have been removed or hidden." The server names nothing, so don't guess which; offer the same Remove list and "Back to Search". `network` and 5xx: Banner (what happened + Retry), keeping the last good comparison visible if there was one (**stale** state).
   - **Partial values:** `title` null → the raw name is the heading; `content_type` null → `—` (accessible name "Not classified"); swarm fields null → `—` (accessible name "Never scraped"); an attribute null in one column → `—`; empty `composition` → "Not classified yet" in place of the bar; no attributes at all → one line saying the torrents have no parsed attributes.
   - **Truncated diff lists:** a heading with the server's `count` ("Only in B · 12,345 files") and, when `truncated`, "List shortened: open the torrent to see every file" with the `/t/<hash>` link. Don't print `files.length`.
4. **Columns layout (from `x-large`, 1024 px):** a real `<table>`: a `<caption>` (visually hidden), one `<th scope="col">` per torrent (resolved title, raw name in Mono `text-small` beneath when it differs, a letter badge A–E used again in the diff and the narrow view), `<th scope="row">` per attribute. Rows in story order: Type, then the parsed attributes in a fixed order you set in a constant (`title`, `year`, `season`, `episode`, `absolute`, `date`, `res`, `source`, `vcodec`, `acodec`, `channels`, `bits`, `hdr`, `lang`, `subs`, `container`, `edition`, `group`, `service`, `pack`, `artist`, `album`, `author`, `alt`, `bitrate`, `flags`; any key not in the list afterwards, by key), then Size, Files, Seeders / Leechers, Trackers reporting, Discovered, Composition. A row whose `differs[key]` is true gets an icon (Phosphor, `aria-hidden`) **and** the visible word "differs" in its row header. Names and values wrap; nothing is cut to an ellipsis-only.
   - **Composition:** one `CategoryBar` per column with `max={scale_bytes}`, `segments` from `composition` (`value: bytes`, `label` per group), `summary` composed from every share ("82% video, 11% audio" via `formatShare(pct_bytes)` and the group labels), `dominant` = the share with the highest `pct_bytes` (ties: bar order). Pair the row with a `DataTableAlternative` (sr-only) built from the same formatted strings.
5. **Per-column actions** (plain buttons, no Menu, so Bits UI stays out of the route's chunk): **Open** (link to `/t/<hash>`), **Copy magnet**, **Remove from comparison** (accessible names include the torrent: "Copy magnet for …").
   - Copy magnet uses the server's `magnet` from `GET /torrents/{hash}` (`getTorrent`), fetched when the column's actions get hover or focus (§10.1's prefetch idea) and otherwise on press; never build a magnet yourself (the server may append trackers, §9). Write it with `navigator.clipboard.writeText` where available. On a plain-HTTP LAN address (no secure context, the common self-hosted case) the Clipboard API is missing: fall back to a hidden-textarea copy, and if that fails too show the magnet in a selected read-only Mono field with "Press Ctrl+C to copy" (⌘C on a Mac). Toast the outcome (`toast.push`). Keep this helper in your folder; S-detail builds its own Copy magnet now, and the runner promotes one to `lib/` after both exist (§10.11's "two places" rule). Say so in the PR.
   - After Remove, focus moves to the next column's first action (or the previous one's, or the page heading).
6. **Narrow widths (below `x-large`): the attribute-first list.** Not the table squeezed: one section per attribute (`<h2>`/`<h3>` per §10.13's heading order, or a `<dl>`), each listing "A · <short name> → value" per torrent; the "differs" marker on the attribute's heading; the composition bars stacked per torrent on the same `scale_bytes`; the actions grouped per torrent at the top as a short list of the torrents (letter, name, Open/Copy/Remove). The file diff keeps its sections. Only one layout is in the DOM at a time.
   - **CSS budget (read this):** Tailwind's CSS is global and is counted against the search route's **20 KB, now 19.82 KB** (W9 decisions). Every utility class you add that isn't already in `build/_app/immutable/assets/*.css` grows it. Reuse existing utilities; put this screen's own layout in the component's `<style>` block, which ships in the route's own CSS chunk. Verified on main: `<style>` with `@reference '../../app.css';` (path relative to the file) and `@variant x-large { … }` inside a rule compiles to `@media (width>=1024px)` in the route chunk and leaves the search CSS at 19.82 KB. In `<style>` use only tokens (`var(--color-…)`, `calc(var(--spacing) * n)` with `n` on the ramp, `var(--radius-…)`); no px literals, no hex.
7. **File-list diff (after the attributes):** with 2 torrents, three sections "Only in A", "Only in B", "In both"; with 3–5, "Only in <letter>" per torrent plus "In all", and one line saying files that some but not all have aren't listed (the server's rule). Sections are disclosures, collapsed by default, headed with the server's `count` (`formatCount`); each row is the path in Mono (wrapping) and the size (`formatBytes`, right-aligned, tabular). Above about 200 rows use `VirtualList` (`web/src/lib/ui/lists`) so 2,000-entry lists scroll smoothly; otherwise a plain `<ul>`.
8. **Keyboard and accessibility (§10.13, WCAG 2.2 AA):** everything reachable by Tab in reading order; visible focus; 44 px targets under `pointer: coarse` (the primitives do this); landmarks and one `<h1>` ("Compare"); the column count in the caption; status and differences as icon + text, never colour alone; composition with its text summary and dominant-share text; no single-key shortcuts of your own (none are in §10.16 for this screen; register nothing). **The `routes.keyboard.test.ts` edit (step "Own"):** in `web/e2e/routes.keyboard.test.ts` change the fixture list `page,\n\t\tgo,\n\t\tkbd\n\t}) => {` to `page,\n\t\tgo,\n\t\tkbd,\n\t\tmock\n\t}) => {` and insert `\t\troute.mock?.(mock);` as the first line of the body, before `await go(route.path);`.
9. **Budgets (§10.1):**
   - **Don't move the search route's numbers.** `npx size-limit` must still pass: Search route JS 39.43 of 45 KB, **CSS 19.82 of 20 KB**, total first load 81.9 of 100 KB on main. Lighthouse on `/search` (`npm run lhci`, `CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome`) has about **0.5 KB of its 102,400-byte total-byte-weight left**: Svelte runtime features a lazy route uses land in the chunk every page loads (W9 decisions), so avoid `svelte/transition`, `svelte/animate` and other runtime extras, run `lhci` before and after, and report both numbers.
   - **Route entries you add to `.size-limit.mjs`:** a helper `own(route)` returning `routeFiles(route)`'s JS and CSS minus the search route's, and four entries `entry('<Route> route (own JS + CSS)', [...js, ...css], '15 KB')` for `/compare`, `/discover`, `/alerts`, `/alerts/[id]` (the route ids as SvelteKit names them). 15 KB matches the detail drawer's budget; it is a proposal for the runner to confirm (§2.19, not an owner number), so say so in the PR. Lazy chunks (dynamic `import()`) don't count; keep it that way for anything heavy.
   - LCP/CLS: no Lighthouse URL exists for this route (`lighthouserc.json` is shared and runs `/search`); keep CLS at 0 by giving skeletons the final heights.
10. **Formatters only from `$lib/format`:** `formatBytes` (size, file sizes), `formatCount` (files, seeders, leechers, each side of `n / m`, diff counts), `formatShare` (composition), `formatDateTime` for Discovered (absolute: Compare is exact lookup, §10.12; add the `RelativeTime` primitive only if you also keep the absolute text visible). Pass `currentLocale()`. Every number on screen has a `data-testid` (`compare-size-<i>`, `compare-seeders-<i>`, `compare-diff-only-<i>-count`, `compare-diff-common-count`, …). **Tokens only:** no hex, no arbitrary values, spacing on the ramp.

Glossary terms come from the shared keys (`m.seeders()`, `m.trackers_reporting()`, `m.discovered()`, `m.raw_name()`, `m.composition()`, `m.content_type()`, `m.video()`, …). **Missing shared keys:** the group labels `images`, `documents`, `archives` (the shared file has only the singular categories), the content-type value labels (Movie, TV, …) and `dominant_share` (`docs/metrics.md` §3).
