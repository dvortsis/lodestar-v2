## Build
1. **Inputs, and nothing else.** A digest is one call to `insights::overview_response(state, query)` with `range=24h` (daily) or `range=7d` (weekly) and `compare=1`, so every number, Δ, conversion, share and percentile is the server's own, under the request's "Show adult content" (the builder applies it). Movers come from `segment_movers(&r.segments, &previous.segments, 3)` when `r.previous` is present. **No arithmetic on counts** beyond picking and formatting: no sums, rates, Δs or re-reads of the store. A field that is `null` renders as `—` (yield with no final cohort: "No completed cohorts yet", `docs/metrics.md` §6.2).
2. **Content, in this order (§10.9.7):**
   - **Subject** (≤ 120 characters): `Lodestar daily digest: <date>` or `Lodestar weekly digest: <from> – <to>`, dates `formatDate`-style in UTC.
   - **Context line:** the period, "UTC" (the server has no time-zone database; the user's `preferences.time_zone` comes with the sender follow-up), and the generation time.
   - **The five KPIs** (§6.2 labels): Searchable torrents, New searchable, Yield, Time to searchable (`≈` p50 and p95), Health (state and reason as text). Each with its Δ from the response and the period text ("vs previous 7 days"); a null Δ prints nothing. Direction is the sign plus `▲`/`▼`, never colour.
   - **Funnel summary** (`funnel_total`): Harvested `≈` → Peer found → Metadata fetched → Stored → Searchable, each count with its conversion; how many cohorts are final; the top three loss reasons by `loss_share` with their names from §6.4.
   - **Top 3 segment movers:** key, Δ and the segment's name ("by group", "by content type"); omitted when there are none.
   - **Open exceptions** (`exceptions[]`): one line each from a fixed phrase per known `kind` (`index_lag`, `cohort_stalled`, and B11b's), its `value` in the metric's formatter and `unit`; an unknown kind prints a generic "Needs attention" line with the kind as escaped text.
   - **Links back:** `/insights?range=<r>&compare=1`; an exception's `fix` as `/insights/<target>` (`stage`) or `/settings/<target>` (`settings`), **only when `target` matches `^[a-z_]{1,32}$`**, else no link. Links are root-relative paths: there's no configured public address yet, so the sender follow-up makes them absolute.
3. **Rendering** (`pub fn render(o: &OverviewResponse, period: DigestPeriod, now: i64) -> Digest { subject, text, html }`, pure, no I/O):
   - **Formatters:** private Rust versions of `formatCount`, `formatPercent` (f = 1, with the `<0.1%`/`>99.9%` edges), `formatDelta` (U+2212 minus), `formatSpan`, `formatDate` that reproduce §3's `en` column exactly; unit tests copy every `en` example from that table. English only; zh is a named follow-up (no server-side message catalogue exists).
   - **Text:** plain UTF-8, `\n` line ends, ≤ 4,000 bytes. Every string from the response that isn't a compile-time constant (segment keys, source names, exception kinds) has C0/C1 controls, DEL and bidi formatting characters (U+061C, U+200E, U+200F, U+202A–U+202E, U+2066–U+2069) removed and is cut to 64 characters with `…`.
   - **HTML:** one small builder type in `digest.rs` that **escapes by default**: `text(&str)` escapes `&`, `<`, `>`, `"` and `'` (`&amp;`, `&lt;`, `&gt;`, `&quot;`, `&#39;`); `raw(&'static str)` takes only string literals (the template's own tags), so data can never reach the output unescaped; attribute values come only from `text()` or the validated link paths above. A complete document: `<!DOCTYPE html>`, `<html lang="en">`, `<meta charset="utf-8">`, `<title>` = subject, then `h1`, `p`, a KPI `table` with `th scope="row"`, `h2` + `p`/`ul` sections, the link `p`. **No `<script>`, `<style>`, `<img>`, external URLs, event-handler attributes or colours**; at most `style="text-align:right"` on number cells (no colour values anywhere). Arrows sit in `<span aria-hidden="true">`. ≤ 96 KiB.
4. **`GET /digest/preview?period=daily|weekly`** (default `weekly`) in `digest.rs`, behind `auth::protected`, `operation_id = "getDigestPreview"`, tag `insights`:
   - `200` with `DigestPreview { generated_at: integer, html: string, period: "daily"|"weekly", range: InsightsRange, subject: string, text: string }` (alphabetical; a `#[schema(example = …)]` for the W6 mock).
   - A bad `period` is `400 bad_parameter` with `field: "period"`; without a session `401`; `503 insights_unavailable` when the builder says so.
   - **JSON only.** The HTML is never served with `Content-Type: text/html` from the app's origin. Say in the PR, for S-insights-3, that the client shows it only in an `<iframe sandbox srcdoc>` (no `allow-scripts`, no `allow-same-origin`) and the text in a `<pre>`.
5. **Sending is out of scope** (§10.9.7's schedule, channels and quiet hour need a settings section and B9's channel bits). Expose `pub(crate) async fn digest(state: &ApiState, period: DigestPeriod) -> ApiResult<Digest>` for that follow-up and list in the PR what it must add: `NotificationKind::Digest`, absolute links from a configured address, the user's time zone and the 03:00 local schedule, "Show adult content" read at send time, and an HTML part (today's email channel builds its own HTML from `Notification.body`).

## Tests
- `render` goldens (text and HTML) for hand-built `OverviewResponse`s: a normal week, a day with no final cohort (yield `—`, "No completed cohorts yet"), paused health, no movers, two exceptions with links and one with a `target` that fails the check (no link), every Δ null (no compare data).
- **Escaping:** a property test that `text(s)` never contains a raw `<`, `>`, `&` (outside an entity), `"` or `'`, and unescapes back to `s`; fixtures with `<script>`, `"><img onerror=…>`, `javascript:` and bidi overrides as segment keys and exception kinds show them inert in HTML and stripped of controls in text; no output ever contains `<script`, `<style`, `<img`, an `on…=` attribute, a `style` other than `text-align:right`, or an `href` other than the validated root-relative paths.
- Size limits hold for maximal inputs (64-character keys, every exception kind); subject ≤ 120 characters.
- Formatters reproduce every `en` example in `docs/metrics.md` §3 for the five you implement.
- Through the router (fixture copied from `tests/insights.rs`): weekly and daily previews match goldens; the numbers in the text equal the same request's `/insights/overview?compare=1` fields; with Adult hidden no `adult` key appears; 401, 400 with `field`, 503 without `insights`.
