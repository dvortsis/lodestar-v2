## Build
1. **One migration** creating:
   - `saved_searches` (id AUTOINCREMENT, name, query text and the normalized AST form the percolator needs, sort, created/updated, `watermark` = last torrent id evaluated, alert on/off, RSS feed on/off);
   - `alerts` (id, saved_search_id FK ON DELETE CASCADE, torrent_id, created, seen/read state) with the indexes §10.8's "New since" divider and unread counts need;
   - `user_items` (torrent_id, favourite, hidden, labels, note, timestamps);
   - `collections` and `collection_items` (ordered, FK cascade);
   - `api_keys` (id, name, **hash only** of the secret (argon2id or SHA-256 of a ≥ 256-bit random secret: state which and why), a short public prefix for display, scopes, created, last_used, expires, revoked) and feed tokens if §12 separates them;
   - `index_watermark_hour(hour INTEGER PRIMARY KEY, last_id INTEGER)`;
   - `query_log` (opt-in: off unless the setting enables it; time, query text, result count, latency; **no IPs, keys or tokens**; bounded retention with a pruning API).
   - Use integer ids, `AUTOINCREMENT` where §7 requires ids never be reused, `STRICT` tables if the existing schema does, and foreign keys consistent with the rest of the schema.
2. **Store APIs** for each table: typed structs, CRUD where the consumers need it, and the queries B9/B11/B12 will run (state their shapes in the PR so those slices can rely on them): saved searches above a watermark, alert unread counts, API-key lookup by prefix + constant-time hash check, the hourly watermark upsert and "searchable hour of torrent id", query-log append and prune.
3. **Deletion and privacy:** deleting a saved search, collection, API key or user item deletes its rows (cascades) and goes through the same WAL scrub path #81 adds for deletes, if #81 has merged by then; otherwise leave a clearly marked call site and say so in the PR.
4. **Upgrade safety:** the migration runs on a v-current database with data (fixtures from M4's tests), is idempotent with the existing migration runner, and the pre-migration snapshot works as it does for earlier versions.

## Tests
- Migration: fresh DB and upgrade from main's latest version, with data; `schema_migrations` advances once; FKs enforced; a second open is a no-op.
- Each API: round trips, cascades, constraint failures, ids never reused after delete.
- API keys: the secret is never stored or returned after creation; lookup is by prefix + hash with constant-time compare; revoked and expired keys fail.
- `index_watermark_hour`: monotonic upsert; "searchable hour" for ids before, at and after boundaries.
- `query_log`: nothing written while the setting is off; pruning bounds it.
- A property test or exhaustive test for any non-trivial encoding (e.g. labels, AST storage).
