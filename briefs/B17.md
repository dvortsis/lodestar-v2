# B17: "Show adult content", off by default (search, facets and Discover exclude Adult unless it's on)
**Model:** Opus (core: content safety, the query compiler, an owner decision). **Branch:** `slice/B17`.

**Spec:**
- `runner/standards.md` (the bar).
- **`docs/owner-decisions.md` §1.8.12:** Adult is a media category; "Show adult content" is **off by default** and turned on with an **18+ confirmation**; detection is cautious.
- Architecture §20.9 "Media categories, including Adult":
  - visibility is a preference, not a legal tier;
  - it applies to Search, Discover, Alerts and Insights segments;
  - outputs (Torznab, Stremio, export) each have their own adult setting, also off by default;
  - with Adult hidden, adult items are **excluded from facet counts and Discover entirely**, not shown as placeholders.
- §20.7 (the filters API; corrections Not adult / Is adult), §8 (the query language: `type:adult`, `adult:<kind>`), §10.4 and §10.10 (Settings), §16 B2's entry (the settings registry and how a section is added) and B5a's (the hidden-torrent clause and the cursor fingerprint that includes it).
- The code:
  - `crates/search/src/{compile.rs,query.rs,lease.rs,cursor.rs}`;
  - `crates/api/src/{search.rs,dto/search.rs}`;
  - `crates/lodestar/src/settings/{README.md,mod.rs,*.rs}` (B2, merged);
  - `crates/filter` (read only: how `ContentType::Adult` and `adult_kind` are stored and indexed).

## Own

- A new settings section module `crates/lodestar/src/settings/content.rs`, with one registration line in `settings/mod.rs`, plus the line in `services.rs` that hands the watch receiver to the API state.

## Build
1. **The setting.** A `content` section in B2's registry:
   - `show_adult: bool`, default `false`, live (no restart).
   - Turning it **on** through `PATCH /settings/content` requires `"confirm_adult": true` in the same body (the server side of the UI's 18+ confirmation). Without it, the PATCH is refused with a clear envelope code (e.g. `adult_confirmation_required`, 422, `field: "show_adult"`). Turning it off needs nothing. Not a password: it's a preference, not a filter change (§20.11 doesn't apply). State that in §16.
   - Env override `LODESTAR_SHOW_ADULT` follows B2's read-only rule.
   - Reserve, but don't wire, the per-output settings (`torznab_adult`, `stremio_adult`, `export_adult`, all false). Their slices wire them. If B2's pattern makes reserving cheap, add them now, marked "not used yet" in the schema; otherwise leave a §16 note.
2. **The clause.** When `show_adult` is false, every search excludes documents whose content type is Adult. Add the clause in the compile step where the hidden-torrent clause is added, so the following get it with no further work:
   - counts (B5a's `count.rs`);
   - exact-on-demand;
   - cursors: the cursor fingerprint must change with visibility, as it does for `hidden`, so a cursor from before a toggle is `bad_cursor`/`cursor_expired` rather than leaking or skipping; test it;
   - facets (B6, through the shared base-query function).
3. **Explicit adult queries while hidden.** `type:adult` or `adult:<kind>` with Adult hidden returns **no hits**, and the response carries a typed notice (e.g. `notices: ["adult_hidden"]`), so the UI can say "Adult content is hidden; turn it on in Settings". Never return adult hits because the query asked for them.
4. **Detail by hash.** `GET /torrents/{hash}` for an Adult torrent while hidden returns 404 or a typed `adult_hidden` refusal, so a pasted hash doesn't bypass the preference. Pick one, justify it in §16, and test it. Note: detail lives in `crates/api/src/torrents.rs`. If the change is a few lines there, make it and say so in the PR (a scope exception); otherwise list it for B13.
5. **What doesn't change:**
   - the filter engine, the floor, CS-5/CSX-5, and the per-torrent corrections (Not adult / Is adult);
   - the crawler and store: Adult torrents are still stored and indexed; this is display only.
   - Alerts, Insights and Discover read the same setting when their slices land. Leave a §16 note naming B9, B11a and B13.

## Tests
- Default (no setting) hides Adult in search results and counts.
- Turning it on without `confirm_adult` is refused and nothing is saved. With it, Adult appears. Turning it off hides again, live, without a restart, via the watch channel.
- `type:adult` while hidden: zero hits plus the notice.
- The cursor across a toggle is refused.
- Detail-by-hash while hidden.
- Env override read-only.
- A non-adult torrent with an `Is adult` correction (§20.7) is hidden too. A detected-adult torrent with a `Not adult` correction is shown: visibility follows the effective class, whatever the index stores. Check how corrections reach the index, and say in the PR if a correction needs a reindex to take effect.
- API goldens; unauthenticated gives 401.
