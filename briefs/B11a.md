## Build
1. **Record searchable time and the Searchable stage** (nothing does yet: `record_index_watermark` has no caller, and no code records `Stage::Searchable`):
   - Let `CommitHook` take more than one sink, keeping B4's `set` behaviour for the hub. The sink only sends `Committed` to a channel; it never blocks the indexer.
   - A task in `crates/lodestar/src/insights.rs`, with its own `Store` connection, applies each commit in one `BEGIN IMMEDIATE` transaction through a new `Store::record_searchable(prev_id, last_id, at)`: the `index_watermark_hour` upsert (same rules as `record_index_watermark`, not a copy), `cohort_hour` `Stage::Searchable` counts by (`discovered_at` hour, `first_source`) for ids in `(prev_id, last_id]` (a primary-key range, one commit's worth), an event-time "newly searchable" counter by content type, and a log-bucketed time-to-searchable histogram per cohort (≤ 10% resolution). Imports (`flags::IMPORTED`) stay out of the funnel.
   - A crash may lose one commit's rows; B11b's `rollup --repair` restores them (say so).
2. **`GET /insights/overview?range=24h|7d|30d|all|custom&from=&to=&compare=0|1`**, shaped as §7.5: `range`, `updated_at`, `stages`, `kpi` (`searchable` from `OpsApi::stats()`, `searchable_delta` only with compare, `imported`, `new_searchable`, `yield` and `time_to_searchable_p50_s/p95_s` over **final cohorts only**, `health`), `trend[]` (hourly up to 7 d, else UTC days summed from hourly rows until B11b compacts; **no rollup row = `null`, never 0**), `annotations[]`, `funnel[]`, `serve`, `ingest_per_hour`, `stale`, `segments`, `exceptions[]`, and `previous` (same shape, the equal-length period before) with `compare=1`.
   - **Finality:** final when nothing is in progress (harvested = stored + lost, stored = searchable) or more than the 72 h retry horizon after the cohort hour. A constant; record it.
   - **Stale:** `{since, reason}` when more than 120 s have passed since the writer's last flush (`WriterStats.last_commit`), reasons such as `paused` or `writer_stalled`; null when fresh.
   - **Null, not 0, where there's no source yet:** Serve before #48's counters, alerts fired before B9, sends before integrations count them. Make those §7.5 rows nullable ("null until …").
   - **Segments:** `by_group` and `by_content_type` from step 1's counter, plus whatever else the data supports; list the rest for B11b. **Adult is left out entirely while "Show adult content" is off** (`ApiState.adult`).
   - **Exceptions:** the kinds you can compute honestly now (e.g. `index_lag` > 30 s, `cohort_stalled`); list the rest.
   - Every rate, share, percentile and Δ is computed here, never by the client.
3. **`GET /insights/events?from=&to=`:** annotations named from `pipeline::event` codes (`restart`, `paused`, `resumed`, `intensity`), unknown codes skipped; paused periods as spans so the client draws gaps.
4. **State:** `pub insights: Option<Arc<dyn insights::InsightsSource>>` on `ApiState`, a trait the binary implements for what `OpsApi` doesn't give (the last flush time). Code→name tables for stages, losses and events live in `crates/api/src/insights.rs`; a test in `crates/lodestar` checks them against `lodestar_sources::{Stage, Loss}` and `pipeline::event`.
5. **Performance:** only indexed range scans on `rollup_hour`, `cohort_hour`, `events`, `index_watermark_hour`; never `torrents` or the index when reading. Cache per (normalized query, last flush). Short calls under the reader lock on the blocking pool.
6. **The `insights` SSE topic** (`InsightsEvent` every 30 s): only if #89 has merged when you start, as a source beside `EventSources.crawler`; otherwise name the follow-up.

## Tests
- `record_searchable`: idempotent per range, monotonic, cohort counts equal an independent `COUNT(*)` over `torrents`; hour-0 ids never counted.
- Reconciliation (§10.17): stored/searchable rollups equal `COUNT(*)`s; stages never increase within a cohort; harvested = Σ terminal + in progress; incomplete cohorts excluded from yield and time to searchable; yield null with no final cohort.
- A paused span gives `null` buckets; a measured zero gives 0. `previous` covers the right period; `searchable_delta` null without compare. No Adult in segments while hidden.
- `EXPLAIN QUERY PLAN` shows an index for every overview query on a store holding a year of hourly rollups, and the overview answers within 50 ms in release there.
- API goldens; 401 without a session; a bad `range` is a 400 with `field`.
