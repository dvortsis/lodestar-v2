## Build
1. **Playwright projects** in `playwright.config.ts`:
   - Breakpoints from §10.3 (each as a viewport), × Riverstone light/dark, × the densities in design-tokens (Comfortable/Compact). Name them so a run can be filtered (`--project=`).
   - A **rotating theme sample**: 6 non-Riverstone themes chosen deterministically from the CI run number (or the date when local), plus an `all-themes` project used only by nightly.
   - A **reduced-motion** project (`reducedMotion: 'reduce'`) and a **keyboard-only** project convention (helpers that forbid mouse use within a test).
   - Theme and density are applied the way the app applies them (the pre-paint script reads storage, and `data-theme`/density attributes); use the real mechanism, not CSS injection.
   - `webServer`: cold `npm run assets` takes about 73 s on CI, so raise the timeout (180 s) and reuse an existing server locally (`reuseExistingServer: !process.env.CI`).
2. **The OpenAPI mock** (`web/e2e/mock/`):
   - A Playwright fixture that intercepts `/api/v1/**` with `page.route`, matches each request to an operation in `src/lib/api/openapi.json` (method + path template), and answers with that operation's documented example.
   - A test overrides any operation with typed data (`schema.d.ts` types), e.g. `mock.on('search', body)`.
   - An unmatched request, or an operation with no example and no override, fails the test loudly, naming the operation. No silent 404s.
   - Error responses use the shared error envelope.
3. **axe:** a helper (`expectNoA11yViolations(page, opts)`) wrapping `@axe-core/playwright`, WCAG 2.2 AA tags, run in every project's smoke test of each existing route. Failures print the rule, target and help URL.
4. **Snapshots:** a helper for full-page visual snapshots that waits for fonts and disables animations; a smoke snapshot of each route that exists today, per project. Commit the Linux baselines CI generates (generate them in the job, upload as an artifact on failure); document how to update them.
5. **Theme gate:** a test that the pre-paint script causes no flash of the wrong theme: load with a stored dark theme and assert the first painted frame's background (via `page.evaluate` at `DOMContentLoaded`, or a screenshot of the first frame) is the dark token value.
6. **size-limit:** an assertion that no brand raster (`/brand/**/*.{avif,webp,png}`) is in the first-load chunk set.
7. **Lighthouse CI** (`lighthouserc.json`): run against the built SPA (`npm run preview`), mobile and desktop, asserting §10.1's budgets: LCP, INP (TBT as its lab proxy), CLS, plus total byte weight. Report only, uploaded as a CI artifact; no external upload server.
8. **`e2e.yml`:**
   - On `pull_request` (paths `web/**`, `brand/source/**`, the workflow): Riverstone light/dark × breakpoints × densities, the rotating 6, reduced motion, axe; then Lighthouse.
   - Nightly (schedule) + `workflow_dispatch`: the `all-themes` project with axe on each.
   - Chromium only, via `npx playwright install --with-deps chromium` **in CI only** (the session's Chromium is at `/opt/pw-browsers`; never run `playwright install` locally).
   - Upload the HTML report and diffs on failure. Pin actions by commit SHA with a version comment; `contents: read`.
9. **`web/e2e/README.md`:** how to run each project, use the mock, update snapshots, and add a keyboard-only flow.

## Don't

- Add dependencies.

- `e2e.yml` is green on the PR.
- The PR description lists the projects and how long the PR run takes, and any app hooks missing.
