## Build
1. **What can be exported** (one request type): a query (`q` or `ast`, `sort`, `hidden`, exactly as `/search` takes them), a list of info hashes (the bulk selection, ≤ 10,000), or a collection id. Formats: `csv`, `json` (NDJSON, one object per line, so it streams), and `magnets` (`text/plain`, one magnet per line). Fields: the torrent summary fields of `docs/metrics.md` §7.1 by default, a documented subset selectable; swarm fields follow the summary's null rules (never-scraped is empty in CSV and `null` in JSON, never 0).
2. **What is never exported:**
   - torrents a filter rule hid unless `hidden=true`; Adult while "Show adult content" is off (read once at the start: say what happens if it changes mid-export); `flags::PRIVATE_SOURCE` torrents, always (§18.7);
   - anything quarantined or tombstoned (they aren't torrents);
   - with a hash list or collection, a withheld hash is skipped and counted only in a `skipped` total that doesn't say which or why.
   Reuse `base_query`/`Visibility` for queries and `discover::withheld` plus the `PRIVATE_SOURCE` check for hashes; don't write a second visibility rule.
3. **Streamed and throttled:**
   - `GET /export?…` (and `POST /export` for an AST or a hash list) answers with a streamed body (`Content-Disposition: attachment` with a safe generated filename, never derived from torrent names), written chunk by chunk as rows are read. **Nothing is written to disk** (§2.17).
   - Reads go in chunks: resolve matching ids from the index in id order (or page with a lease, renewing it so a slow export doesn't hit the 10-minute expiry), then read rows from SQLite a chunk at a time, each under the reader lock and its own short read transaction, releasing between chunks. No transaction stays open across chunks, so WAL checkpoints are never starved.
   - Throttle rows or bytes per second (a constant now, in the decisions file), and stop reading when the client stops reading (backpressure), so a stalled download holds no lock.
   - A row cap per export (state it, e.g. 1,000,000) with the cap reported in the trailer/progress, never silently truncated.
4. **CSV safety:** RFC 4180 quoting; a cell starting with `=`, `+`, `-`, `@`, tab or CR is prefixed with `'` (formula injection); names decoded the way the detail view decodes them; control characters escaped. JSON via `serde_json` only.
5. **`/jobs`:** a registry generalizing the filters' `PreviewJobs` (bounded running and kept, swept, a panic finishes the job as failed). Every running export is a job: `GET /jobs` (kind, state, progress done/total, rate, ETA, started), `GET /jobs/{id}`, `POST /jobs/{id}/pause`, `/resume`, `/cancel`. Pausing an export stops reading (the stream waits) and holds nothing; a paused job resumes or times out (state the limit). `kind` is an enum with `export` now and `import` reserved for the importer framework (§18.8), typed so the Jobs view can render both. Session only; writes are same-origin JSON.
6. **Overhead:** run search and ingest benchmarks with an export running and report the deltas against §1.6.4's budget in the PR (the numbers, not a gate yet).

## Tests
- Each format byte-exact on a small fixture (goldens), including a CSV-injection name, a non-UTF-8 name, an empty result, and null swarm fields.
- Visibility: hidden only with `hidden=true`; Adult never while hidden; `PRIVATE_SOURCE` never, by query, hash list and collection; withheld hashes counted in `skipped` without being named.
- Chunking: an export larger than several chunks; the WAL stays under a bound while an export runs beside a writer inserting torrents (the §15 test); the reader lock is released between chunks (another request completes mid-export).
- Throttle, backpressure (a client that stops reading doesn't block other requests), cancel mid-stream, pause/resume, the row cap, the lease surviving a long export.
- Jobs: limits, sweeping, a panicking job, unknown id 404; unauthenticated 401; cross-origin write 403.
