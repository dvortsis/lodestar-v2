# W9: App shell
**Model:** Sonnet (UI layout per §10). **Branch:** `slice/W9`.

**Spec:**
- `runner/standards.md` (the bar); `docs/owner-decisions.md`; CLAUDE.md's UI rules (tokens only, no hex or arbitrary values, `ui-design-skills` only for gaps).
- Architecture §10.3 (information architecture and navigation), §10.13 (accessibility, WCAG 2.2 AA), §10.16 (keyboard map), §10.19 (brand assets), plus §10.1 budgets and §10.2 spacing.
- `docs/design-tokens.md`, `docs/ui-glossary.md`.
- What exists: W0 scaffold, W1/W2 themes and tokens, W3 assets, W4 messages, W5 typed client and SSE (`web/src/lib/api/`), W6 test harness, W7ab/W7cd primitives (`web/src/lib/ui/`), W8 formatters. W7e (charts) is in review; don't depend on it.

## Own
- `web/src/routes/+layout.svelte`, `web/src/routes/+error.svelte`, `web/src/lib/shell/**`, `web/src/lib/keys/**`, and their tests and Playwright specs; messages in `web/src/lib/shell/messages/{en,zh}.json` (or the per-feature location W4 defines).
- `docs/decisions/<date>-W9.md`.
- **Don't edit:** the auth screens and their state machines (M-auth, in flight, owns `web/src/routes/(auth)/` or wherever its brief says), other routes' pages, `package.json`/lockfile, `web/src/lib/ui/**` (ask in the PR for primitive changes).

## Build
1. **Top bar and nav** per §10.3: the destinations, active state, the responsive collapse (narrow screens), skip link, landmarks.
2. **Status pill:** crawler and index state from the server via W5's client and SSE (`/events`), every number through W8 formatters, "—" when unknown. It never computes counts.
3. **Command palette** and the **keyboard registry** (`web/src/lib/keys/`): features register their own commands and shortcuts from their own files; conflicts detected; §10.16's default map; no shortcut steals typing in inputs; the shortcut sheet can come later (S-keys), but the registry API must support it.
4. **Full-page states** (`+error.svelte` and shell-level states): offline/server unreachable, 404, generic error, first-run redirect hand-off to M-auth's `/setup` (call its exported handler if merged; otherwise a stub with a TODO naming M-auth), using §10.19's illustrations per the asset pipeline.
5. Theme and density switch hooks only as §10.3 places them; Appearance settings are a later slice.

## Tests
- vitest: the keyboard registry (registration, conflicts, scoping, inputs not hijacked), palette filtering, the status pill's null/zero/number states.
- Playwright (W6 harness, private port): navigation by keyboard only, skip link, palette open/run/close, responsive nav at the §10 breakpoints, error and offline pages; axe clean in Riverstone light and dark.

## Done when
- In `web/`: `npm run check`, `npx vitest run`, `npm run build`, `npx size-limit` (first load within §10.1) and `npx playwright test` pass after merging `origin/main`.
- A PR titled `W9: App shell`, listing the registry API, the hand-off points for M-auth and S-keys, any primitive changes requested, and screenshots of the shell in light and dark at desktop and phone widths.
- After merge the runner tags `web-foundations-v1`.
