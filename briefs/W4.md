# W4: Per-feature Paraglide messages and the merge script
**Model:** Sonnet (helper). **Branch:** `slice/W4`.
**Spec:**
- architecture §10.1 (compile-time i18n with paraglide-js, en + zh, tree-shaken) and §10.14 (UX writing);
- `docs/ui-glossary.md` (merged in C0);
- `docs/build-plan.md` §1.3: one message file per feature, merged by a script, so translations never conflict.

## Build
1. **Paraglide 2.x setup** (the dependency is already pinned in `web/package.json`):
   - a `project.inlang/` settings file with locales `en` (base) and `zh`;
   - the vite plugin wired in `vite.config.ts`;
   - compiled output in `src/lib/paraglide/` (gitignored if Paraglide's convention allows; otherwise generated in `prebuild`).
2. **Per-feature message files:**
   - Each feature owns `src/lib/features/<feature>/messages/{en,zh}.json`.
   - Shared strings live in `src/lib/i18n/messages/{en,zh}.json`.
   - Keys are namespaced by feature: `search_results_count`, never a bare `count`.
3. **`web/scripts/messages.ts`** merges every per-feature file into the files Paraglide reads (`messages/{en,zh}.json` at the project's configured path). It fails on:
   - a duplicate key across features;
   - a zh key missing from en (an en key missing from zh is a **warning** that lists the keys, because zh is filled later by H-zh);
   - an invalid ICU or Paraglide placeholder.
   - Run it from `prebuild` and in `npm run check` (one script line, `"messages": "…"`). If another slice also edited the scripts block, merge `origin/main` and keep both.
4. **Glossary seed:** turn every term in `docs/ui-glossary.md` that has an en label into the shared message file, with the zh labels marked TBD left out of zh.json.
5. **Locale handling:**
   - `src/lib/i18n/locale.ts` picks the locale from settings, then `navigator.language`, then en.
   - `<html lang>` is kept in sync.
   - Number and date locale for the formatters (W8) comes from the same source. Export a `currentLocale()` they can use.
6. **Tests:**
   - the merge script: duplicate keys, a missing en key, placeholder validation;
   - a component test rendering a message in en and in zh.
7. **README:** a section in `web/README.md` on how a feature adds messages.

## Don't
- Translate anything beyond the glossary seed.
- Edit feature code (there isn't any yet).

## Done when
- `npm run check`, `npx vitest run`, `npm run build` and `npx size-limit` pass.
- The PR description notes how much the i18n runtime adds to search-route JS. It must stay tree-shaken and small.
