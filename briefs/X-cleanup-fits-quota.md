# X-cleanup-fits-quota: the cleanup stack fits the account's Lambda quota

Runner brief, 2026-11-15. Opus, fleet cleanup infra. Gets an Opus review and a /security-review pass, because this is an IAM and safety bound. Branch `slice/X-cleanup-fits-quota` from current main. PR title `X-cleanup-fits-quota: the cleanup stack fits the account's Lambda quota`. Target ≲ 1,200 changed lines; the two docs refreshes may push it a little over (state why if so).

## Why
- The cleanup stack (`infra/aws/fleet-control/cleanup.json`, built by `build_templates.py` `cleanup_stack()`) gives both broker functions `ReservedConcurrentExecutions: 1`.
- AWS keeps at least 10 units of account concurrency unreserved, so on an account whose Lambda concurrency limit is 10, any reservation fails and the stack can't deploy.
- The owner's quota increase request was denied (owner, 2026-11-15). The fleet-control and pia-delivery stacks are deployed; the cleanup stack is not.

## The bound to keep
The reservation gave "at most one run of each broker at a time". Keep that guarantee with a different mechanism, and loosen nothing:
- Remove `ReservedConcurrentExecutions` from both functions.
- Add a lease the handler (`cleanup_handler.py`) acquires before doing anything:
  - an S3 conditional create (`If-None-Match: *`) of one lease object per mode, in the control bucket the stack already uses;
  - the lease records holder (the request id), mode and expiry, with the expiry longer than the 300 s function timeout;
  - a stale lease is taken over only with a conditional write on its ETag (`If-Match`);
  - the lease is released at the end with a conditional delete or overwrite.
- A run that finds a live lease does nothing, logs one line, and returns a result the alarm or notification path makes visible. Decide which and say so.
- IAM: widen the Executor role by the minimum, which is exactly the lease keys (GetObject, PutObject, DeleteObject on those keys only, same-owner condition kept). No wildcard keys.
- Fail closed: an error reading or writing the lease means no cleanup action this run, plus an alert.
