## Build
1. **Matching (`percolate.rs`, no tokio, no store writes).**
   - Each due search's stored AST (`serde_json` → `Node`; skip and count one that fails) runs as `SearchIndex::query`, the **exact tier only**, ANDed with the id range `(watermark, through]`. It goes through `matching_ids`'s post-filter path, on **one searcher snapshot** per run, with no lease and no result cache.
   - No visibility clauses: alerts are stored for every match (B8) and shown by the read rules (step 4).
   - At most `keep` hits per search per run (the highest ids). The token is checked between searches.
2. **The task (`percolator.rs`).**
   - A `CommitHook::add` sink only raises an atomic `through` (`max_torrent_id`) and wakes the task, so it never blocks the indexer, and commits coalesce. At start, `through` = `SearchIndex::watermark()`, so it catches up from each search's stored watermark after a restart, a swap or downtime.
   - **A run:**
     - `percolation_due(through)`, most-behind first;
     - `percolate`, within a per-run time budget and a per-search range cap (e.g. 100k ids), so a catch-up takes several runs;
     - `record_percolation` on its own `Store`;
     - then announce (step 3).
   - What the budget didn't reach runs next time. Record the numbers against a target: alerts within 5 s of the commit at 200 active searches.
   - **No duplicates across restarts:** `UNIQUE (saved_search_id, torrent_id)`, hits at or below the watermark skipped, and the watermark moved in the same transaction.
   - Search off means no percolation. Each run takes the current `SearchHandle::index()`.
   - `prune_alerts(keep)` runs at start and hourly, never per commit: it scrubs the WAL.
   - **Fixture mode:** the task doesn't start (`fixture::unless_offline` on its stop receiver), so the manifest's alert counts hold (`tests/fixture.rs` `check_store`).
   - Logs name search ids and counts, never a query or a torrent name.
3. **SSE:** `alerts::announce(hub, store, created, adult)`.
   - Per search, the new alerts on shown torrents (`shown_row(store, t, false, adult.shown())`) become one `AlertsEvent`: `matched` (the shown count), `alert` (the highest shown alert id), `max_id` (the highest shown torrent id), and a new `notify` (the search's `alert` flag, so the UI notifies only for those).
   - No shown alerts, no event. It's published through a new `EventHub` method on `publish_tagged`, so a replay after Adult is hidden is screened, as `torrents` is.
4. **Alerts API** (`alerts.rs`, behind `auth::protected`, store calls in `spawn_blocking`):
   - **`GET /saved-searches/{id}/alerts?cursor=&limit=`:** shown alerts, newest first, as `{id, created_at, read, torrent: SearchHit}` (`hit_row`). Limit 1–200. The cursor is the last row *read* (B10a). An unknown id is `404 saved_search_not_found`.
   - **`POST /alerts/read {saved_search?, through}`:** same-origin JSON, through `user_data`. It returns `OkResponse` with no count, since a count would reveal withheld alerts.
   - **`GET /alerts/unread` → `{unread}`, shown-only.** Replace the raw `unread_total` (no caller) with a store count given the hidden content type. It leaves out `flags::HIDDEN`, and while Adult is hidden it leaves out Adult (`content_type` = `ContentType::Adult.code()` with a `torrent_parsed` row). That is exactly `discover::withheld(.., false, adult)`, and a parity test proves it. The badge equals the sum of B10a's per-search `unread`.
   - **The `channels` bits** (webhook, ntfy, Discord, email; append only) are defined once here. Sending waits for a notifications settings section; name the follow-up. Anything that sends must check the fixture gate.
5. **RSS** (`GET /feeds/{id}`, behind `auth::feed_token`):
   - **Who reaches it.** `!access.reaches_feed(id)`, an unknown id and `rss: false` all give one body, `404 feed_not_found`. A token for one search reaches only that search; an all-feeds token or a `FEEDS` key reaches every feed (B12).
   - **The feed:** RSS 2.0 from `rss::render`, with up to 50 of the newest shown alerts.
     - Adult appears only while `content.show_adult` is on. Filter-hidden torrents never appear. `private_source` comes from `flags::PRIVATE_SOURCE`.
     - guid = the info-hash hex; item link `{origin}/t/{hash}`; channel link `{origin}/alerts/{id}`.
     - The `RssItem` magnet is new: `<enclosure url="magnet:?xt=urn:btih:<hex>&amp;dn=…" type="application/x-bittorrent" length="<size>"/>`. Accept only that shape, escape it with `escape_into`, and `clean_line` the titles in `render`.
   - **The origin** comes from `Host`, validated through `Url` (host and port only, else `http://localhost`). It's `https` only when B12's trusted proxy sends `X-Forwarded-Proto: https`.
   - **Headers:** `application/rss+xml; charset=utf-8`. `lastBuildDate` is the newest shown alert's time, so the body is stable. A strong `ETag` over the body, with `If-None-Match` → 304. `Cache-Control: private, max-age=60` and `Referrer-Policy: no-referrer`.
   - **The token or any query string never appears** in a link, a body, a header, an error or a log.

## Tests
- **Percolation:**
  - only `(watermark, through]` alerts, and a paused search doesn't run;
  - re-running a range, or a fresh task over the same store, adds nothing;
  - a capped catch-up loses nothing, and a swap mid-way neither loses nor repeats;
  - a stalled task never delays a commit;
  - the budget stops a run and the next resumes it; a bad AST is skipped.
- **Content safety:** with normal, filter-hidden and Adult matches, the list, the badge, SSE and RSS all leave out what's hidden and agree with B10a's `unread`. Showing Adult brings it back. The count's SQL matches `withheld`.
- **Feeds:** session, own token, all-feeds token and `FEEDS` key pass. Another search's token, `rss: false`, an unknown id, a revoked token and a key without `FEEDS` fail as above. Every other route stays 401 for keys.
- **XML:**
  - a property test: arbitrary names (`& < > " '`, controls, CR, bidi, `]]>`) give XML that parses back with the name intact and no live markup;
  - the magnet shape is enforced; ETag and 304 work;
  - a private-source torrent never appears.
- A log-capture test finds no token, query or torrent name. Goldens; 401 without a session; 403 on cross-origin writes.
