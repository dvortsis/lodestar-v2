## What to build (plan §5.2)
1. **Declarations (item 2, §8 item 1):** the analyzer reads a declaration file (round, day, arm, role candidate or diagnostic, preset, the 12 switch values, exit label, image digest) and checks each arm against it at start and at every boundary. A mismatch or mid-run preset change voids the window. Replace `balanced_preset` / `preset_stayed_balanced` with this only for round-1 runs. Define the declaration file's format (JSON is fine) and a schema check; the runner writes the real one in the CR-SPEC decisions file.
2. **`gate-round` (item 5):** a new command with the inputs and pass conditions exactly as §5.2 item 5 lists them, judging one candidate. Any missing input or any layout or spacing problem gives `not_judged`. Layouts L3, L2, L2b and S (§6.3) and the attempt IDs and retry budget of §6.3 are checked as declared.
3. **Memory fit on the measured window (item 6):** the `anon` slope and its 95 % bound over `ws + 12 h` to `ws + 24 h` of each day's window. An incomplete fit (`meets_bar` unset) or missing `anon` is `not_judged`, never a pass.
4. **Bundle mechanism evidence (item 9, §6.1's table):** for every declared-on switch, run the table's check whatever the run kind, including the lookup-cost pair's and the soft-timeout checks. Before you code each row, check it against the analyzer function it names and tell the runner where a row doesn't map to an existing counter; the runner freezes the table in the CR-SPEC decisions file. An interval over the declared preset's query rate or outstanding cap voids the window. `route_backoff` is declared off (O3), so rule 5.3's route rule is unchanged.
5. **Comparator validity (item 10, §8 item 10):** the booked run ID, `kind=comparator`, `valid`, not rehearsal, a 24 h window, the expected host and network identity. Spacing is measured from `timeline.window_end_utc`, never `result.json` `ended`. An invalid, interrupted or unbooked comparator gives `not_judged`.
6. **Contention (§6.3, O4):** the per-day contention verdict from CPU, steal, disk latency and network (the thresholds §6.3 proposes, as parameters the decisions file freezes), with 10 s sample coverage below 98 % giving `not_judged`. A breach on a B day gives `not_judged` for that day and "solo confirmation required".
7. **One manifest, one verdict (item 12):** a manifest with every input file's hash; from it, each candidate's crawler verdict, both per-day memory verdicts, contention verdicts, shipping eligibility and the Balanced-first selection (§6.2). Running it again on the same archive gives an identical result (test it).
8. **The pass rule (§6.4)** per candidate, and §6.4's cohort wording: carry-in is subtracted for the mean and hourly rates, but kept in the latency histogram with dropped samples above 600 s charged (CR-SPEC §3). A fixture near the 95 % edge matches a hand calculation.
9. **Fixtures:** every row of §5.2's fixture table that is a verdict (all except those the collect slice owns: compiled-default recording, all-off recording, CR-0w first start, the leak-test isolation and the failed leak test). Each fixture has its expected verdict asserted. Use the collect slice's schema; until it arrives, build against a draft and adjust.
10. **Decisions file** `docs/decisions/2026-11-27-X-cr-round1-gate.md`: the declaration format, the `gate-round` command and its outputs, and anything you decided. Note for the runner any rule in §6 or §8 you found ambiguous; don't decide owner-level questions yourself.
