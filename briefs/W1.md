# W1: Theme compiler with contrast and ΔE gates
**Model:** Sonnet (helper). **Branch:** `slice/W1`.
**Spec:**
- architecture §10.18 (all of it: derivation, gates, output, the theme selection UX that consumes the output, and the pre-paint script);
- `docs/design-tokens.md` (merged in C0), which gives the exact names of every token you emit;
- `docs/build-plan.md` §1.3.

## Build
1. **`web/scripts/themes.ts`** (run with `tsx` or `node --experimental-strip-types`; pick whichever already works in the repo):
   - **Input:** `web/themes/*.json` in the Riverstone schema: `{ id, name, family, group, mode: "light"|"dark", license?, source?, colors: { background, surface, text, primary, accent, categorical: [6] } }`.
   - **Derivation:** OKLCH lightness shifts only, so hue and chroma are kept. Derive every role token in design-tokens.md §1–4:
     - inks for primary, accent and status;
     - muted text, field border, divider;
     - hover and selected tints;
     - primary-content;
     - light and dark data variants (`--data-1..6` via the categorical→slot map `[1,5,2,3,4,6]`, plus `--data-other`);
     - the error hue shift;
     - the daisyUI 5 variables.
   - **Colour maths in-house** (no new dependency): sRGB ⇄ OKLab/OKLCH, WCAG 2.x relative-luminance contrast, ΔE_ok, and Brettel or Viénot deuteranopia/protanopia simulation. Keep it in `web/scripts/color.ts` with unit tests.
   - **Gates** (exit non-zero on failure, with a readable report):
     - text ≥ 4.5:1 on background and surface (≥ 7:1 for the High Contrast family);
     - every `*-ink` ≥ 4.5:1;
     - field border and focus ring ≥ 3:1;
     - every data colour ≥ 3:1 on surface;
     - categorical minimum pairwise ΔE_ok ≥ 5 under normal vision is a **warning**, not a failure, together with a CVD simulation report;
     - Riverstone is grandfathered per §10.18.
   - **Output:**
     - Riverstone light and dark go into critical CSS: `web/src/lib/theme/critical.css` (generated, about 1.5 KB) with `:root` / `[data-theme=…]` blocks.
     - Every other theme goes into `web/static/themes.json`, about 5 KB gzipped, loaded lazily.
     - The pre-paint script, `web/src/lib/theme/prepaint.js`, under 1 KB minified. It reads the theme id and cached variables from `localStorage`, sets them before first paint, and falls back to Riverstone, following `prefers-color-scheme` when the mode is "system".
     - Generated files carry a "generated by scripts/themes.ts" header and are exempt from the hex ban (they live under `src/lib/theme/`).
2. **`web/themes/riverstone-light.json` and `riverstone-dark.json`**, from §10.18 / `brand/source/tokens/colors.json`, with the plum `#9381B6` replacing seafoam.
3. **Golden tests** (`web/scripts/themes.test.ts`): the compiler must reproduce the §10.18 derived-token table for Riverstone exactly. That includes `primary-ink #4A7789` light / `#85AFC0` dark, `accent-ink #5B7763`, `muted-text #567079` / `#B2C3C5`, `field-border #8796A2` / `#8C9BA7`, `warning #896D2A`, `error #B45253` / `#DC8080`, and the light data marks `#527F91 #7E9B86 #AE9150 #BF8173 #8796A2 #9381B6`. If your derivation rule can't hit a value exactly, match within ΔE_ok ≤ 0.5 and still pass the contrast rule. List every such case in the PR description.
4. **Package script:** add exactly one line, `"themes": "…"`, to `web/package.json` scripts, and make `npm run build` run it first via `prebuild`. If another slice has also edited the scripts block, merge `origin/main` and keep both.
5. **Wiring:** import `critical.css` from `src/app.css` and inline the pre-paint script in `src/app.html`. Make those two edits only. They don't count as owning those files.

## Don't
- Write the other 46 theme JSONs. W1b does that from `docs/themes.md`.
- Build the theme picker UI.
- Add dependencies.

## Done when
- `npm run themes` passes for Riverstone.
- The golden tests pass.
- `npm run check`, `npx vitest run`, `npm run build` and `npx size-limit` pass, with CSS still ≤ 20 KB.
- A deliberately failing fixture theme (text contrast below 4.5:1) makes `npm run themes` exit 1. That's a test.
