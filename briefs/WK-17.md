## What exists (WK-15, merged)
- **`GET /insights/discover` and `GET /insights/fetch`** carry `by_worker[]`.
  - Discover entries have `worker`, `granted`, `marginal`, `rediscovered` and `dropped`. Fetch entries have `worker`, `committed` and `lost`.
  - Worker 0 is this server's own crawler, followed by remote workers by id.
  - **The field is left out on a single machine.** Absent means render nothing at all: no empty table, no heading.
  - Fetch's `reason` filter doesn't narrow `by_worker`. Say so where the breakdown is shown. `previous` (Compare) doesn't carry it, so the breakdown has no compare column.
- **`GET /insights/workers/summary`** returns `{fleet: null}` or `{fleet: {workers, online, draining, paused, offline, stored_per_hour}}`.
  - It's signed in, not admin-only.
  - `stored_per_hour` is null for an unmeasured hour.
- **`GET /workers`** (WK-14) is admin-only. It's the only source of worker names. Insights never names a worker.
- The types are in `web/src/lib/api/schema.d.ts`. Don't regenerate it: no API change is in scope.

## Build
1. **The fleet pill (§19.7: "Crawling · 3 workers · 4.2k/h").**
   - The pill reads the summary and adds " · N workers · X/h" to its existing text.
   - It shows nothing extra on `fleet: null` or a failed request.
   - Paused and offline counts go in the pill's tooltip or accessible description, not in the visible text.
   - Number formatting follows the locale helpers already in use.
   - **Polling:** at most once every 60 s, and only while the tab is visible. Abort it on unmount.
   - **Bundle:** the pill code is in the first-load bundle, so keep the addition tiny. It must not move first-load size-limit beyond noise. Report the before and after numbers.
2. **Per-worker breakdowns on the Discover and Fetch stage pages:** a section that renders only when `by_worker` is present.
   - It's a table per stage. Use the existing `DataTableAlternative` or table primitives; no new chart dependency.
   - **Names:** for an admin, from `/workers`, fetched lazily and only when `by_worker` is present. Otherwise, and for any id `/workers` doesn't return, use "This server" for 0 and "Worker <id>".
   - Never show an address or token.
3. **The Marginal gain view** (§19.7: "how much each worker adds … to guide where to add the next one").
   - It sits on Discover, under the breakdown, or as its own section.
   - Show marginal per worker, as a count and as a share of that worker's `granted`. Label it **≈**.
   - It gets a one-sentence definition from the DTO doc: finds no other worker claimed while in flight; it mostly under-counts; the latest hours fill in as leases end.
   - **No recommendation engine:** state the numbers plainly. A short hint is fine, for example "Workers on different networks usually add more."
