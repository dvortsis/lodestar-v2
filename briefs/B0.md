# B0: Split the API router and add the error envelope
**Model:** Opus (core). **Branch:** `slice/B0`. **Spec:** architecture §9, §12; `docs/build-plan.md` §1.3 and §3 P0.

## Goal
Restructure the HTTP layer so that later slices each add their own module and change one line, instead of all editing `crates/api/src/lib.rs`. Behaviour stays the same, except that errors use one envelope.

## Today
- `crates/api/src/lib.rs::router` registers `/parse`, `/search`, `/torrents/{hash}`, `/torrents/{hash}/files` and `/password` behind `require_session`, plus the open routes `/auth`, `/setup`, `/login` and `/logout`. The search and parse handlers live in `lib.rs`.
- `crates/lodestar/src/http.rs` serves `/api/status`, `/` (status page), `/metrics` and `/healthz`, and nests `/api/v1`.
- `crates/lodestar/src/main.rs` (443 lines, hand-rolled CLI) wires every service.

## Do
1. **One module per domain in `crates/api`:** `search.rs` (parse + search), `torrents.rs`, `auth.rs`. Each exposes `pub fn routes() -> Router<ApiState>`, split into open and session-protected routers where that applies.
   - `lib.rs` only composes them: one `.merge(x::routes())` line per module.
   - Doc comment there: "add a module, add one line".
2. **Error envelope** `{ "error": { "code": "<snake_case>", "message": "<sentence>", "field"?: "<name>", "start"?: n, "end"?: n } }`.
   - Implement it as one `ApiError` type with `IntoResponse`, in `crates/api/src/error.rs`.
   - Port every handler to it. The parse-error positions (`start`/`end`) must survive.
   - Keep HTTP status codes as they are today.
   - Update `crates/api/tests/api.rs`.
3. **`crates/lodestar/src/services.rs`:** move the service construction and wiring out of `main.rs` (store, pipeline, live indexer, API state, HTTP server) into a builder that returns handles plus a shutdown.
   - `main.rs` keeps CLI parsing and calls the builder.
   - No behaviour change; graceful shutdown order unchanged.
4. Leave `http.rs`'s non-API routes where they are (B3 moves the status page).

## Don't
- Add endpoints, utoipa or DTOs (that's B1).
- Change auth semantics, cookie names or CSRF rules.
- Touch `crates/search` or `crates/store`.

## Done when
- `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` pass.
- The existing API tests pass with only their error-body assertions updated.
- A new test checks the envelope for a 400 parse error, a 401 and a 404.
- `git fetch origin main` and merge it before opening the PR.
