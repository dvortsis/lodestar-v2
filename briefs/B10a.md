## Build
Every route is behind `auth::protected`; every write calls `same_origin_json(&headers)?` first; every store call runs in `spawn_blocking`, reads through `s.reader`, writes through `s.user_data` (a `503 user_data_unavailable` when `None`, like `settings()` in `settings.rs`). Torrents are addressed by 40-hex info hash (`parse_hash` after `to_ascii_lowercase()`); collections and saved searches by integer id. Response struct fields are alphabetical (`dto/mod.rs`); creates return `201` with the object; deletes return `200` with `OkResponse`.

1. **Visibility (content safety), the same everywhere:**
   - Read "Show adult content" once per request: `let adult = s.adult.shown();`.
   - **One torrent by hash** (`GET/PATCH/DELETE /user-items/{hash}`, adding to a collection): look it up as `compare.rs` `visible()` does and call `discover::withheld(&row, e.as_ref(), true, adult)`. `hidden_ok` is `true` because the drawer opens filter-hidden torrents. Unknown and withheld are the **same** `404 torrent_not_found` ("There's no torrent with that hash."), so nothing about an Adult torrent leaks.
   - **Lists** (`GET /user-items`, `GET /collections/{id}`, labels, counts): drop every row for which `withheld(&row, e.as_ref(), hidden, adult)` is true, where `hidden` is the request's `?hidden=true` (default `false`, as search). Keep reading store pages until `limit` visible rows or the end; the cursor is the last row **read**, so skipped rows aren't seen again.
   - **Every count you return counts visible rows only:** `items` on a collection, label counts, list totals. User data is small; recount by reading ids and filtering. Never return the store's raw `Collection.items`.
2. **User items** (`user_items.rs`):
   - `GET /user-items?favourite=&hidden_mark=&label=&hidden=&limit=&cursor=`: marked torrents, newest change first; each row is `{hash, favourite, hidden, labels, note, created_at, updated_at, torrent: SearchHit}` with the hit from `torrents::hit(&row, 0.0, None)` then `search::enrich`. (`hidden_mark` filters your own Hide mark; `hidden` is the filter-rule visibility above.) Limit 1–200, default 50; `cursor` is `"<updated_at>.<torrent_id>"`, a bad one `400 bad_cursor` with `field: "cursor"`.
   - `GET /user-items/{hash}`: the marks, or all-false/empty marks when none (`200`, never 404 for "no marks"), plus `collections: [id]` from `collections_of` (the drawer's "In collections").
   - `PATCH /user-items/{hash}` `{favourite?, hidden?, labels?, note?}`: absent = unchanged; `note: null` clears; maps to `UserItemUpdate`. Trim labels and the note, and turn CRLF into LF, before calling the store. Returns the marks after (all-false when the store returned `None`).
   - `DELETE /user-items/{hash}`: clears every mark.
   - `GET /user-items/labels`: `[{label, count}]`, visible torrents only.
3. **Collections** (`collections.rs`): `GET /collections` (`[{id, name, note, items, created_at, updated_at}]`), `POST /collections` `{name, note?}`, `GET /collections/{id}?after=&limit=` (the collection plus a page of `{position, added_at, torrent: SearchHit}`), `PATCH /collections/{id}` `{name?, note?}` (read current, merge, call `update_collection`), `DELETE /collections/{id}`, `POST /collections/{id}/items` `{hashes: [..]}` (1–500; every hash must be visible, else the one 404 with `field: "hashes"`; all or nothing as the store does), `POST /collections/{id}/items/remove` `{hashes}`, `PUT /collections/{id}/order` `{hashes}` (must name every entry once; the store's `Invalid` becomes `409 stale_order`). Unknown id: `404 collection_not_found`.
4. **Saved searches** (`saved.rs`): `GET /saved-searches` (each summary with `alerts`, `unread`, `last_alert_at` from the store as given), `POST /saved-searches` `{name, q | ast, sort?, alert, rss, paused?}`, `GET /saved-searches/{id}`, `PATCH /saved-searches/{id}` (any subset; read current and merge, so a field you don't send, **including the store's `channels`**, keeps its value), `DELETE /saved-searches/{id}`.
   - The query goes through `search::request_ast(ast, q)` (so `query_syntax` errors keep their span) and `search::sort_param`; store `query` = the text sent (or `ast.to_query()` when an AST was sent) and `ast` = `serde_json::to_string(&ast)`.
   - `watermark` = the index's `s.index.as_ref().map(|h| h.index().watermark())`, or the store's `max_id()` when search is off, so a new or resumed search alerts only on what's indexed from now on.
   - Don't expose `channels` or `watermark` in the DTOs; B9 defines the notifier bits. Unknown id: `404 saved_search_not_found`.
5. **Errors:** map `lodestar_store::Error::Invalid(msg)` to `422 invalid_value` with the `field` your handler knows it came from (`name`, `note`, `labels`, `q`), and `NotFound` to the 404s above; anything else through `error::internal`. Never put a torrent name or a note in an error message.
6. **OpenAPI:** each handler has `#[utoipa::path(operation_id = "…", tag = "library", …)]` and is listed in its module's `ApiDoc`; each response DTO has a `#[schema(example = …)]` so the W6 mock serves it. Then run the regeneration commands below and commit both files.

## Tests (`crates/api/tests/user_data.rs`, fixture copied from `tests/discover.rs` with `user_data: Some(...)`)
- Round trips for every route; goldens for one success and each error code per resource (`LODESTAR_BLESS=1 cargo test -p lodestar-api --test user_data`, then read every recorded file before committing).
- **Content safety:** with a fixture holding a normal, a filter-hidden (`flags::HIDDEN`) and an Adult torrent, all marked and in one collection: with Adult hidden, the Adult one is absent from every list and count, and `GET/PATCH/DELETE /user-items/{adult hash}` and adding it to a collection give the same 404 body as an unknown hash; with Adult shown it appears. The filter-hidden one appears in lists only with `hidden=true`, and can be marked by hash.
- Paging past withheld rows returns full pages and never repeats a row.
- PATCH keeps unsent fields (including `channels`, checked in the store); resuming a paused search moves its watermark; a bad query gives `query_syntax` with `start`/`end`.
- 401 without a session, 403 on a cross-origin write, 415 on a non-JSON write.
