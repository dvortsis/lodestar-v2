# S-alerts: Alerts pages and dialogs
**Model:** Sonnet (helper: list, detail and three dialogs per §10.8 over B9's alerts and B10a's saved searches, with live updates through W5's event client; every count, unread mark and visibility rule is the server's). **Branch:** `slice/S-alerts`. **No `/security-review` required:** the user's query text goes to the server, which parses and validates it; names and torrent names render only as Svelte text (never `{@html}`); the only links built from data are `/alerts/<id>` (an integer from the API), `/t/<hash>` (`^[0-9a-f]{40}$`) and the feed path `/api/v1/feeds/<id>`. No auth, token or filter code is touched. If you find you need more (a feed token, raw HTML, a URL from user text), stop and say so in the PR.

## Build
1. **Endpoints and fields (tag `library`):**
   - `GET /saved-searches` (`listSavedSearches`) → `SavedSearchView[]`, oldest first: `id`, `name`, `q` (query text), `ast`, `sort` (null = relevance), `alert` (in-app alerts), `rss`, `paused`, `alerts` (recorded, shown torrents only), `unread`, `last_alert_at` (null before the first), `created_at`, `updated_at`.
   - `GET /saved-searches/{id}` (`getSavedSearch`) → one view; `404 saved_search_not_found`.
   - `GET /saved-searches/{id}/alerts?cursor=&limit=` (`listAlerts`) → `AlertsPage { items: AlertRow { id, created_at, read, torrent: SearchHit }[], next_cursor }`, newest first, only torrents search would show; `400 bad_cursor`.
   - `POST /alerts/read` (`markAlertsRead`) body `AlertsRead { saved_search, through }` → `{ ok }`, no count.
   - `POST /saved-searches` (`createSavedSearch`) body `SavedSearchCreate { name, q?, sort?, alert, rss, paused? }` (`alert` and `rss` required) → `201 SavedSearchView`; `400 query_syntax` (with `start`, `end`), `q_and_ast`, `invalid_ast`, `unknown_sort`; `409 too_many_saved_searches` (1,000 at most); `422 invalid_value` with `field`.
   - `PATCH /saved-searches/{id}` (`patchSavedSearch`) body `SavedSearchPatch { paused }` for the toggle; `DELETE /saved-searches/{id}` (`deleteSavedSearch`) → `{ ok }`, deletes its alerts and feed tokens.
   - **SSE:** `events.on('alerts', …)`: `AlertsEvent { saved_search, matched, alert, max_id, notify }`. Don't add up `matched` across events: refetch the server's counts instead (step 5).
   - **Missing from the backend, don't fake:** the notifier's **external channels** (webhook, ntfy, Discord, email: B9's bits, stored in `saved_searches.channels`) are neither returned nor settable (B10a); the list and dialogs show the two the API has, **In the app** (`alert`) and **RSS feed** (`rss`), and the rest waits for the notifications settings section (S-settings-2). There's no **last-viewed time** (step 4 words the divider from what exists) and no server sort for the list (keep the server's order; don't re-sort). Report each; never add a local type.
2. **The list (`/alerts`):** an `<h1>` ("Alerts") rendered at once (before data: W9's specs check it), a "New alert" button (step 6), then one row per saved search in the server's order: **name** (link to `/alerts/<id>`), **query** (`Mono`, wrapping; an empty `q` reads "Every new torrent"), **new** (`formatCount(unread)`, `data-testid="alerts-unread-<id>"`; 0 is "0"), **channels** (Badges with icon + text: "In the app", "RSS"; "None" when both are off), **last alert** (`RelativeTime` of `last_alert_at`; null → `—` with the accessible name "No alerts yet"), a **Paused** badge (icon + text) when paused, the **pause toggle** and **Delete**. A real `<table>` from `large` up (row headers on the name), a stacked list below it; both from one data path, only one in the DOM. `Open in Search` per row is optional; the detail page has it.
3. **Pause (no confirmation, §10.8):** the `Toggle` (accessible name includes the search's name) sends `PATCH {paused}`; it shows pending (`aria-busy`, no second send) until the answer, then the server's value. On error it returns to the previous state with an error toast. Resuming shows, once, the server's rule as help text: "Resuming skips torrents indexed while it was paused."
4. **The detail (`/alerts/[id]`):** a non-integer id is a 404 through kit's `error(404)` (W9's error page). Fetch `getSavedSearch` and the first `listAlerts` page together.
   - **Header:** name (`<h1>`), query in `Mono` with **Open in Search** (`/search?q=<encoded q>` plus `&sort=<sort>` when not null), the Paused badge and the toggle, channels, `formatCount(unread)` new as the page opened, Delete. When `rss`: the feed path `/api/v1/feeds/<id>` in a read-only `Mono` input that selects its text on focus, with one line: "Feed readers that can't sign in need a feed token from Settings → Security" (link `/settings/security`; that screen is M-security-settings', not built yet). No clipboard code here.
   - **Rows:** `VirtualList` of alerts, newest first, paged by `next_cursor` (`hasMore`/`onLoadMore`; on `mustRestartPaging(e)` restart from the first page; on any other error clear `hasMore` and show a Banner with Retry). Each row is a small **feature-local** row (`features/alerts/AlertHitRow.svelte`) with §10.4's Comfortable facts (resolved title, raw name in Mono beneath when it differs, composition bar with dominant share, size, files, seeders/leechers, trackers reporting `n / m`, discovered) plus "Matched <RelativeTime of created_at>". The shared result row doesn't exist yet (S-search-2 will own it): put `// TODO(S-search-2): replace with the shared result row` at the top. S-discover builds its own interim row; don't share code across the folders. Opening a row goes to `/t/<hash>`.
   - **The "New since …" divider:** from the rows' server `read` flags as they arrived (newest first), placed between the last row with `read: false` and the first with `read: true`, labelled "New since <formatDateTime(created_at of that first read row)>". That's truthful: every alert after it is newer than the last one you had seen. No read rows loaded yet but more pages exist → it appears when the first read row loads. Every row unread and no more pages → no divider (the header's count says it). No unread rows → no divider. It's a separator (`role="separator"` with the label as its accessible name, or a heading) and isn't hover-only. It stays where it is for the visit; marking read doesn't move it.
   - **Marking read:** once the first page has rendered, if `items[0]` exists and is unread, `POST /alerts/read { saved_search: id, through: items[0].id }` (the highest id you saw). Once per load and once per "Show" (step 5); a failure shows nothing and isn't retried in a loop. Never mark rows you haven't fetched.
5. **Live updates (SSE):** subscribe in an `$effect` on each page (it unsubscribes on leave), with `onResync` refetching what the page shows.
   - **List:** an `alerts` event (any search) refetches `listSavedSearches` through a `latest()` slot; events in one frame cause one refetch. The rows update in place: no reordering, no animation (§10.2).
   - **Detail:** an event whose `saved_search` is this page's id refetches `getSavedSearch` and shows a Banner "<formatCount(unread)> new alerts · Show" (`unread` from the server, so alerts read elsewhere don't count). **Show** reloads the first page (the divider is placed again from the new flags) and marks read through its top id. The banner's text goes to a polite `aria-live` region, at most once every 10 s. The list never shifts under the reader; new rows appear only on Show (§10.4's Live rule). Events for other searches do nothing here. `notify` doesn't matter on these pages (the shell follow-up uses it).
6. **Create ("New alert", and the dialog S-search-3 reuses):** `SaveSearchDialog.svelte` on the `Dialog` primitive, **loaded with a dynamic `import()` on first open** (Bits UI's overlay code is about 15–20 KB gzipped; it must stay out of the route's initial chunk).
   - Fields with **visible labels**: **Name** (required, 1–200 characters), **Query** (`Input mono`; prefilled when opened with `q`; help: "Alerts cover torrents indexed from now on"), **Notifications**: Checkbox "In the app" (`alert`, on by default) and Checkbox "RSS feed" (`rss`, off by default). `sort` passes through when given (from Search); the Alerts page sends none.
   - Errors by code: `query_syntax` → on the Query field: your message plus the server's `message` as detail (it carries the parser's explanation; English only, zh is a follow-up), and select `start`–`end` in the field; `invalid_value` → the field named by `field` (`name`, `q`, `sort`); `too_many_saved_searches` → a form-level Banner ("You have 1,000 saved searches, the most Lodestar keeps. Delete one to add another.", the number through `formatCount`); `q_and_ast`, `invalid_ast`, `unknown_sort` → a generic form error (they mean a bug); `network`/5xx → a form-level error, the dialog stays open with its values.
   - Submit is a `Button` with `loading`; Enter in a field submits; Esc and Cancel close and return focus to the opener (the primitive restores it). On success the Alerts page goes to `/alerts/<new id>`; when another feature passes `onSaved`, that callback decides and the dialog only toasts "Saved '<name>'".
7. **Delete (a specific confirmation, §10.8):** a `Dialog` (lazy, as above) titled "Delete '<name>' and its history?", body "Its alerts are deleted<, and its RSS feed stops working>. This can't be undone." (the RSS clause only when `rss`), buttons **Cancel** (initial focus) and **Delete** (`variant` danger, `loading`). `404 saved_search_not_found` counts as already deleted. After it: from the detail, go to `/alerts` with a toast; from the list, refetch and move focus to the next row's name (or the previous one's, or the heading).
8. **States, each designed:**
   - **Loading:** skeleton rows at final heights, `aria-busy`, the `<h1>` already present; no flash under 300 ms.
   - **Empty list:** EmptyState "No saved searches yet" with one next step, the "New alert" button (Search's "Save search" doesn't exist until S-search-3), illustration `StateScene` id `empty_state_explore` (`$lib/shell/StateScene.svelte`).
   - **Empty detail:** "No matches yet. New torrents that match appear here." (paused: "Paused: no new alerts are recorded."), no illustration.
   - **Errors:** `saved_search_not_found` → "This alert doesn't exist any more" with a link to Alerts; `network`/5xx → Banner with Retry, keeping the last data visible (**stale**); a failed refresh after an event keeps the old counts and shows the Banner.
   - **Partial and null:** `last_alert_at` null, never-scraped swarm `—` ("Never scraped"), `title` null → the raw name, empty composition → "Not classified yet", paused.
