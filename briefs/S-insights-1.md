## Build
1. **Data, and only these calls** (types from `schema.d.ts`, never a local copy):
   - `GET /insights/overview` (`getInsightsOverview`, `range`, `from`, `to`, `compare`) → `OverviewResponse`. One request per state change through a `latest()` slot, so a stale response never overwrites a newer one (§10.12).
   - `GET /crawler` (`getCrawler`) → `CrawlerStatus` for the context bar: `paused`, `since`, `intensity`, `intensity_env`.
   - `POST /crawler/pause`, `POST /crawler/resume`, `PATCH /crawler` (`{ intensity }`). After each, refetch `/crawler` and the overview; never update numbers optimistically.
   - `events.on('crawler', …)` for `paused` and the starting-up counters (`harvested`, `fetched`, `stored` since start), and `events.on('insights', …, { onResync })`. On every `insights` event or resync, refetch the overview through the slot. Nothing publishes `insights` on `main` until #130 merges, so meanwhile refetch on a `crawler` event at most once every 30 s (the server's own cache cadence). No timers: a hidden tab gets no events and so never refetches. Once `insights` events arrive, stop the `crawler`-driven refetch.
2. **The client never computes counts, percentages, Δs, shares, cohorts or rates.** Every number on screen is a field of the response passed through a W8 formatter. No sums, no `previous` minus current, no share = part ÷ total, no per-hour from a count. Bar lengths may be drawn from counts (geometry, `lengthPct`), but no derived number is shown. Where §10.9.2 asks for a number the response doesn't carry, show the panel without it and list it under "Backend gaps" (step 10). A vitest test feeds a response with distinctive values and checks that every rendered number equals a formatter applied to a field.
3. **URL state** (§10.3, §10.9.4): `/insights?range=24h|7d|30d|all|custom&from=&to=&compare=1`. Defaults (`7d`, no compare) are left out of the URL. Parse defensively: an unknown `range`, a `custom` without valid `from` < `to`, or `compare` other than `1` falls back to the default with `replaceState` and no error. Range and compare changes push a history entry (`goto(…, { keepFocus: true, noScroll: true })`), so Back and Forward restore them and refetch. `compare` is ignored for `all` (the server sends no `previous`): show the toggle with a reason ("Not available for All") instead of hiding it.
4. **Global context bar** (sticky, §10.9):
   - Range: a `SegmentedControl` of 24 h / 7 d / 30 d / All / Custom. Custom opens two date inputs; convert the chosen UTC days to Unix seconds for `from`/`to`, and show a server `400` with `field` (`from`, `to`) inline on that input.
   - Time zone: `range.tz` ("UTC") is shown in the bar, and every axis tick and tooltip is formatted with `timeZone: range.tz`, because buckets are UTC hours or days (`docs/metrics.md` §2). The user's time-zone preference isn't loaded app-wide yet; record this in your decisions file.
   - "Compare to previous period" toggle (a parameter, not a filter).
   - "Last updated": `updated_at` with the `RelativeTime` primitive (absolute time in its tooltip).
   - Pause / Resume (`CrawlerStatus.paused`) and intensity (Low / Balanced / Aggressive) with one plain sentence on each level's effect (no numbers: the client has none of its own). When `intensity_env` is set, show the control locked with "Set by {variable}" text and no way to change it.
   - A chip for a non-default range ("Last 30 days ×", "Custom: …"); removing it returns to 7 d (§10.9.4 "every active selection is shown as a chip").
5. **The story, in this order, each level a `<section>` with an `<h2>` and a subtitle naming its time base** (§10.9.2, `docs/metrics.md` §6):
   1. **Stage strip** (`stages`): Discover (`≈`, always), Fetch, Understand, Index, Serve with `formatCompact`; a `null` (`fetch` before it was counted, `index` with search off, `serve` until #48) is `—` with an accessible name ("Not measured yet", "Search is off"). It's a `<nav>` with an ordered list of links that scroll to the level that explains the stage (Discover → Movement, Fetch → Funnel, Understand → Segments, Index → Status, Serve → Serve; record the mapping). The visually hidden text equivalent uses `formatCount`. Narrow screens: a 2-row grid, order kept.
   2. **Status, KPI row, max 5** (`Kpi`): Searchable torrents (`kpi.searchable`, `formatCompact`; Δ `kpi.searchable_delta` with `formatDelta` and the period text, only when the field is non-null; "Imported" `kpi.imported` beside it with `formatCount`); New searchable (`kpi.new_searchable`; 0 is real); End-to-end yield (`kpi.yield`, `formatPercent` f = 1; null → `—` + "No completed cohorts yet"); Time to searchable (`time_to_searchable_p50_s` / `_p95_s`, `formatSpan`, always `≈`; null as yield); Health (`kpi.health.state` + `reason` as icon + text, never colour alone). With #130 merged, add the other Δs from its fields; until then show none (never `previous.kpi` arithmetic). Time-to-searchable Δs need a span kind in `formatDelta` (W8 has `count | compact | percent`): leave them out and list the W8 follow-up.
   3. **Movement** (8 columns at x-large): two **separate, aligned** `LineChart`s with the same `times` (`trend[].at`) and width, never a dual axis: "Newly searchable" (`trend[].searchable`, `--data-1`) and "Unique hashes harvested (≈)" (`trend[].harvested`). `null` points are gaps (paused, not running), never 0. `bucket` = `range.bucket`; axis units "per hour" / "per day".    4. **Exceptions** (4 columns beside Movement at x-large; moved up on narrow screens, §10.9.6): `exceptions[]`, error before warning, each with a status icon + one message per known `kind` (`index_lag`: `value` via `formatSpan`; `cohort_stalled`: `value` via `formatCount`), `since` via `RelativeTime`, and one fix link: `fix.kind` `stage` → `/insights/<target>`, `settings` → `/settings/<target>`, **only when `target` matches `^[a-z_]{1,32}$`**, else no link. An unknown kind gets a generic "Needs attention" line with the kind as text. Empty: one line, "Nothing needs attention".
   5. **Funnel by discovery cohort** (12 columns): an ordered funnel of `funnel_total.stages` (Harvested → Peer found → Metadata fetched → Stored → Searchable), bars from zero, widths proportional to the counts, each label showing the count (`formatCount`) and the server's `funnel_total.conversion` (`formatPercent` f = 1, null `—`). Build it in your folder (`HBarList` re-sorts, which breaks ties in stage order). "N of M cohorts complete" from `final_cohorts` and `cohorts`, with a note that incomplete cohorts are excluded from yield. A per-cohort view of `funnel[]` (a compact bar or table row per cohort) marks every `final: false` cohort **hatched and labelled "incomplete"** (an SVG pattern in `currentColor`/tokens; no hex). Drill-throughs: a stage links to its stage page (`/insights/discover|fetch|understand|index?range=…`), a loss reason to `/insights/fetch?range=…&reason=<reason>`.
   6. **Segments** (6 + 6): `HBarList`s of `segments.by_group` and `segments.by_content_type` (`searchable`, `formatCount`; no share column, because the response has no shares) and `segments.by_source` (yield, `formatPercent` f = 1, with harvested and searchable in its table).
