# S-discover: Discover page
**Model:** Sonnet (helper: one screen per §10.7 over `GET /discover`, which B13 serves; sections, counts and Adult visibility are all decided on the server). **Branch:** `slice/S-discover`. **No `/security-review` required:** torrent names come from the store and are rendered only as Svelte text (never `{@html}`); the only links built from data are `/t/<hash>` (hash matching `^[0-9a-f]{40}$`) and the "See all in Search" link from a content-type value the server returned. Adult visibility is the server's: the client never decides what is Adult. If you find you need anything else, stop and say so in the PR.

## Build
1. **Data: `GET /discover` (`getDiscover`)** with `type` (a tab, absent = every type), `limit` (default 50) and `cursor` (Newest only; send the same `type` with it). `DiscoverResponse`:
   - `newest: NewestSection { hits: SearchHit[], total, total_approx, next_cursor, notices: SearchNotice[] ('adult_hidden'), limit, offset, type }`.
   - `rising`, `recently_resolved`: `HitGroup { status: 'available'|'unavailable', reason: Unavailable | null, hits: SearchHit[], truncated }`.
   - Rows are `SearchHit`: `hash`, `name`, `title`, `resolved_via`, `content_type`, `size`, `files`, `seeders`/`leechers`/`trackers_reporting`/`trackers_checked` (null = never scraped), `discovered_at`, `flags` (`backfill` → "First seen during backfill"), `composition`.
   - **On main today:** Rising is `unavailable: needs_swarm_history` and Recently resolved `unavailable: needs_resolution_history`, and #48 doesn't change that. Build the `available` path anyway (it's the same row list) and the `unavailable` path for **every** `Unavailable` value (`search_disabled`, `no_title`, `needs_swarm_history`, `needs_resolution_history`, `needs_payload_signature`, `needs_piece_roots`) with an exhaustive `switch`, so a new reason fails type-checking.
   - **Missing from the backend, don't fake:** (a) **Rising has no per-row trend**: `SearchHit` carries no `swarm_trend`, so "the trend explained in text" can only be the section's own sentence ("Ranked by seeders gained per day over the last week") until the server adds the value per row. (b) Recently resolved needs the server to read B8's `torrent_parsed.resolved_at` (in the store on main, `crates/store/src/reporting.rs`; the endpoint still says unavailable). (c) `/discover` takes no query or AST, so **the facet rail can't filter it**: there is no rail in this slice. Offer "See all in Search" instead (step 3). (d) `SearchHit` has no `magnet`, so no Copy magnet on Discover rows yet. Report all four as follow-ups; never add a local type.
   - **The swarm flags from #48:** if #48 has merged when you start or before your PR, merge `main` and show `≈` from `seeders_approx` and the "Suspect seeders" label (glossary `swarm_suspect`, icon + text) from `swarm_suspect`. If it hasn't, don't reference them.
2. **The Adult tab:** read `GET /settings/content` (`getSettings`, path `section: 'content'`) once on mount; show the Adult tab only when `fields.show_adult.value === true`. On any error, or until it answers, leave the tab out. If the URL still says `type=adult` while Adult is hidden, the server returns an empty Newest with `notices: ['adult_hidden']`: show that notice ("Adult content is hidden. Turn on Show adult content in Settings to see it.", link to `/settings/content`), never an empty-as-zero list. Never filter rows in the client.
3. **URL state and tabs:** `/discover?type=<tab>` (absent = All); keep `density` and any other parameter. Tabs are links (`<nav>` with `aria-current="page"` on the active one), one per content type in the glossary's order (All, Movie, TV, Music, Audiobook, Ebook, Comic, Software, Game, Images, Video, Other, plus Adult per step 2); a tab change pushes a history entry and restarts paging. An unknown `type` (`400 unknown_type`, `field: "type"`) shows "That type doesn't exist" with a link to All. "See all in Search" links to `/search?q=type:<tab>&sort=-discovered` (or `/search?sort=-discovered` for All): the same query the server runs for Newest, so the counts agree.
4. **Layout:** an `<h1>` ("Discover"), then Newest as the main region (heading with its count: `formatCount(total)`, or `≈ ` + `formatCompact(total)` when `total_approx`; `data-testid="discover-newest-total"`), then Rising and Recently resolved as smaller sections beside it from `x-large` and below it under that. An unavailable section is a compact notice (icon + text, the reason worded per step 1, one next step only when there is one), not a full empty state with an illustration.
   - **Rows:** §10.7 says reuse the result row, but it doesn't exist yet: S-search-2 (not started) owns it in `web/src/lib/features/search/results/`. Build a small **feature-local** row `features/discover/HitRow.svelte` with §10.4's Comfortable facts only: resolved title (raw name in Mono beneath when it differs, "resolved via files" from `resolved_via`), composition bar (`CategoryBar`, 64–120 px via `--compbar-min-width`/`--compbar-max-width`, dominant-share text), size, files, seeders/leechers, trackers reporting `n / m`, discovered (`RelativeTime`, backfill marker). No badges, no actions beyond opening it. Put `// TODO(S-search-2): replace with the shared result row` at the top. Compact density (`?density=compact`) is the 36 px single line (`--row-height-compact`); Comfortable is 64 px (`--row-height-comfortable`); fixed heights per density (§10.1). S-alerts builds the same kind of interim row for its own page; don't share code across the two folders.
   - **List:** `VirtualList` with `role` listbox (or grid, per its README), `onActivate` → `/t/<hash>`, `hasMore` = `next_cursor !== null`, `onLoadMore` → the next page with the same `type`; on `mustRestartPaging(e)` restart from the first page with a short notice; on any other error clear `hasMore` and show a Banner with Retry (VirtualList retries in a loop otherwise, see its prop doc).
   - **CSS budget (read this):** Tailwind's CSS is global and counted against the search route's **20 KB, now 19.82 KB** (W9 decisions). Reuse utilities already in `build/_app/immutable/assets/*.css`; put this screen's own layout in the component's `<style>` (it ships in the route's chunk). Verified on main: `@reference '../../app.css';` (relative path) plus `@variant x-large { … }` inside a rule compiles to the route chunk. In `<style>` only tokens: `var(--…)`, `calc(var(--spacing) * n)` with `n` on the ramp; no px, no hex.
5. **The first-load reveal (§10.2):** on the page's first data only (not on tab changes, paging or refetches), the first ≤ 8 rows fade in (opacity, plus a small transform if you like) with `animation-delay: calc(var(--duration-stagger) * <index>)`, as a CSS keyframe in your `<style>`, not `svelte/transition` (runtime extras land in the shared chunk). Rows are in the DOM, readable and focusable from the start; nothing waits on the animation. Under `prefers-reduced-motion: reduce` nothing animates (the token is 0 there; check it).
6. **Keyboard and accessibility:** register `list.next` (`j`) and `list.previous` (`k`) with `scope: 'discover'` from your page in an `$effect` (they unregister on leave; `keys.pushScope('discover')` while mounted), moving VirtualList's active row; Enter opens (VirtualList's `onActivate`). Single keys never fire in inputs (the registry's rule). If `keys.register` throws because an id is taken, that's a bug to report, not to work around with a new id. Landmarks, heading order (h1 page, h2 sections), visible focus, 44 px targets under coarse pointers, the count in a polite `aria-live` region only when it changes after a tab switch, icon + text for every status.
7. **States, each designed:**
   - **Loading:** 8 skeleton rows at the final row height, section headings present, `aria-busy`; no skeleton for answers under 300 ms.
   - **Empty:** Newest `total` 0 on All: EmptyState "Nothing discovered yet" with one next step (Insights, `/insights`), illustration `StateScene` id `empty_state_explore` (`$lib/shell/StateScene.svelte`). On a tab: "No <type> torrents yet" with a link to All, no illustration.
   - **Error:** `503 search_disabled` (search off): full-page message saying search is turned off and where to turn it on (`/settings/search`); `network`/5xx: Banner (what happened + Retry), keeping the last rows visible (**stale**).
   - **Partial:** `≈` total; unavailable sections; never-scraped `—` (accessible name "Never scraped"); `title` null → the raw name; empty composition → "Not classified yet".
8. **Formatters only from `$lib/format`:** `formatCount`, `formatCompact` (approximate totals only), `formatBytes`, `formatShare`, `formatRelative` via the `RelativeTime` primitive (absolute in its tooltip). Pass `currentLocale()`. Every number has a `data-testid` (`discover-newest-total`, `discover-row-<hash>-size`, …). **The client never computes counts, percentages or cohorts:** no counting rows for a heading, no summing. **Tokens only.**
9. **Messages:** `discover_*` keys in `features/discover/messages/en.json` (§10.14: "Show more" style outcome labels, truthful states, errors as what happened then what to do); glossary terms from the shared keys (`m.discovered()`, `m.seeders()`, `m.backfill()`, …). **Missing shared keys:** the content-type labels (All… Adult), the group labels `images`/`documents`/`archives` and `dominant_share`. If the runner hasn't added them to `web/src/lib/i18n/messages/` by the time you start, use `discover_type_<t>`, `discover_group_<g>` and `discover_dominant_share` and list them in the PR. Unavailable reasons are `discover_unavailable_<reason>`. `zh.json`: proposed translations for every key, same placeholders. If `npm run messages` rewrites `web/src/app.html`, don't commit it; say so.
10. **Budgets (§10.1):** the search route's numbers mustn't move: `npx size-limit` (Search JS 39.43 of 45 KB, **CSS 19.82 of 20 KB**, total first load 81.9 of 100 KB on main) and `npm run lhci` on `/search` (`CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome`; about **0.5 KB of 102,400 bytes left**): run it before and after and report both. The route's own JS + CSS: proposed ≤ 15 KB (S-compare adds the entry). Keep anything heavy behind a dynamic `import()`. No Lighthouse URL exists for `/discover`; keep CLS at 0 with fixed row heights.
11. **You decide (record in your decisions file):** section layout and order at each width, tab overflow at narrow widths (a horizontally scrolling tab strip contained in its own box, or a Select below `large`), the unavailable texts, row field order. **Stop and ask:** any primitive or shared-message change; any field the schema lacks; anything that filters, counts or sorts rows in the client; a budget you can't meet without raising a limit.
