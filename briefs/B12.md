## Build
1. **Keep M-auth's contract** (#93, merged): `/auth`, `/setup`, `/login`, `/logout`, `/password` keep paths, bodies, statuses and codes (`login_required` + `setup_required`, `bad_token`, `bad_password`, `weak_password`, `rate_limited`, `setup_done`, `not_set_up`), the 10-character minimum, the 1,024-byte maximum, the `lodestar_session` cookie (HttpOnly, SameSite=Strict) and the bucket (burst 5, one per 12 s). An accurate `Retry-After` on 429 is allowed (the client caps it at 15 min). Existing auth goldens stay byte-identical.
2. **The fresh-password primitive** (§20.11): one function every confirming route calls, e.g. `auth::require_fresh_password(&Auth, ip, Option<&str>) -> ApiResult<()>`. Missing → `428 confirm_required`, `field: "password"`; wrong → `401 bad_password`; limited → `429 rate_limited`. Never cached or logged; Argon2 on the blocking pool. Still required under proxy-header auth.
3. **Keys and feed tokens** (`keys.rs`):
   - **Make:** ≥ 256 random bits from the OS RNG plus a public prefix, one documented format (e.g. `lsk_<prefix>_<base64url>`); the store gets the prefix and the SHA-256 of the whole string. The secret appears **once**, in the create or regenerate response.
   - **Endpoints** (session only, same-origin JSON): list, create (name, kind, scopes, `saved_search_id` for a feed token, optional expiry), regenerate, revoke, delete. **Create and regenerate need the fresh password**; revoke and delete don't. "Reveal" can't exist (only the hash is kept): a §2.19 refinement to record.
   - **Scopes:** the `u32` bits (e.g. `SEARCH`, `TORZNAB`, `FEEDS`) defined once with their meaning. A key reaches only routes that opt in.
   - **Presenting:** `Authorization: Bearer`, `X-Api-Key`, or the `apikey` query parameter (Torznab); a feed token as `?token=`. Guards such as `auth::key_or_session(routes, scope)` and a feed-token guard, used in tests on a test router; B9 (RSS) and the Torznab slice apply them. **Every existing route stays session-only.** Key requests never set cookies and can't write.
   - `touch_api_key` after a successful check.
4. **Rate limits:** a per-IP bucket for failed key checks, separate from login's (a bad secret and an unknown prefix answer identically, `401 bad_api_key`); a per-key request bucket with `Retry-After`, generous enough for *arr polling; nothing the UI's normal use could hit (search sends a request per ~120 ms debounce). Every limiter map is bounded like `LIMITER_MAX_IPS` and forgets recovered entries. Numbers go in the decisions file.
5. **Proxy-header auth** (off by default):
   - Trusted proxies (IPs/CIDRs), the user header (default `Remote-User`), optionally allowed user names; stored in `auth.json`; read and changed through `GET/PUT /auth/proxy`, the change needing the **fresh password**.
   - The header authenticates **only when the TCP peer is a trusted proxy**; otherwise it's ignored. Cookies keep working.
   - `ClientIp` behind a trusted proxy is the rightmost `X-Forwarded-For` address that isn't a trusted proxy, so login and key limits are per client. Parse defensively (length cap, bad entries skipped).
   - **Recovery:** an environment override (e.g. `LODESTAR_PROXY_AUTH=off`) applied where `Auth::load` runs. Say what B2c's keep-or-revert timer needs from you.
6. **Sessions:** `POST /sessions/revoke-others` (fresh password) rotates the session key and returns a new cookie for this browser, as `change_password` does.
7. **Never logged or echoed:** secrets, hashes, `Authorization`/`X-Api-Key` values, `apikey`/`token` query values, the proxy user header; `Debug` redacts (`dto::REDACTED`).

## Tests
- M-auth's goldens and the shared login bucket unchanged.
- Fresh password: 428, 401, 429, success, nothing remembered between calls.
- Keys: the secret is returned once and never listed or stored; every presentation form; wrong secret, unknown prefix, revoked and expired fail identically; scopes enforced; walking `tests/openapi.rs` `ROUTES` with a key and no cookie gives 401 everywhere; a feed token is limited to its saved search; regenerate kills the old secret.
- Limits: the bad-key bucket, the per-key bucket with `Retry-After`, bounded maps.
- Proxy: honoured only from a trusted peer; a spoofed `X-Forwarded-For` from an untrusted peer ignored; a property test that arbitrary XFF strings never panic and never yield a trusted proxy as the client; the override turns it off.
- A log-capture test over these flows finds no secret, key, token or proxy user.
