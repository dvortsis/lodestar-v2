# X-web-hygiene-1101: CSS headroom, a guard that can't pass vacuously, chunk-load errors
**Model:** Sonnet. An Opus reviewer follows. Runner brief, 2026-11-01. Three follow-ups from #302 and #304.

## Why
1. **CSS budget.** The global CSS entry is 19.93 KB on main against a 20 KB limit (`web/.size-limit.mjs`, entry "CSS"), and S-wizard (#302) takes it to about 19.97 KB. The next UI slice will tip it. Find real bytes rather than raising the limit.
2. **`web/scripts/first-load.mjs` `modulesIn()`** returns `[]` when the graph file is missing, so the first-load guard in `.size-limit.mjs` could pass without checking anything (#304 review b).
3. **Chunk loads without a catch.** `void import('./commands')` in `features/alerts/AlertsListPage.svelte` (about l.101), and the same pattern in `AlertDetailPage` and `detail/DetailHostBody`, turn a failed chunk load into an unhandled rejection (#304 review c).

## Do
1. **CSS: target ≥ 0.4 KB gzip headroom** on the CSS entry without changing any rendered pixel.
   - Measure what's in the built CSS: hand-written rules, Tailwind utilities, and `@layer` blocks. List the biggest contributors.
   - Look for: utilities generated by stray strings in JS or TS (the `!word` trap, test-only strings, comments); hand-written rules that nothing uses; duplicate rules a token or utility already covers; unused `@keyframes` or `@font-face` variants; theme rules repeated per theme that could share a selector.
   - Prefer Tailwind `@source not` / safelist hygiene over editing components. If a component class must change, keep the computed style identical.
   - Lower the CSS limit if you can: new limit = measured + 10% of the cut, never below 0.3 KB headroom. Never raise it.
   - **Baselines must not change.** Run the smoke and all-themes Playwright specs with `--ignore-snapshots` off where possible. If any screenshot changes, stop and tell the runner.
2. **Guard:** make `modulesIn()` throw a clear error when the client manifest exists but the module graph file doesn't. Add a small test.
3. **Chunk-load errors:** give those dynamic imports a `.catch` that matches the repo's existing pattern for a failed lazy part (look for `Lazy.svelte` or how other screens show "couldn't load"). Where the import only warms a cache or registers shortcuts, a silent catch with a comment is fine; where the user waits on it, show the existing failure state. Sweep `web/src` for other bare `void import(` and fix them the same way; list them in the PR.
4. **Decisions file:** `docs/decisions/<date>-X-web-hygiene-1101.md`, with before/after CSS bytes and what you removed.
