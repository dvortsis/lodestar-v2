# B1: Typed DTOs, utoipa and /openapi.json with a drift check
**Model:** Opus (core: the API contract). **Branch:** `slice/B1`.
**Spec, in order of authority:**
- `docs/owner-decisions.md`, then `runner/standards.md` (on branch `runner/standards`, PR #39, until it merges), then CLAUDE.md;
- architecture §9 and §12;
- `docs/build-plan.md` §1.3 (contract-first);
- `docs/metrics.md` §7 on main: **the UI field contract**. DTO field names and nullability must match it exactly.

## Today on main
- `crates/api` is split per domain (B0): `auth`, `search`, `torrents` and `filters` modules, each with `routes()`, composed in `lib.rs::router` with one `.merge` line each.
- Errors use `ApiError` (`error.rs`).
- Handlers build responses with `serde_json::json!`, so there's no typed contract.
- M4 PR 2 (#48, open) will add a swarm module. Coordinate by keeping your changes per module, so its merge is mechanical.

## Do
1. **Typed response and request structs** (`Serialize`/`Deserialize` + utoipa `ToSchema`) for every existing endpoint: auth, setup, login, logout, parse, search (GET and POST, AST), torrents detail and files, password, and every filters and classify route from #47 and #52. Also the envelope `ApiError`.
   - Put them in `crates/api/src/dto/` (one file per domain).
   - Handlers return the typed structs.
   - **The JSON must stay byte-compatible with today's**: same field names, same null/absent behaviour. Prove it with a golden test per endpoint comparing the old `json!` output to the new serialisation, on representative fixtures.
2. **Nullable swarm fields** from metrics.md §7.1/§7.2 are declared now as `Option<…>` and serialised as `null`. M4 PR 2 fills them; until then they're `null` (never scraped). Coordinate names exactly with metrics.md.
3. **OpenAPI:** utoipa `OpenApi` derive covering every route, served at `GET /api/v1/openapi.json`, open (no session; it holds no data). Include the session cookie security scheme and the error envelope as the common error response.
4. **Generator bin:** `crates/lodestar/src/bin/openapi.rs` (or a `lodestar openapi` subcommand) writes `web/src/lib/api/openapi.json`, pretty-printed and with stable key order. Commit the generated file.
5. **Drift check in CI** (`.github/workflows/ci.yml`, one job or step): regenerate and `git diff --exit-code web/src/lib/api/openapi.json`.
   - In `web/`, the existing `npm run api:types` (openapi-typescript) must now produce `src/lib/api/schema.d.ts`. Commit it too.
   - Add a web.yml step checking that schema.d.ts is fresh.
6. **501 stubs:** don't add new endpoints here, but document in `crates/api/README.md` the pattern later slices follow: typed DTO, a 501 stub with an example, then the handler.

## Don't
- Change behaviour, status codes, routes, auth or cookies.
- Add endpoints.
- Touch crates other than `crates/api` and the generator bin, plus the two CI steps.

## Done when
- fmt, clippy (`--all-targets -D warnings`) and the workspace tests pass, including the per-endpoint golden compatibility tests.
- `/api/v1/openapi.json` validates (an openapi-spec-validator equivalent, or utoipa's own validation in a test).
- `npm run api:types` produces schema.d.ts, and `npm run check` passes with it.
- New dependencies: utoipa (and utoipa-axum if used), approved, declared the way crates/api declares its other dependencies.
