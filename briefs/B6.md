## Build
1. **The endpoint.** `GET /api/v1/facets` takes the same query parameters as `GET /search` (`q`, filters, and `hidden`/visibility). There's also a POST with the AST, mirroring search.
   - It returns facet groups only, never hits.
   - **Same base filter as search:** facets must be computed over exactly the documents search would return. Build the base query through the same function search uses, including the hidden-torrent clause and anything B17 adds there for Adult visibility. Don't re-implement it. Test that the facet total equals the search total.
   - A `lease` (from a search response's cursor) may be passed, so facets read the same snapshot as the results. Without it, use the current index.
   - Under the request's `CancelToken` (cancel on client disconnect, as B5a does for search) and a time budget.
2. **Disjunctive term facets.** For each facet field with a selection in the query, its counts are computed with that field's own clause removed, so multi-select works. Other fields' clauses stay.
   - **Fields:** type (content type), ext, category, resolution, lang, release group, codec, HDR, adult subtype (only when Adult is visible), and private/v2/has-nfo/subs/cue/ambiguous booleans. Take the list from §10.4's default groups and "More filters", limited to what the index holds today. Say which ones aren't indexed yet and leave them out.
   - **Rules:**
     - top N per field (8 by default, `?limit.<field>=` up to 100) plus `other`;
     - each value's count;
     - the selected values are always included even when outside the top N.
   - Removing a clause for disjunction must handle the AST shapes the query language allows (OR groups of the same field, negations). Define precisely what "the field's own clause" is for nested or negated cases, document it in §16, and test it.
3. **Histograms.**
   - **Size:** fixed log bins (e.g. powers of 2 from 1 MiB to 1 TiB plus under/over), explicit bin edges in the response.
   - **Discovered:** bins chosen from the range (hour/day/week/month), returned with edges in UTC seconds. The client applies the user's timezone for labels; check metrics.md's timezone rule and follow it. Mark bins before the crawl's first-run time as "backfill" if the store knows it; otherwise leave a TODO naming the slice that will.
   - **Year:** from the parsed year, if indexed.
   - **Seeders / trackers reporting:** buckets ≥ 1 / ≥ 5 / ≥ 50 and "never scraped". **Behind a flag** that stays off until M4's swarm fields exist in the index. The response says `unavailable` instead of zeros (null ≠ 0).
4. **Sampling.**
   - Above 1,000,000 matches, compute facets on a uniform sample (reuse or extend B5a's stratified sampler in `count.rs`) and scale the counts. The response carries `approx: true` per group, plus the sample rate.
   - Exact below the threshold.
   - Document the error bound like B5a did for counts.
5. **Schema bump #1.**
   - Add whatever fast fields or columns facets need (e.g. a fast `ext` set, `res`, `lang`, `group`, `year`, `adult_kind`, if not already reachable through `tag`'s fast column).
   - **Keep within the 512 B/torrent index budget.** Measure before and after on the bench corpus and report it.
   - Bump `SCHEMA_VERSION` exactly once. B5b's `Serving` rebuilds into the new directory in the background and swaps. Add a test that an index at the previous version is rebuilt and serves facets after the swap.
   - B7 (`title_stem` and suggest) will need fields too. Its slice isn't running, so don't anticipate it; the build plan pairs the bump with B7, but run it now with B6's fields only, and note in §16 that B7 needs a second rebuild unless its fields fit in this one. If B7's needs are obvious from §8 and cost little, add them now and say so.
6. **Result cache.** None here; B5c owns the cache. Keep the facet computation a pure function of (snapshot, AST, params) so B5c can cache it.

## Tests
- **analytics-validation fixtures:** a fixed fixture corpus in which, for every facet field, the counts equal an independent SQL `COUNT(*) … GROUP BY` over the store. Disjunctive counts equal "the result count with that field's clause removed", split by value. The result count equals the sum of the disjunctive expectations where the field is single-valued. Histogram bins sum to the result count.
- Disjunction over AND/OR/NOT shapes.
- Selected values outside the top N are present.
- Sampling: exact below the threshold; above it, `approx: true` and within the documented tolerance on a synthetic large set (a small threshold in tests).
- Cancellation stops early (B5a's tripwire fixture).
- The lease snapshot is respected across a commit.
- The schema-bump rebuild and swap work.
- The seeders/trackers flag-off shape.
- API goldens in B1's style. Unauthenticated gives 401.
- `search-bench`: a facets latency class (broad word + all default groups) with a §3-style budget proposal. The existing gate still passes.
