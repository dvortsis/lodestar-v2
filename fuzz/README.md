# Fuzz targets

[cargo-fuzz](https://github.com/rust-fuzz/cargo-fuzz) targets for every parser of untrusted input (architecture §6, §14 M1). They need a nightly toolchain:

```sh
cargo install cargo-fuzz
cargo +nightly fuzz run krpc            # runs until stopped or a crash
cargo +nightly fuzz run metainfo -- -max_total_time=300
```

| Target | Checks |
|---|---|
| `bencode` | No panics. A strict decode that succeeds means the input was canonical. A lenient decode re-encodes to a stable canonical form. |
| `krpc` | No panics. Parsed messages are stable under encode → parse. |
| `metainfo` | No panics in `Info` or `TorrentFile` parsing. Parsed file lists keep the model's invariants and round-trip through the store's blob codec. |
| `filetree` | No panics on corrupt blobs. Accepted blobs round-trip. |
| `tracker_scrape` | No panics in the UDP (BEP 15) and HTTP (BEP 48) scrape reply parsers. Parsed replies never hold more entries than the request allows. |
| `release` | No panics in the release-name parser. Parses are deterministic, and reported groups and versions are text from the name. |
| `lists` | No panics in blocklist decoding, format detection and the hash and IP parsers; IP sets round-trip through their stored encoding. The content filter's normalizer and core never panic on the same text as a name and file list, and the verdict agrees with the full hit list. |
| `utp` | No panics in the uTP packet parser, and parsed packets round-trip. A connection fed hostile packets and local events keeps its buffers bounded and only sends packets that parse. |
| `dht_restart` | No panics in CR-0d's snapshot, marker and witness decoders. The target seals its input itself (the first byte picks the kind, and for a snapshot the next 8 bytes give the wall clock, to the nanosecond), so the body decoders are reached despite the checksum. Whatever decodes is canonical, and a decoded snapshot that resumes never seeds a deadline earlier than the one it records. |
| `update` | No panics in the update envelope, manifest, key statement, freshness, minisign and trust-state parsers, or in `verify::check` against a fixed test trust (also on bodies the fuzzer's bytes become once signed with a test key). A document that verifies re-verifies identically, as a refetch on the state it produced, and that state reloads. |
| `claims` | No panics in the stored-claims decoder (`lodestar_store::claims`, SRC-1, version 2 from ENR-0). An accepted blob is within every limit, has version 2 exactly when it holds an adult-enrichment section, and round-trips through the encoder; an accepted plain body is canonical (it re-encodes to the same bytes). |
| `archive_org` | No panics in the Internet Archive JSON parser (`advancedsearch`, scrape and `metadata` answers, SRC-9). The first byte picks tight caps. Kept items hold a v1 hash only and stay within every cap: title, identifier, collections, file count, file-name bytes and path length, with hidden characters removed. |
| `prowlarr` | No panics in the Prowlarr/Jackett plugin's indexer-list parsers (Prowlarr's JSON, Jackett's `t=indexers` XML) or in mapping Torznab items to discoveries (SRC-7). The first byte picks the manager, the input and whether the indexer is private. Lists hold at most 500 distinct, path-safe ids and never Jackett's `all`; discoveries keep sizes and dates in range and carry no reference when private. |
| `client_list` | No panics in the download clients' torrent-list parsers (qBittorrent, Transmission and Deluge JSON) or in mapping listed torrents to discoveries (SRC-11). The input is one byte picking the client, a two-byte little-endian list length, the list, and then the `.torrent` bytes each listed torrent is given as its export. Lists hold at most 50,000 distinct lowercase hashes with clean, bounded names; every find is `private_source` with no trackers or reference, and an export's claims are used only when its info dict hashes to the listed key. |
| `arr_webhook` | No panics in the Sonarr and Radarr webhook parser or in mapping an event to a discovery (SRC-11b). The input is one byte picking the app (even Sonarr, odd Radarr), then the body. Bodies over 256 KiB, or that aren't one JSON object within the depth, value and array caps, are refused whole; kept titles are clean and at most the claims' name limit, sizes within 1 B to 1 PiB, ids ASCII alphanumeric; only a Grab or Download with a 40-digit hex `downloadId` finds a key, and every find is `private_source` with no trackers, files or reference. |
| `cluster_results` | No panics in the `Results` and `Counters` payload decoders (WK-6, `lodestar_pipeline::wire`). The first byte picks the decoder (even `Results`, odd `Counters`). Payloads over 512 KiB, or with more records or counters than the caps, are refused before allocation; whatever decodes re-encodes to the same bytes, keys each record by one of its swarm hashes, and carries no `pieces` in a raw dict or extra blob; counters are in strictly ascending key order. |
| `cluster_assign` | No panics in the `Assign` payload decoder (WK-5, `lodestar_cluster::assign`). An unknown version or a wrong length is refused; whatever decodes is a valid assignment that encodes back to the same bytes, and a message is accepted only under the payload's own revision. |
| `cluster_have` | No panics in the replicated have-filter's header, delta and chunk-assembly code (WK-3, `lodestar_cluster::have`). The first byte picks the case: a header, a delta, or a header followed by chunks given as a sequence byte (its top bit marks another transfer's chunk) and a length byte. Unknown versions and wrong lengths are refused; whatever decodes encodes back to the same bytes; an assembly completes only from every chunk in order, each of its exact length, and skips chunks of another transfer. |
| `cluster_filter_snapshot` | No panics in what a remote worker judges with (WK-8, `lodestar_pipeline::wire::filter_snapshot`): the filter snapshot, the dictionary snapshot and chunk assembly. The first byte picks the case (0 filter, 1 dictionary, 2 a chunk sequence). Unknown versions, flags and tags are refused, counts and lengths are capped against the bytes left before allocation; whatever decodes re-encodes to the same bytes and builds an engine; a snapshot assembles only from every chunk in order, full but the last. |
| `torrent_cache` | No panics in the torrent-cache plugin's reply check (SRC-13), `torrent_cache::verify_body`: the sync function the plugin's async lookup calls on each body it fetches, which parses the `.torrent` under the plugin's `LIMITS` (8 MiB file cap), re-parses the info dict's raw bytes with no encoding hint and runs `verify`. The first byte picks the key, modulo 3: the dict's v1 hash, its truncated v2 hash, or 20 bytes of input (bit 7 picks interest or unverified). An unparsable body is `Invalid`; a parsed one verifies under the dict's own hash (a v2 match only when it isn't the v1) and is a `Mismatch` under any other key; a kept dict re-parses to the kept `info`. |
| `verified_claims` | No panics in `Verified::claims` and `Verified::provenance` (SRC-13) on bodies `verify_body` accepts under their own hash. The first byte picks the shape: even, a whole body; odd, a `.torrent` built from the input around a fixed info dict (a flags byte for `private` and `creation date`, then the comment and one tracker per `0x00`-separated segment). Kept trackers are the file's own in the `url` crate's form, in order, once each, within the caps, with no query, fragment or user name and only `http`, `https` or `udp`; a private dict gives none and no comment; the comment is the file's, cut to the cap; only a believable `creation date` is kept. |
| `tpdb` | No panics in the ThePornDB answer parser (search pages and lookups, ENR-2b). The first byte picks tight caps. Kept matches have a valid id and a clean, bounded title, studio and performer names, with no more performers than the cap. |
| `stashdb` | No panics in the StashDB GraphQL answer parser (ENR-3). The first byte picks tight caps. Kept scenes have lower-case UUID ids, clean bounded titles and names, valid fuzzy dates and at most `max_performers` performers. |

`seeds/<target>/` holds hand-made inputs a target should start from, such as the BEP 47 padding, symlink and mixed `path.utf-8` shapes for `metainfo` and their blobs for `filetree`. Pass the folder after the corpus so libFuzzer reads it but writes new finds to the (ignored) corpus:

```sh
cargo +nightly fuzz run metainfo fuzz/corpus/metainfo fuzz/seeds/metainfo -- -max_total_time=600
```

CI runs each target for a short time on every pull request (`fuzz` job). Crashes land in `fuzz/artifacts/<target>/`. Minimise one with `cargo +nightly fuzz tmin <target> <file>`, then add it as a regression test in the owning crate.
